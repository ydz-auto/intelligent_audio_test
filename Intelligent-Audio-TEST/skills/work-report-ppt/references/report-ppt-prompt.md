# 企业工作汇报 PPT 写作与排版规范

来源：实战会话中用户确认的《通用工作汇报 PPT 生成 Prompt》。用于技术汇报、项目进展、
阶段总结、方案评审、数据分析、管理层汇报。本文件只管**写什么、怎么写**；分页与容量
硬约束见 `SKILL.md` 的「渲染器硬约束」。

## 一、核心原则

结论先行、数据支撑、逻辑清晰、简洁务实、重点突出。以有效传达信息为首要目标，不追求
视觉复杂度。

## 二、风格

1. **定位**：极简、专业、现代的企业内部汇报风；不花哨、不刻板；信息密度适中，层级分明。
   不用复杂装饰、拟物、炫酷特效，不用海报式模板。
2. **配色**：红白灰。主色 `#C00203` 用于标题强调、重点模块、关键数据、核心结论；白
   `#FFFFFF` 为页面背景；浅灰 `#F2F2F2` 为模块/表格底色；深灰 `#333333` 为正文；中性灰
   `#999999` 为次要信息与分割线。红色只给最重要的信息，避免大面积红底与阴影。
3. **字体字号**：微软雅黑。页标题 26–30pt 加粗；模块标题 18–22pt；正文 14–18pt；数据标签
   12–16pt；注释 10–12pt。
4. **页面**：16:9；留白适中、间距一致；不用动画和转场。

## 三、内容组织

1. **一页一个核心观点**，不在一页讨论不相关话题。
2. **结论先行**，标题要有信息量：
   - 不推荐「项目进展情况」→ 推荐「核心任务按计划推进，关键节点已完成」
   - 不推荐「数据分析」→ 推荐「主要指标持续改善，但部分场景仍存在差距」
   - 不推荐「问题总结」→ 推荐「当前主要问题集中在执行效率和跨部门协作」
   证据不足时不得把推测写成结论。
3. **推荐逻辑**：核心结论 → 关键事实/数据 → 原因分析 → 影响与建议；不同页面可调整。
4. **精炼**：不整段搬文档；提炼关键词、短句、关键数据；一个模块一个核心信息。
5. **准确**：区分客观事实 / 主观判断、已完成 / 计划、已验证 / 待验证、当前结果 / 预期目标。
   不虚构数据、成果、来源或结论。

## 四、布局

- 左右对比：方案对比、优劣势、问题与措施。
- 上下递进：背景 → 问题 → 方法 → 结果。
- 三栏并列：三个模块/维度/方案。
- 图表 + 结论：数据分析、指标对比。
- 流程/时间轴：流程、计划、里程碑。
- 核心结论 + 关键支撑：管理层汇报、阶段总结。

不强制每页卡片化；不把所有信息装进方框；避免整页密集表格、大段连续文字、无意义图标箭头。

## 五、数据呈现

- 重点数据用主色，次要数据用低饱和灰。
- 标清单位与口径；比例合理，不误导；不重复展示同一数据。
- 平台 PPTX 不支持图表对象：趋势用「本期 / 上期 / 变化」三列表格代替；分布用分组计数表。
- 大数字写法：`2,356 近 30 天建档`、`93.7B tokens`、`97.5% 缓存命中`。

## 六、六类汇报的逻辑

| 类型 | 逻辑 |
|---|---|
| 工作进展 | 目标 → 进展 → 已完成 → 问题 → 下一步 |
| 数据分析 | 核心发现 → 关键数据 → 趋势/差异 → 原因 → 建议 |
| 问题分析 | 现象 → 影响范围 → 原因 → 措施 → 验证跟进 |
| 方案评审 | 目标需求 → 备选方案 → 对比维度 → 优劣势与风险 → 推荐 |
| 阶段总结 | 核心成果 → 关键数据 → 主要问题 → 经验 → 后续 |
| 管理层汇报 | 核心结论 → 业务影响 → 关键证据 → 待决策 → 行动建议 |

## 七、语言风格

专业、直接、务实、客观。标题表达观点而非描述主题；文字简短；多用准确动词与明确判断；
保留重要数字、指标、时间节点；避免空泛形容词与夸张表述；术语全篇一致；结论按确定性
程度表述；适当位置点明意义与下一步行动。

## 八、自检

逐页检查：核心观点是否明确、标题是否有价值、逻辑是否清晰、文字是否过多、数据是否相互
支撑、配色与字体是否统一、布局是否整齐、关键结论是否可被证据支撑。
