# work-report-ppt

把「汇报」当成一次取数 + 叙事 + 导出的闭环：**数据只能来自平台报告，版式由平台渲染器决定。**
不做自由排版，也不承诺平台给不了的效果。

## 何时用 / 何时不用

用：

- 用户要一份汇报 PPT / 汇报材料 / 演示文稿，且内容来自平台报告或任务结果；
- 要把报告结论整理成「大纲 + 每页要点」再交付 `.pptx`；
- 要在已有 Studio 文档上改一页、加一页，然后重新导出。

不用：

- 只问某个指标是多少、怎么算 → `report-studio`；
- 多份报告对比、二次对比、趋势 → `report-compare`；
- 用户要自由设计（配图、图表对象、动画、任意版式）→ 直接说明平台不支持，
  只能用「表格 + 文字 + 固定红白灰版式」。

## 渲染器硬约束（先读，再写正文）

Markdown → PPTX 的分页规则是固定的，写之前必须按它组织内容：

| 规则 | 行为 |
|---|---|
| 分页 | `#` 或 `##` 一出现就开新页，该标题即页标题；两者行为一致 |
| 页内模块标题 | `###` / `####` 不分页，渲染为 18pt 加粗小标题 |
| 封面 | 自动生成，大标题取自 Studio 文档的 `title`，不是正文里的 H1 |
| 正文容量 | 每页约 12 个「单位」：段落 1.2 + 每 70 字 +1；条目 1.0 + 每 70 字 +1；**超出自动分页**并加「（1/2）」后缀 |
| 表格 | 表格块单独成页，不占正文；每页最多 12 行，超出按 12 行切页且每页重复表头 |
| 行内强调 | `**` / `__` 会被剥掉；重点只能靠固定主色，不能靠加粗 |
| 不支持 | 图片、图表对象、嵌套列表、有序列表、动画、转场；`---` 只作分隔不产生内容 |
| 中文字体 | 固定微软雅黑；主色 `#C00203`、正文 `#333333`、次要 `#999999`、底色 `#F2F2F2` |
| 画布 | 16:9（13.333 × 7.5 in），页脚固定「Report Studio · 数据来自平台报告」+ 页码 |

## 流程（四步，写操作全走审批）

### 1. 定大纲（必须等用户确认）

输出纯文本大纲，每页一行：

```
P1 标题（结论句）｜内容：要点 1 / 要点 2 / 表格（列名）
P2 标题（结论句）｜...
```

同时说明：预计页数 = 大纲页数 + 1 张封面；表格超过 12 行会再切页。

### 2. 取数（只用 `report_query`）

- 定位报告：`list`（可按 `keyword` / `task_id` / `status` 过滤）→ `detail` 取指标矩阵；
- 需要用例级证据：`cases` / `cases_search`；需要均值：`case_averages`；
- 数字原样引用接口原文，不四舍五入、不换算单位、不跨字段推算；
- 每个准备写进 PPT 的数字，记下它来自哪个字段，后面正文要能对回去。

### 3. 起草或改稿（`report_generate`）

- 新建：`studio_draft`，必填 `report_id` + `body.markdown_content`，强烈建议同时给
  `body.title`（封面标题）；`body.chart_refs` / `body.style_prefs` 在 PPTX 里不生效，
  不要依赖；
- 改稿：`studio_edit`，必填 `doc_id` + `body.expected_version` + 新正文；版本号从
  draft / 上一次 edit 的 `current_version` 取，`409` 表示有人改过，重新取文档再改；
- 完全相同的正文重复 draft 会复用原文档（`reused=true`），不会产生第二份。

### 4. 导出（`report_export`）

`format=pptx`，`doc_id` 优先（没有就用 `report_id` 定位最近更新的 Studio 文档），
可选 `version` / `theme`。导出是异步作业，产物按返回的 `download_ref` 鉴权下载。

## Markdown 正文模板

```markdown
## 核心任务按计划推进，关键节点已完成

- 本周完成任务 2,227 个，done 率 94.5%
- 平均单任务耗时下降 18%

### 关键指标

| 指标 | 本周 | 上周 | 变化 |
| --- | --- | --- | --- |
| done 率 | 94.5% | 91.2% | +3.3pt |
| 返工数 | 79 | 96 | -17 |

## 当前主要问题集中在跨区部署

### 现象
- 上游服务器无配额，镜像是就绪的

### 判断
- 属资源问题，不是代码问题；部署解阻后即可验证
```

约定：每页一个 `##`；页内用 `###` 分 2~4 个模块；每模块 2~4 条 `- `；
表格只放能支撑结论的数字，不放全量明细。

## 写作规范（摘要，完整版见 `references/report-ppt-prompt.md`）

1. **标题写结论**，不写主题：「核心任务按计划推进，关键节点已完成」而不是「项目进展」；
   句式用「做了什么、解决了什么」。
2. **一页一观点**；页数按用户给的下限做，不主动扩页。
3. **数据有出处**，区分事实 / 判断 / 计划 / 待验证；不虚构、不外推。
4. **紧凑**：一条一行，不写长段落；正文块控制在每页 8 个以内，避免自动分页产生残页。
5. **表格克制**：列不超过 6 列，行不超过 12 行；超过先聚合或拆页。
6. **术语一致**：同一概念全篇一个叫法；指标名与报告字段保持一致。

## 审批与话术

- `report_generate` / `report_export` 调用后只生成待审批提案（`APPROVAL_REQUIRED`），
  此时**没有任何副作用**；
- 提案阶段说「已提交审批，批准后才会导出」，拿到执行结果后才说「已导出」；
- 拒绝或过期时如实告知未执行，不要重试刷提案。

## Gotchas

- 只写 H3/H4 不写 H1/H2 → 整篇压成一页，且没有页标题。
- 一页塞太多块 → 渲染器按 12 单位自动分页，出现「标题（1/2）」的半页残页；提前按 8 块/页控制。
- 表格不会出现在文字页里：它被单独抽成一页，正文里剩下的内容会显得空。
- 表格超过 12 行会切成多页并重复表头，但列宽按内容自动分配，超长列名会被压缩。
- `**重点**` 会被剥离，正文里看不到加粗；不要用 Markdown 强调表达层级。
- 封面标题来自 `body.title`；不传就显示「报告」，和正文 H1 无关。
- `theme` 只改封面/页脚的主题标签文字，不改配色；不要承诺「换个主题色」。
- `studio_draft` 同报告 + 同正文会复用文档，想改必须走 `studio_edit` 并带 `expected_version`。
- 平台只支持任务报告（`type=task`）的生成；对比 / 二次对比报告只能引用已有结论。
- 导出异步且产物在服务端，`download_ref` 有时效；过了有效期要重新导出。

## 验收

交付前逐条确认，任一条不满足就不算完成：

- [ ] 大纲在生成前已给用户确认，页数 = 大纲页数 + 1 张封面
- [ ] 正文每个 `##` 对应大纲一页，页标题是结论句
- [ ] 正文里每个数字都能对回 `report_query` 某次返回的字段
- [ ] 每页正文块 ≤ 8，没有因超容量自动分页的残页
- [ ] 表格 ≤ 12 行 / ≤ 6 列，超出已聚合或拆页
- [ ] 事实 / 判断 / 计划在措辞上可区分，没有把推测写成结论
- [ ] 导出经审批执行成功，拿到 `download_ref` 并能下载
- [ ] 回复中包含：页数、每页标题清单、产物下载引用、未解决项
