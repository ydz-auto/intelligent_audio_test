# work-report-ppt

把「报告数据」变成「可交付的汇报 PPT」的固定工作流。

**能力边界先说清**：平台没有「模型直接画 PPT」的工具。PPT 由 Report Studio
导出器从 Studio 文档的 Markdown 渲染，版式（16:9、封面、分节页、页码、表格样式）
由渲染器固定。你能控制的是**内容与结构**：每页标题、要点数量、表格；不能控制
字体、配色、图片、图表与动画。用户要品牌模板 / 配图 / 图表排版时，先说明这条
边界，再给内容方案，不要承诺做到。

## 何时用

- 用户要把一份已有报告（任务报告 / 对比报告 / 二次对比）变成汇报材料；
- 用户要「做几页 PPT 讲结论」「评审用演示」「把分析发给管理层」；
- 用户要把 Studio 文档重新导出成 PPT，或按意见改几页再导。

## 何时不用

- 只要 HTML / PDF / Markdown 交付：直接 `report_export` 对应格式；
- 多报告并排对比、二次对比、趋势结论：先用 `report-compare` 取结论；
- 要跑任务 / 看日志 / 改用例：不是本 Skill 的范围；
- 要改报告本身的指标：平台报告指标不可编辑，只能重新生成（`regenerate`，有破坏性）。

## 固定链路（四步，不跳步）

1. **取数**：`report_query` 的 `detail` / `cases` / `case_averages` 取真实数值；
   记下 `report_id`、指标名与资源名。每个要上 PPT 的数字都必须能回指返回字段。
2. **大纲确认**：先把「页码 + 每页结论式标题 + 3~5 条要点 + 用到的数字」发给用户，
   用户确认后再动笔。未确认不要直接建文档。
3. **写文档**：`report_generate`（`action = studio_draft`）创建 Studio 草稿，
   `body.markdown_content` 用「演示型 Markdown」；已有文档要改时用
   `report_generate`（`action = studio_edit`）+ 当前 `expected_version`，
   每次编辑生成新版本（历史只追加）。
4. **导出**：`report_export`（`format = pptx`，固定 `doc_id` + `version`）。
   返回 `status = done` 才算完成；`pending / running` 如实告诉用户在渲染；
   `failed` 读 `error` 定位。产物通过 `download_ref` 鉴权下载，前端会渲染成
   会话产物卡（PPT 直接下载）并自动打开右侧文档面板。

## Phase 1：大纲（必须先确认）

按页输出，格式固定：

```
P1 封面：<报告名>（由文档标题自动生成，不用写进 markdown）
P2 <结论式标题>｜要点 1 / 2 / 3｜关键数字：xx
P3 <结论式标题>｜表格：指标 / 值｜要点：xx
P4 结论与建议｜3 条行动项
```

规则：

- 标题写结论，不写主题：写「核心任务按计划推进，关键节点已完成」，
  不写「项目进展」；
- 一页一个观点，建议 3–8 页，不主动扩页；
- 数字全部来自第 1 步，事实 / 判断 / 建议分开表述；
- 少于 3 条要点的页并入上一页，避免空页。

## Phase 2：演示型 Markdown 契约

渲染器按标题切页：**`##` 标题 = 一张幻灯片**；封面由文档标题自动生成。

- 正文**不要写 `#` 一级标题**，否则会多出一页重复封面；
- 每个 `##` 下只放 3–5 条 `- ` 要点，单条尽量 ≤ 60 字；
- 段落用于结论句 / 口径说明，不要写成大段正文；
- 表格用 `| 指标 | 值 |`，建议 ≤ 12 行 / 页（超出部分渲染器会拆页或截断）；
- 支持：标题、段落、无序列表、表格、代码块（纯文本）；
- 不支持：图片、图表、嵌套列表、HTML、颜色 / 字号 / 字体标记（写了也不会生效）。

推荐骨架：

```markdown
## 结论：通过率 90.72%，失败集中在打断恢复
- 用例总数 388，已完成 352，失败 0
- 通过率 90.72%，达到本轮验收线
- 失败场景集中在「打断后恢复首轮内容」链路

## 关键数据
| 指标 | 值 |
| --- | --- |
| 用例总数 | 388 |
| 已完成 | 352 |
| 通过率 | 90.72% |

## 结论与建议
- 优先修复打断恢复内容丢失
- 补齐 162 与 318 之间的解释字段
- 下一次回归扩大到多设备与 API 通道
```

完整模板见 `references/slide-markdown.md`。

## 写操作口径

- `studio_draft` / `studio_edit` / `report_export` 都是写操作：调用后先生成
  **待审批提案**（`APPROVAL_REQUIRED`，零副作用），审批通过才执行；
- 提案阶段说「已提交审批，批准后才会生成 / 导出」，拿到执行结果后再报告完成；
- `studio_edit` 必须带当前 `expected_version`；`409` 说明有人先改了，
  重新取文档后再改，不要覆盖；
- 同一文档版本 + 同格式 + 同主题重复导出会复用旧作业（`reused=true`），
  内容不会更新；**要改 PPT 内容必须先 `studio_edit` 出新版本再导出**；
- 表格超过渲染器单页上限时会拆页 / 截断，完整数据引导用户看 HTML / MD 产物。

## 回答与交付

- 大纲阶段：给页数与每页标题，等用户确认；
- 文档阶段：给出 `doc_id` 与 `current_version`，说明正文已落 Studio 文档；
- 导出阶段：给出格式、版本、作业状态；`done` 时告诉用户在产物卡下载，
  并说明「PPT 为固定版式，如需品牌模板/配图需另行处理」；
- 不编造指标、不把提案说成已执行、不承诺渲染器做不到的视觉能力。

## Gotchas

1. **PPT 渲染器只吃 Markdown 结构**：字体、颜色、图片、图表都不生效；
   用户要「红白灰、品牌色」时说明当前是平台固定版式。
2. **`##` 切页**：多写一个 `##` 就多一页；不要把长文塞进一个 `##`。
3. **表格按行拆页**：PPT 单页表格容量有限，指标多的表建议拆成两张表或转成要点。
4. **封面重复**：正文写 `#` 会多一张重复封面页。
5. **导出复用**：同版本同格式重复导出拿到的还是旧文件；改内容必须升版本。
6. **下载链接需登录**：`download_ref` 不能直接粘贴打开，引导用户点产物卡。
7. **写操作要审批**：审批前不要说「已生成 / 已导出」。

## 验收

- [ ] 先用 `report_query` 取真实数据，PPT 里每个数字都能对应返回字段；
- [ ] 大纲经用户确认后才创建 / 修改 Studio 文档；
- [ ] 正文没有 `#`，每页一个 `##` 结论式标题 + 3~5 条要点；
- [ ] 表格行数控制在单页容量内，超出的数据有降级说明；
- [ ] 改稿走了 `studio_edit` + `expected_version`，没有覆盖他人版本；
- [ ] 导出状态如实（done / pending / failed），给了 `download_ref`；
- [ ] 明确说明 PPT 是平台固定版式，没有承诺图片 / 图表 / 品牌模板能力。
