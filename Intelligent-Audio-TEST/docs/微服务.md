# 微服务架构

## 概览

系统由 **10 个后端微服务** + 3 个基础设施组件组成，通过 gRPC 通信，Redis 做服务注册与发现。

```
                    ┌─────────────┐
                    │ api_gateway │ :5000
                    └──────┬──────┘
              gRPC          │
        ┌──────────────────┼──────────────────────┐
        ▼                  ▼                      ▼
┌──────────────┐  ┌──────────────────┐  ┌──────────────────┐
│ 业务服务       │  │ 支撑/通用服务      │  │ gRPC-only 服务    │
│ task_service  │  │ auth_service     │  │ audio_service    │
│  :5001/:50061 │  │  :5009/:51069   │  │  :50052          │
│ e2e_test_svc  │  │ algorithm_svc    │  │ device_service   │
│  :5002/:50051 │  │  :5007/:50067    │  │  :50053          │
│ api_test_svc  │  │ report_service   │  │                  │
│  :5003/:50071 │  │  :5006/:51068    │  │                  │
│ eval_svc      │  │                  │  │                  │
│  :5004/:50091 │  │                  │  │                  │
└───────────────┘  └──────────────────┘  └──────────────────┘
```

## 服务列表

端口统一注册在 [shared/config/service_ports.py](../shared/config/service_ports.py)，**禁止散落硬编码**。

| 服务 | HTTP 端口 | gRPC 端口 | 启动方式 | 说明 |
|---|---|---|---|---|---|
| **api_gateway** | 5000 | — | `uvicorn api_gateway.app:app` | 前端入口，REST API，Socket.IO/SSE 推送，认证鉴权 |
| **task_service** | 5001 | 50061 | `uvicorn task_service.app:app` | 任务调度引擎，创建/启动/停止/暂停任务，状态机，执行引擎 |
| **e2e_test_service** | 5002 | 50051 | `uvicorn e2e_test_service.app:app` | 端到端测试——设备驱动、音频播放编排、结果采集（纯执行器） |
| **api_test_service** | 5003 | 50071 | `uvicorn api_test_service.app:app` | API 接口测试——并发控制、会话执行 |
| **evaluation_service** | 5004 | 50091 | `uvicorn evaluation_service.app:app` | 评估服务——维度管理、指标计算（WER/DER/LLM Judge）、多轮聚合、重新评估 |
| **report_service** | 5006 | 51068 | `uvicorn report_service.app:app` | 报告生成（异步）与查询、对比分析 |
| **algorithm_service** | 5007 | 50067 | `uvicorn algorithm_service.app:app` | 算法配置管理（共享内核）、参考参数生成器 |
| **auth_service** | 5009 | 51069 | `uvicorn auth_service.app:app` | 认证 / OAuth / RBAC 角色权限 |
| **audio_service** | — | 50052 | `python -m audio_service.interfaces.grpc.server` | **gRPC-only**：音频播放、停止、状态查询 |
| **device_service** | — | 50053 | `python -m device_service.interfaces.grpc.server` | **gRPC-only**：播放/环境设备驱动、SPL 测量 |

> 注意：gRPC-only 服务（audio_service / device_service）无 HTTP 入口，不挂载 uvicorn，仅启动 gRPC server。

## 基础设施

| 组件 | 端口 | 用途 |
|---|---|---|
| PostgreSQL 16 | 5432 | 业务数据库（任务、用例、设备、结果、评估、报告、用户） |
| Redis 7 | 6379 | 服务注册/发现、日志 Pub/Sub、分布式协调、EventBus |
| MinIO | 9000/9001 | 对象存储（音频、结果、报告、归档）/ 控制台 |
| 前端 Vite | 5173 | Vue 3 dev server，Vite proxy → api_gateway :5000 |

## 服务间通信

所有跨服务调用走 gRPC，proto 定义在 [shared/proto/](../shared/proto/)（11 个 .proto）：

| 调用方 → 被调方 | gRPC Service | 主要 RPC 用途 |
|---|---|---|
| api_gateway → task_service | TaskDataService | 任务 CRUD、读取进度、提交用例结果等 |
| api_gateway → evaluation_service | EvaluationService | 维度 CRUD、读取评分结果 |
| api_gateway → audio_service | AudioConfigService | 音频 CRUD、上传/转换/预览 |
| api_gateway → device_service | DeviceConfigService/PlaybackConfigService/SPLConfigService | 设备/播放设备/SPL CRUD |
| api_gateway → algorithm_service | AlgorithmService | 算法配置 CRUD |
| api_gateway → auth_service | AuthService | 用户信息查询 |
| api_gateway → report_service | ReportService | 报告列表/详情查询 |
| task_service → e2e_test_service | ExecutionService | StartE2ETask / StopE2ETask |
| task_service → api_test_service | APITestService | CreateAPITest / StartAPITest |
| task_service → evaluation_service | EvaluationService | EvaluateCase / Reevaluate |
| task_service → audio_service | AudioService / PlaybackService | 音频播放编排 |
| task_service → device_service | DeviceService / DeviceResultService | 设备驱动创建/销毁、结果采集 |
| e2e_test_service → task_service | TaskDataService | SubmitResult / UpdateTaskCaseStatus |
| e2e_test_service → audio_service | AudioService / PlaybackService | 音频播放 |
| e2e_test_service → device_service | DeviceService / EnvDeviceService | 设备驱动、环境设备控制 |
| api_test_service → evaluation_service | EvaluationService | EvaluateCase |
| evaluation_service → task_service | TaskDataService | 读取 TestResult/TaskCase 数据 |
| evaluation_service → algorithm_service | AlgorithmService | SyncDimensionRelations / GetRelationsByDimension |
| evaluation_service → device_service | DeviceResultService | ReextractResult（重新提取设备结果） |

gRPC 客户端工厂：[shared/clients/grpc_clients.py](../shared/clients/grpc_clients.py)，`lru_cache` 复用 channel。出站调用的业务语义封装在各服务 `infrastructure/acl/` 下的 ACL 仓储中。

## 服务内部架构（DDD 四层）

每服务统一按 `interfaces → application → domain → infrastructure` 四层组织：

```
task_service/
├── domain/               # 纯领域逻辑
│   ├── entities/         # TaskAggregate, TaskCaseEntity (pure @dataclass)
│   ├── value_objects/    # TaskConfig, AlgorithmParams
│   ├── events/           # TaskStarted, TaskCompleted
│   └── services/         # 领域服务（纯逻辑，无 DB/HTTP 依赖）
├── application/          # 用例编排（CQRS）
│   ├── commands/         # CreateTask, StartTask...
│   ├── queries/          # GetTask, GetTaskProgress...
│   └── handlers/         # Command/Query Handler
├── infrastructure/       # 技术实现
│   ├── persistence/      # PO 模型 + Repository 实现
│   │   └── models/       # task_models, testcase_models 等 PO
│   ├── acl/              # ACL 仓储（调其他服务 gRPC，返回 DTO）
│   └── oss/              # OSS 存储
└── interfaces/           # 入站适配器
    ├── grpc/             # gRPC servicer + server
    └── api/              # HTTP 路由（如有）
```

## 服务注册与发现

[shared/utils/service_registry.py](../shared/utils/service_registry.py)

- 启动时注册到 Redis Hash `service:info:{service_name}:{instance_id}`
- 心跳 15s TTL，超时自动剔除
- 调用方从 Redis 获取可用实例列表

## 配置管理

所有配置通过环境变量，参考 [.env.example](../.env.example)。关键配置项：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DATABASE_URL` | — | PostgreSQL 连接串（必填） |
| `REDIS_URL` | redis://localhost:6379 | Redis 连接串 |
| `OSS_ENDPOINT` | http://localhost:9000 | RustFS (S3 兼容) 地址 |
| `OSS_ACCESS_KEY` / `OSS_SECRET_KEY` | intelligent_audio_test / intelligent_audio_test666 | RustFS 凭据 |
| `PORT` | 服务各自默认 | HTTP 端口 |
| `GRPC_PORT` | 服务各自默认 | gRPC 端口 |
| `AUTH_MODE` | off | 认证模式：off/dev/prod |
| `DISTRIBUTED_COORDINATOR_ENABLED` | true | 分布式协调器开关，Redis 不可达自动降级 |
| `SERVICE_HOST` | localhost | 本服务主机名（服务发现用） |
| `TASK_SERVICE_HOST` | localhost | 其他服务地址（跨服务 gRPC 用） |

## Docker 部署

```bash
cd Intelligent-Audio-TEST/docker
docker compose up -d
```

docker-compose.yml 包含：**9 个容器化后端服务** + postgres + redis + rustfs，全部纳入编排且均带 healthcheck（postgres/redis/rustfs 为健康依赖，应用服务启动后经 /health 或 gRPC 探活）。audio_service / device_service 依赖宿主声卡与 USB/ADB，按宿主形态运行、不进 compose。每个容器化服务独立 Dockerfile：

```
docker/
├── Dockerfile.api_gateway
├── Dockerfile.api_test_service
├── Dockerfile.e2e_test_service
├── Dockerfile.task_service
├── Dockerfile.evaluation_service
├── Dockerfile.report_service
├── Dockerfile.algorithm_service
├── Dockerfile.auth_service
├── Dockerfile.frontend
└── docker-compose.yml
```

构建上下文为项目根（`Intelligent-Audio-TEST/`，即 docker/ 的上一级），`.dockerignore` 位于项目根。`docker compose up -d --wait` 会阻塞至全部服务 healthcheck 通过；AUTH_MODE / JWT_SECRET / OSS 凭据等可用环境变量或 docker/.env 覆盖（见 [.env.example](../.env.example)）。api_adapter_service 独立适配服务及其 `Dockerfile.api_adapter_service` 已随 INT-1176 删除。

多实例通过 `deploy.replicas` / `--scale` 控制。api_test_service 默认 2 副本且不发布宿主端口（服务间经容器网络互访，会话亲和路由按注册表中各副本自解析地址精确寻址，INT-69）；如需宿主机直连调试，在 compose.override.yml 中对单副本追加 `ports` 映射。

## 一键启动（本地开发）

[stack.py](../stack.py) 是全栈唯一启停入口：Docker compose 起 9 个容器化后端 + 3 个基础设施，
再拉起宿主机 audio_service / device_service（依赖本机声卡与 ADB，不能进容器）：

```bash
python stack.py up          # compose 栈 + 宿主 audio/device
python stack.py status      # 容器 + 宿主服务状态
python stack.py health      # HTTP /health + gRPC/基础设施 TCP
python stack.py down        # 优雅停宿主服务 → compose down
```

启动流程：
1. `docker/run_stack.py up`（分离模式，容器归 Docker daemon）
2. 按 compose 解析出的宿主端口注入环境，启动宿主 device_service(:50053)
3. pyaudio 自检通过后启动宿主 audio_service(:50052)

端口口径由 `docker compose config` 解析，不在脚本里手抄；宿主服务环境见
`scripts/host_services/control.py`。
