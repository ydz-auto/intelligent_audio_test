# 系统架构文档

## 概览

智能语音测试平台，用于对语音识别（ASR）、语音翻译、说话人识别、TTS 等 AI 算法进行端到端和 API 自动化测试、评估与报告生成。

系统采用微服务架构，5 个业务服务 + 3 个基础设施组件，通过 gRPC 通信，Redis 做服务注册/发现与分布式协调。

```
前端 (Vue3 + Electron)
    │  HTTP (axios) + WebSocket (Socket.IO) + SSE
    ▼
┌─────────────────────────────────────────────────────┐
│                  api_gateway (:5000)                 │
│              FastAPI + Socket.IO + SSE               │
└──────────────────────┬──────────────────────────────┘
                       │ gRPC
        ┌──────────────┼──────────────┐
        ▼              ▼               ▼
┌──────────────┐ ┌──────────┐ ┌──────────────┐
│ task_service │ │  e2e_svc  │ │api_test_svc │
│  :5001      │ │  :5002   │ │   :5003      │
│  :50061 grpc│ │ :50051   │ │  :50071 grpc │
└──────┬───────┘ └──────────┘ └──────┬───────┘
       │ gRPC                    gRPC │
       │                              ▼
       │                     ┌──────────────┐
       │                     │adapter_svc   │
       │                     │  :8000       │
       │                     └──────────────┘
       ▼
┌─────────────────────────────────────────────────────┐
│  PostgreSQL :5432  │  Redis :6379  │  MinIO :9000  │
└─────────────────────────────────────────────────────┘
```

## 技术栈

| 维度 | 选型 |
|---|---|
| 后端框架 | FastAPI + uvicorn（5 个服务统一） |
| 跨服务通信 | gRPC + protobuf（grpcio） |
| ORM | SQLAlchemy（declarative_base + scoped_session） |
| 数据库 | PostgreSQL 15 |
| 缓存/消息 | Redis 7（服务注册、PubSub 日志广播、分布式协调） |
| 对象存储 | MinIO/S3 兼容 OSS |
| 实时通信 | Socket.IO（日志/进度推送）+ SSE 事件流 |
| 前端 | Vue 3 + TypeScript + Vite + Pinia + Electron |
| 部署 | Docker Compose（每服务独立 Dockerfile） |

## 服务详解

### 1. api_gateway — API 网关

| 项 | 值 |
|---|---|
| HTTP | :5000 |
| gRPC | — |
| 职责 | 前端入口，REST API，转发请求到后端服务，WebSocket/SSE 推送 |

内部采用 DDD 分层：
- `controllers/` — ~20 个控制器（task/audio/device/report/execution 等）
- `routes/` — ~16 个蓝图路由
- `domain/` — 领域实体、事件、值对象
- `application/` — 命令/查询分离（CQRS）
- `websocket/` — Socket.IO 服务端，实时日志/进度
- `infrastructure/` — OSS 客户端、持久化、读模型

### 2. task_service — 任务调度引擎

| 项 | 值 |
|---|---|
| HTTP | :5001 |
| gRPC | :50061 |
| 职责 | 任务创建/启动/停止/暂停/恢复，用例分发，评估计算，报告生成 |

核心组件：
- `core/execution_engine.py` — **执行引擎**（单例），任务调度主循环
- `evaluation/` — 评估模块（多轮聚合、维度评分、结果计算）
- `grpc/` — gRPC 服务端，暴露 ExecutionService

### 3. e2e_test_service — 端到端测试服务

| 项 | 值 |
|---|---|
| HTTP | :5002 |
| gRPC | :50051 |
| 职责 | 设备驱动、音频播放、声压级测量、结果采集 |

核心组件：
- `drivers/` — 多设备驱动（Android/HarmonyOS/Doubao ASR/Plaud 等）+ 工厂模式
- `audio/` — 音频引擎、播放编排器、SPL 服务
- `device/` — 结果采集、时间戳对齐、RTTM/STM 处理
- `env_device/` — 环境设备控制（导轨等）

### 4. api_test_service — API 接口测试服务

| 项 | 值 |
|---|---|
| HTTP | :5003 |
| gRPC | :50071 |
| 职责 | API 测试执行、并发控制、结果上报 |

核心组件：
- `core/api_executor.py` — API 测试执行器
- `core/api_concurrency_manager.py` — 并发控制（进程内信号量 + Redis 分布式信号量）
- `core/api_task_runner.py` — 任务运行器
- `clients/` — API 客户端/驱动

### 5. api_adapter_service — 语音 LLM 适配层

| 项 | 值 |
|---|---|
| HTTP | :8000 |
| gRPC | — |
| 职责 | 多轮对话适配，对接火山 AST/通义千问/Mock 等语音 LLM |

核心组件：
- `adapters/` — 多适配器（http/sse/qwen/volc_ast/mock）+ 工厂模式
- `services/session_store.py` — 会话管理
- `services/task_manager.py` — 对话任务管理
- `proto/` — 火山 AST proto 定义

## 服务间通信

所有跨服务调用走 gRPC，proto 定义在 [shared/proto/](../shared/proto/)：

| 调用方 → 被调方 | Service | 主要 RPC |
|---|---|---|
| api_gateway → task_service | ExecutionService | StartTask / StopTask / PauseTask / ResumeTask / GetTaskStatus |
| task_service → e2e_test_service | AudioService | PlayAudio / StopAudio / GetAudioInfo |
| | DeviceService | CreateDriver / DestroyDriver / RegisterTaskEvents |
| | PlaybackService | StartPlayback / StopPlayback |
| | DeviceResultService | CollectResult / ReextractResult |
| | EnvDeviceService | ControlEnvDevice |
| | ExecutionService | StartE2ETask / StopE2ETask / GetE2ETaskStatus |
| task_service → api_test_service | APITestService | CreateAPITest / StartAPITest / StopAPITest |
| api_test_service → api_adapter_service | AdapterService | SendRound / Health |

gRPC 客户端工厂：[shared/clients/grpc_clients.py](../shared/clients/grpc_clients.py)，`lru_cache` 复用 channel。

## 任务执行流程

[task_service/core/execution_engine.py](../task_service/core/execution_engine.py) 的 `_run_task` 主流程：

```
1. 初始化
   ├── 更新任务状态 → running
   └── 发送进度更新

2. 主循环（while not stop_event）
   ├── 取下一个 pending 用例
   ├── 检查暂停/停止信号（Redis 标志位 + 本进程 Event）
   ├── E2E：检查设备在线状态
   └── 分发执行
       ├── API 任务 → CAS 占用用例(pending→queued) → gRPC 调用 api_test_service.CreateAPITest
       └── E2E 任务 → gRPC 调用 e2e_test_service.StartE2ETask

3. 等待循环
   ├── 等待所有用例执行+评估完成
   ├── 事件驱动等待（task_completion_events）
   └── 超时保护（300s）

4. 最终状态更新
   ├── failed_cases > 0 → failed，否则 completed
   ├── 原子更新统计（SQL 子查询 UPDATE）
   └── 检查队列启动下一个任务
```

### 任务状态机

```
pending → queued → running → evaluating → completed
                  │         │            ├── failed
                  │         └── reevaluate_queued → reevaluating → completed
                  ├── paused → running
                  └── stopped
```

### 用例执行状态

```
execution_status: pending → queued → running → completed / failed / stopped
evaluation_status: queued → pending → running → calculating → completed / failed / stopped
```

## 数据模型

数据模型定义在 [shared/models/models.py](../shared/models/models.py)，约 30 个表。

### 核心表

| 表 | 说明 | 关键字段 |
|---|---|---|
| `test_tasks` | 测试任务 | id, name, type(api/e2e), status, config(JSON), total_cases, completed_cases, failed_cases |
| `test_cases` | 测试用例 | id, name, config(JSON: rounds/dimensions), algorithm_params(JSON), test_type(api/e2e) |
| `task_case_relations` | 任务-用例关联 | task_id, test_case_id, execution_status, evaluation_status, duration |
| `test_results` | 测试结果 | task_id, test_case_id, device_id, api_id, algorithm_result(JSON), result_data_path |
| `test_result_dimensions` | 结果维度得分 | test_result_id, dimension_id, round_number, score, status |
| `devices` | 被测设备 | name, model, system, serial_number, status, supported_algorithms(JSON) |
| `apis` | API 配置 | name, vendor, api_url, max_process, api_endpoints(JSON) |
| `audios` | 音频文件 | name, duration, audio_type(dry/noise/prompt), asr_text |

### ER 关系（简）

```
test_tasks ──< task_case_relations >── test_cases
    │                                        │
    └──< test_results >── test_result_dimensions >── dimensions
                │
                ├── devices (e2e)
                └── apis (api)
```

## 服务注册与发现

[shared/utils/service_registry.py](../shared/utils/service_registry.py)

- 启动时注册到 Redis Hash `service:info:{service_name}:{instance_id}`
- 加入 Redis Set `service:set:{service_name}`
- 心跳 15s TTL，超时自动剔除
- 调用方从 Redis 获取可用实例列表

## 分布式协调

[shared/utils/distributed_coordinator.py](../shared/utils/distributed_coordinator.py)

多实例部署时启用（`DISTRIBUTED_COORDINATOR_ENABLED=true`）：

| 机制 | 用途 |
|---|---|
| DistributedLock | 任务级互斥锁（SET NX EX + Lua 释放） |
| DistributedSemaphore | API 全局并发限制（Lua 原子 INCR/DECR） |
| 控制标志位 | 跨实例 stop/pause 信号传播 |
| try_claim_task | 任务抢占去重 |

详见 [分布式协调器文档](./distributed-coordinator.md)。

## 多实例部署

同一服务起多个实例，用不同端口，开启分布式协调：

```powershell
# task_service 实例 A
$env:PORT="5001"; $env:GRPC_PORT="50061"; $env:DISTRIBUTED_COORDINATOR_ENABLED="true"
python -m uvicorn task_service.app:app --port 5001

# task_service 实例 B
$env:PORT="50011"; $env:GRPC_PORT="500611"
python -m uvicorn task_service.app:app --port 50011
```

Docker 多实例通过 `deploy.replicas` 控制，详见 [微服务文档](./microservices.md)。
