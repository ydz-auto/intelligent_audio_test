# 系统架构文档

## 概览

智能语音测试平台，用于对语音识别（ASR）、语音翻译、说话人识别、TTS 等 AI 算法进行端到端和 API 自动化测试、评估与报告生成。

系统采用 **DDD + CQRS + 消息驱动** 微服务架构：**11 个后端微服务** + 3 个基础设施组件，通过 gRPC 通信，Redis 做服务注册/发现与分布式协调。每个微服务按 `interfaces → application → domain → infrastructure` 四层分层。

```
前端 (Vue3 + TypeScript + Vite + Electron)
    │  HTTP (axios) + Socket.IO + SSE（Vite proxy → :5000）
    ▼
┌─────────────────────────────────────────────────────┐
│                  api_gateway (:5000)                 │
│      FastAPI + AuthMiddleware + Socket.IO + SSE      │
└──────────────────────┬──────────────────────────────┘
                       │ gRPC
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
┌──────────────┐ ┌────────────┐ ┌──────────────┐
│  业务服务      │ │ 支撑服务     │ │ gRPC-only    │
│ task_service │ │ auth_svc   │ │ audio_svc    │
│  :5001/:50061│ │ :5009/:69  │ │  :50052      │
│ e2e_svc      │ │ algorithm  │ │ device_svc   │
│  :5002/:50051│ │ :5007/:67  │ │  :50053      │
│ api_test_svc │ │ report_svc │ │              │
│  :5003/:50071│ │ :5006/:68  │ │              │
│ eval_svc     │ │ adapter_svc│ │              │
│  :5004/:50091│ │ :5008/:81  │ │              │
└──────┬───────┘ └────────────┘ └──────────────┘
       │ gRPC（跨服务调用，共享 kernel）
       ▼
┌─────────────────────────────────────────────────────┐
│  PostgreSQL :5432  │  Redis :6379  │  MinIO :9000  │
└─────────────────────────────────────────────────────┘
```

## 技术栈

| 维度 | 选型 |
|---|---|
| 后端框架 | FastAPI + uvicorn（11 个服务统一） |
| 跨服务通信 | gRPC + protobuf（grpcio），proto 定义在 `shared/proto/` |
| ORM | SQLAlchemy 2.0（declarative_base + scoped_session） |
| 数据库 | PostgreSQL 16 |
| 缓存/消息 | Redis 7（服务注册、PubSub 日志广播、分布式协调） |
| 对象存储 | MinIO/S3 兼容 OSS（单桶模式 + 前端分片直传） |
| 实时通信 | Socket.IO（日志/进度推送）+ SSE 事件流 |
| 认证 | OAuth2 + JWT（HS256）+ RBAC |
| 前端 | Vue 3.4 + TypeScript 5.9 + Vite 5 + Pinia + Electron 31 |
| 部署 | Docker Compose（每服务独立 Dockerfile）+ run_all.py 一键启动 |

## 任务执行流程

[task_service/core/execution_engine.py](../task_service/core/execution_engine.py) 主流程：

```
1. 初始化
   ├── 更新任务状态 → running
   └── 发送进度更新

2. 主循环（while not stop_event）
   ├── 取下一个 pending 用例
   ├── 检查暂停/停止信号（Redis 标志位 + 本进程 Event）
   ├── E2E：检查设备在线状态
   └── 分发执行
       ├── API 任务 → CAS 占用用例(pending→queued) → gRPC 调用 api_test_service.CreateAPITest
       └── E2E 任务 → gRPC 调用 e2e_test_service.StartE2ETask

3. 等待循环
   ├── 等待所有用例执行+评估完成（事件驱动 task_completion_events）
   └── 超时保护

4. 最终状态更新
   ├── failed_cases > 0 → failed，否则 completed
   ├── 原子更新统计（SQL 子查询 UPDATE）
   └── 检查队列启动下一个任务
```

### 任务状态机

```
pending → queued → running → evaluating → completed
                  │         │            ├── failed
                  │         └── reevaluate_queued → reevaluating → completed
                  ├── paused → running
                  └── stopped
```

### 用例执行状态

```
execution_status: pending → queued → running → completed / failed / stopped
evaluation_status: queued → pending → running → calculating → completed / failed / stopped
```

## 认证与鉴权

- `AuthMiddleware`（[api_gateway/middleware.py](../api_gateway/middleware.py)）解析 JWT → 注入 `request.state.user_id / role_id / permissions`
- 认证模式 `AUTH_MODE`：`off`（默认，跳过鉴权）/ `dev`（本地 OAuth + JWT）/ `prod`（华为云 OAuth）
- 认证实现位于 [api_gateway/application/services/auth/](../api_gateway/application/services/auth/)（auth_service + huawei_oauth + local_oauth + token_service）
- 认证路由 [api_gateway/routes/auth_bp.py](../api_gateway/routes/auth_bp.py)：login / callback / refresh / logout / me
- auth_service 微服务提供 DDD 四层 + gRPC（ValidateToken / GetUserPermissions 骨架）
- 详见 [oauth.md](./oauth.md) 与 [RBAC权限划分.md](./RBAC权限划分.md)

## 微服务内部 DDD 分层约定

每个微服务统一按四层组织：

```
task_service/
  domain/               # 纯领域逻辑（dataclass 聚合根/值对象/事件/领域服务）
  application/          # 用例编排（commands/queries/handlers，CQRS）
  infrastructure/       # 技术实现（persistence/models PO + repository + acl 出站适配）
  interfaces/           # 入站适配器（grpc servicer + server、api 路由）
```

强制规则（详见 [DDD重构.md](./DDD重构.md)）：
1. `interfaces/` 层零 DB 访问
2. `domain/` 层零基础设施依赖（不 import db/PO/shared.utils.log_handler）
3. repository 实现必须继承 `domain/repositories/` 的 ABC
4. application 层面向 ABC 编程（默认实例用 infrastructure 模块级单例）
5. Command/Query handler 分离
6. repository 返回 dict/Entity，绝不返回 ORM 对象
7. 跨服务数据访问必须经 `infrastructure/acl/` ACL 仓储调 gRPC，禁止 import 他服务 PO
