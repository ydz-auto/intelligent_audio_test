### 3.4 全局算法切换器（本卡主案，负责人口径落地）

**定位**：登录壳右上角功能区**首位**（§3.1）；公共站头**不出现**（00 总表 §3.5 拍板）；设置工作区算法列表分区**不联动**（该分区展示全部算法并承担 CRUD 本体，切换器只读引用在线算法数据源）。

**数据源（实测）**：`GET /algorithm/options`（门槛 `algorithm:read`，`algorithm_bp.py:165-167`）→ gRPC `GetAlgorithmOptions`（servicers.py:325-341）→ **仅在线算法**（`ListAlgorithmDefinitionsQuery(status='online')`），响应经 `algorithmApi.getOptions` 平移（DTO `AlgorithmOptionDto`：`value/name/group_id?/group_name?/icon?`，`algorithmDto.ts:141-146`）。选项按 `group_name` 聚合分组（缺失归「未分组」），组内按返回序。与测试执行步骤0「可选算法」同源（INT-355 §3.3）。

**触发钮（照 model-group-selector.tsx ModelTriggerButton 实测形态）**：

- `Button variant='outline' role='combobox' size='sm'`：`flex h-8 items-center gap-2 border px-3 font-medium bg-background text-foreground hover:bg-accent transition-colors focus:!ring-0 shadow-none`；内容 = Box 图标（`size-4 text-muted-foreground`）+ 当前算法名（`text-xs truncate`，未选显「全部算法」）+ ChevronsUpDown（`h-4 w-4 opacity-50`）。
- 移动端图标态：`w-8 justify-center p-0 sm:w-auto sm:justify-start sm:px-3`，图标 `block sm:hidden`、文字 `hidden sm:block`（实测断点手法）。
- aria：`aria-expanded` / `aria-haspopup='listbox'`；无 `algorithm:read` 权限**整钮不渲染**（隐藏而非置灰——admin/tester/algo_engineer 显，device_admin/guest 隐，§5）。

**下拉面板（Popover + Command 组合框，照 model-group-selector 实测结构）**：

```

└─ Command
   ├─ CommandInput placeholder「搜索算法…」
   ├─ CommandList（max-h-80 滚动）
   │  ├─ CommandGroup heading「默认」→ CommandItem「全部算法」（Layers 图标；value=null）
   │  ├─ CommandGroup heading={group_name}…（逐组）
   │  │  └─ CommandItem：算法名（text-sm truncate）+ 状态徽章（Badge outline「在线」——options 全在线，仅占位统一）+ 选中 Check（ms-auto size-4）
   │  └─ CommandEmpty「未找到匹配算法」
   └─ （页脚提示行：text-xs text-muted-foreground px-3 py-2「切换后全局生效：任务、用例、设备、报告、日志列表将按此算法过滤」）
```

**行为契约（store 本体，INT-355 §3.3 消费方对齐）**：

1. **Zustand store** `useGlobalAlgorithmStore`：`{ algorithmType: string | null; setAlgorithm(type: string): void; clear(): void }`；持久化 localStorage key **`iatp:algorithm:v1`**（INT-355 §6 表既定 key，本卡落读写件）。
2. 选中项 → `setAlgorithm(value)` → 关面板 → toast「已切换全局算法为 {名称}」→ 全局生效：各业务列表请求自动附 `algorithm_type`（消费点 INT-354 任务/INT-356 用例/INT-361 音频·设备/INT-360 报告/INT-362 日志——后端各 query service `algorithm_type` 参数实测在册）；「全部算法」→ `clear()` → toast「已恢复全部算法」。
3. **列表联动指引**（统一给各消费页，不新增机制）：受影响列表 queryKey 携带 `algorithmType` 段，store 变更即自动重查（TanStack Query 天然联动，无需手写失效）。
4. **双向同步**：测试执行两页步骤0 选择即写回同一 store（INT-355 §3.3）——导航栏钮文案实时反映 store 值（订阅选择器）。
5. **持久化恢复**：启动 rehydrate；持久化值不在当前 options 中（算法被删/下线）→ **静默回落 `null`（全部算法）**，不发 toast（下线算法不可作为过滤值，options 实测仅在线）。
6. **登出清空**：随登出流程清除（同 newAPI `clearAuthenticatedClientState` 语义，多账号切换不串值）。
7. 键盘：无自定义快捷键（不发明）；面板内 cmdk 自带 ↑↓/Enter/Esc。
