**核心层级关系（拍板）**：

```
任务（report.task_name / algorithm_type）
 └─ 资源（summary.resources / resource_headers —— 设备 device_stats + API api_stats 双维度）
     └─ 结果（每资源下多个结果：轮次级[多轮对话 rounds] / 多结果级[results 数组] / 原始值集合 raw_data）
         └─ 评估维度（all_metrics 主维度 main + 子维度 sub，parent_dimension_name 归组）
             └─ 维度值（metric_data 均值 / tag_metric_data / case_type_stats / raw_data 原始值集合）
用例（case：带分组 category + 标签 tags，标签带分类 tag.category_id/category_name）
 └─ 多资源 × 多结果 × 多维度 × 多值（case.metrics / case.results / case.algorithm_results / case.reference_params / case.audios）
```

- **维度×资源矩阵表**（DataTable 对位，主/子维度层级分组）：

### 3.5 用例级报告卡片（TestCaseReportDetail 对位——七块复杂结构）

#### 3.5.1 块一：评分指标（主/子维度层级分组表格，单表 + 多轮横向 Tab 对比双模式）

- **单设备模式**（`isComparison=false`）：DataTable 四列——指标名称 / 指标数值 / 得分 / 详情·错误；得分徽章五档语义色（`score-5` success 绿 / `score-3,4` warning 橙 / `score-1,2` destructive 红 / `score-0` 灰，实测 `score-badge`）；**维度行可折叠长文本错误信息**（`collapsible-text`，>50 字显「展开/收起」）。
- **对比模式**（`isComparison=true`，多设备/多 API 同时执行）：**轮次横向 Tab 栏**（`round-tab-bar`，实测）——`roundTabs` 从指标 key `@round:N`/`@overall` 与结果/参考/用例参数字段的 `paramCode@round:N`/`round_number` 提取，「第N轮」+「整体」；自动选中第一个有评估数据的 Tab，无评估数据的「整体」Tab 不显示；**主维度/子维度层级分组表格**（`currentRoundTableData` 实测）——列=指标名称 + 每设备一列，行=分组标题行（`isGroupHeader` 加粗，仅组内有子维度且主维度名≠组名时插）+ 主维度行 + 子维度行（`isSubDim` 缩进），子维度按 `parent_dimension_name` 归入父维度组，组与子维度按中文名排序；指标 key 显示友好化 `(第N轮)/(整体)`；数值按 `metricConfigs[].decimalPlaces`（默认 2）精度显示。
- 空态：「暂无指标数据」。

#### 3.5.2 块二：多轮对话结果（轮次数 / 每轮展开 / 聚合卡）

- 判定：`algorithmResults` 中首个含 `rounds` 数组的对象（`parseMultiRoundResult` 实测，兼容 `round` 0 基 / `roundNumber` 1 基）；标题「多轮对话结果 ({totalRounds} 轮)」。
- **聚合卡**（`multi-round-aggregated` 实测）：平均 WER / 平均 LLM 评分 / 平均延迟（s）/ 打断次数——优先后端 `aggregated`（snake_case `avg_wer/avg_llm_judge/avg_latency/interruption_count`），兜底前端由各轮 `evaluation.wer/llm_judge`、`latency`、`interruption.detected` 计算。
- **每轮展开列表**（`round-item` 实测）：头=「第 N 轮」+ 延迟 + 打断徽标（`interruption.detected` → 红底「打断」）+ 展开箭头；展开详情字段=**输入音频**（`round.input.audio_name`）/ **ASR 输出**（`round.output.asr_text`）/ **参考文本**（`getReferenceTextForRound` 取参考文本字段）/ **延迟**（s）/ **打断**（时间戳 s 或「检测到打断」）/ **维度评分**（`roundEvalData` 徽章组，label 映射：平均 WER/平均延迟/平均 LLM 评分/打断次数/WER/LLM 评分/延迟）/ **LLM 评语**（`extractLlmReasoning` 取 evaluation.reasoning 或 raw_response 解析）。

### 3.6 分组/标签/分类对比 + 正态分布统计图（负责人新加标签分类）

> 覆盖要求：CaseTagComparison（按用例标签对比）+ CaseCategoryComparison（按用例分类对比）+ **正态分布统计图**（displayType='distribution'，前端用原始值集合自行计算分布）。机制已在 §3.3.5/§3.3.6 落位，本节约束共性：

- **显示类型切换器**（`useDisplayTypes` 实测，两对比组件共用）：`表格 / 柱状图 / 折线图 / 雷达图 / 正态分布图`（默认表格）；每个评估维度一个 `.metric-container`（标题「{metric.name} 对比（单位：{metric.unit}）」+ 类型切换器 + 折叠）。
- **正态分布图数据装配**（`generateDistributionChartData` 实测，shared/useReportShared.ts:232）：
  - 原始值来源：矩阵中每 `(分组|标签, 设备)` 的 `{metric}_raw` 数组（后端 `raw_data` 直传，或前端从 `dimensionScores`/`metrics` 每次得分累积）——`deviceRawDataMap[device]` 收集 + `allRawData` 汇总，过滤非数字，`seenArrays` 去重同数组引用。
  - 计算：`calculateNormalDistribution` → `mean=Σ/n`、`variance=Σ(x-mean)²/n`、`stdDev=√variance`；`step=stdDev/8`、`min=mean-32*step`（无负数则 0）、`max=mean+32*step`、`intervals=round((max-min)/step)`；每设备区间直方图 `{x: 区间中点, y: count}`（末区间含右端点），`_step` 存步长。
  - 返回 `{labels, datasets, rawData, deviceRawData(按资源 label 键)}` → 交给 ChartComponent（§3.7）。
- **统计卡**（ChartStatsCard 对位，§3.7）：样本数量 / 平均值 (μ) / 标准差 (σ) / 最小值 / 下四分位数 (Q1) / 中位数 (Q2) / 上四分位数 (Q3) / 最大值 + **正方向区间**（`[0,μ) / (μ,μ+σ] / (μ+σ,μ+2σ] / (μ+2σ,μ+3σ] / 超出+(μ+3σ)` 百分比）+ **负方向区间**（有负值时：`[-μ,0) / [-(μ+σ),-μ) / … / 超出-(μ+3σ)` 百分比）；设备 Tab 按 `distributionStatsByDevice` 切换。
- **编辑持久化**（两对比组件实测）：表头/单元格点击重命名（分组名/标签名/资源 label）→ 同步 `summary.caseCategories` / `summary.allCaseTags` / `summary.resourceHeaders` → `scheduleSaveSummary` 200ms 防抖 → `PUT /reports/{id}`。
- **标签分类**（负责人新加）：`all_case_tags` 项含 `category_id/category_name`（schema `ReportTagMetricTagGroup:34` / `ReportTagCategoryMetric:47` 实测）——标签筛选器按分类分组展示（分类组头 + 组内标签），标签对比矩阵行仍按单标签独立均值；分类维度同时由 `case_categories`（分组）对比承载。

### 3.7 图表（ChartComponent 全类型）

> **引擎裁定**：按 INT-439 口径改用现前端同款 **Chart.js v4 + chartjs-plugin-zoom**（`frontend/src/chart/` 实测；INT-360 的 VChart 在本域废止——分布图依赖 zoom/pan 重分箱 + 统计卡，VChart 无法等价）。深浅色/多主题走语义 token（`--chart-1..5` 随预设联动，chart.js 用等价 hex 常量 `chartConfig.colors`，与 `tokens.css` 保持映射）。

- **ChartComponent props**（实测）：`title / data(labels+datasets) / type(bar|line|pie|doughnut|radar|polarArea|distribution|scatter|heatmap) / options / showHeader / showFooter / showActions / loading / stats / height(默认500) / enableZoom(默认true)`；emits `chartReady / export`。
- **图表类型**（全类型支持）：
  - `bar` 条形/对比柱：`getChartData` 分组/标签×资源柱状，`backgroundColor` chart 色 + alpha `'B3'`、`borderRadius:4`。
  - `line` 折线：`tension:0.3`、`fill:false`，通过率/指标趋势。
  - `distribution` 正态分布图：标题「正态分布分析」、x 轴「不同区间的{title}」（linear）、y 轴「区间内用例数量」（stepSize:1）、tooltip 显 `[start, end)` 区间 +「N 个」；**折线图/直方图切换**（`chartSubType`，distribution 模式以子类型渲染）；**zoom/pan 后重分箱**（`rebinDistributionData`：固定 20 区间按可见范围重计 → 更新 datasets + 固定 x min/max）；**resetZoom 恢复原始数据**。
  - `radar` 雷达（多资源 series，值归一化百分比）/ `pie` / `doughnut` / `polarArea`（图例右置、无缩放）。
  - `scatter` 散点图：**两个变量关系**（如 指标值×执行时长、通过率×延迟），`showLine:false` 点图 + tooltip 双变量；`heatmap` 热力图：**密度分布**（如 设备×评估维度 值矩阵、时间×任务类型 分布），canvas 网格 + 色阶 `--chart-1..5` alpha 分级（报告管理功能设计文档.md:346-351 实测）。

- **ChartActions 对位**：重置缩放 / **图表导出 图片·SVG·PDF**（报告管理功能设计文档.md:359-362 实测）——PNG 走 `toBase64Image` → `{title}.png` 下载 + emit `export`；SVG/PDF 走序列化/打印导出（实施卡按 chart.js v4 生态确认插件选型）。
- **缩放交互**：wheel/drag/pinch 缩放（mode 随鼠标位置 x/xy 切换）+ pan，`enableZoom=false` 时禁用。
- **空态**：「暂无数据」；**加载**：「图表加载中...」；数据源：分组/标签对比矩阵（§3.3.5/3.3.6）与任务级统计（device_stats.success_rate 折线、metric_data 柱状/雷达）。

## 10. 待负责人确认 / 现状缺陷（建议后端或实施卡立项）

> 全部为本卡逐端点/逐文件实测发现的真实缺口，设计稿按「不虚构、不隐藏问题」标注。

1. **report 三端点无路由级权限装饰器**：`report_bp.py` 的 `secondary_compare`（:87）、`search_report_cases`（:117）、`download_case_logs`（:122）未挂 `require_permission`——与 seed 的 `report:compare/report:read/report:download_log` 语义不对齐；RBAC 矩阵按权限码出，建议后端补装饰器。
2. **导出 format 服务端能力**：`POST /reports/export` 支持 csv/excel/pdf/html（schema 实测），实施卡确认各 format 响应（pdf 可用性、csv 批量语义）。
3. **`summary.tables` 烘焙缺口**：任务级对比表格数组（§3.3.4）由 `report.summary.tables` 驱动（V9.7.31 ReportView `report.value?.summary?.tables || []` 实测）；若后端报告生成未烘焙该字段，前端需从 `metric_data/device_stats/api_stats` 装配兜底对比表——实施卡确认。
4. **AI 增强搁置**：`test_reports` 无 `ai_summary/ai_anomalies/ai_trend` 字段，`POST /reports/{id}/qa` 无实现——分析结论按纯文本编辑设计，AI 摘要/异常面板/趋势预测不引入（INT-360 §10-3 口径保留）。
5. **报告列表全局算法联动**：现状前端为独立算法筛选，本卡按 INT-344 收敛为联动 chip（§2），`ReportListQuery.algorithm_type` 已支持。
6. **正态分布图原始值依赖 `raw_data`**：分布图均值/标准差由前端从矩阵 `_raw` 原始值集合计算（§3.6），依赖后端 `raw_data` 输出 `values[]`（flatten_raw_data 实测已支持）；无 `_raw` 的历史报告分布图退化空态「暂无数据」，实施卡标注。
7. **分组/标签重命名持久化字段**：`scheduleSaveSummary` 写 `PUT /reports/{id}` 的 `summary.caseCategories/allCaseTags/allTags/resourceHeaders`（schema `ReportUpdateSummaryField` 实测在册），编辑冲突（多人并发）由实施卡确认覆盖语义。
8. **图表引擎迁移裁定**：INT-360 定 VChart 与现前端 Chart.js 冲突；本卡按 INT-439 口径改 Chart.js v4 + zoom（分布图 zoom/pan 重分箱 + ChartStatsCard 统计卡 VChart 无法等价）——**本卡裁定覆盖 INT-360 §4.5/§10-9**，实施卡按 Chart.js 出。
9. **日志文件列表端点缺（INT-1055）**：`GET /reports/{id}/cases/{caseId}/logs/download` 现为整包 logs.zip（无文件列表/多选/单文件大小）。文件选择 Dialog（§4.10a）需日志文件列表端点——**契约建议**：`GET /reports/{report_id}/cases/{case_id}/logs` → `{ items: [{ name, size, updated_at? }] }`；下载端点扩展 `?files=[name...]`（缺省全部）打包 zip。开【FEAT】卡挂主项目；落地前前端留桩示例列表（文件名/大小），实施卡等 FEAT done 再接线。Vue 侧同步（19 §9）。
