### 2.2 全局算法切换器口径（负责人 2026-10-14）

- 报告中心 `/reports`：工具栏渲染**只读联动 chip**（Badge secondary + × 清空，INT-344 契约）——全局算法非空时列表请求自动附 `algorithm_type`；chip 为空则不带。空态给「更换算法」+「查看全部（临时解除，仅本页）」。
- 报告查看 `/report/$reportId`：报告本身快照了 `algorithm_type`（详情头展示算法徽标），不随全局切换联动（报告是历史快照，算法不可变）；报告头展示该报告所用算法，与全局切换器数据源同源标注。
- 页面不新建独立算法下拉作为默认态（现状算法筛选收编进联动 chip + 筛选栏算法维度可改选，同 17_配置运维 §2.2 口径）。

## 10. 待负责人确认清单 / 现状缺陷（建议后端或实施卡立项）

> 全部为本卡逐端点/逐字段实测发现的真实现状缺口，设计稿按「不虚构、不隐藏问题」原则标注。

1. **report 三端点无路由级权限装饰器**：`report_bp.py` 的 `secondary_compare`（:87）、`search_report_cases`（:117）、`download_case_logs`（:122）**未挂 `require_permission`**——与 seed 的 `report:compare`/`report:read`/`report:download_log` 语义不对齐。本卡 RBAC 矩阵按权限码出（guest 可见），建议后端补装饰器后按码收敛。
2. **导出 format 服务端能力 vs 前端现状**：`POST /reports/export` 支持 format=csv/excel/pdf/html（ReportExportRequest schema 实测），但现前端导出走客户端 HTML-ZIP/JSON（reportExport.ts）未接服务端；设计改服务端导出（§4.9），实施卡需确认后端各 format 响应（含 pdf 是否可用、csv 批量语义）。
3. **AI 增强报告搁置**：`doc/功能设计文档/05_报告管理/AI增强报告与结果分析功能设计文档.md` 头注「负责人 2026-10-10：搁置，不计完成度」——`test_reports` 无 `ai_summary/ai_anomalies/ai_trend` 字段，`POST /reports/{id}/qa` 无实现。本卡分析结论按纯文本编辑设计，AI 摘要横幅/异常面板/趋势预测/问答浮窗**不引入**；对比报告趋势预测虚线标注「数据无预测段时省略」。若后续恢复 AI 立项，报告查看页组件位（分析结论上方/对比趋势下）预留。
4. **报告列表无全局算法联动**（现状为独立算法筛选）：本卡按 INT-344 全局切换器口径收敛为联动 chip（§2.2），请求自动附 `algorithm_type`——后端 `ReportListQuery.algorithm_type` 已支持（schema 实测）。
5. **对比入口分散**：现状对比仅在历史报告批量栏（任务对比）+ 任务域；本卡补报告查看页「对比」无直接入口（对比=新建报告），保留批量浮条 + 生成 Dialog 双入口即可，不新增页内对比抽屉（避免与 /ai-chat 报告工作台重叠，INT-415 已落地）。
6. **收藏/回收站依赖 favorites 服务**：`favorite/deleted` 过滤、`favoritesPort` restore/purge 为跨模块能力（INT-141/215），实施卡需确认 favorites 服务端点对 report 实体的覆盖（列表请求 `favorite/deleted` 参数已实测生效）。
7. **报告生成入口职责**：任务域行菜单「查看报告」（INT-354 §3.6.2）已覆盖任务侧生成；本卡报告中心「生成报告」（report:create，任务选择器）为补充入口——两入口并存，避免任务侧改动。
8. **双状态并存（生成生命周期 vs 发布状态）**：`report_service` 报告实体有 `pending/generating/completed/failed` 生成生命周期（progress 接口），列表 `status` 列另有 `draft/published` 发布状态——列表只显发布状态（现状口径），生成中反馈走 §5.9 进度 Dialog + Socket.IO 事件；设计不将生成生命周期并入列表状态徽章（避免双状态混淆，现状 UI 将「非 draft 视为已发布」的口径在实施卡需确认是否收敛为严格 published）。
9. **图表引擎迁移（Chart.js → VChart）**：现 Vue 前端实际用 Chart.js v4（含 zoom 插件），设计文档意图为 ECharts；本卡按「图表组件对齐 newAPI」裁定 VChart（§4.5）。Chart.js 专有的分布图/缩放平移能力在报告场景仅「具体用例」内嵌分布视图需要——实施卡可选 VChart histogram 或标记待后端聚合接口，勿为单个视图引入 zoom 插件依赖。
10. **分页规格对齐**：现前端 `PaginationComponent` pageSize 默认 10、选项 10/20/50/100，网关 `ReportListQuery.per_page` 默认 20；本卡按 newAPI DataTablePagination 统一 `[10,20,30,40,50,100]` 默认 20（与 INT-354/356/362 同族一致），后端已支持服务端分页无需改动。
