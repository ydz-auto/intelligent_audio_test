#### 3.6.5 逐目标执行模式契约与跨组件状态同步（FEAT INT-1115 裁定 2026-10-21；2026-10-21 第二次修订：同类型依赖口径）

**载荷契约（INT-1115 方案一致性审计员已裁定，非「待」项）**：

- POST /tasks 顶层可选 `target_modes: [{target_type, target_id, mode}]`：
  - `target_type` ∈ {device, api}（后端新增 `TargetType` 枚举）；`target_id` = 设备/API id（int）；`mode` ∈ {parallel, serial}（复用 `ExecutionMode`）。

  - 校验：`target_id` 必须命中本次 `device_ids`/`api_ids`；`target_modes` 出现时**必须恰好覆盖全部选中目标一次**（不漏/不多/不重复），否则 422；缺省（不传或空数组）= 全目标并行（零回归）。

**引擎调度语义（2026-10-21 第二次修订：原 INT-1115 审计口径被负责人口径覆盖，**待 INT-1115 修订**）**：

- 串行目标仅等前序**同类型**目标终态（API 串行只等前序 API、设备串行只等前序设备）；设备组与 API 组独立并行、互不等待（API 不用等设备、设备也不用等 API）。

**跨组件状态同步（卡片角标 / 示意图 / 请求载荷三处一致）**：

## 4. 步骤间状态与数据流（组件无关口径）

| 状态 | 载体 | 持久化 |
| --- | --- | --- |
| 当前步骤 | URL search `step`（0-4） | ✓ 可分享/刷新 |
| 视图模式（表格/卡片） | URL search `view` | ✓ |
| 全局算法 | Zustand `useGlobalAlgorithmStore`（INT-344 契约） | localStorage（导航栏同源，`iatp:algorithm:v1`） |
| 已选用例集 | Zustand 页面级 store（`useCaseSelectionStore`：手动勾选集 + 圈定模式 manual/filter-all） | 内存（刷新回到 step=1 重选——用例集属敏感流程态，不进 URL 防超长） |
| 已选资源集 | Zustand 页面级 store | 内存 |
| 并发数 | 同上（默认 4 / API 自动求和） | 内存 |
| 逐卡执行模式（每目标并行/串行） | Zustand：resource store `selectionOrder`（统一选中顺序）+ execution store `targetModes`（每目标模式 map）；派生 `useTargetModes()`（§3.6.5） | 内存 |
| 进行中任务 id | 同上 + TanStack Query `['task-progress', id]` | 内存（刷新丢，任务在任务管理可续看） |

- 步骤解锁校验集中一处（`canEnterStep(step)` 纯函数，照 setup-wizard validate* 模式声明式）：step≥2 需已选算法；step=3 需任务已启动；step=4 需报告就绪。跳转未解锁步骤 = toast.warning + Tooltip 说明（不静默）。
- 步骤切换动效：250ms cubic-bezier(0.33,1,0.68,1) 进场（基座卡 §4.2），`prefers-reduced-motion` 关停。
