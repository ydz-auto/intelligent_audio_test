### 1.3 内容与交互机制（文档页的核心资产，逐条实测）

1. **目录提取**：手册 md 必须有 `## 目录` 段，其下是 `- [标题](#锚点)` 列表；`createGuideDocument` 用正则 `^## [^\n]+\r?\n(?=\s*- \[)` 截取该段（guide-document.tsx:42-46），再逐条解析链接；每个条目按标题在全文中的标题层级决定嵌套（depth>3 → 缩进展示，guide-document.tsx:53）。
2. **标题锚点**：渲染时为 h1-h6 生成 slug id——转小写、去标点、空格转连字符、重名追加 `-1/-2`（markdown.tsx:744-758）；目录链接写成 `#${encodeURIComponent(id)}`，保证中文锚点 URL 安全。
3. **正文链接改写**：仓库内相对链接换成站内目标——`(./README.md)` → `#目录`、`(./about.md)` → `/about`、`(./api-guide.md)` → `/user-guide-api`、`(./user-guide.md)` → `/user-guide`（guide-document.tsx:56-61）；其余外链统一 `target=_blank rel=noopener noreferrer`。
4. **占位符**：`{{API_BASE_URL}}` → `${apiBaseUrl}/v1`、`{{API_ROOT}}` → apiBaseUrl（guide-document.tsx:37-38）；apiBaseUrl 由 `useApiBaseUrl` 提供：优先 `status.api_base_url || server_address`，校验 http/https 且不含用户凭据，非法回退 `window.location.origin`，去尾部 `/` 与 `/v1`。**本平台接线契约**：newAPI 直读的 `api_base_url`/`server_address` 是 wire snake_case 字段，本平台在 infrastructure 层 `statusApi` 转 camelCase DTO（`apiBaseUrl`/`serverAddress`）后再供 application 消费，前端只见 camelCase Domain（§7 契约）。
5. **滚动追踪（scroll spy）**：rAF 节流；遍历目录对应标题元素，取「顶边 ≤112px 的最后一个」为当前节；页面触底（scrollY+innerHeight ≥ scrollHeight-2）时强制高亮最后一节；点击条目立即置 active（index.tsx:73-107）。
6. **移动端目录**：整目录收进 Collapsible（触发器「目录」+ BookOpen，ChevronDown 随展开转 180°）；桌面 `isDesktop`（≥1024px）常开；点击条目后收起菜单，并把焦点移到目标标题（`tabIndex=-1` + `focus({preventScroll:true})`，键盘可达）。
7. **代码高亮**：shiki core 懒加载单例，仅装手册用到的语言（bash/json/powershell/python/toml）+ github-light/github-dark 双主题；未支持语言（如 text）不高亮但照常展示与复制；chunk 加载失败静默回退原文（guide-code-block.tsx:41-95）。
8. **复制**：CopyButton 写入剪贴板**原文**（含换行符），成功后图标 Check + 文案「已复制」；每个 pre 恰好对应一个复制按钮。
9. **安全**：marked 输出强制过 DOMPurify 白名单（markdown.tsx:59-144，允许 SVG/MathML 子集），所有链接补 `_blank + noopener noreferrer`。
10. **未登录导航**：文档页本身公开；站头上标记 `requiresAuth` 的导航项点击后弹「需要登录」5 秒倒计时对话框（public-header.tsx:199-228、496-524）——文内链到登录后页面时沿用同一机制，不中断阅读。

### 3.2 路由与守卫

- 路由：`/user-guide`、`/user-guide-api` 为顶层公开路由（TanStack Router 文件路由，公开 meta，不进 `_authenticated` 组）——对齐 newAPI 两路由公开可读。

## 4. 内容设计（两本手册）

### 4.1 手册来源与结构约定

- 手册正文是**构建期 Markdown 资产**（`?raw` 导入，对齐 newAPI），落新前端 `web/src/features/user-guide/content/`；本平台站内单语言中文，不建多语言 content 目录（`getDocumentLanguage` 固化返回 zh，机制保留以便将来扩展）。
- 每本手册首行 H1（页内大标题）+ `## 目录` + `- [标题](#锚点)` 列表——目录提取正则依赖此结构（§1.3-1），锚点列表与正文标题一一对应（回归测试断言全可达）。
- 实施卡按下述大纲写正文；**接口事实与操作说明一律取自 `doc/接口文档/*.md`、`doc/页面设计文档/*.md`、`docs/RBAC权限划分.md`，禁止杜撰**。

### 4.2 平台使用手册大纲（对位 docs/user-guide.md 的「概念→准备→操作→排错」骨架）

1. **快速开始**：登录 → 配置评估维度（`/Evaluation`）→ 管理设备（`/devices`）→ 导入测试音频（`/audio-import`）→ 创建用例（`/testcases`）→ 执行测试（`/start-test` 开始测试）→ 查看报告（`/report-center` 报告中心 / `/report/$reportId` 详情）（编号步骤，每步带站内链接）。
2. **核心概念**：测试执行 / 测试用例 / 任务 / 报告 / 评估维度 / SPL 映射（概念表格：概念 ｜ 一句话解释 ｜ 所在页面）。
3. **准备工作**：评估维度管理（`/Evaluation`）、设备管理（`/devices`）、导入音频管理（`/audio-import`）——对齐首页「使用帮助」卡现有三步（InfoSection.vue 帮助文案「首次使用请先配置评估维度和播放设备，然后导入测试音频」）。
4. **用例管理**（`/testcases`）：分组与标签、参考参数、导入/导出/模板。
5. **执行测试**：开始测试（/start-test）；实时进度与日志查看。
6. **任务与发布**（/tasks）：日常任务页签、已发布任务页签（发布/执行/新版本/归档）。
7. **查看报告**：报告中心 `/report-center`（管理页，双页签「测试报告/历史报告」，侧栏「报告中心」直达）、报告展示页 `/reports`（已发布报告对外展示，顶部导航「报告」直达）、报告详情 `/report/$reportId`、报告对比与下载——对齐 INT-441 报告双入口拆分；`/test-reports`、`/history-reports` 旧链已并入报告中心对应页签（redirect 兼容），不再作为独立页表述。
8. **执行失败自查**：对照全局错误码（201 资源锁定 / 202 不存在 / 203 状态冲突 / 204 引擎异常 / 302 硬件超时 / 303 系统繁忙——接口文档 01 §2.4）给「现象 ｜ 检查方式」表。

### 4.3 平台 API 手册大纲（对位 docs/api-guide.md 的「准备→调用→异步→排错」骨架）

1. **准备接入信息**：Base URL `{{API_BASE_URL}}`（= 站点根 + `/api/v1`）、JWT Bearer；AUTH_MODE=off 时免令牌。
2. **认证**：`POST /api/v1/auth/login` 获取 access_token → 请求头 `Authorization: Bearer {token}`；刷新/登出端点（auth_service 路由实测）。
3. **响应格式与错误码**：`code/message/data/detail` 统一结构 + HTTP 状态码表 + 全局错误码表（0/101/102/103/201~205/301~303，接口文档 01 §2.3-2.4 全量照搬）。
4. **任务接口**：`GET /api/v1/tasks`（分页/筛选参数表——07_任务管理.md §7.1 实测）、`POST /api/v1/tasks`、`POST /api/v1/tasks/:id/start`、`POST /api/v1/tasks/:id/stop`、`POST /api/v1/tasks/:id/control`、`GET /api/v1/tasks/:id/progress`——每个带 curl 示例（bash）。
5. **用例 / 音频 / 设备 / 报告接口**：每类 1-2 个代表性端点 + curl（取 02/04/05/06/08 号接口文档实测端点）。
6. **实时推送**：SSE（`sse:read`）与 WebSocket 日志订阅（`log:websocket`）说明。
7. **错误处理与重试**：429/5xx 指数退避、幂等与重复提交风险、流式断开语义（对齐 newAPI API 手册同节结构，结合本平台 code 错误码）。
8. **常见问题**（401/403/202/203/302/303 对照表）；**联系支持**。
9. **Windows 与调用环境**：bash 与 PowerShell 双示例（对齐 newAPI `curl.exe`/`Get-Credential` 做法）。

### 4.4 文内交互件（全部复用 newAPI 现成组件与机制）

- curl/bash 示例块（`GuideCodeBlock`，语言 bash）+ PowerShell 变体；关键参数表、状态对照表走 Markdown 表格 + 滚动包裹。
- 站内链接（/tasks 等）由 `guideSource` 改写为 router 路径；官方外链独立 `_blank`。
