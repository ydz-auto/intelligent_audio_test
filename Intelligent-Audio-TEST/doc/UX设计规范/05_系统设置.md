### 1.3 newAPI 设置分组与分区全表（信息架构基准）

侧边栏单组「系统管理」（组内 8 个可折叠子组，每个子组下是分区链接；`system-settings.config.ts` + 各 section-data.ts 实测）：

| 图标（lucide） | 子组 | 分区（`$section`） |
| --- | --- | --- |
| Settings | 站点与品牌 | 系统信息 / 系统公告 / 顶部导航 / 侧边栏模块 |
| Shield | 认证 | 基础认证 / OAuth 集成 / Passkey / Bot 防护 / 自定义 OAuth |
| CreditCard | 计费与支付 | 额度 / 货币与显示 / 模型定价 / 分组定价 / 支付网关 / 签到奖励 |
| Box | 模型 | 全局模型 / Gemini / Claude / Grok / 模型部署 |
| Route | 请求策略 | 请求检查 / 会话与重试 / 渠道健康 |
| ShieldAlert | 安全与限额 | 速率限制 / SSRF 防护 / Token 限额 |
| Layout | 控制台内容 | 数据看板 / 公告 / API 地址 / FAQ / Uptime Kuma / 聊天预设 / 绘图 |
| Wrench | 运维 | 系统行为 / 监控告警 / SMTP 邮件 / Worker 代理 / 日志维护 / 性能 / 系统维护 |

分区数据形态：布尔/字符串/数字选项由后端 KV 返回，前端按默认值类型安全解析（布尔 `value==='true'||'1'`、数字 `Number(trim)`、数组 JSON.parse + 元素类型校验，失败回退默认值——`use-system-options.ts` 实测）。

保存交互（`use-settings-form.ts` + `use-update-option.ts` 实测）：

1. 表单基线 = 服务端值；`isDirty` 时页头标题旁出现琥珀点徽标「未保存的更改」。
2. 点「保存更改」只收集**脏且与基线不同**的字段，逐项 `PUT /api/option/`；无差异时 `toast.info('没有需要保存的更改')`。
3. 成功 `toast.success('设置已更新')`，失效 `system-options` 查询缓存（展示类键还失效 `status`）。
4. 重置按钮回基线并 `toast.success('表单已重置为已保存的值')`；`isDirty=false` 时禁用。
5. 脏表单路由离开 → `useBlocker` 弹 ConfirmDialog（「离开/留下」）+ 刷新/关页 beforeunload。
6. 复杂编辑区（公告管理、自定义 OAuth 表）在分节内自带对话框/表格，与通用保存链解耦。

## 3. 布局结构（本平台新前端）

### 3.1 页面总骨架

```
AuthenticatedLayout
└─ AppSidebar（drill-in：命中 /system-settings/* 时根导航树替换为设置树）
   ├─ SidebarViewHeader：「← 返回工作台」（Link → /，hover 变前景色）
   ├─ SidebarGroupLabel「系统管理」（11px 大写间距灰字）
   └─ 各域 Collapsible（图标+名称，ChevronRight 展开转 90°）→ 分区子链接
└─ <Outlet/>  → SettingsPage（每个 <域>/<分区> 一条路由，组件懒加载）
   ├─ SectionPageLayout.Title：分区中文名 + <span id=标题状态位/>（挂未保存徽标）
   ├─ SectionPageLayout.Actions：表单动作 Portal（重置 / 保存更改）
   └─ SectionPageLayout.Content：SettingsSection（分节标题 h3 + SettingsForm 双列栅格）
```

### 3.2 侧边栏设置树（中文全量）

lucide 图标对齐 newAPI 语义（Settings/Shield/…），文案全中文：

- 「站点设置」（Settings）：站点信息 / 站点公告 / 导航模块
- 「认证设置」（Shield）：认证方式 / OAuth 提供方
- 「算法配置」（Box）：算法列表 / 分组管理
- 「测试配置」（FlaskConical）：评估维度 / SPL 映射 / 标签管理
- 「安全设置」（ShieldAlert）：访问控制
- 「运维设置」（Wrench）：日志维护

实现照 `system-settings.config.ts` 的 `SidebarView` 结构：`pathPattern: /^\/system-settings(\/|$)/`、`parent: { to: '/', label: '返回工作台' }`、`getNavGroups` 返回上述树（nav items 由各域 section-registry 的 `getSectionNavItems` 拼装，URL 为 path 风格）。

### 3.3 分区路由与守卫

- 路由：`_authenticated/system-settings/$domain.$section.tsx`（或按域拆 `$domain/` 子目录，对齐 newAPI 每域一路由文件）；`/system-settings` 与 `/system-settings/<域>` 重定向到该域默认分区（对齐 `system-settings/index.tsx`、`site/index.tsx` 的 redirect 模式）。
- `beforeLoad` 校验 section 白名单，非法值重定向默认分区（对齐 `site/$section.tsx`）。
- 权限：对位 newAPI 超管守卫——本平台按权限码守卫（`system:manage` 或沿用各页现有权限码如 `algorithm:read`），无权限跳 403（对齐 `route.tsx` 的 redirect 模式，具体权限码口径随实施卡定）。
- 搜索参数：分区切换优先路径参数；需要附加态的分区用 `validateSearch`（zod + `.catch(默认值)`，对齐 `route-config.ts`）。

## 4. 分区内容设计（分区 = 表单页 / 分区 = 管理页 两种母版）

### 4.1 母版 A：KV 表单分区（对齐 basic-auth / system-behavior / system-info 模式）

适用：站点信息、站点公告、认证方式、访问控制、日志维护。

- 结构：`SettingsSection`（h3 分节标题 `text-base font-semibold`）→ `SettingsForm`（`grid gap-y-6 lg:grid-cols-2`，开关行/textarea 自动跨双列）→ 控件。
- 开关行：`SettingsSwitchItem`（`flex flex-row items-center justify-between gap-4 py-2.5`，左 Label+Description 右 Switch）；带子配置的开关用 `SettingsControlGroup`（`bg-muted/20 rounded-xl border px-3 py-2.5`）包住联动的输入行（`SettingsControlChildren` 左侧竖线缩进）。
- 文本项：`FormLabel + FormControl(Input/Textarea) + FormDescription(text-xs text-muted-foreground) + FormMessage`，四段垂直排。
- 校验：zod schema；错误红字 + 输入框 destructive ring（`aria-invalid` 样式直接用 newAPI 控件现成态）。
- 保存：页头动作区「保存更改」（default 变体 sm）+「重置」（outline sm，干净时禁用）；脏徽标与离开守卫照 §1.3 全套接入。
- 空态/加载/错误：整页 Loading（Loader2+「正在加载设置…」）、ErrorState（「设置加载失败」+「重试」）、成功 toast「设置已更新」。

### 4.2 母版 B：资源管理分区（对齐 custom-oauth / announcements 模式）

适用：OAuth 提供方、算法列表/分组管理、评估维度、SPL 映射、标签管理。统一结构：

```
SettingsSection（分节标题 + 一句说明）
├─ 说明 Alert（可选：如 OAuth 回调地址格式，code 样式 + CopyButton）
├─ 工具行：左侧说明文字 / 右侧「+ 新建」Button(size='sm')
├─ StaticDataTable（列定义 + 空态文案 + 行操作 StaticRowActions：编辑/删除）
├─ ConfirmDialog（删除确认，destructive）
└─ Dialog/Sheet 表单（ProviderFormDialog 同款：react-hook-form + zod + 双列 SettingsForm 栅格）
```

各分区映射要点（现状取自 Vue 源码，逐条照搬字段）：

- **OAuth 提供方**（现 `OAuthProviderManagement.vue`）：列表列 = 名称/Slug/状态/Client ID/授权端点/操作；新建对话框 = 自动发现（Issuer URL + 「自动发现端点」按钮，回填授权/Token/用户信息端点）+ 表单字段（名称、Slug、图标、状态、Client ID/Secret、三端点、Scopes、四个字段映射）。状态用 Badge（启用=primary 系、停用=muted）。
- **算法列表**（现 `AlgorithmConfigPage.vue` 列表页签）：列 = 算法类型/名称/分组/状态/参数数/操作（编辑/复制/删除）；筛选 = 搜索（算法类型或名称）+ 分组下拉 + 状态下拉；编辑进分区级 Dialog（现 829 行大模态窗拆为：基本信息表单 + 参数表格 Tab + 参数映射 Tab，Dialog 内 Tab 用 Tabs 组件，删除/复制走 ConfirmDialog）。分页用 TanStack Table 受控分页。
- **分组管理**（现模态窗内「所属分组」下拉 + 新建分组散点）：独立分区表格（分组名/描述/排序/算法数/操作），对齐 newAPI「分组定价」分区的资源表形态。
- **评估维度 / SPL 映射 / 标签管理**：沿用母版 B；标签管理保留「左分类树 + 右标签表」布局（`CategorySidebar.vue` 现状），分类树放分节左列（lg 双列，左 `col-span-1` 树、右表）。
- 全部中文文案见 §6；对话框宽度、动画、遮罩直接用 newAPI Dialog/Sheet 现成样式，不自研。

### 4.3 分区懒加载与状态

- 每分区组件 `lazy()` + Suspense；fallback 用 LoadingState（「正在加载…」）。
- 数据获取：表单分区走 `useQuery(['system-options'])`（staleTime 5min，对齐 `use-system-options.ts`）；资源分区按资源建独立 queryKey，保存后 `invalidateQueries`（对齐 `use-update-option.ts` 的缓存失效模式）。
- 本平台后端无 newAPI 的 `/api/option/` KV 通道：实施卡需先落「系统选项」读/写接口（读全量 KV、写单键）或按域拆 REST；本规范按 KV 通道设计交互，REST 拆分时仅替换 api.ts 一层（interfaces 不感知）。

## 7. React 组件树 + DDD 四层落位

```
interfaces/
├─ routes/_authenticated/system-settings/
│  ├─ route.tsx                 # 工作区守卫（权限码）+ Outlet（对位 newAPI route.tsx）
│  ├─ index.tsx                 # 重定向默认域
│  └─ $domain.$section.tsx      # 分区路由：section 白名单校验 + lazy 组件
├─ features/system-settings/
│  ├─ components/               # SettingsPage / SettingsPageFrame / settings-page-context(Portal)
│  │                            # SettingsSection / SettingsCard / SettingsAccordion
│  │                            # SettingsForm* 栅格 / FormDirtyIndicator / FormNavigationGuard
│  ├─ site|auth|algorithm|testing|security|operations/
│  │  ├─ section-data.ts        # 分区常量（id/中文标题/默认分区）
│  │  ├─ section-registry.tsx   # createSectionRegistry 实例 + lazy 构建器
│  │  └─ <各分区>.tsx           # 母版 A 表单或母版 B 表格+对话框
│  └─ index.tsx                 # <Outlet/>
└─ components/layout/config/system-settings.config.ts   # SidebarView 注册（设置树+返回工作台）
application/
├─ settings/useSystemOptions.ts     # useQuery(['system-options']) + 选项类型解析
├─ settings/useUpdateOption.ts      # useMutation 单键写入 + toast + 缓存失效
├─ settings/useSettingsForm.ts      # 脏收集/基线对比/差异提交（纯逻辑，无 UI）
└─ oauth/useOAuthProviders.ts、algorithm/useAlgorithmConfig.ts、…（各资源分区 hooks）
infrastructure/
├─ api/optionApi.ts                 # GET/PUT /api/option（KV 通道；REST 拆分仅改此层）
└─ api/oauthProviderApi.ts、algorithmApi.ts、…（DTO→domain 映射，沿现有 api_gateway 契约）
domain/
└─ model/option.ts、oauthProvider.ts、algorithm.ts（值对象/类型，算法/OAuth 沿用现有 domain 模型）
```

- 组件树（routes/features/layout config）全部在 **interfaces 层**；hooks（状态编排、缓存、脏管理）在 **application 层**；HTTP 客户端与 DTO 在 **infrastructure 层**；实体/值对象在 **domain 层**——与整站 DDD 四层约定一致。
- 现有 Vue 可复用逻辑对照：`useAlgorithmConfigPage.ts`（列表态/筛选/分页逻辑 → application 层 hooks 平移）、`algorithmDto.ts`（DTO → infrastructure 层原样保留）、`AlgorithmConfigModal.vue` 的表单分组与参数页签结构（拆进母版 B 对话框，交互不变）。
