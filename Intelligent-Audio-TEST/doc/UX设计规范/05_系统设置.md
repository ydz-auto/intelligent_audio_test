本平台差异：无 role 数值，改用**权限码集合**判定（见 §2.1）。

保存交互（`use-settings-form.ts` + `use-update-option.ts` 实测）：

1. 表单基线 = 服务端值；`isDirty` 时页头标题旁出现琥珀点徽标「未保存的更改」。
2. 点「保存更改」只收集**脏且与基线不同**的字段，逐项 `PUT /api/option/`；无差异时 `toast.info('没有需要保存的更改')`。
3. 成功 `toast.success('设置已更新')`，失效 `system-options` 查询缓存（展示类键还失效 `status`）。
4. 重置按钮回基线并 `toast.success('表单已重置为已保存的值')`；`isDirty=false` 时禁用。
5. 脏表单路由离开 → `useBlocker` 弹 ConfirmDialog（「离开/留下」）+ 刷新/关页 beforeunload。
6. 复杂编辑区（公告管理、自定义 OAuth 表）在分节内自带对话框/表格，与通用保存链解耦。

- **角色清单（5 系统角色）**：`scripts/migrations/202608/seed_rbac.py:174-180`——admin（超级管理员，持通配 `*`）/ tester（测试工程师，含测试主管）/ algo_engineer（算法工程师，含质量负责人）/ device_admin（设备管理员）/ guest（游客，只读）。角色实体含 `is_system`（内置角色不可删除，`auth_service/domain/entities/role.py:40`）。
- **权限点 100 个**：`seed_rbac.py:46-168`（按 22 个业务模块组织：task 11 / published_task 4 / testcase 7 / audio 6 / device 5 / playback 5 / spl 5 / digital_spl 4 / api_config 5 / report 7 / evaluation 5 / algorithm 5 / group 4 / tag 4 / log 3 / home 2 / sse 1 / user 6 / role 4 / permission 1 / auth 6 / 通配 `*` 1）。code 形如 `资源:操作`。

### 3.3 分区路由与守卫

- 路由：`_authenticated/system-settings/$domain.$section.tsx`（或按域拆 `$domain/` 子目录，对齐 newAPI 每域一路由文件）；`/system-settings` 与 `/system-settings/<域>` 重定向到该域默认分区（对齐 `system-settings/index.tsx`、`site/index.tsx` 的 redirect 模式）。
