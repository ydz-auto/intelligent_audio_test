### 1.4 newAPI 关键机制（本页引用的现成交互件）

1. **身份呈现**：角色 Badge（neutral）+ 用户 ID Badge（info，复制按钮 `copyText`）；头像用户名哈希取色（§1.2）——本平台 `/auth/me` 不含 roleName（前端会话缓存兜底，`authStore.ts:126` 注释实测），设计按「角色名取前端 auth store 缓存、取不到显示「—」」出。
2. **账户绑定交互**：提供方行两态（未绑定→outline「绑定」钮；已绑定→success 徽章 + ghost destructive「解绑」钮）；解绑走 ConfirmDialog（destructive，描述「将无法再通过该方式登录」）；绑定中/解绑中全组禁用（`bindingsLocked`）；成功 toast。**本平台差异**：无二次验证（X-Security-Proof 机制不适用，本平台绑定端点仅验登录态），省略 `SecureVerificationDialog` 依赖。
3. **修改密码交互**：AccountActionCard 行 + 按钮弹 ChangePasswordDialog；三字段 + zod（新密码 8–128 位、两次一致 refine）；提交中 Spinner；成功后关窗 + toast。**本平台差异**：无 `has_password` 字段（UserAggregate 未对外暴露）、无二次验证——对话框简化为「当前密码/新密码/确认新密码」三字段直提。
4. **卡片栅格**：`CardStaggerContainer` 进入动画 + `TitledCard` 标题卡 + 双列响应式栅格（xl 断点右列 360px sticky）——全部照搬。

### 2.0 本平台个人中心后端能力事实基线（全部实测，只设计现有能力）

数据契约与权限门槛（`api_gateway/routes/*.py` + `auth_service/application/handlers/auth_handlers.py` + `frontend/src/domain/model/auth.ts`）：

| 能力 | 端点（实测） | 返回/语义 | 权限门槛 |
| --- | --- | --- | --- |
| 当前用户信息 | `GET /auth/me`（auth_bp.py:183-186） | `{user_id, username, role_id, permissions}`（**无 email、无 roleName**；roleName 由前端 authStore 会话缓存兜底，authStore.ts:126 注释） | 登录即可（JWT） |
| 公开 OAuth 提供方列表 | `GET /auth/oauth/providers`（oauth_bp.py:41-44） | `{providers: [{id, name, slug, icon}]}`（仅启用项，无凭证字段） | 公开 |
| 第三方绑定列表 | `GET /auth/oauth/bindings`（oauth_bp.py:114-123） | `{bindings: [{provider_id, provider_name, provider_slug, provider_icon, provider_user_id}]}`（提供方已删除行跳过） | 登录即可（端点内自验用户态） |
| 绑定（携票据落库） | `POST /auth/oauth/bindings`（oauth_bp.py:126-137） | body `{bind_ticket}`；幂等，重复绑定 no-op | 登录即可 |
| 解绑 | `DELETE /auth/oauth/bindings/{provider_id}`（oauth_bp.py:140-149） | 幂等（无绑定行也成功） | 登录即可 |
| 绑定授权跳转 | `GET /auth/oauth/{slug}/authorize?intent=bind`（oauth_bp.py:47-62） | 302 到提供方授权页；state 短时效签名 | 登录后发起 |
| 绑定回调回传 | `GET /auth/oauth/{slug}/callback`（oauth_bp.py:65-109，intent=bind 分支） | 302 回 `{base}/#/AccountSettings?bind_ticket=…`（`_FRONTEND_BIND_REDIRECT`，oauth_bp.py:30）；前端携票落库 | 回调公开 |
| 我的收藏 | `GET /favorites?entity_type=`（favorite_trash_bp.py:34-37） | `{data: {task: [ids], report: [ids], testcase: [ids]}}`（per-user） | 登录即可（require_auth） |
| 任务列表 | `GET /tasks`（task_bp.py:11-14） | 分页+过滤（status/algorithm_type/search/date/favorite/deleted/evaluation_status/merged）；**无 `created_by` 参数暴露**（网关 TaskListQuery 缺参，底层 ListTasksQuery 有 `created_by`，task_queries.py:31） | `task:read` |
| 报告列表 | `GET /reports`（report_bp.py:29-31） | 列表；无按用户过滤参数 | `report:read` |

**能力缺口（影响本页设计，全部标注待后端立项，不杜撰）**：
1. **自助修改密码**：无端点（auth_bp 仅 login/callback/refresh/logout/me；user_bp PUT /users/{id} 系 admin 管他人，`user:update`）；密码哈希由 auth_service `user_repository` 管理。→ 修改密码 UI 按 newAPI 版式设计并标注「后端端点缺失，实施卡前置=待后端立项」。
2. **自助修改资料**：无端点（用户名/邮箱修改仅 admin 经 user_bp）。→ 个人信息卡只读 + 「如需修改请联系管理员」说明。
3. **我的任务/我的报告按用户过滤**：查询层已有（ListTasksQuery.created_by、报告表 `created_by_user_id` 索引），网关未暴露参数。→ 个人数据快捷区深链带 `scope=mine` 契约，服务端过滤待后端立项。
4. **邮箱展示**：`/auth/me` 不含 email（用户表有 email 字段，`user_models.py:80`）。→ 个人信息卡邮箱行「待后端立项」（扩展 /auth/me 后补）。
5. **登录会话 / 访问令牌 / 二次验证 / 通行密钥 / 隐私开关 / 自助删号**：全部无后端能力。→ 归「不引入」清单（§2.2），不做占位壳。

### 3.2 用户身份卡（ProfileHeader 对位）

Card `gap-0 overflow-hidden py-0`，上区=身份行，下区=个人数据快捷条（§3.3，替代 newAPI 额度统计条）。

身份行（左→右）：
