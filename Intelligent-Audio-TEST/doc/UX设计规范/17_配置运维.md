### 6.2 保存语义：草稿 vs 发布（INT-591 核心，对齐后端定义全量保存事务 RPC + 草稿/乐观锁）

> 依据：INT-591 裁定「自动保存 → 写**草稿**（界面显示「上次保存 HH:mm:ss」）；显式「发布」→ 全量校验 + 原子提交；乐观锁冲突（他人已改）→ 提示刷新；离开页有脏态守卫提醒」+ 主项目【后端】算法定义全量保存事务 RPC 卡（草稿/乐观锁后端语义；RPC 端点形态以该卡为准，本子节为前端 UI 契约，§12-9 标注）。倒计时基元复用 newAPI `hooks/use-countdown.ts`（`{secondsLeft,isActive,start,stop,reset}`，`initialSeconds` 默认 30）；30 秒档位与 newAPI `features/auth/constants.ts` `EMAIL_VERIFICATION_COUNTDOWN`/`PASSWORD_RESET_COUNTDOWN = 30` 同款。

- 计时起点/重置/归零语义沿用 §6.1a：Sheet 打开且表单**首次变脏**（`formState.isDirty` false→true）启动 30s；每次内容变更重置回 30s（RHF `watch` 变更 → `start(30)`）；**不可手动关闭**（数据不丢兜底）；Sheet 关闭随组件卸载自然停止。
- 归零 → **结构校验**通过 → 写草稿（不再走 `POST/PUT /algorithm/definitions` 直接提交——**INT-591 升级为草稿 RPC**）；成功 → 「上次保存 HH:mm:ss」更新 + `form.reset(form.getValues())` 快照重置（isDirty 归零，脏态守卫不再误弹）+ invalidate 草稿查询 + **不关 Sheet**；若仍有新变更重新计时。
- 结构校验不过 → 倒计时暂停（`stop()`）+ footer 内联 Alert「有校验未通过，草稿暂存暂停」；修正后重新计时。
- 失败 → toast「草稿保存失败，请检查网络后重试」+ 不自动重试（保留编辑态转手动）。

**参数行失焦防抖保存（保留旧习惯，INT-591 §4）**
- 旧 Vue 语义：参数行编辑失焦 → 防抖 → 逐条粒度端点入库（`useAlgorithmParamOps` blur 防抖）。**INT-591 明确保留「失焦防抖保存」习惯**，但按 INT-585 回归断言（新 Sheet 不得出现逐参 `/algorithm/params` 调用）与草稿模型落位：**参数行任一输入失焦 → 1.5s 防抖 → 结构校验 → 写草稿（聚合草稿 RPC）**，粒度端点不重新引入。
- 防抖保存成功 → 「上次保存 HH:mm:ss」更新；30s 计时重新启动（失焦保存视为一次保存事件）。

**校验时机（INT-591 §2 要求写清）**
- **草稿保存 = 宽松结构校验**：参数代码非空、同作用域代码唯一；违反显示软提示（行内红字 + 倒计时暂停）但不弹阻断；范围约束/正则等在草稿阶段**不校验**（草稿是中间态，允许暂存未完备内容）。
- **发布 = 严格全量校验**：全部必填口径 + 算法代码正则 `^[a-z][a-z0-9_]*$`（新建态）+ 参数代码同作用域唯一 + 范围 min≤max + 类型合法 → 字段级红字 + `aria-invalid` destructive ring；发布按钮 disabled 当 invalid（`schema.safeParse` 实时计算口径，§6.1a 平移）。
