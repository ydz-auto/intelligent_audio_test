## 待实现：用例结构化配置（轮次为顶层 + 独立列参数）

用例配置采用**轮次为顶层 + 独立列参数**架构：`config` 只承载**结构性配置**（`{ rounds, dimensions, background_noise, source_audio, auto_generated }`），算法参数和参考参数从 config 中剥离，回归 `test_cases` 表独立列，按轮分组存储。

### 核心设计原则

- **轮次为顶层单元**：每一轮包含该轮所需的结构性配置
- **每轮结构性自包含**：不同轮次可以有不同的音频、噪声、评估维度等
- **复制机制**：添加新轮次时，允许复制一整轮信息，或用户勾选需要复制的部分到下一轮
- **config 只承载结构性配置**：`{ rounds, dimensions, background_noise, source_audio, auto_generated }` — rounds 编排轮次，dimensions 为多轮维度（用例级跨轮聚合）
- **保留独立列（按轮分组）**：`test_cases.algorithm_params` 和 `test_cases.reference_params` 数据库列保留，按轮分组存储
- **algorithm_params 独立列**：按轮分组存算法参数 `[{round_number, params:[{field_code, field_value}]}]`，由 `case_algorithm_params` 表定义驱动，新增参数只需 INSERT 不改代码
- **reference_params 独立列**：按轮分组存参考参数路径 `[{round_number, reference_params_path}]`，内容仍存文件，列里只存路径，避免 MB 级数据撑大数据库行
- **referenceParams 存文件、独立列存路径**：上传音频时自动生成参考文本文件，用户可在前端编辑，`reference_params` 列只存路径
- **JSON 字段（非关联表）**：rounds 存储在 `config` JSON 列中，始终整体读写
- **API/E2E 共用结构**：同一个 `rounds[]` 结构，不同字段按 test_type 选择性渲染
- **编辑器显示条件仅看 test_type**（api/e2e），不看 algorithmType
- **结构性字段 vs 表驱动参数分离**：
  - 结构性字段（round 顶层，Schema 固定）：`roundNumber`、`audios`、`backgroundNoise`、`evaluation`
  - 表驱动参数（`test_cases.algorithm_params` 独立列）：由 `case_algorithm_params` 表定义，`[{round_number, params:[{field_code, field_value}]}]` 格式，新增参数只需 INSERT 不改代码
- **无 SessionConfigEditor**：会话参数不在原始需求中
- **无 waitTime 在轮次顶层**：waitTime 移入 algorithm_params 独立列，E2E 等待设备响应完成由引擎自动判定，API 由 session_timeout 控制

### config 整体结构（只含结构性配置）

```json
{
  "rounds": [
    {
      "roundNumber": 1,
      "audios": [{ "audio_id": "a1", "playbackDeviceId": "d1", "spl": 75, "playOrder": 1 }],
      "backgroundNoise": { "audioId": "n1", "spl": 60, "deviceIds": [], "loop": true },
      "evaluation": { "enabled": true, "dimensions": [{ "id": 1, "name": "WER", "params": {} }] }
    }
  ],
  "dimensions": [
    { "id": 1, "name": "WER", "weight": 1.0, "threshold": 80 }
  ],
  "background_noise": null,
  "source_audio": null,
  "auto_generated": false
}
```

> config 不再包含 `algorithmParams` / `referenceParamsPath`，这两类参数回归 `test_cases` 表独立列。

### test_cases.algorithm_params 独立列（按轮分组）

```json
[
  {
    "round_number": 1,
    "params": [
      { "field_code": "interferers", "field_value": [{"id":"int1","audioId":"intf1","spl":60}] },
      { "field_code": "railDistance", "field_value": 50 },
      { "field_code": "volumeLevel", "field_value": 70 },
      { "field_code": "voiceprintEnabled", "field_value": true },
      { "field_code": "promptAudioId", "field_value": "prompt_001" }
    ]
  }
]
```

### test_cases.reference_params 独立列（按轮分组，只存路径）

```json
[
  { "round_number": 1, "reference_params_path": "ref_params/93cc5cd7-bd4f-4936-af4c-dae14ab9a098/round_1.json" }
]
```

> **分层规则**：config 的 round 顶层只放结构性字段（Schema 固定，不随算法变化），算法参数存 `test_cases.algorithm_params` 独立列（由 `case_algorithm_params` 表定义，新增参数只需 INSERT）。`backgroundNoise` 是 E2E 基础环境配置，放在 round 顶层。

### referenceParams 存储策略

| 项目 | 说明 |
|------|------|
| 生成时机 | 用户上传音频并关联到轮次时，`ReferenceParamsGenerator` 自动从 `AudioAnnotation` 生成参考文本，写入文件 |
| 存储位置 | 文件系统（如 `ref_params/{case_id}/round_{n}.json`） |
| 独立列中 | `test_cases.reference_params` 列 — 只存文件路径（按轮分组 `[{round_number, reference_params_path}]`） |
| 用户可编辑 | 前端提供查看/编辑界面：读取文件内容 → 用户修改 → 保存回文件 |
| 读取时机 | 执行测试时，按路径读取文件 |
| 体积 | config 始终 KB 级；referenceParams 文件可达 MB 级但不影响数据库行 |

### referenceParams 生命周期

```
上传音频 → 音频标注(AudioAnnotation) → ReferenceParamsGenerator 自动生成文件
→ 文件路径写入 test_cases.reference_params 独立列（按轮分组）
→ 用户在前端可查看/编辑文件内容
→ 执行测试时按路径读取
```

| # | 步骤 | 配置来源 | 是否必须 | 说明 |
