## 背景：从 6+1 维度到 12 个 xiaoyi 域注册键

voice_llm 改造之前，评估服务只支持 6 个传统 ASR 指标（wer / ser / cpwer / tcpwer / stm_wer / der）加一个通用 `llm_judge`。

改造后，围绕小艺（语音大模型）的对话能力新增了大量评估维度，目前**注册表共 18 个键**：

| 分组 | 键 |
|------|----|
| 传统 ASR 六键 | `wer` `ser` `cpwer` `tcpwer` `stm_wer` `der` |
| xiaoyi 域十二键 | 见下表 |

**xiaoyi 域 12 个注册键（颜色 = 所属子包，与架构图分组一致）**：

| 子包（颜色） | 注册键 |
|-------------|--------|
| turn_taking（紫） | `turn_taking`(主) `tor` `false_takeover` `takeover_latency` `high_freq_turn_taking` `high_freq_llm_judge` `interruption_metrics` |
| rejection_scene_awareness（绿） | `non_interactive_latency` `noise_latency` |
| env_judge（青） | `rejection_judge` `interruption_judge` |
| llm_judge（黄） | `llm_judge` |

> 量级变化的核心手段：**策略模式**（每个 task_type 一个 Calculator 策略类 + 自动注册）+ **主维度/子维度组织模式**（`turn_taking` 主维度统管 7 个子维度）。本文整篇围绕这两条主线展开。
>
> 注意：`tor` / `false_takeover` / `takeover_latency` 三个键**不在** `api.py` 的 `SUPPORTED_TASK_TYPES`（15 项）里，它们通过 `turn_taking` 的子任务（`sub_tasks`）分发，但注册表中有独立 Calculator。

## 一、三层架构总览

对应架构图 ①② 分区：

```
POST /submit (task_type + task_params)
  │
  ▼
controllers / api.py           ① API 层：_validate_and_dispatch_task 参数校验、本地/远程分发
  │
  ▼
services / task_service.py     ① 服务层：TaskService.calculate(task_type, task_params)
  │                                → CALCULATORS[task_type].run(task_params)  未注册 → ValueError
  │
  ▼
BaseCalculator(ABC)            ② 策略基类：run() 模板方法
  ├─ prepare_params() 参数装配（多轮折叠 / collar 默认 / LLM 参数抽离）
  └─ calculate()     子类实现（每个维度各自实现）
  │
  ▼
xiaoyi_metrics 5 个子包         ③ 子包全景：turn_taking(编排中枢) + rejection_scene_awareness
                                   + env_judge + llm_judge + interruptbility(纯函数库)
```

**注册分发链路**：`task_type` 到达 `TaskService.calculate` 后查 `CALCULATORS` 注册表，命中则调 `CALCULATORS[task_type].run(task_params)` 一键路由；未知类型走红色失败线（API 层返回 `CODE_BUSINESS_ERROR` / 服务层抛 `ValueError`）。

## 二、核心机制一：策略模式 + 注册表

### 1. 注册表

`TaskService` 维护一个**类属性字典**，任何 Calculator 实例按 task_type 键注册：

```python
class TaskService:
    CALCULATORS = {}                      # task_type → Calculator 实例

    @classmethod
    def register_calculator(cls, task_type, calculator):
        cls.CALCULATORS[task_type] = calculator

    @classmethod
    def calculate(cls, task_type, task_params):
        calculator = cls.CALCULATORS.get(task_type)
        if calculator is None:
            raise ValueError(f"未知任务类型: {task_type}")
        return calculator.run(task_params)
```

### 2. 自动注册

[`calculators/__init__.py`](file:///d:/00_code/V9.7.10/eval_server/app/services/calculators/__init__.py) **import 即注册**：import 各子包策略类 → 逐行 `TaskService.register_calculator(...)`。新增一个指标只需两步：

1. 新建子包 `xxx/strategy.py`，定义 `XxxCalculator(BaseCalculator)`；
2. 在 `__init__.py` import 并注册一行。

不侵入 `api.py` / `task_service.py` 的任何分支逻辑。

### 3. 基类模板方法

[`base.py`](file:///d:/00_code/V9.7.10/eval_server/app/services/calculators/base.py) 的 `BaseCalculator(ABC)` 固化两段流程：

```python
def run(self, task_params):
    params = self.prepare_params(task_params)   # ① 参数装配
    return self.calculate(params)               # ② 子类实现的具体计算
```

- `validate()`：默认 `(True, None)`；实际校验在 API 层 `_validate_and_dispatch_task` 拦截参数缺失，run 模板本身不含 validate。
- `prepare_params()`：默认走 `TaskService._prepare_params`（多轮折叠 / collar 默认值），可按需覆写。
- `calculate()`：**抽象方法，子类唯一必须实现**。

基类同时提供 9 个公共提取方法（`_is_multi_round` / `_get_round0` / `_get_round` / `_get_round_or_last` / `_unwrap_value` / `_collect_flat_from_rounds` / `_collect_audio_from_rounds` / `_collect_scalar_from_rounds` / `_pick_field`），单轮/多轮取值逻辑全部收敛在基类，子类不再各自处理。

### 4. 继承体系：3 个域基类 + 12 个实例类

```
BaseCalculator(ABC)
├── TurnTakingBase              → 7 个维度类（含 turn_taking 主维度聚合）
│     TurnTakingCalculator        （主维度，多轮聚合）
│     TorCalculator / FalseTakeoverCalculator / TakeoverLatencyCalculator
│     HighFreqTurnTakingCalculator / HighFreqLlmJudgeCalculator
│     InterruptionMetricsCalculator
├── _RejectionBase              → 2 类（NonInteractive + NoiseLatency）
├── _BaseEnvJudgeCalculator     → 2 类（RejectionJudge + InterruptionJudge）
└── LlmJudgeCalculator          独立实现（不建域基类，孤立节点）
```

## 三、核心机制二：主维度 / 子维度组织模式

以 `turn_taking` 作为**主维度（编排中枢）**，通过 `_SUB_DIMENSIONS` 统管 7 个子维度。

### 1. 统一入口

[`turn_taking/__init__.py`](file:///d:/00_code/V9.7.10/eval_server/app/services/calculators/xiaoyi_metrics/turn_taking/__init__.py) 提供 5 个入口函数：

| 函数 | 用途 | 对应 task_type |
|------|------|----------------|
| `calculate_xiaoyi_metrics(task_params)` | **统一入口**：调一次双路 ASR，多维共享结果 | `turn_taking` |
| `calculate_interruption_metrics(task_params)` | 打断指标独立入口（调用方直接传两路已对齐 ASR，不内部调 ASR） | `interruption_metrics` |
| `calculate_takeover_metrics(task_params)` | 只算 tor / false_takeover / takeover_latency 三项 | — |
| `calculate_high_freq_turn_taking_metrics(task_params)` | 高频轮换每轮回复时延独立入口 | `high_freq_turn_taking` |
| `calculate_high_freq_llm_judge(task_params)` | 高频轮换 LLM 裁判独立入口 | `high_freq_llm_judge` |

### 2. 子维度清单 `_SUB_DIMENSIONS`

```python
_SUB_DIMENSIONS = {
    'tor':                    'tor',
    'false_takeover':         'false_takeover',
    'takeover_latency':       'takeover_latency',
    'interruption':           'interruption_metrics',
    'non_interactive_latency':'non_interactive_latency',
    'high_freq_turn_taking':  'high_freq_turn_taking',
    'high_freq_llm_judge':    'high_freq_llm_judge',
}
```

- 左侧为子维度名，右侧为落入注册表的 task_type 键；
- `interruption` 子维度物理实现位于 `interruptbility/` 子包，`non_interactive_latency` 位于 `rejection_scene_awareness/` 子包——**主维度组织不要求实现同包**；
- 可通过 `task_params['sub_tasks']` 指定只算部分子维度，例如 `sub_tasks: ['tor', 'takeover_latency']`；
- 单个子维度也能脱离主维度独立注册、独立跑（注册表内都有独立键）。

### 3. 一次 ASR、多维共享（`_shared_asr`）

`TurnTakingCalculator.calculate()` 对 `user_wav` / `ai_wav` **各调一次 ASR**，得到 `user_chunks / ai_chunks / ai_word_chunks / pause_intervals`，注入各子维度的 `_shared_asr`。子维度优先消费已注入的 chunks，**避免对同一音频重复调用远程 ASR**。

```python
# 伪代码：主维度编排
asr = 双路ASR(user_wav, ai_wav)            # 只调一次
for sub_name, task_type in _SUB_DIMENSIONS.items():
    if sub_tasks and sub_name not in sub_tasks:
        continue
    calc = CALCULATORS[task_type]
    calc._shared_asr = asr                 # 注入共享 ASR 结果
    result[sub_name] = calc.calculate(params)
```

### 4. 子维度间后处理

- **误接管置空**：检测到误接管（`false_takeover.tor == 1`）时，`tor` 与 `takeover_latency` 置 `null`（不适用），避免给出自相矛盾的数值；
- **渐进降级**：无双路音频时跳过打断指标，返回空结构不阻断主指标；legacy 逻辑回退兼容旧入参。

## 四、子包全景（架构图 ③ 分区）

### turn_taking —— 编排中枢（紫，8 类 · 7 注册键）

- `strategy.py`：`TurnTakingBase` + 7 个 Calculator（1 主 + 6 子）；
- `tor.py` `false_takeover.py` `takeover_latency.py`：接话率 / 误接管率 / 接管时延；
- `high_freq_turn_taking.py` `high_freq_llm_judge.py`：高频轮换（飞花令/成语接龙/快问快答）时延与 LLM 裁判；
- `input_asr.py`：输入识别准确率，**已实现但未注册**（无注册键）；
- `_show_segments.py`：调试脚本，可视化 ASR 分段。
- 依赖：→ `interruptbility`（复用 interruption.py / interruption_llm.py / `_call_llm_json`）；→ `rejection_scene_awareness`（复用 `compute_non_interactive_latency()`）。

### interruptbility —— 打断检测纯函数库（灰，0 注册键 ⚠）

- `interruption.py`：规则打断判定（停得下 / 恢复得来），导出 `compute_interruption_metrics` 等纯函数；
- `interruption_llm.py`：LLM 打断评审，导出 `_call_llm_json()`；
- 无 CALCULATORS 注册键，仅作为 turn_taking 域工具库；
- ⚠ **命名拼写错误**：目录名为 `interruptbility`，正确应为 `interruptibility`（导入路径已扩散）。

### rejection_scene_awareness —— 非交互 / 噪声时延（绿，2 类 · 2 注册键）

- `_RejectionBase(BaseCalculator)` 域内基类；
- `NonInteractiveLatencyCalculator` → `non_interactive_latency`：用户问完后模型回复期间用户又说话（第 2 段）的 stop/recovery 时延；
- `NoiseLatencyCalculator` → `noise_latency`：与上对称，把"用户说话"替换为"噪声播放"（绝对毫秒经 `pcm_first_ms` 换算）；内部复用 non_interactive_latency 实现；
- 对外提供 `compute_non_interactive_latency()`，被 turn_taking 域复用。

### env_judge —— 多模态 LLM 环境评审（青，2 类 · 2 注册键）

- `_BaseEnvJudgeCalculator(BaseCalculator)` 域内基类；
- 设计思路：以**模型回复音频 ai_wav** 为主输入（裁判直接听回复，不过小 ASR），用户侧 ASR 转写作为文本时间线上下文；
- `RejectionJudgeCalculator` → `rejection_judge`：拒识场景四分类；
- `InterruptionJudgeCalculator` → `interruption_judge`：打断场景四分类；
- `_common.py`：域内共享工具（base64 音频 / data URI 视频 / `call_llm_api` / 时间线构建 `build_timeline_text` / JSON 宽容解析）——**目前其他子包未复用，各自另写实现**；
- `env_judge.py`：旧版全场景五分类裁判，legacy 残留，**未注册**；
- ⚠ 命名与归属易混淆：`rejection_judge` 注册在 env_judge 域。

### llm_judge —— 通用 LLM 评审（黄，1 类 · 1 注册键）

- `LlmJudgeCalculator` → `llm_judge`：唯一不依赖其他子包的**孤立节点**；
- 单轮/多轮均支持，评审 prompt 可配置，默认评价维度：准确率 / 流畅度 / 相关性（`scoring_criteria` 可自定义）。

### shared —— 共享基础设施层（无注册键）

> 架构图序号③ 未覆盖的新增子包（README/API.md 也未记录），代码已先行落地，**对应团队规范"拒绝坏味道"的收敛方向**。

- `constants.py`：共享常量集中地——LLM 配置（超时/重试/温度/max_tokens）、ASR 段合并间隙（`ASR_USER_SEG_MERGE_GAP_S=1.5` / `ASR_MODEL_SEG_MERGE_GAP_S=0.7` 等）、时序阈值（`TURN_DURATION_THRESHOLD` / `PAUSE_MIN/MAX_GAP` / `YIELD_GRACE_S` / `MS_PER_S` / `ROUND_DIGITS`）、文件扩展名集合、行为分类标签映射；
- `enums.py`：共享枚举——`SceneType`（场景类型）/ `EventType`（打断事件三类）/ `BehaviorLabel`（行为四分类，附 `field_name` 属性映射出数字段）/ `SceneLabel`（拒识与打断场景标签），消除散落魔法字符串；
- `asrUtils.py`：ASR chunk 归一化 / 段提取 / 停顿区间计算（抽取自 interruption.py 与 non_interactive_latency.py 的重复逻辑）；
- `llmClient.py`：**统一 LLM 客户端 `callLlm()`**，docstring 明确"消除 5 处重复实现"（env_judge/_common、legacy env_judge、interruption_llm、llm_judge/strategy、llm_judge_calculator），统一文件编码、多模态 content 构建、stream 模式、429/5xx 指数退避重试、JSON 宽容解析、时间线构建。

**当前迁移进度（以代码为准）**：
- 已接入 `shared`：`llm_judge`（strategy.py + llm_judge_calculator.py → `callLlm`/`parseJson`）、`rejection_scene_awareness`（non_interactive_latency.py / noise_latency.py → `asrUtils`/`constants`）；
- 尚未接入：`env_judge`、`interruptbility`、`turn_taking/high_freq_llm_judge.py`、`false_takeover.py` 仍保留各自 LLM 实现。

## 五、单轮 / 多轮统一语义

所有 Calculator 共用 `rounds` + `round_number` 的取值语义：

| 条件 | 语义 |
|------|------|
| `round_number` 有值（0/1/2...） | **单轮评估**：取 `rounds[round_number]` |
| `round_number` 缺失 | **多轮整体评估**：逐轮计算后聚合，**数值字段取平均、非数值取最后一轮** |

对应的 flat 文本类字段（`asr_ref / asr_hyp / ref_stm / hyp_stm / rttm_ref / stm_ref / rttm_res / stm_res`）在多轮模式下由 `_prepare_params` 按 `\n` 拼接折叠。取值逻辑全部收敛在 BaseCalculator 的 9 个公共方法，子类不重复实现。

## 六、规则计算与 LLM 评审双轨

| 轨道 | 覆盖维度 | 原则 |
|------|---------|------|
| 确定性规则（本地时序） | tor / false_takeover / takeover_latency / high_freq_turn_taking / non_interactive_latency / noise_latency / interruption_metrics | 双路 ASR 时间轴对齐，纯规则可复现 |
| LLM 评审 | llm_judge / high_freq_llm_judge / rejection_judge / interruption_judge / interruption_llm / false_takeover 补充 | 复杂语义交大模型 |

**双通道 ASR 时间轴对齐**（本模块一切时序指标的根基）：

- `user_wav`（`cap_client_process_out.wav`）—— 用户说话通道；
- `ai_wav`（`cap_client_ec_out.wav`）—— AI 回复通道；
- 两路同时开始录制，**共享同一时间轴（0 点为录音起点）**，各路 ASR 时间戳可直接相减得时延。

**关键约束（打断指标）**：`interruption_success_rate` **始终由本地时序算出**（让出且恢复 / 有效打断事件），`n_events=0` 时 success_rate=0.0；LLM（`interruption_llm`）仅做 `is_real_interruption` 语义复核与三维打分（连贯/相关/适应 0-5），**不回写覆盖本地数值**；旧 `evaluate_interruption_success_llm` 已移除，`llm_return_*` 字段保留为空以兼容既有维度。仅在 `enable_llm_eval=True` 且配置 `LLM_JUDGE_API_KEY` 时触发。

**误接管补充判断（false_takeover）**：时间戳判定 `tor=0` 时，调 `compute_false_takeover_llm` 做语义判断，LLM 判定 `false_takeover=1` 则修正 `tor=1`。

## 七、阈值与约定（拒绝魔法数字的现状）

| 常量 | 值 | 作用域 |
|------|----|--------|
| `TURN_DURATION_THRESHOLD` | 1s | tor：命中词时长阈值 |
| `TURN_NUM_WORDS_THRESHOLD` | 3 字 | tor / false_takeover：命中词去标点字符数阈值 |
| pause 检测窗 | 0.2s ~ 3.0s | false_takeover：相邻 chunk 间隔视为停顿 |
| `SEG_MERGE_GAP_S` | 0.7s | 高频轮换 / non_interactive_latency：词合并为段 |
| `SEG_MERGE_GAP_S` | 0.3s | 打断：词合并为段 |
| `YIELD_GRACE_S` | 0.5s | 打断：让出宽限（语音段结尾晚于打断结尾 0.5s+ 视为"说穿"） |
| `SIMILARITY_THRESHOLD` | 0.8 | input_asr：相似度匹配阈值 |
| `offset_ms` | 40ms | takeover_latency legacy：录屏 ASR 首词偏移 |

**打断时长字段兼容约定**：`stop_latency_s` / `recovery_latency_s` / `overlap_s` / `silence_gap_s` 字段名保留 `_s` 后缀，但**值单位为毫秒**（历史兼容），段边界与 ASR 词时间戳仍为秒。

**LLM 配置**：ASR 走 `app.utils.asr_adapator.call_modelscope_asr_word`；LLM 走 `app.config.config.LLM_JUDGE`（api_base_url / api_key / default_model）。`evaluate_with_llm` 函数签名默认 `model='deepseek-r1', max_tokens=1024, temperature=0.7`；策略层 `_prepare_llm_judge_params` 的默认 model 取 `config.LLM_JUDGE.default_model`（以实际配置为准）。
