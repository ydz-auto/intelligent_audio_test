## 1. 背景与问题

在 voice_llm 改造的第 2 步（选用例）中，发现三个断层问题：

| 断层 | 现象 | 根因 |
|------|------|------|
| 分组能力半成品 | `groupNameType`/`customGroupName`/`inheritTags` 字段定义了但控制器未使用 | 字段未接入用例创建逻辑 |
| 多轮用例上传不支持 | `_create_test_case_from_audio` 只生成平面 config，无 `rounds` | 上传流程未透传 rounds 配置 |
| 标注→参考参数链路断开 | `apply_to_config` 因 `rounds` 为空而 no-op | 上传时未构建 rounds，导致参考参数不生成 |

**额外遗漏**：音频详情模态窗（DetailViewModal）不支持标注任意字段显示。

### 1.1 2026-07-07 新增问题

| 问题 | 现象 | 根因 |
|------|------|------|
| 蛇形/驼峰 key 混乱 | `roundNumber` 丢失、`algorithmParams`/`referenceParamsPath` 读取不一致 | NamingRequest 把所有 key 转蛇形，但 `TestCaseUploadConfig.rounds` 是 `List[Dict]` 没归一化，后端又用驼峰访问 |
| `spl: ""` 导致 400 | `test_case_config.rounds.0.audios.0.spl: Input should be a valid number` | 前端 `uploadOptions.spl` 是空字符串，pydantic `Optional[float]` 无法解析 |
| `PlaybackDevice` 作用域错误 | `cannot access local variable 'PlaybackDevice'` | `from ... import PlaybackDevice` 写在 `if` 块内部，作用域问题 |
| `_persist_annotations_and_raw` 缺 flush | 后续 SQL 查询查不到新标注 | `db.session.add()` 后没 flush，创建用例时标注还没入库 |
| 前端 `makeAudioConfig` 漏写字段 | `spl` 和 `playbackDeviceId` 收了参数但没写进 audios | 原始 bug |
| spl/playback_device_name 无法从标注提取 | 上传后 `audios[]` 里没有 spl 和 playback_device_id | 后端没有从标注 JSON 提取并注入的逻辑 |

## 2. 解决方案

### 2.1 分组能力 → 标签视图方案

**决策**：不改分组逻辑，给用例管理增加标签视图（`view=tag`）。

**理由**：
- 分组（TestCaseGroup）已有完整 CRUD，再改会造成逻辑混乱
- 用户真正需要的是"按标签维度查看用例"
- 标签视图是只读聚合视图，不影响数据结构

### 2.2 多轮用例上传 → rounds 透传

**架构**：

```
前端文件夹选择 → folderParser.ts 解析 → 构建 testCaseConfig.rounds
→ mergeChunks API 透传 → _create_test_case_from_audio(rounds_config=...)
→ config = { rounds: [...] } → ReferenceParamsGenerator.apply_to_config(tc)
```

**两种轮次模式**：

| 模式 | 触发条件 | rounds 结构 |
|------|---------|------------|
| `multi_round` | 单个音频的最子级文件夹 | 每个音频 = 一轮 |
| `single_round_multi_audio` | 多个音频的最子级文件夹 | 多音频同轮 |

**标注文件位置规则**：最子级文件夹的父级目录下，文件名 = 最子级文件夹名。

### 2.3 标注→参考参数 → 同步生成

**时机**：`_create_test_case_from_audio` 中，rounds 模式下同步调用 `ReferenceParamsGenerator.apply_to_config(new_tc)`。

**文件命名**：`{case_id}_round_{n}.json`，逐轮生成。

### 2.4 蛇形 key 统一 → pydantic schema 自动归一化

**决策**：后端统一用蛇形 key，pydantic schema 自动处理蛇形/驼峰双向兼容。

**架构**：

```
前端（驼峰或蛇形）
→ NamingRequest.normalize_keys_to_snake 递归转蛇形
→ pydantic APIModel（alias_generator=to_camel + populate_by_name=True）
→ RoundConfigItem（validation_alias=AliasChoices('round_number', 'roundNumber')）
→ model_dump(by_alias=False) 输出蛇形 dict
→ 后端代码统一用蛇形 key 访问
```

**关键改动**：
1. `TestCaseUploadConfig.rounds` 从 `List[Dict[str, Any]]` 改成 `List[RoundConfigItem]`，让 pydantic 自动归一化 key
2. `RoundConfigItem` 的所有字段用 `AliasChoices` 双向兼容蛇形和驼峰
3. `rounds_config` 用 `r.model_dump(exclude_none=True, by_alias=False)` 转回蛇形 dict 列表
4. 后端代码所有 `roundNumber` → `round_number`、`algorithmParams` → `algorithm_params`、`referenceParamsPath` → `reference_params_path`
5. 读取处兼容蛇形和驼峰：`round_item.get('reference_params_path') or round_item.get('referenceParamsPath')`

### 2.5 spl/playback_device_name 从标注提取 → 注入到 audios[]

**决策**：标注 JSON 的 segments 里写 `spl` 和 `playback_device_name`，后端提取并注入到 `rounds[].audios[]`，设备名按名字查表换 ID。

**四种模式都适用**：单轮单音频、单轮多音频、多轮每轮单音频、多轮每轮多音频。

**流程**：

```
标注 JSON segments[].spl / segments[].playback_device_name
→ 后端预查 PlaybackDevice 表，构建 dev_name_to_id 映射
→ 遍历 rounds_resolved[].audios[]，对缺 spl 或 playback_device_id 的 audio_item
→ 从 raw_annotations 的 segments 里提取
→ playback_device_name 查 dev_name_to_id 换成 playback_device_id
→ 兜底：e2e 且仍缺，用默认设备 / 默认 spl
```

**设备名而非 ID 的理由**：用户在标注 JSON 里写设备名（如 `"0.5m+180°"`）比写设备 ID 更直观，后端按名字查表换 ID。

### 2.6 标注任意字段显示 → 动态列

**常量**：

```typescript
const KNOWN_SEGMENT_FIELDS = ['speaker', 'start', 'end', 'text', 'duration', ...]
const KNOWN_DATA_KEYS = ['segments', 'text', 'annotations', 'timestamps', 'timestamps_global']
```

**策略**：已知字段专门列渲染，额外字段动态检测并显示为额外列 / 键值对编辑。

### 4.1d 后端 - NamingRequest 递归转蛇形

```python
class NamingRequest(FlaskRequest):
    def get_json(self, *args, **kwargs):
        data = super().get_json(*args, **kwargs)
        return normalize_keys_to_snake(data)

def normalize_keys_to_snake(data, depth=0):
    if isinstance(data, list):
        return [normalize_keys_to_snake(item, depth + 1) for item in data]
    if isinstance(data, dict):
        out = {}
        for k, v in data.items():
            key = k if _SNAKE_LIKE_KEY_RE.fullmatch(k) else to_snake(k)
            out[key] = normalize_keys_to_snake(v, depth + 1)
        return out
    return data
```

### 4.5 前端 - folderParser.ts 核心函数（含 spl/playback_device_id）

```typescript
export interface RoundAudioConfig {
  audio_name: string
  play_order: number
  spl?: number
  playback_device_id?: string
}

// 判定轮次模式
export function determineRoundMode(audioFiles: AudioFileInfo[]) {
  return audioFiles.length === 1 ? 'multi_round' : 'single_round_multi_audio'
}

// 构建 rounds 配置
export function buildRoundsConfig(audioFiles, allFiles, spl, playbackDeviceId) {
  const mode = determineRoundMode(audioFiles)
  const makeAudioConfig = (audio: AudioFileInfo, playOrder: number): RoundAudioConfig => {
    const cfg: RoundAudioConfig = {
      audio_name: audio.name,
      play_order: playOrder
    }
    // spl 为有效数字时才写入（空字符串/undefined 不传，后端从标注提取）
    if (spl != null && spl !== '' && !isNaN(Number(spl))) {
      cfg.spl = Number(spl)
    }
    if (playbackDeviceId) cfg.playback_device_id = playbackDeviceId
    return cfg
  }
  if (mode === 'single_round_multi_audio') {
    return [{ roundNumber: 1, audios: audioFiles.map((a, i) => makeAudioConfig(a, i)) }]
  } else {
    return audioFiles.map((audio, idx) => ({
      roundNumber: idx + 1,
      audios: [makeAudioConfig(audio, 0)]
    }))
  }
}
```
