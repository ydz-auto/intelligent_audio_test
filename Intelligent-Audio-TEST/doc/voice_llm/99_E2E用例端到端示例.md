## 测试场景

- **被测设备**：智能音箱（通过 ADB 控制）
- **测试目标**：全局背景噪声（跨轮持续）+ 干扰人环境下，3 轮语音交互的识别准确率与响应时延
- **环境参数**：每轮导轨距离 50cm、设备音量 70%；第 1 轮先做声纹注册
- **评估维度**：每轮 WER + LLM Judge；整体 WER（round_number=NULL）

## 一、前端配置

用户在 `CaseForm` 中填写，`test_type = 'e2e'`：

```
CaseForm (test_type = 'e2e')

│   └── 算法类型: voice_llm
│
├── 多轮配置 (RoundConfigEditor) — rounds[]
│   ├── 第 1 轮

│   │   ├── algorithmParams (case_algorithm_params 表驱动):
│   │   │   ├── rail_distance: 50            ← 导轨距离（env_device bundle）
│   │   │   ├── volume_level: 70             ← 设备音量（env_device bundle）
│   │   │   ├── interferers: [ {audio, spl, playback_device, start_delay, loop} ]
│   │   │   └── voiceprint: {audio, spl, playback_device, voiceprint_wait_time}

│   ├── 第 2/3 轮: 同上（第 2 轮 voiceprint_enabled: false 跳过注册）
│   └── ...
│
├── 全局背景噪声 (case 级)
│   └── background_noise: {audio, spl, playback_device_names[], loop}
│
└── 整体评估维度
    └── WER (dim_1, weight=50)
```

### 参数代码命名约定（camelCase ↔ snake_case）

前端 `AlgorithmConfigModal.vue` 的 `PARAM_CODE_PRESETS` 使用 **camelCase** 参数代码：

| 前端参数代码 (camelCase) | 入库 field_code (snake_case) | 编辑器 | 说明 |
|---|---|---|---|
| `railDistance` | `rail_distance` | slider 10~200 (step 5, 单位 cm) | 导轨距离，FEATURE_BUNDLES.env_device |
| `volumeLevel` | `volume_level` | slider 0~100 | 设备音量，FEATURE_BUNDLES.env_device |
| `voiceprint` | `voiceprint` | audio_select | 声纹注册配置（单对象） |
| `interferers` | `interferers` | audio_select (默认 `'[]'`) | 干扰人数组 |
| `promptAudioId` | `prompt_audio_id` | audio_select | 提示音 |

转换发生在**请求层**：前端提交的 JSON body 经 `NamingRequest.normalize_keys_to_snake` 自动将 camelCase key 转为 snake_case 后入库。因此：

- 前端组件/代码只见 camelCase（`railDistance`）
- 后端 Config JSON / `case_algorithm_params.field_code` / executor 全部使用 snake_case（`rail_distance`）

## 三、执行流程

用户点击"创建任务" → `ExecutionEngine` 调度 → `E2EExecutor.execute_e2e_case(task_id='task_001', case_id=101)` → `_execute_e2e_with_rounds()`。

### 六阶段总览

```
阶段一   _prepare_rounds          设备并行初始化 + 预创建 TestResult（result_id）
阶段1.5  start_background_noise   全局背景噪声启动（跨轮持续，player_key='bg_noise_<device_index>'）
阶段二   _run_rounds_loop         多轮循环，每轮 _execute_single_round
阶段三   _finalize_rounds         结果聚合 + 最终写入 + 整体评估触发
阶段3.5  finally: stop_background_noise   只停 bg_noise_ 前缀 player
阶段四   finally: teardown_devices        设备统一清理
```

### 阶段一：_prepare_rounds（预创建）

```
get_device_info → register_task_devices → initialize_devices(first_round_params 透传)
→ _save_result 预创建 TestResult:
    result_id = 501
    execution_status = 'running'
    result_data = { multi_round: True, total_rounds: 3 }
    algorithm_result = {
      test_type: 'e2e', algorithm_type: 'voice_llm',
      total_rounds: 3, rounds: [], aggregated: {}
    }
```

> 三段式写入的第 1 段：先拿到 `result_id`，后续每轮增量更新同一行，不再"执行完一次性建结果"。

### 阶段1.5：全局背景噪声启动

`playback_orchestrator.start_background_noise(case_config, task_id)`：

```
build_noise_info({}, case_config)     # 强制取 case 级 background_noise
→ build_noise_play_configs            # loop=True, is_noise=True, type='noise'
→ 按 device_index 分组 play_multi，提交线程池
   player_key = 'bg_noise_<device_index>'   # 不走 play_overlap，避免与轮次播放冲突
→ 等待 playback_started_event (timeout=60s)
```

全局噪声**跨轮持续**，直到阶段 3.5 才停止。

### 阶段二：每轮 _execute_single_round（以第 1 轮为例）

```
Step 0  round_algo_params = _normalize_algorithm_params(round_config['algorithm_params'])
        → { rail_distance: '50', volume_level: '70', interferers: [...], voiceprint: {...} }

Step 1  环境设备（导轨）
        _device_manager.setup_env_devices_for_round(round_algo_params, task_id)
        _ENV_DEVICE_PARAM_MAP = { 'rail_distance': ('rail', λ v → {'distance_cm': float(v)}) }
        → EnvDeviceFactory.create('rail') → dev.is_available() → dev.setup()
        → 返回 env_states（供第 9 步恢复）

        ※ executor 不直接调用 device_driver.move_rail / set_volume：
          - 导轨由 EnvDeviceFactory 抽象设备管理（setup/teardown）
          - 音量由设备驱动 pre_process/post_process 生命周期自管理

Step 2  声纹注册（每轮）
        _register_voiceprint(task_id, tc_rel_id, round_algo_params, test_case_id)
        voiceprint 单对象归一化:
          { audio_id, playback_device_id, spl(默认70.0), wait_time(默认5.0) }
        → playback_orchestrator.play_voiceprint:
          DB 加载 PlaybackDevice/Audio → get_device_index → resolve_spl_gain
          → play_overlap → 等待 playback_started_events → sleep(wait_time)
        → 失败 raise RuntimeError 中止整个测试

Step 3  设备预处理
        pre_process_devices(device_info_list, task_id,
                            extra_params={round_number: 0, total_rounds: 3,
                                          **round_algo_params})
        → 设备驱动开始录音/监听，音量设置在此生命周期内完成

Step 4  play_round（playback_orchestrator）
        ① resolve_dry_audios(round.audios)   # 过滤 noise 类型音频，按 play_order 排序
        ② 全局噪声已启动 → 跳过轮次级背景噪声
        ③ build_dry_configs:
             round1.wav → { file, device_index: 3, channel: 0, gain: 0.72,
                            offset: 0, duration, play_order: 1,
                            loop: False, is_noise: False, type: 'dry', audio_id }
             # playback_device_id → DB 加载 PlaybackDevice → get_device_index
             # resolve_spl_gain(spl_mapping_id, spl=65) → SPL 转软件增益
        ④ interferers 从 round_algo_params 读取 → build_interferer_configs:
             someone_talking.wav → { ..., gain: 0.60, delay: 1.0,
                                     is_noise: True, type: 'interferer' }
             # start_delay 单位启发式：>100 视为毫秒
             # type='interferer' 不参与交叠时间轴；单个配置不完整仅 WARNING 跳过
        ⑤ 5.1 步：跳过与全局噪声同 device_index 的干扰人
             # 同一 PortAudio 设备无法同时开两个输出流（dev_lock 死锁）
        ⑥ 合并统一 audio_to_play 列表 → play_overlap → play_multi 按设备分组并行
        ⑦ 等 playback_started_events → sleep(total_duration)（干声时长）
        ⑧ stop_task_audio(task_id, player_type='device_*')
             # 只停本轮 device_* player，保留 global_noise_*（全局噪声继续）
        ⑨ timeline 写入 playback_start_time_ms / playback_end_time_ms（毫秒级）

Step 5  _collect_playback_timestamps(task_id, play_result, case_config)
        → executor._playback_timestamps[task_id] 缓存毫秒级时间戳

Step 6  设备后处理
        post_process_devices(..., extra_params={
            round_number, total_rounds, **round_algo_params,
            playback_start_time_ms, playback_end_time_ms,
            playback_timestamps_detail: [ {audio_id, play_order, start_ms, end_ms} ]
        })
        → 设备驱动停止录音、上传音频，按毫秒时间戳统计时延

Step 7  每轮结果收集
        _collector.collect_results(task_id, test_case_id, device_info_list,
                                   algorithm_type, case_reference_params, round_algo_params)
        内部（E2ECollector）:
          ① 从 executor._playback_timestamps 取时间戳
          ② _calculate_actual_offset（actual_time − record_start_time − theory_offset，
             key="{audio_id}_{play_order}"，由独立 TimestampAligner 完成对齐）
          ③ extra_params 注入 playback_time_offsets / reference_params /
             playback_start_time_ms / playback_end_time_ms / playback_timestamps_detail
          ④ 委托 DeviceResultCollector.collect_raw_results
          ⑤ 按 result_type 提取 adjusted_reference_params
        → 返回 (round_results, adjusted_case_ref_params)

Step 8  字段映射 + 标记轮次
        r['round_number'] = 0
        get_device_result_collector().convert_results(tagged_results, algorithm_type)
        → raw 字段映射为 target 字段（output_text / question_text 等）
        → 同时生成维度专属 key（target__dim_N）

Step 9  单轮提交（三段式写入的第 2 段）
        _build_and_submit_round_data(...):
          round_data = {
            round: 0,
            input:  { audio_name: 'round1.wav', audio_path: '...', type: 'audio' },
            output: { output_text: '今天天气怎么样', output_text__dim_1: '...' },
            latency: 2.1,
            evaluation: {}
          }
          → update_test_result(result_id, algo_result={...rounds 累积...},
                               execution_status='running')     # 增量覆盖写
          → 单轮评估 _evaluate_result(round_number=0)          # 见第五节

Step 10 环境设备恢复（导轨复位）
        teardown_env_devices_for_round(env_states, task_id) → dev.teardown(state)
```

**第 2 轮差异**：`voiceprint_enabled: false` → Step 2 跳过注册；干声换 round2.wav。
**第 3 轮差异**：干声换 round3.wav，其余同第 1 轮结构。

任一轮失败：`_run_rounds_loop` 记录失败 round_data 后 `break`，不再执行剩余轮次（已执行轮次的结果保留）。

### 阶段三：_finalize_rounds（聚合与最终写入）

```
① get_final_results(rounds_data, all_round_results, case_config) 覆写优先
     # 算法定制 final 提取器（返回非 False 时替代默认逐轮聚合，
     # 走 raw_results → 包装 → convert_results）
② _aggregator.build_algorithm_result(task_id, all_round_results, case_config, algorithm_type)
     # 构建 { test_type, algorithm_type, total_rounds, rounds[], aggregated }
③ write_result_data_file(...)
     # 持久化 { multi_round, total_rounds, raw_results_list,
     #          adjusted_reference_params? } → result_data_path
④ update_test_result(result_id, algo_result,
                     execution_status='completed'/'failed',
                     response_time=总耗时, result_data_path=...)   # 三段式第 3 段
⑤ rounds[].evaluation 回填:
     _has_round_dims → update_algorithm_result_evaluation(result_id)
       # 从 DB 查各轮 TestResultDimension，回填 rounds[round_idx].evaluation
⑥ 整体评估:
     _has_overall_dims（case 级 dimensions 非空）→ _evaluate_result(round_number=None)
⑦ process_results → 更新 TaskCase 状态（completed/failed/pending）
```

### 阶段 3.5 / 四：finally 清理

```
finally:
    stop_background_noise(task_id)   # 只停 bg_noise_ 前缀 player，全局噪声停止
    teardown_devices(...)            # 设备统一清理（关闭驱动、释放资源）
```


字段来源：

| 字段 | 来源 |
|---|---|
| `rounds[].input/output/latency` | `_build_and_submit_round_data`（target 字段映射自 `convert_results`） |
| `rounds[].wait_time` | `round_config.waitTime`（默认 5000，`build_algorithm_result` 补写） |
| `rounds[].evaluation` | `update_algorithm_result_evaluation` 从 DB 回填（维度名小写+下划线 → score） |
| `aggregated.avg_latency` | `build_algorithm_result` 直接算术平均（4 位小数） |
| `aggregated.avg_wer / avg_llm_judge` | `RoundAggregator` 聚合后经 `_update_algorithm_result_aggregated` **合并**写入（构建时为 null 占位） |

> 旧结构中的 `session_id` / `rail_distance`（顶层）/ `voiceprint_registered` / `rounds[].interruption`（打断）字段**已移除**；打断统计不再存在于结果链路。

### 4.2 三段式写入时序

```
_prepare_rounds              每轮 _build_and_submit_round_data        _finalize_rounds
（预创建，第 1 段）            （增量 update，第 2 段）                  （最终写，第 3 段）
─────────────────           ──────────────────────────────          ─────────────────────
result_id=501                rounds=[R0] → rounds=[R0,R1] → ...      algo_result 最终态
execution_status='running'   execution_status='running'              execution_status='completed'
rounds=[]                    + 单轮评估触发                            response_time / result_data_path
```

### 4.3 result_data 文件（raw 明细落盘）

`_finalize_rounds` 的 `write_result_data_file` 将原始明细持久化：

```json
{
  "multi_round": true,
  "total_rounds": 3,
  "raw_results_list": [ "...每轮 raw_results（含 device_raw/timestamps）..." ],
  "adjusted_reference_params": { "...按 result_type 提取的校正后参考参数..." }
}
```

路径写入 `TestResult.result_data_path`。

### 4.4 TestResultDimension 记录

每轮评估产生 2 条维度记录（WER / LLM Judge），3 轮共 6 条 + 1 条整体：

```
TestResultDimension 表:
┌─────┬──────────────┬──────────┬───────┬─────────────────────────────────┐
│ id  │ dimension_name│ round_number │ score │ raw_value                          │
├─────┼──────────────┼──────────┼───────┼─────────────────────────────────┤
│ 501 │ WER          │ 0        │ 95.0  │ {"wer": 0.05, "errors": [...]}     │
│ 502 │ 回答质量评估  │ 0        │ 4.5   │ {"scores":{...}, "reasoning":"..."}│
│ 503 │ WER          │ 1        │ 88.0  │ {"wer": 0.12, "errors": [...]}     │
│ 504 │ 回答质量评估  │ 1        │ 3.5   │ {"scores":{...}, "reasoning":"..."}│
│ 505 │ WER          │ 2        │ 97.0  │ {"wer": 0.03, "errors": [...]}     │
│ 506 │ 回答质量评估  │ 2        │ 4.9   │ {"scores":{...}, "reasoning":"..."}│

└─────┴──────────────┴──────────┴───────┴─────────────────────────────────┘
```

> `round_number=NULL` 记录由 `RoundAggregator.aggregate_round_results` 写入：仅当整体记录不存在、或已存在但 score 为 NULL（兜底）时创建/覆盖；已有整体评估结果**不会被聚合覆盖**（尊重 get_final_results/定制评估的优先级）。

## 五、评估数据流详解

评估是**异步**的：executor 每轮结束即提交单轮评估，经 `evaluation_service` 的 **EndpointWorker 队列**分发到 eval_server，结果回调写回 DB。

```
E2EExecutor                  evaluation_service / EndpointWorker          eval_server (5001)
    │                              │                              │
    │  第 0 轮 Step 9               │                              │
    │──_evaluate_result(           │                              │
    │    round_number=0)           │                              │
    │                              │                              │
    │                  _submit_to_endpoint_worker                  │
    │                  → worker(按 endpoint_url 缓存)              │
    │                    .task_queue.put(task_data)                │
    │                              │                              │
    │                  EndpointWorker._worker_loop                 │
    │                  (max_concurrent 消费线程)                    │
    │                  TestResultDimension 状态流转:                │
    │                    queued → running                          │
    │                              │                              │
    │                  api_request_handler.create_task             │
    │                  POST /api/create_task (multipart)           │
    │                  音频字段提取: 单轮提顶层 / 多轮 rounds_{idx}_{field} │
    │                              │──WER: task_type='wer' ────────► wer_calculator
    │                              │     → WER=0.05 → score=95.0   │
    │                              │──LLM Judge: task_type='llm_judge'
    │                              │     → llm_judge_calculator ──► GPT-4
    │                              │       overall_score=4.5       │
    │                              │◄──回调: score + raw_value ────┤
    │                  写入 TestResultDimension(round_number=0,    │
    │                  evaluation_status='completed')              │
    │                              │                              │
    │  第 1/2 轮同上 (round_number=1/2)                             │
    │                              │                              │
    │  所有轮次维度完成               │                              │
    │                  EvaluationResultProcessor                   │
    │                    .update_task_case_status()                │
    │                  → is_multi_round_result? (round_number      │
    │                     IS NOT NULL 的维度记录存在) → true        │
    │                  → check_all_round_dimensions_completed?     │
    │                     (无 pending 状态) → true                 │
    │                  → RoundAggregator.aggregate_round_results() │
    │                    按维度名分组，completed 记录取算术平均:       │
    │                      WER:       (95+88+97)/3 = 93.33         │
    │                      LLM Judge: (4.5+3.5+4.9)/3 = 4.3        │
    │                    → 写 avg_{dim_name} 维度记录               │
    │                    → round_number=NULL 整体记录(不覆盖已有)    │
    │                    → _update_algorithm_result_aggregated     │
    │                       合并写入 algorithm_result.aggregated    │
    │                    → 附 round_count / completed_rounds       │
    │                              │                              │
    │  executor._finalize_rounds    │                              │
    │    update_algorithm_result_evaluation()                      │
    │    → 从 DB 回填 rounds[].evaluation                           │
    │    → _evaluate_result(round_number=None) 整体评估             │
```

要点：

- **每轮即时评估**：单轮评估在 `_build_and_submit_round_data` 内触发，不等全部轮次结束
- **整体评估双重来源**：executor `_finalize_rounds` 直接提交 `round_number=None` 的整体评估（case 级 dimensions）；`RoundAggregator` 聚合结果仅作兜底/补充，不覆盖已有整体记录
- **按端点排队**：EndpointWorker 以 `endpoint_url` 为键缓存，队列串行 + `max_concurrent` 并发消费，避免打爆评估端点

## 七、完整数据流总结

```

testcase_controller（双记录 CRUD）

  ▼
ExecutionEngine 调度 → E2EExecutor._execute_e2e_with_rounds
  │
  ├─ 阶段一  _prepare_rounds：设备并行初始化 + 预创建 TestResult(result_id)

  └─ 阶段四 finally teardown_devices
           │
           ▼
评估异步链路
  EndpointWorker 队列(按 endpoint_url) → queued → running
  → api_request_handler.create_task (multipart)
  → 回调写 TestResultDimension(round_number=N)

           ▼
```

## 关键设计要点回顾

| 要点 | 体现 |
|------|------|
| 命名分层 | 前端 camelCase（railDistance）→ NamingRequest 请求层转 snake_case → Config/DB/executor 全 snake_case（rail_distance），Infrastructure 层唯一知道存储格式 |
| 配置驱动 | round 顶层放结构性字段（roundNumber/audios/evaluation/referenceParamsPath），`algorithm_params` 放表驱动参数，新增参数只需 INSERT case_algorithm_params |
| 三段式写入 | 预创建拿 result_id → 每轮增量 update（running）→ 最终写（completed + result_data_path），中断也有部分结果 |
| 统一音频模型 | 干声/噪声/干扰人统一 `{file, device_index, channel, gain, delay, loop, is_noise, type}` 走 `play_overlap` → `play_multi` |
| 全局噪声共存 | case 级噪声跨轮持续（bg_noise_<dev>），轮次播放只停 device_*；与全局噪声同设备的干扰人自动跳过（PortAudio dev_lock 防死锁） |
| 环境设备抽象 | 导轨经 EnvDeviceFactory（setup/teardown + 状态恢复），executor 不碰 device_driver.move_rail；音量由驱动 pre_process/post_process 自管理 |
| SPL 增益配置化 | spl → spl_service.spl_to_gain(mapping_id, spl)，无 mapping 时 gain=1.0 |
| 毫秒级时间戳 | playback_start_time_ms / playback_end_time_ms / playback_timestamps_detail 贯穿 post_process → collect_results → 设备驱动时延统计 |
| 单轮 + 整体评估 | 每轮评估（round_number=N）在轮次内即时提交；整体评估（round_number=None）由 executor 提交，RoundAggregator 聚合仅兜底不覆盖 |
| 聚合职责分离 | avg_latency 由 build_algorithm_result 直接计算；avg_wer/avg_llm_judge 由 RoundAggregator 查 DB 聚合合并；报告层亦可直查 DB |
| 评估异步化 | EndpointWorker 按 endpoint_url 排队 + max_concurrent 并发消费，multipart 文件上传（多轮 rounds_{idx}_{field} 命名） |
