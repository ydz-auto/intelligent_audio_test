# 模态窗文本选择闪退问题修复文档

## 问题描述

在模态窗内的 `<input>` / `<textarea>` 等文本输入框中，用户使用鼠标拖选文本时，模态窗会立即关闭（闪退），导致用户无法正常选择和编辑文本内容。

## 根因分析

### 核心原因：Vue 3 原生 DOM 事件与组件自定义事件的冲突

问题出在 `GlobalModalContainer.vue` 中对子组件的事件监听方式。

#### 事件触发链路

```
用户在 input 中拖选文本
  → 浏览器触发原生 select DOM 事件（HTML 标准行为）
  → 事件冒泡到子组件根元素
  → Vue 3 将 @select 同时作为原生事件监听器绑定到子组件根元素
  → 触发 GlobalModalContainer 中的 @select 处理器
  → 执行 handleClose(modalId)
  → 模态窗关闭（闪退）
```

#### Vue 3 事件机制说明

Vue 3 中，当父组件使用 `@eventName` 监听子组件事件时：

- 如果子组件在 `defineEmits` 中声明了 `eventName`，则 `@eventName` 仅作为自定义事件监听器
- 如果子组件**未在** `defineEmits` 中声明 `eventName`，则 `@eventName` 会**同时**作为原生 DOM 事件监听器绑定到子组件的根元素

在 `GlobalModalContainer.vue` 中，`@select` 被用于监听子组件的自定义 `select` 事件（如 AudioSelectModal 的音频选择回调），但大部分子组件（如 CRUDFormModal、SPLCalibrationModal 等）并未在 `defineEmits` 中声明 `select` 事件。因此，`@select` 被同时绑定为了原生 DOM 事件监听器。

当用户在 input 中选择文本时，浏览器触发的原生 `select` 事件冒泡到子组件根元素，被 `@select` 监听器捕获，导致模态窗被意外关闭。

### 次要原因：BasicModal.vue 中的事件处理干扰

1. **`handleMouseUp` 函数**：在鼠标释放时调用 `window.getSelection().removeAllRanges()` 清除文本选区，干扰了正常的文本选择操作
2. **`handleKeyDown` 中阻止 Ctrl+A**：阻止了用户在模态窗内使用 Ctrl+A 全选文本的操作

## 修复方案

### 1. GlobalModalContainer.vue — 过滤原生 DOM 事件

在 `<script>` 中定义 `isNativeEvent` 辅助函数，通过检测对象属性特征判断是否为原生 DOM 事件：

```typescript
const isNativeEvent = (data: any): boolean => {
  return data !== undefined && data !== null
    && typeof data === 'object'
    && data.target !== undefined
    && data.type !== undefined
    && typeof data.preventDefault === 'function'
}
```

在所有事件处理器中调用 `isNativeEvent(data)` 过滤掉原生 DOM 事件，仅处理组件自定义事件：

```vue
@select="(data: any) => {
  if (isNativeEvent(data)) return;  // 过滤原生 select 事件
  modalItem.resolve(data);
  handleClose(modalId);
}"
```

同样对 `@close`、`@confirm`、`@cancel`、`@save`、`@selectMultiple` 都添加了相同的保护。

> **注意**：不能在 Vue 模板中直接使用 `data instanceof Event`，因为 `Event` 构造函数不在 Vue 模板的执行上下文中，会导致 `TypeError: Right-hand side of 'instanceof' is not an object` 错误，使所有模态窗按钮失效。

### 2. BasicModal.vue — 移除干扰性事件处理

- 移除 `@mouseup="handleMouseUp"` 事件绑定
- 移除 `handleMouseUp` 函数（该函数会清除文本选区）
- 移除 `handleKeyDown` 中对 Ctrl+A 的阻止逻辑
- 保留 Escape 键关闭模态窗的功能

### 3. main.css — 添加文本选择保护样式

为模态窗内的输入元素添加 `user-select: text` 样式，确保文本选择功能正常：

```css
.trae-browser-inspect-draggable {
    user-select: text !important;
    pointer-events: auto !important;
}

.modal input,
.modal textarea,
.modal-overlay input,
.modal-overlay textarea {
    user-select: text !important;
    pointer-events: auto !important;
}
```

## 修改文件清单

| 文件 | 修改内容 |
|------|----------|
| `frontend/src/components/common/modal/GlobalModalContainer.vue` | 定义 `isNativeEvent` 辅助函数；所有事件处理器添加 `if (isNativeEvent(data)) return;` 原生事件过滤 |
| `frontend/src/components/common/modal/BasicModal.vue` | 移除 `handleMouseUp` 函数及其绑定；移除 Ctrl+A 阻止逻辑 |
| `frontend/src/assets/styles/main.css` | 添加模态窗内输入元素的文本选择保护样式 |

## 影响范围

- 所有通过 GlobalModalContainer 渲染的模态窗组件
- BasicModal 基础模态窗组件
- 模态窗内的所有文本输入交互
- 模态窗的取消、关闭、确认等按钮

## 测试验证

修复后应验证以下场景：

1. ✅ 在 CRUDFormModal 的 input 字段中拖选文本，模态窗不关闭
2. ✅ 在 SPLCalibrationModal 的 input 字段中拖选文本，模态窗不关闭
3. ✅ 在模态窗内使用 Ctrl+A 全选文本
4. ✅ AudioSelectModal 的自定义 select 事件仍能正常触发
5. ✅ Escape 键仍能正常关闭模态窗
6. ✅ 点击遮罩层关闭模态窗（maskClosable 模式）仍正常
7. ✅ 点击关闭按钮仍能正常关闭模态窗
8. ✅ 点击取消按钮仍能正常关闭模态窗
9. ✅ 点击确认/保存按钮仍能正常提交并关闭模态窗
