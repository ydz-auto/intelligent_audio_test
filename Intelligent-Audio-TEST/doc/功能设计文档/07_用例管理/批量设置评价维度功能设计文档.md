# 批量设置评价维度功能设计文档

## 1. 概述

### 1.1 文档目的

本文档描述智能语音测试系统中"批量设置评价维度"功能模块的详细设计。该功能允许用户在用例列表页选中多个用例后，通过模态窗统一配置各轮次的单轮评估维度和多轮整体评估维度。

### 1.2 功能定位

批量设置评价维度功能位于用例管理的批量操作流程中，主要解决以下场景需求：

- **多轮独立配置**：不同轮次可设置不同的评估维度（如第1轮评估准确率，第2轮评估响应延迟）
- **最后一轮动态解析**：用 `-1` 代表"最后一轮"，按每个用例的实际轮次数动态解析（2轮用例的最后一轮是第2轮，3轮用例的最后一轮是第3轮）
- **整体评估维度**：支持配置跨轮次聚合的整体评估维度（`config.dimensions`），与单轮维度独立
- **灵活清空**：不选任何维度即清空对应位置的评估维度

### 1.3 术语定义

| 术语 | 解释 |
|------|------|
| 单轮评估维度 | 写入 `config.rounds[n].evaluation.dimensions`，仅对该轮测试结果生效 |
| 多轮整体评估维度 | 写入 `config.dimensions`，基于所有轮次的整体表现进行评估 |
| 最后一轮 | 用 `-1` 表示，后端按用例实际轮次数动态解析为最后一轮 |
| 逐轮设置模式 | 每个轮次独立配置维度，未选维度的轮次会被清空 |
| 统一设置模式 | 所有轮次或选中轮次使用同一套维度 |

## 2. 模态窗交互设计

### 2.1 三种轮次范围模式

模态窗"单轮评估维度 - 轮次范围"区域提供三种单选项：

| 模式 | 说明 | 未选维度的轮次 |
|------|------|---------------|
| 所有轮次（统一设置） | 所有轮次使用同一套维度 | 全部清空 |
| 指定轮次（统一设置） | 选中的轮次使用同一套维度，支持"最后一轮"选项 | 不受影响 |
| 逐轮设置（每轮可不同） | 每个轮次 Tab 独立配置维度 | 清空 |

### 2.2 逐轮设置模式

选中"逐轮设置"后，下方出现轮次 Tab 页签：

- **轮次 Tab**：第1轮、第2轮、...、最后一轮，每个 Tab 显示已选维度数量的角标
- **动态增减轮次**：每个 Tab 右侧有 × 关闭按钮（至少保留1轮），末尾有"+ 添加轮次"按钮
- **快捷操作工具栏**：
  - 从其他轮次复制：将其他轮次的维度配置复制到当前轮次
  - 清空当前轮次：清除当前轮次的所有维度
  - 应用到所有轮次：将当前轮次的维度配置应用到所有其他轮次
- **最后一轮 Tab**：用 `-1` 表示，后端叠加合并到用例实际最后一轮（去重，已有的维度保留，"最后一轮"中有但目标轮次没有的维度补充进来）

### 2.3 多轮整体评估维度

模态窗底部独立区域"多轮整体评估维度（跨轮次聚合）"：

- 独立选择维度和配置权重/阈值
- **不选任何维度即清空**已有的 `config.dimensions`
- 与单轮维度互不干扰

### 2.4 提示文字

| 位置 | 提示内容 |
|------|---------|
| 轮次范围（逐轮设置） | 逐轮设置模式下，未选维度的轮次将被清空 |
| 轮次范围（统一模式） | 不选任何维度点确定即清除选中轮次的评估维度 |
| 整体评估维度 | 不选任何维度将清空已有的整体评估维度 |

## 3. 数据流设计

### 3.1 前端数据结构

```typescript
// 模态窗 handleConfirm 发出的数据
{
  dimensions: [],              // 统一模式下的维度列表（per_round 模式下为空数组）
  testType: 'api' | 'e2e',
  roundMode: 'all' | 'specific' | 'per_round',
  roundNumbers: number[],     // specific 模式下选中的轮次（含 -1）
  roundDimensions: {          // per_round 模式下各轮次的维度
    1: [{ id, name, weight, threshold }],
    2: [...],
    '-1': [...]              // 最后一轮
  },
  multiDimensions: []         // 整体评估维度（空数组=清空，始终发送）
}
```

### 3.2 后端请求体

```json
{
  "action": "update_dimensions",
  "ids": ["uuid1", "uuid2"],
  "dimensions": [],
  "test_type": "e2e",
  "round_mode": "per_round",
  "round_numbers": [],
  "round_dimensions": {
    "1": [...],
    "2": [...],
    "-1": [...]
  },
  "multi_dimensions": []
}
```

> **注意**：JSON 序列化后 `round_dimensions` 的 key 全部为字符串（`"1"`、`"2"`、`"-1"`），后端用 `str(rn)` 查找。

### 3.3 数据存储位置

| 数据 | 存储位置 | 说明 |
|------|---------|------|
| 单轮维度 | `config.rounds[n].evaluation.dimensions` | 每轮独立 |
| 整体维度 | `config.dimensions` | 跨轮次聚合 |

## 4. 后端处理逻辑

### 4.1 入口函数

`TestCaseController._batch_update_dimensions(req_data)`

### 4.2 参数解析

```python
round_mode = getattr(req_data, 'round_mode', None) or 'all'
round_numbers = getattr(req_data, 'round_numbers', None) or []
round_dimensions = getattr(req_data, 'round_dimensions', None) or {}
multi_dimensions = getattr(req_data, 'multi_dimensions', None)
dimensions_data = getattr(req_data, 'dimensions', None)
```

### 4.3 校验规则

| 条件 | 结果 |
|------|------|
| 非 per_round 模式且 dimensions 为 None 且 multi_dimensions 为 None | 报错 |
| per_round 模式且 round_dimensions 为空且 multi_dimensions 为 None | 报错 |

### 4.4 轮次维度写入逻辑

```
for each test_case:
    last_rn = len(rounds)  # 用例实际轮次数

    if round_mode == 'per_round':
        # 逐轮设置：遍历所有轮次，每轮写入对应维度
        for round_item in rounds:
            rn = round_item.round_number
            dims = round_dimensions[str(rn)] or []
            if rn == last_rn and round_dimensions["-1"]:
                # 最后一轮：叠加合并 -1 的维度（去重）
                dims = merge(dims, round_dimensions["-1"])
            round_item.evaluation.dimensions = dims

    elif dimensions_data is not None:
        # 统一模式：所有/指定轮次共用同一套维度
        for round_item in rounds:
            if round_mode == 'specific' and rn not in round_numbers:
                if not (rn == last_rn and -1 in round_numbers):
                    continue  # 未选中的轮次跳过，不受影响
            round_item.evaluation.dimensions = dimensions_data

    # 整体评估维度：非 None 就写入（空列表=清空）
    if multi_dimensions is not None:
        config.dimensions = multi_dimensions
```

### 4.5 最后一轮叠加合并规则

当用例的某轮是最后一轮（`rn == last_rn`）时：

1. 先取 `round_dimensions[str(rn)]` 的维度作为基础
2. 再取 `round_dimensions["-1"]`（最后一轮 Tab）的维度
3. 按 `id` 去重合并：基础轮次已有的维度保留，"最后一轮"中有但基础轮次没有的维度补充进来

**示例**：2轮用例，第2轮选了维度A、B，最后一轮选了维度B（权重不同）、C
- 最终第2轮维度 = A（第2轮权重）、B（第2轮权重）、C（最后一轮权重）

### 4.6 超出用例实际轮次的处理

如果模态窗设了第3轮的维度，但用例只有2轮，第3轮的数据**自动丢弃**（后端只遍历用例实际存在的 rounds 数组）。

## 5. 前端实现

### 5.1 涉及文件

| 文件 | 职责 |
|------|------|
| `BatchDimensionModal.vue` | 模态窗 UI 组件，管理三种模式的状态和用户交互 |
| `useBatchActions.ts` | 批量操作 composable，接收模态窗结果并调用 store |
| `testCaseStore.ts` | Pinia store，发送 HTTP 请求并同步本地状态 |

### 5.2 分支逻辑（useBatchActions.ts）

```
if roundMode == 'per_round' && roundDimensions:
    # 逐轮模式：传递 roundDimensions + multiDimensions（含空数组）
elif roundMode == 'per_round' && multiDimensions:
    # 逐轮模式但只设了整体维度（含空数组=清空）
else:
    # 统一模式：传递 dimensions + multiDimensions（含空数组）
```

### 5.3 本地状态同步（testCaseStore.ts）

HTTP 请求成功后，前端本地状态同步更新：

- **per_round 模式**：遍历用例的 rounds，每轮按 `roundDimensions[rn]` 写入；最后一轮叠加 `-1` 的维度
- **统一模式**：选中的轮次写入统一维度，未选中的轮次不动
- **整体维度**：`multiDimensions !== undefined` 时写入 `config.dimensions`（空数组=清空）

## 6. 各模式行为矩阵

| 操作 | 所有轮次（统一） | 指定轮次（统一） | 逐轮设置 |
|------|----------------|----------------|---------|
| 选了维度A、B | 所有轮次写入A、B | 选中轮次写入A、B，未选轮次不动 | 各轮按Tab独立写入 |
| 不选任何维度 | 所有轮次清空 | 选中轮次清空，未选轮次不动 | 所有轮次清空 |
| 整体维度选了C | config.dimensions = [C] | config.dimensions = [C] | config.dimensions = [C] |
| 整体维度不选 | config.dimensions = [] | config.dimensions = [] | config.dimensions = [] |
| 设了第3轮但用例只有2轮 | 第3轮数据丢弃 | 第3轮数据丢弃 | 第3轮数据丢弃 |
| 设了"最后一轮"维度 | N/A | 各用例最后一轮更新 | 各用例最后一轮叠加合并 |

## 7. Schema 定义

```python
class TestCaseBatchActionRequest(APIModel):
    dimensions: Optional[List[Dict[str, Any]]]  # 统一模式维度列表
    round_dimensions: Optional[Dict[str, Any]]   # 逐轮模式 {轮次号: 维度列表}
    multi_dimensions: Optional[List[Dict[str, Any]]]  # 整体评估维度
    round_mode: Optional[str] = 'all'  # all | specific | per_round
    round_numbers: Optional[List[int]]  # specific 模式选中的轮次（含 -1）
```
