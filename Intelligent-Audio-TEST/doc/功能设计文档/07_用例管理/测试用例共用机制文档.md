# 测试用例共用机制文档

## 1. 概述

测试用例采用统一模型设计，测试用例本身不区分类型。测试用例配置分为API测试配置和E2E测试配置两种类型，通过灵活的关联机制支持不同的测试场景。这种设计允许测试用例在API测试和端到端测试中共用，提高测试用例的复用性和维护效率。

## 2. 核心设计理念

### 2.1 统一测试用例模型

测试用例采用统一的数据模型设计，测试用例本身不区分类型。通过以下核心机制支持多场景共用：

- **通用属性**：所有测试用例共享基本属性，如名称、描述、分组、标签等
- **灵活配置**：通过JSON格式的配置字段支持不同测试场景的特定需求
- **配置类型区分**：
  - 在配置的音频数组（`config.audios`）中通过`test_type`字段标记配置类型（API或E2E）
  - 在配置的评测维度对象（`config.dimensions`）中通过`api`和`e2e`子字段分别配置不同测试类型的评测维度
  - 实现同一用例支持多种测试场景
- **分组管理**：测试用例必须选择所属分组，分组来源于`TestCaseGroup`模型，支持在分组选择时动态新增
- 
- 端到端测试音频配置 ：
- 每个E2E测试用例至少配置一个音频
- 支持为每个音频单独配置声压级（spl）
- 每个音频必须指定播放设备（playback_device_id）
- 支持多干声音频配置，通过play_order控制播放顺序
- 多干声音频处理机制 ：

- 音频ASR文本和翻译文本按play_order顺序拼接
- 拼接后的文本用于测试结果的指标计算
- 
- 背景噪声配置 ：
- 支持配置独立的噪声播放设备
- 背景噪声与干声同时播放
- 噪声在指定的噪声播放设备上播放，与干声播放设备可不同
- 
### 2.2 测试配置类型标识机制

系统通过以下机制标识不同的测试配置类型，主要包含两种类型：

- **音频配置标识**：在`config.audios`数组中通过`test_type`字段标记配置类型（API或E2E）
- **评测维度配置标识**：在`config.dimensions`对象中通过`api`和`e2e`子字段分别配置不同测试类型的评测维度

主要配置类型：
- `api`：API测试配置，用于直接调用被测API进行测试
- `e2e`：E2E测试配置，用于通过真实设备和应用进行完整流程测试

测试用例本身不区分类型，通过配置不同类型的音频和评测维度来支持不同的测试场景。

## 3. 数据库模型设计

### 3.1 核心模型结构

```
+-----------------+
|   TestCase      |
+-----------------+
| id              |
| name            |
| description     |
| config (JSON)   | <-- 包含所有配置信息，包括音频、评估维度等
| group_id        |
| created_at      |
| updated_at      |
| deleted         |
+-----------------+
```

**config字段JSON结构示例**：
```json
{
  "background_noise": {
    "audio_id": 10,
    "spl": 65.0
  },
  "audios": [
    {
      "audio_id": 101,
      "test_type": "api"
    },
    {
      "audio_id": 101,
      "test_type": "e2e",
      "spl": 70.0,
      "playback_device_id": 5,
      "play_order": 1
    }
  ],
  "dimensions": {
    "api": [1, 2, 3],
    "e2e": [2, 3, 4]
  }
}
```

### 3.2 关键配置关系

1. **测试用例与音频配置**：
   - 测试用例通过`config.audios`数组配置多个音频
   - 每个音频对象通过`test_type`字段标记配置类型（API或E2E）
   - 支持为同一用例配置不同类型的音频序列
   - API测试音频配置：仅包含`audio_id`和`test_type`字段
   - E2E测试音频配置：包含`audio_id`、`test_type`、`spl`、`playback_device_id`（必填）和`play_order`等字段

2. **测试用例与评估维度关联**：
   - 通过`config.dimensions`对象按测试类型配置评估维度，支持API和E2E分开配置
   - `config.dimensions.api`：API测试使用的评估维度ID数组
   - `config.dimensions.e2e`：E2E测试使用的评估维度ID数组
   - 允许为不同测试类型配置不同的评估维度，实现更灵活的测试场景支持

3. **测试用例与背景噪音关联**：
   - 通过`config.background_noise`配置背景噪音音频和音量

4. **测试用例与标签关联**：
   - 支持通过标签对测试用例进行分类和过滤
   - 便于在不同测试场景中快速查找和复用用例

## 4. 测试用例共用流程

### 4.1 测试用例创建

1. **基本信息填写**：
   - 填写测试用例名称、描述
   - **分组选择**：从下拉列表中选择所属分组，分组数据来源于`TestCaseGroup`模型
   - **动态新增分组**：在分组选择下拉框中支持直接输入新分组名称，系统自动创建新分组并关联
   - 配置通用属性，如背景噪音等

2. **音频配置**：
   - 在`config.audios`数组中添加音频配置项
   - 为API测试配置音频：仅设置`test_type`为`api`，不配置`spl`、`playback_device_id`和`play_order`
   - 为E2E测试配置音频：设置`test_type`为`e2e`，并指定`playback_device_id`、`spl`和`play_order`
   - 支持同一用例同时配置多个不同类型的音频配置项

3. **评估维度配置**：
   - 为API测试配置评估维度：在`config.dimensions.api`数组中选择适用的评估维度ID
   - 为E2E测试配置评估维度：在`config.dimensions.e2e`数组中选择适用的评估维度ID
   - 支持为不同测试类型配置不同的评估维度，实现更精准的测试评估

### 4.2 测试用例执行

1. **任务创建**：
   - 创建测试任务，指定任务类型（`api`或`e2e`）
   - 选择要执行的测试用例
   - 配置执行环境（API、设备等）

2. **执行时的配置适配**：
   - 系统根据任务类型从`config.audios`数组中自动筛选适用的音频配置
   - API任务：
     - 仅使用`test_type`为`api`的音频配置
     - API测试音频配置仅包含`audio_id`和`test_type`字段，不需要SPL、播放设备和播放顺序配置
     - 使用`config.dimensions.api`中的评估维度
   - E2E任务：
     - 仅使用`test_type`为`e2e`的音频配置，并关联相应的播放设备
     - 使用`config.dimensions.e2e`中的评估维度

3. **结果处理**：
   - 根据任务类型和对应的评估维度生成测试结果
   - 支持同一测试用例在不同任务类型下的结果对比

### 4.3 测试用例复用

1. **复制复用**：
   - 支持复制现有测试用例，快速创建新的测试用例
   - 复制时会同时复制完整的`config`配置、标签和评估维度
   - 可以根据需要修改特定类型的音频配置

2. **跨类型复用**：
   - 测试用例本身不区分类型，可以直接在不同类型的测试任务中使用
   - 系统会自动根据任务类型从`config.audios`中筛选适配相应的配置

3. **配置调整**：
   - 可以为现有测试用例的`config.audios`数组添加新类型的配置项
   - 支持为现有测试用例的`config.dimensions`对象添加或修改特定类型的评测维度配置
   - 支持修改特定类型的配置，不影响其他类型的配置
   - 可以灵活调整`playback_device_id`以支持不同设备的测试

## 5. 接口支持

### 5.1 测试用例管理接口

系统提供统一的测试用例管理接口，支持：

- `GET /api/v1/testcases`：获取测试用例列表，支持按标签、分组、关键词过滤
- `GET /api/v1/testcases/:id`：获取测试用例详情，包含完整配置信息
- `POST /api/v1/testcases`：新增测试用例，支持配置不同类型的配置
- `PUT /api/v1/testcases/:id`：更新测试用例，支持调整不同类型的配置
- `DELETE /api/v1/testcases/:id`：删除测试用例（逻辑删除）
- `POST /api/v1/testcases/:id/copy`：复制测试用例，方便复用

### 5.2 测试任务执行接口

测试任务执行接口支持：

- 创建不同类型的测试任务（API或E2E）
- 关联测试用例和执行环境
- 根据任务类型自动适配测试用例的配置

## 6. 优势与收益

### 6.1 提高测试用例复用率

- 同一测试用例可以通过配置不同类型的配置来支持API测试和E2E测试
- 减少测试用例的重复创建和维护工作
- 便于保持不同测试场景下测试用例的一致性

### 6.2 降低维护成本

- 测试用例修改时，所有关联的测试配置都会自动更新
- 统一的管理界面，便于集中维护和管理
- 减少测试用例版本不一致的问题

### 6.3 增强测试覆盖度

- 可以快速为测试用例添加不同类型的配置来扩展测试场景
- 支持同一测试用例在不同任务类型下的结果对比
- 便于发现API任务和E2E任务之间的差异

### 6.4 提高测试效率

- 测试用例创建和配置更加灵活高效
- 支持快速复制和调整测试用例配置
- 便于在不同测试场景之间切换和执行

## 7. 应用场景

### 7.1 从API测试配置到E2E测试配置的扩展

1. 创建测试用例，配置API类型的音频和评估维度
2. 为该测试用例添加E2E测试配置，包括播放设备和特定的音频配置
3. 创建E2E测试任务，关联该测试用例
4. 执行测试，系统自动使用E2E测试配置

### 7.2 同一测试用例在不同设备上的E2E测试

1. 创建测试用例，配置基本的音频
2. 为不同设备添加特定的音频配置（相同配置类型，不同`playback_device_id`）
3. 创建针对不同设备的E2E测试任务
4. 执行测试，系统根据设备自动使用相应的配置

### 7.3 测试用例的跨团队复用

1. 测试用例创建后，通过标签进行分类
2. 不同团队可以根据标签查找和使用测试用例
3. 支持根据团队需求调整测试用例配置
4. 保持测试用例的核心逻辑一致，仅调整特定配置

## 8. 最佳实践

### 8.1 测试用例设计建议

1. **核心逻辑与配置分离**：将测试用例的核心逻辑与特定测试场景的配置分离
2. **合理使用标签**：为测试用例添加合适的标签，便于查找和复用
3. **评估维度的分开配置**：通过`config.dimensions.api`和`config.dimensions.e2e`为不同测试类型配置独立的评测维度，实现更精准的测试评估
4. **配置类型的清晰区分**：为不同类型的配置添加明确的描述

### 8.2 测试执行建议

1. **任务类型与配置适配**：确保测试任务类型与测试用例的配置匹配
2. **执行环境的合理配置**：根据任务类型配置合适的执行环境
3. **结果的对比分析**：对同一测试用例在不同任务类型下的结果进行对比分析
4. **定期维护测试用例**：定期检查和更新测试用例配置，确保其有效性

## 9. 总结

测试用例共用机制通过统一的模型设计和灵活的配置类型机制，实现了测试用例通过配置不同类型的音频和评测维度来支持API测试和E2E测试。核心设计包括：

1. **音频配置分离**：在`config.audios`数组中通过`test_type`字段标记配置类型，支持为同一用例配置不同类型的音频序列
2. **评测维度分离**：在`config.dimensions`对象中通过`api`和`e2e`子字段分别配置不同测试类型的评测维度，实现更精准的测试评估

这种设计提高了测试用例的复用性和维护效率，降低了测试成本，同时增强了测试覆盖度和测试效率。通过合理的测试用例设计和执行策略，可以充分发挥测试用例共用机制的优势，提高测试工作的整体效率和质量。
