# 测试任务合并功能设计文档

## 1. 功能概述

### 1.1 目的
允许用户将多个已完成（completed 状态）的测试任务合并成一个新的汇总任务，便于集中管理和分析测试结果。

### 1.2 适用场景
- 多个相同配置的任务执行完成后，需要统一查看结果
- 对比不同时间段相同用例在不同设备上的执行情况
- 合并多个小任务为一个大任务进行归档管理

## 2. 功能约束

### 2.1 合并条件
- 必须选择至少 2 个任务
- 所有选中的任务状态必须都是 `completed`
- 任务类型无限制（api、e2e、merged 等）

### 2.2 冲突处理
- **同设备同用例**：保留所有执行记录（方案A），通过 `merged_at` 时间戳区分
- 不删除原任务，仅标记状态为 `merged`

## 3. API 接口

### 3.1 请求信息

| 项目 | 值 |
|------|-----|
| URL | `/api/v1/tasks/merge` |
| Method | POST |
| Content-Type | application/json |

### 3.2 请求参数

```json
{
  "task_ids": [1, 2, 3]
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| task_ids | Array[Integer] | 是 | 要合并的任务ID列表 |

### 3.3 响应成功

```json
{
  "code": 0,
  "message": "成功合并 3 个任务",
  "data": {
    "merged_task_id": 100,
    "merged_task_name": "合并任务_task1_task2_task3"
  }
}
```

### 3.4 响应错误

| 错误码 | 错误信息 | 说明 |
|--------|----------|------|
| 1001 | 合并需要至少两个任务 | task_ids 数量不足 |
| 1004 | 部分任务未找到 | 存在无效的任务ID |
| 2005 | 任务未完成，无法合并 | 存在非 completed 状态的任务 |

## 4. 数据表处理

### 4.1 涉及的数据表

| 表名 | 处理方式 | 说明 |
|------|----------|------|
| `test_tasks` | INSERT + UPDATE | 创建新任务，原任务状态更新为 merged |
| `test_results` | UPDATE | 更新 task_id，添加 merged_from 和 merged_at |
| `test_result_dimensions` | 级联更新 | 通过 test_result_id 关联自动更新 |
| `task_device_relations` | INSERT | 从 test_results.device_id 提取唯一值 |
| `task_api_relations` | INSERT | 从 test_results.api_id 提取唯一值 |
| `task_case_relations` | INSERT | 从 test_results.test_case_id 提取唯一值 |
| `task_tags` | INSERT | 从原任务的 tags 提取唯一值 |

### 4.2 字段映射

#### test_results 表新增字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| merged_from | Integer | 来源任务ID |
| merged_at | DateTime | 合并时间 |

#### test_tasks 表更新字段

| 字段名 | 值 |
|--------|-----|
| status | merged |
| merged_into | 新任务ID |

### 4.3 新任务字段计算

| 字段 | 计算方式 |
|------|----------|
| name | `合并任务_{任务名1}_{任务名2}[_等N]` |
| type | merged |
| status | completed |
| total_cases | SUM(原任务.total_cases) |
| completed_cases | SUM(原任务.completed_cases) |
| failed_cases | SUM(原任务.failed_cases) |
| started_at | MIN(原任务.started_at) |
| completed_at | MAX(原任务.completed_at) |
| actual_duration | MAX(原任务.actual_duration) |
| description | `合并自任务: 任务名1, 任务名2, ...` |

## 5. 前端交互

### 5.1 按钮启用条件

```javascript
const canMerge = computed(() => {
  // 1. 至少选择2个任务
  if (selectedTasks.value.size < 2) return false;
  
  // 2. 所有任务状态都是 completed
  const selectedTasksArray = tasks.value.filter(t => selectedTasks.value.has(t.id));
  return selectedTasksArray.every(t => t.status === 'completed');
});
```

### 5.2 操作流程

1. 用户在任务列表中选择多个任务（checkbox）
2. 批量操作栏显示"合并任务"按钮
3. 点击按钮，弹出确认弹窗
4. 用户确认后，调用 API 执行合并
5. 合并成功后，刷新任务列表
6. 原任务状态变为 merged，新任务出现在列表中

### 6.2 核心逻辑

**文件**: `backend/controllers/task_controller.py`

```python
@staticmethod
def merge():
    from backend.models.models import (
        TestResult, TestResultDimension, 
        TaskDevice, TaskAPI, TaskCase, TaskTag, Tag
    )
    
    data = request.get_json()
    task_ids = data.get('task_ids')
    
    # 验证
    if not task_ids or len(task_ids) < 2:
        return error_response("合并需要至少两个任务")
    
    tasks = Task.query.filter(Task.id.in_(task_ids)).all()
    for t in tasks:
        if t.status != 'completed':
            return error_response(f"任务 '{t.name}' 未完成")
    
    # 创建新任务
    new_task = Task(
        name=f"合并任务_{...}",
        type='merged',
        status='completed',
        total_cases=sum(t.total_cases for t in tasks),
        ...
    )
    db.session.add(new_task)
    db.session.flush()
    
    # 复制关联数据
    device_ids_set = set()
    api_ids_set = set()
    case_ids_set = set()
    tag_ids_set = set()
    
    for task in tasks:
        # 更新 test_results
        results = TestResult.query.filter_by(task_id=task.id).all()
        for result in results:
            result.task_id = new_task.id
            result.merged_from = task.id
            result.merged_at = datetime.now()
            
            device_ids_set.add(result.device_id)
            api_ids_set.add(result.api_id)
            case_ids_set.add(result.test_case_id)
        
        # 收集标签
        for tag in task.tags:
            tag_ids_set.add(tag.id)
    
    # 插入关联记录
    for device_id in device_ids_set:
        db.session.add(TaskDevice(task_id=new_task.id, device_id=device_id))
    # ... 其他关联表
    
    # 更新原任务状态
    for task in tasks:
        task.status = 'merged'
        task.merged_into = new_task.id
    
    db.session.commit()
```

## 7. 注意事项

1. **事务处理**：整个合并过程在一个数据库事务中，失败时回滚
2. **性能考虑**：大批量数据合并时，可能需要异步处理
3. **数据追溯**：通过 `merged_from` 和 `merged_at` 字段可以追溯每条结果的原始任务
4. **权限控制**：建议添加权限验证，仅管理员或任务创建者可以合并

## 8. 后续优化建议

1. **批量异步合并**：大数量任务合并时，使用异步队列处理
2. **合并历史记录**：记录合并操作的人员、时间等信息
3. **合并回退**：支持将合并的任务拆分回原任务
4. **合并策略选择**：提供选项选择是保留所有记录还是去重
