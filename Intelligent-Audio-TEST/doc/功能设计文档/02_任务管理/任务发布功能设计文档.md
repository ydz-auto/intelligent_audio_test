# 任务发布功能设计文档

## 1. 文档说明

### 1.1 目标

日常执行任务数量较多，其中部分任务经过验证后需要沉淀为可复用、可追踪、可再次执行的已发布任务。本功能将日常任务发布为已发布任务，并通过版本快照保证已发布任务配置稳定。

## 2. 业务模型

### 2.1 日常任务

日常任务 `Task` 表示一次测试执行实例，负责执行状态、进度、报告、日志和测试结果。现有 `Task.status` 继续表示执行生命周期：`pending`、`queued`、`running`、`paused`、`completed`、`failed`、`stopped` 等。

### 2.2 已发布任务

已发布任务表示经过确认的任务定义，不直接承担执行进度。已发布任务从日常任务发布得到，发布时保存完整配置快照。

已发布任务状态：

| 状态 | 含义 |
| --- | --- |
| `published` | 当前可用 |
| `archived` | 已归档，不允许作为默认任务执行 |

发布状态与日常任务执行状态分离，不向 `Task.status` 中增加 `published`。

## 3. 功能范围

### 3.1 第一阶段

- 从日常任务发布已发布任务。
- 发布前校验任务状态和配置完整性。
- 保存发布时的配置快照。
- 查询已发布任务列表和详情。
- 归档已发布任务。
- 基于已发布任务快照创建新的日常执行任务。
- 支持已发布任务版本。
- 记录发布、执行和归档操作。

### 3.2 暂不包含

- 多级审批流。
- 复杂组织、角色和租户权限模型。
- 定时调度和周期执行。
- 跨环境同步。
- 已发布版本原地修改。

## 4. 核心流程

### 4.1 发布

```text
选择日常任务
  -> 校验状态和配置
  -> 填写已发布任务名称、说明
  -> 生成配置快照
  -> 创建已发布任务 v1
```

发布不会改变源日常任务的执行状态，也不会删除源任务。

### 4.2 执行

```text
已发布任务 vN
  -> 读取发布快照
  -> 创建新的日常 Task
  -> 复用现有 queued/running/completed 执行链路
```

每次执行都生成新的日常任务，并记录来源已发布任务 ID 和版本号。

### 4.3 版本

已发布任务采用不可变版本：

```text
已发布任务 v1 -> 已发布任务 v2 -> 已发布任务 v3
```

旧版本保留用于查看历史和结果追溯；已发布任务不做原地修改。

## 5. 发布规则

### 5.1 可发布状态

默认允许发布：

- `completed`
- `failed`
- `stopped`
- `pending`（任务已完成配置且业务允许未执行任务发布）

不允许发布：

- `queued`
- `running`
- `paused`
- `evaluating`
- `reevaluate_queued`
- `reevaluating`

### 5.2 数据校验

1. 源任务存在且未删除。
2. 已发布任务名称不能为空。
3. 至少包含一个测试用例。
4. 用例、设备、API、算法配置可以完整读取。
5. 所有关联 ID 存在且不重复。
6. 版本号按已发布任务递增。
7. 快照和已发布任务记录在同一个事务中提交。

### 5.3 归档

- 归档不物理删除数据。
- 归档已发布任务不可直接执行。
- 已经创建的日常执行任务不受归档影响。
- 归档操作幂等。

## 6. 数据模型

### 6.1 `published_tasks`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | bigint | 已发布任务 ID |
| `source_task_id` | bigint | 来源日常任务 ID，可为空 |
| `name` | varchar | 已发布任务名称 |
| `description` | text | 说明 |
| `type` | varchar | `api`、`e2e` 等任务类型 |
| `status` | varchar | `published`、`archived` |
| `version` | integer | 版本号，从 1 开始 |
| `is_current` | boolean | 是否当前版本 |
| `snapshot_config` | json | 发布时的完整配置快照 |
| `publish_reason` | text | 发布说明 |
| `published_by` | varchar | 发布人 |
| `published_at` | datetime | 发布时间 |
| `archived_by` | varchar | 归档人 |
| `archived_at` | datetime | 归档时间 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

### 6.2 快照结构

```json
{
  "caseIds": ["case-1", "case-2"],
  "deviceIds": [1, 2],
  "apiIds": [3],
  "config": {},
  "algorithmType": "translation",
  "algorithmParams": {},
  "tags": ["回归", "正式"],
  "sourceTaskId": 123
}
```

前端和 Domain 使用 camelCase；snake_case 只允许出现在后端数据库和 DTO 转换层。

### 6.3 日常任务追溯字段

建议给 `test_tasks` 增加可选字段：

| 字段 | 说明 |
| --- | --- |
| `published_task_id` | 来源已发布任务 ID |
| `published_task_version` | 来源已发布任务版本 |
| `execution_source` | `manual` 或 `published_task` |

## 7. 接口设计

接口前缀：`/published-tasks`。

### 7.1 发布

```http
POST /published-tasks
```

```json
{
  "sourceTaskId": 123,
  "name": "翻译能力正式回归任务",
  "description": "已发布任务说明",
  "publishReason": "完成基线验证"
}
```

### 7.2 列表

```http
GET /published-tasks?page=1&perPage=10&status=published&keyword=翻译
```

支持分页、关键字、状态、类型、标签、来源任务和排序。

### 7.3 详情

```http
GET /published-tasks/{publishedTaskId}
```

返回已发布任务元数据、完整快照、来源任务摘要和版本信息。

### 7.4 执行

```http
POST /published-tasks/{publishedTaskId}/execute
```

接口读取快照并创建新的日常任务，返回新日常任务 ID，不将已发布任务置为 `running`。

### 7.5 新版本

```http
POST /published-tasks/{publishedTaskId}/versions
```

请求可以指定新的来源任务或新的已发布任务名称。

### 7.6 归档

```http
POST /published-tasks/{publishedTaskId}/archive
```

接口需要幂等，重复归档返回当前结果。

## 8. 前端设计

### 8.1 日常任务页

在 `TaskCard` 操作菜单增加：

- 发布为已发布任务。
- 查看已发布版本。

发布弹窗展示来源任务、状态、用例数量、设备数量、API 数量、算法摘要、已发布任务名称和发布说明。


## 9. 权限与审计

预留权限编码：

- `task.publish`
- `published_task.read`
- `published_task.execute`
- `published_task.version.create`
- `published_task.archive`

审计事件：

- `PUBLISHED_TASK_CREATED`
- `PUBLISHED_TASK_VERSION_CREATED`
- `PUBLISHED_TASK_EXECUTED`
- `PUBLISHED_TASK_ARCHIVED`

审计记录至少包含操作人、操作时间、已发布任务 ID、版本号、来源任务 ID 和操作结果。

## 10. 异常处理

| 场景 | 处理方式 |
| --- | --- |
| 源任务不存在 | 返回 404，不创建已发布任务 |
| 源任务正在执行 | 返回业务错误，提示完成后发布 |
| 关联资源不存在 | 发布失败并列出缺失资源 |
| 重复提交 | 通过幂等键或唯一约束返回已存在版本 |
| 快照写入失败 | 事务回滚，不保留半成品 |
| 已发布任务已归档 | 禁止执行并提示选择可用版本 |
| 创建日常任务失败 | 已发布任务保持 `published`，不产生残缺任务 |

## 11. 迁移与兼容

1. 新增 `published_tasks` 表及索引。
2. 为 `test_tasks` 增加来源追溯字段，允许为空。
3. 部署已发布任务接口和前端入口。
4. 现有日常任务不回填已发布任务记录。

兼容要求：

- 旧任务接口字段保持不变。
- 新字段为空时按未发布处理。
- 现有任务执行、报告、日志和重试流程不受影响。
- 不使用 `Task.status = published`。

## 12. 测试与验收

### 12.1 后端测试

- 发布状态校验。
- 缺少用例或关联资源时拒绝发布。
- 快照完整性和源任务修改隔离。
- 版本号递增和重复发布幂等。
- 归档幂等及归档后禁止执行。
- 已发布任务执行创建日常任务并记录来源。

### 12.2 前端测试

- 发布入口按任务状态正确启用或隐藏。
- 发布弹窗校验和错误提示。
- 发布成功后列表和版本标识刷新。
- 已发布任务执行后跳转到新日常任务详情。

### 12.3 验收标准

1. 用户可以从满足条件的日常任务发布已发布任务。
2. 发布后可以查看已发布任务及版本信息。
3. 修改源任务不会改变已发布快照。
4. 已发布任务执行会创建新的日常任务。
5. 已归档已发布任务不能直接执行。
6. 原有任务状态、筛选、统计和执行流程无回归。
