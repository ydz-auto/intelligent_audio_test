# 架构设计

> 版本：v3.0 | 日期：2026-09-10 | 状态：最终方案

---

## 一、背景与问题

### 1.1 现状

API 测试当前有两条链路，存在三个核心问题：

```
路径 A (use_adapter=True):  APISessionExecutor → adapter 微服务(localhost:8000) → vendor API
路径 B (use_adapter=False): APISessionExecutor → _send_direct → vendor API
```

1. **adapter 微服务是黑盒** — vendor 适配逻辑在另一个进程，本仓库不可控、不可单测
2. **APIDriver 太薄** — 无状态工具类，没有连接生命周期，每次调用 new 一个实例
3. **APIClient 的 WebSocket 是"伪流式"** — 连接→全量发→全量收→关闭，不是 chunk-by-chunk 双向流

### 1.2 新需求

ChatGPT Realtime API 等 WebSocket 全双工流式 API 需要：
- 音频按 chunk 双向流式传输（100ms/chunk）
- AI 说话时可被用户打断（barge-in），API 主动推送 `speech_started` / `response.cancelled` 等事件
- 多轮交互在同一 WebSocket 连接内完成
- 需要模拟噪声、干扰人、barge-in 等复杂场景

---

## 二、设计目标

1. **废弃 APIDriver** — vendor 适配逻辑收回到 adapter 类体系
2. **废弃 _execute_linear** — 单轮=rounds[1] 特例，统一走 SessionExecutor
3. **与 device_driver 对称** — adapter 类有完整 `initialize/pre_process/send/recv/post_process/teardown` 生命周期
4. **支持 Realtime WebSocket** — 真流式 chunk-by-chunk 双向传输，事件驱动状态机
5. **新增 vendor 只需继承** — 覆盖 3~4 个抽象方法即可接入新 vendor

## 三、总体架构

### 3.1 架构图

```

│                    ExecutionEngine (核心调度 + 路由)                       │
│  _execute_single_or_multi()                                             │
│    ├── 按被测设备类型路由：                                              │
│    │   ├── 物理设备      → E2EExecutor                                   │
│    │   ├── HTTP API 设备  → APISessionExecutor                           │
│    │   │   ├── stream == True  → 流式模式 (HttpStreamAdapter)            │
│    │   │   └── stream == False → 非实时 (HttpAPIAdapter)                 │
│    │   └── WebSocket API → RealtimeSessionExecutor (RealtimeAPIAdapter)  │
│    │                                                                      │
│    └── 同一 Task 内不同 TaskCase 可关联不同设备类型，混跑 E2E+API+Realtime│
│                                                                          │

│  废弃: _execute_linear() / _run_single_api() / health_check→poll→result │

├──────────────────────────────────────────────────────────────────────────┤
│                       APIAdapterFactory (工厂)                           │
│  get_adapter(api_config, case_config)                                   │
│    ├── protocol == 'websocket'  → RealtimeAPIAdapter 子类               │

│    └── protocol == 'http' + !stream → HttpAPIAdapter 子类               │
├──────────────────────────────────────────────────────────────────────────┤
│  BaseAPIAdapter (基类)                                                  │
│    ├── HttpAPIAdapter (非实时: 请求→完整响应)                            │
│    │    ├── VolcASTAdapter       (火山引擎 ASR/AST)                     │
│    │    └── QwenLLMAdapter       (通义千问 LLM)                         │
│    ├── HttpStreamAdapter (流式: chunk 请求→SSE 事件流)                   │
│    │    ├── VolcStreamAdapter    (火山引擎流式)                         │
│    │    └── QwenStreamAdapter    (通义千问流式)                         │
│    └── RealtimeAPIAdapter (全双工: WS chunk 双向流)                      │
│         ├── OpenAIRealtimeAdapter (ChatGPT Realtime)                    │
│         └── DoubaoRealtimeAdapter (豆包流式)                            │
├──────────────────────────────────────────────────────────────────────────┤
│  生命周期: initialize → pre_process → send/recv → post_process → teardown│
│  非实时: send() 同步返回完整结果, recv() 不调用                           │
│  流式:   send(chunk) 多次调用, recv() 收集 SSE 事件流                     │
│  全双工: send(chunk)/recv(event) 并发, 后台 recv 线程                    │
│  噪声混入: 轮次级混音缓冲 > 全局级，不单独推送                            │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3.2 路由分发（按被测设备类型）

```
              ExecutionEngine._run_task()
                        │
              ┌─────────┴─────────┐
              │ 遍历 TaskCase       │
              │ 查关联的被测设备     │
              └─────────┬─────────┘
                        │
          ┌─────────────┼─────────────┬─────────────────┐
          │             │             │                 │
    物理设备        HTTP API 设备   HTTP API 设备    WebSocket API 设备
          │             │             │                 │
          ▼             ▼             ▼                 ▼
   E2EExecutor   APISessionExecutor  APISessionExecutor  RealtimeSession
   (物理采集)    stream=False        stream=True           Executor
                (HTTP 非实时)       (HTTP SSE 流式)      (WS 全双工)
```

> **关键变更**：不再按 `task.type` 路由，改为按每个 TaskCase 关联的被测设备类型路由。  
> 同一 Task 内不同 TaskCase 可关联不同类型设备，混跑 E2E + API + Realtime。  
> 废弃 `_execute_linear` 和 `APITaskRunner` 的 6 步轮询模式。  
> 所有 HTTP API 测试统一走 `APISessionExecutor`，单轮只是 `rounds=[1]` 的特例。

### 3.5 E2E device_driver vs Realtime api_adapter 行为对称映射

> 核心洞察：Realtime api_adapter 的"AI 说话检测 / barge-in 检测"与 E2E device_driver 完全对称，
> 差异仅在检测手段（事件驱动 vs RMS 轮询）。executor 只管调 `adapter.post_process(is_interruption=...)`，
> 不关心检测细节。

| 生命周期 / 操作 | E2E device_driver (harmony_xiaoyichat) | Realtime api_adapter |
|---------------|---------------------------------------|---------------------|
| `initialize()` | 开 app + enable PCM dump + 清缓存 + 点开小艺 | WebSocket 连接 + 启动 recv 线程 |
| `pre_process()` | 清 PCM + 启动录屏 + 打开通话 + 快照 AI PCM 基线 | `session.update`(VAD/音频格式/voice) + 等 `session.updated` |
| **AI 说话检测** | `_wait_ai_reply_start_via_pcm()` — 轮询 AI PCM 尾部 1s RMS > 阈值 | `_wait_ai_speaking()` — `recv()` 等 `ai_audio_delta` 事件 |
| **AI 说完检测** | `_wait_ai_reply_end_via_pcm()` — 双阶段: 等 RMS>阈值(开始) → 等 RMS<阈值×8s(静默结束) | `_wait_ai_complete()` — 等 `ai_audio_delta`(开始) → 等 `ai_audio_done`(结束) |
| **首帧时延** | `_detect_ai_pcm_first_frame()` — 轮询 PCM size 增长 | commit → 第一个 `ai_audio_delta` 事件时间戳 |
| **barge-in 轮** | `is_interruption=True` → 只等 AI 开始说话(阶段A) → 跳过等说完 → 直接收尾进下一轮 | `is_interruption=True` → `_wait_ai_speaking()` 只等 AI 开始 → 推送打断音频 → 检测 `speech_started`/`response_cancelled` |
| `post_process()` | UI 法: 等"说话可打断"消失(AI开始) → 等"正在听…"出现(AI结束) | 事件法: `recv` 等 `ai_audio_delta`(开始) → 等 `ai_audio_done`(结束) |
| `get_results()` / 采集 | 拉 PCM → 转 wav → 提取文本 → 返回 `{user_wav, ai_wav, start_ms, end_ms, first_frame_ms, question, answer}` | `adapter.ai_audio` 属性已收集完毕 + 事件日志 |
| `teardown()` | 停录屏 + 挂断 + 回桌面 + 清缓存 | `ws.close()` |

**关键差异**：

| 维度 | E2E | Realtime |
|------|-----|----------|
| 检测手段 | PCM RMS 能量轮询 + UI 控件文案（"说话可打断"/"正在听…"） | API 事件驱动（`response.audio.delta` / `input_audio_buffer.speech_started` / `response.cancelled`） |
| 精度 | 秒级（轮询间隔 0.1~1s） | 毫秒级（事件时间戳） |
| 延迟 | 高（需轮询文件 size / RMS） | 低（事件即时推送） |
| 抗干扰 | 差（UI 文案不稳定，RMS 有误判） | 强（API 事件是权威信号） |

### 3.6 前后端统一设计

> **原则**：不再区分 HTTP API 测试 / Realtime API 测试 / E2E 测试三条独立链路。  
> 统一为"创建任务时选被测设备"，设备类型决定执行方式，一个任务内可混跑不同类型设备。

#### 后端路由统一

| 路由前缀 | 控制器 | 用途 |
|---------|--------|------|
| `/api/tasks` | `task_controller.py` | 任务 CRUD（不区分类型） |
| `/api/test-cases` | `testcase_controller.py` | 用例 CRUD（纯数据，不区分类型） |
| `/api/devices` | `device_controller.py` | 被测设备管理（物理设备 + API 设备统一管理） |
| `/api/digital-spl` | `device_controller.py` | 数字域 SPL 校准 |

#### 前端统一入口

| 路由路径 | 组件 | 说明 |
|---------|------|------|
| `/TaskCreate` | `TaskCreate.vue` | 任务创建页面，步骤2 选被测设备（设备列表含物理设备 + API） |
| `/E2ETest` | `E2ETest.vue`（现有） | E2E 设备测试（不动） |
| `/APITest` | `APITest.vue`（现有） | API 测试（不动） |
| `/RealtimeAPITest` | `RealtimeAPITest.vue`（新增） | Realtime API 测试（与 APITest 对称） |

> v3.1 恢复独立 Realtime API 测试页面，与 E2ETest / APITest 三页面对称。

#### 设备类型与执行器映射

| 被测设备类型 | 执行器 | 适配器 | 评估维度 |
|-------------|--------|--------|---------|
| 物理设备 | `E2EExecutor` | `DeviceDriver` | 全维度（物理设备采集） |
| HTTP API | `APISessionExecutor` | `HttpAPIAdapter` / `HttpStreamAdapter` | tor / false_takeover / takeover_latency / llm_judge |
| WebSocket API | `RealtimeSessionExecutor` | `RealtimeAPIAdapter` | interruption_metrics / interruption_judge / noise_latency / rejection_judge |

#### ExecutionEngine 路由分发（v3.1 更新）

> ExecutionEngine 自身按 `device_type` 路由，不再通过 APIExecutor 中间层。

```python
# execution_engine.py 中的 _execute_single_or_multi
def _execute_single_or_multi(self, app, task_id, tc_rel_id, data):
    case_config = self._load_case_config(test_case_id)
    device = self._load_device(tc_rel_id)  # 查 TaskCase 关联的被测设备
    device_type = device.get('device_type')  # 'physical' / 'http_api' / 'websocket_api'

    if device_type == 'physical':
        return self.e2e_executor.execute(app, task_id, tc_rel_id, data, case_config)
    elif device_type == 'websocket_api':
        return self.realtime_executor.execute(app, task_id, tc_rel_id, data, case_config)

    # HTTP API（含单轮和多轮）
    return self.api_session_executor.execute(app, task_id, tc_rel_id, data, case_config)
```
