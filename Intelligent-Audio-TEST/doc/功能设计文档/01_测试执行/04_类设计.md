# 类设计（测试执行）

> 版本：v1.0（V9.7.31 适配版，2026-09-10，适配自 V9.7.10《04_类设计》v3.0/v3.1）
> 架构基线：DDD + CQRS + 微服务 + 分布式部署；服务间 gRPC（shared/proto，11 个 proto + ACL 仓储模式）；无 MQ，事件走 Redis EventBus

---

## 适配总述

V9.7.10 为单体 Flask 架构，适配器/执行器/混音服务全部位于 `backend/utils/clients/`、`backend/services/` 单一进程内。V9.7.31 拆分为 12 微服务后，本篇按**服务落位**重排类设计，核心变化：

| # | V9.7.10 单体设计 | V9.7.31 落位 | 变更类型 |
|---|------------------|--------------|----------|
| 1 | `backend/utils/clients/base_api_adapter.py`（BaseAPIAdapter 等） | `api_test_service` 适配器体系（3.2 节） | 迁移重构 |
| 2 | `backend/services/execution/realtime_session_executor.py` | `api_test_service/application`（RealtimeSessionExecutor，3.2 节） | 迁移重构 |
| 3 | `backend/services/audio/audio_stream_orchestrator.py`（进程内离线混音） | **混音下沉** `audio_service` RenderAudioStreamServicer（4.1 节），api_test_service 侧仅保留 gRPC 流消费客户端（3.2 节） | 下沉（新增） |
| 4 | `backend/models/models.py`（SQLAlchemy 单体大模型） | 各服务 `infrastructure/persistence/models/*_models.py` PO + `domain/entities` 聚合（3.1 节） | DDD 拆分 |
| 5 | `backend/models/models.py::ApiRmsSplMapping` | `api_test_service` 聚合，按 DDD 五层落位（3.1 节） | 迁移重构 |
| 6 | `log_and_emit`（进程内 WebSocket 直推） | EventBus（Redis）发布 → api_gateway 订阅 → Socket.IO 转发前端（2.2 节） | 事件化（新增） |
| 7 | 进程内 threading.Event（stop/pause） | shared BaseExecutor ControlMixin + DistributedLock/分布式协调（2.1、2.4 节） | 分布式化 |
| 8 | `task.type`/`test_type` 裸字符串 | `TaskType`/`TestType`/`DeviceType` 枚举（2.3 节）；**不引入 `'realtime_api'`**，realtime 由 `DeviceType.WEBSOCKET_API` 表达 | 枚举化（新增） |
| 9 | Flask `evaluation_service` 进程内调用 | gRPC `submit_evaluate_case`（`shared/clients/_grpc_task_data.py:15`） | gRPC 化 |

**标注约定**：
- **（新增）**：V9.7.31 新引入的类/字段/方法/proto，源文档不存在或结构不同；
- **【适配说明：...】**：源文档已有设计在 V9.7.31 下的落位差异；
- 方法签名：**Domain 层（领域模型/值对象/领域事件）用 camelCase**（新规范，存量 snake_case 方法随重构统一）；**Infrastructure/Application 实现层（Python）如实使用 snake_case**。

| `_aggregate` | 轮次聚合：round_count/total_latency/avg_latency/barge_in_total/barge_in_success_rate + `eval_params`（rounds、user_wav、ai_wav、original_topic、enable_llm_eval） |

| `_submit_evaluation` | gRPC `submit_evaluate_case(task_id, result_id, test_case_id, algorithm_result, eval_params)`（`shared/clients/_grpc_task_data.py:15`），不再进程内调用评估 |

**生产者-消费者与帧/终态分离**：
- **事件队列**：`RealtimeAPIAdapter._recv_loop` 线程为生产者，`_event_queue` 为消费者队列，`recv(timeout)` 阻塞取事件 → executor 永不直接读 WebSocket；
- **帧结果与最终结果分离**：适配器内部维护逐帧列表（`_frame_timestamps/_frame_types/_frame_payloads`），executor 只读聚合后的 `adapter.output`（`AdapterOutput`）——帧级指标（first_frame_ms）与终态指标（ai_audio 总量/文本）互不耦合；
- **barge-in 打断检测**：打断轮在推送后开 5s 检测窗，命中 `RealtimeEventType.USER_SPEECH_STARTED` 或 `RESPONSE_CANCELLED` 即判定打断成功并记录 `barge_in_latency_ms`。

**OpenAI 密钥链（（新增）配置化约定）**：`_build_connect_headers` 按 `case_config.api_key → api_config.meta.api_key → env OPENAI_API_KEY` 三级解析，禁止硬编码密钥。

        位深转换/重采样/通道上下混

| 成员 | 说明 |
|------|------|
| `RenderAudioStream(request, context)`（（新增）proto，server-streaming） | 请求携带 `task_id/tc_rel_id/api_id/round_config/audio_config`；响应流 `RenderAudioChunk{seq, data(base64), duration_ms}` |

### 4.2 AudioStreamOrchestrator — 混音编排（自 playback_orchestrator 体系下沉复用）

> 对应 V9.7.10 §5.6/§5.7b。落位 `audio_service/infrastructure/audio/`（新增模块，紧邻 `playback_orchestrator.py`），**复用同一套时间轴/格式/增益部件**：`audio_timeline.calculate_speaker_aware_audio_delays`（E2E 实时混音同源算法）、格式适配、`spl_service.SPLMappingService`。

**混音 6 步（与 V9.7.10 语义一致）**：

```mermaid
flowchart LR
    A["Step1 加载各源 PCM<br/>主讲人/干扰人/噪声"] --> B["Step2 格式适配<br/>统一到 api.audio_config 目标格式"]
    B --> C["Step3 RMS 补偿 + SPL 增益<br/>归一化 -30dBFS → 按映射调增益"]
    C --> D["Step4 时间轴编排<br/>calculate_speaker_aware_audio_delays"]
    D --> E["Step5 混音叠加<br/>float32 缓冲按 start_time 相加<br/>np.clip(-32768, 32767) 防削波"]
    E --> F["Step6 切片输出<br/>chunk_duration_ms 切分 → base64 chunk"]
```

**关键参数（配置化，拒绝魔法数字）**：

| 常量 | 值 | 来源/回退 |
|------|----|-----------|
| 目标采样率 | 24000 | `api.audio_config.sample_rate`，未配置回退（OpenAI 兼容） |
| 位深 | 16bit（int16） | `api.audio_config.bit_depth` |
| `TARGET_RMS_DBFS` | -30.0 | 与 E2E `audio_driver` 增益补偿基准一致 |
| `chunk_duration_ms` | 100 | 适配器 `_chunk_duration_ms` 对齐 |

**噪声合并优先级（与 E2E playback_orchestrator 一致）**：轮次级 `background_noise` > case 级；`loop=True` 时铺满整个混音缓冲；噪声混入轮次混音，不单独推送。

**E2E vs Realtime 混音/SPL 对照**（V9.7.31 落位视角）：

| 维度 | E2E（物理设备实时链路） | Realtime API（本节，下沉后） |
|------|--------------------------|------------------------------|
| 混音时机 | 实时（audio_driver 回调内逐帧叠加） | 离线（推送前一次性混音完成） |
| 执行进程 | audio_service（播放驱动） | audio_service（RenderAudioStreamServicer） |
| SPL 映射查询 | `SPLMappingService.spl_to_gain(mapping_id, target_spl)`（设备侧映射） | `ApiRmsSplService` 语义（api_id → `api_rms_spl_mappings`，经 audio_service 入参传入或回调） |
| SPL 关联 | PlaybackDevice 1:N SPLMapping | API 1:N ApiRmsSplMapping |
| 校准方式 | 物理校准（播放测试音 + 实测 SPL） | 数字校准（发送已知 RMS + 评估识别效果） |
| 输出 | int16 → 物理播放设备 | int16 → base64 → gRPC 流 → WebSocket chunk |

> 【适配说明】：V9.7.10 `ApiRmsSplService`（api 进程内，按 `api_id` 查库）随混音下沉拆分为两半——插值/限幅算法上移至 `ApiRmsSplMappingAggregate.gainAt`（3.1.2，Domain 层），映射查询由 audio_service 经 ACL/入参完成；`spl_service.py` 的 `SPLMappingService`（设备侧）不动。

### 4.3 SPLMappingService（存量，设备侧）
