## 一、核心机制：生产者-消费者 + 事件队列

Realtime 适配器的实时性依赖 **一个后台接收线程 + 一个阻塞队列**，推送和接收完全并行互不阻塞。

```
┌─────────────────────────────────────────────────────────────────┐
│                        RealtimeAPIAdapter                        │
│                                                                  │
│  ┌─ 推送方向（executor → API）─────────────────────────────┐    │
│  │                                                          │    │
│  │  executor                 adapter.send()                │    │
│  │    │                        │                            │    │
│  │    │ adapter.send(chunk_0)  │ _send_audio_chunk()        │    │
│  │    │───────────────────────►│ ws.send({audio: base64})   │    │
│  │    │ sleep(100ms)           │                            │    │
│  │    │ adapter.send(chunk_1)  │ _send_audio_chunk()        │    │
│  │    │───────────────────────►│ ws.send({audio: base64})   │    │
│  │    │ ...                    │                            │    │
│  │    │ adapter.commit_input()│ _send_json({commit})       │    │
│  │    │───────────────────────►│                            │    │
│  │    │                        │                            │    │
│  └────┼────────────────────────┼────────────────────────────┘    │
│       │                        │                                 │
│       │           ┌────────────▼────────────┐                    │
│       │           │  _recv_loop (daemon)     │                    │
│       │           │  while connected:        │                    │
│       │           │    raw = ws.recv()        │                    │
│       │           │    event = json.loads(raw)│                    │
│       │           │    _event_queue.put(event)│                    │
│       │           └────────────┬────────────┘                    │
│       │                        │                                 │
│       │           ┌────────────▼────────────┐                    │
│       │           │  _event_queue            │                    │
│       │           │  (queue.Queue, 阻塞)     │                    │
│       │           └────────────┬────────────┘                    │
│       │                        │                                 │
│  ┌────┼────────────────────────┼────────────────────────────┐    │
│  │  接收方向（API → executor）─┘                            │    │
│  │                                                          │    │
│  │  executor                  adapter.recv()               │    │
│  │    │                          │                         │    │
│  │    │ adapter.recv(timeout=5)  │ event_queue.get()       │    │
│  │    │◄─────────────────────────│ ◄── 取出一个事件        │    │

│  │    │                          │  ├─ _record_raw_event  │    │

│  │    │                          │  ├─ _ai_audio_chunks    │    │
│  │    │                          │  │   .append(pcm)       │    │
│  │    │                          │  ├─ _mark_first_frame() │    │
│  │    │                          │  └─ _record_frame()     │    │

│  │    │◄─────────────────────────│ 返回归一化事件           │    │
│  │    │   {type: "ai_audio_delta"}                        │    │

│       │                                                        │
│       ▼                                                        │
```

## 二、推送方向（executor → API）

### 2.1 流程

```
executor
  │
  │ 1. RenderAudioStream.render()
  │    → 逐帧流式混音（主讲人 + 干扰人 + 噪声）+ SPL 增益 + 切片
  │    → [chunk_0, chunk_1, ..., chunk_N]  (base64 PCM)
  │
  │ 2. for chunk in chunks:
  │      adapter.send(chunk, is_audio=True)
  │      sleep(chunk_duration_ms / 1000)   ← 模拟实时流式速率
  │
  │ 3. adapter.commit_input()              ← 标记输入结束
  │      → mark_commit()                   ← 记录 commit 时间戳（用于首帧延迟）
  │      → ws.send({type: "input_audio_buffer.commit"})
  │
  ▼
```

### 2.2 关键点

| 要点 | 说明 |
|------|------|
| **切片推送** | 逐帧流式混音后按 `chunk_duration_ms`（默认 100ms）切片，逐 chunk 发送 |
| **模拟实时速率** | `sleep(chunk_duration_ms / 1000)` 控制推送节奏，不一次性灌入 |
| **commit 时间戳** | `commit_input()` 内部调 `mark_commit()` 记录时间，用于计算首帧延迟 |
| **非阻塞** | 推送是同步 `ws.send()`，但发送速度快（网络 IO），不阻塞接收线程 |

## 三、接收方向（API → executor）

### 3.1 后台接收线程 `_recv_loop`

```
_recv_loop (daemon Thread, adapter.initialize() 时启动)
  │
  ├── while self._connected and self._ws:
  │     │
  │     ├── raw = self._ws.recv()          ← 阻塞等待 WebSocket 消息
  │     │
  │     ├── if isinstance(raw, bytes):
  │     │     event = {"type": "binary", "data": raw}
  │     │
  │     ├── else:
  │     │     event = json.loads(raw)       ← JSON 事件
  │     │
  │     └── self._event_queue.put(event)   ← 入队，不解析
  │
  └── 异常时:
        if self._connected:
          _event_queue.put({"type": "connection_closed", "error": str(e)})
        break
```

**设计要点**：
- `_recv_loop` **只负责收消息入队**，不做任何厂商字段解析
- 事件队列是 `queue.Queue`（线程安全阻塞队列）
- executor 调 `recv()` 时从队列取事件，如果队列为空则阻塞等待
- 推送和接收完全并行，互不阻塞

### 3.2 executor 取事件 `adapter.recv()`

```
adapter.recv(timeout=5)
  │
  ├── raw_event = self._event_queue.get(timeout=5)    ← 阻塞等待，最多 5s
  │
  └── return self._parse_event(raw_event)              ← 交给子类解析
```

### 3.3 子类 `_parse_event` 解析（以 OpenAI 为例）

```
_parse_event(event)
  │
  ├── 1. _record_raw_event(event)           ← 原始事件完整保留（含时间戳）
  │
  ├── 2. 解析 OpenAI 特有 type 字段
  │
  ├── 3. 按事件类型写入基类统一属性:
  │     │
  │     ├── response.audio.delta:
  │     │     pcm = base64.b64decode(delta)  ← OpenAI 特有：delta 是 base64
  │     │     _ai_audio_chunks.append(pcm)   ← 帧结果：逐帧存储
  │     │     _mark_first_frame()             ← 首帧延迟计算
  │     │     _record_frame('ai_audio_delta', len(pcm))
  │     │     return {"type": "ai_audio_delta", "size": len(pcm)}
  │     │
  │     ├── input_audio_buffer.speech_started:
  │     │     barge_in_detected = True
  │     │     _record_frame('user_speech_started')
  │     │     return {"type": "user_speech_started"}
  │     │
  │     ├── response.cancelled:
  │     │     barge_in_detected = True
  │     │     _record_frame('response_cancelled')
  │     │     return {"type": "response_cancelled"}
  │     │
  │     ├── response.done:
  │     │     _ai_complete = True
  │     │     _record_frame('ai_audio_done')
  │     │     return {"type": "ai_audio_done"}
  │     │
  │     └── ...
  │
  └── 返回归一化事件 {type: "...", ...}
       │
       └── executor 只看 type，不碰厂商字段
```

## 四、帧结果与最终结果

### 4.1 帧结果（逐帧中间状态）

每个事件到达时实时记录，不等回复结束：

```python
# 基类维护的帧结果属性
_frame_timestamps: List[float]    # 每帧到达时间戳
_frame_types: List[str]            # 每帧事件类型
_frame_payloads: List[Any]         # 每帧 payload
_ai_audio_chunks: List[bytes]      # AI 音频帧列表（逐帧 PCM）
_ai_text_chunks: List[str]         # AI 文本 token 列表
```

**帧结果用途**：
| 用途 | 说明 |
|------|------|
| 延迟分析 | `_frame_timestamps[0]` - `_commit_ts` = 首帧延迟 |
| 时序分析 | 每帧时间戳可还原 AI 回复的时间线 |
| barge-in 精确时间点 | `user_speech_started` 帧的时间戳 = 打断发生的精确时刻 |
| 帧级音频分析 | 每帧 PCM 可单独分析（如按帧计算 RMS） |

### 4.2 最终结果（聚合后）

executor 通过 `adapter.output` 获取完整结果：

```python
@dataclass
class AdapterOutput:
    audio: bytes              # = b''.join(_ai_audio_chunks)  所有帧拼接
    text: str                 # = ''.join(_ai_text_chunks)    所有 token 累积
    video_chunks: list        # 视频帧列表
    images: list              # 图片列表
    event_log: list           # = [(ts, type, payload), ...]  归一化事件时间线
    raw_event_log: list       # = [(ts, raw_event), ...]      原始事件时间线
    latency_ms: int           # = _mark_first_frame 计算       首帧延迟
    frame_results: list       # = [{ts, type, payload}, ...]  逐帧记录
```

**最终结果用途**：
| 用途 | 说明 |
|------|------|
| 语音质量评估 | `output.audio` → 保存 wav → 提交评估 |
| 语义评估 | `output.text` → 文本对比 |
| 多模态评估 | `output.video_chunks` / `output.images` |
| 端到端延迟 | `output.latency_ms` |
| 事件回放 | `output.event_log` → 完整时间线分析 |

```
 │           └─ recv(timeout=2) ◄──── event_queue.get()      │

 │                                                            │

 │                                                            │
 │     adapter.send(chunk_0) ──────────────────────────────► 接收打断音频
```

## 七、与 E2E 设备驱动的对比

| 维度 | E2E (device_driver) | Realtime (adapter) |
|------|---------------------|---------------------|
| 推送方式 | PyAudio callback 实时混音播放 | `adapter.send()` 逐 chunk WebSocket 推送 |
| 接收方式 | PyAudio 录音 callback 抓取 PCM | `_recv_loop` 后台线程 → 事件队列 |
| AI 说话检测 | PCM RMS 轮询 + UI 控件检测 | 事件驱动（`response.audio.delta`） |
| 打断检测 | RMS 阈值 + sleep 延迟 | 事件驱动（`speech_started` / `cancelled`） |
| 混音 | PyAudio callback 内实时叠加 | `RenderAudioStream` 逐帧流式混音（100ms 滑动窗口） → base64 chunk |
| 延迟测量 | 录屏首帧 + 时间戳 | 事件时间戳精确到 ms |
| 结果存储 | PCM 文件 | `adapter.output`（帧结果 + 最终聚合） |
| 连接生命周期 | 每次测试新建 | WebSocket 连接跨多轮保持 |

## 八、关键设计原则

### 8.1 推送与接收分离

```
推送: executor.send() → ws.send()        ← 同步，快速返回
接收: _recv_loop → event_queue           ← 后台线程，持续运行
取结果: executor.recv() → queue.get()    ← 阻塞等待，有事件才返回
```

**不阻塞**：推送时 `_recv_loop` 继续接收；接收时 executor 可以继续推送下一个 chunk。

### 8.2 厂商字段隔离

```
_recv_loop     → 只入队，不解析（厂商无关）
_parse_event   → 子类解析厂商字段，写入基类统一属性（厂商相关）
executor       → 只读归一化事件 type + adapter.output（厂商无关）
```

**executor 永远不碰** `event["delta"]`、`event["audio_chunk"]` 等厂商字段。

### 8.3 帧结果实时记录

`_parse_event` 每次被调用时就 `_record_frame()`，**不等回复结束**。
这意味着即使 AI 还在说话，executor 也能通过 `adapter.output.frame_results` 获取已收到的帧。

### 8.4 最终结果按需聚合

`adapter.output` 是 property，每次访问时实时聚合：
```python
audio = b''.join(self._ai_audio_chunks)    # 实时拼接所有帧
```

executor 可以在任意时刻读取，不需要等 AI 完全回复。
