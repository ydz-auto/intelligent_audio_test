# 音频引擎 (Audio Engine) 设计文档

## 概述

音频引擎是基于 PyAudio 的音频播放管理系统，支持多通道设备选择、采样率转换和灵活的声道映射。设计用于 E2E 测试场景中的音频播放预览。

**声纹识别重叠播放**：音频引擎支持声纹识别算法的双音频重叠播放，通过 overlap_rate 或 overlap_time 参数控制前后两个音频的重叠比例。

### 三层架构

音频播放采用分层设计，各层职责明确：

```
┌─────────────────────────────────────────────────────────────┐
│  调用方层：为什么播                                          │
│  e2e_executor / testcase_controller                         │
│  只传高层配置（round_config / preview_config）               │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  编排层：播什么 + 怎么排                                     │
│  PlaybackOrchestrator (playback_orchestrator.py)            │
│  - 解析音频配置（干声/噪声/干扰人）                          │
│  - 设备绑定（device_unique_id → device_index）              │
│  - SPL 增益计算                                             │
│  - 时间轴调度（交叠/顺序/speaker 感知）                      │
│  - 合并为统一 audio_to_play 列表                             │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  驱动层：怎么出声                                            │
│  AudioEngine / AudioService / AudioDriver (audio_engine.py) │
│  - play_overlap(): 按设备分组，启动多线程                    │
│  - play_multi(): 同一流中混合播放，回调驱动                  │
│  - 采样率转换、增益补偿、延迟处理                            │
└─────────────────────────────────────────────────────────────┘
```

**B 类调用方**（单音频播放，不需要编排层）直接调用 `AudioService.play_audio()`：
- `audio_controller.py` — 音频试听
- `playback_controller.py` — 设备测试播放
- `spl_controller.py` — SPL 校准播放

## 核心组件

### 1. AudioDriver (抽象基类)

定义音频驱动的接口规范：

```python
class AudioDriver(ABC):
    @abstractmethod
    def play(self, file_path, device_index, channel_index, gain, loop, stop_event, offset):
        pass

    @abstractmethod
    def play_overlap(self, primary_file, secondary_file, device_index, channel_index,
                     gain, overlap_rate, stop_event):
        """重叠播放：同时播放两个音频文件，按 overlap_rate 控制重叠区域"""
        pass

    @abstractmethod
    def stop(self):
        pass

    @abstractmethod
    def get_devices(self):
        pass

    @abstractmethod
    def play_multi(self, audio_configs, device_index, stop_event):
        """在同一个流中混合播放多个音频文件"""
        pass

    @abstractmethod
    def calculate_gain_compensation(self, file_path):
        """计算增益补偿（根据音频实际 RMS 调整增益）"""
        pass
```

### 2. PyAudioDriver (PyAudio 实现)

实际的音频播放驱动，基于 PyAudio 库实现。

#### 初始化参数

| 参数 | 类型 | 说明 |
|------|------|------|
| file_path | str | 音频文件路径 |
| device_index | int | 输出设备索引 |
| channel_index | int | 声道索引 (0-based) |
| gain | float | 增益系数 (0.0-1.0) |
| loop | bool | 是否循环播放 |
| stop_event | threading.Event | 停止事件信号 |
| offset | float | 起始播放位置 (秒) |

### 3. AudioService (音频服务)

管理音频播放的公共服务层，提供设备缓存和多任务支持。

**核心方法**：

| 方法 | 调用方 | 用途 |
|------|--------|------|
| `play_overlap()` | PlaybackOrchestrator | A 类场景：多音频编排播放（主讲人+噪声+干扰人） |
| `play_audio()` | B 类调用方 | 单音频播放（音频试听、设备测试、SPL 校准） |
| `stop_task_audio()` | 任意 | 停止指定任务的所有音频流 |

**A 类调用链路**（编排播放）：
```
PlaybackOrchestrator
    → AudioService.play_overlap(audio_to_play)
        → 按 device_index 分组
        → PyAudioDriver.play_multi(configs, device_index)
            → pyaudio stream + callback
```

**B 类调用链路**（直接播放）：
```
audio_controller / playback_controller / spl_controller
    → AudioService.play_audio(task_id, file, ...)
        → PyAudioDriver.play_multi([config], device_index)
            → pyaudio stream + callback
```

## 重要背景：PyAudio 设备流限制

### 问题描述

**PyAudio 不允许同一设备同时打开多个流**。这是 PyAudio 的技术限制，因为每个音频设备在操作系统层面只能被一个流独占访问。

但是，`channel` 参数是用来在**同一个流**中选择输出通道的，用于多声道设备的声道映射。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    PyAudio 设备流限制说明                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  错误做法：每个音频单独打开一个流（会失败）                                │
│  ┌──────────┐    ┌──────────┐                                          │
│  │  设备34  │    │  设备34  │  ❌ 同时打开多个流会报错                   │
│  │ Stream A │    │ Stream B │     [Errno -9996] Invalid device        │
│  │ channel=0│    │ channel=1│                                          │
│  └──────────┘    └──────────┘                                          │
│                                                                          │
│  正确做法：在同一个流中播放多个音频（使用 play_multi）                    │
│  ┌──────────┐                                                           │
│  │  设备34  │  ✅ 同一个流，不同通道                                      │
│  │ Stream A │     - channel=0 → 输出到通道0                           │
│  │ channel=0│     - channel=1 → 输出到通道1                           │
│  │ channel=1│                                                           │
│  └──────────┘                                                           │
│                                                                          │
└─────────────────────────────────────────────────────────────────────────┘
```

### 解决方案：play_multi 方法

为了支持同一设备的多声道同时播放，新增了 `play_multi` 方法，该方法：

1. **在同一个 PyAudio 流中混合多个音频**
2. **每个音频映射到不同的输出通道**
3. **支持独立的增益控制**

```python
def play_multi(self, audio_configs, device_index=0, stop_event=None):
    """
    在同一个流中混合播放多个音频文件

    Args:
        audio_configs: 音频配置列表，每个元素为 dict:
            {
                'file': 文件路径,
                'channel': 输出通道索引,
                'gain': 音量增益
            }
        device_index: 设备索引
        stop_event: 停止事件
    """
```

## 声纹识别重叠播放 (Overlap Playback)

### 重叠播放原理

重叠播放是指在播放第一个音频（primary）后，在第一个音频播放到末尾时，同时开始播放第二个音频（secondary），两个音频在重叠区域同时播放。

```
时间轴：
─────────────────────────────────────────────────────────────────►

音频1: [███████████████████████░░░░░░░░░░]
         ↑                    ↑
       开始               重叠开始点 (音频1剩余 30%)

音频2:                    [░░░░░░░░░░███████████████████████]
                           ↑                    ↑
                       重叠开始点            播放完成
                       (音频2开始)

重叠区域: 30% 的音频长度，两音频同时播放
```

### overlap_rate 和 overlap_time 参数说明

| 参数 | 类型 | 说明 | 优先级 |
|------|------|------|-------|
| overlap_time | float | 交叠时间（秒），两个音频同时播放的时间段，优先级更高 | 高 |
| overlap_rate | float | 交叠率 (0.0-1.0)，0.5 表示 50% 交叠 | 低 |

**计算逻辑**：
- `overlap_time > 0`：使用 overlap_time 作为交叠时间
- `overlap_rate > 0`：交叠时间 = duration × overlap_rate
- 二者都为 0 或 None：顺序播放（无交叠）

**交叠时间 vs 延迟时间**：
- 交叠时间（overlap_time）：两个音频同时播放的时间段
- 延迟时间（delay）：第n个音频比第1个音频晚开始的时间

| overlap_rate | 交叠时间 | 延迟时间 | 效果 |
|-------------|---------|---------|------|
| 0 | 0 | 累计时长 | 完全顺序 |
| 0.5 | duration × 0.5 | 累计时长 × 0.5 | 50%交叠 |
| 1.0 | duration | 0 | 完全交叠（同时开始） |

| overlap_rate | 含义 | 示例 |
|-------------|------|------|
| 0.0 | 无重叠，连续播放 | [AAA][BBB] |
| 0.3 | 30% 重叠 | [AAA][BBB] → [AA[AB]BB] |
| 0.5 | 50% 重叠（推荐） | [AA[AB]BB] |
| 0.7 | 70% 重叠 | [A[AAB]BB] |
| 1.0 | 完全重叠，同时播放 | [AA][BB] → 同时开始 |

### 设备与播放配置

重叠播放需要考虑两种场景：

**场景1：不同设备**
```
设备A: 播放音频1 (channel=0)
设备B: 播放音频2 (channel=0)
```
→ 两个独立流，可并行

**场景2：同一设备的不同通道**
```
设备A:
  - channel=0: 播放音频1
  - channel=1: 播放音频2
```
→ 同一设备，需使用 `play_multi` 在同一个流中混合

```
┌─────────────────────────────────────────────────────────────┐
│                    重叠播放设备配置                           │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  场景1 - 不同设备：                                          │
│    主音频 (primary):  playback_device_id=5  ──→  设备5      │
│    次音频 (secondary):  playback_device_id=8  ──→  设备8     │
│    → 可并行播放                                              │
│                                                              │
│  场景2 - 同一设备不同通道：                                   │
│    主音频:  playback_device_id=4, channel=1 ──→ 设备34      │
│    次音频:  playback_device_id=3, channel=0 ──→ 设备34      │
│    → 需使用 play_multi 在同一流中混合                        │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**关键区分**：

| 配置层级 | 字段 | 来源 | 说明 |
|---------|------|------|------|
| **主音频设备** | `playback_device_id` | TestCase.config.audios[0].playback_device_id | 指定主音频播放设备 |
| **次音频设备** | `playback_device_id` | TestCase.config.audios[1].playback_device_id | 指定次音频播放设备 |
| **时间重叠率** | `overlap_rate` | 算法配置 | 控制重叠时间比例（0.0-1.0） |
| **重叠时间** | `overlap_time` | 算法配置 | 控制重叠时间（秒），优先级高于 overlap_rate |

**用例配置到音频引擎的映射**：
```
TestCase.config.audios
├─ [0]: { "audio_id": 101, "playback_device_id": 5, "play_order": 1 }
│        ↓
│        primary_file=音频101, primary_device_id=5
│
└─ [1]: { "audio_id": 102, "playback_device_id": 8, "play_order": 2 }
         ↓
         secondary_file=音频102, secondary_device_id=8

overlap_rate / overlap_time (来自算法配置)
        ↓
控制主音频和次音频的重叠时间
```

### 公共方法：calculate_gain_compensation

用于计算增益补偿，根据音频实际 RMS 调整增益，确保达到预期的 SPL。

```python
def calculate_gain_compensation(self, file_path):
    """计算增益补偿（根据音频实际 RMS 调整增益，确保达到预期的 SPL）"""
    try:
        audio_seg = AudioSegment.from_file(file_path)
        current_rms_db = audio_seg.dBFS
        gain_db = -30.0 - current_rms_db
        gain_compensation = 10 ** (gain_db / 20)
        return gain_compensation
    except Exception as e:
        logger.warning(f"Failed to calculate RMS for gain adjustment: {e}")
        return 1.0
```

**原理**：
- 目标 RMS: -30dBFS（标准参考电平）
- 计算: `gain_db = -30 - current_rms_db`
- 例如：current_rms = -40dBFS，需要 +10dB 增益

### 交叠播放流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    交叠播放流程                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. PlaybackOrchestrator 构建统一 audio_to_play 列表             │
│     ├─ 主讲人: type='dry',       is_noise=False, loop=False      │
│     ├─ 噪声:   type='noise',     is_noise=True,  loop=True       │
│     └─ 干扰人: type='interferer',is_noise=False, loop=True/False │
│                                                                  │
│  2. 计算延迟时间（按 type 分类处理）                              │
│     ├─ 主讲人: delay 参与交叠计算（speaker 感知）                 │
│     ├─ 噪声:   delay = 0（强制，立即播放）                        │
│     └─ 干扰人: delay 保留 startDelay（不参与干声交叠）             │
│                                                                  │
│  3. 按设备分组 → 每个设备一个线程 → play_multi                    │
│                                                                  │
│  4. play_multi 回调处理（核心循环判定）                            │
│     ├─ use_loop = is_noise or loop                               │
│     ├─ 循环音频: 播完 → rewind → 重放                            │
│     ├─ 非循环音频: 播完 → 填静音 → 标记 dry_finished             │
│     ├─ all_empty 排除: 噪声和循环音频不算"无内容"                 │
│     └─ all_dry_finished 排除: 噪声和循环音频不参与结束判定        │
│                                                                  │
│  5. 流结束判定                                                   │
│     ├─ 所有非循环干声播完 + 所有延迟归零                          │
│     └─ 返回 paComplete，流停止                                   │
│                                                                  │
│  6. 同步停止（Orchestrator 层）                                  │
│     ├─ 计算 total_duration = max(audio_timelines.end)            │
│     └─ sleep(total_duration) → stop_task_audio()                │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

**回调内音频类型行为对照表**：

| 属性 | 主讲人 | 干扰人 loop=True | 干扰人 loop=False | 噪声 |
|------|--------|------------------|-------------------|------|
| `use_loop` | `False` | `True` | `False` | `True` |
| 播完后行为 | 填静音 | rewind 重放 | 填静音 | rewind 重放 |
| 计入 `all_dry_finished` | ✅ | ❌ | ✅ | ❌ |
| 计入 `all_empty` | ✅ | ❌ | ✅ | ❌ |
| `delay` | 交叠计算 | 保留 startDelay | 保留 startDelay | 强制 0 |

### 与算法配置集成

根据智能语音算法配置化方案，声纹识别算法的 overlap_rate/overlap_time 参数传递链路：

```
算法定义 (speaker_recognition)
        ↓ case_config.algorithm_params.overlap_rate / overlap_time
用例配置 (TestCase.algorithm_params)
        ↓
CaseParameterExtractor.get_overlap_rate() / get_overlap_time()
        ↓
AudioService.play_overlap(overlap_rate, overlap_time)
        ↓
重叠播放控制 (PyAudioDriver)
```

### 参数映射关系

| 组件类型 | 源参数 | 目标键 | 说明 |
|---------|--------|--------|------|
| device | overlap_rate | overlap_rate | 设备层重叠率参数 |
| api | overlap_rate | overlap | API层重叠率参数 |
| audio_engine | overlap_rate / overlap_time | overlap_rate / overlap_time | 音频引擎重叠播放控制 |

## 声纹识别场景识别机制

### 1. 算法识别逻辑

声纹识别场景通过用例/任务关联的算法类型识别：

```python
def is_speaker_recognition_case(task_or_case_config: dict) -> bool:
    """
    判断是否为声纹识别测试场景

    Args:
        task_or_case_config: 任务或用例配置

    Returns:
        True=声纹识别场景, False=普通场景
    """
    # 优先级1: 检查算法参数中是否包含 overlap_rate 或 overlap_time
    case_config = task_or_case_config.get('case_config', {})
    algorithm_params = case_config.get('algorithm_params', {})
    if 'overlap_rate' in algorithm_params or 'overlap_time' in algorithm_params:
        return True

    # 优先级2: 任务配置直接指定算法类型
    if task_or_case_config.get('algorithm_type') == 'speaker_recognition':
        return True

    # 优先级3: 用例配置中的算法类型
    if case_config.get('algorithm_type') == 'speaker_recognition':
        return True

    return False
```

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    声纹识别场景识别与调用流程                              │
```

### 设备匹配逻辑

`get_device_index(unique_id)` 支持多种匹配方式：

### 5. 回调函数处理

```python
def callback(in_data, frame_count, time_info, status):
    # 1. 读取音频数据
    data = wf.readframes(frame_count)

    # 2. 转换为 float32 并应用增益
    audio_data = np.frombuffer(data, dtype=np.int16).astype(np.float32)
    audio_data = audio_data * gain * gain_compensation * GLOBAL_SAFE_GAIN

    # 3. 创建输出缓冲区
    out_buffer = np.zeros(frame_count * stream_channels, dtype=np.float32)

    # 4. 声道映射
    if file_channels == 1:
        if channel_index < stream_channels:
            out_buffer[channel_index::stream_channels] = audio_data
    elif file_channels == 2:
        out_buffer[channel_index::stream_channels] = audio_data[0::2]

    # 5. 转换回 int16
    out_buffer = np.clip(out_buffer, -32768, 32767).astype(np.int16)
    return (out_buffer.tobytes(), pyaudio.paContinue)
```

### 6. play_multi 回调处理

回调函数在每个 PyAudio 流中循环调用，处理所有音频的混合输出。

**核心循环判定**（2026-06 修复）：

```python
use_loop = is_noise or audio_loop
```

- 旧代码：`use_loop = is_noise`，只有噪声循环，干扰人 `loop=True` 无法生效
- 新代码：`use_loop = is_noise or audio_loop`，噪声和 `loop=True` 的音频都循环

```python
def callback(in_data, frame_count, time_info, status):
    out_buffer = np.zeros(frame_count * stream_channels, dtype=np.float32)

    for i, wf in enumerate(wave_files):
        is_noise = audio_is_noise_list[i]
        audio_loop = audio_loops_list[i]
        use_loop = is_noise or audio_loop

        # 1. 处理延迟
        delay = audio_delays[i]
        if delay > 0:
            audio_delays[i] = max(0, delay - elapsed_time)
            data = bytes(frame_count * 2)  # 静音
        else:
            data = wf.readframes(frame_count)

        # 2. 文件末尾处理
        if len(data) == 0:
            if use_loop:
                wf.rewind()
                data = wf.readframes(frame_count)
            else:
                dry_finished_list[i] = True
                data = bytes(frame_count * 2)  # 静音

        # 3. 增益 + 通道映射
        audio_data = np.frombuffer(data, dtype=np.int16).astype(np.float32)
        effective_gain = audio_gains[i] * gain_compensations[i] * GLOBAL_SAFE_GAIN
        audio_data = audio_data * effective_gain
        ch_idx = channel_indices[i]
        out_buffer[ch_idx::stream_channels] += audio_data[:limit]

    # 4. 流结束判定
    all_dry_finished = all(
        dry_finished_list[i]
        for i in range(len(wave_files))
        if not audio_is_noise_list[i] and not audio_loops_list[i]
    )
    if all_dry_finished and all_delays_zero:
        return (None, pyaudio.paComplete)

    out_buffer = np.clip(out_buffer, -32768, 32767).astype(np.int16)
    return (out_buffer.tobytes(), pyaudio.paContinue)
```

**循环行为对照表**：

| 音频类型 | `is_noise` | `loop` | `use_loop` | 播完后 | 计入结束 |
|----------|------------|--------|------------|--------|----------|
| 主讲人 | `False` | `False` | `False` | 静音 | ✅ |
| 噪声 | `True` | `True` | `True` | rewind | ❌ |
| 干扰人(loop) | `False` | `True` | `True` | rewind | ❌ |
| 干扰人(单次) | `False` | `False` | `False` | 静音 | ✅ |

## Flask App Context 传递机制

### 问题背景

`execute_audio_playback` 在后台线程中执行时，需要调用 `spl_service.spl_to_gain()` 查询数据库获取 SPL 增益映射。但 Flask 的数据库连接（SQLAlchemy）需要在有效的 App Context 中才能访问。

### 问题描述

```
主线程 (HTTP 请求)
    ↓
创建后台线程执行音频播放
    ↓
后台线程中调用 spl_service.spl_to_gain()
    ↓
❌ 后台线程没有有效的 Flask App Context
    ↓
数据库查询失败，返回默认增益 1.0
```

### 解决方案

在启动后台线程前获取 Flask app 实例，并传递给 `execute_audio_playback`：

```python
# testcase_controller.py
app = current_app._get_current_object()  # 在主线程中获取有效的 app

def play_audio(app):
    result = execute_audio_playback(
        task_id=preview_task_id,
        ...
        app=app  # 传递给后台线程
    )

threading.Thread(target=play_audio, args=(app,)).start()
```

### 关键函数参数

| 函数 | 参数 | 说明 |
|------|------|------|
| `execute_audio_playback` | `app` | Flask 应用实例，用于后台线程中访问数据库 |
| `get_audio_configs_for_offset` | `app` | 传递给 `spl_service.spl_to_gain()` |
| `spl_service.spl_to_gain` | `app` | 创建 App Context 用于数据库查询 |

### spl_service.spl_to_gain 内部逻辑

```python
def spl_to_gain(mapping_id, target_spl, app=None):
    if app is not None:
        with app.app_context():  # 使用传入的 app 创建 context
            return _do_lookup()
    elif has_app_context():
        return _do_lookup()  # 使用当前线程的 context
    else:
        # 后台线程中无法获取 context，返回默认值
        return 1.0
```

### 注意事项

1. **必须在启动线程前获取 app**：`current_app._get_current_object()` 在主线程的 HTTP 请求处理上下文中有效
2. **后台线程中不要尝试获取 app**：在后台线程中调用 `current_app._get_current_object()` 会抛出 `RuntimeError`
3. **确保 app 参数正确传递**：所有涉及数据库访问的函数调用链都要传递 `app` 参数

## 常见问题

### 1. 采样率不支持

**错误**: `[Errno -9997] Invalid sample rate`

**原因**: WASAPI 模式不支持任意采样率

**解决**: 使用 `scipy.signal.resample_poly` 重采样到设备支持的标准采样率

### 2. 声道不匹配

**现象**: mono 音频在 stereo 设备上只有单边发声

**解决**:
- 优先打开 stereo (2通道) stream
- 使用 `channel_index` 选择输出声道

### 3. 同一设备多流错误

**错误**: `[Errno -9996] Invalid device`

**原因**: PyAudio 不允许同一设备同时打开多个流

**解决**: 使用 `play_multi` 方法在同一个流中混合多个音频

### 4. 设备匹配失败

**现象**: 选择 `[Ch 1]` 但找不到设备

**解决**:
- 提取 `[Ch N]` 后缀
- 匹配基础设备名
- 优先选择 WASAPI 设备

### 5. 无交叠时干声未播放就停止

**现象**: overlap_time=0 或 overlap_rate=0 时，干声还没开始播放就停止了

**原因**: `execute_audio_playback` 中计算 `total_duration` 的条件 `if overlap_time and overlap_time > 0 and len(dry_audios_info) >= 2` 过于严格，当 overlap_time=0 时 total_duration=0，导致立即停止

**解决**: 移除该条件限制，始终根据 `audio_timelines` 计算 `total_duration = max(t.get('end', 0) for t in audio_timelines)`
