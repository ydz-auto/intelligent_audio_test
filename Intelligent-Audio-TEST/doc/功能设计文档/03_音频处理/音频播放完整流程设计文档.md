# 音频播放完整流程设计文档

## 1. 概述

本文档描述音频从提交到真正开始播放的完整技术流程，涵盖数据准备、时间轴计算、设备解析、音频混音和实际播放的全部环节。

## 2. 采样率来源

### 2.1 三种采样率的区别

| 环节 | 采样率来源 | 说明 |
|------|-----------|------|
| **音频文件** | WAV 文件头 `wf.getframerate()` | 音频本身的采样率，如 44100、48000 |
| **播放设备** | `pyaudio.get_device_info_by_index()['defaultSampleRate']` | Windows 驱动返回的设备默认采样率 |
| **数据库存储** | `PlaybackDevice.sample_rate` | 注册设备时写入的采样率字段 |

### 2.2 设备采样率获取方式

设备采样率通过 **PyAudioDriver.get_devices()** 查询得到：

```python
# audio_engine.py L833-847
def get_devices(self):
    devices = []
    for i in range(self.pa.get_device_count()):
        dev_info = self.pa.get_device_info_by_index(i)
        host_api_info = self.pa.get_host_api_info_by_index(dev_info.get('hostApi'))
        if dev_info.get('maxOutputChannels') > 0:
            devices.append({
                "index": i,
                "name": dev_info.get('name'),
                "channels": dev_info.get('maxOutputChannels'),
                "sample_rate": int(dev_info.get('defaultSampleRate')),  # 设备默认采样率
                "host_api": host_api_info.get('name')
            })
    return devices
```

> **注意**：这里的 `defaultSampleRate` 是设备驱动报告的默认采样率，不是 pyaudio 探测设备支持的采样率列表。

### 2.3 播放时的采样率处理

在 `PyAudioDriver.play_multi()` 中（L946-954），打开流之前会尝试多种配置组合：

```python
dev_info = self.pa.get_device_info_by_index(device_index)
max_channels = int(dev_info.get('maxOutputChannels', 2))
default_sample_rate = dev_info.get('defaultSampleRate', 44100)

# 尝试的配置组合
candidate_configs = set()
candidate_configs.add((max_channels, original_rate))      # 音频原始采样率
candidate_configs.add((2, original_rate))
candidate_configs.add((max_channels, 48000))
candidate_configs.add((2, 48000))
candidate_configs.add((max_channels, 44100))
candidate_configs.add((2, 44100))
candidate_configs.add((max_channels, default_sample_rate))
candidate_configs.add((2, default_sample_rate))
```

然后尝试用每种组合打开流，直到成功为止。

### 2.4 重采样机制

当音频文件采样率与设备采样率不一致时，会自动进行重采样（L1026-1029）：

```python
file_rate = file_rates_list[i] if i < len(file_rates_list) else stream_rate
if file_rate != stream_rate:
    audio_data = self.resample_audio_data(audio_data, file_rate, stream_rate)
    actual_frames = len(audio_data) // file_ch
```

重采样使用 `scipy.signal.resample_poly`，通过计算原始采样率和目标采样率的最大公约数进行多相滤波重采样。

## 3. 完整播放流程

### 3.1 流程总览

```
前端预览请求 / E2E 测试执行
    ↓
TestCaseController.preview() / E2EExecutor._execute_e2e_with_rounds()
    ↓
PlaybackOrchestrator.preview() / play_round()  ← 统一编排：配置构建 + 设备绑定 + 时间轴
    ↓
build_audio_timelines()  ← 计算交叠时间轴，考虑 speaker 感知
    ↓
AudioService.get_device_index()  ← 把 device_unique_id 转成 pyaudio 索引
    ↓
AudioService.play_overlap()  ← 按设备分组，启动多线程播放
    ↓
PyAudioDriver.play_multi()
    ↓
pyaudio.open() 打开流 + 回调函数驱动播放
```

#### Step 2: 准备播放信息

**playback_orchestrator.py** — `PlaybackOrchestrator`

Orchestrator 内部完成配置构建，对外只需传高层配置：

1. `_resolve_dry_audios()` — 遍历音频配置，按 `audio_type` 分类干声/噪声，从数据库加载 Audio 对象
2. `_build_noise_info()` — 解析噪声音频和设备列表
3. `_build_dry_configs()` — 构建主讲人 audio_to_play 配置（含设备索引、通道、SPL 增益）
4. `_build_noise_play_configs()` — 构建噪声 audio_to_play 配置（`loop=True`, `is_noise=True`, `type='noise'`）
5. `_build_interferer_configs()` — 构建干扰人 audio_to_play 配置（`type='interferer'`, `is_noise=False`, 保留 `delay`）
6. `build_audio_timelines()` — 计算交叠时间轴（speaker 感知）
7. 合并三类音频为统一 `audio_to_play` 列表，调用 `AudioService.play_overlap()`

**三类音频语义拆分**（`audio_to_play` 统一数据结构）：

| 字段 | 主讲人 | 噪声 | 干扰人 |
|------|--------|------|--------|
| `type` | `'dry'` | `'noise'` | `'interferer'` |
| `is_noise` | `False` | `True` | `False` |
| `loop` | `False` | `True` | `True/False` |
| `delay` | `0` | `0`（强制） | 保留 `startDelay` |

#### Step 3: 构建时间轴

**audio_engine.py** — `build_audio_timelines()` L323-L397

该函数计算每个音频的实际开始时间和结束时间：

```python
audio_timelines.append({
    'config': audio_config,
    'audio': audio_obj,
    'file': file_path,
    'start': start_time,      # 计算得到的开始时间
    'end': start_time + duration,  # 结束时间
    'timeline_duration': duration
})
```

**Speaker 感知交叠逻辑**：
- 相邻音频有共同 speaker → 顺序播放（start_time = prev_end_time）
- 相邻音频无共同 speaker 且 overlap_time > 0 → 交叠（start_time = prev_end_time - overlap_time）
- 相邻音频无共同 speaker 且 overlap_rate > 0 → 交叠（start_time = prev_end_time * (1 - overlap_rate)）
- 否则 → 顺序播放

该函数计算每个音频相对于全局时间的延迟：


#### Step 4.1: playback_device_id 类型兼容

**问题**：`audio_config.get('playback_device_id')` 返回的类型可能是字符串 `"11"` 或整数 `11`，而 `playback_devices_map` 的 key 可能是另一种类型。

**修复方案**（L439-440）：
```python

device_info = playback_devices_map.get(playback_dev_id_int) or playback_devices_map.get(playback_dev_id)
```

**原理**：Python 字典中 `11` (int) 和 `"11"` (str) 是不同的 key，同时尝试两种方式可以兼容两种类型。

#### Step 5: 设备索引解析

**audio_engine.py** — `AudioService.get_device_index()` L1136-L1265

该函数将 `device_unique_id`（如 `"扬声器 (RME Fireface 802) [Ch 1]"`）转换为 pyaudio 的设备索引。

**匹配策略优先级**：
1. 精确匹配（名称完全一致）
2. 基础名称匹配（去掉 `[Ch X]` 部分）
3. 添加"扬声器"前缀匹配
4. 模糊匹配（包含关系）
5. 括号内容匹配（提取 `(X- RME Fireface UCX II)` 中的设备名）

**API 优先级**：
```
Windows WDM-KS > Windows DirectSound > Windows WASAPI > MME
```

**RME 设备特殊处理**：优先选择不带"扬声器"字样的设备（避免降混到 1/2 通道）。

设备列表会缓存 5 秒，避免频繁扫描导致驱动崩溃：
```python
def _get_cached_devices(self):
    with self._lock:
        current_time = time.time()
        if self._device_cache is None or (current_time - self._cache_time) > self._cache_duration:
            self._device_cache = self.driver.get_devices()
            self._cache_time = current_time
        return self._device_cache
```

#### Step 7: PyAudio 实际播放

**audio_engine.py** — `PyAudioDriver.play_multi()` L849-L1110

这是最终调用 pyaudio 打开流并播放的核心函数：

1. **打开音频文件**：使用 `wave.open()` 读取音频，获取原始采样率和通道数
2. **获取设备信息**：调用 `pa.get_device_info_by_index()` 获取设备支持的最大通道数和默认采样率
3. **尝试打开流**：遍历多种 (channels, sample_rate, format) 组合，直到成功
4. **预重采样（如需要）**：如果音频采样率与设备采样率不一致，在播放前一次性完成重采样
5. **创建回调函数**：在回调中处理：
   - 读取每个音频文件的数据
   - 延迟处理（根据 delay 值决定是否开始播放）
   - 混音（多音频叠加到同一缓冲区）
   - 增益应用（包括 SPL 增益补偿）
   - 输出到设备

**预重采样逻辑**（L940-L1010）：

在流打开前，如果发现音频采样率与设备采样率不一致，会一次性完成重采样：

```python
target_rate = default_sample_rate

# 检查是否需要重采样
needs_resample = any(file_rate != target_rate for file_rate in audio_file_rates)

if needs_resample:
    # 一次性读取全部数据并重采样
    for i, wf in enumerate(audio_files):
        file_rate = audio_file_rates[i]
        if file_rate == target_rate:
            continue

        # 读取原始数据
        wf.rewind()
        audio_data = wf.readframes(wf.getnframes())
        audio_np = np.frombuffer(audio_data, dtype=np.int16).astype(np.float32)

        # 重采样
        resampled_np = self.resample_audio_data(audio_np, file_rate, target_rate)
        resampled_np = np.clip(resampled_np, -32768, 32767).astype(np.int16)

        # 保存到临时文件
        temp_file = os.path.join(resample_temp_dir, f'resampled_{i}.wav')
        with wave.open(temp_file, 'wb') as resampled_wf:
            resampled_wf.setnchannels(audio_file_channels[i])
            resampled_wf.setsampwidth(2)
            resampled_wf.setframerate(target_rate)
            resampled_wf.writeframes(resampled_np.tobytes())

        resampled_wf_new = wave.open(temp_file, 'rb')

# 关闭原始文件
for wf in audio_files:
    wf.close()

# 替换为预重采样后的文件
audio_files = resampled_audio_files
audio_file_rates = resampled_audio_rates
original_rate = target_rate
```

**配置精简**：由于所有音频都已转为 `default_sample_rate`，打开流时只需尝试两种配置：
- `(max_channels, target_rate)`
- `(2, target_rate)`

**回调函数核心逻辑**（L979-1062）：

回调函数不再进行重采样（因为预重采样已处理），只负责音频混音和输出：

```python
def callback(in_data, frame_count, time_info, status):
    out_buffer = np.zeros(frame_count * stream_channels, dtype=np.float32)

    for i, wf in enumerate(wave_files):
        # 1. 处理延迟
        delay = audio_delays[i]
        if delay > 0:
            audio_delays[i] = max(0, delay - elapsed_time)
            data = bytes(frame_count * 2)  # 输出静音
        else:
            data = wf.readframes(frame_count)

        # 2. 读取数据（已预重采样，无需在回调中重采样）
        audio_data = np.frombuffer(data, dtype=np.int16).astype(np.float32)

        # 3. 应用增益
        effective_gain = audio_gains[i] * self.GLOBAL_SAFE_GAIN * gain_compensations[i]
        audio_data = audio_data * effective_gain

        # 4. 混音到输出缓冲区
        if file_ch == 1:
            out_buffer[ch_idx:frame_count*stream_channels:stream_channels] += audio_data
        elif file_ch == 2:
            out_buffer[ch_idx:frame_count*stream_channels:stream_channels] += audio_data[0::2]
            out_buffer[ch_idx+1:frame_count*stream_channels:stream_channels] += audio_data[1::2]

    # 5. 输出
    out_buffer = np.clip(out_buffer, -32768, 32767).astype(np.int16)
    return (out_buffer.tobytes(), pyaudio.paContinue)
```

## 4. 关键数据结构

### 4.1 音频配置 (audio_to_play)

统一的播放配置结构，通过 `type` / `is_noise` / `loop` 三个字段区分音频类型：

```python
# 主讲人
{
    'file': '/path/to/audio.wav',
    'device_index': 5,
    'channel': 0,
    'gain': 0.5,
    'offset': 0,
    'duration': 10.5,
    'play_order': 1,
    'loop': False,                        # 控制循环行为（独立字段）
    'is_noise': False,                    # 音频类型标识
    'type': 'dry',                        # 来源：dry / noise / interferer
    'delay': 0.0,                         # 主讲人无延迟
    'audio_id': 123,
}

# 噪声
{
    'file': '/path/to/noise.wav',
    'device_index': 6,
    'channel': 0,
    'gain': 0.8,
    'loop': True,
    'is_noise': True,
    'type': 'noise',
    'delay': 0.0,                         # 噪声延迟强制为 0
    'play_order': 0,
}

# 干扰人
{
    'file': '/path/to/interferer.wav',
    'device_index': 7,
    'channel': 0,
    'gain': 1.0,
    'loop': True,                         # 干扰人可配置是否循环
    'is_noise': False,                    # 人声类型，非噪声
    'type': 'interferer',
    'delay': 1.5,                         # 保留 startDelay（秒）
}
```

**三字段语义说明**：

| 字段 | 含义 | 主讲人 | 噪声 | 干扰人 |
|------|------|--------|------|--------|
| `type` | 来源分类 | `dry` | `noise` | `interferer` |
| `is_noise` | 音频类型（人声/背景音） | `False` | `True` | `False` |
| `loop` | 播放行为（是否循环） | `False` | `True` | `True/False` |

**回调内循环判定**：`use_loop = is_noise or loop`，噪声和 `loop=True` 的音频都会 rewind 重放，但不计入 `all_dry_finished` 结束判定。

## 6. SPL 增益计算

### 6.1 SPL 映射机制

在 `get_audio_configs_for_offset()` 中（L446-457），会根据设备的 SPL 映射计算增益：

```python
if device_obj and device_obj.current_spl_mapping_id:
    target_spl = audio_config.get('spl', 65.0)
    gain = spl_service.spl_to_gain(
        device_obj.current_spl_mapping_id,
        target_spl,
        app=app
    )
    gain_db = 20 * np.log10(gain) if gain > 0 else -999
else:
    gain = device_info.get('gain', 1.0)
```

### 6.2 增益补偿

`PyAudioDriver.calculate_gain_compensation()` L762-L773 根据音频实际 RMS 调整增益：

```python
audio_seg = AudioSegment.from_file(file_path)
current_rms_db = audio_seg.dBFS
gain_db = -30.0 - current_rms_db  # 目标 RMS 为 -30 dBFS
gain_compensation = 10 ** (gain_db / 20)
```

最终增益 = `audio_gains[i] * GLOBAL_SAFE_GAIN * gain_compensation`

## 9. 采样率总结

**采样率不是 pyaudio "探测"出来的，而是：**

1. **设备采样率**：Windows 驱动返回的 `defaultSampleRate`，通过 `pyaudio.get_device_info_by_index()` 获取

2. **播放时会尝试多种组合**：44100、48000、设备默认采样率等，找到能成功打开流的配置

3. **音频采样率与设备采样率不匹配时**：在流打开成功后、播放前进行**预重采样**，一次性将音频转为设备采样率，存储到临时文件

4. **预重采样临时文件路径**：`config.py` 中配置 `RESAMPLE_TEMP_PATH`，默认为 `项目根目录/temp_resample`

5. **回调函数不再进行重采样**：预重采样使得回调函数只负责音频混音和输出，保证了实时性
