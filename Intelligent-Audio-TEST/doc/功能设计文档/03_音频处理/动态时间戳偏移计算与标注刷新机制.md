# 动态时间戳偏移计算与标注刷新机制

## 1. 功能概述

### 1.1 问题背景

在 E2E（端到端）测试中，参考参数生成器（`reference_params_generator.py`）预计算理论时间戳，但实际播放音频时存在系统延迟、设备响应延迟、音频加载延迟等，导致理论时间戳与实际录制的音频时间戳不匹配。

### 1.2 VAD 静音去除问题

部分设备内置 VAD（语音活动检测）功能，会自动去除开始说话前的静音。这意味着：
- **设备返回的时间戳**：首个时间戳可能是 0.1s（VAD 去除静音后）
- **参考时间戳**：首个时间戳可能是 2.0s（含静音）
- **系统测量的 playback_time_offsets**：可能是 0.5s（播放延迟）

如果直接使用 playback_time_offsets 调整参考时间戳：
```
2.0 + 0.5 = 2.5s  # 但设备首个时间戳是 0.1s，差距仍然很大
```

### 1.3 解决方案

在执行时动态计算 **effective_offset**（有效偏移量）：
1. 从设备 raw_results 中提取 rttm/stm 首个时间戳（设备实际）
2. 从参考参数中提取参考首个时间戳
3. 计算 `effective_offset = 设备首个时间戳 - 参考首个时间戳`
4. 用 effective_offset 调整参考参数

```
effective_offset = 0.1 - 2.0 = -1.9s
参考调整后 = 2.0 + (-1.9) = 0.1s ≈ 设备时间戳 ✓
```

## 2. 技术设计

### 2.1 核心思路

1. **记录关键时间点**：在录音开始时记录 `record_start_time`，在每个音频播放时记录 `actual_play_time`
2. **计算系统偏移**：比较理论时间与实际时间的差异，计算 `playback_time_offsets`
3. **采集设备结果**：收集设备返回的 raw_results
4. **计算有效偏移**：从 raw_results 中提取设备首个时间戳，计算 `effective_offset`
5. **调整标注**：根据 effective_offset 调整 RTTM/STM 标注中的时间戳
6. **实时应用**：将调整后的标注用于评估计算和结果存储

### 2.2 数据结构

```python
# E2EExecutor 中维护的时间戳记录
_playback_timestamps = {
    task_id: {
        'record_start_time': float,      # 录音开始时间戳
        'audio_play_times': [            # 音频播放时间列表
            {
                'audio_id': str,
                'actual_time': float,
                'is_overlap': bool       # 是否重叠播放
            }
        ],
        'theory_offsets': {               # 理论偏移量（基于 overlap_rate）
            audio_id: {
                'play_order': int,
                'spl': float,
                'playback_device_id': int
            }
        }
    }
}
```

## 3. 代码实现

### 3.1 时间戳记录（e2e_executor.py）

**位置**：`E2EExecutor._pre_process_devices`

def _pre_process_devices(self, device_info_list, case_name, task_id, phase, **kwargs):
    record_start_time = time.time()

        'audio_play_times': [],
        'theory_offsets': {}

**位置**：`E2EExecutor._play_dry_audios_overlap`（重叠播放）

### 3.3 偏移量计算（e2e_executor.py）

**位置**：`E2EExecutor._calculate_actual_offset`

```python
def _calculate_actual_offset(self, task_id, playback_timestamps):
    record_start_time = playback_timestamps.get('record_start_time')
    audio_play_times = playback_timestamps.get('audio_play_times', [])
    
    if not record_start_time or not audio_play_times:
        return 0.0
    
    sorted_play_times = sorted(audio_play_times, key=lambda x: x.get('actual_time', 0))
    first_actual_time = sorted_play_times[0].get('actual_time', record_start_time)
    
    actual_offset = first_actual_time - record_start_time - first_theory_offset
    
    return actual_offset
```

### 3.4 有效偏移量计算与标注调整（device_result_collector.py）

**核心方法**：`DeviceResultCollector._calculate_effective_offset_and_adjust`

流程：
1. 先收集设备结果（`collect_raw_results`）
2. 从 raw_results 中提取设备首个时间戳（`recording_rttm_content` 或 `recording_stm_content`）
3. 从 reference_params 中提取参考首个时间戳
4. 计算 `effective_offset = 设备首个时间戳 - 参考首个时间戳`
5. 用 effective_offset 调整参考参数

```python
# 核心计算逻辑
device_first_timestamp = self._get_device_first_timestamp(all_results)
ref_first_timestamp = self._get_reference_first_timestamp(reference_params)
effective_offset = device_first_timestamp - ref_first_timestamp
adjusted_reference_params = self._apply_single_offset(reference_params, effective_offset)
```

**新增方法**：

| 方法 | 功能 |
|------|------|
| `_calculate_effective_offset_and_adjust` | 计算 effective_offset 并调整参考参数 |
| `_get_device_first_timestamp` | 从 raw_results 提取设备首个时间戳 |
| `_extract_first_timestamp_from_text` | 从 RTTM/STM 文本提取首个时间戳 |
| `_get_reference_first_timestamp` | 从 reference_params 提取参考首个时间戳 |
| `_apply_fallback_offset` | 无法计算 effective_offset 时回退使用 playback_time_offsets |

**位置**：`DeviceResultCollector.collect_raw_results`

```python
# 调整 segments
for seg in value['segments']:
    new_seg = seg.copy()
    if 'start' in new_seg:
        new_seg['start'] = new_seg['start'] + offset
    if 'end' in new_seg:
        new_seg['end'] = new_seg['end'] + offset
    adjusted_segments.append(new_seg)

# 调整 RTTM 文本
# SPEAKER file_id 1 start_time duration <NA> speaker_id <NA>
parts[3] = f"{new_start_time:.2f}"

# 调整 STM 文本
# file_id speaker start_time end_time text
parts[2] = f"{new_start_time:.2f}"
parts[3] = f"{new_end_time:.2f}"
```

## 4. 数据流

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           E2E 测试执行流程                                   │
└─────────────────────────────────────────────────────────────────────────────┘

1. _pre_process_devices
   └─ 记录 record_start_time

2. _play_dry_audios / _play_dry_audios_overlap
   └─ 记录 actual_play_time

3. _collect_results
   └─ 计算 playback_time_offsets（系统测量的播放延迟）
       └─ _calculate_actual_offset()

4. DeviceResultCollector.collect_raw_results (device_result_collector.py)
   └─ Step 1: 收集设备结果，获取 raw_results
   └─ Step 2: 提取设备首个时间戳
       └─ _get_device_first_timestamp()
   └─ Step 3: 提取参考首个时间戳
       └─ _get_reference_first_timestamp()
   └─ Step 4: 计算 effective_offset = 设备首个时间戳 - 参考首个时间戳
       └─ _calculate_effective_offset_and_adjust()
   └─ Step 5: 用 effective_offset 调整参考参数
       └─ _apply_single_offset()
   └─ 存入 adjusted_reference_params

5. _process_results (base_executor.py)
   └─ 用调整后标注替换原始标注

6. _evaluate_result (base_executor.py)
   └─ CaseParameterExtractor._build_evaluation_params()
       └─ 使用调整后标注计算评估参数

7. 评估服务
   └─ 基于调整后标注计算得分

8. test_results 表存储
   └─ result_data.adjusted_reference_params = 调整后标注
```

### 4.1 关键公式

| 公式 | 说明 |
|------|------|
| `playback_time_offset = actual_play_time - record_start_time - theory_offset` | 系统测量的播放延迟 |
| `effective_offset = 设备首个时间戳 - 参考首个时间戳` | 有效偏移量（考虑 VAD 静音去除） |
| `参考调整后时间戳 = 参考原始时间戳 + effective_offset` | 调整后的参考时间戳 |

## 8. 测试验证

### 8.1 验证方法

1. 执行 E2E 测试用例
2. 检查日志中的偏移量计算：
   ```
   [_calculate_effective_offset_and_adjust] device_first_ts=0.100, ref_first_ts=2.000, effective_offset=-1.900
   ```
3. 查询数据库验证存储：
   ```sql
   SELECT id, result_data->>'$.adjusted_reference_params'
   FROM test_results
   WHERE result_data LIKE '%adjusted_reference_params%';
   ```

### 8.2 预期效果

- 系统播放延迟存在时，会通过 playback_time_offsets 反映
- VAD 去除静音导致设备/参考首个时间戳不一致时，使用 effective_offset 调整
- effective_offset = 设备首个时间戳 - 参考首个时间戳
- 评估分数基于调整后的标注计算
- 存储的 `result_data` 包含调整后的标注供后续分析

### 8.3 回退机制

如果无法从设备 raw_results 中提取首个时间戳（例如设备未返回 rttm/stm 内容），会回退使用系统测量的 `playback_time_offsets`：

```
[_calculate_effective_offset_and_adjust] Cannot get device first timestamp, fallback to playback_time_offsets
[_apply_fallback_offset] Using playback_time_offsets: 0.500
```

## 9. 旧数据修复

### 9.1 问题

旧数据存储的 `adjusted_reference_params` 可能是使用旧的 `playback_time_offsets` 计算的，对于有 VAD 静音去除的设备可能不准确。

### 9.2 解决方案

使用重新评估功能修复旧数据：

| 参数组合 | 行为 | 能否修复旧 offset 问题 |
|----------|------|----------------------|
| `reextract_device_output=true` | 从存档重新提取设备输出，重新计算 effective_offset | ✅ 可以 |
| `reextract_device_output=false` | 使用存储的 `adjusted_reference_params` | ❌ 不能 |

**推荐操作**：对于有 VAD 静音去除问题的设备历史数据，执行：
```json
POST /api/v1/evaluation/task/reevaluate
{
    "task_id": 123,
    "reevaluate_type": "all",
    "reextract_device_output": true
}
```

### 9.3 重新提取时的 effective_offset 计算逻辑

当 `reextract_device_output=true` 时：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                     重新提取 effective_offset 计算流程                        │
└─────────────────────────────────────────────────────────────────────────────┘

1. 从 TestCase 表获取原始 reference_params
   └─ TestCase.reference_params（未调整的原始参考参数）

2. 从存档提取设备输出 extracted_result
   └─ 包含 recording_rttm_content / recording_stm_content

3. 计算 effective_offset
   ├─ 设备首个时间戳 = 从 extracted_result 提取
   ├─ 参考首个时间戳 = 从 original_reference_params 提取
   └─ effective_offset = 设备首个时间戳 - 参考首个时间戳

4. 调整参考参数
   └─ adjusted_reference_params = _apply_single_offset(reference_params, effective_offset)

5. 保存到新的 TestResult.result_data
```

**关键代码**（`device_result_reextractor._calculate_adjusted_reference_params`）：

```python
device_first_ts = _get_device_first_timestamp_from_result(extracted_result)
ref_first_ts = _get_reference_first_timestamp(original_reference_params)
effective_offset = device_first_ts - ref_first_ts
adjusted_params = _apply_single_offset(original_reference_params, effective_offset)
```

### 9.4 回退机制

如果无法计算 effective_offset（例如无法从 TestCase 获取原始 reference_params），会回退使用旧的 `adjusted_reference_params`：

```
[_calculate_adjusted_reference_params] original_reference_params is None, fallback to old adjusted_reference_params
```
