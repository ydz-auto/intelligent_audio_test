# 音频标注与参考参数功能设计文档

## 概述

本文档描述音频标注数据的存储机制以及测试用例参考参数的生成逻辑。

## 一、音频标注存储

### 1.1 数据模型

音频标注数据存储在 `AudioAnnotation` 表（对应模型类 `AudioAnnotation`），其结构如下：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer | 主键ID |
| audio_id | Integer | 关联音频ID (外键) |
| format | String | 标注格式 (json/rttm/stm) |
| name | String | 标注名称/描述 |
| data | JSON | 标注数据内容 |
| source_language | String | 源语言代码 |
| target_language | String | 目标语言代码 |
| deleted | Boolean | 逻辑删除标志 |
| created_at | DateTime | 创建时间 |
| updated_at | DateTime | 更新时间 |

### 1.2 标注数据来源

**所有音频标注都由前端解析并存储到 AudioAnnotation 表。**

后端不再负责解析任何标注文件（如 RTTM、STM 等格式），只负责存储前端传递过来的标注数据。

### 1.3 存储场景

1. **音频上传时**：通过 `merge_chunks` 方法，前端传递 `annotations` 数组，后端创建 `AudioAnnotation` 记录
2. **更新元数据时**：通过 `update_metadata` 方法，前端传递更新后的 `annotations` 数组

### 1.4 已移除的功能

以下功能已被移除，不再从 txt 文件解析标注：
- `parse_audio_txt_file` 函数已删除
- 不再从与音频同名的 txt 文件解析标注数据

## 二、参考参数生成

### 2.1 算法参考参数定义表

`algorithm_reference_params` 表定义了每个算法需要哪些参考参数：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer | 主键ID |
| algorithm_type | String | 关联算法类型 |
| code | String | 参数代码 |
| name | String | 参数显示名称 |
| param_type | String | 参考类型：text, audio, rttm_text, rttm_json, stm_text, stm_json |
| help_text | String | 帮助提示文字 |
| deleted | Boolean | 逻辑删除标志 |

### 2.2 生成器架构

`ReferenceParamsGenerator` 类采用策略模式，根据 `algorithm_type` 选择对应的生成器类：

```python
_generators: Dict[str, List[type]] = {
    'translation': [TranslationASRGenerator, TranslationTextGenerator, TranslationRTTMGenerator, TranslationSTMGenerator],
    'asr': [ASRGenerator, ASRRTTMGenerator, ASRSTMGenerator],
    'tts': [TTSGenerator],
    'speaker_recognition': [SpeakerRecognitionGenerator, SpeakerRecognitionRTTMGenerator],
    'vad': [VADGenerator, VADRTTMGenerator]
}
```

### 2.3 数据提取来源

| 生成器类 | 提取来源 | 生成的参考参数代码 |
|---------|---------|------------------|
| TranslationASRGenerator | Audio.asr_text | asr_reference_text |
| TranslationTextGenerator | AudioAnnotation | translation_reference_text |
| TranslationRTTMGenerator | AudioAnnotation (rttm格式) | asr_reference_rttm |
| TranslationSTMGenerator | AudioAnnotation (stm格式) | asr_reference_stm |
| ASRGenerator | Audio.asr_text | asr_reference_text |
| ASRRTTMGenerator | AudioAnnotation (rttm格式) | asr_reference_rttm |
| ASRSTMGenerator | AudioAnnotation (stm格式) | asr_reference_stm |
| TTSGenerator | Audio.asr_text | tts_reference_text |
| SpeakerRecognitionGenerator | Audio.asr_text | speaker_reference_text |
| SpeakerRecognitionRTTMGenerator | AudioAnnotation (rttm格式) | speaker_reference_rttm |
| VADGenerator | Audio.asr_text | vad_reference_text |
| VADRTTMGenerator | AudioAnnotation (rttm格式) | vad_reference_rttm |

### 2.4 生成流程

1. 根据测试用例的 `algorithm_type` 查找对应的生成器类列表
2. 遍历每个生成器类，调用其 `generate(config)` 方法
3. 从用例配置的 `audios` 列表中获取音频ID
4. 从 `AudioAnnotation` 表根据 `audio_id` 和 `format` 查询标注数据
5. 根据需要处理重叠播放场景的时间戳调整
6. 生成参考参数并存储到测试用例的 `reference_params` 字段

### 2.5 重叠播放支持

参考参数生成器支持重叠播放场景的时间戳调整：

- 从用例配置的 `algorithm_params` 中获取 `overlap_rate`（重叠率，0.0-1.0）
- 计算每个音频的开始时间偏移
- 根据偏移量调整标注片段的时间戳
- 合并多个音频的标注片段并按时间排序

## 三、数据流总结

### 3.1 标注存储流程

```
前端解析标注文件 → API传递annotations数组 → 后端存储到AudioAnnotation表
```

### 3.2 参考参数生成流程

```
创建测试用例 → 选择算法类型 → 根据algorithm_reference_params配置 →
从AudioAnnotation表提取标注 → 生成参考参数 → 存储到测试用例的reference_params字段
```

### 3.3 评估时参数获取流程

```
评估任务 → 根据算法查找algorithm_reference_params配置 →
根据param_type从reference_params提取对应格式的值 →
传递给评估API
```
