# 声纹识别交叠播放时间计算文档

## 概述

本文档解释声纹识别（Speaker Recognition）算法中，多音频交叠播放（Overlap Playback）的时间计算逻辑，包括：
1. 链式交叠概念
2. 交叠时间（overlap_time）与交叠率（overlap_rate）的区别
3. 有效延迟（effective_delay）计算
4. 进度条拖动时的 offset 计算
5. 边界情况处理

## 1. 核心概念澄清

### 链式交叠（Chain Overlap）

当前实现采用**链式交叠**模式：每个音频与**前一个**音频在结尾处交叠 `overlap_time` 秒。

```
音频0:  0s -------- 24.185s
音频1:       5s -------- 29.185s  (与音频0在结尾5s处交叠)
音频2:          10s -------- 34.185s (与音频1在结尾5s处交叠)
音频3:               15s -------- 39.185s
...
```

### overlap_time vs overlap_rate

**overlap_time（交叠时间）**：
- 定义：每个音频与前一个音频**同时播放的时间段长度**（秒）
- 含义：如 `overlap_time = 5s` 表示每个音频与前一个音频同时播放 5 秒
- 优先级：**高于** overlap_rate

**overlap_rate（交叠率）**：
- 定义：每个交叠时间占前一个音频时长的比例 (0.0-1.0)
- 含义：如 `overlap_rate = 0.2` 表示每个音频在前一个音频结束前 20% 的时间开始
- 示例：24s 音频 × 0.2 = 4.8s 交叠

### 关键公式（链式交叠）

```python
# 链式交叠公式（使用 prev_end_time 实现真正的链式交叠）
prev_end_time = 0
for i, config in enumerate(sorted_dry):
    if i == 0:
        start_time = 0
    else:
        if overlap_time > 0:
            start_time = prev_end_time - overlap_time
            if start_time < 0:
                start_time = 0  # 边界：超过前一个音频时长时，从0开始
        elif overlap_rate > 0:
            start_time = prev_end_time * (1 - overlap_rate)
        else:
            start_time = prev_end_time  # 顺序播放

    audio_delays_with_config.append((config, start_time))
    prev_end_time = start_time + effective_duration

# 其中：
# - i: 音频索引（从1开始）
# - prev_end_time: 前一个音频的结束时间
# - effective_duration: 当前音频的有效时长（duration - offset）
# - overlap_time: 交叠时间（秒），优先级最高
```

## 2. 音频总时间计算

### 问题描述

当多个音频使用链式交叠模式播放时，总播放时间取决于音频数量和交叠时间。

### 计算公式

对于 N 个音频，时长均为 D，交叠时间为 T：
```
total_duration = D + (N-1) * (D - T)
```

### 示例

| 音频数 | 每个音频时长 | overlap_time | total_duration |
|--------|-------------|--------------|----------------|
| 2 | 24.185s | 5s | 24.185 + (24.185 - 5) = 43.37s |
| 3 | 24.185s | 5s | 24.185 + 2 × 19.185 = 62.555s |
| 100 | 24.185s | 5s | 24.185 + 99 × 19.185 = 1924.4s |

## 3. 有效延迟（effective_delay）计算

### 定义

有效延迟是指前一个音频开始播放后，等待多长时间**开始播放**当前音频。

### 计算公式（链式交叠）

```python
if i == 0:
    start_time = 0  # 第一个音频立即开始
else:
    if overlap_time > 0:
        start_time = prev_end_time - overlap_time
        if start_time < 0:
            start_time = 0  # 边界：超过前一个音频时长时，从0开始
    elif overlap_rate > 0:
        start_time = prev_end_time * (1 - overlap_rate)
    else:
        start_time = prev_end_time  # 顺序播放
```

### 100个音频 + overlap_time=5s 示例

假设每个音频 24.185s（使用新的链式交叠公式）：

| 音频 | 开始时间 | 结束时间 | 交叠时间 |
|------|---------|---------|----------|
| 0 | 0s | 24.185s | - |
| 1 | 19.185s | 43.37s | 5s (与音频0) |
| 2 | 38.37s | 62.555s | 5s (与音频1) |
| 3 | 57.555s | 81.74s | 5s (与音频2) |
| ... | ... | ... | ... |
| 99 | 1884.215s | 1924.4s | 5s (与音频98) |

**关键**：每个音频的开始时间 = 前一个音频的结束时间 - overlap_time

## 4. 进度条拖动时的 Offset 计算

### 问题描述

当用户拖动进度条到某个位置时，需要重新计算每个音频的起始播放位置。

### 目标时间映射

```
用户目标时间 → 找到该时间点正在播放的音频 → 计算 offset
```

### 计算公式

```python
offset = target_time - audio_start_time
if offset < 0:
    offset = 0  # 从头开始
```

### 边界处理

1. **offset < 0**: 设为 0（从头开始播放）
2. **offset >= duration**: 设为 duration - 0.1（播放最后部分）

## 6.1 同声道混合机制

**Speaker 感知逻辑负责判断时序关系（顺序/交叠），实际的同声道混合由 `play_multi` 的 callback 函数处理**。

| 场景 | 时序关系 | 物理层处理 |
|------|---------|-----------|
| 同 speaker + 同声道 | 顺序播放 | 不涉及混合 |
| 不同 speaker + 同声道 | 交叠 | `out_buffer[ch] += audio1 + audio2` 混合 |
| 同 speaker + 不同声道 | 顺序播放 | 不涉及混合 |
| 不同 speaker + 不同声道 | 交叠 | 不同声道输出，无混合 |

**同声道混合原理**：

```python
# play_multi callback 中
out_buffer[ch_idx:limit*stream_channels:stream_channels] += audio_data[:limit]
```

**效果示例**：

```
音频1 (spk0):        [AAAAAAA        ]────────────────────────►  channel=0
音频2 (spk1):             [BBBBB]────────────────────────►  channel=0

时间轴：0 ─────────────────────────────────────────────────►
         0-7s: 只有 spk0 播放
         7-12s: spk0 + spk1 同时播放，信号叠加
         12s+: 只有 spk1 播放
```

## 7. 边界情况处理

### 边界情况完整矩阵

| 场景 | duration | overlap_time | overlap_rate | start_time计算 | 结果 |
|------|----------|-------------|-------------|----------------|------|
| 1 | 24.185s | 5s | - | prev_end - 5 | 链式交叠，正常工作 |
| 2 | 24.185s | 0 | 0 | prev_end | 顺序播放 |
| 3 | 24.185s | 24.185s | - | prev_end - 24.185 | start_time=0，完全交叠 |
| 4 | 24.185s | 30s (>duration) | - | prev_end - 30 | start_time<0，限制为0 |
| 5 | 24.185s | 50s (>2*duration) | - | prev_end - 50 | start_time<0，限制为0 |
| 6 | 24.185s | - | 0 | prev_end | 顺序播放 |
| 7 | 24.185s | - | 1.0 | 0 | 完全交叠，所有音频同时开始 |
| 8 | 24.185s | - | 0.5 | prev_end * 0.5 | 50%交叠率 |
| 9 | 50s | 10s | - | prev_end - 10 | 正常链式交叠 |
| 10 | 10s | 15s (>duration) | - | prev_end - 15 | start_time<0，限制为0 |

### 关键边界处理规则

#### 1. overlap_time > 前一个音频的结束时间

当 `overlap_time` 超过前一个音频的结束时间时，`start_time` 会被限制为 0：

```python
if overlap_time and overlap_time > 0:
    start_time = prev_end_time - overlap_time
    if start_time < 0:
        log_and_emit('WARNING', 'audio_engine', f"overlap_time={overlap_time} > prev_end_time={prev_end_time}, clamping start_time to 0")
        start_time = 0
```

**示例场景**：
- audio[0]=10s, overlap_time=15s → start_time[1]=0（完全交叠）
- audio[0]=10s, audio[1]=10s, overlap_time=25s → start_time[2]=0（完全交叠）

#### 2. overlap_rate 边界限制

`overlap_rate` 会被限制在 [0.0, 1.0] 范围内：

```python
result = max(0.0, min(1.0, float(overlap_rate)))
```

#### 3. overlap_rate = 1（完全交叠）

当 `overlap_rate = 1` 时，所有音频同时开始：

```python
start_time = 0  # 所有音频立即开始
```

#### 4. overlap_time = 0 且 overlap_rate = 0（顺序播放）

当两者都为 0 时，执行顺序播放：

```python
start_time = prev_end_time  # 前一个结束后才开始
```

#### 5. 不同长度音频的边界处理

当音频长度不同时：

```python
# audio[0] = 10s, audio[1] = 30s, overlap_time = 5s
# audio[1] start_time = 10 - 5 = 5s
# audio[1] end_time = 5 + 30 = 35s
# audio[2] start_time = 35 - 5 = 30s
```

#### 6. offset 偏移量的边界处理

offset 用于进度条拖动时被限制在有效范围内：

```python
effective_duration = max(0, total_duration - audio_offset)
```

### 边界情况可视化示例

#### 场景：overlap_time > duration（完全交叠）

```
音频时长: 10s, overlap_time = 15s

音频0: 0s -------- 10s
音频1: 0s -------- 10s  (start_time=0，与音频0完全交叠)
音频2: 0s -------- 10s  (start_time=0，与音频0、1完全交叠)
```

#### 场景：正常链式交叠

```
音频时长: 10s, overlap_time = 3s

音频0: 0s -------- 10s
音频1: 7s -------- 17s  (3s交叠: 7s~10s)
音频2: 14s -------- 24s (3s交叠: 14s~17s)
音频3: 21s -------- 31s (3s交叠: 21s~24s)
```

## 9. 常见问题

### Q1: overlap_time 和 overlap_rate 同时设置时，哪个生效？

A: overlap_time 优先级更高。当 overlap_time > 0 时，会忽略 overlap_rate。

### Q2: 为什么100个音频时，所有后续音频的 delay 都是相同的？

A: 这是因为之前的代码使用了 `cumulative_duration`（错误）而不是 `prev_end_time`（正确）来计算。已修复为链式交叠模式，使用 `prev_end_time` 作为计算基准。

### Q3: 如果 overlap_time 超过前一个音频的时长怎么办？

A: start_time 会被限制为 0，表示当前音频与前一个音频同时开始（完全交叠）。

### Q4: 链式交叠和两两交叠有什么区别？

**链式交叠**：
- 每个音频与前一个音频交叠
- 音频0→音频1交叠→音频1→音频2交叠→...

**两两交叠**：
- 相邻的音频配对交叠
- (音频0, 音频1) 交叠 → (音频2, 音频3) 交叠 → ...

### Q5: 100个音频 + overlap_time=5s，总时长是多少？

假设每个音频 24.185s：
```
total_duration = 24.185 + 99 × (24.185 - 5) = 24.185 + 99 × 19.185 = 1924.4s
```
