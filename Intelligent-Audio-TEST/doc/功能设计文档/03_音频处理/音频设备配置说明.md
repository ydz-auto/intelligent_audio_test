# 音频设备配置与多通道映射说明

本文档旨在说明本系统中 RME 系列声卡（Fireface 802, UCX II）的多通道配置逻辑及 Windows 驱动环境下的最佳实践。

## 1. 核心硬件配置 (RME Settings)

为了确保 6 个以上的通道能够独立工作，必须正确配置 RME 的 WDM 映射数量。

### 1.1 WDM Devices 设置
在 RME Fireface Settings 面板中：
- **设置项**：`WDM Devices` (下拉框)
- **推荐值**：设置为 **`4`** 或更高。
- **原理**：该数字代表从 Analog 1+2 开始，连续映射多少对立体声设备到 Windows。
    - 设置为 `3` 时：只能看到 Analog 1-6。
    - 设置为 `4` 时：可以看到 Analog 1-8。
- **注意**：如果该值设置过低，高位通道（如 Analog 7/8）将没有独立的系统设备，会被 Windows MME 驱动强制降混（Downmix）到 Analog 1/2 输出。

## 2. 软件驱动优先级逻辑

本系统的音频引擎 (`audio_engine.py`) 针对 Windows 环境下的多通道问题进行了深度优化。

### 2.1 API 优先级
由于 Windows 默认的 MME 驱动（设备名通常以“扬声器”开头）对多通道支持极差，系统在匹配设备时遵循以下优先级：
1. **Windows WDM-KS** (内核流)：低延迟，通道映射最准确。
2. **Windows DirectSound**：兼容性好，支持多通道偏移。
3. **Windows WASAPI**：独占模式支持。
4. **MME**：仅作为最后的回退方案（存在降混风险）。

### 2.2 自动避坑逻辑
当系统发现一个设备在 MME 模式下名为“扬声器”但在 DirectSound 模式下有更具体的名称时，会**自动切换到 DirectSound/WDM-KS**，从而避免信号在驱动层被降混。

## 3. 通道映射关系 (Seed Data)

系统通过 `scripts/seed_playback_devices.py` 将物理端口映射为逻辑测试设备。

### 3.1 映射示例 (RME 802)
- **Analog 1/2**: 映射到 `扬声器 (RME Fireface 802)`。
- **Analog 3/4**: 映射到 `Analog (3+4) (RME Fireface 802)`。
- **Analog 5/6**: 映射到 `Analog (5+6) (RME Fireface 802)`。
- **Analog 7/8**: 映射到 `Analog (7+8) (RME Fireface 802)` (需 WDM Devices >= 4)。

## 4. 安全防护机制

为了保护昂贵的测试硬件和实验人员的听力，系统内置了强制限幅：
- **全局增益限制**：`GLOBAL_SAFE_GAIN = 0.3` (在 `audio_engine.py` 中定义)。
- **效果**：即使前端请求 100% 音量，实际输出波形幅值最高也只有 30%。
- **推荐测试增益**：在验证脚本中使用 `gain=0.5`，结合全局限制，实际输出增益为 `0.15` (15%)。

## 5. 维护与更新

当硬件环境发生变化（如插拔声卡、修改 WDM 数量）后，请执行以下命令刷新系统数据库：

```powershell
python scripts/seed_playback_devices.py
```

执行后，可运行验证脚本检查所有通道：

```powershell
python scripts/verify_multichannel_playback.py
```
