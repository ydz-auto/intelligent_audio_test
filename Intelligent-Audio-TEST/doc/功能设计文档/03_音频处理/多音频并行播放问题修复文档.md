# 多音频并行播放问题修复文档

## 问题描述

在测试用例预览功能中，当多个音频配置到同一物理设备的不同声道时，出现以下问题：
1. 只有一个音频能播放，其他音频丢失
2. 不同设备的音频播放间隔过长
3. 每个声道的播放时序不正确

## 问题分析

### 问题1：音频覆盖而非混合

**现象**：当多个音频配置到同一设备时，只有最后一个音频能播放成功。

**原因**：`play_multi` 的 callback 中，将音频数据写入 `out_buffer` 时使用了赋值操作 `=`：

```python
out_buffer[ch_idx:limit*stream_channels:stream_channels] = audio_data[:limit]
```

当多个音频的 `channel` 值相同时（都配置到同一声道），后写入的音频会**覆盖**前面已写入的音频，导致只有最后一个音频能播放。

**解决方案**：将赋值操作 `=` 改为相加操作 `+=`：

```python
out_buffer[ch_idx:limit*stream_channels:stream_channels] += audio_data[:limit]
```

这样多个音频会**混合相加**后输出，而非互相覆盖。

### 问题2：设备间播放延迟过长

**现象**：第一个设备的音频播放完后，等待约4秒才开始播放第二个设备的音频。

**原因**：`play_overlap` 函数中，使用 `min_delay` 来决定每个设备的启动时间：

```python
min_delay = min([d for c, d in audio_list_with_delays])
...
if delay > 0:
    time.sleep(delay)
```

对于 Device 32（play_order=1-7），其最小 delay 是 play_order=1 的值 4.181s，导致第二个设备需要等待 4.181 秒才启动。

**解决方案**：移除设备级别的延迟等待，让所有设备同时开始播放。具体的播放时序由各音频的 `delay` 参数在 `play_multi` 内部通过填充静音来控制。

```python
# 移除以下代码
# if delay > 0:
#     time.sleep(delay)
#     thread.start()
# 改为直接启动
thread.start()
```

### 问题3：单音频 delay 未传递

**现象**：当每个设备只有1个音频时，即使计算出了 delay，音频也不会延迟播放。

**原因**：`play_device_audios` 函数中，当 `len(audio_list) == 1` 时，`delay` 被硬编码为 0：

```python
# 修改前
multi_configs = [{
    ...
    'delay': 0  # 硬编码为 0
}]
```

**解决方案**：从 `audio_list_with_delays` 中获取实际的 delay 值：

```python
# 修改后
config = audio_list[0]
_, delay = audio_list_with_delays[0]
multi_configs = [{
    ...
    'delay': delay  # 使用实际的 delay 值
}]
```

### 问题4：每个声道的 delay 应该独立

**现象**：同一设备的多个声道按顺序播放，而非并行播放。

**原因**：`calculate_audio_delays` 函数按物理设备分组，导致同一设备的所有声道共享同一个 delay。

**解决方案**：移除设备分组逻辑，让每个声道（playback_device）都有独立的 delay，按 `play_order` 依次累加：

```python
# 按 play_order 排序，每个音频独立计算 delay
for i, config in enumerate(sorted_dry):
    if i == 0:
        start_time = 0
    else:
        if overlap_rate is not None and overlap_rate > 0:
            start_time = cumulative_duration * (1 - overlap_rate)
        else:
            start_time = cumulative_duration
    audio_delays_with_config.append((config, start_time))
    cumulative_duration += effective_duration
```

## 技术背景

### 设备与声道的区别

- **物理设备**（device_index）：PyAudio 的设备索引，代表一个物理音频设备
- **声道**（channel）：设备上的音频通道，如左声道、右声道

`playback_device_id`（数据库ID）代表的是具体哪个声道（PlaybackDevice），而非物理设备。

同一物理设备（如 RME Fireface 802）的不同声道（如 Analog 7+8 Ch1、Analog 7+8 Ch2）共享同一个 PyAudio device_index，但有不同的 channel_index。

### PyAudio 播放限制

- 每个物理设备同时只能使用一个 PyAudio stream
- 如果需要在同一设备上播放多个音频，需要在 stream 内部进行混合

### 统一公式

为了支持重叠和非重叠播放，使用统一公式计算每个音频的开始时间：

```
start_time = cumulative_duration * (1 - overlap_rate)
```

- `overlap_rate = 0`：非重叠播放，`start_time = cumulative_duration`（累加）
- `overlap_rate > 0`：重叠播放，`start_time = cumulative_duration * (1 - overlap_rate)`

## 播放时序控制

修复后的播放时序控制机制：

1. **设备级别**：所有设备同时开始播放（移除 `time.sleep` 延迟）

2. **声道级别**：每个声道（playback_device）有独立的 delay，通过 `play_multi` 内部的填充静音来控制：
   - 每个音频有自己的 `delay` 值
   - 当 `delay > 0` 时，输出静音数据（填充 0）
   - 当 `delay <= 0` 时，输出实际音频数据
   - 多个音频同时有数据时，通过 `+=` 混合相加

3. **计算逻辑**：
   - 按 `play_order` 依次累加每个音频的 delay
   - `delay[i] = cumulative_duration of previous audios`
   - 示例：
     - play_order=0: delay=0s
     - play_order=1: delay=4.181s
     - play_order=2: delay=8.362s
