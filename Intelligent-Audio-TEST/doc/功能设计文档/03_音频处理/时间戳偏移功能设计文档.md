# 时间戳偏移功能设计文档

## 概述

本文档详细说明 E2E 测试中时间戳偏移功能的完整设计，包括理论时间戳生成、实际偏移计算、以及参考参数调整的完整流程。

---

## 1. 核心概念

### 1.1 理论时间偏移（Theory Offset）

基于 `overlap_rate`（重叠率）计算的理论播放开始时间：

```
start_time = cumulative_duration * (1 - overlap_rate)
```

- `overlap_rate = 0`：非重叠播放，`start_time = cumulative_duration`（累加）
- `overlap_rate > 0`：重叠播放，`start_time = cumulative_duration * (1 - overlap_rate)`

### 1.2 实际时间偏移（Actual Offset）

实际录音时间与理论时间的差异：

```
actual_offset = actual_play_time - record_start_time - theory_offset
```

- `actual_play_time`：音频实际开始播放的时间戳
- `record_start_time`：录音开始的时间戳
- `theory_offset`：理论时间偏移

### 1.3 有效偏移量（Effective Offset）

基于设备返回结果计算的实际对齐偏移量：

```
effective_offset = device_first_ts - ref_first_ts
```

或使用最大重叠对齐算法计算最优偏移量。

### 1.4 调整后的参考参数（Adjusted Reference Params）

将偏移量应用到参考参数的时间戳上，使参考时间戳与实际录音对齐：

```
adjusted_start = original_start + offset
adjusted_end = original_end + offset
```

## 2. 时间戳对齐策略

### 2.1 对齐策略概述

系统采用**混合对齐策略**，根据数据情况自动选择最优方法：

| 策略 | 适用场景 | 准确性 | 说明 |
|------|----------|--------|------|
| **最大重叠对齐** | 片段数 ≥ 2 | ⭐⭐⭐⭐⭐ | 处理丢句/多句场景 |
| **首个时间戳对齐** | 片段数 < 2 | ⭐⭐⭐ | 传统方法，假设首句对齐 |
| **回退对齐** | 无法提取时间戳 | ⭐⭐ | 使用系统测量的播放偏移 |

### 2.2 最大重叠对齐算法

**核心思想**：不依赖"首个时间戳"，而是遍历所有可能的偏移量，选择使总重叠时间最大的那个。

#### 算法流程

```
输入: device_segments[], ref_segments[]
输出: best_offset, max_overlap

步骤1: 生成候选偏移量
  ├── 文本相似度匹配（如果有文本）
  │   └── 找出文本相似的片段对，计算偏移量
  ├── 时长优先采样
  │   └── 选择时长较长的片段生成候选偏移
  └── 时间分布均匀采样
      └── 均匀覆盖时间轴的片段生成候选偏移

步骤2: 计算每个候选的总重叠时间
  for offset in candidate_offsets:
      adjusted_ref = shift_all(ref_segments, offset)
      overlap = compute_total_overlap(device_segments, adjusted_ref)
      if overlap > max_overlap:
          max_overlap = overlap
          best_offset = offset

步骤3: 置信度检查
  if max_overlap >= MIN_OVERLAP_THRESHOLD (0.5s):
      return best_offset
  else:
      回退到首个时间戳对齐
```

#### 采样策略

| 策略 | 采样数量 | 说明 |
|------|----------|------|
| 文本相似度匹配 | 最多100对 | 按相似度排序，处理有文本的场景 |
| 时长优先采样 | 15个 | 优先选择时长较长的片段（更稳定） |
| 时间分布采样 | 15个 | 均匀覆盖时间轴，处理片段分布不均 |

#### 重叠时间计算

```python
def compute_total_overlap(segs_a, segs_b):
    total = 0.0
    for a in segs_a:
        for b in segs_b:
            overlap_start = max(a['start'], b['start'])
            overlap_end = min(a['end'], b['end'])
            if overlap_end > overlap_start:
                total += overlap_end - overlap_start
    return total
```

### 2.3 场景验证

#### 场景1：第一句丢句

```
参考参数:  [seg1: 0.0-1.5s] [seg2: 1.5-3.0s] [seg3: 3.0-4.5s]
设备返回:  [seg2: 1.5-3.0s] [seg3: 3.0-4.5s]

候选偏移量:
  device[0] vs ref[0]: 1.5 - 0.0 = +1.5s → overlap = 1.5s
  device[0] vs ref[1]: 1.5 - 1.5 = 0.0s  → overlap = 3.0s ✓ 最大
  device[0] vs ref[2]: 1.5 - 3.0 = -1.5s → overlap = 0s

最优偏移: 0.0s ✅ 正确！
```

#### 场景2：片段合并/拆分

```
设备返回:  [0.0-5.0s] "你好世界今天天气很好"     ← 1个大片段
参考参数:  [0.0-1.5s] [1.5-3.0s] [3.0-5.0s]    ← 3个小片段

时长优先采样确保大片段被选中，重叠时间计算仍能找到正确偏移。
```

def _calculate_offset_by_max_overlap(self, device_segments, ref_segments, max_offset=30.0):
    """基于最大重叠时间计算最优偏移量"""
    candidate_offsets = self._generate_candidate_offsets(device_segments, ref_segments)
    
    for offset in candidate_offsets:
        adjusted_ref = shift_all(ref_segments, offset)
        overlap = self._compute_total_overlap(device_segments, adjusted_ref)
        if overlap > max_overlap:
            max_overlap = overlap
            best_offset = offset
    
    return best_offset, max_overlap

## 5. 对齐信息记录

### 5.1 数据结构

对齐信息会自动保存到 `TestResult.result_data` 的 `alignment_info` 字段中：

```json
{
  "alignment_info": {
    "method": "max_overlap",
    "offset": 1.234,
    "max_overlap": 5.678,
    "device_segment_count": 15,
    "ref_segment_count": 12,
    "device_first_ts": 0.5,
    "ref_first_ts": 0.0
  }
}
```

### 5.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `method` | string | 对齐方法，见下表 |
| `offset` | float | 计算出的偏移量（秒） |
| `max_overlap` | float | 最大重叠时间（仅 max_overlap 方法） |
| `device_segment_count` | int | 设备返回的片段数量 |
| `ref_segment_count` | int | 参考参数的片段数量 |
| `device_first_ts` | float | 设备首个时间戳 |
| `ref_first_ts` | float | 参考首个时间戳 |

### 5.3 method 可能的值

| 值 | 说明 |
|---|------|
| `max_overlap` | 使用最大重叠对齐，有偏移调整 |
| `max_overlap_no_adjustment` | 最大重叠对齐，偏移量≈0无需调整 |
| `first_timestamp` | 首个时间戳对齐，有偏移调整 |
| `first_timestamp_no_adjustment` | 首个时间戳对齐，偏移量≈0 |
| `fallback` | 回退使用 playback_time_offsets |
| `none` | 无法计算偏移 |

## 9. 常见问题

### 9.1 偏移量为 0

如果计算出的偏移量接近 0（< 0.001s），说明设备返回的时间戳与参考参数已对齐，不需要调整。

### 9.2 设备返回丢句/多句

最大重叠对齐算法会自动处理：
- **丢句**：通过重叠时间计算找到正确的对应片段
- **多句**：同样通过重叠时间识别正确偏移

### 9.3 片段合并/拆分

时长优先采样和时间分布采样策略确保：
- 合并的大片段会被优先选中
- 拆分的小片段会被均匀采样
- 重叠时间计算不受片段粒度影响

### 9.4 不同 play_order 的偏移量不同

如果不同音频的偏移量不同（如设备响应延迟不同），系统会根据每个片段的 `play_order` 分别应用对应的偏移量。

## 10. 验证方法

1. **查看日志**：检查对齐日志，确认使用的对齐方法和计算的偏移量
2. **查看数据库**：检查 `test_results.result_data` 中的 `alignment_info` 字段
3. **验证评估**：对比调整前后的评估结果，确认时间戳对齐后评估更准确
4. **场景测试**：模拟丢句/多句场景，验证最大重叠对齐的正确性
