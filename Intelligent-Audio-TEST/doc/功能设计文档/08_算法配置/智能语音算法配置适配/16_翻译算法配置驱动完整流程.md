# 翻译算法配置驱动完整流程文档

## 概述

本文档以翻译算法(Translation)为例，详细说明从用例配置到设备驱动/API执行，再到评估结果的完整参数配置、映射和转换流程。

> **架构变更说明**：已删除 `TranslationDirection`、`Language`、`PromptAudioRelation` 数据库表。翻译方向(`translation_direction`)、源语言(`source_language`)、目标语言(`target_language`) 现在都是**普通用例参数**，由算法配置定义，通过用例参数透传到执行器，不再需要执行器单独提取或查表。

## 二、用例配置参数流程

### 2.1 用户配置界面

用户在用例创建/编辑界面选择翻译算法后，需要配置：

1. **基本信息**：用例名称、描述
2. **算法参数**（由算法配置动态生成）：
   - `translation_direction` - 翻译方向（文本输入，如 `zh2en`）
   - `source_language` - 源语言（文本输入，如 `zh`）
   - `target_language` - 目标语言（文本输入，如 `en`）
   - 其他参数（如模型选择等）
3. **音频配置**：
   - 干音频
   - 噪声音频
   - 提示音频（直接配置音频ID）

## 三、参数映射与转换

### 3.1 字段映射器 (field_mapper.py)

`FieldMapper` 类负责从算法配置中动态获取参数字段定义。**不再包含翻译方向的关键字匹配逻辑**，所有参数都是配置驱动的：

```python
class FieldMapper:
    def get_reference_field_codes(self, algorithm_type: str) -> Dict[str, str]:
        """获取参考文本字段代码 — 纯配置驱动，无硬编码"""
        device_params = self._get_device_params(algorithm_type)
        api_params = self._get_api_params(algorithm_type)
        params = device_params + api_params

        field_codes = {
            'reference': [],
            'input_reference': None,
            'output_reference': None,
            'input_field': None,
            'output_field': None,
        }

        for param in params:
            code = param.get('code', '')
            param_type = param.get('param_type', '')
            ui_group = param.get('ui_group', '')

            if param_type == 'reference':
                field_codes['reference'].append(code)
                if ui_group == 'input':
                    field_codes['input_reference'] = code
                elif ui_group == 'output':
                    field_codes['output_reference'] = code

            if 'input' in code.lower() and not field_codes['input_field']:
                field_codes['input_field'] = code
            if 'output' in code.lower() or 'result' in code.lower():
                if not field_codes['output_field']:
                    field_codes['output_field'] = code

        # 从 param_mappings 配置中补充 input/output 字段
        mappings = self._get_param_mappings(algorithm_type)
        for comp_type in ['device', 'api', 'evaluation']:
            ...

        return field_codes
```

### 3.2 参数透传机制

翻译方向等参数**不再由执行器单独提取**，而是通过用例参数透传：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        用例配置 (test_cases.config)                     │
│  rounds[0].algorithmParams = {                                          │
│      "translation_direction": "zh2en",                                  │
│      "source_language": "zh",                                           │
│      "target_language": "en"                                            │
│  }                                                                      │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                    前端 CaseForm.syncStructuredFields()                 │
│  将 algorithmParams 中的值同步到 case_config 顶层：                     │
│  case_config.translation_direction = "zh2en"                            │
│  case_config.source_language = "zh"                                     │
│  case_config.target_language = "en"                                     │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│              后端执行器（透传，不单独提取）                              │
│  api_executor: case_algorithm_params → build_create_task_data()         │
│  e2e_executor: case_config → driver.initialize(**case_config)           │
│  reference_params_generator: 直接返回参考值，不做方向匹配               │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.3 关键设计原则

1. **执行器不提取翻译方向**：`api_executor`、`e2e_executor` 不再调用 `field_mapper.get_reference_field_codes()` 来提取 `translation_direction`
2. **参数全透传**：用例的 `algorithmParams` 通过 `case_algorithm_params` / `round_algo_params` 透传到 API 请求和设备驱动
3. **参考参数直接返回**：`reference_params_generator.get_reference_value()` 不再按方向过滤，直接返回第一个可用项
4. **提示音频直接配置**：`prompt_config` 直接存储音频 ID，不再按方向匹配

### 5.2 多轮会话参数透传

多轮会话中，每轮的 `algorithmParams` 直接透传到请求上下文：

```python
def _build_round_context(self, session, round_number, round_config, ...):
    round_algo_params = round_config.get('algorithmParams', [])
    
    context = {
        'session_id': session.session_id,
        'round_number': round_number,
        ...
    }
    
    # 透传所有用例参数到请求上下文
    for param in round_algo_params:
        fc = param.get('field_code', '')
        fv = param.get('field_value', '')
        if fc and fc not in context:
            context[fc] = fv
    
    return context
```

```python
def get_reference_value(param, test_type, ref_type=None, ...):
    value = param.get('value')
    
    if isinstance(value, list):
        if not value:
            return ''
        # 直接返回第一个可用项
        first_item = value[0]
        if isinstance(first_item, dict):
            return first_item.get('text', '')
        return str(first_item)
    
    if isinstance(value, dict):
        return {
            'text': value.get('text', ''),
            'json': value.get('json', value.get('segments', []))
        }
    ...
```

## 八、扩展其他算法

要支持新算法（如ASR、TTS），只需：

### 8.1 数据库配置

1. 在 `algorithm_definitions` 添加算法记录
2. 在 `algorithm_params` 添加参数定义（如 `language`、`model` 等）
3. 在 `param_mappings` 添加映射规则

### 8.2 示例：ASR算法配置

```python
# algorithm_params 配置
{
    'param_code': 'language',
    'param_name': '识别语言',
    'param_type': 'text',
    'help_text': '语言代码（如 zh, en, ja）'
}

# param_mappings 配置
{
    'component_type': 'device',
    'direction': 'input',
    'source_param': 'language',
    'target_key': 'language'
}
```

### 8.3 自动映射

`FieldMapper` 会自动从配置中读取：
- `api_input_fields` - API输入字段定义
- `api_output_fields` - API输出字段定义
- `device_output_fields` - 设备输出字段定义
- `reference` - 参考参数字段

无需修改代码，只需配置数据库即可支持新算法。

## 九、总结

配置驱动架构的核心优势：

1. **配置化**：所有算法特定参数从数据库配置读取
2. **透传**：用例参数直接透传到执行器，执行器不提取特定字段
3. **泛化**：同一套代码支持多种算法
4. **扩展性**：新增算法只需配置，无需修改代码
5. **无硬编码**：`field_mapper` 不包含翻译方向/语种的关键字匹配

关键类和方法：
- `AlgorithmConfigLoader` - 加载算法配置
- `FieldMapper` - 字段映射与参数获取（纯配置驱动）
- `e2e_executor.py` - E2E测试执行器（参数透传）
- `api_executor.py` - API测试执行器（参数透传）
- `reference_params_generator.py` - 参考参数生成（直接返回值）
- `evaluation_service.py` - 评估服务
