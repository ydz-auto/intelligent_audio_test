# 翻译算法配置驱动完整流程文档

## 概述

本文档以翻译算法(Translation)为例，详细说明从用例配置到设备驱动/API执行，再到评估结果的完整参数配置、映射和转换流程。

> **架构变更说明**：已删除 `TranslationDirection`、`Language`、`PromptAudioRelation` 数据库表。翻译方向(`translation_direction`)、源语言(`source_language`)、目标语言(`target_language`) 现在都是**普通用例参数**，由算法配置定义，通过用例参数透传到执行器，不再需要执行器单独提取或查表。

## 二、用例配置参数流程

### 2.1 用户配置界面

用户在用例创建/编辑界面选择翻译算法后，需要配置：

1. **基本信息**：用例名称、描述
2. **算法参数**（由算法配置动态生成）：
   - `translation_direction` - 翻译方向（文本输入，如 `zh2en`）
   - `source_language` - 源语言（文本输入，如 `zh`）
   - `target_language` - 目标语言（文本输入，如 `en`）
   - 其他参数（如模型选择等）
3. **音频配置**：
   - 干音频
   - 噪声音频
   - 提示音频（直接配置音频ID）

### 2.2 配置存储

用例配置拆分为三列存储（`test_cases` 表），分工明确——`config` 只存结构性配置，算法参数与参考参数各占独立列：

**① `config` 列 — 结构性配置（JSON，不含算法参数和参考参数）**：

```json
{
  "rounds": [
    {
      "round_number": 1,
      "audios": [
        {"audio_id": 16, "test_type": "api", "spl": null, "playback_device_id": null, "play_order": 0},
        {"audio_id": 16, "test_type": "e2e", "spl": 65, "playback_device_id": 13, "play_order": 1}
      ],
      "background_noise": {"audio_id": 1, "spl": 15, "device_ids": []},
      "interferers": [],
      "evaluation": {"dimensions": [{"id": 9, "name": "BLEU", "threshold": 80, "weight": 50}]}
    }
  ],
  "background_noise": {"audio_id": 1, "spl": 15, "device_ids": []},
  "dimensions": {
    "api": [{"id": 9, "name": "BLEU", "threshold": 80, "weight": 50}],
    "e2e": [{"id": 9, "name": "BLEU", "threshold": 80, "weight": 50}]
  },
  "tags": ["福州"]
}
```

**② `algorithm_params` 列 — 算法参数（JSON，按轮分组）**：

```json
[
  {
    "round_number": 1,
    "params": [
      {"field_code": "translation_direction", "field_value": "zh2en"},
      {"field_code": "source_language", "field_value": "zh"},
      {"field_code": "target_language", "field_value": "en"}
    ]
  }
]
```

**③ `reference_params` 列 — 参考参数路径（JSON，按轮分组，内容存文件）**：

```json
[
  {"round_number": 1, "reference_params_path": "static/ref_params/<case_id>/round_1.json"}
]
```

#### 兼容性说明

- 轮次键名兼容 `round_number` / `roundNumber`；算法参数项兼容 `field_code`/`fieldCode`、`field_value`/`fieldValue`（由 `case_parameter_extractor._normalize_algorithm_params_to_list` 统一转换）；
- 背景噪音支持**轮级与用例级双层配置**：播放链中用例级全局噪声优先（存在且有效时轮级噪声不播放），评估链中轮级缺省时注入用例级副本（`_normalize_round_eval_fields`）；
- `background_noise` 实际字段：`audio_id` / `spl` / `audio`（文件名）/ `device_ids`（设备ID列表）/ `playback_device_names`（设备名列表）等；
- 轮内结构化音频字段（`audios` / `background_noise` / `interferers`）中的 `audio_id` 在运行时自动补全 `audio_path`。

#### 翻译算法参数说明

算法参数以 `field_code`/`field_value` 键值对按轮存储于 `algorithm_params` 列：

| 字段 (field_code) | 值类型 | 说明 |
|------|------|------|
| translation_direction | String | 翻译方向字符串，如 `zh2en`、`en2zh` |
| source_language | String | 源语言代码，如 `zh`、`en` |
| target_language | String | 目标语言代码，如 `en`、`zh` |

参考参数不再嵌于 config：由参考参数生成器按算法配置（`algorithm_reference_params`）逐轮生成文件（`static/ref_params/<case_id>/round_<N>.json`），`reference_params` 列仅存路径。

#### 非特有字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| background_noise | Object | 背景噪音配置（轮级与用例级双层，播放链用例级优先） |
| background_noise.audio_id | Integer | 噪音音频ID |
| background_noise.spl | Integer | 噪音音量(dB) |
| background_noise.audio / audio_name | String | 噪音音频文件名（运行时按 audio_id 补全 audio_path） |
| background_noise.device_ids | Array | 噪音播放设备ID列表（兼容 playback_device_names 设备名列表） |
| audios | Array | 轮级结构化音频配置列表（`rounds[].audios`） |
| audios[].audio_id | Integer | 音频ID（运行时自动补全 audio_path） |
| audios[].test_type | String | 测试类型：`api`、`e2e` |
| audios[].spl | Integer | 音量(dB) |
| audios[].playback_device_id | Integer | 播放设备ID |
| audios[].play_order | Integer | 播放顺序 |
| interferers | Array | 干扰音配置（评估链由 algorithm_params 提升为轮级） |
| dimensions | Object | 评估维度配置：顶层用于整体评估，`rounds[n].evaluation.dimensions` 用于单轮评估 |
| dimensions.api | Array | API测试评估维度 |
| dimensions.e2e | Array | E2E测试评估维度 |
| dimensions[].id | Integer | 维度ID |
| dimensions[].name | String | 维度名称 |
| dimensions[].threshold | Integer | 阈值 |
| dimensions[].weight | Integer | 权重 |

## 三、参数映射与转换

### 3.1 字段映射器 (field_mapper.py)

`FieldMapper` 类负责从算法配置中动态获取参数字段定义。**不再包含翻译方向的关键字匹配逻辑**，所有参数都是配置驱动的：

```python
class FieldMapper:
    def get_reference_field_codes(self, algorithm_type: str) -> Dict[str, str]:
        """获取参考文本字段代码 — 纯配置驱动，无硬编码"""
        device_params = self._get_device_params(algorithm_type)
        api_params = self._get_api_params(algorithm_type)
        params = device_params + api_params

        field_codes = {
            'reference': [],
            'input_reference': None,
            'output_reference': None,
            'input_field': None,
            'output_field': None,
        }

        for param in params:
            code = param.get('code', '')
            param_type = param.get('param_type', '')
            ui_group = param.get('ui_group', '')

            if param_type == 'reference':
                field_codes['reference'].append(code)
                if ui_group == 'input':
                    field_codes['input_reference'] = code
                elif ui_group == 'output':
                    field_codes['output_reference'] = code

            if 'input' in code.lower() and not field_codes['input_field']:
                field_codes['input_field'] = code
            if 'output' in code.lower() or 'result' in code.lower():
                if not field_codes['output_field']:
                    field_codes['output_field'] = code

        # 从 param_mappings 配置中补充 input/output 字段
        # （兼容历史键名：source_direction 优先于 direction，target_key 优先读取）
        mappings = self._get_param_mappings(algorithm_type)
        for comp_type in ['device', 'api', 'evaluation']:
            comp_mappings = mappings.get(comp_type, [])
            for mapping in comp_mappings:
                direction = mapping.get('source_direction', mapping.get('direction', 'output'))
                target_key = mapping.get('target_key', mapping.get('source_param'))

                if direction == 'output' and not field_codes.get('output_field'):
                    field_codes['output_field'] = target_key
                elif direction == 'input' and not field_codes.get('input_field'):
                    field_codes['input_field'] = target_key

        return field_codes
```

### 3.2 参数透传机制

翻译方向等参数**不再由执行器单独提取**，而是通过用例算法参数独立列按轮透传：

```
┌─────────────────────────────────────────────────────────────────────────┐
│           用例算法参数 (test_cases.algorithm_params 独立列)              │
│  [{ "round_number": 1, "params": [                                      │
│      { "field_code": "translation_direction", "field_value": "zh2en" }, │
│      { "field_code": "source_language",       "field_value": "zh" },    │
│      { "field_code": "target_language",       "field_value": "en" }     │
│  ]}]                                                                    │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│              后端执行器（透传，不单独提取）                              │
│  APISessionExecutor._build_round_context():                             │
│      field_code/field_value 扁平化合并进轮请求上下文                     │
│  E2EExecutor._execute_single_round():                                   │
│      _normalize_algorithm_params() 扁平化为 dict                        │
│      → driver.initialize(device_sn, ..., **round_algo_params)           │
│  reference_params_generator: 直接返回参考值，不做方向匹配               │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.3 关键设计原则

1. **执行器不提取翻译方向**：`APIExecutor`（含 `APISessionExecutor`）、`E2EExecutor` 不再调用 `field_mapper.get_reference_field_codes()` 来提取 `translation_direction`
2. **参数全透传**：用例的算法参数以独立列 `algorithm_params` 按轮存储（`field_code`/`field_value`），经 `round_algo_params` 扁平化后透传到 API 请求和设备驱动
3. **参考参数直接返回**：`reference_params_generator.get_reference_value()` 不再按方向过滤，直接返回第一个可用项
4. **提示音频直接配置**：`prompt_config` 直接存储音频 ID，不再按方向匹配

## 四、设备驱动输入输出

### 4.1 设备驱动接口

设备驱动后端位于 `backend/utils/device_driver/` 目录（`base_driver.py` 基类、`driver_factory.py` 工厂、`registry.py` 驱动注册表），基类接口使用 **kwargs 接收算法特定参数：

```python
# backend/utils/device_driver/base_driver.py
class BaseDriver:
    def initialize(self, device_sn, task_id=None, test_case_id=None, **kwargs) -> bool:
        """初始化设备"""
        ...

    def get_results(self, device_sn, task_id=None, test_case_id=None, **kwargs) -> dict:
        """获取设备输出结果"""
        ...

    def get_final_results(self, device_sn, task_id=None, test_case_id=None, **kwargs):
        """获取最终汇总结果"""
        ...
```

具体驱动（如 `harmony_translation_driver.py`、`android_driver.py` 等）按需实现上述接口，并通过 `registry.py` 注册。

### 4.4 设备参数映射配置

设备输入/输出字段由 `algorithm_device_params` 表定义（`direction=input/output`，如 `asr`、`translation` 为设备输出字段）；跨源取值的映射规则由 `param_mappings` 表配置（`source` 指明参数来源）：

| algorithm_type | source | source_direction | source_param | target_param | 说明 |
|----------------|--------|------------------|--------------|--------------|------|
| translation | case | input | translation_direction | translation_direction | 翻译方向（来自用例算法参数） |
| translation | case | input | source_language | source_language | 源语言（来自用例算法参数） |
| translation | case | input | target_language | target_language | 目标语言（来自用例算法参数） |
| translation | device | output | asr | asr | 设备 ASR 识别结果 |
| translation | device | output | translation | translation | 设备翻译结果 |

> 评估维度级映射在上述基础上通过 `dimension_id` 列关联维度（供 `FieldMapper.get_dimension_mapped_device_output_fields()` 使用）。

## 五、API测试输入输出

### 5.1 API测试流程

API测试通过 `APITaskRunner`（`backend/services/execution/api_task_runner.py`）执行，请求体由 `FieldMapper.build_create_task_data()` 配置驱动构建，再经 `APIDriver.execute()` 发送：

```python
# backend/services/execution/api_task_runner.py
```

### 5.2 多轮会话参数透传

多轮会话中，每轮的算法参数（`algorithm_params` 独立列按轮分组）直接透传到请求上下文（`APISessionExecutor._build_round_context`）：

```python
def _build_round_context(self, session, round_number, round_config, ...):
    round_algo_params = round_config.get('algorithm_params', [])

    context = {
        'session_id': session.session_id,
        'round_number': round_number,
        ...
    }

    # input_text 特殊处理：取该轮算法参数中的 input_text 作为本轮输入
    for param in round_algo_params:
        fc = param.get('field_code', '')
        fv = param.get('field_value', '')
        if fc == 'input_text':
            input_text = fv

    # 其余参数扁平化合并进请求上下文（不覆盖已有键）
    for param in round_algo_params:
        fc = param.get('field_code', '')
        fv = param.get('field_value', '')
        if fc and fc not in context:
            context[fc] = fv

    return context
```

### 5.3 API映射配置

API输入/输出字段由 `algorithm_api_params` 表定义（`direction=input/output`，`param_type` 支持 `text`/`audio_stream`/`audio_file` 等）；跨源取值的映射规则由 `param_mappings` 表配置：

| algorithm_type | source | source_direction | source_param | target_param | 说明 |
|----------------|--------|------------------|--------------|--------------|------|
| translation | case | input | translation_direction | translation_direction | 翻译方向（来自用例算法参数） |
| translation | api | output | asr_text | asr_text | 源文本（API输出） |
| translation | api | output | translated_text | translated_text | 翻译文本（API输出） |

## 六、评估输入输出

### 6.1 评估服务接口

评估服务 `evaluation_service.py` 使用统一入口 `evaluate_case`（多轮统一构建 rounds 列表，单轮也走此路径）：

```python
def evaluate_case(self, task_id, result_id, test_case_id, algorithm_result, **kwargs):
    """
    评估入口

    Args:
        task_id: 任务ID
        result_id: 测试结果ID（test_results）
        test_case_id: 用例ID
        algorithm_result: 算法输出结果
        **kwargs: 额外参数
            - algorithm_type: 算法类型（缺省取用例的 algorithm_type）
            - test_type: 测试类型 'api' / 'e2e'（默认 'api'）
            - round_number: 轮次编号（None=整体评估；指定轮时只取对应轮，0-indexed）
            - reference_params_col: 参考参数独立列（按轮读取参考文件内容）
    """
```

内部逻辑要点：

- 从 `TestCase.algorithm_params` 独立列读取按轮算法参数，经 `_build_rounds_list` 统一构建 rounds 列表；
- 仅当评估映射用到 `source='case_config'` 时才组装用例配置（剥离 dimensions/evaluation、补全 audio_path）；
- 维度配置：单轮评估取 `rounds[n].evaluation.dimensions`，整体评估合并所有轮次 dimensions + 顶层 `config.dimensions`。

### 6.2 评估输入

算法输出结果（`algorithm_result`）以输出字段代码（`output_field_code`，由算法配置/映射决定）为键，如：

```python
algorithm_result = {
    'asr': '你好世界',
    'translation': 'Hello world'
}
```

参考文本（`ref_texts`）由 `field_mapper.get_evaluation_input_fields(algorithm_type)` 定义的评估输入字段驱动，从 `reference_params` 独立列按轮读取的参考文件内容中提取；评估输入还可映射轮级结构化字段（`source=case_config`）：`audios`（被播放音频，历史映射名 `played_audios`）、`background_noise`、`interferers` 等。

### 6.3 参考参数生成

`reference_params_generator.get_reference_value()` 直接返回参考值，不再按方向过滤（`algorithm_type`/`case_config` 参数保留用于兼容扩展）：

```python
def get_reference_value(
    param: Dict[str, Any],
    test_type: str,
    ref_type: str = None,
    algorithm_type: str = None,
    case_config: Dict[str, Any] = None
) -> Any:
    value = param.get('value')

    if isinstance(value, list):
        if not value:
            return ''
        # json 类型参数（如 pause）直接返回整个 list
        if ref_type == 'json':
            return value
        # 直接返回第一个可用项
        first_item = value[0]
        if isinstance(first_item, dict):
            return first_item.get('text', '')
        return str(first_item)

    if not ref_type or ref_type in ['text', 'audio']:
        if isinstance(value, dict):
            return {
                'text': value.get('text', ''),
                'json': value.get('json', value.get('segments', []))
            }
        return {'text': str(value) if value else '', 'json': []}

    if ref_type in ['rttm_json', 'stm_json', 'rttm', 'stm']:
        if isinstance(value, dict):
            return {
                'text': value.get('text', ''),
                'segments': value.get('segments', [])
            }
        return {'text': '', 'segments': []}
    ...
```

### 6.4 评估配置映射

评估配置不再使用 `param_mappings.component_type='evaluation'` 旧结构，而是由以下模型分工：

| 模型/机制 | 职责 |
|-----------|------|
| `EvaluationDimensionParam` | 维度参数定义（`param_direction=input/output`），派生 `required_inputs` / `output_fields` |
| `AlgorithmDimensionRelation` | 算法与评估维度的关联 |
| `param_mappings`（`dimension_id` 关联） | 维度级字段映射（如设备输出字段 → 维度输入），供 `FieldMapper.get_dimension_mapped_device_output_fields()` 使用 |
| `Dimension.statistic_method` | 聚合统计方式：`average` / `weighted_wer` / `pass_rate`（对应 `aggregation_strategies.py` 中的 `SimpleAverageStrategy` / `WeightedSumRatioStrategy` / `PassRateStrategy` 注册表） |

## 八、扩展其他算法

要支持新算法（如ASR、TTS），只需：

### 8.1 数据库配置

1. 在 `algorithm_definitions` 添加算法记录
2. 按用途在 `algorithm_device_params` / `algorithm_api_params` / `algorithm_reference_params` 添加参数定义（如 `language`、`model` 等）
3. 在 `case_algorithm_params` 添加用例配置界面的动态表单控件（`scope` 指定 `common`/`api`/`e2e`）
4. （可选）在 `param_mappings` 添加跨源映射规则

### 8.2 示例：ASR算法配置

```python
# algorithm_api_params 配置（API输入字段定义）
{
    'param_code': 'language',
    'param_name': '识别语言',
    'param_type': 'text',
    'direction': 'input',
    'required': True,
    'help_text': '语言代码（如 zh, en, ja）'
}

# case_algorithm_params 配置（用例配置界面控件）
{
    'param_code': 'language',
    'param_name': '识别语言',
    'param_type': 'text',
    'scope': 'api',
    'required': True
}

# param_mappings 配置（可选：跨源映射）
{
    'source': 'case',
    'source_direction': 'input',
    'source_param': 'language',
    'target_param': 'language'
}
```

### 8.3 自动映射

`FieldMapper` 会自动从算法配置中读取（均按 `algorithm_type` 加载）：
- `get_device_input_fields()` / `get_device_output_fields()` - 设备输入/输出字段定义
- `get_api_input_fields()` / `get_api_output_fields()` - API输入/输出字段定义
- `get_evaluation_input_fields()` / `get_evaluation_output_fields()` - 评估输入/输出字段定义
- `get_case_input_fields()` / `get_reference_input_fields()` - 用例输入/参考参数字段定义
- `get_reference_field_codes()` - 参考参数字段代码
- `build_create_task_data()` - API请求体构建（遍历 API input fields + transform）

无需修改代码，只需配置数据库即可支持新算法。

## 九、总结

配置驱动架构的核心优势：

1. **配置化**：所有算法特定参数从数据库配置读取（三张分类参数表 + 用例专属参数表）
2. **透传**：用例参数（`algorithm_params` 独立列按轮分组）直接透传到执行器，执行器不提取特定字段
3. **泛化**：同一套代码支持多种算法
4. **扩展性**：新增算法只需配置，无需修改代码
5. **无硬编码**：`field_mapper` 不包含翻译方向/语种的关键字匹配

关键类和方法：
- `AlgorithmConfigLoader`（`get_config_loader()`）- 加载算法配置
- `FieldMapper` - 字段映射与参数获取（纯配置驱动）
- `APIExecutor` / `APISessionExecutor` / `APITaskRunner` - API测试执行（参数透传，`backend/services/execution/`）
- `E2EExecutor`（`e2e_executor.py`）- E2E测试执行器（参数透传）
- `BaseDriver` / `E2EDeviceManager`（`backend/utils/device_driver/`）- 设备驱动与设备管理
- `reference_params_generator.py` - 参考参数生成（直接返回值）
- `evaluation_service.py` - 评估服务（`evaluate_case`）
