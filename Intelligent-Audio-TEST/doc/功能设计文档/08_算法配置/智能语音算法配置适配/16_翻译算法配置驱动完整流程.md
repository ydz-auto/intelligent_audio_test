# 翻译算法配置驱动完整流程文档

## 概述

本文档以翻译算法(Translation)为例，详细说明从用例配置到设备驱动/API执行，再到评估结果的完整参数配置、映射和转换流程。

## 二、用例配置参数流程

### 2.1 用户配置界面

用户在用例创建/编辑界面选择翻译算法后，需要配置：

1. **基本信息**：用例名称、描述
2. **算法参数**：
   - `translation_direction_id` - 翻译方向（从下拉框选择）
   - 其他参数（如模型选择等）
3. **音频配置**：
   - 干音频
   - 噪声音频
   - 提示音频（与翻译方向关联）

### 2.2 配置存储

配置保存到 `test_cases.config` 字段（JSON格式）：

## 三、参数映射与转换

### 3.1 字段映射器 (field_mapper.py)

`FieldMapper` 类负责从配置中动态获取算法特定参数：

```python
class FieldMapper:
    def _get_algorithm_extra_config(self, algorithm_type: str) -> Dict[str, Any]:
        """
        获取算法的额外配置
        """
        config = {
            'needs_extra_params': False,
            'case_fields': {},          # {参数名: case表字段名}
            'query_fields': {},         # {参数名: 数据库查询字段名}
            'format_strings': {},       # {参数名: 格式化字符串}
            'db_model': None,           # 数据库模型名
            'db_id_field': 'id',        # ID字段名
            'db_lang_fields': {'source': 'source_language', 'target': 'target_language'},
            'default_lang': {'source': 'zh', 'target': 'en'},
            'output_keys': {},         # {用途: 变量名}
        }
```

### 3.2 翻译算法的配置

对于翻译算法，`_get_algorithm_extra_config` 返回：

```python
{
    'needs_extra_params': True,
    'case_fields': {
        'translation_direction_id': 'translation_direction_id'
    },
    'query_fields': {
        'direction_id': 'translation_direction_id'
    },
    'format_strings': {
        'translation_direction': '{source}2{target}'
    },
    'db_model': 'TranslationDirection',
    'db_id_field': 'id',
    'db_lang_fields': {
        'source': 'source_language',
        'target': 'target_language'
    },
    'default_lang': {
        'source': 'zh',
        'target': 'en'
    },
    'output_keys': {
        'direction': 'translation_direction'
    }
}
```

## 五、API测试输入输出

### 5.1 API测试流程

API测试通过 `api_executor.py` 执行，同样使用配置驱动：

```python
def execute_api_case(self, task_id, tc_rel_id, api_case_id, algorithm_type, case_field_values):
    # 1. 从配置获取参数
    extra_config = field_mapper._get_algorithm_extra_config(algorithm_type)
    
    # 2. 构建API请求参数
    request_params = self._build_request_params(
        api_case, algorithm_type, case_field_values
    )
    
    # 3. 执行API调用
    response = self._execute_api_request(api_case.url, request_params)
    
    # 4. 处理响应
    result = self._process_api_response(response, algorithm_type)
```

### 5.2 API参数映射

| 阶段 | 参数来源 | 说明 |
|------|----------|------|
| 输入 | case_field_values | 从用例配置获取 |
| 输入 | algorithm_params | 从用例config.algorithm_params获取 |
| 输出 | api_response | API返回结果 |

## 六、评估输入输出

### 6.1 评估服务接口

评估服务 `evaluation_service.py` 使用统一接口：

```python
def evaluate(self, algorithm_type, algo_results, reference_data, **kwargs):
    """
    评估入口
    
    Args:
        algorithm_type: 算法类型
        algo_results: 算法输出结果
        reference_data: 参考数据
        **kwargs: 额外参数
    """
```

### 6.2 评估输入

```python
algo_results = {
    'asr': '你好世界',
    'translation': 'Hello world',
    'source_language': 'zh',
    'target_language': 'en'
}

reference_data = {
    'input': {
        'text': '你好世界',
        'code': 'asr_reference_text'
    },
    'output': {
        'text': 'Hello world',
        'code': 'translation_reference_text'
    }
}

extra_params = {
    'direction_id': 1,
    'translation_direction': 'zh2en'
}
```

| 结果处理 | `_process_results` | all_results, extra_params | test_results |
| 评估计算 | `evaluation_service.evaluate` | algo_results, reference_data | scores |

## 八、扩展其他算法

要支持新算法（如ASR、TTS），只需：

### 8.1 数据库配置

1. 在 `algorithm_definitions` 添加算法记录
2. 在 `algorithm_params` 添加参数定义
3. 在 `param_mappings` 添加映射规则

### 8.2 示例：ASR算法配置

```python
# algorithm_params 配置
{
    'param_code': 'language',
    'param_name': '识别语言',
    'param_type': 'select',
    'options_source': 'languages'
}

# param_mappings 配置
{
    'component_type': 'device',
    'direction': 'input',
    'source_param': 'language',
    'target_key': 'language'
}
```

### 8.3 自动映射

`FieldMapper` 会自动从配置中读取：
- `case_fields` - 用例字段映射
- `query_fields` - 数据库查询字段
- `format_strings` - 格式化字符串
- `db_model` - 数据库模型

无需修改代码，只需配置数据库即可支持新算法。

## 九、总结

配置驱动架构的核心优势：

1. **配置化**：所有算法特定参数从数据库配置读取
2. **泛化**：同一套代码支持多种算法
3. **扩展性**：新增算法只需配置，无需修改代码
4. **一致性**：E2E测试、API测试、评估使用同一套配置体系

关键类和方法：
- `AlgorithmConfigLoader` - 加载算法配置
- `FieldMapper` - 字段映射与参数获取
- `e2e_executor.py` - E2E测试执行器
- `api_executor.py` - API测试执行器
- `evaluation_service.py` - 评估服务
