# 参考参数功能设计

## 1. 功能概述

### 1.1 功能定位
参考参数是算法配置的重要组成部分，用于存储评估过程中的参考数据，如参考文本、参考音频、标注文件等。这些数据用于与算法输出进行对比评估。

### 1.2 使用场景
- **ASR 语音识别评估**：提供参考文本（reference_text）用于计算 WER/CER 等指标
- **TTS 语音合成评估**：提供参考音频（reference_audio）用于对比 MOS 评分
- **说话人识别**：提供 RTTM/STM 标注文件用于 VAD 和说话人分离评估
- **翻译质量评估**：提供参考译文用于 BLEU 等指标计算
- **VAD 语音活动检测**：提供 STM 标注文件用于对比评估

---

## 2. 数据结构设计

参考参数采用**双层设计**：算法配置层（`algorithm_reference_params` 表，定义"生成什么"）+ 用例数据层（`test_cases.reference_params` 独立列，存放"生成结果文件路径"）。

### 2.1 数据库字段

**算法参考参数定义表 (algorithm_reference_params)** — 定义每个算法的参考参数结构（唯一索引：algorithm_type + code，WHERE deleted=false）：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| algorithm_type | String(50) | 关联算法类型（外键 → algorithm_definitions.type） |
| code | String(100) | 参考参数代码（用户自定义，如 `asr_ref_text`） |
| name | String(100) | 参数显示名称 |
| param_type | String(30) | 参考类型：text / audio / json / rttm / stm |
| annotation_code | String(100) | 关联的音频标注代码（匹配 AudioAnnotation.code，如 asr / translation / diarization） |
| annotation_format | String(20) | 关联的音频标注格式：text / json / rttm / stm |
| field_path | String(255) | 标注数据字段路径（可选），如 `model`、`segments[].emotion` |
| merge_mode | String(20) | 多音频合并方式：join（空格拼接，默认）/ collect（收集数组）/ first（取第一个） |
| help_text | Text | 帮助提示文字 |
| deleted | Boolean | 逻辑删除标志 |

**测试用例表 (test_cases)** — 参考参数独立列（内容存文件，列中仅存路径）：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| reference_params | JSON | 参考参数路径，按轮分组：`[{"round_number": 1, "reference_params_path": "static/ref_params/<case_id>/round_1.json"}]` |

> 旧设计中参考参数内嵌于 `algorithm_definitions.reference_params`（`{params: [{type, code, api, e2e}]}` 结构，值按 api/e2e 手工填写）已废弃：值改由参考参数生成器从音频标注数据（AudioAnnotation）逐轮自动提取。

### 2.2 参考参数结构

**生成结果文件条目**（`static/ref_params/<case_id>/round_<N>.json`，统一 `{code, type, value}` 结构）：

```typescript
interface ReferenceParamItem {
  code: string;              // 参考参数代码（对应 algorithm_reference_params.code）
  type: string;              // 参考类型：text, audio, json, rttm, stm
  value: any;                // 参考值：文本串 / 数组 / {segments, text, json} 结构
  annotation_code?: string;  // 标注代码（可选）
  annotation_format?: string;// 标注格式（可选）
}
```

**用例独立列条目**：

```typescript
interface ReferenceParamsEntry {
  round_number: number;          // 轮次编号（1-indexed）
  reference_params_path: string; // 该轮参考参数文件路径
}
```

### 2.3 参考类型说明

| 类型值 (param_type) | 说明 | 用途 |
|--------|------|------|
| text | 文本 | ASR 参考文本、翻译参考译文、TTS 输入文本 |
| audio | 音频文件 | TTS 参考音频、说话人音频 |
| json | JSON 数据 | 结构化参考数据（如情感序列、停顿列表；取值时整个 list 返回） |
| rttm | RTTM 标注 | 说话人时间标注（value 为 `{segments, text, json}`） |
| stm | STM 标注 | 语音转写标注、VAD 标注（value 为 `{segments, text, json}`） |

## 3. 数据结构示例

### 3.1 算法参考参数配置（algorithm_reference_params）

以 ASR 为例（算法配置弹窗"参考参数"标签页维护，经 `/api/v1/algorithm/reference-params` 保存）：

```json
[
  {
    "algorithm_type": "asr",
    "code": "asr_ref_text",
    "name": "ASR参考文本",
    "param_type": "text",
    "annotation_code": "asr",
    "annotation_format": "json",
    "field_path": null,
    "merge_mode": "join"
  },
  {
    "algorithm_type": "asr",
    "code": "rttm_ref",
    "name": "说话人标注",
    "param_type": "rttm",
    "annotation_code": "diarization",
    "annotation_format": "rttm",
    "field_path": null,
    "merge_mode": "join"
  },
  {
    "algorithm_type": "asr",
    "code": "ref_emotions",
    "name": "情感序列",
    "param_type": "json",
    "annotation_code": "asr",
    "annotation_format": "json",
    "field_path": "segments[].emotion",
    "merge_mode": "collect"
  }
]
```

### 3.2 生成的参考参数文件

用例创建 / 音频关联后，生成器逐轮写入 `static/ref_params/<case_id>/round_1.json`：

```json
[
  {
    "code": "asr_ref_text",
    "type": "text",
    "value": "你好世界 今天天气不错"
  },
  {
    "code": "translation_ref",
    "type": "text",
    "value": [
      {"translation_direction": "zh2en", "source_language": "zh",
       "target_language": "en", "text": "The weather is nice today"}
    ]
  },
  {
    "code": "rttm_ref",
    "type": "rttm",
    "value": {
      "segments": [{"start": 0.0, "end": 3.5, "speaker": "spk0", "text": "你好世界"}],
      "text": "SPEAKER test 1 0.00 3.50 <NA> <NA> spk0 <NA> <NA>",
      "json": "[...]"
    }
  }
]
```

> 双记录架构下，生成过程内部仍计算 api/e2e 两类值，但最终仅保留该用例记录 `test_type` 对应的值写入 `value` 字段；`normalize_reference_params()` 负责旧结构（含 api/e2e 键）到新结构的归一化。

### 3.3 用例独立列存储

```json
[
  {"round_number": 1, "reference_params_path": "static/ref_params/12/round_1.json"},
  {"round_number": 2, "reference_params_path": "static/ref_params/12/round_2.json"}
]
```

### 3.4 字段说明

| 字段 | 说明 |
|------|------|
| `code` | 参考参数代码，对应 `algorithm_reference_params.code` 与 ParamMapping 的 `source_param` |
| `type` | 参考类型：`text` / `audio` / `json` / `rttm` / `stm` |
| `value` | 参考值：文本串、数组（翻译参考 / 字段路径收集）或 `{segments, text, json}` 结构化对象 |
| `annotation_code` / `annotation_format` | 生成来源的标注信息（可选） |
| `round_number` / `reference_params_path` | 独立列条目：轮次（1-indexed）与文件路径 |

## 4. 后端 API 设计

### 4.1 算法参考参数 CRUD

前缀 `/api/v1/algorithm`（`backend/blueprints/algorithm_bp.py`），在算法配置弹窗"参考参数"标签页自动保存：

**获取参考参数列表** `GET /api/v1/algorithm/reference-params?algorithm_type={type}`

**创建参考参数** `POST /api/v1/algorithm/reference-params`
```json
{
  "algorithm_type": "asr",
  "code": "asr_ref_text",
  "name": "ASR参考文本",
  "param_type": "text",
  "annotation_code": "asr",
  "annotation_format": "json",
  "field_path": null,
  "merge_mode": "join"
}
```

**更新参考参数** `PUT /api/v1/algorithm/reference-params/{id}?algorithm_type={type}`

**删除参考参数** `DELETE /api/v1/algorithm/reference-params/{id}?algorithm_type={type}`

### 4.2 用例级 ref-params 单轮读写

前缀 `/api/v1/testcases`（用例蓝图）：

```
GET /api/v1/testcases/<tc_id>/rounds/<round_number>/ref-params
    # 读取该轮参考参数文件内容（config.rounds 中该轮 referenceParamsPath 指向的 JSON）

PUT /api/v1/testcases/<tc_id>/rounds/<round_number>/ref-params
    # 请求体 {"referenceParams": [...]}，经 normalize_reference_params 归一化后
    # 直接写回该轮参考参数文件
```

### 4.3 批量刷新

批量动作"刷新参考参数"（`TestCaseController._batch_refresh_reference`）：

- **≤50 个用例**：同步逐个调用 `refresh_reference_texts(tc)`，等待完成后返回更新数量
- **>50 个用例**：调用 `submit_reference_refresh_task(ids)` 提交后台任务，立即返回 `task_id`

轮询接口：

```
GET /api/v1/testcases/refresh_task/<task_id>
    # 返回任务状态（pending/running/completed/failed）与进度信息
```

## 5. 前端组件设计

### 5.1 AlgorithmConfigModal 参考参数标签页

在算法配置弹窗（`frontend/src/components/algorithm/AlgorithmConfigModal.vue`）的"参考参数"标签页中维护 `algorithm_reference_params` 配置，每行包含：

| 列 | 控件 | 说明 |
|----|------|------|
| 参数代码 | 文本输入框 | 如 `asr_ref_text` |
| 显示名称 | 文本输入框 | 如 `ASR参考文本` |
| 参考类型 | 下拉选择 | text / audio / json / rttm / stm |
| 标注代码 | 下拉选择 | asr / translation / diarization 等（匹配 AudioAnnotation.code） |
| 标注格式 | 下拉选择 | text / json / rttm / stm |
| 字段路径 | 文本输入框 | 如 `model` 或 `segments[].emotion`（留空走默认提取逻辑） |
| 合并方式 | 下拉选择 | 拼接（join）/ 收集数组（collect）/ 取第一个（first） |

配置经 `/api/v1/algorithm/reference-params` 接口自动保存，无需手动提交。

### 5.2 参考值渲染逻辑

参考值内容按 `type` 渲染：
- `text` → 文本展示/编辑
- `json` → JSON 编辑器
- `rttm` / `stm` → 结构化片段（segments）与原始文本（text）双视图
- `audio` → 音频选择器

### 5.3 参数映射中的参考参数来源

在"参数映射"编辑器（`frontend/src/components/algorithm/MappingEditor.vue`）中，`source` 支持 `reference`（五类来源 case / reference / device / api / case_config 之一）：

```
┌────────────────────────────────────────────────────────────────┐
│  评估参数映射                                            [▼]    │
├────────────────────────────────────────────────────────────────┤
│  来源类型(source): [reference ▼]                               │
│  来源参数(source_param): [asr_ref_text ▼]  ← 参考参数代码       │
│  目标参数(target_param): [asr_ref]                              │
│  维度(dimension_id): [1 ▼]                                      │
│  转换(transform_type): [none ▼]                                 │
└────────────────────────────────────────────────────────────────┘
```

## 7. 数据流

```
算法配置：参考参数标签页（AlgorithmConfigModal.vue）
       ↓
CRUD → POST/PUT /api/v1/algorithm/reference-params
       ↓
algorithm_reference_params 表（定义：生成什么、从哪个标注取、如何合并）
       ↓
用例创建 / 复制 / 更新 / 音频关联轮次（触发刷新，详见生成器文档"调用时机"）
       ↓
ReferenceParamsGenerator.apply_to_config(test_case)
  1. 读取 algorithm_reference_params 配置
  2. 逐轮从 config.rounds[].audios 获取音频ID
  3. 批量预加载 AudioAnnotation 标注数据
  4. 重叠播放时间戳调整（speaker 感知）
  5. 归一化为 {code, type, value}，逐轮写文件
       ↓
static/ref_params/<case_id>/round_<N>.json
       ↓
test_cases.reference_params 独立列：
[{"round_number": N, "reference_params_path": ".../round_N.json"}]
       ↓
测试执行 / 评估 / 报告：按轮加载文件内容
  - 评估：evaluate_case(reference_params_col=...) → _build_rounds_list 按轮取值
  - 报告：get_reference_params_for_report（多轮按 code@round:N 展开）
```

## 8. 参数映射流程

### 8.1 核心组件

参考参数的映射处理涉及以下核心组件：

| 组件 | 文件路径 | 职责 |
|------|----------|------|
| **AlgorithmConfigLoader** | `backend/utils/algorithm/algorithm_config_loader.py` | 单例加载算法配置：`get_reference_params(algorithm_type)` 返回参考参数定义，`get_param_mapping(algorithm_type, 'evaluation')` 返回评估映射 |
| **CaseParameterExtractor** | `backend/utils/algorithm/case_parameter_extractor.py` | `_load_round_ref_file(reference_params_col, round_number)` 按轮加载参考参数文件 |
| **ReferenceParamsGenerator** | `backend/utils/algorithm/reference_params_generator.py` | 模块级函数 `get_reference_value(param, test_type, ref_type, ...)` 按格式取参考值 |
| **EvaluationService** | `backend/services/evaluation/evaluation_service.py` | `_build_rounds_list` 遍历 param_mappings，按 source 类型组装每轮评估参数 |

### 8.2 参数映射配置

参考参数通过 `ParamMapping` 的 `source='reference'` 标识来源（五类来源 case / reference / device / api / case_config 之一）：

```json
{
  "algorithm_type": "asr",
  "source": "reference",
  "source_param": "asr_ref_text",
  "target_param": "asr_ref",
  "dimension_id": 1,
  "transform_type": "none"
}
```

- `source_param`：参考参数代码（对应 `algorithm_reference_params.code` / 文件条目的 `code`）
- `target_param`：评估参数键名（须与评估维度参数 `EvaluationDimensionParam.param_code` 一致）

### 8.3 处理流程

#### 步骤一：按轮加载参考文件（EvaluationService._build_rounds_list）

```python
# evaluation_service.py — algo_result.rounds[].round 为 0-indexed，
# reference_params_col 的 round_number 为 1-indexed
round_ref_data = CaseParameterExtractor._load_round_ref_file(
    reference_params_col, round_number + 1
)
```

#### 步骤二：按映射取值（source == 'reference'）

```python
# evaluation_service.py - _build_rounds_list 内
elif source == 'reference':
    ref_item = round_ref_data.get(source_param)
    if ref_item and isinstance(ref_item, dict):
        ref_type = None
        for ref_def in loader.get_reference_params(algorithm_type):
            if ref_def.get('code') == source_param:
                ref_type = ref_def.get('type')
                break
        value = gen_reference_value(
            ref_item, test_type, ref_type,
            algorithm_type=algorithm_type, case_config={}
        )
```

#### 步骤三：按类型取值（reference_params_generator.get_reference_value）

```python
def get_reference_value(param, test_type, ref_type=None,
                        algorithm_type=None, case_config=None) -> Any:
    # value 为 list：ref_type=='json' 时返回整个 list，否则取第一个可用项
    # ref_type 为 None/text/audio/rttm_text/stm_text：返回 {text, json}
    # ref_type 为 rttm_json/stm_json/rttm/stm：返回 {text, segments}
```

### 8.4 完整数据流

```
test_cases.reference_params 独立列
  [{"round_number": 1, "reference_params_path": "static/ref_params/12/round_1.json"}]
            │
            ▼
┌─────────────────────────────────────────────────────────┐
│ EvaluationService.evaluate_case(reference_params_col=…) │
│ → _build_rounds_list：按轮 _load_round_ref_file 加载     │
└─────────────────────────────────────────────────────────┘
            │
            ▼
┌─────────────────────────────────────────────────────────┐
│ 遍历 param_mappings（source='reference'）                │
│ round_ref_data.get(source_param) → {code, type, value}  │
└─────────────────────────────────────────────────────────┘
            │
            ▼
┌─────────────────────────────────────────────────────────┐
│ gen_reference_value(ref_item, test_type, ref_type)      │
│ 按 ref_type 返回 {text, json} 或 {text, segments}       │
└─────────────────────────────────────────────────────────┘
            │
            ▼
评估参数（每轮一项，以 target_param 为键）
{
    "asr_ref": "你好世界 今天天气不错",  ← 来自参考文件（source=reference）
    "asr_result": "识别结果",            ← 来自算法输出（source=device/api）
    "dimension_ids": [1, 2]
}
```

### 8.5 测试类型区分

双记录架构下 **api/e2e 为独立用例记录**（`test_cases.test_type`，独立列与文件均属单条用例记录）：参考参数在生成时即按该用例记录的 `test_type` 保留对应值写入 `value` 字段；评估链取值无需再按 api/e2e 挑选，`get_reference_value` 的 `test_type` 参数仅保留于签名中作兼容。
