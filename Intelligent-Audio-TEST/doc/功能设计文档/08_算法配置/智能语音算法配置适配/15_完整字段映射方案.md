## 1. 整体架构

### 1.1 数据流概述

### 1.3 核心概念

| 概念 | 说明 |
|------|------|
| **映射分组（component_type）** | device（设备）、api（算法服务）、case（用例参数）、case_config（用例配置轮次字段）、reference（参考参数）、evaluation（评估维度）。运行时由 `AlgorithmConfigLoader.get_param_mapping(algorithm_type, component_type)` 按分组查询 |
| **字段方向（source_direction）** | input（输入）、output（输出） |
| **字段类型（param_type / field_type）** | text（文本）、audio（音频）、number（数值）、boolean（布尔）、json、rttm、stm |
| **参数映射（param_mappings）** | `source_param → target_param` 的转换关系，携带 `source`、`source_direction`、`dimension_id`、`transform_type` |

### 1.4 核心组件

字段映射涉及以下四个核心组件（均位于 `backend/utils/algorithm/` 子目录），协同完成数据流转：

| 组件 | 文件路径 | 职责 |
|------|----------|------|
| **AlgorithmConfigLoader** | `backend/utils/algorithm/algorithm_config_loader.py` | 单例。从数据库加载算法定义、设备/API/用例/参考参数、参数映射并缓存，提供 `get_param_mapping(algorithm_type, component_type)` 等配置查询，支持 `reload_if_changed()` 热更新 |
| **CaseParameterExtractor** | `backend/utils/algorithm/case_parameter_extractor.py` | 从用例配置（含 `algorithm_params` / `reference_params` 独立列按轮分组结构）提取并构建设备参数、API参数、评估参数（`get_evaluation_params` / `get_round_evaluation_params`），提供表单 schema 生成（`get_algorithm_form_schema`） |
| **FieldMapper** | `backend/utils/algorithm/field_mapper.py` | 单例。执行字段映射转换（`convert_device_output`、`build_create_task_data`），维护内置转换函数表（none/json_parse/base64/to_string/to_int/to_float/to_bool/rttm_to_obj/stm_to_obj） |
| **AlgorithmResultFieldMapper** | `backend/utils/algorithm/algorithm_result_field_mapper.py` | 从 `param_mappings` 表动态获取算法输出字段（`get_output_fields(algorithm_type, test_type)`），执行结果字段映射（`map_api_results`）、按轮提取（`extract_round_results`），替代硬编码字段名 |

**组件协作流程（评估参数构建）：**

```
用例配置 (case_config + algorithm_params/reference_params 独立列)
       │
       ▼
CaseParameterExtractor.get_evaluation_params()  ──▶ 提取用例参数，读取独立列按轮取值
       │                                                  │
       ▼                                                  │
AlgorithmConfigLoader.get_param_mapping(type, 'evaluation')  ──▶ 根据 param_mappings.source 识别来源
       │                                                  │
       ▼                                                  │
按 source 取值：case→用例参数 / case_config→config.rounds 轮次字段 /
reference→参考参数文件 / device|api→algorithm_result（含 rounds[].output）/
adjusted_reference→修正后参考（algorithm_result.adjusted_reference_params）
       │
       ▼
评估参数 (evaluation_params, key=target_param)
```

## 2. 用例-算法特殊字段

### 2.1 特殊字段定义

用例在调用算法时，需要传递一些特殊字段用于标识、分组等：

```typescript
interface TestCaseSpecialFields {
  // 用例标识
  case_id: number;           // 用例ID
  case_name: string;         // 用例名称

  // 分组字段（用于聚合计算）
  tag?: string;              // 标签分组
  device_id?: string;        // 设备ID
  task_id?: number;          // 任务ID

  // 算法选择
  algorithm_type: string;    // 算法类型：asr/translation/tts/speaker_recognition/voice_llm

  // 语言方向（翻译）
  source_lang?: string;      // 源语言
  target_lang?: string;      // 目标语言
  translation_direction?: string; // 翻译方向：zh2en/en2zh
}
```

### 2.2 特殊字段配置

特殊字段的**定义**由"用例专属参数表" `case_algorithm_params`（模型 `CaseAlgorithmParam`）驱动，通过算法配置管理页面维护；**取值**保存在 `test_cases.algorithm_params` 独立列（按轮分组，`[{round_number, params: [{field_code, field_value}]}]`）。前端表单通过 `GET /api/v1/algorithm/form-schema/<algo_type>` 动态加载（由 `CaseParameterExtractor.get_algorithm_form_schema()` 生成，返回 camelCase 字段 `fieldCode/fieldName/fieldType/required/defaultValue/component/options/uiOrder/uiGroup`）：

```json
{
  "algorithm_type": "asr",
  "case_param_definition": {
    "param_code": "tag",
    "param_type": "text",
    "required": false,
    "scope": "common"
  },
  "case_value_storage": {
    "round_number": 1,
    "params": [{"field_code": "tag", "field_value": "中文"}]
  }
}
```

## 3. 三步映射详细说明

### 3.1 映射表 (param_mappings) 字段说明

参数映射表用于定义数据在不同组件之间的流转关系：

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `algorithm_type` | String | 算法类型 | translation, asr, tts |
| `source` | String | 来源组件类型 | case, reference, device, api, case_config |
| `source_param` | String | 源参数代码 | source_language, translation |
| `source_direction` | String | 源参数方向 | input, output |
| `dimension_id` | Integer | 目标评估维度ID（可空，空为全局映射） | 1, 2, 3 |
| `target_param` | String | 目标参数代码 | candidate_text, source_lang |
| `transform_type` | String | 转换类型 | none, uppercase, lowercase, json_parse, base64 |

> 唯一约束：`uq_algorithm_source_to_dimension(algorithm_type, source, source_param, dimension_id)`（仅对未删除记录生效）。`transform_type` 在数据库层取值为 none/uppercase/lowercase/json_parse/base64；`FieldMapper` 运行时另注册内置转换 `to_string/to_int/to_float/to_bool/rttm_to_obj/stm_to_obj`（rttm_to_obj/stm_to_obj 将标注文本转为 `{text, json}` 对象）。

### 3.2 source 字段含义

| source 值 | 说明 | 数据来源 |
|-----------|------|----------|
| `case` | 用例参数 | `test_cases.algorithm_params` 独立列（按轮分组）中配置的参数 |
| `case_config` | 用例配置轮次字段 | `case_config.rounds[]` 的结构性字段（如被播放音频 audios、背景噪声 background_noise、干扰人 interferers） |
| `reference` | 参考参数 | `test_cases.reference_params` 独立列按轮指向的参考参数文件（`referenceParamsPath`） |
| `device` | 设备输出 | 设备驱动执行后输出的参数 |
| `api` | API输出 | API 调用后返回的参数 |
| `adjusted_reference` | 修正后参考（仅运行时） | 执行阶段写入 `algorithm_result.adjusted_reference_params` 的修正参考（如按设备拉取的实际音频修正的 RTTM/STM/文本），不落 `param_mappings` 表；评估映射缺失时由 `AlgorithmConfigLoader._get_evaluation_mappings` 对 `rttm_ref/stm_ref/asr_ref` 目标自动补充 |

### 3.3 三步映射详解

#### 步骤一：Case → Device / API（用例参数映射）

将用例中配置的参数映射到调用设备或API时需要的输入参数。

```
用例参数(Case) → 设备输入参数(Device) / API输入参数(API)
```

**示例：翻译算法**

| 用例参数 (Case) | 映射到 | 设备输入 (Device) | 映射到 | API输入 (API) |
|-----------------|--------|-------------------|--------|---------------|
| source_lang=zh | → | input_lang=zh | → | source_lang=zh |
| target_lang=en | → | target_lang=en | → | target_lang=en |

#### 步骤二：Device / API → 评估维度（结果映射）

将设备或API执行后的输出结果映射到评估维度需要的参数。

```
设备输出(Device) / API输出(API) → 评估维度参数(Evaluation)
```

**示例：翻译算法BLEU评估**

| 设备输出 (Device) | 映射到 | API输出 (API) | 映射到 | 评估维度 (Evaluation) |
|-------------------|--------|---------------|--------|---------------------|
| translation=结果1 | | translated=结果1 | → | candidate=结果1 |
| | | | | reference=参考文本 |

#### 步骤三：Reference → 评估维度（参考参数映射）

将用例中存储的参考参数直接映射到评估维度，用于计算得分。

```
参考参数(Reference) → 评估维度参数(Evaluation)
```

**示例：ASR评估**

| 参考参数 (Reference) | 映射到 | 评估维度 (Evaluation) |
|---------------------|--------|---------------------|
| reference_text=标准答案 | → | asr_ref=标准答案 |
| reference_audio=标准音频 | → | ref_audio=标准音频 |

**示例：翻译评估**

| 参考参数 (Reference) | 映射到 | 评估维度 (Evaluation) |
|---------------------|--------|---------------------|
| reference_text=标准译文 | → | translation_ref=标准译文 |

## 4. 设备输入/输出字段映射

### 4.1 设备字段类型

| 字段类型 | 说明 | 示例 |
|----------|------|------|
| `text` | 文本字段 | 文本输入、识别结果 |
| `audio` | 音频字段 | 音频文件路径/URL |
| `number` | 数值字段 | 采样率、音量 |
| `boolean` | 布尔字段 | 是否启用某功能 |

### 4.2 设备输入字段

设备在执行算法前需要的输入参数。参数定义存储于 `algorithm_device_params` 表（模型 `AlgorithmDeviceParam`），`AlgorithmConfigLoader` 序列化结构如下：

```typescript
interface AlgorithmParamDefinition {
  id: number;
  algorithm_type: string;
  code: string;              // 参数代码（param_code）
  name: string;              // 参数名称
  label: string;             // 显示名称
  type: string;              // 参数类型（param_type）：text/audio/number/boolean/json/rttm/stm
  direction: 'input' | 'output';
  required: boolean;
  default_value?: any;
  validation_rules?: string;
  help_text?: string;
  ui_order: number;
  ui_group: string;          // 分组（如 input/output/basic）
  hidden: boolean;
}

// FieldMapper 构建的运行时输入字段（get_device_input_fields）：
// { code, name, type, source: 'case', required, default_value, transform: 'none', param_type, component_type: 'device' }
```

### 4.3 设备输出字段

设备驱动执行算法后的输出（`get_device_output_fields` 返回列表，`source` 固定为 `device_output`）：

```typescript
interface DeviceOutputField {
  code: string;              // 字段键名
  name: string;              // 显示名称
  type: string;              // 输出类型：text/audio 等
  source: 'device_output';
  required: boolean;
  default_value?: any;
  transform: string;         // 转换类型（默认 none）
  param_type: string;
  component_type: 'device';
}
```

### 4.4 翻译算法的设备字段配置（实际示例）

基于设备驱动后端（`backend/utils/device_driver/`，`DriverRegistry` 按 `app_type + version + platform` 三元组注册与解析，`@register_driver` 装饰器声明字段）分析，翻译算法的设备端字段：

**设备输入参数：**
| 参数名 | 类型 | 说明 |
|--------|------|------|
| `device_id` | string | 设备标识 |
| `translation_direction` | string | 翻译方向 (zh2en/en2zh) |

**设备输出结果：**
| 字段名 | 类型 | 说明 |
|--------|------|------|
| `asr` | text | ASR识别结果 |
| `translation` | text | 翻译结果 |

```json
{
  "algorithm_type": "translation",
  "component_type": "device",
  "input_fields": [

    {"key": "translation_direction", "label": "翻译方向", "type": "text", "required": true, "source": "case", "default_value": "zh2en"}
  ],
  "output_fields": [
    {"key": "asr", "label": "ASR识别结果", "type": "text"},
    {"key": "translation", "label": "翻译结果", "type": "text"}

}
```

## 5. API输入/输出字段映射

### 5.1 API字段类型

| 字段类型 | 说明 | 示例 |
|----------|------|------|
| `text` | 文本字段 | 识别文本、翻译文本 |
| `audio` | 音频字段 | 音频数据、音频URL |
| `json` | JSON对象 | 复杂结构数据 |

### 5.2 API输入字段

算法微服务需要的输入参数。参数定义存储于 `algorithm_api_params` 表（模型 `AlgorithmApiParam`），序列化结构同 4.2 的 `AlgorithmParamDefinition`（`direction='input'`）。运行时字段由 `FieldMapper.get_api_input_fields` 构建，输入值合并来源为 `case_config.algorithm_params` 与显式入参（audio_path/vendor/max_process/max_timeout/endpoints 等，见 `build_create_task_data`）：

```typescript
interface APIInputField {
  code: string;              // 字段键名（API参数名）
  name: string;              // 参数名称
  type: string;              // text/audio/number/json 等
  source: string;            // 取值来源：case（用例参数）或 device（设备输出字段代码）
  required: boolean;
  default_value?: any;
  transform: string;         // 转换类型：none/json_parse/base64 等
  param_type: string;
  component_type: 'api';
}
```

### 5.3 API输出字段

算法微服务返回的结果（`get_api_output_fields`，`source` 固定为 `api`）：

```typescript
interface APIOutputField {
  code: string;              // 字段键名
  name: string;              // 显示名称
  type: string;              // text/audio/number/json
  source: 'api';
  required: boolean;
  default_value?: any;
  transform: string;
  param_type: string;
  component_type: 'api';
}
```

### 5.4 翻译算法的API字段配置（实际示例）

基于 API 会话执行器（`APISessionExecutor`，由 ExecutionEngine 按 `device_type=http_api` 路由）与 `FieldMapper.build_create_task_data` 分析，翻译API的实际请求和响应字段：

**API输入参数（创建任务时）：**
| 参数名 | 类型 | 说明 | 来源 |
|--------|------|------|------|
| `audio_path` | audio | 音频文件路径 | device_output |
| `trans_direction` | text | 翻译方向 | case (translation_direction) |
| `vendor` | text | 供应商 | case/api_config |
| `max_process` | number | 最大并发 | api_config |
| `max_timeout` | number | 超时时间 | api_config |

**API输出结果：**
| 字段名 | 类型 | 说明 |
|--------|------|------|
| `result` / `translation_result` | text | 翻译结果 |
| `task_id` | text | 任务ID |

```json
{
  "algorithm_type": "translation",
  "mapping_group": "api",
  "input_fields": [
    {"code": "audio_path", "label": "音频路径", "type": "audio", "required": true, "source": "device"},
```

### 6.1 评估维度输入字段

评估维度计算需要的输入参数（`FieldMapper.get_evaluation_input_fields` 构建，`component_type` 固定为 `evaluation`；字段定义可由 `evaluation_dimension_params` 表补充默认值/说明）：


```typescript
interface EvaluationOutputParam {
```

## 7. 完整映射流程

### 7.1 数据流转示例

```
场景：ASR评估

Step 1: 用例配置
────────────────────────────────────────
{
  "case_id": 1,
  "algorithm_type": "asr",
  "tag": "中文",
  "device": {
    "audio_file": "/path/to/audio.wav",
    "sample_rate": 16000
  }
}

Step 2: 设备执行 → 设备输出
────────────────────────────────────────
{
  "audio_file": "/path/to/audio.wav",
  "asr_result": "识别文本结果",
  "audio_duration": 5.2
}

Step 3: API执行（字段映射）
────────────────────────────────────────
输入映射：
  device_output.audio_file → api_input.audio_url
  device_output.sample_rate → api_input.sample_rate

API调用：
{
  "audio_url": "/path/to/audio.wav",
  "sample_rate": 16000
}

API返回：
{
  "result": "识别文本结果",
  "confidence": 0.95
}

Step 4: 评估计算（字段映射）
────────────────────────────────────────
输入映射：
  api_output.result → evaluation_input.asr_result
  reference.reference_text → evaluation_input.asr_ref
  case.tag → evaluation_input.tag

评估调用：
{
  "task_type": "wer",
  "dimensions": ["wer"],
  "group_by": "tag",
  "asr_result": "识别文本结果",
  "asr_ref": "参考文本",
  "tag": "中文",
  "cases": [
    {"id": 1, "asr_result": "...", "asr_ref": "...", "tag": "中文"}
  ]
}

Step 5: 评估结果
────────────────────────────────────────
{
  "dimensions": ["wer"],
  "results": {
    "中文": {"wer": 10.0, "total_errors": 30, "total_chars": 300}
  },
  "overall": {"wer": 10.0, "total_errors": 30, "total_chars": 300}
}
```

| source | 源字段 | 目标字段 | 转换类型 | 说明 |

| device | audio_file | audio_url | none | 设备输出 → API输入 |

## 8. 数据库模型

### 8.1 参数映射表（param_mappings，实际实现）

```sql
CREATE TABLE param_mappings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    algorithm_type VARCHAR(50) NOT NULL,         -- 关联算法类型
    source VARCHAR(20) NOT NULL DEFAULT 'api',   -- case, reference, device, api, case_config
    source_param VARCHAR(50) NOT NULL,           -- 源参数代码
    source_direction VARCHAR(10) DEFAULT 'output',  -- 源参数方向：input, output
    dimension_id INTEGER,                        -- 目标评估维度ID（可空，空为全局映射）
    target_param VARCHAR(50) NOT NULL,           -- 目标参数代码
    transform_type VARCHAR(20) DEFAULT 'none',   -- none, uppercase, lowercase, json_parse, base64
    deleted BOOLEAN DEFAULT FALSE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (algorithm_type) REFERENCES algorithm_definitions(type) ON DELETE CASCADE,
    FOREIGN KEY (dimension_id) REFERENCES dimensions(id) ON DELETE CASCADE
);
-- 部分唯一索引（仅未删除记录生效）
CREATE UNIQUE INDEX uq_algorithm_source_to_dimension
    ON param_mappings (algorithm_type, source, source_param, dimension_id)
    WHERE deleted = false;
```

> 说明：模型 `ParamMapping` 的 `to_dict()` 会按 `source` 分发到设备参数/API参数/用例参数/参考参数四张参数表回填 `param_name`，供前端展示。

### 8.2 评估维度参数表（evaluation_dimension_params，实际实现）

评估维度的输入/输出字段不再单独建 `dimension_fields` 表，统一由 `evaluation_dimension_params`（模型 `EvaluationDimensionParam`，多算法共用）承载，通过 `param_direction` 区分输入/输出：

```sql
CREATE TABLE evaluation_dimension_params (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    dimension_id INTEGER NOT NULL,               -- 关联评估维度
    param_code VARCHAR(50) NOT NULL,             -- 参数代码（评估API需要的字段名）
    param_name VARCHAR(100),                     -- 参数显示名称
    label VARCHAR(100),                          -- 字段显示名称
    field_type VARCHAR(20) DEFAULT 'text',       -- text, audio, number, boolean, json, timestamp
    param_direction VARCHAR(10) NOT NULL DEFAULT 'input',  -- input(输入参数), output(结果提取字段)
    field_path VARCHAR(200),                     -- 结果提取路径（output 专用，如 wer 或 data.result.wer）
    agg_role VARCHAR(20),                        -- 聚合角色（output 专用）：numerator/denominator/value/pass_le/pass_ge/pass_eq
    output_role VARCHAR(10),                     -- 输出字段角色（output 专用）：main/aux
    visible_in_report BOOLEAN DEFAULT TRUE,
    required BOOLEAN DEFAULT TRUE,
    default_value TEXT,                          -- 默认值（JSON格式）
    pass_threshold FLOAT,                        -- 达标阈值（pass_rate 策略专用）
    help_text TEXT,
    ui_order INTEGER DEFAULT 0,
    deleted BOOLEAN DEFAULT FALSE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (dimension_id) REFERENCES dimensions(id) ON DELETE CASCADE
);
CREATE UNIQUE INDEX uq_dimension_param_code_direction
    ON evaluation_dimension_params (dimension_id, param_code, param_direction)
    WHERE deleted = false;
```

### 10.1 用例加载字段的流程

用例在创建/编辑时，需要根据选择的算法类型动态加载对应字段：

### 10.2 用例加载的字段来源

| scope | 说明 | 示例 |

| **e2e** | 仅设备调用类型用例 | 设备侧播放、采集相关参数 |
