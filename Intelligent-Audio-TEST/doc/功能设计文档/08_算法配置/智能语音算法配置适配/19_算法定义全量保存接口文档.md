# 19. 算法定义全量保存接口文档（INT-589）

> 负责人 2026-10-17 拍板：算法保存走后端聚合事务。本卡交付「RPC 就绪 + 接口文档（含客户端类型签名）」；
> React 接线归接线卡（V9.7.31-UX 工作区），本卡不实现前端接线。

## 一、背景与设计要点

- 旧路径 `CreateAlgorithm` RPC 只消费 7 个基础字段，schema 里的嵌套数组（device/api/case 参数、
  mappings、associated_dimensions、reference_params）写路径被静默丢弃；
- 新 RPC `SaveAlgorithmDefinition` 一次提交完整定义 + 六类子实体，聚合事务原子落库；
- **乐观锁**：以 `algorithm_definitions.updated_at` 为版本做 CAS 条件更新，并发覆盖返回
  `CONFLICT`，前端据此提示「有他人改动，请刷新」；
- **草稿**：新增 `algorithm_definition_drafts` 表（JSON 快照），30s 自动保存写草稿快照、
  恢复时物化、显式发布才写正式六表（草稿与已发布分离，不破坏 type 全表唯一与 config_cache
  只加载 online 的语义）。

## 二、RPC 契约（algorithm_service.AlgorithmDefinitionService）

沿用现有 `data=JSON` 信封。`AlgorithmResponse` 新增 `string code` 字段。

```
message AlgorithmResponse {
  bool success = 1;
  string message = 2;
  string data = 3;   // JSON 序列化的结果
  string code = 4;   // SAVED / OK / CONFLICT / VALIDATION_FAILED（INT-589）
}
```

### 2.1 SaveAlgorithmDefinition —— 全量保存（发布）

```proto
rpc SaveAlgorithmDefinition(SaveAlgorithmDefinitionRequest) returns (AlgorithmResponse);
// SaveAlgorithmDefinitionRequest { string data }
```

`data` JSON：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | int? | 更新必填 | 定义 ID；无 → 新建，有 → 按 id 更新 |
| `algorithm_type`（或 `type`） | string | 新建必填 | 算法类型代码（全表唯一） |
| `name` | string | 是 | 算法显示名称 |
| `group_id` / `description` / `status` / `icon` / `display_order` | 基础字段 | 否 | status: online/offline/draft |
| `expected_updated_at` | string(ISO) | 更新必填 | 乐观锁版本，取自最近一次读取的 `updated_at` |
| `device_params` / `api_params` / `case_params` / `reference_params` | array | 否 | 参数列表（payload 键名 camelCase，与旧保存路径一致） |
| `mappings` | list 或 dict | 否 | 参数映射：平铺 `[{source, source_param, ...}]` 或按 source 分组 `{"device": [...]}` |
| `associated_dimensions` | array | 否 | 关联评估维度 `[{dimension_id, is_default, weight}]` |

响应 `code`：

| code | success | 语义 | 前端分支 |
|------|---------|------|---------|
| `SAVED` | true | 新建成功，`data.id` 为新建 ID | 跳转详情 |
| `OK` | true | 更新成功 | 关闭保存中状态 |
| `CONFLICT` | false | 乐观锁冲突（他人已修改） | 提示「有他人改动，请刷新」 |
| `VALIDATION_FAILED` | false | 校验失败（必填缺失 / 维度不存在 / type 已存在） | 展示 message |

### 2.2 SaveAlgorithmDefinitionDraft —— 30s 自动保存（草稿快照）

```proto
rpc SaveAlgorithmDefinitionDraft(SaveAlgorithmDefinitionDraftRequest) returns (AlgorithmResponse);
// SaveAlgorithmDefinitionDraftRequest { string data }
```

`data` JSON 为完整定义快照（含 `algorithm_type`）。**不落正式六表**，写入
`algorithm_definition_drafts.snapshot`（按 algorithm_type upsert）。成功 `success=true`。

响应 `data`：

```json
{ "saved": true, "algorithm_type": "<type>", "saved_at": "<ISO 时间戳>" }
```

- `saved_at`：服务端最后保存时间，取 `algorithm_definition_drafts.updated_at`（ISO 时间戳），
  供前端 footer「上次保存 HH:mm:ss」展示（前端 `useAlgorithmDraft.ts` 消费 `result.savedAt`）。
  首次保存与再次保存均返回该字段（upsert 语义下即最新一次写快照时间）。
  （裁定日期 2026-10-18，INT-683；草稿为 last-write-wins 快照，不做 CAS/冲突）

### 2.3 GetAlgorithmDefinitionDraft —— 草稿恢复

```proto
rpc GetAlgorithmDefinitionDraft(GetAlgorithmDefinitionDraftRequest) returns (AlgorithmResponse);
// GetAlgorithmDefinitionDraftRequest { string algorithm_type }
```

成功时 `data` 为草稿快照 JSON（与保存时的 payload 同构）；无草稿时 `data={}`。

### 2.4 ClearAlgorithmDefinitionDraft —— 清除草稿快照（INT-1514）

```proto
rpc ClearAlgorithmDefinitionDraft(ClearAlgorithmDefinitionDraftRequest) returns (AlgorithmResponse);
// ClearAlgorithmDefinitionDraftRequest { string algorithm_type }
```

删除 `algorithm_definition_drafts` 中该 `algorithm_type` 的快照行（与
`SaveAlgorithmDefinition` 成功后的 `clear_snapshot` 同口径）。幂等：无草稿时
`success=true`、`data.cleared=false`。

响应 `data`：

```json
{ "algorithm_type": "<type>", "cleared": true }
```

**调用方（网关编排，前端不直接调）**：`PUT /algorithm/definitions/{type}`（编辑发布）、
`POST /algorithm/definitions`（新建）、`DELETE /algorithm/definitions/{type}`（删除）、
`POST /algorithm/bulk-delete`（批量删除，仅清实际删除的类型）成功后，网关
`AlgorithmCommandService` 调一次本 RPC；清除失败只记日志、不改变主操作结果
（与 `handle_save_definition`「清除失败不阻断发布」一致），残留快照下次发布/删除时再清。
（修复日期 2026-10-23，INT-1514；旧聚合更新 RPC 不带草稿清理，见 INT-1483 走查 E4）

## 三、HTTP 网关路由（api_gateway）

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| PUT | `/algorithm/definitions/save` | `algorithm:definition_manage` | 全量保存（发布），body 同 2.1 data |
| PUT | `/algorithm/definitions/draft` | `algorithm:definition_manage` | 草稿自动保存，body 同 2.2 data |
| GET | `/algorithm/definitions/draft/{algo_type}` | `algorithm:read` | 草稿恢复 |

HTTP 语义：`SAVED/OK` → 200；`CONFLICT` → 409（`detail.code="CONFLICT"`）；
`VALIDATION_FAILED` → 422（`detail.code="VALIDATION_FAILED"`）。

> 路由静态段 `save`/`draft` 必须先于参数段 `/definitions/{algo_type}` 注册
> （已按此顺序写入 `api_gateway/routes/algorithm_bp.py`）。

## 四、客户端类型签名（frontend-react 接线卡参考）

```ts
// 全量保存入参（与后端 AlgorithmDefinitionSaveRequest 对齐）
export interface AlgorithmDefinitionSavePayload {
  id?: number | null;               // 更新必填
  algorithm_type?: string;          // 新建必填（或 type）
  name: string;
  group_id?: number | null;
  description?: string | null;
  status?: 'online' | 'offline' | 'draft';
  icon?: string | null;
  display_order?: number;
  expected_updated_at?: string;     // 更新必填（ISO，取自最近读取的 updated_at）
  device_params?: AlgorithmParamItem[];
  api_params?: AlgorithmParamItem[];
  case_params?: CaseAlgorithmParamItem[];
  reference_params?: ReferenceParamItem[];
  mappings?: Record<string, MappingItem[]> | MappingItem[];
  associated_dimensions?: Array<{ dimension_id: number; is_default?: boolean; weight?: number }>;
}

export type AlgorithmSaveCode = 'SAVED' | 'OK' | 'CONFLICT' | 'VALIDATION_FAILED';

export interface AlgorithmSaveResult {
  code: AlgorithmSaveCode;
  id: number;
  algorithm_type: string;
}

export interface DraftSaveResult {           // INT-683：草稿保存响应 data
  saved: boolean;
  algorithm_type: string;
  saved_at?: string;                          // ISO，服务端最后保存时间
}

// HTTP 层（api_gateway 返回 ApiResponse 信封）
// 200: data = AlgorithmSaveResult
// 409: detail.code === 'CONFLICT' → 提示「有他人改动，请刷新」
// 422: detail.code === 'VALIDATION_FAILED' → 展示 message
export async function saveAlgorithmDefinition(payload: AlgorithmDefinitionSavePayload): Promise<AlgorithmSaveResult>;
export async function saveAlgorithmDefinitionDraft(payload: AlgorithmDefinitionSavePayload): Promise<DraftSaveResult>;
export async function getAlgorithmDefinitionDraft(algorithmType: string): Promise<AlgorithmDefinitionSavePayload | null>;
```

## 五、后端落库语义（供验收/联调参考）

1. **事务边界**：`AlgorithmDefinitionRepository.save_full` 同 session upsert 根 + 六类子实体，
   单次 commit/rollback，任一步失败整体回滚（旧 Commit/Flush/Rollback 事务 RPC 不动）；
2. **幂等**：六张子表按自然键 find-or-upsert、排除软删项（device/api:
   `algorithm_type+param_code+direction`；case: `algorithm_type+param_code`；
   reference: `algorithm_type+code`；mapping: `algorithm_type+source+source_param+dimension_id`；
   relation: `algorithm_type+dimension_id`）。命中活跃行 → 更新；命中软删行 → 复活；
   未命中 → 插入；提交集外活跃行按全量替换语义软删；
3. **乐观锁**：更新路径 `UPDATE ... WHERE id=? AND deleted=false AND updated_at=<expected>` +
   rowcount 校验，0 → CONFLICT；
4. **跨服务校验**：发布时经 `evaluation_service.EvaluationConfigService.GetDimensionByIds`
   对 `associated_dimensions` 的 dimension_id 做存在性校验（草稿保存不做）；
5. **草稿**：`algorithm_definition_drafts` 表 JSON 快照，发布成功后自动清除快照。
