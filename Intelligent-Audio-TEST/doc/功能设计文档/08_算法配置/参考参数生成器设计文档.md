# 参考参数生成器设计文档

## 概述

参考参数生成器（ReferenceParamsGenerator）是系统的核心组件，负责根据用例配置和音频标注数据，自动生成测试所需的参考参数。

## 数据流程

```
┌─────────────────┐     ┌──────────────────────────┐     ┌─────────────────────────┐
│ AlgorithmRefe   │     │ test_case.config         │     │ AudioAnnotation         │
│ renceParam      │     │ .rounds[n].audios        │     │ .code                   │
│ (算法配置定义)   │     │ (各轮音频配置)            │     │ (diarization/asr/      │
│                 │     │                          │     │  translation)           │
└────────┬────────┘     └────────────┬─────────────┘     └───────────┬─────────────┘
         │                       │                             │
         │   读取定义           │  逐轮读取音频ID              │  查询标注数据
         ▼                       ▼                             ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                      ReferenceParamsGenerator                            │
│  1. 根据 algorithm_type 读取参考参数配置                                 │
│  2. 逐轮（round）从 rounds[n].audios 获取音频ID列表                      │
│  3. 查询 AudioAnnotation 表获取标注数据（批量预加载）                     │
│  4. 处理重叠播放的时间戳调整（speaker 感知）                              │
│  5. 生成参考参数 (text/json/rttm/stm)，统一为 {code,type,value} 结构     │
└─────────────────────────────────────────────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────────┐
│              逐轮写入文件 + 路径存入独立列                                 │
│  static/ref_params/<case_id>/round_1.json                               │
│  [ {"code": "asr_ref_text", "type": "text", "value": "..."},            │
│    {"code": "translation_ref", "type": "text", "value": [...]},         │
│    {"code": "rttm_ref", "type": "rttm", "value": {...}} ]               │
│                                                                          │
│  test_cases.reference_params 独立列：                                    │
│  [ {"round_number": 1, "reference_params_path": "...round_1.json"} ]    │
└─────────────────────────────────────────────────────────────────────────┘
```

## 核心数据结构

### 1. AlgorithmReferenceParam（算法参考参数配置）

存储在 `algorithm_reference_params` 表中，定义每个算法的参考参数结构（唯一索引 `uq_algorithm_reference_param_code`：algorithm_type + code，WHERE deleted=false）：

| 字段 | 说明 | 示例 |
|------|------|------|
| `algorithm_type` | 算法类型 | `asr`, `translation`, `speaker_recognition` |
| `code` | 参考参数代码（用户自定义） | `my_asr_text`, `custom_diarization` |
| `name` | 参数显示名称 | `ASR参考文本` |
| `param_type` | 参数类型 | `text`, `audio`, `json`, `rttm`, `stm` |
| `annotation_code` | 标注代码 | `asr`, `translation`, `diarization` |
| `annotation_format` | 标注格式 | `json`, `text`, `rttm`, `stm` |
| `field_path` | 标注数据字段路径（可选） | `model`, `segments[].emotion` |
| `merge_mode` | 多音频合并方式（默认 `join`） | `join`, `collect`, `first` |
| `help_text` | 帮助提示文字 | — |
| `deleted` | 逻辑删除标志 | `false` |

### 2. AudioAnnotation（音频标注数据）

存储在 `audio_annotations` 表中：

| 字段 | 说明 | 示例 |
|------|------|------|
| `audio_id` | 关联音频ID | `4`, `17` |
| `code` | 标注代码 | `asr`, `translation`, `diarization` |
| `format` | 标注格式 | `json`, `text`, `rttm`, `stm` |
| `data` | 标注数据（JSON） | `{"segments": [...], "text": "..."}` |
| `source_language` / `target_language` | 翻译标注的语向 | `zh` / `en` |

### 3. test_case.config（用例配置，逐轮结构）

```python
{
    "rounds": [
        {
            "round_number": 1,
            "audios": [
                {"audio_id": 4, "play_order": 1},
                {"audio_id": 17, "play_order": 2}
            ],
            "algorithm_params": [
                {"field_code": "overlap_rate", "field_value": 0.25},
                {"field_code": "overlap_time", "field_value": 0}
            ]
        }
    ]
}
```

> 重叠率 `overlap_rate` / 重叠时间 `overlap_time` 从轮内 `algorithm_params` 读取（支持 `[{field_code, field_value}]` 列表与平面 dict 两种格式），仅作用于该轮的生成过程。

## 生成器架构

### 类结构

`ReferenceParamsGenerator` 为单一类（位于 `backend/utils/algorithm/reference_params_generator.py`），按参数特征分发到模块级提取函数，而非子类策略模式：

```
ReferenceParamsGenerator (主类，classmethod)
├── generate(test_case)                    # 逐轮生成，合并所有轮的结果
├── generate_for_round(test_case, round_data)  # 单轮独立生成（使用该轮 audios/algorithm_params）
├── apply_to_config(test_case)             # 逐轮写文件，路径存入 reference_params 独立列
├── on_audio_associated(test_case, round_number)  # 音频关联轮次后轻量刷新该轮
├── load_from_file(filepath)               # 从参考参数文件加载
├── get_reference_text(reference_params_col, code)     # 按代码取参考文本
├── get_all_reference_params(reference_params_col)     # 加载独立列引用的全部文件
├── get_reference_params_for_report(reference_params_col)  # 报告用（多轮按 code@round:N 展开）
└── _preload_audio_data(audio_ids)         # 批量预加载音频元数据与标注

模块级提取函数（按分支优先级调用）
├── _extract_field_from_audios(...)        # field_path 字段路径提取
├── _extract_translation_from_audios(...)  # 翻译参考（按共同语向交集）
├── _extract_annotation_with_overlap(...)  # 结构化标注（RTTM/STM + 重叠时间戳调整）
├── _extract_text_from_audios(...)         # 默认文本提取（segments[].text 拼接）
├── normalize_reference_params(params)     # 归一化为 {code, type, value} 统一结构
└── get_reference_value(param, ...)        # 按格式（text/rttm_text/rttm_json 等）取值
```

### 提取函数的调用分发

生成器根据 `AlgorithmReferenceParam` 配置的参数特征自动选择提取函数，覆盖全部算法类型，无需按算法注册子类。

## 生成逻辑详解

### 0. 字段路径提取（field_path）

当 `AlgorithmReferenceParam` 配置了 `field_path` 时，生成器会从标注 `data` 中按路径提取指定字段，而非使用默认的 text/segments 提取逻辑。

#### field_path 格式

| 格式 | 含义 | 示例 |
|------|------|------|
| `model` | 取 `data["model"]`（顶层标量） | `"whisper-large-v3"` |
| `score` | 取 `data["score"]`（顶层标量） | `0.92` |
| `segments[].emotion` | 遍历 `data["segments"]`，每项取 `["emotion"]` | `["happy", "neutral"]` |
| `segments[].confidence` | 遍历 `data["segments"]`，每项取 `["confidence"]` | `[0.95, 0.88]` |

#### merge_mode 合并方式

当一个用例的同一轮包含多个音频时，各音频提取的值需要合并：

| merge_mode | 行为 | 适用场景 |
|-----------|------|---------|
| `join`（默认） | 空格拼接成字符串 | `segments[].text` 这类文本 |
| `collect` | 收集成数组 | `model`、`score` 这类标量 |
| `first` | 只取第一个音频的值 | 所有音频共享同一个值时 |

#### 配置示例

假设上传的 JSON 标注文件为：

```json
{
  "name": "asr",
  "code": "asr",
  "txt": [
    { "speaker": "spk1", "start": 0.5, "end": 2.3, "text": "你好世界", "confidence": 0.95, "emotion": "neutral" },
    { "speaker": "spk2", "start": 3.0, "end": 5.1, "text": "今天天气不错", "confidence": 0.88, "emotion": "happy" }
  ],
  "model": "whisper-large-v3",
  "score": 0.92,
  "noise_type": "cafe"
}
```

在算法配置的"参考参数"标签页配置：

| 参数代码 | 参考类型 | 标注代码 | 字段路径 | 合并方式 | 说明 |
|---------|---------|---------|---------|---------|------|
| `asr_ref_text` | text | asr | *(空)* | join | 走默认逻辑，提取 seg.text 拼接 |
| `rttm_ref` | rttm | diarization | *(空)* | join | 走默认逻辑，提取 segments |
| `ref_model` | text | asr | `model` | collect | 提取 data.model |
| `ref_score` | text | asr | `score` | collect | 提取 data.score |
| `ref_noise` | text | asr | `noise_type` | first | 提取 data.noise_type |
| `ref_emotions` | json | asr | `segments[].emotion` | collect | 从每个 segment 取 emotion |

#### 提取函数

核心提取函数为 `_extract_field_from_audios()`：

```python
def _extract_field_from_audios(config, field_path, merge_mode='join',
                                annotation_code=None, annotation_format=None):
    """
    从音频标注的 data 中按字段路径提取值
    
    field_path 格式:
    - 'model'              → 自动补全为 'segments[].model'，遍历 data['segments'] 取 ['model']
    - 'segments[].emotion' → 遍历 data['segments']，每项取 ['emotion']
    
    merge_mode:
    - 'join'    → 空格拼接成字符串
    - 'collect' → 收集成数组
    - 'first'   → 只取第一个音频的值
    """
```

> **注意**：不含 `[]` 的 field_path 会被自动补上 `segments[].` 前缀（标注数据统一存为 segments 结构），即 `model` 实际按 `segments[].model` 提取。此外，当 `param_type='text'` 且 `field_path` 为空时，生成器兜底按 `segments[].<code>` 取值（code 即参考参数代码）。

#### 分支优先级

在 `_generate_single_param()` 中，提取逻辑的优先级为：

1. **field_path 有值** → 调用 `_extract_field_from_audios()`
2. **annotation_code == 'translation'**（或 code 含 translation）→ 调用 `_extract_translation_from_audios()`
3. **param_type in ['json', 'rttm', 'stm']** → 调用 `_extract_annotation_with_overlap()`
4. **其他** → 调用 `_extract_text_from_audios()`

### 1. 文本类型参考参数（text/json）

**处理逻辑**：
1. 从 `config.audios` 按 `play_order` 排序
2. 逐个查询音频的标注数据
3. 直接拼接所有文本内容

**示例**：
```python
# 音频4的ASR文本: "你好世界"
# 音频17的ASR文本: "Hello World"
# 合并后: "你好世界 Hello World "
```

### 2. 结构化标注（RTTM/STM）

**处理逻辑**：
1. 计算每个音频的时间偏移（支持重叠播放）
2. 调整每个片段的时间戳
3. 合并所有片段并按时间排序
4. 转换为 RTTM/STM 格式

#### 2.1 重叠播放时间偏移计算

结构化标注提取（`_extract_annotation_with_overlap`）实际采用 **speaker 感知偏移** `_calculate_speaker_aware_offsets()`：

- 相邻音频**有共同 speaker** → 顺序播放（offset = 前一音频结束时间）
- 相邻音频**无共同 speaker** → 按 `overlap_time`（秒，优先）或 `overlap_rate`（比例）交叠

```python
def _calculate_speaker_aware_offsets(audios_config, overlap_rate, overlap_time=0, preload_context=None):
    """
    假设:
    - 音频1时长: 10s（spk0），音频2时长: 10s（spk1，无共同 speaker）
    - 重叠率: 0.25 (25%)

    计算结果:
    - 音频1偏移: 0s
    - 音频2偏移: 10 * (1 - 0.25) = 7.5s
    - 若音频2与音频1有共同 speaker，则音频2偏移 = 10s（顺序播放）
    """
```

另有简化版 `_calculate_audio_offsets()`（链式交叠公式，不感知 speaker），供不依赖说话人标注的场景使用。偏移调整通过 `_adjust_segment_timestamps()` 对每段 start/end 加偏移量，并注入 `play_order` 便于排序。

#### 2.2 时间戳调整

```python
def _adjust_segment_timestamps(segments, offset):
    # 每个片段的 start 和 end 加上偏移量
    for seg in segments:
        seg['start'] = seg['start'] + offset
        seg['end'] = seg['end'] + offset
```

#### 2.3 RTTM 格式

```
SPEAKER test 1 0.00 3.50 <NA> <NA> spk0 <NA> <NA>
文本内容
SPEAKER test 1 7.50 3.50 <NA> <NA> spk1 <NA> <NA>
文本内容
```

#### 2.4 STM 格式

```
test spk0 0.00 3.50 文本内容
test spk1 7.50 3.50 文本内容
```

## 输出格式

### 参考参数文件结构

每轮的参考参数写入 `static/ref_params/<case_id>/round_<n>.json`（`Config.REF_PARAMS_STORAGE_PATH` 目录），单条参数为统一 `{code, type, value}` 结构：

```python
[
    {
        "code": "asr_ref_text",            # 参考参数代码
        "type": "text",                     # 参数类型
        "value": "你好世界 Hello World",    # 参考值（文本）
        "annotation_code": "asr",           # 标注代码（可选）
        "annotation_format": "json"         # 标注格式（可选）
    },
    {
        "code": "translation_ref",
        "type": "text",
        "value": [
            {"translation_direction": "zh2en", "source_language": "zh",
             "target_language": "en", "text": "翻译文本..."}
        ]
    },
    {
        "code": "rttm_ref",
        "type": "rttm",
        "value": {
            "segments": [...],              # 时间戳调整后的结构化片段
            "text": "SPEAKER test 1 0.00...",  # RTTM 文本格式
            "json": "[...]"                 # segments 的 JSON 字符串
        },
        "annotation_code": "diarization",
        "annotation_format": "rttm"
    }
]
```

> 双记录架构下，生成过程内部仍计算 api/e2e 两类值，但最终仅保留该用例记录 `test_type` 对应的值写入 `value` 字段；`normalize_reference_params()` 负责旧结构（含 api/e2e 键）到新结构的归一化。

### 独立列存储

```python
# test_cases.reference_params 独立列（按轮分组，每轮一个文件）
[
    {"round_number": 1, "reference_params_path": "static/ref_params/12/round_1.json"},
    {"round_number": 2, "reference_params_path": "static/ref_params/12/round_2.json"}

```

多轮报告中同一 code 的多轮参数会展开为 `code@round:N` 键（`get_reference_params_for_report`）。

## 调用时机

参考参数生成器（含 `refresh_reference_texts` 封装）在以下场景被调用：

1. **创建/复制/更新用例时** — `testcase_controller.py`
   - 创建用例、复制用例、更新影响参考参数的字段后自动刷新（见性能优化·条件刷新）

2. **音频关联轮次时** — `audio_controller.py`
   - 上传/关联音频后调用 `refresh_reference_texts`；音频关联到具体轮次时走轻量入口 `on_audio_associated(test_case, round_number)`，仅重生成该轮

3. **批量刷新时** — `testcase_controller.py`
   - 批量动作"刷新参考参数"：≤50 个用例同步逐个刷新；>50 提交异步任务（见 §ref-params 接口与批量刷新）

4. **执行测试时** — `api_executor.py`、`base_executor.py`
   - 通过 `get_reference_text` / `get_all_reference_params` 从独立列文件加载参考值用于评分

5. **评估时** — `evaluation_service.py`、`case_parameter_extractor.py`
   - 评估维度 source=reference 时按轮取参考文件内容

6. **报告导出/结果重提取时** — `report_controller_task.py`、`report_controller_base.py`、`device_result_reextractor.py`
   - 读取参考参数（多轮按 `code@round:N` 展开）生成测试报告

## ref-params 接口与批量刷新

参考参数文件的维护走用例蓝图（前缀 `/api/v1/testcases`，见 `backend/blueprints/testcase_bp.py`）：

### 单轮读写

```
GET /api/v1/testcases/<tc_id>/rounds/<round_number>/ref-params
    # 读取该轮参考参数文件内容（config.rounds 中该轮 referenceParamsPath 指向的 JSON）

PUT /api/v1/testcases/<tc_id>/rounds/<round_number>/ref-params
    # 请求体 {"referenceParams": [...]}，经 normalize_reference_params 归一化后
    # 直接写回该轮参考参数文件
```

### 批量刷新（≤50 同步 / >50 异步）

批量刷新入口为 `TestCaseController._batch_refresh_reference`：

- **≤50 个用例**：同步逐个调用 `refresh_reference_texts(tc)`，等待完成后返回更新数量
- **>50 个用例**：调用 `submit_reference_refresh_task(ids)` 提交后台任务，立即返回 `task_id`

```python
# backend/utils/common/reference_refresh_task.py
submit_reference_refresh_task(case_ids) -> str    # 经 execution_engine.api_task_pool 提交后台任务
get_reference_refresh_task_status(task_id) -> dict  # 查询状态/进度（total/updated/failed/progress/failed_cases）
```

轮询接口：

```
GET /api/v1/testcases/refresh_task/<task_id>
    # 返回任务状态（pending/running/completed/failed）与进度信息
```

## 性能优化

### 优化背景

当用例包含大量音频（如100+条）时，参考参数生成存在严重的 N+1 查询问题，导致保存接口响应缓慢。

### 优化策略

#### 1. 条件刷新（Conditional Refresh）

**位置**：`testcase_controller.py` 的 `update()` 方法

**原理**：只在影响参考参数的字段变化时才触发刷新

```python
need_refresh_reference = False

if TestCaseController._audios_changed(current_config, merged_config):
    need_refresh_reference = True

if algorithm_type is not None and algorithm_type != tc.algorithm_type:
    need_refresh_reference = True
    tc.algorithm_type = algorithm_type

if algo_params_col:
    old_params = TestCaseController._get_algo_params_list_from_columns(tc.algorithm_params, 1)
    new_params = TestCaseController._get_algo_params_list_from_columns(algo_params_col, 1)
    if TestCaseController._has_overlap_param_changed(old_params, new_params):
        need_refresh_reference = True

if need_refresh_reference:
    refresh_reference_texts(tc)
```

**效果**：
- 更新名称/描述/标签/分组时跳过耗时操作
- 响应时间从秒级降到毫秒级

#### 2. 批量预加载（Batch Preload）

**位置**：`reference_params_generator.py` 的 `_preload_audio_data()` 方法

**原理**：在生成参数前，一次性查询所有音频的元数据和标注

```python
@classmethod
def _preload_audio_data(cls, audio_ids: List[int]) -> Dict[str, Any]:
    audio_map = {}
    annotation_map = {}
    duration_map = {}
    
    audios = Audio.query.filter(Audio.id.in_(audio_ids)).all()
    audio_map = {a.id: a for a in audios}
    
    annotations = AudioAnnotation.query.filter(
        AudioAnnotation.audio_id.in_(audio_ids),
        AudioAnnotation.deleted == False
    ).all()
    
    for ann in annotations:
        annotation_map.setdefault(ann.audio_id, []).append(ann)
    
    return {
        'audio_map': audio_map,
        'annotation_map': annotation_map,
        'duration_map': duration_map
    }
```

**效果**：
- 查询次数从 O(N) 降到 O(1)
- 100条音频场景下减少 90%+ 数据库往返

### 性能对比

| 场景 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| 更新名称/描述 | 触发参考参数生成 | **跳过** | ~100% |
| 100条音频更新 | 400-500次DB查询 | **2-3次**DB查询 | ~95% |
| 音频配置变化 | N+1查询 | 批量查询 | ~90% |

### 触发刷新的条件

| 字段变化 | 是否触发刷新 | 原因 |
|----------|--------------|------|
| `name` | ❌ 否 | 不影响参考参数 |
| `description` | ❌ 否 | 不影响参考参数 |
| `tags` | ❌ 否 | 不影响参考参数 |
| `group_id` | ❌ 否 | 不影响参考参数 |
| `config.rounds[].audios` | ✅ 是 | 音频配置变化影响参考参数（`_audios_changed` 对比新旧 config） |
| `algorithm_type` | ✅ 是 | 算法类型变化影响参考参数结构 |
| 轮内 `algorithm_params` 中的 `overlap_rate` / `overlap_time` | ✅ 是 | 重叠参数变化影响时间戳偏移（`_has_overlap_param_changed` 按轮对比独立列） |
