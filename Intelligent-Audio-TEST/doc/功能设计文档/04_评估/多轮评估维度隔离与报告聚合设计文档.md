# 多轮评估维度隔离与报告聚合设计文档

## 1. 背景

在多轮测试场景下，用例的评估维度配置存在三种模式：

| 配置模式 | 说明 | DB 记录 |
|---------|------|---------|
| **每轮都评估** | 每轮各自配置 `rounds[n].evaluation.dimensions` | round=0, round=1, ... 各有记录 |
| **只配特定轮次** | 仅某一轮配置了评估维度 | 只有该 round 有记录 |
| **配了整体评估** | 顶层 `config.dimensions` 配置了多轮聚合维度 | round_number=None 的 overall 记录 |

原有实现存在以下问题：

1. **空维度轮次被无意义评估**：某轮 `dimensions: []` 时，只要 `enabled` 没被显式设为 `False`，评估仍被提交，导致超时失败。
2. **维度全局合并**：`evaluate_case` 内部合并所有轮次 + 顶层的 dimensions 去重，不按 `round_number` 过滤，导致每轮都评估了不该评估的维度。
3. **重新评估不走逐轮**：reevaluator 的 E2E 分支只走 `round_number=None` 的整体评估，没有逐轮提交。
4. **执行阶段聚合多余**：`e2e_aggregator.update_algorithm_result_evaluation` 硬编码 `wer`/`llm_judge` 维度名做聚合，实际维度名是中文，全部匹配不上；且报告层不读 `algo_result.aggregated`，聚合结果无用。
5. **报告取值不区分轮次**：`extract_dimension_values` 遍历 `TestResultDimension` 时不区分 `round_number`，同一维度多条记录（round=0, round=1, overall）混在一起，后遍历到的覆盖前面的，取值不确定。
6. **pass_rate 策略数据被合并**：对 `statistic_method=pass_rate` 的维度，`agg_items` 收集时用的是 `extract_dimension_values` 返回的算术平均值，多轮被合并成 1 个 item，`PassRateStrategy` 统计结果错误。

## 2. 设计目标

- **维度隔离**：单轮评估只评该轮配置的维度，整体评估只评顶层配置的维度。
- **空维度跳过**：某轮 `dimensions` 为空时跳过评估，不提交评估请求。
- **重新评估对齐**：重新评估流程与正常执行流程一致，逐轮 + 整体评估。
- **报告取值正确**：按优先级取值——有 overall 取 overall，无 overall 取各轮算术平均（average 维度）或每轮独立 item（pass_rate 等策略维度）。
- **聚合策略适配**：3 种聚合策略（average / pass_rate / weighted_wer）均正确处理多轮数据。

## 3. 修改内容

### 3.1 维度隔离：单轮评估触发条件

**文件**：`backend/services/execution/e2e_executor.py`

**修改位置**：`_build_and_submit_round_data` 方法

**修改前**：
```python
_round_eval = _case_rounds[round_idx].get('evaluation', {})
if isinstance(_round_eval, dict) and _round_eval.get('enabled', True) is False:
    _round_eval_enabled = False
```

**修改后**：
```python
_round_eval = _case_rounds[round_idx].get('evaluation', {})
if isinstance(_round_eval, dict):
    if _round_eval.get('enabled', True) is False:
        _round_eval_enabled = False
    elif not _round_eval.get('dimensions'):
        _round_eval_enabled = False
```

**效果**：当本轮 `dimensions` 为空（或不存在）时，跳过该轮评估，不提交评估请求。

### 3.2 维度隔离：evaluate_case 按 round_number 过滤

**文件**：`backend/services/evaluation/evaluation_service.py`

**修改位置**：`_load_test_case_and_refs` 方法

**修改前**：合并所有轮次 + 顶层 dimensions 去重。

**修改后**：
```python
if round_number is not None:
    # 单轮评估：只取该轮的 dimensions
    if round_number < len(rounds_list):
        round_eval = rounds_list[round_number].get('evaluation', {})
        if isinstance(round_eval, dict):
            unique_dimension_ids = round_eval.get('dimensions', [])
else:
    # 整体评估：只取顶层 config.dimensions
    unique_dimension_ids = case_config.get('dimensions', [])
```

**效果**：

| 评估场景 | 维度来源 |
|---------|---------|
| 单轮评估 (`round_number=0/1/...`) | `rounds[round_number].evaluation.dimensions` |
| 整体评估 (`round_number=None`) | `config.dimensions` |

### 3.3 重新评估对齐：逐轮 + 整体评估

**文件**：`backend/services/execution/reevaluation_executor.py`

**修改位置**：E2E 分支（原 `_evaluate_e2e_case` 方法）

**修改前**：一次性调用 `evaluate_case(round_number=None)`，只走整体评估。

**修改后**：
1. **逐轮评估**：遍历每轮，检查 `evaluation.enabled` 和 `dimensions` 是否为空，非空时调用 `evaluate_case(round_number=round_idx)`
2. **整体评估**：检查顶层 `config.dimensions` 是否非空，非空时调用 `evaluate_case(round_number=None)`
3. **返回值**：`any_submitted` 跟踪是否有任一轮或整体真正提交了评估

### 3.4 执行阶段聚合简化：只回填 rounds[].evaluation

**文件**：`backend/services/execution/e2e_aggregator.py`

**修改位置**：`update_algorithm_result_evaluation` 方法

**修改前**：
- 回填 `rounds[].evaluation`
- 硬编码计算 `avg_wer` 和 `avg_llm_judge`（维度名不匹配，结果全 null）
- 写入 `algo_result.aggregated`

**修改后**：
- 仅回填 `rounds[].evaluation`（每轮的维度分数）
- 不再计算 `aggregated`（聚合由报告层直接查 DB 完成）

### 3.5 RoundAggregator 合并而非覆盖

**文件**：`backend/services/evaluation/round_aggregator.py`

**修改位置**：`_update_algorithm_result_aggregated` 方法

**修改前**：
```python
result_data['aggregated'] = aggregated  # 覆盖
```

**修改后**：
```python
existing_aggregated = result_data.get('aggregated', {})
existing_aggregated.update(aggregated)  # 合并
```

### 3.6 报告取值：extract_dimension_values 按优先级取值

**文件**：`backend/utils/report/report_utils.py`

**修改位置**：`extract_dimension_values` 方法

**修改前**：遍历所有维度记录，不区分 `round_number`，后覆盖前。

**修改后**：按优先级取值：

```python
# 1. 按 round_number 分两组收集
for dr in dim_results:
    if dim_round is None:
        dim_overall[dim_id] = dim_val       # overall 组
    else:
        dim_rounds[dim_id].append(dim_val)  # 单轮组

# 2. 按优先级取值
for dim_id, dim_name in dim_id_to_name.items():
    if dim_id in dim_overall:
        values[dim_name] = dim_overall[dim_id]                    # 优先 overall
    elif dim_id in dim_rounds and dim_rounds[dim_id]:
        values[dim_name] = round(sum(scores) / len(scores), 4)   # 各轮算术平均
    else:
        values[dim_name] = None
```

**取值规则**：

| 用例配置 | DB 记录 | 取值方式 |
|---------|---------|---------|
| 配了整体评估 | round_number=None | 取 overall 的 dimension_value |
| 每轮都评估，无 overall | round=0, round=1, ... | 各轮 dimension_value 算术平均 |
| 只配特定轮次 | 只有 round=1 | 取该轮的 dimension_value |
| 某轮未评估 | 该轮无记录或 dimension_value=None | 不计入平均 |

### 3.7 聚合策略适配：pass_rate 等维度每轮独立成 item

**文件**：`backend/utils/report/report_utils.py`

**修改位置**：`calculate_core_metrics` 方法中 `custom_agg_dims` 的 item 收集逻辑

**修改前**：
```python
# 用 extract_dimension_values 返回的值（已算术平均）作为 1 个 item
agg_item = {'dimension_value': score, ...}
resource_agg_items[dim_name][resource].append(agg_item)
```

**修改后**：
```python
# 从 dim_results_map 取每轮的独立记录，每轮一个 item
for dr in dim_results_map[result.id]:
    if dr_dim_id == target_dim_id and dr_val is not None:
        agg_item = {'dimension_value': dr_val, 'api_raw_response': raw_resp, ...}
        resource_agg_items[dim_name][resource].append(agg_item)
```

**效果**：对 `statistic_method != 'average'` 的维度（如 `pass_rate`、`weighted_wer`），每轮作为一个独立 item 传给聚合策略类。

### 3.8 报告查询：_get_dimension_results_batch 恢复全量查询

**文件**：`backend/controllers/report_controller_task.py`

**修改位置**：`_get_dimension_results_batch` 方法

**修改前**：查询不带 `round_number` 过滤。

**中间状态**：加了 `round_number.is_(None)` 只查 overall。

**修改后**：恢复查所有轮次记录，新增 `round_number` 字段到查询结果：

```python
dim_results = db.session.query(
    TestResultDimension.test_result_id,
    TestResultDimension.dimension_id,
    TestResultDimension.dimension_value,
    TestResultDimension.round_number,          # 新增
    TestResultDimension.api_raw_response,
    Dimension.name.label('dimension_name')
).join(Dimension, TestResultDimension.dimension_id == Dimension.id)\
 .filter(TestResultDimension.test_result_id.in_(result_ids)).all()
```

## 4. 聚合策略适配分析

系统共有 3 种聚合策略（`aggregation_strategies.py`）：

| 策略 | `statistic_method` | 逻辑 | 适配情况 |
|------|-------------------|------|---------|
| **SimpleAverageStrategy** | `average` | `sum(values) / count` | 不走 `custom_agg_dims`，走 `extract_dimension_values` → `resource_accumulator` 算术平均，不受改动影响 |
| **PassRateStrategy** | `pass_rate` | `达标 item 数 / 总 item 数 * 100` | 改动后从 `dim_results_map` 取每轮独立 item，不再被算术平均合并，`pass_count / total` 正确 |
| **WeightedSumRatioStrategy** | `weighted_wer` | `Σ(numerator) / Σ(denominator)` | 同样走 `custom_agg_dims` 分支，每轮独立成 item，`api_raw_response` 也按每轮取 |

## 5. 数据流

### 5.1 执行阶段

```
e2e_executor._finalize_rounds
  ├── 逐轮评估: evaluate_case(round_number=0) → 只取 rounds[0].evaluation.dimensions
  ├── 逐轮评估: evaluate_case(round_number=1) → 只取 rounds[1].evaluation.dimensions
  ├── 整体评估: evaluate_case(round_number=None) → 只取 config.dimensions（如果有）
  └── update_algorithm_result_evaluation(task_id, result_id)
      └── 回填 rounds[].evaluation（仅回填，不聚合）
```

### 5.2 重新评估阶段

```
reevaluation_executor._evaluate_e2e_case
  ├── 逐轮评估: evaluate_case(round_number=0)
  ├── 逐轮评估: evaluate_case(round_number=1)
  ├── 整体评估: evaluate_case(round_number=None)（如果有 config.dimensions）
  └── 返回 any_submitted
```

### 5.3 报告生成阶段

```
report_controller_task._generate_task_report_async
  ├── _get_dimension_results_batch(result_ids)
  │   └── 查询所有 TestResultDimension 记录（含 round_number）
  ├── calculate_core_metrics(results, all_dimensions, dim_results_map)
  │   ├── for result in results:
  │   │   ├── extract_dimension_values(result.id, all_dimensions, dim_results_map)
  │   │   │   ├── 有 overall → 取 overall 的 dimension_value
  │   │   │   └── 无 overall → 取各轮 dimension_value 算术平均
  │   │   ├── average 维度: 累加到 resource_accumulator → 算术平均
  │   │   └── 非 average 维度: 从 dim_results_map 取每轮独立 item → 传给策略类
  │   ├── _calculate_resource_averages(resource_accumulator) → metric_data
  │   └── _apply_resource_aggregation_strategies(metric_data, agg_items)
  │       ├── average → SimpleAverageStrategy (已在 step 9 算好，不替换)
  │       ├── pass_rate → PassRateStrategy (用每轮独立 item 重新计算)
  │       └── weighted_wer → WeightedSumRatioStrategy (用每轮独立 item 重新计算)
  ├── calculate_case_type_stats_optimized(results, all_dimensions, dim_results_map)
  └── calculate_device_api_stats(results, all_dimensions, dim_results_map)
```

## 7. 注意事项

1. **`enabled` 开关优先级**：`evaluation.enabled=False` 仍然优先于 `dimensions` 空检查，只有 `enabled` 未被设为 `False`（默认 `True`）时才检查 `dimensions` 是否为空。

2. **聚合逻辑不变**：报告层的聚合策略（`aggregation_strategies.py`）本身未修改，只是确保传入策略类的数据正确。

3. **整体评估独立性**：整体评估（`round_number=None`）由 `evaluate_case` 提交到评估服务端，服务端返回结果后写入 `TestResultDimension(round_number=None)`，报告层直接读取。

4. **兜底查询适配**：`extract_dimension_values` 的兜底查询（无 `dim_results_map` 时）也改为全量查后按优先级取值，不再 `.first()` 只取一条。

5. **`report_controller_base.py` 待改**：`extract_dimension_values` 在 `report_controller_base.py` 中有另一个实现，影响报告用例列表和搜索接口，存在相同问题，待后续适配。
