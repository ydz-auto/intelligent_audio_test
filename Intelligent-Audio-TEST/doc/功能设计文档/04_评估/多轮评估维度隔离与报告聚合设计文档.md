# 多轮评估维度隔离与报告聚合设计文档

## 1. 背景

在多轮测试场景下，用例的评估维度配置存在三种模式：

| 配置模式 | 说明 | DB 记录 |
|---------|------|---------|
| **每轮都评估** | 每轮各自配置 `rounds[n].evaluation.dimensions` | round=0, round=1, ... 各有记录 |
| **只配特定轮次** | 仅某一轮配置了评估维度 | 只有该 round 有记录 |
| **配了整体评估** | 顶层 `config.dimensions` 配置了多轮聚合维度 | round_number=None 的 overall 记录 |

原有实现存在以下问题：

1. **空维度轮次被无意义评估**：某轮 `dimensions: []` 时，只要 `enabled` 没被显式设为 `False`，评估仍被提交，导致超时失败。
2. **维度全局合并**：`evaluate_case` 内部合并所有轮次 + 顶层的 dimensions 去重，不按 `round_number` 过滤，导致每轮都评估了不该评估的维度。
3. **重新评估不走逐轮**：reevaluator 的 E2E 分支只走 `round_number=None` 的整体评估，没有逐轮提交。
4. **执行阶段聚合多余**：`e2e_aggregator.update_algorithm_result_evaluation` 硬编码 `wer`/`llm_judge` 维度名做聚合，实际维度名是中文，全部匹配不上；且报告层不读 `algo_result.aggregated`，聚合结果无用。
5. **报告取值不区分轮次**：`extract_dimension_values` 遍历 `TestResultDimension` 时不区分 `round_number`，同一维度多条记录（round=0, round=1, overall）混在一起，后遍历到的覆盖前面的，取值不确定。
6. **pass_rate 策略数据被合并**：对 `statistic_method=pass_rate` 的维度，`agg_items` 收集时用的是 `extract_dimension_values` 返回的算术平均值，多轮被合并成 1 个 item，`PassRateStrategy` 统计结果错误。

## 2. 设计目标

- **维度隔离**：单轮评估只评该轮配置的维度，整体评估只评顶层配置的维度。
- **空维度跳过**：某轮 `dimensions` 为空时跳过评估，不提交评估请求。
- **重新评估对齐**：重新评估流程与正常执行流程一致，逐轮 + 整体评估。
- **报告取值正确**：按优先级取值——有 overall 取 overall，无 overall 取各轮算术平均（average 维度）或每轮独立 item（pass_rate 等策略维度）。
- **聚合策略适配**：4 种聚合策略（average / pass_rate / weighted_wer / ratio）均正确处理多轮数据。

### 3.9 新增比率统计策略：RatioStrategy（statistic_method='ratio'）

**文件**：`backend/utils/report/aggregation_strategies.py`、`backend/utils/report/report_utils.py`、`backend/scripts/migrations/202609/seed_interruption_v2.py`、`backend/controllers/report_controller_task.py`、`backend/models/models.py`、`backend/scripts/migrations/202609/add_agg_denominator_column.py`

**背景**：打断指标 v2 的 8 个数量类维度（打断成功/失败/询问数量 + 回复/恢复/无关/静默/询问行为数量）原为 `average` 聚合，报告展示"平均次数"。实际需求是聚合为**占比比例**：如"打断成功数量"应展示为"打断成功率 = Σ成功次数 / Σ分母 × 100%"。

**分母口径下沉到所有统计方式**：`agg_denominator`（按轮次/按用例）不仅 ratio 使用，**average / pass_rate 同样生效**（weighted_wer 分母来自原始字段的 Σ分子/Σ分母，不随口径变化）：

| 统计方式 | 按用例（`case`，默认） | 按轮次（`round`） |
|---------|----------------------|------------------|
| `average` | Σ用例值 / 用例数（每用例等权） | Σ各轮值 / 轮次数（多轮用例权重更大） |
| `pass_rate` | 达标用例数 / 用例数 | 达标轮次数 / 轮次数 |
| `ratio` | Σ数量 / 用例数 × 100 | Σ数量 / 轮次数 × 100 |
| `weighted_wer` | Σ分子/Σ分母（口径无关） | 同左 |

**分母口径的关键约束**：分母不能从 `api_raw_response` 的字段（如 `interruption.interruption_rounds`）读取——无整体结果时每轮 item 都携带同一份列表会重复计数、LLM 降级时该字段为空会缺分母。因此分母只能取**配置了该维度的用例数**或**有值的轮次数**，且按维度配置决定：

- `agg_denominator='round'`（按轮次）：分母 = Σ各用例该维度有值轮次数（`item['round_count']`，average 累加时每轮 1 个样本）
- `agg_denominator='case'`（按用例）：分母 = 配置了该维度且有值的用例数（按 `test_result_id` 去重）

两口径都覆盖 **多轮/单轮 × 有整体结果/无整体结果** 4 种场景：
有整体结果时每用例收集 1 个 overall item（值=用例总数），轮次数通过 `round_count` 记录；无整体结果时每轮 1 个 item（值=该轮数量），按用例去重后同样只计一次轮次数/用例数。

**新增策略**：

```python
class RatioStrategy(AggregationStrategy):
    """比率/占比统计：Σ(分子) / Σ(分母) * 100，产出百分比 (0~100)。

    分子 = Σ(item['dimension_value'])（各结果/轮次的原始数量，如打断成功数量）。
    分母口径由 denominator_mode 决定（维度配置 agg_denominator，值 round/case）：
      - 'case'（按用例，默认）：分母 = 配置了该维度且有值的用例数（按 test_result_id 去重）
      - 'round'（按轮次）：分母 = 各用例该维度有值轮次数之和（item['round_count']）
    无轮次记录（如纯 overall 数据）时按轮次口径回退为用例数。
    """

    def aggregate(self, items, output_params=None, denominator_mode=None):
        mode = (denominator_mode or 'case').lower()
        total_num = 0
        seen_cases = set()
        n_cases = 0
        total_rounds = 0
        for item in items:
            num_val = _parse_numeric(item.get('dimension_value'))
            if num_val is None:
                continue
            total_num += num_val
            case_id = item.get('test_result_id')
            if case_id is not None and case_id not in seen_cases:
                seen_cases.add(case_id)
                n_cases += 1
                rc = item.get('round_count')
                total_rounds += int(rc) if rc else 0
        if mode == 'case':
            if n_cases == 0:
                return None
            return round(total_num / n_cases * 100, 2)
        denominator = total_rounds if total_rounds > 0 else n_cases
        if denominator == 0:
            return None
        return round(total_num / denominator * 100, 2)
```

注册表新增：`'ratio': RatioStrategy()`；`AggregationStrategy.aggregate` 及各策略签名统一增加 `denominator_mode=None` 参数。

**item 结构扩展**（report_utils.py 三处 item 收集循环）：每项新增 `round_count`（该用例该维度有值的轮次数），供按轮次口径做分母。

**排除轮次（exclude_rounds）**：按轮次口径统计时，维度可配置排除指定轮次（如上下文轮 0），被排除的轮次不参与分母。**比率维度（ratio）有整体结果时**，分子 = 整体值 − Σ被排除轮次的逐轮值（下限 0），分母 = 未排除轮次数——整体值是上下文重判的用例判定总数（如打断失败数），与逐轮值可能不一致，故以整体为基准扣减被排除轮次，避免"改用各轮明细"导致的分子低估（如整体判定 2 次失败、逐轮只记 1 次）；无整体结果或非 ratio 维度仍取各轮明细（跳过被排除轮次）；`round_count` 只计未排除轮次；按轮次平均（`_get_round_values`）同样跳过被排除轮次；若全部轮次被排除或无轮次记录，回退整体值 1 个样本。

**前端多选下拉 + 最后一轮**：前端展示为多选下拉（第1轮~第10轮，值 = 后端轮次号从 0 起，故"第1轮"=0）；另有「最后一轮」选项，以哨兵值 `-1` 存储。聚合时 `_resolve_exclude_rounds` 把 `-1` 解析为**该用例该维度的最大轮次**（逐用例解析，因各用例轮次数可能不同）；无轮次记录时 `-1` 无效。

**维度配置变更**：

| 字段 | 修改前 | 修改后 |
|------|--------|--------|
| `statistic_method` | `average` | `ratio`（8 个数量类维度） |
| `score_unit` | `次` | `%` |
| `agg_denominator`（新增列，默认 `case`） | - | 8 个数量类维度 `round`；其余（含停止指令遵循）`case` |
| `exclude_rounds`（新增列，默认 `[]`） | - | 按轮次统计时排除的轮次（不参与分子/分母），用户可配置，如 `[0, 2]` |
| 数量类 main 输出参数 | `agg_role='value'` | 不变（分子直接用 dimension_value） |

**报告 unit 联动**（report_controller_task.py `_build_all_metrics`）：

```python

    unit = "%"
# 修改后：ratio 同样产出百分比，强制为 %（并透出 agg_denominator 到 all_metrics）
```

**效果**：例如资源级聚合下，打断失败数量 = Σ(各用例打断失败数量) / Σ(各用例有值轮次数) × 100 = 打断失败占比(%)。

### 3.10 写侧（上传/批量导入）维度落库规则

> 「所有 / 指定 / 逐轮」三档；INT-1600 前置审核确认后端写侧未支持，INT-1607 可行性评审
> 裁定「需调整（不通过，可实施）」后按 S1~S10 修订，实施卡 INT-1606（代码）、INT-1615（本卡）。

**文件**：`audio_service/application/services/_creation_round_config_mixin.py`
**修改位置**：`_build_config_and_apply_dimensions`（及其内部私有 helper）

**修改前**：只要顶层 `dimensions` 为真，就把同一份逐轮维度**无条件写进每一轮**（且各轮共享
同一 list 引用），`rounds[i].evaluation.dimensions` 被抹平成同一套；轮的维度归属丢失，
「指定 / 逐轮」两档无法落库。

**修改后（R1~R6）**：

| 规则 | 落库行为 |
|------|---------|
| **R1 整体判定** | 任一轮自带 `evaluation.dimensions`（是 list，**显式 `[]` 也算**；判定在 `test_type` 过滤之前）→ 本次请求**整体以载荷为准**：自带轮写「归一化 → `test_type` 过滤 → 按 `(id, round_scope)` 去重保序」后的逐轮维度（只替换 `evaluation['dimensions']`，其它键保留，每轮独立 list 拷贝）；未自带轮写 `[]`；顶层逐轮维度**一律忽略**并记 WARNING（含 audio / test_type 标识） |
| **R2 回填兼容** | **所有轮都未自带** → 顶层逐轮集合写入每一轮（每轮独立拷贝）；顶层 `round_scope='multi'` 写 `config.dimensions`。旧调用方（只传顶层 `dimensions`）行为零变化 |
| **R3 整体维度归并** | `config['dimensions']` = 顶层 multi ∪ 各轮 multi，顶层在前、按轮序追加，归一化 + `test_type` 过滤后按 `id` 去重保序；轮内 multi 从轮内移除。E2E 整体评估只认顶层 `config.dimensions`（`e2e_test_service/.../finalization_mixin.py` 的 `_has_overall_dims`），仅留轮内会让 E2E 永不出整体分并触发 `case_evaluation` 的空评估提前收口 |
| **R4 无维度可写** | 无顶层有效维度且无轮自带 → 维持现状，只给缺少 `evaluation.dimensions` 的轮补 `[]`，不覆盖已有；轮内 `dimensions` 非 list 的按 R5 归一为 `[]`（INT-1615 审计 P2-1：不归一会把脏形态留到读侧 `case_loader` 迭代时抛 TypeError） |
| **R5 容错** | 轮内 `dimensions` 非 list（`None` / dict）→ 视同未自带：**R1 / R4 归一为 `[]`；R2 按顶层回填集合覆盖**（如轮内 `dimensions: None` + 顶层 `[{'id': 1}]` → 该轮得 `[{'id': 1}]`）——三个分支脏形态都不落库；`evaluation: null` → 归一为 `{}` 再写；轮 item 非 dict → 跳过；裸 `int` 条目归一为 `{'id': n}`。均不抛异常（`/audios/upload/merge` 不因脏载荷 500） |
| **R6 结构不变** | `rounds` 数组不增删、不重排；不新增字段、不改 proto、不改网关 DTO |

**基础定义**：

- 逐轮集合 = `round_scope != 'multi'`（不是 `== 'single'`；`per_round` 与未标注同样按逐轮，
  对齐读侧 `case_loader._merge_dimensions_config`）。**唯一有意变更**：顶层 `round_scope='per_round'`
  由「被丢弃」改为「按逐轮写入」。
- 顶层 raw 只有解析结果是 list 才有效：`{'dimensions': []}` 是真值 dict 但视同「无顶层维度」，
  不能按 truthiness 判。

**载荷示例**（R1：整体以载荷为准）：

```json
{
  "test_case_config": {
    "rounds": [
      {"round_number": 1, "audios": [{"audio_name": "a.wav"}],
       "evaluation": {"dimensions": [{"id": 11, "name": "字准", "test_type": "api", "round_scope": "single"}]}},
      {"round_number": 2, "audios": [{"audio_name": "b.wav"}], "evaluation": {"dimensions": []}}
    ],
    "dimensions": []
  }
}
```

R1 结果：round1 维度 `[11]`（tt=e2e 时为 `[]`）；round2 `[]`；`config['dimensions']` 不存在。

**边界与前端义务**：

- 读/评估侧不改：`case_loader._merge_dimensions_config` 已按轮取。
- 维度目录接口（`DimensionItem` / `/evaluation/dimensions/options`）目前不返回 `test_type` /
  `round_scope` / `llmJudgeConfig`，UI 要分流或配整体口径须另开 FEAT 扩 DTO（不在本改动范围）。
- 前端上传弹窗须从「发维度 id 列表」改为「发维度对象」（至少 `{id}`；逐轮配权重/阈值/LLM 时
  带 `name/weight/threshold/llmJudgeConfig`）。注意：归并进 `config.dimensions` 的 **multi 条目
  必须带 `name`**——网关详情 DTO `TestCaseDimensionItem.name` 为必填，缺失会让
  `GET /api/v1/testcases/{id}` 校验失败（既有约束，非本次引入的写侧行为）。

## 4. 聚合策略适配分析

系统共有 4 种聚合策略（`aggregation_strategies.py`）：

| 策略 | `statistic_method` | 逻辑 | 适配情况 |
|------|-------------------|------|---------|
| **SimpleAverageStrategy** | `average` | `sum(values) / 分母`，分母按 `agg_denominator` 取用例数或轮次数 | 按用例口径（默认）走 `extract_dimension_values` → `resource_accumulator` 算术平均；按轮次口径累加时每轮 1 个样本 |
| **PassRateStrategy** | `pass_rate` | `达标数 / 分母 * 100`，分母按 `agg_denominator` 取用例数或轮次数 | 从 `dim_results_map` 取每轮独立 item，按口径取分母，`pass_count / total` 正确 |
| **WeightedSumRatioStrategy** | `weighted_wer` | `Σ(numerator) / Σ(denominator)` | 分母来自原始字段的 Σ，与按轮次/按用例口径无关；每轮独立 item |
| **RatioStrategy** | `ratio` | `Σ(数量) / 分母 × 100`，分母按 `agg_denominator` 取轮次数或用例数 | 走 `custom_agg_dims` 分支；item 携带 `round_count`，无论有/无整体都不重复计数 |

## 5. 数据流

### 5.1 执行阶段

```
e2e_executor._finalize_rounds
  ├── 逐轮评估: evaluate_case(round_number=0) → 只取 rounds[0].evaluation.dimensions
  ├── 逐轮评估: evaluate_case(round_number=1) → 只取 rounds[1].evaluation.dimensions
  ├── 整体评估: evaluate_case(round_number=None) → 只取 config.dimensions（如果有）
  └── update_algorithm_result_evaluation(task_id, result_id)
      └── 回填 rounds[].evaluation（仅回填，不聚合）
```

### 5.2 重新评估阶段

```
reevaluation_executor._evaluate_e2e_case
  ├── 逐轮评估: evaluate_case(round_number=0)
  ├── 逐轮评估: evaluate_case(round_number=1)
  ├── 整体评估: evaluate_case(round_number=None)（如果有 config.dimensions）
  └── 返回 any_submitted
```

### 5.3 报告生成阶段

```
report_controller_task._generate_task_report_async
  ├── _get_dimension_results_batch(result_ids)
  │   └── 查询所有 TestResultDimension 记录（含 round_number）
  ├── calculate_core_metrics(results, all_dimensions, dim_results_map)
  │   ├── for result in results:
  │   │   ├── extract_dimension_values(result.id, all_dimensions, dim_results_map)
  │   │   │   ├── 有 overall → 取 overall 的 dimension_value
  │   │   │   └── 无 overall → 取各轮 dimension_value 算术平均
  │   │   ├── average 维度: 累加到 resource_accumulator → 算术平均
  │   │   └── 非 average 维度: 从 dim_results_map 取每轮独立 item → 传给策略类
  │   ├── _calculate_resource_averages(resource_accumulator) → metric_data
  │   └── _apply_resource_aggregation_strategies(metric_data, agg_items)
  │       ├── average → SimpleAverageStrategy (已在 step 9 算好，不替换)
  │       ├── pass_rate → PassRateStrategy (用每轮独立 item 重新计算)
  │       ├── weighted_wer → WeightedSumRatioStrategy (用每轮独立 item 重新计算)
  │       └── ratio → RatioStrategy (Σ数量/Σ轮次数或用例数 × 100，按 agg_denominator 口径)
  ├── calculate_case_type_stats_optimized(results, all_dimensions, dim_results_map)
  └── calculate_device_api_stats(results, all_dimensions, dim_results_map)
```

## 7. 注意事项

1. **`enabled` 开关优先级**：`evaluation.enabled=False` 仍然优先于 `dimensions` 空检查，只有 `enabled` 未被设为 `False`（默认 `True`）时才检查 `dimensions` 是否为空。

2. **聚合逻辑不变**：报告层的聚合策略（`aggregation_strategies.py`）本身未修改，只是确保传入策略类的数据正确。

3. **整体评估独立性**：整体评估（`round_number=None`）由 `evaluate_case` 提交到评估服务端，服务端返回结果后写入 `TestResultDimension(round_number=None)`，报告层直接读取。

4. **兜底查询适配**：`extract_dimension_values` 的兜底查询（无 `dim_results_map` 时）也改为全量查后按优先级取值，不再 `.first()` 只取一条。

5. **`report_controller_base.py` 已适配**：`extract_dimension_values` 已改为与 report_utils 同款优先级取值（有 overall 取 overall、无 overall 取各轮算术平均），兜底查询全量查后按优先级取值，不再 `.first()` 只取一条；影响报告用例列表和搜索接口，两处输出与 report_utils 完全一致（已验证：用例 3766 全维度无差异）。

6. **分母口径不读原始响应字段**：各策略（average/pass_rate/ratio）分母只取"有值轮次数（round_count）"或"配置该维度的用例数"，不读 `interruption.interruption_rounds` 等原始响应字段，避免无整体结果时每轮重复携带导致的重复计数、以及 LLM 降级为空导致的缺分母。

7. **历史报告需重新生成**：打断数量类维度由 `average` 改为 `ratio` 是维度配置变更，已生成的报告（如 293）的 `metric_data` 是旧口径平均值，需对报告执行 `regenerate` 才会按新占比口径重算。

8. **排除轮次仅在按轮次口径生效**：`exclude_rounds` 只影响 `agg_denominator='round'` 的聚合（含按轮次平均/达标率/比率）；按用例口径无需排除。排除轮次仍以维度有值的轮次为准（无值的轮次本就不参与统计）。
