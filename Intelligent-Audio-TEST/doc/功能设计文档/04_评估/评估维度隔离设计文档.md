# 评估维度隔离设计文档

## 1. 背景

### 1.1 问题描述

在多轮 E2E 测试场景中，用例配置如下：

```json
{
  "rounds": [
    {
      "round_number": 1,
      "evaluation": { "dimensions": [] }
    },
    {
      "round_number": 2,
      "evaluation": { "dimensions": [{"id": 24}, {"id": 21}, ...] }
    }
  ],
  "dimensions": []
}
```

上述用例只在第 2 轮配置了评估维度，第 1 轮和顶层均无维度。但实际运行时，**两轮都被触发了评估**，原因有两个：

1. **单轮触发只检查 `enabled`，不检查 `dimensions` 是否为空**：即使该轮 `dimensions: []`，只要 `enabled` 没被显式设为 `False`（默认 `True`），评估仍被提交。

2. **`evaluate_case` 合并所有轮次 + 顶层的维度**：加载维度时遍历所有轮的 `evaluation.dimensions` 去重合并，只要任意一轮有维度，合并后集合就非空，所有轮都会评估。

这导致：
- 无维度的轮被无意义地提交评估，浪费评估服务资源。
- 无维度的轮可能因评估服务超时（600 秒）而失败，连带整个用例被标记为失败。

### 1.2 修复目标

| 评估场景 | 维度来源 | 触发条件 |
|---------|---------|---------|
| 单轮评估 (`round_number=N`) | 只取 `rounds[N].evaluation.dimensions` | `enabled != False` **且** `dimensions` 非空 |
| 整体评估 (`round_number=None`) | 只取顶层 `config.dimensions` | `config.dimensions` 非空 |

## 2. 修改内容

### 2.1 单轮评估触发条件（e2e_executor.py）

**文件**：`backend/services/execution/e2e_executor.py`
**方法**：`_build_and_submit_round_data`
**位置**：约第 502-524 行

#### 修改前

```python
# 检查本轮 evaluation.enabled 开关，enabled 为 False 时跳过单轮评估
_round_eval_enabled = True
if case_config:
    _case_rounds = case_config.get('rounds', [])
    if _case_rounds and round_idx < len(_case_rounds):
        _round_eval = _case_rounds[round_idx].get('evaluation', {})
        if isinstance(_round_eval, dict) and _round_eval.get('enabled', True) is False:
            _round_eval_enabled = False

if _round_eval_enabled:
    self._evaluate_result(...)
```

只检查 `enabled`，不检查 `dimensions` 是否为空。

#### 修改后

```python
# 检查本轮 evaluation.enabled 开关，enabled 为 False 时跳过单轮评估
# 同时检查本轮 dimensions 是否为空，为空时也跳过单轮评估
_round_eval_enabled = True
if case_config:
    _case_rounds = case_config.get('rounds', [])
    if _case_rounds and round_idx < len(_case_rounds):
        _round_eval = _case_rounds[round_idx].get('evaluation', {})
        if isinstance(_round_eval, dict):
            if _round_eval.get('enabled', True) is False:
                _round_eval_enabled = False
            elif not _round_eval.get('dimensions'):
                _round_eval_enabled = False

if _round_eval_enabled:
    self._evaluate_result(...)
```

新增 `elif not _round_eval.get('dimensions')` 判断：当本轮 `dimensions` 为空列表 `[]` 或不存在时，跳过该轮评估。

### 2.2 维度加载按轮次隔离（evaluation_service.py）

**文件**：`backend/services/evaluation/evaluation_service.py`
**方法**：`_load_test_case_and_refs`
**位置**：约第 367-420 行

#### 修改前

```python
def _load_test_case_and_refs(self, test_case_id, field_mapper, kwargs, task_id):
    ...
    test_case_config = test_case.config or {}
    # 合并所有轮次 dimensions + 顶层 dimensions
    dimensions_config = []
    seen_dim_ids = set()
    rounds = test_case_config.get('rounds', [])
    if rounds and isinstance(rounds, list):
        for round_item in rounds:
            evaluation = round_item.get('evaluation', {})
            round_dims = evaluation.get('dimensions', [])
            for d in round_dims:
                ...  # 去重合并
    # 合并顶层 config.dimensions
    top_dims = test_case_config.get('dimensions', [])
    for d in top_dims:
        ...  # 去重合并
```

不区分 `round_number`，合并所有轮次 + 顶层的维度。

#### 修改后

**方法签名新增 `round_number` 参数**：

```python
def _load_test_case_and_refs(self, test_case_id, field_mapper, kwargs, task_id, round_number=None):
```

**调用处传入 `round_number`**（`evaluate_case` 方法内）：

```python
case_data = self._load_test_case_and_refs(
    test_case_id, field_mapper, kwargs, task_id, round_number
)
```

**维度加载逻辑按 `round_number` 分支**：

```python
test_case_config = test_case.config or {}
dimensions_config = []
seen_dim_ids = set()
rounds = test_case_config.get('rounds', [])

if round_number is not None:
    # 单轮评估：只取指定轮的 dimensions
    if rounds and isinstance(rounds, list) and round_number < len(rounds):
        round_item = rounds[round_number]
        if isinstance(round_item, dict):
            evaluation = round_item.get('evaluation', {})
            if isinstance(evaluation, dict):
                round_dims = evaluation.get('dimensions', [])
                for d in round_dims:
                    dim_id = d.get('id') if isinstance(d, dict) else d
                    if dim_id and dim_id not in seen_dim_ids:
                        seen_dim_ids.add(dim_id)
                        dimensions_config.append(d)
else:
    # 整体评估：只取顶层 config.dimensions
    top_dims = test_case_config.get('dimensions', [])
    for d in top_dims:
        dim_id = d.get('id') if isinstance(d, dict) else d
        if dim_id and dim_id not in seen_dim_ids:
            seen_dim_ids.add(dim_id)
            dimensions_config.append(d)
```

- `round_number` 为整数 → 只取 `rounds[round_number].evaluation.dimensions`
- `round_number` 为 `None` → 只取顶层 `config.dimensions`

## 3. 影响范围

### 3.1 单轮评估流程

```
e2e_executor._build_and_submit_round_data
  → 检查 enabled + dimensions 是否为空
  → 非空才调用 _evaluate_result(round_number=round_idx)
    → evaluation_service.evaluate_case
      → _load_test_case_and_refs(round_number=round_idx)
        → 只取 rounds[round_idx].evaluation.dimensions
```

### 3.2 整体评估流程

```
e2e_executor._finalize_rounds
  → 检查 _has_overall_dims (config.dimensions 非空)
  → 非空才调用 _evaluate_result(round_number=None)
    → evaluation_service.evaluate_case
      → _load_test_case_and_refs(round_number=None)
        → 只取 config.dimensions
```

### 3.3 聚合逻辑

`_finalize_rounds` 中的聚合触发条件不受影响：

- `_has_round_dims`：遍历所有轮检查是否有 `dimensions` 非空，用于判断是否调用 `update_algorithm_result_evaluation`（回填各轮分数到 algo_result）。
- `_has_overall_dims`：检查顶层 `config.dimensions` 是否非空，用于判断是否提交整体评估。

这两个判断在修改前后逻辑一致，无需变更。

## 4. 典型用例验证

### 4.1 场景一：只最后一轮配维度

```json
{
  "rounds": [
    { "evaluation": { "dimensions": [] } },
    { "evaluation": { "dimensions": [{"id": 24}, {"id": 21}] } }
  ],
  "dimensions": []
}
```

| 轮次 | 修改前 | 修改后 |
|------|--------|--------|
| Round 0 | 评估（用 Round 1 的维度） | **跳过**（dimensions 为空） |
| Round 1 | 评估（用 Round 1 的维度） | 评估（用 Round 1 自己的维度） |
| 整体 | 跳过（顶层 dimensions 为空） | 跳过（顶层 dimensions 为空） |

### 4.2 场景二：每轮各有不同维度

```json
{
  "rounds": [
    { "evaluation": { "dimensions": [{"id": 1}] } },
    { "evaluation": { "dimensions": [{"id": 2}] } }
  ],
  "dimensions": [{"id": 3}]
}
```

| 轮次 | 修改前 | 修改后 |
|------|--------|--------|
| Round 0 | 评估（用维度 1+2+3） | 评估（只用维度 1） |
| Round 1 | 评估（用维度 1+2+3） | 评估（只用维度 2） |
| 整体 | 评估（用维度 1+2+3） | 评估（只用维度 3） |

### 4.3 场景三：只有顶层聚合维度

```json
{
  "rounds": [
    { "evaluation": { "dimensions": [] } },
    { "evaluation": { "dimensions": [] } }
  ],
  "dimensions": [{"id": 1}]
}
```

| 轮次 | 修改前 | 修改后 |
|------|--------|--------|
| Round 0 | 评估（用维度 1） | **跳过**（dimensions 为空） |
| Round 1 | 评估（用维度 1） | **跳过**（dimensions 为空） |
| 整体 | 评估（用维度 1） | 评估（用维度 1） |

## 5. 注意事项

1. `enabled` 开关仍优先生效：若 `enabled` 为 `False`，无论 `dimensions` 是否为空都跳过评估。

2. `dimensions` 为空列表 `[]` 和 `dimensions` 不存在（`None`）行为一致，都会跳过该轮评估。

3. 整体评估不再合并各轮的 dimensions，只认顶层 `config.dimensions`。如果需要在整体评估中使用某轮的维度，需显式配置到顶层 `config.dimensions`。

4. 聚合逻辑（`update_algorithm_result_evaluation` 和 `round_aggregator`）不受影响，仍按 `TestResultDimension` 的 `round_number` 分组聚合。
