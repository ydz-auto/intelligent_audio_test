# 系统健康汇总端点 GET /api/v1/system/health

> 实施卡：INT-787（FEAT 契约 INT-766）｜状态：已落地（2026-10-19）

## 1. 概述

「关于」页版本与服务状态卡真实接线数据源。网关聚合**自身健康 + 认证服务健康**，
返回统一信封；端点**公开无权限**（权限语义同根路径 `/health`）。

- 背景：根路径 `GET /health`（`api_gateway/app.py`）已存在，但 docker/nginx 只反代
  `/api/`、`/socket.io/`、`/ws`，前端无法访问根路径；`auth_service` 的 `/health`
  在独立服务端口 5009，同样不经前端反代。
- 引入本端点后，前端 `fetchSystemHealth`（React 接线侧 `healthApi.ts`，标「待
  INT-766」）即出真实健康数据，状态卡不再降级「检测中」。
- 前端不做改动：本卡仅后端。前端已按本契约等待端点。

## 2. 契约

### 2.1 路径与方法

```
GET /api/v1/system/health
```

- 公开无权限：须在 `api_gateway/middleware.py` `AuthMiddleware.PUBLIC_PATHS` 白名单
  内（否则 AUTH_MODE=prod 强制态下「关于」页匿名访问会被 401）。
- 无请求参数；无鉴权头要求。

### 2.2 响应 schema（统一信封）

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": {
    "gateway": {
      "status": "ok",
      "service": "api_gateway",
      "version": "V9.7.31",
      "database": "intelligent_audio_test"
    },
    "auth": {
      "status": "ok",
      "service": "auth_service"
    }
  }
}
```

| 字段 | 取值来源 | 说明 |
|---|---|---|
| `success` / `code` / `message` | 网关统一信封 `success_response` | `message` 固定 `"ok"`（前端不消费文案） |
| `data.gateway` | 复用根路径 `/health` 口径 | `version = Config.PLATFORM_VERSION`；`database = database_name_of(Config.DATABASE_URL)`（INT-246 库名解析） |
| `data.auth` | 探测 `auth_service` `/health`（HTTP **5009**，勿混 5001 task_service） | 透传下游 `status`/`service` |

### 2.3 auth 探测降级语义（契约必须项②）

`auth_service` 探测失败（连接拒绝 / 超时 / 非 200 / 非 JSON）**不得拖垮整卡**：
返回 **200 信封** + `auth: { "status": "error", "service": "auth_service" }`
（前端映射「异常」徽章）；仅网关自身不可用才整卡失败。

- 探测用 httpx 短超时（`AUTH_PROBE_TIMEOUT_SECONDS = 2`）；
- `trust_env=False`：忽略 Windows 注册表系统代理对 localhost 请求的劫持；
- 探测端口取 `shared/config/service_ports.py` 注册表 `AUTH_SERVICE_HTTP_PORT`（5009），
  主机取 `BaseConfig.AUTH_SERVICE_HOST`（默认 localhost），不硬编码。

## 3. 实现

| 文件 | 说明 |
|---|---|
| `api_gateway/application/services/system_health_service.py` | 应用服务：`_gateway_health()`（网关口径）+ `_probe_auth()`（探测与降级）+ `get_system_health()`（聚合） |

## 4. 验收口径

- 响应符合 §2.2 统一信封；`data.gateway`/`data.auth` 正确聚合。
- AUTH_MODE=prod 强制态下匿名访问 200（非 401）。
- 相关 pytest 通过；改动不破坏既有路由（根 `/health` 行为不变）。
- 前端 `fetchSystemHealth`（`data.gateway` / `data.auth`）与本 schema 完全一致。
