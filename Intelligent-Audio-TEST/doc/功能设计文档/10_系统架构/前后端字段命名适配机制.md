# 前后端字段命名规范适配机制

## 1. 概述

本文档描述了系统中前后端字段命名规范的适配机制，确保前后端数据交互的一致性和规范性。后端采用 Python snake_case 命名规范，前端采用 JavaScript camelCase 命名规范，系统通过自动转换机制实现无缝对接。

## 2. 命名规范定义

### 2.1 后端命名规范

后端 Python 代码采用 snake_case（小写下划线分隔）命名规范，这是 Python 社区的标准命名约定。snake_case 的特点包括：全部使用小写字母，单词之间使用下划线分隔，具有良好的可读性和 Python 风格。

**后端字段命名示例：**
```python
class TaskListItem(APIModel):
    id: int                          # 短字段可保持原样
    name: str
    description: Optional[str] = None
    created_at: Optional[str] = None
    total_cases: Optional[int] = None
    completed_cases: Optional[int] = None
    task_id: str
    error_message: Optional[str] = None
    max_audio_duration: Optional[int] = None
    needs_prompt_audio: Optional[bool] = None
```

### 2.2 前端命名规范

前端 JavaScript/TypeScript 代码采用 camelCase（小驼峰）命名规范，这是 JavaScript 社区的标准命名约定。camelCase 的特点包括：首字母小写，后续单词首字母大写，字母之间无分隔符，与 JavaScript 内置对象方法命名一致。

**前端字段命名示例：**
```typescript
interface TaskListItem {
    id: number;
    name: string;
    description?: string;
    createdAt?: string;
    totalCases?: number;
    completedCases?: number;
    taskId: string;
    errorMessage?: string;
    maxAudioDuration?: number;
    needsPromptAudio?: boolean;
}
```

## 3. 适配机制原理

### 3.1 核心实现

后端通过 Pydantic 的 `alias_generators` 功能实现自动字段名转换。核心配置位于 `backend/schemas/base.py` 文件中，该文件定义了统一的 `APIModel` 基类，所有数据模型都继承自此类。

**核心配置代码：**
```python
from pydantic import BaseModel, ConfigDict
from pydantic.alias_generators import to_camel

class APIModel(BaseModel):
    model_config = ConfigDict(
        alias_generator=to_camel,      # 自动将 snake_case 转换为 camelCase
        populate_by_name=True,          # 支持同时使用两种字段名
        extra="ignore",                 # 忽略额外字段
    )
```

### 3.2 转换规则

系统遵循标准的命名转换规则，将 Python snake_case 自动转换为 JavaScript camelCase。转换规则如下：对于普通单词组合，直接保持小写即可，如 `name` 保持为 `name`；对于多单词组合，将每个单词首字母大写后拼接，如 `task_id` 转换为 `taskId`；对于缩写词，保持全部小写，如 `api_id` 转换为 `apiId`。

**字段名转换对照表：**

| 后端字段（snake_case） | 前端字段（camelCase） |
|------------------------|----------------------|
| `id` | `id` |
| `name` | `name` |
| `task_id` | `taskId` |
| `created_at` | `createdAt` |
| `total_cases` | `totalCases` |
| `completed_cases` | `completedCases` |
| `error_message` | `errorMessage` |
| `max_audio_duration` | `maxAudioDuration` |
| `needs_prompt_audio` | `needsPromptAudio` |
| `app_version` | `appVersion` |
| `serial_number` | `serialNumber` |
| `last_online_at` | `lastOnlineAt` |
| `source_language` | `sourceLanguage` |
| `api_endpoints` | `apiEndpoints` |
| `decimal_places` | `decimalPlaces` |
| `estimated_exec_time` | `estimatedExecTime` |

### 3.3 双向支持

通过 `populate_by_name=True` 配置，后端模型同时支持两种命名方式的字段输入。这一特性带来了显著的便利性：API 请求时可以使用 snake_case 或 camelCase 格式，后端都能正确解析；数据库查询结果使用 snake_case 字段名时能正确映射到模型；代码内部可以自由选择使用哪种命名风格。

### 5.2 请求参数适配

前端发起请求时，如果需要传递 snake_case 格式的参数，可以使用以下方式进行转换。对于简单的参数对象，可以使用手动转换或工具函数；对于复杂对象，建议使用专业的命名转换库。

**请求参数转换示例：**
```typescript
// utils/case-converter.ts
import { snakeCase, camelCase } from 'lodash';

function toSnakeCase<T extends Record<string, any>>(obj: T): Record<string, any> {
    const result: Record<string, any> = {};
    for (const [key, value] of Object.entries(obj)) {
        const snakeKey = snakeCase(key);
        if (value !== undefined && value !== null) {
            if (Array.isArray(value)) {
                result[snakeKey] = value.map(item => 
                    typeof item === 'object' ? toSnakeCase(item) : item
                );
            } else if (typeof value === 'object' && value !== null) {
                result[snakeKey] = toSnakeCase(value);
            } else {
                result[snakeKey] = value;
            }
        }
    }
    return result;
}

function toCamelCase<T extends Record<string, any>>(obj: T): T {
    const result: Record<string, any> = {};
    for (const [key, value] of Object.entries(obj)) {
        const camelKey = camelCase(key);
        if (value !== undefined && value !== null) {
            if (Array.isArray(value)) {
                result[camelKey] = value.map(item =>
                    typeof item === 'object' ? toCamelCase(item) : item
                );
            } else if (typeof value === 'object' && value !== null) {
                result[camelKey] = toCamelCase(value);
            } else {
                result[camelKey] = value;
            }
        }
    }
    return result as T;
}

export { toSnakeCase, toCamelCase };
```

### 5.3 Axios 响应拦截器

配置 Axios 响应拦截器，自动将后端返回的 snake_case 字段转换为 camelCase，减少重复代码。

**响应拦截器配置：**
```typescript
// api/axios.ts
import axios from 'axios';
import { toCamelCase } from '@/utils/case-converter';

const api = axios.create({
    baseURL: import.meta.env.VITE_API_BASE_URL,
    timeout: 30000,
});

api.interceptors.response.use(
    response => {
        const { data } = response;
        if (data && typeof data === 'object') {
            response.data = toCamelCase(data);
        }
        return response;
    },
    error => {
        return Promise.reject(error);
    }
);

export default api;
```

## 7. 最佳实践

### 7.1 后端开发规范

在定义数据模型时应遵循以下规范：所有 API 响应模型必须继承 `APIModel` 基类，确保自动转换生效；字段命名统一使用 snake_case，保持 Python 代码风格一致；对于枚举类型字段，使用字符串类型而非数字类型，提高可读性；Optional 字段应提供合理的默认值，如 `None`、`[]`、`{}` 等；复杂嵌套结构应拆分为独立的模型类，便于复用和维护。

**规范示例：**
```python
# 正确示范
class TaskCaseBrief(APIModel):
    case_id: str
    name: str
    status: Optional[str] = None
    execution_status: Optional[str] = None
    started_at: Optional[str] = None
    completed_at: Optional[str] = None
    duration: Optional[float] = None
    error_message: Optional[str] = None

# 避免的做法
class BadExample(APIModel):  # 未继承基类
    CaseId: str              # 使用 camelCase
    caseId: str              # 混合命名风格
```

### 7.2 前端开发规范

在使用 API 数据时应遵循以下规范：类型定义应与后端 Schema 保持一一对应，确保接口契约一致；组件中使用数据时应直接使用 camelCase 格式，无需手动转换；避免在业务代码中混用 snake_case 和 camelCase，保持命名风格统一；对于新增字段，应在后端 Schema 和前端类型定义中同步添加。

**规范示例：**
```typescript
// 正确示范
const TaskCard: React.FC<{ task: TaskListItem }> = ({ task }) => {
    return (
        <div>
            <h3>{task.name}</h3>
            <span>进度: {task.completedCases}/{task.totalCases}</span>
            <span>状态: {task.status}</span>
        </div>
    );
};

// 避免的做法
const BadComponent: React.FC<{ task: any }> = ({ task }) => {
    return (
        <div>
            {/* 混用命名风格 */}
            <span>{task.created_at}</span>      {/* snake_case */}
            <span>{task.taskStatus}</span>      {/* camelCase */}
        </div>
    );
};
```

### 7.3 特殊情况处理

对于某些特殊场景，需要注意以下处理方式：第三方 API 返回的字段名可能不符合规范，应在数据接收层进行统一转换；数据库字段名可能与 API 字段名不同，应在 ORM 层处理映射关系；WebSocket 推送数据同样遵循 camelCase 转换规则，前后端处理方式一致。

**第三方数据转换示例：**
```python
class ExternalApiResponse(APIModel):
    raw_field_name: str = Field(alias="RawFieldName")
    another_field: int = Field(alias="anotherField")
    
    @property
    def processed_data(self) -> ProcessedData:
        return ProcessedData(
            fieldName=self.raw_field_name,
            count=self.another_field,
        )
```

## 8. 常见问题

### 8.1 字段名转换失败

**问题描述：** 后端返回的某些字段未正确转换为 camelCase。

**排查步骤：** 首先检查字段所在模型是否正确继承自 `APIModel` 基类；然后确认字段定义是否符合 Python 命名规范（snake_case）；最后检查 `populate_by_name` 配置是否生效。

**解决方案：**
```python
# 确保继承 APIModel
class MyModel(APIModel):
    my_field: str          # 正确：snake_case

# 避免
class BadModel(BaseModel): # 未继承 APIModel
    myField: str          # 错误：使用了 camelCase
```

### 8.2 嵌套对象转换

**问题描述：** 嵌套对象中的字段未正确转换。

**解决方案：** 确保嵌套对象类型同样继承自 `APIModel`，Pydantic 会递归处理所有嵌套模型。

```python
class ParentModel(APIModel):
    child: ChildModel      # ChildModel 必须继承 APIModel

class ChildModel(APIModel):
    child_field: str
```

### 8.3 列表项转换

**问题描述：** 数组中的对象字段未正确转换。

**解决方案：** 确保数组项的类型定义正确，数组项同样会被递归转换。

```python
class ParentModel(APIModel):
    items: List[ChildModel]    # ChildModel 必须继承 APIModel
```

## 9. 性能考虑

### 9.1 转换开销

Pydantic 的字段名转换在模型实例化时进行，对于大型数据结构和频繁 API 调用场景，转换开销可能累积。为优化性能，可采取以下措施：对于不需要转换的数据，使用普通字典而非模型类；批量数据处理时，考虑分页或流式处理；复杂查询场景，合理使用缓存减少重复转换。

### 9.2 缓存策略

对于不频繁变化的配置类数据，可在客户端进行缓存，避免重复请求和转换。

```typescript
const configCache = new Map<string, ConfigData>();

async function getCachedConfig(key: string): Promise<ConfigData | null> {
    if (configCache.has(key)) {
        return configCache.get(key)!;
    }
    const data = await fetchConfig(key);
    if (data) {
        configCache.set(key, data);
    }
    return data;
}
```

## 10. 版本兼容性

### 10.1 字段变更策略

当需要修改字段名时，应遵循以下策略确保平滑过渡：在过渡期内同时支持新旧两种字段名；使用 Pydantic 的 `validation_alias` 或 `alias` 参数配置别名；旧字段在新版本中标记为 deprecated 并在文档中说明移除时间。

```python
class ItemModel(APIModel):
    new_name: str = Field(alias="newName")
    old_name: Optional[str] = Field(default=None, alias="oldName")
    
    @computed_field
    @property
    def display_name(self) -> str:
        return self.new_name or self.old_name or ""
```

### 10.2 向后兼容

API 版本管理中应保持字段命名的一致性，避免不同版本使用不同的命名风格。推荐使用 URL 版本控制（如 `/api/v1/`、`/api/v2/`）来区分不同版本的 API。
