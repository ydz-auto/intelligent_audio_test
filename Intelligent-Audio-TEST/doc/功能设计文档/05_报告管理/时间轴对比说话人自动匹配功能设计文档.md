# 时间轴对比说话人自动匹配功能设计文档

## 1. 功能概述

### 1.1 背景问题

在时间轴对比功能中，参考数据（Ground Truth）和算法结果数据中的说话人标记可能不同。例如：
- 参考 RTTM/STM 中标注为 `speaker1`、`speaker2`
- 算法结果中识别为 `speaker4`、`speaker5`

虽然它们在时间轴上是同一个说话人，但因标注时的命名不同，导致无法正确匹配显示。

### 1.2 目标

实现基于时间重叠的最优说话人自动匹配算法，使参考和结果的说话人能够正确对应，提升时间轴对比的可读性。

### 1.3 与 DER 计算的一致性

本功能参考 `pyannote.metrics.diarization.DiarizationErrorRate` 的说话人映射原理，采用**最优分配（Optimal Assignment）**思路，通过计算时间重叠量来确定说话人对应关系。

## 2. 技术方案

### 2.1 核心算法

采用**贪心算法**计算最优说话人映射：

#### 2.1.1 算法流程

```
1. 提取参考数据中的唯一说话人列表: R = [ref_spk1, ref_spk2, ...]
2. 提取结果数据中的唯一说话人列表: S = [res_spk1, res_spk2, ...]
3. 预计算每个说话人的片段集合
4. 计算所有 (ref_spk, res_spk) 组合的重叠时间
5. 按重叠时间降序排序
6. 贪心选择：依次选择重叠时间最大的未匹配组合
```

#### 2.1.2 重叠时间计算

```python
def compute_overlap_time(seg1_list, seg2_list):
    total_overlap = 0
    for seg1 in seg1_list:
        for seg2 in seg2_list:
            overlap_start = max(seg1.start, seg2.start)
            overlap_end = min(seg1.end, seg2.end)
            if overlap_end > overlap_start:
                total_overlap += overlap_end - overlap_start
    return total_overlap
```

#### 2.1.3 贪心选择

```javascript
// 按重叠时间降序排序
overlaps.sort((a, b) => b.overlapTime - a.overlapTime);

// 贪心选择
const speakerMapping = {};
const usedRef = new Set();
const usedRes = new Set();

for (const { refSpk, resSpk, overlapTime } of overlaps) {
    if (!usedRef.has(refSpk) && !usedRes.has(resSpk) && overlapTime > 0) {
        speakerMapping[refSpk] = resSpk;
        usedRef.add(refSpk);
        usedRes.add(resSpk);
    }
}
```

### 2.2 性能优化

#### 2.2.1 预计算说话人片段

在计算重叠时间前，先将片段按说话人分组，避免重复过滤：

```javascript
const refSegsMap = {};
for (const spk of refSpeakers) {
    refSegsMap[spk] = referenceSegments.filter(s => s.speaker === spk);
}
```

#### 2.2.2 使用 computed 缓存

将说话人映射结果缓存为 Vue computed 属性，避免重复计算：

```javascript
speakerMapping() {
    const refData = this.cachedReferenceData || [];
    const resData = this.cachedResultData || [];
    return this.computeOptimalSpeakerMapping(refData, resData);
}
```

#### 2.2.3 边界情况处理

- 参考或结果为空时，返回空映射 `{}`
- 只有一个说话人时，直接返回一对一映射
- 重叠时间为0时，不建立映射关系

#### 4.2.2 模板中使用映射

#### 4.2.3 匹配片段时使用映射

```javascript
isMatchSegment(speaker, seg) {
    const mappedSpeaker = this.speakerMapping[speaker];
    if (!mappedSpeaker) return false;
    
    const resData = this.cachedResultData || [];
    const resSegments = resData.filter(s => s.speaker === mappedSpeaker);
    
    const tolerance = 0.5;
    return resSegments.some(resSeg =>
        Math.abs(resSeg.start - seg.start) < tolerance &&
        Math.abs(resSeg.end - seg.end) < tolerance
    );
}
```

## 5. 边界情况处理

### 5.1 数据为空

当参考数据或结果数据为空时，返回空映射对象：

```javascript
if (refSpeakers.length === 0 || resSpeakers.length === 0) {
    return {};
}
```

### 5.2 单一说话人

当只有唯一一个说话人时，直接返回一对一映射：

```javascript
if (refSpeakers.length === 1 && resSpeakers.length === 1) {
    return { [refSpeakers[0]]: resSpeakers[0] };
}
```

### 5.3 无重叠

当没有任何重叠时间（overlapTime === 0）时，不建立映射关系，结果该说话人将无法匹配到对应的结果片段。

### 5.4 说话人数量不一致

当参考和结果中的说话人数量不同时，贪心算法会选择重叠时间最大的组合进行匹配，未匹配到的说话人将显示在时间轴上但没有匹配结果。

## 7. 性能考量

### 7.1 时间复杂度

- 假设参考中有 R 个唯一说话人，结果中有 S 个唯一说话人
- 片段预过滤：O(N) 其中 N 为总片段数
- 重叠时间计算：O(R × S × M × N) 其中 M,N 为每个说话人的平均片段数
- 贪心选择：O(R × S × log(R × S))

### 7.2 空间复杂度

- 预计算的片段映射：O(N)
- 重叠时间矩阵：O(R × S)

### 7.3 优化建议

1. **数据量很大时**：可以限制每个说话人的最大片段数，或者使用采样方式计算
2. **实时性要求高时**：可以将映射结果缓存，只在数据变化时重新计算
3. **支持手动映射**：提供 UI 让用户可以手动调整映射关系，作为自动映射的补充

## 8. 后续优化建议

### 8.1 支持手动映射

- 在 UI 上提供手动映射配置
- 手动映射优先级高于自动映射
- 支持保存映射配置

### 8.2 显示映射置信度

- 显示映射的重叠时间占比
- 帮助用户判断映射可靠性

### 8.3 匈牙利算法替代

当前使用贪心算法，理论上可以进一步使用匈牙利算法（Hungarian Algorithm）获得全局最优解，但考虑到：
1. 贪心算法在大多数场景下已经能获得很好的结果
2. 匈牙利算法复杂度较高
3. 前端性能考虑

当前方案选择贪心算法，如需更高精度可以升级为匈牙利算法。
