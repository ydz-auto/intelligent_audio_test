# 报告轮次数据修复文档

## 问题描述

在多轮测试场景中，报告用例卡片的执行结果（algorithm_results）和评估结果（metrics）存在轮次数据不一致的问题：

1. **评估结果（metrics）轮次编号正确**：来自 `TestResultDimension.round_number`，构建为 `{dim_name}@round:{rn+1}`
2. **执行结果（algorithm_results）轮次编号缺失**：当 `result_data` 中存在预提取的 `algorithm_results` 快照时，报告生成直接使用快照数据并跳过 `build_algorithm_results_for_result`，导致快照中的评估结果字段没有 `@round:N` 后缀和 `round_number`

## 根因分析

### 数据流

```
评估完成 → _build_and_store_algorithm_results() → 调用 build_algorithm_results_for_result()
    → 生成 algorithm_results 快照 → 存入 test_results.result_data['algorithm_results']

报告生成 → _build_case_data()
    → 读取 result_data['algorithm_results'] 快照
    → 如果快照存在：直接 extend + continue（跳过 build_algorithm_results_for_result）
```

### 问题所在

`report_controller_task.py` 第 358-361 行（修复前）：

```python
snapshot = result_data.get('algorithm_results') if result_data else None
if snapshot:
    case_obj["algorithm_results"].extend(snapshot)
    continue  # 直接跳过，不经过轮次标记逻辑
```

快照是在评估完成时生成的。如果快照生成时 `build_algorithm_results_for_result` 的代码版本较旧（没有轮次标记逻辑），快照中的评估结果字段就没有 `@round:N` 后缀。报告生成时直接使用快照，导致轮次标记缺失。

## 修复方案

在报告生成读取快照时，对快照中的评估结果字段动态注入轮次标记。

### 修改文件

`backend/controllers/report_controller_task.py`，`_build_case_data` 方法中快照处理逻辑。

### 修复代码逻辑

```python
snapshot = result_data.get('algorithm_results') if result_data else None
if snapshot:
    # 对快照注入轮次标记
    result_dims = dim_results_map.get(result.id, [])
    is_multi_round = any(getattr(dr, 'round_number', None) is not None for dr in result_dims)
    if is_multi_round:
        # 1. 构建 dimension_id → round_number 映射
        dim_id_to_round = {}
        for dr in result_dims:
            dim_id = getattr(dr, 'dimension_id', None)
            rn = getattr(dr, 'round_number', None)
            if dim_id is not None and dim_id not in dim_id_to_round:
                dim_id_to_round[dim_id] = rn

        # 2. 构建 param_code → dimension_id 映射
        param_to_dim_id = {}
        for _dim_id, aux_list in aux_params_map.items():
            for aux_info in aux_list:
                p = aux_info['param']
                param_to_dim_id[p.param_code] = _dim_id

        # 3. 遍历快照，给有 dimension_name 但没有轮次标记的字段注入 @round:N
        for item in snapshot:
            if not isinstance(item, dict):
                continue
            pc = item.get('param_code') or item.get('paramCode') or ''
            # 已有轮次标记的跳过
            if '@round:' in pc or '@overall' in pc:
                continue
            dim_name = item.get('dimension_name')
            if not dim_name:
                continue
            # 通过 param_code 查 dimension_id，再查 round_number
            did = param_to_dim_id.get(pc)
            rn = dim_id_to_round.get(did)
            if rn is not None:
                new_pc = f'{pc}@round:{rn + 1}'
                item['param_code'] = new_pc
                item['label'] = f'{pc} (第{rn + 1}轮)'
                item['round_number'] = rn + 1
            else:
                new_pc = f'{pc}@overall'
                item['param_code'] = new_pc
                item['label'] = f'{pc} (整体)'

    case_obj["algorithm_results"].extend(snapshot)
    continue
```

### 轮次编号规则

| 场景 | TRD round_number | metric/param_code 后缀 | round_number 字段 |
|------|-----------------|----------------------|------------------|
| 多轮-具体轮 | 0 | `@round:1` | 1 |
| 多轮-具体轮 | 1 | `@round:2` | 2 |
| 多轮-汇总 | None | `@overall` | None |
| 单轮 | 任意 | 无后缀 | — |

## 验证结果

以任务320（豆包pcmE2E测试，2轮，只评估第2轮）的 B-IS-002 用例为例：

### 评估结果（metrics）

修复前：11 条，无轮次后缀
修复后：11 条，全部正确标记

```
metric=打断恢复时延@round:2, value=None, rn=1
metric=打断成功率@round:2, value=0.0, rn=1
metric=平均连贯性@round:2, value=0.0, rn=1
...
```

### 执行结果（algorithm_results）

修复前：43 条，全部无轮次后缀（`rn=None`）
修复后：43 条，42 条带 `@round:2` 后缀（`rn=2`），1 条 plain

```
param_code=avg_overlap_s@round:2, dim=打断恢复时延, rn=2, value=4295.0
param_code=interruption_resume_rate@round:2, dim=打断成功率, rn=2, value=0.0
...
```

## 涉及文件

| 文件 | 说明 |
|------|------|
| `backend/controllers/report_controller_task.py` | `_build_case_data` 方法，快照轮次注入逻辑 |
| `backend/services/evaluation/evaluation_result_processor.py` | `_build_and_store_algorithm_results`，快照生成入口 |

## 注意事项

- 此修复为**读取时动态注入**，不修改 `result_data` 中的原始快照数据
- 重新评估会生成新快照，新快照走修复后的 `build_algorithm_results_for_result`，直接就是正确数据
- 重新生成报告不会修改快照，但会动态注入轮次标记，因此历史数据也能正确显示
