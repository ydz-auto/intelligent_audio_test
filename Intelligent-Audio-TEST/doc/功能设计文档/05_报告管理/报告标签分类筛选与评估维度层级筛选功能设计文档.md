# 标签分类筛选与评估维度层级筛选（全页面）功能设计文档

## 1. 文档说明

### 1.1 目标

系统中「标签筛选」与「评估维度筛选」目前多为**平铺展示**：标签没有分类维度、评估维度没有「分类 → 主维度 → 子维度」层级。本功能为**所有涉及这两类筛选的页面**补齐结构化能力，并统一交互：

1. **标签筛选**：标签按「标签分类」分组/筛选（复用全局标签体系的 `TagCategory`，不新增数据模型）。
2. **评估维度筛选**：维度按「分类 → 主维度 → 子维度」层级展示与筛选（复用评估维度体系的 `Category` / `Dimension`，不新增数据模型）。

> **边界说明**：标签「等级」字段本期不做；标签不做第三级主/子结构（保持「分类 → 标签」两级）；不改标签管理页、不改数据库表结构。

## 2. 现状分析

### 2.1 标签体系现状

全局标签已具备「分类」两级结构：

- 表 `tag_categories`（[TagCategory](../../../backend/models/models.py)）：`name / description / color / sort_order`。
- 表 `tags`（[Tag](../../../backend/models/models.py)）：`name / description / color / category_id`（外键 → `tag_categories.id`）。

相关接口（已存在，本期直接复用）：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/tags/categories` | 标签分类列表（分页、关键字） |
| `GET /api/v1/tags/by-category` | 按分类返回分类及其下标签列表 |

### 2.2 评估维度体系现状

评估维度具备三级结构（[Dimension](../../../backend/models/models.py)）：

- `categories` 表：分类（如 准确性、流畅度、响应速度）。
- `dimensions` 表：`category_id`（所属分类）、`dimension_type`（`main` 主维度 / `sub` 子维度）、`parent_dimension_id`（主维度 ID）、`parent_dimension_name`（主维度名，冗余）。

相关接口（已存在，本期直接复用）：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/evaluation/dimensions/options` | 维度选项列表，含 `category_id / dimension_type / parent_dimension_id / parent_dimension_name` |
| `GET /api/v1/evaluation/categories` | 评估分类列表 |

> 评估维度管理页（`Evaluation.vue`）的「分组视图」已经是「按分类聚合、分类内保留主/子维度层级」的实现，可作为本期交互与样式的一致性参考。

## 3. 功能设计总览

### 3.1 统一策略

为避免 5 个页面各自重复实现，抽取**两个可复用前端组件** + **两个 composable**：

| 复用件 | 能力 |
| --- | --- |
| `TagCategorySelector.vue` | 标签分类选择条 + 按分类过滤的标签云（slot 内嵌到各页面筛选区） |
| `useTagCategoryFilter.ts` | 加载分类、构建「分类 → 标签名」映射、选中分类状态、过滤逻辑 |
| `DimensionTreeSelector.vue` | 维度分类选择条 + 「主维度 → 子维度」树（勾主自动带子，输出叶子维度名） |
| `useDimensionHierarchy.ts` | 加载维度对象、按维度名匹配报告数据、构建「分类 → 主 → 子」树、勾选展开逻辑 |

各页面接入方式一致：

```
[标签分类选择条]  → 选中分类 → 过滤标签云 + 把分类展开为标签集合参与筛选
[维度分类选择条]  → 选中分类 → 只显示该分类维度 + 勾选主维度自动带子维度 → 叶子维度名参与筛选
```

### 3.2 后端改动原则

- 报告用例筛选接口（`searchCases` / `case-averages`）新增 `tagCategoryId` 参数，由后端解析分类下标签名集合并过滤。
- 其余页面（用例列表、音频导入）数据已在本地，**分类展开为标签集合的过滤在前端完成，无需后端改动**。

## 4. 界面与交互设计

### 4.1 标签分类筛选（统一样式）

改造前：

```
用例标签 (已选 0 个)
标签云：嘈杂(12) 多人(8) 安静(5) 街道(3) ...
```

改造后：

```
用例标签 (已选 0 个)
[全部] [人数] [场景] [语种] [环境] ...        ← 标签分类选择条
[搜索标签...]
标签云：嘈杂(12) 多人(8) 安静(5) ...          ← 只显示当前分类下的标签
```

交互规则：

1. 默认「全部」：标签云平铺显示所有标签，行为与现状一致。
2. 点击某分类：标签云仅显示该分类下的标签；清空不属于该分类的已选标签；筛选条件按「用例标签命中该分类任一标签」生效。
3. 分类范围内继续点选标签做精确过滤（多选 OR 语义，与现状一致）。
4. 点「全部」或「重置」：分类回全部、标签清空。

**页面差异说明**：

| 页面 | 筛选执行方 | 说明 |
| --- | --- | --- |
| 报告详情 3 组件 | 后端 | 请求带 `tagCategoryId` |
| 用例列表卡片页 | 前端 | 选中分类 → 展开为该分类标签集合，参与本地 `tagFilter` 匹配 |
| 音频导入页 | 前端 | 选中分类 → 展开为标签集合参与本地过滤 |

### 4.2 评估维度层级筛选（统一样式）

改造前：

```
评估维度 (已选 0 个)
维度云：WER(12) BLEU(8) ROUGE-L(5) 语速(3) ...
```

改造后：

```
评估维度 (已选 0 个)
[全部] [准确性] [流畅度] [响应速度] ...        ← 维度分类选择条
[搜索评估维度...]
▼ 准确性
    ☐ 语义相似度（主）
       ☐ BLEU（子）  ☐ ROUGE-L（子）
    ☐ 字准率 WER（主，无子维度）
▼ 流畅度
    ☐ 语速（主）
       ☐ 停顿次数（子）
```

交互规则：

1. 分类选择条：点某分类只显示该分类下维度；点「全部」显示所有。
2. 主维度可折叠/展开；带子维度的主维度作为分组展示。
3. **勾选主维度 = 自动勾选其下全部子维度**（主维度为聚合语义，已确认 A 方案）；也可单独勾选子维度。
4. 勾选后把**叶子维度名**（子维度 / 无子维度的主维度）作为筛选条件：报告详情传后端 `metrics`；本地页面做本地匹配。
5. 只展示页面实际用到的维度（报告详情沿用 `usedMetricNames` 过滤；用例列表沿用现有 `dimensionFilterOptions` 数据范围）。
6. 重置：分类回「全部」，维度勾选清空。

## 5. 后端设计

### 5.1 请求 Schema 变更（`backend/schemas/report.py`）

`ReportSearchCasesRequest` 与 `GetCaseAveragesRequest` 均新增字段：

```python
tag_category_id: Optional[int] = Field(
    None,
    alias='tagCategoryId',
    validation_alias=AliasChoices('tag_category_id', 'tagCategoryId'),
)
```

### 5.2 `search_report_cases`（`backend/controllers/report_controller_base.py`）

1. 解析 `tagCategoryId`。
2. 存在时查询 `Tag` 表获取该分类下全部标签名集合 `S`（分类不存在或为空时按无命中处理）。
3. 过滤条件：用例 `ReportCase.tags` 命中 `S` 中任一标签名即匹配（与现有 `tags` 多选 OR 语义一致）。
4. 与现有 `tags` 参数合并为同一个 OR 条件集合。
5. `include_untagged` 逻辑不变：未勾选标签且未指定分类时才筛「无标签」用例。

新增辅助方法：

```python
@staticmethod
def _resolve_category_tag_names(tag_category_id):
    """解析标签分类ID → 该分类下所有标签名列表；分类不存在或为空返回 None"""
    if not tag_category_id:
        return None
    cat = db.session.get(TagCategory, tag_category_id)
    if not cat:
        return None
    names = [t.name for t in Tag.query.filter_by(category_id=cat.id).all()]
    return names or None
```

### 5.3 `get_case_averages_by_filters`（`backend/controllers/report_controller.py`）

- 解析 `tagCategoryId` 为标签名集合 `S`。
- `_query_test_cases_and_results` 增加 `tag_category_id` 参数：
  - 将 `S` 与已选 `tags` 合并为一个名称集合；
  - `include_untagged=False` 时：`TestCase.tags` 命中任一标签即匹配（`Tag.name.in_(S ∪ tags)`）；
  - `include_untagged=True` 时：命中任一标签 **或** 无标签 均匹配（沿用现状 OR 逻辑）。

### 5.4 接口参数汇总

| 接口 | 方法 | 新增参数 | 语义 |
| --- | --- | --- | --- |
| `/api/v1/reports/<id>/cases/search` | POST | `tagCategoryId` | 用例标签命中该分类下任一标签名 |
| `/api/v1/reports/case-averages` | POST | `tagCategoryId` | 用例标签命中该分类下任一标签名 |

## 6. 前端设计

### 6.1 数据来源（统一）

| 数据 | 接口（前端封装） | 用途 |
| --- | --- | --- |
| 标签分类列表 | `api.tags.getCategories({ page: 1, per_page: 1000 })` | 分类选择条选项 |
| 分类 → 标签名映射 | `api.tags.getTagsByCategory()` | 选中分类后过滤标签云 |
| 维度全量对象 | `evaluationApi.getOptions()` | 维度名 → 分类/主/子关系映射 |
| 评估分类列表 | `evaluationApi.getCategories()` | 维度分类选择条选项 |

### 6.2 新增可复用件

- `frontend/src/components/common/TagCategorySelector.vue`：props 接收 `allTags`（标签名数组），内部加载分类数据，emit `update:categoryId` / `update:selectedTags`，内部处理搜索与分页。
- `frontend/src/composables/useTagCategoryFilter.ts`：`{ tagCategories, tagCategoryNamesMap, selectedCategoryId, filteredTags, selectCategory, reset }`。
- `frontend/src/components/common/DimensionTreeSelector.vue`：props 接收 `allMetrics`（`{name, unit}` 数组），内部加载维度层级数据并按 base 名匹配，emit `update:selectedMetricNames`（叶子维度名数组）。
- `frontend/src/composables/useDimensionHierarchy.ts`：`{ dimensionCategories, dimensionMap, tree, selectedCategoryId, selectedMetricNames, toggleMetric, toggleParent, reset }`。

维度名匹配规则：报告/用例中的指标名可能是 `维度@round:N` / `维度@overall`（多轮场景），匹配时剥离 `@` 后缀取 base 名再与维度对象对齐。

### 6.3 各页面接入点

| 页面/组件 | 标签接入 | 维度接入 |
| --- | --- | --- |
| `SpecificCaseComparisonComponent.vue` | 筛选区插入 `TagCategorySelector`；请求带 `tagCategoryId` | 维度云换 `DimensionTreeSelector`；`metrics` 传叶子维度名 |
| `CaseCategoryComparisonComponent.vue` | 同上（`applyFilters` 的 `searchCases` / `getCaseAveragesByFilters` 带 `tagCategoryId`） | 同上 |

| `TestCaseListContainer.vue` | `BadgeFilter` 标签下拉改为「分类 → 标签」两级；标签视图可加分类分组头 | `BadgeFilter` 维度下拉选项按分类分组 |
| `AudioImport.vue` | 标签筛选组件内嵌 `TagCategorySelector` 逻辑，选中分类展开为标签集合本地过滤 | 无 |

### 6.4 不改动项

- 标签管理页 `TagManagement.vue` 不改。
- 评估维度管理页 `Evaluation.vue` 不改（已是参考实现）。
- 用例配置模态窗 `DimensionConfigPanel.vue` 不改。
- 路由、数据库表结构不加字段/表。
- 后端 `metrics` 过滤语义（OR contains）维持现状。

## 7. 边界情况

| 场景 | 处理 |
| --- | --- |
| 标签分类下无标签 | 选择该分类时标签云为空并显示「暂无可用的用例标签」，筛选结果为空属正常 |
| 报告中的标签名不在全局标签库（历史数据/已删除标签） | 归入「全部」下正常显示；选中某分类时不显示 |
| 维度名在维度管理接口中不存在（历史/已删除维度） | 归入「全部」，不参与分类分组，但仍可单独勾选过滤 |
| 多轮指标名带 `@round:N` / `@overall` 后缀 | 按 base 名匹配维度树；勾选后传给后端的过滤名与现状保持一致 |
| 主维度自身无值（仅子维度有值） | 勾选主维度自动带子维度，不会筛空（方案 A） |
| 分类/维度选项数据量大 | 沿用各页面现有搜索/分页交互，不额外做虚拟滚动 |
| 本地过滤页面（用例列表/音频导入） | 分类选择仅影响候选集合与选中状态，不改变数据加载 |

## 8. 测试要点

1. 标签：分类选择条切换 → 标签云变化、筛选结果变化、重置恢复（报告 3 组件 + 用例列表 + 音频导入各验一遍）。
2. 标签：先选标签再切分类 → 不属于该分类的已选标签被清空。
3. 维度：分类选择条切换 → 只显示该分类维度（报告 3 组件 + 用例列表）。
4. 维度：勾选主维度 → 其全部子维度自动选中；单独勾选子维度正常。
5. 维度：多轮报告（`@round:N` 后缀）下维度筛选不误伤、可正确匹配 base 名。
6. 组合筛选：分类 + 标签 + 维度 + 关键字同时生效（AND 关系）。
7. 回归：不选任何筛选时各页面行为与改造前完全一致。
