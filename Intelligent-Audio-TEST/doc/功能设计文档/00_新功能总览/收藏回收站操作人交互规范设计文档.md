# 收藏 / 回收站 / 操作人交互规范设计文档（任务 · 报告 · 用例）

## 1. 文档说明

### 1.1 目标与定位

收藏星标、回收站（软删除）、操作人（删除人/删除时间）展示是 V9.7.31 新增的跨模块前端能力（INT-141 实现），覆盖任务 / 报告 / 用例三个列表视图。本文档以**修复验收后的终态实现**为基准（INT-215 全量 UX 修复 + INT-219 报告侧后端字段补齐），回写三视图的统一交互口径，作为后续方案一致性审计与新增列表页开发的对照基准。

覆盖范围：

- 回收站入口、行内星标、收藏筛选、单项/批量恢复、彻底删除（purge）二次确认；
- 回收站条目信息展示：删除人 / 删除时间（含 AUTH_MODE=off 空态）、「已删除」徽章；
- 操作反馈口径：判真规则与通知通道。

> **边界说明**：本文档只约束收藏 / 回收站 / 操作人三类交互；各视图其余列表能力（筛选、排序、分页、批量对比等）见各域功能设计文档。不新增数据模型（复用各实体 `deleted / deleted_at / deleted_by_user_id` 列与 `favorites` 表）。

## 2. 核心概念与角色权限

| 概念 | 定义 |
| --- | --- |
| 收藏 | per-user 星标。`user_id` 由后端从 JWT 解析，前端不传；重复收藏/取消幂等（返回 `already_favorited`）。AUTH_MODE=off 时为未收藏语义。 |
| 回收站 | 软删除集合。列表以专用参数拉取（任务 `deleted=true` / 报告 `deleted=true` / 用例 `only_deleted=true`），条目可恢复或彻底删除。 |
| 恢复（restore） | 可逆操作，把软删条目置回活跃集合；**不设二次确认**（唯一例外：用例「全部恢复」，见 §5.3）。 |
| 彻底删除（purge） | **物理删除，不可恢复**；服务端逐行校验 admin/owner（`filter_purgeable_owners`，无整批放行），非授权用户 purge 计数为 0 且有可见反馈。 |
| 删除人 / 删除时间 | `deleted_by_user_id` / `deleted_at`，软删时由后端写入；AUTH_MODE=off（无用户体系）时 `deleted_by_user_id` 为 NULL。 |

## 3. 统一交互口径

三视图共享一个通用工具栏组件与四组范式；新增列表页必须对齐，禁止回到视图内自制口径。

### 3.1 收藏 / 回收站工具栏（`FavoriteTrashBar`）

- 组件：`frontend/src/components/common/FavoriteTrashBar.vue`（common，三视图复用；INT-215 收敛此前三份复制的样式块与任务侧裸 checkbox 口径）。
- 三枚 bar-toggle 控件（按钮式开关，active 态主色描边+着色；禁用态半透明 + not-allowed 光标）：

| 控件 | 图标 | 行为 | 备注 |
| --- | --- | --- | --- |
| 仅看收藏 | `fas fa-star`（amber 着色） | 切换 `favoriteOnly`，列表按当前用户收藏过滤 | 回收站态禁用；title「仅显示我收藏的项目」 |
| 回收站 | `fas fa-trash-restore` | 切换 `trashMode`，进入/退出已删集合 | title「回收站：已删除项目，可恢复或彻底删除」 |
| 全部恢复 | `fas fa-undo` | 恢复当前回收站全部（后端圈定，见 §5.3） | **仅用例视图启用**（`showRestoreAll`），title「恢复回收站中的全部用例」 |

- 回收站入口统一为工具栏按钮。任务侧原「状态徽章筛选项：已删除（回收站）」已移除（INT-215 P6）；任务侧数据承载仍为 `filters.status='deleted'`（批量按钮可见性等既有逻辑不变），对上层暴露 `taskTrashMode` 计算属性。

### 3.2 行内星标

| 项 | 口径 |
| --- | --- |
| 图标 | 收藏态 `fas fa-star`（实心）/ 未收藏 `far fa-star`（空心），**按行动态生成**，禁止恒定图标 |
| 着色 | 收藏态 `color: var(--favorite-star)`（`tokens.css`：`--favorite-star: var(--color-amber-500)`）；未收藏不着色。禁止硬编码魔法色（INT-215 P7 已清除历史 `#f5a623`） |
| 标题 | 按行切换「收藏 / 取消收藏」 |
| 状态源 | 任务 / 报告：`useFavorites` 收藏集合驱动（`isFavorite(id)`）；用例：行级 `isFavorite` 驱动，切换后 `patchTestCaseFavorite` 就地回写、星标即时可见（无需整表重拉） |
| 位置 | 任务 / 报告 = 卡片操作区行内按钮；用例 = 卡片 actions 星标项（actions 工厂函数按行求值，`TestCaseCard` 支持函数型 `iconClass/iconStyle`） |
| 防抖 | 同一行切换进行中（`pendingIds`）时忽略重复点击 |
| 回收站态 | 星标动作隐藏（三视图一致）——已删集合不提供收藏入口 |

### 3.3 收藏筛选 × 回收站互斥

- 进入回收站时若「仅看收藏」为勾选态，**自动清空勾选**；回收站态下收藏开关禁用（组件 `favoriteDisabled`）。
- 收藏过滤参数仅在实际生效时发送（三视图统一：`favoriteOnly && !trashMode` 才携带 `favorite`），禁止「勾选亮着但请求静默失效」的实现（INT-215 前的历史缺陷）。

### 3.4 确认弹窗范式（BASIC_CONFIRM）

- 危险操作确认统一走 `MODAL_TYPES.BASIC_CONFIRM` 自定义模态（`GlobalModalContainer` → `ModalConfirm`），禁止 `window.confirm`（全站范式，INT-215 P4 收敛 5 处历史回退）。
- purge 类确认统一 `danger: true`（红色确认键 + 危险图标）。
- 单项文案模板：

  > 彻底删除{实体}「{名称}」？该操作不可恢复（仅管理员/所有者可执行）。
  > confirmText=`彻底删除`，cancelText=`取消`

- 批量文案模板：`彻底删除选中的 {N} 个{实体}？该操作不可恢复（仅管理员/所有者可执行）。`
- 恢复为可逆操作不设确认；唯一例外为用例「全部恢复」——需向用户展示圈定数量（`恢复回收站中的全部 {N} 个用例？`，非 danger）。
- 用户取消（resolve false / reject）均静默返回，不发起请求。

### 3.5 操作反馈口径

判真规则（三视图统一）：**恢复按后端返回 `restored_count`、彻底删除按 `purged_count` 判定真实结果**；禁止未校验 count 直接报成功（假成功反馈为 INT-215 P1 修复项）。

| 场景 | 反馈 |
| --- | --- |
| count > 0 | success：「已恢复 N 个…」/「{实体}「名称」已恢复」/「已彻底删除 N 个…」 |
| count = 0 | info：「无可恢复项（…可能已被恢复）」/「无可删除项（…可能已被删除或不满足权限）」——非 admin purge 403 由此对用户可见 |
| 请求失败 | error：「恢复 / 彻底删除 / 收藏操作失败: …」 |
| 收藏切换成功 | success：「已收藏 / 已取消收藏」（按切换后的收藏态文案） |
| `loadFavorites` 失败 | warning：「收藏状态加载失败，星标状态可能不准确」（禁止静默降级为空集合，INT-215 P5） |
| 用例全部恢复圈定失败 / 为空 | error「获取回收站用例失败…」/ info「回收站为空」 |

通知通道（既有差异，如实记录）：

- 任务 / 用例：全局 `useNotification`（`composables/modal/useNotification.ts`，success/error/warning/info/info 五级）。
- 报告：页内 toast（3 秒自动消退；Teleport 到 `#global-fixed-elements`，避免 `fixed` 包含块随页面滚动截获）。反馈类型与判真口径与上表一致。
- 通道差异不阻塞验收；收敛为单一通道属可选迭代项（见 §8.2）。

## 4. API 与数据契约

### 4.1 操作端点（`frontend/src/infrastructure/api/favoritesApi.ts`）

| 操作 | 端点 | 返回 |
| --- | --- | --- |
| 收藏 | `POST /{entityType}s/{id}/favorite` | `already_favorited`（幂等） |
| 取消收藏 | `DELETE /{entityType}s/{id}/favorite` | 幂等 |
| 收藏集合 | `GET /favorites?entity_type={type}` | `{ task: id[], report: id[], testcase: id[] }` |
| 恢复 | `POST /{entityType}s/restore`，body `{ ids }` | `{ restored_count }` |
| 彻底删除 | `POST /{entityType}s/purge`，body `{ ids }` | `{ purged_count }`（服务端 admin/owner 校验） |

`entityType ∈ task | report | testcase`；`ids` 传单个即单项操作、多个即批量。任务批量恢复/批量删除走既有 `tasksPort.batchAction` 通道（见 §5.1）。

### 4.2 列表过滤参数（snake_case 转换收敛在 Infrastructure 层）

| 视图 | 收藏过滤 | 回收站过滤 | 承载 |
| --- | --- | --- | --- |
| 任务 | `favorite=true`（同名透传） | `deleted=true` | `filters.status='deleted'` → `params.deleted`（`useTaskList`） |
| 报告 | `favorite=true` | `deleted=true` | `trashMode` ref（`loadReports`） |
| 用例 | `favorite=true` | `only_deleted=true` | `trashMode` ref → `currentFetchExtra()` 统一注入分组/标签两视图（`QUERY_PARAM_MAP: onlyDeleted → only_deleted`） |

- 用例圈定接口 `POST /testcases/ids`（`fetchCaseIdsByFilter`）：回收站态必须传 `onlyDeleted=true`，使全选 / 全部恢复的圈定口径与可见数据一致；普通态**不发送**该参数（wire 契约由 `testcasesApi.trashView.spec.ts` 锁定）。`algorithm_type / dimension_id` 一并透传（INT-215 P2/P2-R1：修复前服务层静默丢弃两参数，导致全部恢复/起跑圈定范围错误）。

### 4.3 回收站条目字段（前端 camelCase Domain）

| 字段 | 后端列 | 语义 |
| --- | --- | --- |
| `deleted` | `deleted` | 软删标记（驱动「已删除」徽章 / 删除信息 meta 显示） |
| `deletedAt` | `deleted_at` | 删除时间 |
| `deletedByUserId` | `deleted_by_user_id` | 删除人用户 id；AUTH_MODE=off 为 NULL |
| `isFavorite` | `is_favorite` | 用例链路行级消费；报告 DTO 契约声明（INT-219）；任务 / 报告星标态由收藏集合驱动，不依赖行级字段 |

三实体字段映射（DTO→Domain→adapter）由 `trashFieldsMapping.spec.ts`（8 例）锁定。`GET /tasks`、`GET /reports`、`GET /testcases`（含 `view=tag` 标签视图）列表响应均含上述字段。

## 5. 三视图交互规格

### 5.1 任务（Tasks）

| 环节 | 规格 |
| --- | --- |
| 回收站入口 | 工具栏「回收站」按钮（状态徽章筛选项已移除）；统计面板保留「已删除」计数卡 |
| 卡片动作 | 回收站态追加「恢复」（`fa-undo`，success）/「彻底删除」（`fa-fire`，danger），动作项仅回收站态显示；星标动作回收站态隐藏；普通态保留既有动作 + 行内星标 |
| 单项恢复 | `restored_count` 判真 →「任务「名称」已恢复」（P6 补齐单项恢复） |
| 批量 | 批量栏常驻（批量删除/任务对比/合并任务/导出数据）+ 回收站态追加「批量恢复」（`fa-undo`）/「批量彻底删除」（`fa-fire`，二者仅 `filters.status==='deleted'` 可见）；批量彻底删除走 BASIC_CONFIRM danger，成功后清空选中集 |
| 已删除标识 | **TaskCard 回收站态以「已删除」徽章（`fa-trash` + destructive 色）替代原状态徽章**（checkbox / 无 checkbox 双布局一致） |
| 删除信息 | 卡片 meta 追加「删除时间 / 删除人」胶囊（仅 `deleted=true` 显示） |
| 选中集 | 进出回收站清空选中集（防普通态勾选的活跃任务流入回收站态批量彻底删除，S4 同口径） |
| 已知差异 | 批量栏的对比/合并/导出在回收站态未屏蔽；批量恢复走既有 `batchAction('restore')` 通道、无 count 反馈（见 §8.2） |

### 5.2 报告（HistoryReports）

| 环节 | 规格 |
| --- | --- |
| 回收站入口 | 工具栏「回收站」按钮 |
| 卡片动作 | 二态模板：普通态 = 星标 / 查看 / 编辑 / 删除 / 发布(草稿)；回收站态 = 「恢复」（success）/「彻底删除」（danger） |
| 批量栏 | 二态模板（S4）：普通态 = 批量对比 / 批量删除；回收站态 = **批量恢复 / 批量彻底删除**（按钮带选中计数）——对已删报告屏蔽对比/删除这两类 no-op 按钮 |
| 确认 | 批量彻底删除 = BASIC_CONFIRM danger + 不可恢复/权限警示；批量恢复无确认（可逆），按 `restored_count` 反馈 |
| 删除信息 | 回收站态卡片 meta 追加「删除时间 / 删除人」；**无「已删除」徽章替换**——报告卡保留类型 / 状态标签（草稿/已发布），删除信息以 meta 呈现 |
| Tab / 选中 | 回收站列表在当前 Tab 分区内展示；Tab 切换与进出回收站均清空选中集 |

| 环节 | 规格 |
| --- | --- |
| 回收站入口 | 工具栏「回收站」按钮 +「全部恢复」（`showRestoreAll`） |

| 分页 / 选中 | 容器对 `trashMode` 的 watch：进出回收站重置分组分页 `currentPage=1` 并清空选中集（S3，对照报告侧口径） |

## 6. 操作人 / 删除时间展示规范

| 项 | 口径 |
| --- | --- |
| 显示条件 | 仅 `deleted=true` 的条目（回收站态）显示；三视图一致 |
| 删除时间 | `deletedAt` 经 `formatDate`（默认 `YYYY-MM-DD HH:mm:ss`）；NULL / 空 → 显示「—」 |
| 删除人 | `deletedByUserId` 非空 → `用户 #<id>`；NULL（AUTH_MODE=off 或历史数据）→「—」 |
| 展示形态 | 任务 = meta 胶囊（`fa-calendar-times` / `fa-user-times` 图标，与既有 meta 同容器同样式，nowrap 胶囊流式排布）；报告 = 卡片 meta 行；用例 = 独立 meta 块（`meta-label` 标签）。均为卡片流式布局、无表格列宽概念，溢出由容器换行承载 |
| 数据来源 | 后端 `deleted_at / deleted_by_user_id`（`GET /tasks`、`GET /reports`、`GET /testcases` 列表响应均含；报告侧由 INT-219 `b5d2d9cd` 闭合） |
| 演进项 | 删除人当前展示用户 id 而非用户名（列表响应仅含 user_id）；用户名展示待用户体系统一补字段（INT-215 审计观察项） |

## 7. 架构红线符合性

- **前端只见 camelCase Domain**：`deletedAt / deletedByUserId / isFavorite`；snake_case↔camelCase 转换收敛在 Infrastructure（`favoritesApi.ts` / `testcasesApi.ts` 的 `QUERY_PARAM_MAP` / 三实体 DTO→adapter），由 `trashFieldsMapping.spec.ts`、`testcasesApi.trashView.spec.ts` 锁定契约。
- **端口模式**：视图 / 组合式函数仅经 port / api 模块触达后端（`favoritesApi`、`testcasesPort.getIdsByFilter`），不直连 http 细节。
- **视觉 token 化**：星标色 `--favorite-star`（amber 标度派生），无魔法色；工具栏收敛 `common/FavoriteTrashBar.vue` 单一实现，无复制样式块。
- **CQRS 读侧无副作用**：收藏 / 回收站过滤均为只读查询；命令侧（favorite / restore / purge）独立端点。
- **权限**：`user_id` 从 JWT 解析经出站拦截器注入（`x-user-id`），前端不可伪造；purge 服务端逐行 owner/admin 校验。
