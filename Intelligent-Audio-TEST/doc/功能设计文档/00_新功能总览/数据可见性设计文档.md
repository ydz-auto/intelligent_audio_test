# 数据可见性设计文档（私有/共享分级）

> 功能域：横切（B 任务 / C 用例 / D 报告 / 评估 / 音频 / 收藏）
> 关联卡：INT-423（FEAT 总卡）、INT-462（一期基座，shared 层）
> 负责人裁定：2026-10-15（问答式拍板，规格阶段不再重复征询；实现演进裁定见各子卡）

## 一、背景与目标

平台业务资源（用例 / 任务 / 评估维度 / 测试报告 / 收藏 / 音频等）目前只有
RBAC **权限点维度**的访问控制，无行级可见性概念：`created_by_user_id`（owner
字段）仅作「记录是谁建的」审计展示，列表对所有有权限的用户全量可见。

负责人口头需求（2026-10-15）：「得给用例 任务 评估维度 测试报告 任务报告 收藏
音频 等分私有 还是共享，私有的只允许用户自己 CRUD」。

本体系引入「**私有 / 共享**」两级可见性：

- **私有资源**：仅创建者（owner）+ admin（豁免）可 CRUD；
- **共享资源**：按现有 RBAC 权限点访问（全员或按角色可见），行为与现状一致。

## 二、可见性模型（负责人拍板 2026-10-15）

1. **仅二值**：`private` / `shared`，不做三值（无团队共享/公开）。加团队机制不做。
2. **默认共享**：存量与新建资源均默认 `shared`（零回归）；新建时可选私有。
3. **共享范围由 RBAC 角色承载**：RBAC 角色本质上即职能用户组，**不另建平行
   teams/groups 机制**。`visibility` 与 RBAC **正交叠加**：
   - `visibility` 只回答「owner 之外是否可见」；
   - `private` = 仅 owner + admin 豁免；
   - `shared` = 回落 RBAC 权限点语义（`资源:read` 可见）；
   - admin 调整某类资源共享范围走现有权限点配置（`is_system` 角色可改权限），
     不动可见性字段。
4. **引用连带**：引用链跟随宿主——任务/报告可见则其引用的用例结果在任务语境
   可见，用例本体可见性不变。
5. **admin 豁免**：admin 可见全部（含私有），访问私有数据留审计事件
   `PRIVATE_RESOURCE_ACCESS`。

## 三、行级过滤与 owner 校验（CQRS 纪律）

- **查询侧（列表）**：Repository / ReadModel 层加行级过滤条件
  `visibility='shared' OR owner=me OR admin`，不可见行不进入结果集，不整批放行。
  实现：`shared/infrastructure/visibility_filter.py` 三助手——
  - `visible_condition(owner_col, vis_col, user_id, is_admin)` → SQLAlchemy 条件
    （admin 恒真 / 未认证仅 shared / 认证用户 shared+owner）；
  - `check_visible(owner, vis, user_id, is_admin)` → 单条详情/CRUD 校验，不通过抛
    `VisibilityDenied`（网关层映射 403/404，防探测口径推荐 404）；
  - `filter_visible_owners(rows, user_id, is_admin)` → 批量逐行过滤（镜像
    `purge_permission.filter_purgeable_owners` 逐行口径）。
- **命令侧（详情/更新/删除）**：Application 层先取资源 → `check_visible` owner
  校验；私有资源非 owner 一律拒绝，共享资源回落 `require_permission` 既有语义。
- **操作人来源**：`user_id` / `is_admin` 一律取自
  `shared/infrastructure/user_context.py` 的 `x-user-id` / `x-user-is-admin`
  （gRPC metadata 透传），禁止从业务表反查当前用户身份。

## 四、引用连带规则

- **宿主优先**：任务/报告可见 → 其引用的用例结果在任务语境可见（详情内联数据
  不做二次 owner 过滤），用例本体可见性不变。
- **音频跟随用例**：用例建/改时把引用音频的 `visibility` 同步为用例的
  `visibility`；同一音频被多用例引用时取**最宽松**（任一用例 shared 则音频
  shared，避免过度隐藏）。
- **分组/标签**：私有分组/标签仅隐藏实体本身（列表/编辑/删除），不隐藏成员用例；
  共享用例详情语境仍显示其分组/标签名。
- **报告子表**（report_summaries 等 7 表）跟随父报告，不单独设列；
  **test_results** 跟随任务，不单独设列。

## 五、admin 豁免与审计

- admin（`x-user-is-admin=true`）跨过 owner/visibility 过滤，全量可见全量可操作。
- admin 访问/修改私有资源落审计事件：
  `AuditEvent.PRIVATE_RESOURCE_ACCESS`（含资源类型/ID/操作人/动作）。
- 共享资源正常访问不落审计。

## 六、`资源:share` 权限点

- 新增 7 个权限点：`task:share` / `testcase:share` / `group:share` / `tag:share` /
  `audio:share` / `report:share` / `evaluation:share`。
- 授予（seed_rbac，幂等重跑）：tester 全给；algo_engineer 给
  `report:share` / `evaluation:share`；admin 通配 `'*'` 自动覆盖；
  device_admin / guest 不给。
- 语义：修改资源可见性（shared↔private）走 `PATCH /{id}/visibility`，
  `require_permission('资源:share')` + owner 校验（admin 豁免），成功后写审计。
- audios 可见性修改不走独立端点（跟随用例，见 §四），保留 `audio:share`
  权限点以备后续。

## 七、数据迁移（幂等）

- **10 张资源表**加列
  `visibility VARCHAR(20) NOT NULL DEFAULT 'shared'`（存量自动回填 shared）：
  `test_tasks` / `test_cases` / `test_case_groups` / `tags` / `tag_categories` /
  `published_tasks` / `audios` / `test_reports` / `dimensions` / `categories`。
- `published_tasks` 额外补 `created_by_user_id BIGINT NULL` + 索引；
  存量 `published_by` 为 String 发布人名无法反查 user_id → **存量置 NULL 不回填**
  （保持共享现状，零回归）；新发布/新版本写入当前 user_id。
- 索引：各表 `idx_<表>_visibility ON <表>(visibility)`；
  高频列表表（test_tasks / test_cases / test_reports / audios / dimensions）加
  `idx_<表>_created_visibility ON <表>(created_by_user_id, visibility)` 复合索引。
- 迁移脚本 `scripts/migrations/202610/add_visibility_columns_int423.py`
  镜像 `add_operator_columns_int299.py` 的 `_col_exists → ALTER TABLE` 幂等模式，
  二次执行全 [SKIP] 不报错。

## 八、前端交互（一期）

- 列表页：可见性徽标（私有带小锁图标）+「全部/共享/私有」筛选 chips
  （服务端筛选 `?visibility=private|shared`）。
- 详情/编辑：非 owner 打开私有资源 → 隐藏编辑/删除入口 + 403 提示 toast；
  路由直达统一 404/403 页。
- 新建/编辑表单：可见性选择器（默认共享，带说明文案）；记用户偏好
  localStorage `visibility_pref`。
- 切换可见性：详情页「分享/设为私有」→ `PATCH /{id}/visibility`，成功后列表
  即时刷新徽标。
