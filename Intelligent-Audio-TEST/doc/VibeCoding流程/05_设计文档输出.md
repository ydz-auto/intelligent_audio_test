# 步骤三：设计文档输出 — AI 主力生成，人做检查

## 流程概览

```
输入：技术设计方案（已评审通过）
  │
  ▼
AI：生成完整设计文档（API 定义、数据模型、接口规范）
  │
  ▼
人工：检查文档完整性和一致性
  │
  ▼
产出：设计文档
```

## 角色分工

| 角色 | 职责 | 关键动作 |
|------|------|----------|
| AI | 主力生成 | 生成 API 定义、数据模型、接口规范、错误码 |
| 人工 | 检查审核 | 检查完整性、一致性、补充遗漏项 |

## 具体做法

### 输入

将步骤二评审通过的技术设计方案作为输入，交给 AI 生成设计文档。

### AI 生成的设计文档

#### 数据模型

```python
class AudioPlayRequest:
    audio_id: int              # 音频文件ID
    device_name: str           # 播放设备名称
    spl: float                 # 声压级 (dB)
    delay: float               # 延迟时间 (秒)
    overlap_rate: float        # 交叠率 (0.0-1.0)

class AudioEngine:
    def play_multi(audio_list: List[AudioPlayRequest]) -> PlayResult
    def stop_all() -> None
    def get_playback_status() -> Dict[str, PlaybackStatus]
```

#### 接口定义

```
POST /api/audio/play
  Request: { "audio_list": [...], "overlap_rate": 0.3 }
  Response: { "task_id": "...", "status": "playing" }

POST /api/audio/stop
  Request: { "task_id": "..." }
  Response: { "status": "stopped" }

GET /api/audio/status
  Response: { "devices": [...], "playing": [...] }
```

### 人工检查

| 检查项 | 结论 | 说明 |
|--------|------|------|
| API 定义完整性 | ✅ 通过 | 覆盖播放、停止、状态查询 |
| 数据模型字段 | ✅ 覆盖需求 | 包含所有必要字段 |
| 错误码定义 | ⚠️ 缺失 | 需要让 AI 补充 |
| 并发限制 | ⚠️ 缺失 | 人工补充：最大同时播放数 = 设备数 × 声道数 |

## Prompt 模板

```
你是一个 API 设计师。

技术设计方案：
{粘贴步骤二产出的技术设计方案}

请帮我生成完整的设计文档，包括：
1. 数据模型定义（含字段类型和说明）
2. API 接口定义（Request/Response 格式）
3. 错误码定义
4. 并发和限制说明
5. 使用示例
```

## 文档检查清单

### 完整性检查
- [ ] 所有 API 接口是否都有 Request/Response 定义
- [ ] 数据模型是否覆盖所有需求字段
- [ ] 是否包含错误码定义
- [ ] 是否包含并发限制说明

### 一致性检查
- [ ] API 字段命名是否统一（camelCase vs snake_case）
- [ ] 数据类型是否前后一致（如时间单位统一为秒或毫秒）
- [ ] 枚举值是否在所有接口中保持一致

### 可用性检查
- [ ] 是否提供了使用示例
- [ ] 是否说明了调用顺序和依赖关系
- [ ] 是否包含分页、排序等通用参数说明

## 常见 AI 文档缺陷

| 缺陷类型 | 表现 | 修正方式 |
|----------|------|----------|
| 缺少错误码 | 只定义成功响应 | 要求 AI 补充完整错误码表 |
| 缺少并发限制 | 不说明系统容量上限 | 人工补充限制条件 |
| 字段命名不统一 | 同一概念在不同接口中命名不同 | 统一命名规范 |
| 缺少版本管理 | API 无版本号 | 添加版本前缀 `/api/v1/` |
