# 步骤六：设计文档输出 — AI 主力生成，人做检查

## 流程概览

```
输入：技术设计方案（已评审通过）
  │
  ▼
开发实现：代码编写、单元测试
  │
  ▼
联调验证：集成测试、问题修复
  │
  ▼
AI：生成最终落地文档（架构文档、接口文档、Issue记录）
  │
  ▼
人工：检查文档完整性和一致性
  │
  ▼
产出：设计文档包
```

## 重要说明

**设计文档输出是在联调之后，基于最终落地的实现生成的文档**，而非开发前的设计预期文档。这样可以确保：

1. **文档与代码一致**：文档反映的是真实的系统状态
2. **问题记录完整**：联调中发现的问题被完整记录
3. **接口定义准确**：接口文档基于实际运行的API生成
4. **后续迭代有据**：方便后续排查问题和功能迭代

## 角色分工

| 角色 | 职责 | 关键动作 |
|------|------|----------|
| AI | 主力生成 | 基于代码和联调结果生成架构文档、接口文档、Issue记录 |
| 人工 | 检查审核 | 检查完整性、一致性、补充遗漏项、整理问题分类 |

## 设计文档输出内容

### 1. 架构文档

位置：`doc/功能设计文档/`

架构文档应该包含以下内容：

| 模块 | 内容 | 示例 |
|------|------|------|
| 系统概述 | 系统定位、核心能力、适用场景 | 音频引擎功能总述.md |
| 核心概念 | 关键术语、层次结构、技术限制 | 设备与声道层次、PyAudio限制 |
| 架构组件 | 组件层次、核心方法、工作原理 | AudioService → AudioDriver → PyAudioDriver |
| 技术问题 | 遇到的技术问题与修复方案 | 多音频并行播放问题、播放时序控制 |
| 数据流 | 完整的数据流转过程 | 播放执行流程、设备扫描匹配 |
| 线程安全 | 并发处理、上下文管理 | Flask App Context传递 |
| 问题排查 | 常见问题、排查方法、解决方案 | 问题现象 → 可能原因 → 解决方案 |
| 文件清单 | 相关文件路径与说明 | backend/utils/audio_engine.py 等 |

### 2. 接口文档

位置：`doc/接口文档/`

接口文档应该包含以下内容：

### 3. Issue文档

位置：`doc/issues/`

Issue文档应该包含以下内容：

| 内容 | 说明 | 示例文件 |
|------|------|----------|
| 问题描述 | 问题现象、触发条件 | PostgreSQL获取插入ID方式修复.md |
| 根因分析 | 问题原因、代码层面分析 | 报告列表加载缓慢问题修复.md |
| 修复方案 | 代码修改、配置调整 | integer_to_bigint_migration.md |
| 影响范围 | 受影响的模块、功能 | 测试用例模态窗音频显示未知音频问题修复.md |
| 测试验证 | 验证步骤、测试结果 | 模态窗文本选择闪退修复未生效问题.md |

Issue文档命名规范：
```
{序号}_{问题简述}.md
例如：001_配置文件重构_环境变量提取.md
```

## 具体做法

### 输入

将联调完成后的代码和测试结果作为输入，交给 AI 生成设计文档。

### AI 生成的设计文档

#### 架构文档示例

基于音频引擎的实际实现：

```markdown
# 音频引擎功能总述

## 一、系统概述
音频引擎是基于 PyAudio 的音频播放管理系统，专门为 E2E 测试场景设计。

### 1.1 核心能力
| 功能模块 | 说明 |
|---------|------|
| 多设备播放 | 支持同时在多个物理设备上播放音频 |
| 多声道混合 | 支持在同一设备的不同声道同时播放不同音频 |
...

## 二、核心概念
### 2.1 设备与声道层次
物理设备 (device_index) → 声道 (channel_index) → PlaybackDevice

### 2.2 PyAudio 技术限制
PyAudio 不允许同一设备同时打开多个流 → 使用 play_multi 混合

...

## 四、关键技术问题与修复
### 4.1 多音频并行播放问题
问题1：音频覆盖而非混合
原因：play_multi callback 中使用赋值 = 而非相加 +=
修复：改为 += 操作
```

#### 接口文档示例

基于实际API生成：

```markdown
## 音频播放接口

### 基本信息
- 接口路径: /api/audio/play
- 请求方法: POST
- 认证方式: Bearer Token

### 请求参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| audio_list | array | 是 | 音频播放配置列表 |
| overlap_rate | float | 否 | 交叠率(0.0-1.0) |

### 请求示例
{
  "audio_list": [
    {
      "audio_id": 101,
      "playback_device_id": 1,
      "spl": 70.0
    }
  ],
  "overlap_rate": 0.3
}
```

#### Issue文档示例

基于联调中发现的问题：

```markdown
# 多音频并行播放问题修复

## 问题现象
同设备多音频播放时，只有最后一个音频能播放

## 根因分析
play_multi 的 callback 中使用赋值 = 而非相加 +=
导致后加载的音频数据覆盖了前面的音频数据

## 修复方案
```python
# 修复前
out_buffer[ch_idx::stream_channels] = audio_data[:limit]

# 修复后
out_buffer[ch_idx::stream_channels] += audio_data[:limit]
```

## 测试验证
- 同设备两个音频同时播放 ✓
- 音频混合效果符合预期 ✓
```

## 常见文档缺陷

| 缺陷类型 | 表现 | 修正方式 |
|----------|------|----------|
| 架构文档不完整 | 缺少技术问题记录 | 要求 AI 补充完整技术问题与修复 |
| 接口文档不准确 | 与实际API不一致 | 对照实际API验证并修正 |
| Issue记录不完整 | 缺少根因或修复方案 | 要求 AI 补充完整问题分析 |
| 文件清单错误 | 文件路径引用错误 | 检查文件是否真实存在 |
| 技术问题遗漏 | 没有记录遇到的问题 | 补充所有技术问题与解决方案 |
