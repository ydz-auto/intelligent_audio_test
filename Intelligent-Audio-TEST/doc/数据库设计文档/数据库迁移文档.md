### 3.4 原始报文指针列回填与切换门禁（INT-1807 / C1）

`test_result_dimensions` 的原始报文（`api_raw_response` / `api_request_body`）改为
「内容寻址对象 + 行上指针」的第一步。分两件事：

1. **结构（进引导链）**：`scripts/migrations/202610/add_raw_payload_pointers_int1807.py`
   ——补两组各五列（uri / sha256 / bytes / content_type / created_at），全部可空、
   无默认值、无索引。引导链编号 ㊽-5，排在 ㊽ INT-1741 ANALYZE 之前；幂等，全新库
   为全 SKIP。
2. **存量回填（人工执行，不进引导链）**：
   `scripts/migrations/202610/backfill_raw_payload_pointers_int1807.py`
   ——主库要解压约 695MB TOAST，必须限流分批，不要挂进部署：

```bash
# 门禁（只读，可重复执行；两项都为 0 才算可以切读写路径）
python scripts/migrations/202610/backfill_raw_payload_pointers_int1807.py --gate
# 预览 → 执行（--limit-groups 分次跑，进度按 uri IS NULL 续跑）
python scripts/migrations/202610/backfill_raw_payload_pointers_int1807.py
python scripts/migrations/202610/backfill_raw_payload_pointers_int1807.py --apply \
    --batch-groups 200 --sleep 0.5
```

**切换门禁查询**（两项必须同时为 0）：

```sql
SELECT
  count(*) FILTER (WHERE api_raw_response IS NOT NULL AND api_raw_response_uri IS NULL) AS resp_missing,
  count(*) FILTER (WHERE api_request_body IS NOT NULL AND api_request_body_uri IS NULL) AS req_missing
FROM test_result_dimensions;
```

回填写对象一律 `allow_fallback=False`（INT-1805 / D1）：OSS 不可用即失败、不落本地
盘、不产生 `local://` 路径，失败组不写 uri，重跑自动补。

### 3.5 原始报文 JSON 两列的 DROP + VACUUM FULL（INT-1813 / M1）

存量回填门禁归零、C2（uri-only 读写）与 A1（离线搬运带对象）同批上线并观察 ≥1 个
完整测试轮次之后，才删两个 JSON 列。**PG 16 的 `DROP COLUMN` 只改系统目录、不重写
数据**，被删列的 TOAST 要等行重写才释放——只 DROP 不 `VACUUM FULL`，磁盘一个字节都
不会少。

脚本：`scripts/migrations/202610/drop_raw_payload_columns_int1813.py`（**不进引导链**，
人工窗口执行；重复执行幂等，列已不存在即 `[SKIP]`，不会重复 VACUUM）。

```bash
# 门禁（只读）：回填门禁 0 / 近 24h 无新内联写入 / 指针无断链 / 抽样读对象校验 sha256
python scripts/migrations/202610/drop_raw_payload_columns_int1813.py --gate --verify-objects 20
# 执行：DROP → VACUUM FULL → ANALYZE，打印前后 pg_total_relation_size /
#       pg_relation_size / pg_table_size / TOAST 关系大小与差值
python scripts/migrations/202610/drop_raw_payload_columns_int1813.py --apply     --confirm-deployed-round --confirm-read-path --strict-24h
# 窗口内回滚（对象全部保留）：加回两列并按 uri + sha256 从对象写回
python scripts/migrations/202610/drop_raw_payload_columns_int1813.py --restore --apply
```

前置门禁（脚本内断言，缺一不可）：①C2+A1 已同批部署且已观察 ≥1 个完整测试轮次
（`--confirm-deployed-round`，DB 查不出来）；②`api_raw_response IS NOT NULL AND
api_raw_response_uri IS NULL` = 0（request 同理；两列已删时为 N/A）；③近 24h 新写入
两列全为 SQL NULL（窗口内无行须 `--ack-no-recent-traffic` 承认，主库建议
`--strict-24h`）；④报告侧读路径已走对象（`--verify-objects N` 抽样下载校验或
`--confirm-read-path`）。

锁与窗口：`ALTER` 只拿一次 `ACCESS EXCLUSIVE`（`lock_timeout` 默认 5s，拿不到即失败、
不排队）；`VACUUM FULL` 全程持锁且需额外约一个表大小的临时磁盘（约 275MB）；
执行前脚本查 `pg_stat_activity` 的 `idle in transaction` / 等锁会话并拒绝带锁风险执行
（锁队列会把整个域的 gRPC 拖成 400/60s）。

**副本实测（2026-10-26，pg_dump 副本 + 真实 rustfs 对象）**：51,857 行，
`pg_total_relation_size` 325.66MB → 27.44MB（−298.22MB），TOAST 230.34MB → 8KB；
`DROP` 16ms / `VACUUM FULL` 327ms / `ANALYZE` 422ms；重复执行 `[SKIP]`；
删列后应用读对象路径对 199 行抽样与删列前逐行 deep-equal；`--restore` 写回后同样
deep-equal（反向回填可行）。

**ORM 同步**：`evaluation_service/infrastructure/persistence/models/result_models.py`
的 `TestResultDimension` 已摘掉这两个列的映射——**删列与摘映射必须同批上线**，
库里有列而 ORM 也映射、或列已删而 ORM 仍映射，都会让全列 SELECT / INSERT 报
`UndefinedColumn`（副本上实测复现）。

## 4. 关键问题处理

### 4.1 序列重置问题

**问题**: 迁移时序列可能未正确设置，导致新插入数据 ID 冲突。

**原因**:
- 序列重置在数据迁移**之前**执行
- 空表的 `setval(seq, 0)` 会报错

**解决**: 迁移脚本已修复，顺序为先迁移数据，再重置序列。

### 4.2 Boolean 类型转换

**问题**: PostgreSql 用 0/1 存储布尔值，PostgreSQL 用 true/false。

**解决**: 迁移脚本自动转换：
```python
if column_name in BOOLEAN_COLUMNS:
    if value in (0, '0', 'false', 'False', False):
        return False
    if value in (1, '1', 'true', 'True', True):
        return True
```

### 4.3 NULL 值处理

**问题**: 部分字段（如 `apis.api_url`）在 PostgreSql 中为 NULL。

**解决**: `fix_null_values()` 函数修复：
```python
NULL_FIXES = {
    'apis': {'api_url': "''"},
    'dimensions': {'api_endpoints': "'[]'"},
    'categories': {'config': "''"},
    'languages': {'config': "''"},
}
```

### 4.4 字段差异问题

**问题**: PostgreSql 和 PostgreSQL 模型定义可能不一致。

**示例**: `task_case_relations` 表在 PostgreSql 中有 `algorithm_type` 和 `algorithm_params` 字段，但模型未定义。

**解决**: 保持模型与 PostgreSql schema 一致，必要时更新模型。
