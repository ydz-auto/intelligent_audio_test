## 3. 迁移步骤详解

### 3.1 脚本执行流程

| 步骤 | 函数 | 说明 |
|------|------|------|
| 1 | `recreate_database()` | 重建 PostgreSQL 数据库，创建用户和权限 |
| 2 | `grant_schema_privileges()` | 授予 public schema 权限 |

## 4. 关键问题处理

### 4.1 序列重置问题

**问题**: 迁移时序列可能未正确设置，导致新插入数据 ID 冲突。

**原因**:
- 序列重置在数据迁移**之前**执行
- 空表的 `setval(seq, 0)` 会报错

**解决**: 迁移脚本已修复，顺序为先迁移数据，再重置序列。

### 4.2 Boolean 类型转换

**问题**: PostgreSql 用 0/1 存储布尔值，PostgreSQL 用 true/false。

**解决**: 迁移脚本自动转换：
```python
if column_name in BOOLEAN_COLUMNS:
    if value in (0, '0', 'false', 'False', False):
        return False
    if value in (1, '1', 'true', 'True', True):
        return True
```

### 4.3 NULL 值处理

**问题**: 部分字段（如 `apis.api_url`）在 PostgreSql 中为 NULL。

**解决**: `fix_null_values()` 函数修复：
```python
NULL_FIXES = {
    'apis': {'api_url': "''"},
    'dimensions': {'api_endpoints': "'[]'"},
    'categories': {'config': "''"},
    'languages': {'config': "''"},
}
```

### 4.4 字段差异问题

**问题**: PostgreSql 和 PostgreSQL 模型定义可能不一致。

**示例**: `task_case_relations` 表在 PostgreSql 中有 `algorithm_type` 和 `algorithm_params` 字段，但模型未定义。

**解决**: 保持模型与 PostgreSql schema 一致，必要时更新模型。

- 检查 PostgreSQL 是否正常运行
- 使用 `python -u scripts/migrate_data.py` 禁用输出缓冲

```bash

```

### 7.4 外键约束错误
迁移脚本会自动禁用外键，如仍有问题检查表顺序。

## 8. 注意事项

1. **迁移前备份**: 建议备份 PostgreSql 数据库
2. **迁移中勿操作**: 迁移过程中不要同时操作数据库
3. **序列验证**: 迁移后务必运行 `fix_sequences.py` 验证
4. **应用配置**: 确保 `config.py` 中的数据库 URI 已更新
