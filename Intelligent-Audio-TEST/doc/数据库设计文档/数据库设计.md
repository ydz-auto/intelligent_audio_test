# 数据库设计

## 1. 整体设计

### 1.1 设计原则

- **统一命名规范**：采用snake_case命名法，表名使用复数形式
- **数据完整性**：合理设置主键、外键、约束和默认值
- **性能优化**：为常用查询字段添加索引
- **扩展性**：设计灵活的表结构，支持未来功能扩展
- **安全性**：采用逻辑删除，保护数据安全
- **一致性**：统一数据类型和字段命名

### 1.2 技术栈

- **数据库**：PostgreSQL 15+
- **ORM**：SQLAlchemy 2.0+
- **主键策略**：自增主键 (SERIAL) 或 UUID

**config字段详细结构**：
```json
{
  "background_noise": {
    "audio_id": 10,            // 背景噪声音频ID
    "spl": 65.0                // 背景噪声声压级
  },
  "audios": [                  // 音频配置数组
    {
      "audio_id": 101,         // 音频ID
      "test_type": "api",      // 测试类型：api/e2e
      "spl": 70.0,             // 声压级
      "playback_device_id": null,  // 播放设备ID（E2E测试必填）
      "play_order": 1          // 播放顺序
    },
    {
      "audio_id": 101,
      "test_type": "e2e",
      "spl": 70.0,
      "playback_device_id": 5,  // E2E测试必填播放设备ID
      "play_order": 1
    }
  ],
  "dimensions": {              // 评测维度配置，按测试类型区分
    "api": [1, 2, 3],          // API测试使用的评测维度ID数组
    "e2e": [2, 3, 4]           // E2E测试使用的评测维度ID数组
  }
}
```

## 6. 数据库初始化脚本

```sql
-- 创建表结构的SQL脚本示例

-- 用户表
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    role VARCHAR(20) NOT NULL,
    status VARCHAR(20) NOT NULL,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
);

-- 测试用例分组表
CREATE TABLE IF NOT EXISTS test_case_groups (
    id VARCHAR(50) PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE,
    description TEXT,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
);

-- 标签表
CREATE TABLE IF NOT EXISTS tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(50) NOT NULL UNIQUE,
    description TEXT,
    color VARCHAR(20),
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
);

-- 音频表
CREATE TABLE IF NOT EXISTS audios (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(255) NOT NULL,
    original_filename VARCHAR(255),
    file_path VARCHAR(500) NOT NULL,
    size INTEGER NOT NULL,
    duration FLOAT NOT NULL,
    format VARCHAR(20),
    sample_rate INTEGER,
    channels INTEGER,
    bitrate INTEGER,
    asr_text TEXT,
    audio_type VARCHAR(20) NOT NULL DEFAULT 'dry',
    description TEXT,
    deleted BOOLEAN NOT NULL DEFAULT FALSE,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
);

-- 音频翻译表
CREATE TABLE IF NOT EXISTS audio_translations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    audio_id INTEGER NOT NULL,
    translated_text TEXT NOT NULL,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    FOREIGN KEY (audio_id) REFERENCES audios(id)
);

-- 测试用例表
CREATE TABLE IF NOT EXISTS test_cases (
    id VARCHAR(50) PRIMARY KEY,
    name VARCHAR(150) NOT NULL,
    description TEXT,
    config JSON NOT NULL,
    group_id VARCHAR(50),
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    deleted BOOLEAN NOT NULL DEFAULT FALSE,
    FOREIGN KEY (group_id) REFERENCES test_case_groups(id)
);

-- 测试用例标签关联表
CREATE TABLE IF NOT EXISTS test_case_tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    test_case_id VARCHAR(50) NOT NULL,
    tag_id INTEGER NOT NULL,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (test_case_id) REFERENCES test_cases(id),
    FOREIGN KEY (tag_id) REFERENCES tags(id)
);

-- 设备表
CREATE TABLE IF NOT EXISTS devices (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(100) NOT NULL,
    model VARCHAR(100) NOT NULL,
    description TEXT,
    type VARCHAR(50) NOT NULL,
    system VARCHAR(50) NOT NULL,
    system_version VARCHAR(20) NOT NULL,
    app_name VARCHAR(100) NOT NULL,
    app_version VARCHAR(20) NOT NULL,
    location VARCHAR(100),
    max_audio_duration FLOAT,
    needs_prompt_audio BOOLEAN DEFAULT FALSE,
    prompt_config JSON,
    status VARCHAR(20) NOT NULL DEFAULT 'offline',
    last_online_at DATETIME,
    deleted BOOLEAN NOT NULL DEFAULT FALSE,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
);

-- 播放设备表
CREATE TABLE IF NOT EXISTS playback_devices (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(100) NOT NULL,
    model VARCHAR(100) NOT NULL,
    device_type VARCHAR(20) NOT NULL,
    sample_rate INTEGER NOT NULL,
    channel_index INTEGER DEFAULT 0,
    device_unique_id VARCHAR(100) NOT NULL,
    description TEXT,
    status INTEGER NOT NULL DEFAULT 2,
    is_deleted INTEGER NOT NULL DEFAULT 0,
    current_spl_mapping_id INTEGER,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    created_by VARCHAR(50),
    FOREIGN KEY (current_spl_mapping_id) REFERENCES spl_mappings(id),
    UNIQUE(device_unique_id, channel_index)
);

-- 声压级映射表
CREATE TABLE IF NOT EXISTS spl_mappings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(100) NOT NULL,
    device_id INTEGER,
    device_type VARCHAR(50),
    distance FLOAT DEFAULT 1.0,
    target_spl FLOAT,
    digital_gain FLOAT,
    calibration_status VARCHAR(20) DEFAULT 'uncalibrated',
    test_frequency INTEGER DEFAULT 1000,
    calibration_data JSON,
```

# 总结

本数据库设计文档提供了一个完整的智能语音测试系统后端数据库设计方案，涵盖了用户管理、标签管理、测试用例管理、API配置管理、设备管理、音频文件管理、测试任务管理、测试结果管理、评估维度管理和日志管理等核心模块。设计遵循了统一的命名规范和设计原则，确保了数据的完整性、一致性和安全性。

主要设计特点：

1. **测试用例统一管理**：测试用例不再区分API测试/E2E测试，而是通过`test_cases.config`字段配置不同测试类型的音频和评测维度
2. **灵活的测试配置机制**：通过`config.audios`数组配置不同类型的音频，通过`config.dimensions`对象配置不同类型的评测维度
3. **简化的表结构设计**：移除了独立的`test_case_audios`和`test_case_dimensions`关联表，将相关配置集中存储在`config`字段中
4. **完整的音频元数据管理**：
   - 音频表添加了asr_text字段，存储语音识别文本
   - 创建了audio_translations表，支持为音频配置翻译文本
4. **标签规范化管理**：将标签从JSON字段改为独立的表结构，支持标签的共享和统一管理
5. **多实体标签关联**：支持测试用例、任务、音频和设备等多个实体关联标签
6. **优化的索引设计**：为核心表添加了合适的索引，提高查询效率
7. **清晰的关系图**：直观展示了系统各实体之间的关联关系

该设计具有良好的扩展性和性能，可以支持系统的未来发展和功能扩展。同时，文档提供了详细的索引设计、关系图、数据字典、初始化脚本、迁移策略、性能优化建议、安全建议和维护建议，为系统的开发和维护提供了全面的指导。
