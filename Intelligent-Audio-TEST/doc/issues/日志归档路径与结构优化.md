# 日志归档路径与结构优化

## 问题背景

### 问题1：动态路径依赖工作目录

原代码使用 `os.path.join(os.getcwd(), 'archives')` 动态获取归档目录路径，存在问题：

- `os.getcwd()` 返回运行时工作目录，可能因启动方式不同而变化
- 导致归档文件位置不确定，难以管理和查找
- 与项目其他静态路径配置风格不一致

### 问题2：归档目录结构不合理

原目录结构：
```
archives/
  tasks/
    task_{task_id}.json       # 任务日志（日志只有 task_id）
  cases/
    case_{test_case_id}.json  # 用例日志（日志只有 test_case_id）
  other/
    other_{timestamp}.json    # 其他日志
```

存在问题：
- `tasks/task_{task_id}.json` 存放的是任务执行相关日志，但这些日志的 `test_case_id` 都是 null
- `cases/case_{test_case_id}.json` 存放的是用例预览（preview）类别的日志，而非用例CRUD操作日志
- 没有区分"任务中用例执行日志"（同时有 task_id + test_case_id）和"用例CRUD操作日志"（只有 test_case_id）
- 归档文件按单一ID存储，没有按日期细分，单个文件可能过大

## 解决方案

### 1. 静态路径配置

在 `backend/config/config.py` 中新增配置项：

```python
# 归档文件存储路径
ARCHIVE_PATH = os.path.join(PROJECT_ROOT, 'archives')
```

修改 `backend/controllers/log_controller.py`，导入配置并替换所有动态路径：

```python
from backend.config.config import Config

archive_dir = Config.ARCHIVE_PATH  # 替换 os.path.join(os.getcwd(), 'archives')
```

### 2. 新目录结构

```
archives/
  tasks/
    {task_id}/                     # 任务目录（数字ID）
      {test_case_id}/              # 用例执行日志（UUID，同时有 task_id + test_case_id）
        {YYYY-MM-DD}.json          # 按日期归档
      {YYYY-MM-DD}.json            # 只有 task_id 的日志（如报告生成、任务调度等）
  cases/
    {test_case_id}/                # 用例CRUD日志目录（UUID）
      {YYYY-MM-DD}.json            # 按日期归档（用例创建/编辑/删除/预览等操作）
  other/
    {YYYY-MM-DD}.json              # 其他日志（无 task_id 和 test_case_id）
```

### 3. 分类逻辑

日志归档时按以下优先级分类：

| 条件 | 存放位置 | 说明 |
|------|---------|------|
| `task_id` + `test_case_id` 都有 | `tasks/{task_id}/{test_case_id}/{date}.json` | 任务中用例执行日志 |
| 只有 `task_id` | `tasks/{task_id}/{date}.json` | 任务级别日志（报告、调度等） |
| 只有 `test_case_id` | `cases/{test_case_id}/{date}.json` | 用例CRUD操作日志 |
| 都没有 | `other/{date}.json` | 系统其他日志 |

### 4. 相关方法修改

| 方法 | 修改内容 |
|------|---------|
| `archive_logs()` | 按任务-用例层级 + 日期归档，提取日志日期字段 |
| `get_archive_status()` | 递归遍历新结构统计归档文件数量 |
| `get_archived_logs()` | 支持按 task_id/test_case_id 查询，读取所有日期文件 |
| `download_archive()` | 使用 `os.walk` 递归查找归档文件 |
| `delete_archive()` | 使用 `os.walk` 递归查找并删除归档文件 |

## 涉及文件

- `backend/config/config.py` - 新增 `ARCHIVE_PATH` 配置
- `backend/controllers/log_controller.py` - 修改归档相关方法
