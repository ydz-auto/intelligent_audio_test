# 报告列表加载缓慢问题修复

## 问题描述

报告列表页面加载非常慢，2 个报告需要 10 秒才能加载完成。

## 问题原因

`ReportSummary` 表包含多个大型 JSON 字段：

| 字段 | 说明 |
|------|------|
| `case_categories` | 用例分组列表 |
| `all_case_tags` | 用例标签列表 |
| `devices` | 设备列表 |
| `apis` | API列表 |
| `resources` | 资源列表 |
| `resource_headers` | 资源头信息 |
| `all_metrics` | 评估维度列表 |

但报告列表页只需要以下 4 个简单的统计字段：
- `total_cases` - 总用例数
- `completed_cases` - 完成用例数
- `failed_cases` - 失败用例数
- `pass_rate` - 通过率

**原代码问题：**

```python
query = Report.query.options(joinedload(Report.task), joinedload(Report.summary_info))
```

使用 `joinedload(Report.summary_info)` 会加载整个 `ReportSummary` 记录，包括所有大型 JSON 字段。这导致：

1. 数据库查询变慢（读取大量不需要的数据）
2. 网络传输变慢（从数据库传输大量数据到应用层）
3. 内存占用增加

## 解决方案

使用 SQLAlchemy 的 `load_only()` 只加载需要的字段：

```python
from sqlalchemy.orm import joinedload, load_only

query = Report.query.options(
    joinedload(Report.task),
    joinedload(Report.summary_info).load_only(
        ReportSummary.total_cases,
        ReportSummary.completed_cases,
        ReportSummary.failed_cases,
        ReportSummary.pass_rate
    )
)
```

## 修改文件

- `backend/controllers/report_controller_base.py` - `get_all()` 函数

## 效果

查询速度从 10 秒级别降到毫秒级别。

## 相关优化建议

1. **索引优化**：确保 `report_summaries.report_id` 有索引（当前已有 `unique=True` 约束）
2. **分页优化**：列表页已使用后端分页，避免一次性加载过多数据
3. **字段分离**：当前设计已将大数据量字段分离到 `ReportDetailData` 表，列表页只查询 `ReportSummary` 表
