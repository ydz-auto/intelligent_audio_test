# 测试用例CRUD模态窗音频显示"未知音频"问题修复文档

## 问题概述

**问题描述**: 在测试用例CRUD模态窗中，配置音频一栏全部显示"未知音频"，无法正确显示已配置音频的实际名称。

**发现日期**: 2026-05-21

**影响范围**: 测试用例编辑功能，用户无法看到已配置的音频文件名称。

---

## 问题分析

### 1. 相关代码位置

- `frontend/src/components/common/test-case/TestCaseModal/useAudioConfig.ts` - 音频配置管理逻辑
- `frontend/src/components/common/test-case/TestCaseModal/index.vue` - 模态窗主组件
- `frontend/src/components/common/test-case/TestCaseModal/CaseForm.vue` - 用例表单组件

### 2. 问题根源

在 `useAudioConfig.ts` 中，`getAudioName` 函数负责根据音频ID查找音频名称：

```typescript
function getAudioName(audioId: string | number): string {
  const allAudios = [...dryAudios.value, ...noiseAudios.value];
  const audio = allAudios.find(a => String(a.id) === String(audioId));
  return audio ? audio.name : '未知音频';
}
```

该函数从 `dryAudios` 和 `noiseAudios` 列表中查找音频。这两个列表由 `loadResources` 函数填充：

```typescript
async function loadResources(configuredAudioIds: (string | number)[] = []) {
  // 获取第一页音频数据
  const allAudiosRes = await audiosApi.getAll({ perPage: 1000 });
  // ...
  
  // 处理不在第一页结果中的音频
  const missingAudioIds = configuredAudioIds.filter(id => !firstPageIds.has(id));
  
  if (missingAudioIds.length > 0) {
    const missingAudiosRes = await audiosApi.getByIds(missingAudioIds);
    // 补充到列表中
  }
}
```

### 3. 问题原因

在 `index.vue` 中打开模态窗时调用 `loadResources()`，但**没有传入已配置的音频ID参数**：

```typescript
watch(() => props.visible, (newVal) => {
  if (newVal) {
    loadTestGroups();
    if (props.mode === 'case') {
      audioConfig.loadResources();  // ❌ 缺少参数
      dimensionConfig.loadDimensions();
    }
  }
}, { immediate: true });
```

当编辑已有测试用例时：
1. `formData.config.audios` 中包含已配置的音频ID
2. `loadResources()` 不传参数，只获取第一页1000条音频
3. 如果已配置的音频不在第一页结果中，`dryAudios`/`noiseAudios` 列表中找不到该音频
4. `getAudioName()` 返回 "未知音频"

---

## 修复方案

### 修改文件

`frontend/src/components/common/test-case/TestCaseModal/index.vue`

### 修改内容

新增 `extractConfiguredAudioIds` 函数，在调用 `loadResources` 时传入已配置的音频ID：

```typescript
watch(() => props.visible, (newVal) => {
  if (newVal) {
    loadTestGroups();
    if (props.mode === 'case') {
      const configuredAudioIds = extractConfiguredAudioIds(props.formData);
      audioConfig.loadResources(configuredAudioIds);  // ✅ 传入已配置音频ID
      dimensionConfig.loadDimensions();
    }
  }
}, { immediate: true });

function extractConfiguredAudioIds(formData: any): (string | number)[] {
  const ids: (string | number)[] = [];
  if (formData?.config?.audios && Array.isArray(formData.config.audios)) {
    formData.config.audios.forEach((audio: any) => {
      if (audio.audioId) {
        ids.push(audio.audioId);
      }
    });
  }
  if (formData?.config?.backgroundNoise?.audioId) {
    ids.push(formData.config.backgroundNoise.audioId);
  }
  return ids;
}
```

## 技术细节

### `loadResources` 函数的音频获取流程

1. **获取第一页数据**: `audiosApi.getAll({ perPage: 1000 })` 获取最多1000条音频
2. **检查缺失音频**: 对比传入的 `configuredAudioIds` 与第一页结果，找出缺失的音频ID
3. **批量获取缺失音频**: `audiosApi.getByIds(missingAudioIds)` 获取不在第一页中的音频
4. **合并到列表**: 将缺失音频补充到 `dryAudios` 或 `noiseAudios` 列表

### 为什么只获取第一页

数据库中可能存储了大量音频文件（超过1000条），一次性获取全部会：
- 增加API响应时间
- 占用更多内存
- 影响用户体验

因此采用"第一页 + 按需补充"的策略，只加载当前用例实际需要的音频信息。
