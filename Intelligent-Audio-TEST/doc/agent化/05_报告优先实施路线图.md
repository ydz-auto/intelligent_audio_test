
# 05 报告优先：DeepSeek Harness 产品与实施路线图

> 决策日期：2026-10-08。**报告是本项目最主要的产品功能；DeepSeek Harness 是统一 Agent 技术底座。** 本文是实施计划、非已完成成果。关联：[00_DeepSeek_Harness统一迁移设计](00_DeepSeek_Harness统一迁移设计.md)、[04_前后端改造方案](04_前后端改造方案.md)、[对话式报告工作台](../功能设计文档/05_报告管理/对话式报告工作台功能设计文档.md)。

## 一、Report First：产品流程

**选择/生成报告 → 阅读可信指标 → AI 起草 → 对话编辑 → 图表预览 → 版本管理 → 导出 PDF/PPTX/HTML/MD。**

DSH 支持自然语言推理、Tool Calling 和上下文，不接管指标运算或实际报告资产的存储。旧有报告七表与 Report Service 是数据事实源；Report Studio Document 与版本快照是交付文档源；DSH Session 是 Agent 对话历史。三者按 ID 关联但绝不混为同一张状态表。

### 产品入口（优先报告，而非万能聊天）

| 入口 | 用户操作 | 后端工作 |
| --- | --- | --- |
| 报告中心、历史报告、ReportView | 标准报告 / AI 文档报告 | 读取已生成报告的七表数据 |
| 任务页 | 生成 AI 报告 | 先由现有报告服务生成单任务结构化报告，再进入 Studio |
| 多任务对比 | 生成对比报告 | 复用 compare 原计算链路，获得 reportId |
| 历史报告二次对比 | 生成二次对比 | 复用 secondary-compare 计算链路，再进入 Studio |
| 通用 Agent 页面 | 非报告操作 | 不属于首个报告版本的前置条件 |

现有 `api_gateway/routes/report_bp.py` 的报告进度端点为 404 占位；从任务生成新报告时，不能依赖此未实现的进度 API。需先实现/接入已验证的生成状态机制，成功取得 reportId 后才能创建 Studio 文档和会话。

## 二、报告功能第一优先级

| 级别 | 功能 | 上线门槛 |
| --- | --- | --- |
| P0 | task / comparison / secondary_comparison 三种报告的数据读取、复算及权限 | 必须 |
| P0 | 双栏对话式 Studio，基于真实报告生成 Markdown 初稿 | 必须 |
| P0 | 数据来源引用，数值和图表由 Report Service 计算，不允许模型编造 | 必须 |
| P0 | AI 局部改稿、人工编辑、diff、历史版本、恢复及并发冲突处理 | 必须 |
| P0 | 图表预览、可追溯 ChartSpec、受控模板 | 必须 |
| P0 | PDF/PPTX/HTML/MD 可真实导出，文件格式、字体、图表经过验收 | 必须 |
| P0 | 用户/报告/文档/下载授权、模型故障降级、断线可恢复 | 必须 |
| P1 | 数据追问、跨报告趋势、异常指标下钻、引用式总结 | 紧接主线 |
| P2 | 通过报告触发重测、测试用例修改、设备驱动生成、通用 Agent 工作台 | 后置 |

P0 是**首个正式可交付版本**的范围，不意味着在一次 PR 中完成。能够聊天不等于能够生成客户可用的报告。

## 三、设计取舍和边界

- **UI**：保留原标准报告；新增 `/report/:id/studio` 作为 AI 文档报告工作台。左侧对话/执行证据，右侧 Markdown/图表/文档编辑，并可查看历史版本和导出任务。通用 `/agent` 页面后置，复用同一 DSH 实例，不复制会话引擎。
- **前端实现**：`frontend/src/views/ReportStudio/`、`components/report/studio/`、`composables/report/useReportStudio.ts`、`store/reportStudioStore.ts`，配合已有 `infrastructure/api`、DTO/Adapter 和共用 Agent SSE Client；snake_case 仅在 Infrastructure 层。
- **后端实现**：`api_gateway/routes/agent_bp.py` 负责 DSH 会话/Run/SSE；`api_gateway/routes/report_studio_bp.py` 负责文档/版本/图表/导出；`report_service/application/` 继续负责事实计算；`agent_worker/plugins/report_studio/` 承接 DSH Typed Tools。
- **DSH 工具**：`report_get_facts`、`report_query_metrics`、`studio_create_draft`、`studio_apply_edit`、`studio_insert_chart`、`studio_get_versions`、`studio_restore_version`、`studio_request_export`，只有当前用户允许的工具可被装配。
- **文档一致性**：Document Service 在一次事务中写文档及不可变版本；每次 AI/人工写入携带 `expectedVersion`，冲突为 409，绝不采取“后写入自动覆盖”。恢复旧版本产生新版本。
- **导出**：版本固定为 `documentId + documentVersion + chartSpecVersion`；确定性导出服务不执行模型生成代码。PDF/PPTX 使用服务端计算结果与静态图，不将 ChartSpec 解释为可执行 JS。
- **数值与检索**：问“设备 B 为什么差”时，先查询 report 指标和可比样本，再按需查任务日志和设备状态；文档知识 RAG 可选；`rg` 仅用于源码定位，不能代替报告数据 API。
- **安全**：上游 DSH 仍为 Developer Preview、未经安全审计，应用受限 Profile、最小权限和网络隔离；对现有报告 API 做用户/资源权限复核，生产禁用 AUTH_MODE=off。

## 四、按 PR 拆分的交付路线

| 阶段 | PR/工作包 | 真实验收 |
| --- | --- | --- |
| R0 数据与安全 | R0.1 锁定 DSH Profile/SDK 并审查权限；R0.2 核对三类报告的真实读取路径和生成状态 | 标准报告无回归、七表计算口径清楚 |
| R1 初稿技术闭环 | R1.1 DSH Worker/Bridge/Session/SSE；R1.2 Report Query/Facts Plugin；R1.3 Studio 双栏+文档草稿落库 | 使用真实报告生成可保存且带指标来源的 Markdown |
| R2 编辑与资产 | R2.1 Document/Version/ChartSpec 数据模型；R2.2 AI/人工结构化编辑、diff、冲突及恢复；R2.3 HTML/MD | 多轮编辑不丢数据，版本可追溯，导出可重试 |
| R3 正式报告交付 | R3.1 受控图表预览；R3.2 PDF；R3.3 PPTX；R3.4 三类真实报告视觉/数值回归 | **首个可发布报告产品版本**：文件可打开、数据图表正确、分页及中文排版合格 |
| R4 深度报告分析 | 跨报告比较问答、趋势归因、日志/用例/设备引用、质量基准 | 结论可追溯，缺失数据不编造，模型故障时标准模式可用 |
| R5 非报告 Agent | 用例生成、自动重试/审批、UiAutoDev 驱动提案、通用工作台 | 不影响报告主线可用性 |

技术演示可以在 R1 完成，但**外部/真实业务发布必须以 R3 正式交付指标为门槛**，不能把对话流通当作产品验收。

## 五、核心端到端测试矩阵

1. 三类报告各选固定测试数据；覆盖多设备、多轮次、多个评分维度、对比差异和缺失值。报告数值与现有 Report Service 结果逐字段核对。
2. “生成高层汇报两页版 → 把柱状图换雷达图 → 加风险清单 → 导出 PPTX”完整交互；AI 只控制叙述和文档结构，图表依参数化事实源构建。
3. “AI 改稿 + 用户手改 + 撤销/恢复 + 并发提交”，检查事务快照、一致版本与 409 冲突。
4. HTML/PDF/PPTX 使用同一文档和 ChartSpec 版本；检查分页、中文字体、表格溢出、图表、下载许可、文件可打开。
5. 断网、DSH Worker 重启、模型超时、导出失败，不能使已保存文档或原报告丢失；标准报告仍可浏览。
6. 用户 A 不能以猜测 reportId/documentId/runId/exportId 的方式访问用户 B 资产；DHS/DSH 工具禁止任意 Shell、生产数据库与设备凭据。

## 六、范围之外与已有文档关系

原 `03_技术设计文档.md` 的自研 Agent Loop、独立 `backend/ai/report_agent.py` 以及重复 Session/history 不实施；所有模型/工具/会话使用同一个 DSH Runtime。以前“任务失败诊断→自动重试”的路线移动到报告深入分析之后。旧报告设计文档的前几章描述了成熟的产品交互目标，实施时以其第 15 章 DSH 设计和本文优先级为准。
