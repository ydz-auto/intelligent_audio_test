# 原始报告导出（灵犀Agent）设计

> 版本：v1 ｜ 日期：2026-11-24 ｜ 分支：V10.11.2
> 关联：VEGA-86 / VEGA-88 验收结论；`skills/report-studio/SKILL.md`（v1.2.0 修订）

## 1. 问题

灵犀Agent 现有的 `report_export` 只能导出 **Studio 文档**（AI 起草的 Markdown
正文），渲染器 `report_studio_renderer.parse_markdown` 只支持标题 / 段落 / 列表 /
代码 / 表格 / 分隔线六种块，**导不出平台原始报告里的用例明细**（每条用例各维度
的值）。用户反馈：导出报告"缺失了很多信息"，"每一条用例都可以点击查看详细情况"
这一在平台页面上成立的能力，导出后不存在。

音频：数据量太大，本次不打包音频文件。

### 1.1 三条导出链路现状

| 链路 | 入口 | 用例明细 | 可交互 | 音频 |
|---|---|---|---|---|
| Studio 文档导出 | `report_export` 意图工具 | 无 | 无 | 无 |
| 旧版后端 HTML | `GET /reports/export?format=html` | 无 | 无 | 无 |
| 前端 ZIP 快照 | 报告页「导出 HTML」 | 有（`data-export-case-detail`） | 有（展开 / 筛选 / 分页） | 按钮被删 |

前端 ZIP 快照链路已经实现了「每条用例可展开、各维度值可见、带筛选面板」，
是本次要复用的能力；但它只在浏览器里跑（克隆 DOM），Agent 侧无法调用。

## 2. 目标与非目标

**目标**

1. 灵犀Agent 新增 `report_export_raw` 意图工具：按 `report_id` 产出一份
   **与平台报告页同构的静态 HTML**，每条用例可展开查看各维度值；
2. 产物同步渲染、直接登记为 `done`（复用 Studio 导出作业表与下载通道），
   支持 `html`；`md` 以「用例明细表」形态输出（无交互，但信息完整）；
3. 前端 ZIP 快照导出修复音频按钮：保留「播放音频」入口并明确标注
   "音频需在平台内播放"（不打包音频）。

**非目标**

- 不打包音频文件；
- 不改动 Studio 文档导出（`report_export`）的现有语义；
- 不改报告数据与评估逻辑。

## 3. 方案

### 3.1 后端：`report_export_raw` 意图工具

```text
report_export_raw(report_id, format=html|md, theme?)
  → 提案（proposal_diff_export_raw：report_id + format + 用例数预估）
  → 审批通过
  → ToolGateway._run_report_export_raw
       1. GET /reports/{id}            取 summary / metric_data / case_type_stats / all_metrics
       2. GET /reports/{id}/cases      翻页取全量用例（per_page=200）
       3. render_raw_report_html(...)  服务端渲染同构 HTML（可折叠用例卡 + 纯 DOM 脚本）
       4. 写入 Studio 导出作业目录，登记 export job（format=html/md, doc_id=raw:<report_id>）
       5. 返回 export_id / download_ref（鉴权下载，与 Studio 导出同一通道）
```

渲染器新增 `report_service/application/services/raw_report_renderer.py`：

- 输入：报告详情 + 全量用例；
- HTML：内联 CSS + 内联 JS（`file://` 可用），每条用例 `<details>` 折叠，
  展开后分三块（对齐平台 `case-report-detail` 用例详情页）：
  1. **参考数据**：`referenceParams`（布尔 → 是 / 否）；
  2. **执行结果**：`algorithmResults` 按 `dimension_name` 分组（子维度归父维度，
     无维度归「设备/API 执行结果」），字段 = `label` + `param_code`，值按
     `param_type` 格式化（timestamp → `YYYY-MM-DD HH:mm:ss`，number → 2 位小数，
     boolean → 是 / 否，json 缩进 2）；元信息码（`device_type` / `total_rounds`
     等）与 `rounds` 开头的多轮结果不在此铺平；
  3. **评分指标**：`metrics` 按「轮次 × 资源 × 维度」列出 `metric → value`，
     主 / 子维度按 `parent_dimension_name` 归组；
- MD：汇总表 + 按用例分节（参考数据 / 执行结果 / 评分指标三块同构）；
- 不引用任何外部资源，不含音频。

> 实测口径（报告 506，188 条用例）：只有 24 条用例的 `metrics[].value` 非空，
> 106 条有 `algorithmResults`。用户在平台点开用例看到的「各维度值」大部分来自
> **执行结果**而非评分指标，所以渲染器必须同时承载两块，只做 `metrics` 会导出
> 一张全是「—」的空表。

### 3.1.1 注册表三处登记（踩坑）

新增意图工具要同时在三处登记，缺一处执行期就会失败：

| 位置 | 作用 | 漏登记的表现 |
|---|---|---|
| `shared/agent_tools/intent_tools.py` `IntentTool` + `LOCAL_INTENT_TOOL_NAMES` | Schema / 风险 / 权限 / 本地工具分派 | 工具不存在 |
| `shared/agent_tools/mcp_registry.py` `_tool(...)` | 目标 REST（`resolve_rest_call` 走 `_lookup_rest_tool`） | 审批后执行返回 `未知工具：report_studio_export_raw_report` |
| `skills/report-studio/SKILL.md` `allowed-tools` | Skill 装配表范围校验（`_scope_denial`） | `SKILL_TOOL_DENIED`，执行期被拒 |

### 3.2 前端：ZIP 快照保留音频入口

`result-field.tsx` 的「播放音频」按钮加 `data-export-audio-hint`，导出克隆时
不删除，改为置灰 + 提示文案「音频需在平台内播放」。

### 3.3 鉴权 / 权限

- 权限码复用 `report:read`（只读取数）+ `report:studio:export`（产出文件）；
- 下载走现有 `GET /report-studio/exports/{id}/download`，按 `created_by` 归属。

## 4. 验收

| # | 项 | 期望 |
|---|---|---|
| 1 | `report_export_raw` html | 产物含全部用例，每条可展开，展开后参考数据 / 执行结果 / 评分指标三块可见 |
| 2 | `report_export_raw` md | 产物含全部用例的三块明细表 |
| 3 | 数值一致 | 产物数值与 `GET /reports/{id}` / `cases` 完全一致 |
| 4 | 音频 | ZIP 产物中音频入口保留并标注"需在平台内播放" |
| 5 | 回归 | 现有 `report_export`（Studio）行为不变 |
| 6 | Skill 装配 | `report-studio` 的 `allowed-tools` 含 `report_export_raw`，激活 Skill 后可调用 |
