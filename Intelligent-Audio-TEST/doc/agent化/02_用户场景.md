## 二、音频导入与标注

### 场景 1：批量导入音频 + 自动标注

**用户**：测试工程师\
**触发方式**：对话面板输入

```
用户："帮我导入这批录音文件，URL列表我贴在下面了，
      标注也一起带上，按目录结构自动打标签"

Agent:
  1. 解析 URL 列表
  2. 调用 import_audio_from_url 逐个导入
  3. 自动提取目录结构作为标签
  4. 调用 batch_annotate_audios 批量标注
  5. 汇报："已导入 50 条音频，自动打标签 5 类：
          对话(15) / 命令(12) / 噪声(8) / 翻译(10) / ASR(5)"
```

### 场景 2：上传音频 + 自动提取标注

**用户**：测试工程师\
**触发方式**：对话面板 + 文件上传

```
用户："这个音频文件上传一下，标注在随附的 JSON 里"

Agent:
  1. 调用 upload_audio_with_annotations
  2. 自动持久化标注数据到 audio_annotations 表
  3. 自动剔除用例参数字段，只保留参考参数+元数据
  4. 汇报："音频已上传，标注已提取：
          - ASR 文本: '播放一首歌'
          - 参考翻译: 'play a song'
          - 分段数: 3
          - 时长: 12.5s"
```

### 场景 3：本地文件批量上传 + LLM 整理

**用户**：测试工程师\
**触发方式**：对话面板 + 文件批量上传

用户本地有一批音频+标注文件，不想手动逐个上传配置，让 Agent 自动整理。

```
用户：[拖拽上传 50 个文件到对话面板]
用户："这批文件帮我整理一下上传，
      音频是 wav，标注是同名 json，按文件夹名打标签"

Agent:
  1. 前端解析上传的文件列表，发现 25 个 wav + 25 个 json
  2. Agent 要求前端："先给我看 2 条标注内容，我分析下数据结构"
     → 前端读取 audio_001.json 和 audio_013.json 内容发给 Agent
  3. LLM 分析标注内容，理解数据结构：
     - 字段：text / segments / translation / speaker_count / language
     - 哪些字段提取为算法参数（input_text / reference_translation）
     - 哪些字段是参考参数
     - 标注格式是否统一
  4. LLM 分析文件名和目录结构：
     - /对话场景/ → 标签: 对话
     - /命令场景/ → 标签: 命令
     - /噪声场景/ → 标签: 噪声
  5. LLM 自动匹配 wav 和 json 的对应关系（同名匹配）
  6. 发现 audio_004 无标注 → interrupt 问用户：
     "audio_004 无标注，自动生成空标注还是跳过？"
  7. 前端按 Agent 计划逐个上传文件（FormData）
     → 后端 upload_audio_with_annotations 接收
  8. 汇报："已整理并上传 25 条音频：
          对话(10) / 命令(8) / 噪声(7)
          标注匹配率: 96%（24/25，1条无标注已生成空标注）
          参数提取: 从标注中提取 input_text / reference_translation
          有 2 条标注缺失 speaker_count，已自动从音频分析补全"
```

**前端交互流程**：

```
┌─ 对话面板 ──────────────────────────────────────┐
│                                                 │
│  用户拖拽文件到此处                               │
│  ┌─────────────────────────────────────────┐   │
│  │ 📁 对话场景/                              │   │
│  │   📄 audio_001.wav  📄 audio_001.json   │   │
│  │   📄 audio_002.wav  📄 audio_002.json   │   │
│  │ 📁 命令场景/                              │   │
│  │   📄 audio_003.wav  📄 audio_003.json   │   │
│  │ 📁 噪声场景/                              │   │
│  │   📄 audio_004.wav  (无标注)             │   │
│  └─────────────────────────────────────────┘   │
│                                                 │
│  AI: 检测到 25 个文件，正在分析结构...           │
│  AI: 请先让我看 2 条标注内容...                  │
│  AI: 标注字段: text/segments/translation/        │
│      speaker_count，格式统一                    │
│  AI: 参数提取: input_text + reference_translation │
│  AI: 发现 3 个分组，标注匹配 24/25               │
│  AI: audio_004 无标注，自动生成空标注还是跳过？  │
│  用户: "生成空的就行"                            │
│  AI: 上传中 [████████░░] 20/25                  │
│  AI: 上传完成，25 条音频已入库                   │
└─────────────────────────────────────────────────┘
```

**技术实现**：

前端负责文件读取和解析（浏览器 File API），Agent 负责分析整理和异常处理：

```
1. 用户拖拽文件 → 前端 File API 读取文件列表（文件名+目录结构+大小）
2. 前端把清单发给 Agent → Agent 初步分析：25 wav + 25 json，3 个文件夹
3. Agent 要求前端采样 2 条标注内容 → 前端读取 JSON 内容发给 Agent
4. Agent (LLM) 分析标注内容：
   - 理解字段结构（text/segments/translation/speaker_count）
   - 识别哪些字段提取为算法参数、哪些是参考参数
   - 判断标注格式是否统一
5. Agent 生成上传计划：
   - 音频↔标注配对（同名匹配）
   - 目录结构 → 标签映射
   - 参数提取规则
   - 发现异常（缺标注/格式不一致）→ interrupt 询问用户
6. 前端按 Agent 计划逐个读取文件内容 → FormData 上传
   → 后端 upload_audio_with_annotations 接收
7. Agent 实时汇报上传进度和结果
```

**关键分工**：Agent 不碰文件内容（不读二进制），只做分析大脑；前端做读取和上传的手脚。采样读取标注是为了让 LLM 理解数据结构，不全读（只读 2 条，token 消耗可控）。
