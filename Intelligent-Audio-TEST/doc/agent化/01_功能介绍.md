## 产品主线与优先级（2026-10-08 补充）

**报告管理及对话式 Report Studio 是本项目 Agent 化的核心产品能力**，不以“通用 Agent 能做多少业务工具”为第一阶段价值指标。应先交付单任务/多任务对比/二次对比报告的“读取权威数据→AI 起草→对话调整→图表→版本恢复→PDF/PPTX/HTML/MD 导出”闭环，通用 Agent 工作台、设备驱动生成、重试自动化为后续能力。

- 主入口：现有报告中心和报告详情页，支持“标准报告 / AI 文档报告”模式；不强制用户先进入通用 `/agent`。
- AI 只负责撰写、解读和受控编辑，所有数字、聚合口径及图表数据由现有 Report Service 和报告 7 表提供。
- DeepSeek Harness 作为统一 Agent Runtime；Report Studio 与其他 Agent 使用相同引擎、不同业务 UI。文档及导出采用独立可恢复版本。
- 首个可对用户交付的里程碑需有真实 PDF/PPTX 报告产物，不能只停留在对话/摘要演示。详见 [05_报告优先实施路线图.md](05_报告优先实施路线图.md)。

## 一、概述

### 1.1 什么是 Agent 化

将现有测试平台从"人操作界面完成每一步"升级为"人用自然语言描述目标，Agent 自主规划并执行全流程"。

改造前：
```
用户手动操作：导入音频 → 写标注 → 建用例 → 配维度 → 创建任务 → 启动执行 → 查看结果 → 生成报告
```

改造后：
```
用户说："帮我导入这批音频，按标注内容分3类生成用例，跑一遍测试，出个分析报告"
Agent 自主完成全部步骤，关键操作前向用户确认
```

### 1.2 核心价值

| 维度 | 改造前 | 改造后 |
|---|---|---|
| 操作方式 | 逐页面手动操作 | 自然语言对话，一句话触发全流程 |
| 用例创建 | 手动填写每轮配置 | AI 读取标注自动生成 |
| 设备驱动 | 每接新设备手写代码 | 用户在 UiAutoDev 选元素，AI 自动生成驱动 |
| 结果分析 | 看数字自己判断 | LLM 自动分析，自然语言报告 |
| 失败排查 | 翻日志找原因 | AI 自动诊断，给出修复建议 |
| 批量任务 | 逐个手动执行 | Auto 自动化，受预算约束并实时汇报 |

## 三、功能模块详解

### 3.1 音频导入与标注管理

Agent 能够自动化音频导入流程，并根据标注内容智能分类。

**工具清单**：

| 工具 | 说明 |
|---|---|
| `import_audio_from_url` | 从 URL 导入音频，自动提取目录结构作为标签 |
| `upload_audio_with_annotations` | 上传音频 + 标注，自动持久化标注数据 |
| `batch_annotate_audios` | 批量给多个音频添加标注 |
| `update_audio_metadata` | 更新音频元数据（名称/标签/算法关联） |
| `get_folder_tree` | 获取音频文件夹树，支持多维筛选 |

**典型场景**：
- 用户："把这批录音文件导入进来，标注也一起带上"
- Agent 调用 `upload_audio_with_annotations` → 自动提取标注 → 按内容分类

### 3.2 用例生成与编辑

Agent 读取音频标注内容，根据标注类型自动生成不同场景的测试用例，支持对话式微调。

**工具清单**：

| 工具 | 说明 |
|---|---|
| `list_test_cases` | 列出用例，支持按算法/类型/关键词/标签筛选 |
| `get_test_case_detail` | 获取用例完整配置 |
| `create_test_case` | 创建用例（含多轮配置+评估维度） |
| `update_test_case` | 编辑用例（name/rounds/dimensions/algorithmParams） |
| `update_test_case_name` | 只改用例名称 |
| `duplicate_test_case` | 复制用例做变体 |
| `delete_test_case` | 删除用例（软删除） |
| `update_round_config` | 编辑某一轮配置（audios/algorithmParams/evaluation） |
| `add_round` / `remove_round` | 增删轮次 |
| `refresh_reference_params` | 根据标注重新生成参考参数 |

**典型场景**：
- 用户："看看这批音频的标注，按内容分成对话/命令/噪声三类用例"
- Agent：`batch_get_annotations` → LLM 分析分类 → `create_test_case` × 3

### 3.12 设备驱动生成

Agent 通过 UiAutoDev 获取用户选择的 UI 元素信息，结合 LLM 生成设备驱动代码。

**核心机制**：用户在 UiAutoDev 中选择关键 UI 元素，元素信息自动推送到对话面板，LLM 基于这些精确的元素信息（resource_id / xpath / text / class）生成继承 BaseDeviceDriver 的驱动类代码。

**工具清单**：

| 工具 | 说明 |
|---|---|
| `receive_picked_elements` | 接收 UiAutoDev 推送的选中元素，附加到当前会话 |
| `generate_driver_from_elements` | 基于用户选择的元素信息 + 描述，LLM 生成驱动代码提案 |
| `publish_driver_proposal` | 代码提案经静态检查/隔离测试与人工审批后，受控发布并注册到 DriverFactory |

**工作流程**：

```
1. 用户在 UiAutoDev 中连接设备，浏览 APP 界面
2. 用户在 UiAutoDev 元素树中点选关键元素（录音按钮/结果文本等）
   → 元素信息自动推送到对话面板，出现元素卡片
3. 用户为每个卡片选择操作类型（点击/输入/提取/等待）
4. 用户点"发送" → LLM 收到所有元素卡片 → 生成驱动代码提案
5. 提案经静态检查与隔离环境测试 → 用户确认 → 受控发布写入驱动目录并注册到 DriverFactory
```

**支持的系统**：

| 系统 | 命令工具 | UI 框架 | 元素定位方式 |
|---|---|---|---|
| Android | adb | uiautomator2 | resource_id / xpath / text |
| HarmonyOS | hdc | hypium (UiDriver/By) | By.text / By.id |
| iOS | wda | facebook-wda | name / label / value |

**典型场景**：
- 用户："帮我写豆包APP的Android驱动"
- 用户在 UiAutoDev 中选择：语音入口按钮 → 录音按钮 → 停止按钮 → 结果文本
- Agent 接收元素信息 → `generate_driver_from_elements` → 生成代码提案 → 检查/审批 → 受控发布注册

## 四、运行模式

### 4.1 交互模式

每步关键操作前向用户确认，适合需要人把控的场景。

```
用户："帮我根据这批音频标注自动生成用例"
  ↓
Agent: "已读取50条标注，识别出3类场景，生成3个用例，确认创建吗？"
  ↓ 用户确认
Agent: 执行创建 → "3个用例已创建，继续执行测试吗？"
  ↓ 用户确认
Agent: 执行测试 → ...
```

### 4.2 Auto 模式（自主模式）

Agent 按应用层编排的步骤自主执行，写操作生成审批提案，运行受预算约束，进度实时推送；异常或超出重试策略时暂停。适合批量任务和无人值守场景。

```
用户："帮我导入音频 → 生成用例 → 跑测试 → 出报告，全程自动"
  ↓
[Auto 自动化启动]
  步骤 1: 读取标注 → 分类
  步骤 2: 生成用例 + 打标签（写操作，生成审批提案）
  步骤 3: 用户批准 → 创建用例
  步骤 4: 创建任务（写操作，生成审批提案）→ 用户确认后启动
  步骤 5-11: 轮询任务状态
  步骤 12: 收集结果
  步骤 13: LLM 分析
  步骤 14: "全流程完成，报告如下：..."
```

### 4.3 两种模式对比

| 维度 | 交互模式 | Auto 模式 |
|---|---|---|
| 确认频率 | 每个关键写操作前 | 计划级批量审批；已授权操作不重复确认 |
| 适用场景 | 需要人把控的精细操作 | 批量任务、重复流程 |
| 异常处理 | 暂停等用户决策 | 按工具契约限次重试，超限暂停 |
| 运行上限 | 不限 | 受工具调用数/时长/token 预算约束（可配置） |

## 六、上下文管理

Agent 采用 5 层上下文管理，确保长任务不丢失信息：

| 层 | 机制 | 作用 |
|---|---|---|
| 第1层 | 工具结果压缩 | 工具返回只保留摘要，完整数据存领域服务/对象存储 |
| 第2层 | 上下文分区 | 结构化证据不进对话消息，按任务按需装配 |
| 第3层 | 消息窗口策略 | 对话历史只保留最近 N 轮 + 任务摘要 |
| 第4层 | Agent Run 持久化 | PostgreSQL 保存运行、步骤、审批与事件游标；按已完成业务步骤恢复，进程重启后可续传 |
| 第5层 | 按需证据与工具隔离 | 每次模型调用只装配当前任务所需证据；工具按权限和风险分域，不传递无关完整历史 |

## 七、安全与隔离

Agent 主进程只运行固定的 Harness 与注册工具，不执行模型生成的任意代码，不提供通用 Shell 或任意文件读写。领域操作通过现有受认证服务 API 完成，并在服务端校验权限与领域状态。

设备驱动代码由 LLM 生成**代码提案**，不直接写入生产目录：先经格式/语法/静态检查与隔离环境测试，人工审批通过后由受控发布流程落地，并记录版本与操作者。设备操作通过设备服务类型化 API，校验设备授权、租用状态并记录审计。

若未来需要自动执行生成代码，必须另立安全评审与隔离运行方案，至少包含无特权容器、只读基础镜像、受限临时文件系统、默认禁网、资源与输出限制、凭证隔离及设备代理白名单；静态检查不能替代沙盒，不支持安全隔离的环境不得降级为本机子进程执行。
