## 一、概述

### 1.1 什么是 Agent 化

将现有测试平台从"人操作界面完成每一步"升级为"人用自然语言描述目标，Agent 自主规划并执行全流程"。

改造前：
```
用户手动操作：导入音频 → 写标注 → 建用例 → 配维度 → 创建任务 → 启动执行 → 查看结果 → 生成报告
```

改造后：
```
用户说："帮我导入这批音频，按标注内容分3类生成用例，跑一遍测试，出个分析报告"
Agent 自主完成全部步骤，关键操作前向用户确认
```

### 1.2 核心价值

| 维度 | 改造前 | 改造后 |
|---|---|---|
| 操作方式 | 逐页面手动操作 | 自然语言对话，一句话触发全流程 |
| 用例创建 | 手动填写每轮配置 | AI 读取标注自动生成 |
| 设备驱动 | 每接新设备手写代码 | 用户在 UiAutoDev 选元素，AI 自动生成驱动 |
| 结果分析 | 看数字自己判断 | LLM 自动分析，自然语言报告 |
| 失败排查 | 翻日志找原因 | AI 自动诊断，给出修复建议 |
| 批量任务 | 逐个手动执行 | Solo 模式无人值守，定期汇报 |

## 三、功能模块详解

### 3.1 音频导入与标注管理

Agent 能够自动化音频导入流程，并根据标注内容智能分类。

**工具清单**：

| 工具 | 说明 |
|---|---|
| `import_audio_from_url` | 从 URL 导入音频，自动提取目录结构作为标签 |
| `upload_audio_with_annotations` | 上传音频 + 标注，自动持久化标注数据 |
| `batch_annotate_audios` | 批量给多个音频添加标注 |
| `update_audio_metadata` | 更新音频元数据（名称/标签/算法关联） |
| `get_folder_tree` | 获取音频文件夹树，支持多维筛选 |

**典型场景**：
- 用户："把这批录音文件导入进来，标注也一起带上"
- Agent 调用 `upload_audio_with_annotations` → 自动提取标注 → 按内容分类

### 3.2 用例生成与编辑

Agent 读取音频标注内容，根据标注类型自动生成不同场景的测试用例，支持对话式微调。

**工具清单**：

| 工具 | 说明 |
|---|---|
| `list_test_cases` | 列出用例，支持按算法/类型/关键词/标签筛选 |
| `get_test_case_detail` | 获取用例完整配置 |
| `create_test_case` | 创建用例（含多轮配置+评估维度） |
| `update_test_case` | 编辑用例（name/rounds/dimensions/algorithmParams） |
| `update_test_case_name` | 只改用例名称 |
| `duplicate_test_case` | 复制用例做变体 |
| `delete_test_case` | 删除用例（软删除） |
| `update_round_config` | 编辑某一轮配置（audios/algorithmParams/evaluation） |
| `add_round` / `remove_round` | 增删轮次 |
| `refresh_reference_params` | 根据标注重新生成参考参数 |

**典型场景**：
- 用户："看看这批音频的标注，按内容分成对话/命令/噪声三类用例"
- Agent：`batch_get_annotations` → LLM 分析分类 → `create_test_case` × 3

### 3.12 设备驱动生成

Agent 通过 UiAutoDev 获取用户选择的 UI 元素信息，结合 LLM 生成设备驱动代码。

**核心机制**：用户在 UiAutoDev 中选择关键 UI 元素，元素信息自动推送到对话面板，LLM 基于这些精确的元素信息（resource_id / xpath / text / class）生成继承 BaseDeviceDriver 的驱动类代码。

**工具清单**：

| 工具 | 说明 |
|---|---|
| `receive_picked_elements` | 接收 UiAutoDev 推送的选中元素，存入会话 State |
| `generate_driver_from_elements` | 基于用户选择的元素信息 + 描述，LLM 生成驱动代码 |
| `register_driver_to_factory` | 将生成的驱动注册到 DriverFactory |

**工作流程**：

```
1. 用户在 UiAutoDev 中连接设备，浏览 APP 界面
2. 用户在 UiAutoDev 元素树中点选关键元素（录音按钮/结果文本等）
   → 元素信息自动推送到对话面板，出现元素卡片
3. 用户为每个卡片选择操作类型（点击/输入/提取/等待）
4. 用户点"发送" → LLM 收到所有元素卡片 → 生成驱动代码
5. 用户确认 → 代码写入文件 → 注册到 DriverFactory
```

**支持的系统**：

| 系统 | 命令工具 | UI 框架 | 元素定位方式 |
|---|---|---|---|
| Android | adb | uiautomator2 | resource_id / xpath / text |
| HarmonyOS | hdc | hypium (UiDriver/By) | By.text / By.id |
| iOS | wda | facebook-wda | name / label / value |

**典型场景**：
- 用户："帮我写豆包APP的Android驱动"
- 用户在 UiAutoDev 中选择：语音入口按钮 → 录音按钮 → 停止按钮 → 结果文本
- Agent 接收元素信息 → `generate_driver_from_elements` → 生成代码 → `register_driver_to_factory`

## 四、运行模式

### 4.1 交互模式

每步关键操作前向用户确认，适合需要人把控的场景。

```
用户："帮我根据这批音频标注自动生成用例"
  ↓
Agent: "已读取50条标注，识别出3类场景，生成3个用例，确认创建吗？"
  ↓ 用户确认
Agent: 执行创建 → "3个用例已创建，继续执行测试吗？"
  ↓ 用户确认
Agent: 执行测试 → ...
```

### 4.2 Solo 模式（自主模式）

Agent 自主跑完全程，定期 check-in 汇报进度，异常时暂停。适合批量任务和无人值守场景。

```
用户："帮我导入音频 → 生成用例 → 跑测试 → 出报告，全程自动"
  ↓
[Solo Mode 启动]
  轮 1: 读取标注 → 分类
  轮 2: 生成用例
  轮 3: 打标签
  轮 4: check-in → "已生成3个用例，继续执行测试吗？"（用户可选跳过后续确认）
  轮 5: 创建任务
  轮 6-12: 轮询任务状态
  轮 13: 收集结果
  轮 14: LLM 分析
  轮 15: "全流程完成，报告如下：..."
```

### 4.3 两种模式对比

| 维度 | 交互模式 | Solo 模式 |
|---|---|---|
| 确认频率 | 每个关键操作前 | 每 N 轮 check-in 一次 |
| 适用场景 | 需要人把控的精细操作 | 批量任务、重复流程 |
| 异常处理 | 暂停等用户决策 | 自动重试3次，超限暂停 |
| 最大循环 | 不限 | 50 轮（可配置） |

## 五、前端交互

### 5.1 对话面板

Agent 的主要交互界面，支持：

- **自然语言对话**：用户输入需求，Agent 理解并执行
- **流式输出**：SSE 流式传输，打字机效果
- **元素卡片**：UiAutoDev 选中元素自动出现在对话上下文中
- **确认面板**：关键操作前弹出确认（查看 diff / 确认 / 修改 / 取消）
- **进度展示**：Solo 模式下展示当前轮次和执行进度
- **上下文状态**：展示 Agent 当前"记得"什么（已读取的标注、已创建的用例等）

## 六、上下文管理

Agent 采用 5 层上下文管理，确保长任务不丢失信息：

| 层 | 机制 | 作用 |
|---|---|---|
| 第1层 | 工具结果压缩 | 工具返回只保留摘要，完整数据存 State |
| 第2层 | State 分区存储 | 结构化数据不进 messages，用独立字段承载 |
| 第3层 | 消息窗口策略 | 对话历史只保留最近5轮 + 任务摘要 |
| 第4层 | Checkpointer 持久化 | PostgreSQL 保存完整状态，进程重启可恢复 |
| 第5层 | 子图上下文隔离 | 每个子 Agent 有独立 messages，压缩后返回主图 |

## 七、沙盒与安全（未来扩展）

> **当前阶段不需要实现沙盒。** Agent 主要是调现有 API + LLM 文本分析，不涉及任意代码执行。设备驱动代码由 LLM 生成 → 用户在对话面板审批 → Agent 写入文件 → 注册到 DriverFactory。以下沙盒方案为未来 Agent 自动执行代码时启用。

Agent 生成的代码（设备驱动、测试脚本）不能直接在主进程执行，必须在沙盒中隔离运行。

| 防护层 | 机制 | 说明 |
|---|---|---|
| 代码静态检查 | AST 分析 | 禁止 import os/subprocess、禁止 eval/exec |
| Docker 容器隔离 | 文件系统/网络/进程隔离 | 只能写 /tmp，只能访问 ADB/HDC 端口 |
| 资源限制 | CPU/内存/超时 | 512MB 内存、1 CPU、60 秒超时 |
| 设备白名单 | USB 设备映射 | 只允许 ADB/HDC 端口，不直接访问硬件 |
| 降级方案 | 子进程隔离 | 无 Docker 环境用 subprocess + 超时 + 环境变量限制 |
