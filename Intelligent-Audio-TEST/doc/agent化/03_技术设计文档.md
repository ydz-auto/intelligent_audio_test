## 一、设计原则与技术选型

### 1.1 现状与决策

本设计文档是待实施方案。当前代码库没有 Agent 运行时、LangChain/LangGraph 或向量数据库依赖；服务主体是 FastAPI 微服务，API Gateway 已有认证、Redis Pub/Sub、SSE、Socket.IO，领域能力通过 HTTP/gRPC 提供。方案应接入现有边界，不照搬旧 Flask/Controller 结构。

本次决策采用轻量、可替换的编程 Agent Runtime（Harness）：明确的 Agent Loop + OpenAI 兼容模型协议 + 有类型/权限/审批约束的工具注册表 + 持久化任务状态。DeepSeek 是可选模型提供方，不是 Agent 框架；模型可按配置替换，并通过真实任务评测选型。

| 能力 | 决策 | 说明 |
|---|---|---|
| Agent 执行 | 自有轻量 Harness | 负责模型请求、工具调用循环、预算、停止条件、事件流；工作流确定时由应用代码显式编排，不让 Supervisor 自由路由全部 61 个工具 |
| 模型接入 | OpenAI-compatible HTTP API 适配器 | DeepSeek 可作为默认候选，开发/生产分别配置 endpoint、model、key、timeout；不将供应商 SDK 渗入 Domain/Application |
| 工具协议 | 内部 typed tool registry；MCP 作为跨进程/第三方工具的可选适配协议 | 本服务内调用使用受控应用端口，不因“Agent”而把所有内部函数暴露成远程工具 |
| 请求与流式 | FastAPI + 现有 SSE | Agent 事件沿用 SSE；执行进度/业务事件继续使用 Redis Pub/Sub 与既有推送链路 |
| 状态与任务 | PostgreSQL 持久化会话/运行/审批/工具审计；Redis 用于短期事件转发 | 不把完整业务数据或无限对话历史塞进单个 State；长任务使用持久化作业与可恢复步骤 |
| 人工审批 | 服务端审批状态机 | 高风险写操作先生成结构化提案，用户确认后由服务端校验并执行；不能只依赖 Prompt 或前端按钮 |
| 领域能力 | 调用现有 API/gRPC/Application 服务 | 不直接跨服务访问数据库，不让 Agent 绕过授权和领域规则 |
| 源码检索 | `rg` 精确搜索 + AST/LSP 结构化索引按需启用 | 检索结果必须带路径、行号和片段；只对授权仓库搜索，命令固定、参数转义、限制路径和输出量 |
| 知识检索 | 不默认部署向量 RAG | 业务事实走领域查询 API；源码走搜索工具；只有文档语义问答经评测证明有缺口，才单独增加文档检索能力 |
| 驱动生成 | UiAutoDev 元素选择 + 代码提案 + 沙盒验证 + 人工批准 | 生成代码不得由 Agent 直接写入生产目录或自动注册/执行 |

### 1.2 Agent Loop 边界

每轮运行由显式状态机控制：`接收请求 → 身份/权限解析 → 选择允许工具 → 模型决策 → 参数校验 → 风险审批（如需）→ 工具执行 → 结果摘要 → 继续或结束`。Runtime 必须实施调用次数、总时长、token、单工具超时和最大输出限制；达到任一预算即停止并返回可解释状态。重试只针对可判定的瞬时错误，并遵守幂等键，不能对有副作用的工具盲目重放。

默认从单 Agent + 窄工具集开始。仅当评测显示上下文/权限/延迟的隔离有明确收益时，再拆分专用 Agent；不预设 Supervisor + 8 子图。业务流程（导入→建用例→执行→报告）优先用应用层显式步骤编排，LLM 用于分类、参数抽取、摘要和受限决策，不负责猜测业务状态转换。

### 1.3 模型与工具契约

模型适配器只处理供应商协议和流式/非流式响应。每个工具声明稳定名称、版本、输入/输出 Pydantic Schema、所需权限、风险级别、超时、幂等策略及审计字段。模型输出只是“不可信的调用提议”；执行器重新校验用户身份、资源归属、权限、参数和当前领域状态。

只读工具可在权限范围内直接执行。创建、更新、删除、启动设备、发布报告、写文件等副作用操作默认需显式审批；审批记录绑定用户、资源、参数摘要、幂等键和过期时间，确认后再次校验状态。工具结果返回最小必要摘要和资源引用，避免把大体积音频/结果集送入模型。

### 1.4 依赖策略

当前不新增 LangChain/LangGraph、向量数据库或模型专属 SDK 作为核心依赖。首期仅增加经评审的 HTTP 客户端/模型协议实现及运行状态迁移；若后续引入 MCP、代码索引或文档搜索，分别作为可选 Adapter，并通过准确率、延迟、成本、安全和维护复杂度评测决定是否保留。

## 二、整体架构

### 2.1 架构图

```
前端对话面板
  ↓ HTTPS + SSE
API Gateway (FastAPI)
  ├── 认证/授权/限流/请求关联 ID
  ├── Agent Chat API：创建运行、续传事件、提交审批
  └── 现有 SSE / Socket.IO 推送保持职责不变
        ↓ 应用端口
Agent Runtime（独立模块，首期随 API Gateway 部署）
  ├── 固定 Agent Loop（预算、停止、超时、幂等）
  ├── Model Adapter（OpenAI-compatible；DeepSeek 可配置）
  ├── Tool Registry（按用户权限装配窄工具集）
  ├── Policy/Approval Service（审批状态机 + 审计）
  ├── Context Builder（近期对话 + 任务摘要 + 按需证据）
  └── Search Adapter（仅授权工作区的 rg/结构化代码搜索）
        ↓ 受控 HTTP/gRPC 客户端
现有领域服务（task/audio/device/evaluation/report 等）
        ↓
PostgreSQL：会话、Agent Run、审批、工具审计、步骤状态
Redis：短期事件转发/进度通知，不作为唯一任务状态存储
```

设备驱动代码生成/验证采用隔离的独立工作流：UiAutoDev 元素 → 生成提案 → 静态检查/沙盒测试 → 人工审批 → 受控发布；不能由通用 Agent Loop 获得任意文件系统或 Shell 权限。

### 2.2 Agent 事件契约

SSE 使用带 `run_id`、单调递增 `sequence`、`event_type`、`created_at` 和结构化 `data` 的事件。首期事件类型固定为 `run_started`、`assistant_delta`、`tool_proposed`、`approval_required`、`tool_started`、`tool_completed`、`run_progress`、`run_completed`、`run_failed`。事件需能按运行 ID 重放；断线重连使用 Last-Event-ID 或显式 cursor。不得把内部 State、凭证、完整工具参数或未经脱敏的日志直接流给前端。

### 2.3 和现有系统的集成

| 现有组件 | Agent 集成方式 |
|---|---|
| API Gateway FastAPI 与 AuthMiddleware | 注册受认证/权限控制的 Agent 路由；会话归属以服务端身份为准，不信任请求体中的 user_id |
| 领域 HTTP/gRPC API | Tool Adapter 调用现有服务接口；继续执行各自权限、校验和领域规则 |
| PostgreSQL | 新增 Agent Run、Approval、Tool Audit 等独立持久化模型/迁移；不复用不存在的 LangGraph Checkpointer |
| Redis Pub/Sub | 用于运行事件和异步业务进度转发；关键运行状态仍以 PostgreSQL 为准 |
| `api_gateway/routes/sse_bp.py` | 复用现有 SSE 基础设施或新增专用 Agent SSE 路由；明确认证和重放契约 |
| Socket.IO | 保持现有任务日志/设备事件用途；不与 Agent 文本流重复承载 |
| MCP | 仅在需要与外部工具进程互操作时增加 MCP Server/Client Adapter；域内工具先走内部端口 |

## 三、目录结构

### 3.1 建议模块边界（按当前 FastAPI 仓库落地）

```
api_gateway/
  routes/agent_bp.py                 # 创建运行、查询运行、审批、SSE
  application/agent/
    run_service.py                   # 用例编排与运行生命周期
    agent_loop.py                    # 有预算的模型/工具循环

    policy_service.py                # 权限、风险分级与审批状态机
    tools/                            # 按业务域拆分的 typed tool adapters
    ports/                            # ModelClient、Tool、RunRepository 等端口
  infrastructure/agent/
    model_client.py                   # OpenAI-compatible HTTP Adapter
    run_repository.py                # PostgreSQL 实现
    event_publisher.py                # Redis/SSE 事件适配
    code_search.py                   # 受限 rg/AST 搜索适配器
  domain/agent/

    enums.py                          # 状态、风险等级、事件类型

frontend/src/

  components/agent/                   # Chat、审批、进度等展示组件

```

模块路径需与现有项目实际目录和命名规范对齐；不要照搬不存在的 `backend/` 或 Flask Blueprint 路径。Domain 不依赖模型 SDK、FastAPI、Redis 或数据库。工具 Adapter 只能调用已授权的 Application 端口或现有服务 API。

### 3.2 配置新增

Agent 配置放在 API Gateway 配置层，并按开发/生产环境注入，不提交真实密钥。配置项应包括 `AGENT_ENABLED`、`AGENT_MODEL_PROVIDER`、`AGENT_MODEL_NAME`、`AGENT_MODEL_BASE_URL`、`AGENT_MODEL_API_KEY`、`AGENT_REQUEST_TIMEOUT_SECONDS`、`AGENT_MAX_TOOL_CALLS`、`AGENT_MAX_RUN_SECONDS`、`AGENT_MAX_OUTPUT_BYTES`、`AGENT_APPROVAL_TTL_SECONDS`、`AGENT_SEARCH_ROOTS`、`AGENT_SEARCH_MAX_RESULTS`。运行预算应有集中默认值和启动校验，避免散落魔法数字。

## 四、核心执行设计

### 4.1 运行与步骤模型

运行状态以持久化领域模型表达，不把业务对象堆进通用 Agent State。`AgentRun` 记录身份、会话、状态、预算和终止原因；`RunStep` 记录步骤序号、步骤类型、输入/输出摘要、幂等键和执行状态；`Approval` 绑定用户、资源、操作摘要、到期时间与决定。状态值使用枚举，模型上下文只接收必要摘要。

```text
AgentRunStatus: queued | running | waiting_approval | completed | failed | cancelled | budget_exceeded
RunStepStatus: pending | running | completed | failed | skipped
ApprovalStatus: pending | approved | rejected | expired
```

### 4.2 Agent Loop

Application 层负责一个受预算约束的显式循环。模型只返回文本或结构化工具提议；循环检查停止条件、权限和预算，调用 Tool Registry 中的工具，再把受限结果加入下一轮上下文。流程型任务由 Application 用例显式编排，不依赖模型自由跳转节点。

```python
async def run_agent(run_id, request, user, services):
    while await services.budget.can_continue(run_id):
        decision = await services.model.complete(
            await services.context.build(run_id, request, user)
        )
        if decision.is_final:
            return await services.runs.complete(run_id, decision.text)

        proposal = services.tools.parse_proposal(decision.tool_call)
        result = await services.policy.validate_and_execute(
            run_id=run_id,
            user=user,
            proposal=proposal,
        )
        await services.context.append_tool_result(run_id, result.summary)

    return await services.runs.stop_for_budget(run_id)
```

上述伪代码展示职责边界，不限定具体模型 SDK 或协程实现。每轮模型请求和工具执行都记录步骤；预算耗尽、用户取消、模型错误和工具错误使用不同终止状态。重试策略属于具体工具契约，副作用操作必须幂等且不得由通用循环盲目重放。

### 4.3 工具注册与执行

工具描述包含稳定名称/版本、Pydantic 输入输出 Schema、所需权限、风险等级、超时、幂等策略和审计策略。注册表只向当前用户暴露允许的窄工具集；执行器不接受模型提供的模块名、函数名、URL 或命令作为动态调用目标。

```python
class ToolDefinition:
    name: str
    version: str
    input_schema: type[BaseModel]
    output_schema: type[BaseModel]
    required_permissions: frozenset[Permission]
    risk_level: ToolRiskLevel
    timeout_seconds: int
    requires_approval: bool
    idempotent: bool
```

Tool Adapter 通过 Application 端口或领域服务 API 完成业务操作，不直接调用 Controller 私有方法或跨服务数据库。调用前重新读取资源并验证归属、状态和权限；结果只返回模型所需的最小摘要、分页数据或资源引用。

### 4.4 审批状态机

需要审批的工具调用先保存不可变提案，并将 AgentRun 转为 `waiting_approval`。审批 API 校验审批人权限、提案归属、有效期和一次性状态；批准后执行器重新检查资源状态与授权，再以提案绑定的幂等键调用目标服务。拒绝、过期、重复提交或资源已变化时不执行。

```text
提案创建 → pending
pending → approved → 执行中 → completed / failed
pending → rejected / expired
```

前端只展示服务端提案与审批结果；不能通过修改请求体、Prompt 或客户端状态绕过审批策略。Auto/自动化模式不得提升写权限，也不能跳过高风险操作的审批。

### 4.5 受限代码搜索

源码检索提供专用 Search Adapter，不向 Agent 暴露通用 Shell。首期仅接受结构化参数：授权工作区标识、字面搜索词或受限正则、文件类型、路径范围、结果上限。Adapter 将工作区映射到服务端配置的根目录，使用参数数组调用固定的 `rg` 可执行文件，不拼接 Shell 命令；路径规范化后必须仍位于授权根目录内。

搜索结果返回工作区相对路径、行号、匹配片段和截断标记。限制正则复杂度、扫描文件类型、最大命中数、单次耗时和总输出字节数；排除凭证、构建产物、依赖缓存及二进制文件。需要符号关系或精确重构时再评估 AST/LSP 索引，不能把 grep 命中当作完整程序语义。

### 4.6 驱动生成与设备操作

UiAutoDev 选中的元素和用户描述作为输入，由模型生成代码提案；代码保存到隔离的提案存储，不写入生产目录、不修改 DriverFactory。随后执行格式/语法/静态检查和隔离环境测试，审阅通过后由受控发布流程写入目标仓库并记录版本与操作者。

设备调试通过设备服务的类型化 API 操作，并校验用户对设备的授权、设备租用状态和允许动作。每步操作记录审计并按风险要求确认；截图通过受限资源引用提供，避免把大体积 Base64 图片反复放入上下文。Agent 不获得任意文件系统、Shell、ADB/HDC 命令或生产设备直连权限。

### 4.7 模型适配器

`ModelClient` 作为 Application 端口，基础设施 Adapter 通过配置的 OpenAI-compatible HTTP API 实现请求、结构化输出和流式 token 解析。请求超时、重试、模型名、最大输出和密钥均由环境配置管理；开发与生产凭证隔离。供应商特有字段不得进入 Domain 模型，模型响应视为不可信输入并经 Schema 校验。

### 4.8 API 与事件流

在 API Gateway 注册 FastAPI Agent 路由，接口至少包括创建运行、读取运行、读取/续传事件、审批和取消。请求身份来自认证中间件；请求体不允许指定其他用户身份。SSE 仅承载面向客户端的事件契约，服务端以 PostgreSQL 运行记录和事件序号为准，Redis Pub/Sub 仅用于实例间唤醒/转发。

UiAutoDev 元素选择使用经过认证、绑定会话归属的 API 或现有实时通道，不能直接写入运行状态。事件字段、断点续传和敏感字段过滤按第二章契约实施；现有业务 SSE 与 Socket.IO 的职责保持不变。

## 五、上下文、持久化与可观测性

### 5.1 上下文构建

每次模型调用都由 Context Builder 生成有上限的上下文：系统策略、当前用户请求、最近对话窗口、持久化任务摘要，以及为当前决策按需获取的最小业务证据。音频、完整评估结果和大型日志保存在领域服务/对象存储中，只向模型提供摘要、分页片段和受控引用。摘要不能被当作事实来源；涉及业务状态时必须重新查询领域服务。

### 5.2 运行状态持久化

PostgreSQL 记录会话、运行状态、当前步骤、预算使用量、待审批提案、工具调用审计和事件游标。每个有副作用步骤在执行前写入 `pending`，以幂等键调用领域服务，收到结果后写入 `completed`；恢复时对 `pending` 步骤先查询/核对领域状态，不盲目重复执行。对话消息设置保留和删除策略，密钥、设备凭证、音频二进制和未脱敏日志不进入模型上下文或审计参数。

### 5.3 长任务恢复

长任务用持久化运行记录和可恢复业务步骤恢复，而非依赖进程内循环或仅有数据库快照。测试任务本身仍由 task_service 管理；Agent 订阅/查询既有任务状态并汇总结果。客户端断线不会取消已提交的任务，用户可以按 `run_id` 查询状态、继续审批或终止尚未提交的步骤。

### 5.4 可观测性

每个运行贯穿 `request_id`、`conversation_id`、`run_id`、`user_id`、工具名/版本、模型名、耗时、token 用量、审批决定和错误类别。日志避免记录完整 Prompt、密钥、敏感音频信息及未脱敏工具参数。监控至少覆盖成功率、失败分类、工具调用分布、模型延迟、人工审批率、单位任务成本和预算中止率。

## 六、安全与隔离

Agent 主进程只运行固定的 Harness 和注册工具，不执行模型生成的任意代码，不提供通用 Shell、任意 URL 请求或任意文件读写。业务工具调用现有受认证服务接口，并在服务端应用层校验权限和领域状态。

源码搜索通过第二章定义的专用 `rg` Adapter 限定授权根目录、参数、文件类型、耗时和输出；这不是 Shell 能力，也不能用于执行命令。文件生成只写入隔离的提案存储，发布与设备操作都经独立审批和审计流程。

若未来要执行生成代码，必须另立安全评审与隔离运行方案，至少包括无特权容器、只读基础镜像、受限临时文件系统、默认禁网、CPU/内存/时间/输出限制、凭证隔离及设备代理白名单。静态检查不能替代沙盒，也不能单独证明代码安全；不支持安全隔离的环境不得降级为本机子进程执行。

### 6.1 安全策略矩阵

| 能力 | Agent Runtime | 受控 Adapter / 隔离流程 |
|---|---|---|
| 领域查询/命令 | 不直连数据库 | 通过授权的领域服务 API；写命令按风险审批 |
| 源码检索 | 不提供通用 Shell | 固定参数化 `rg` 适配器，仅搜索授权工作区 |
| 文件读取/写入 | 无任意文件系统权限 | 读取限定搜索结果；生成内容写入提案存储 |
| 生成代码执行 | 禁止 | 未来经独立安全评审后使用隔离环境 |
| 设备操作 | 不直连设备/ADB/HDC | 设备服务 API、租用校验、操作审计与必要审批 |
| 外部网络 | 不允许模型指定目标 URL | 仅由配置端点的模型/服务 Adapter 发起请求 |

## 七、运行预算与停止策略

每次运行应用统一配置的工具调用数、总时长、模型 token、单工具超时和最大输入/输出字节数。任一预算耗尽即以明确终止原因结束，不通过无限递归或隐式自动重试继续运行。用户取消、错误和预算中止均落库并产生事件。

Auto 表示可以自动串联已授权的只读步骤和明确批准过的业务流程，不代表无限循环或放宽权限。高风险写操作仍进入审批状态机；定期进度事件用于可见性，不替代审批。模型和工具错误按可重试类别处理，重试次数与退避由配置和工具幂等契约共同限制。

## 八、前端设计

### 8.1 分层与领域模型

前端遵守项目分层约束：`views/` 和 `components/` 只消费 camelCase Domain 与 composables Ports；Application composables/store 编排用例并缓存 ReadModel；Domain 模型零依赖；Infrastructure 的 API/DTO/Adapter 负责 snake_case 转换。页面不直接解析底层 SSE DTO 或调用 Infrastructure HTTP 客户端。

核心模型至少包含 `conversationId`、`runId`、`runStatus`、`sequence`、消息、结构化工具提案、审批状态和进度。状态与事件类型用枚举/联合类型表达；不使用 `any`、索引签名兜底或供应商特有字段。

### 8.2 对话与审批交互

页面提供对话、运行状态、工具执行进度、待审批提案和取消运行操作。批准/拒绝针对服务端生成的 `approvalId` 提交；不能用自由文本命令恢复 Agent 内部状态。断线后根据 `runId` 和最后 `sequence` 续传事件，历史 ReadModel 从 API 获取。

### 8.3 SSE 消费

Infrastructure Adapter 将 SSE DTO 转为 Domain 事件，Application composable 根据事件更新消息、运行状态、审批和进度 ReadModel。`assistant_delta` 只追加文本；`approval_required` 创建待审提案；终止事件结束流。重复/旧 `sequence` 不重复应用，序号缺口触发续传查询。

UiAutoDev 选择的元素作为经过校验的 Domain 输入附加到当前会话，不通过页面直接访问 Socket.IO 或将不可信字段扩散到 Domain。

***

## 九、编排决策与边界

方案采用显式 Agent Loop，而不是在多个 Agent 框架或平台托管 Runtime 之间做抽象兼容。编排复杂度留在 Application 用例和工具契约中，运行记录、审批和事件流使用项目现有 PostgreSQL、FastAPI、Redis Pub/Sub 与 SSE 基础设施。

首期不预设 Supervisor、多 Agent 或 61 个工具的全集注册。按场景逐步开放只读工具，评测分类/参数抽取/任务完成率、错误率、延迟、成本和审批负担；只有确实需要隔离上下文或权限时才引入专用 Agent/独立服务。MCP 仅用于跨进程互操作，不作为域内调用的默认协议。

## 十、设备驱动生成方案对比

### 10.1 方案对比

| 方案               | 谁探索  | 准确性 | 速度 | 用户控制力 | 部署成本      |
| ---------------- | ---- | --- | -- | ----- | --------- |

### 10.2 选择 UiAutoDev + LLM 的理由

1. UiAutoDev 原生界面已足够好用，不造轮子
2. 人比 AI 更懂哪个元素是关键，选择更精确
3. UiAutoDev 直接给 resource\_id/xpath，LLM 只做代码生成
4. 不需要跑 9B VLM 模型，部署简单
5. 三平台通用（Android/harmonyOS/iOS）

### 10.3 OpenAutoGLM 作为可选增强

如果后续需要自主探索能力，可以集成 OpenAutoGLM 作为可选模块：

* OpenAutoGLM 做初步探索，找到大致操作链路

* UiAutoDev 补充精确元素信息

* 两者数据合并后喂给 LLM 生成代码

## 十一、设计取舍与验证

### 11.1 Runtime 与模型解耦

Harness 由项目维护，以小型显式循环、稳定工具契约和持久化运行模型为核心。DeepSeek 等模型只是配置项，候选需通过代表性任务集评测后决定；不把“开源”或单次演示效果作为唯一选型依据。模型 API 失败时返回明确错误状态，不自动切换到未经验证的模型。

### 11.2 检索取舍

业务事实以领域服务查询结果为准；源码定位首选授权目录内的 `rg` 精确搜索。需要跨文件符号关系、类型关系或安全重构能力时，评测 AST/LSP 索引能否带来可量化收益。文档语义检索只有在真实问答集上验证精确搜索与领域 API 不足后才单独引入，不把向量库作为默认基础设施。

### 11.3 上线门槛

每阶段都使用固定任务集测量任务完成率、事实引用正确率、工具参数正确率、未授权调用拦截率、审批正确性、延迟、模型成本和失败恢复。生产启用前完成威胁建模、权限矩阵、审计留存、密钥管理、限流预算和故障演练；未达门槛时维持 `AGENT_ENABLED=false`。

## 十二、实施计划

### 12.1 阶段划分

| 阶段 | 内容 | 交付与验收重点 |
|---|---|---|
| P0 基础 | 配置、ModelClient Port/Adapter、AgentRun/RunStep/Approval 持久化、事件契约 | 开发/生产配置隔离；迁移可回滚；预算和状态转移有测试 |
| P1 只读助手 | FastAPI 路由、Harness Loop、少量领域查询工具、受限 `rg` 搜索 | 身份/权限来自服务端；工具 Schema 和输出上限生效；SSE 可重放 |

| P5 受控推广 | 评测、监控、限流、故障演练与权限审计 | 指标达门槛后逐环境启用；保留关闭开关和运行终止能力 |
