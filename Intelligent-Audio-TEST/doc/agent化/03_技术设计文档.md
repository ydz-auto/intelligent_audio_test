## 一、技术选型

### 1.1 核心组件

| 组件                | 选型                                    | 理由                              |
| ----------------- | ------------------------------------- | ------------------------------- |
| Agent 框架          | LangGraph + langchain-openai          | 2026 Agent 事实标准，Supervisor 模式成熟 |
| LLM 调用            | langchain-openai (OpenAI 兼容)          | 支持 GPT-4o / Claude / 智谱 GLM 等   |
| 流式传输              | SSE (Server-Sent Events)              | 单向事件流天然匹配，自动重连                  |
| 状态持久化             | PostgreSQL Checkpointer               | 复用现有 PostgreSQL，进程重启不丢状态        |
| Human-in-the-loop | `interrupt()` + `Command(resume=...)` | 关键操作需用户确认                       |
| 工具复用              | 调用现有 Controller/Service 层             | 不直接操作 DB，复用已有逻辑                 |
| 设备驱动生成            | UiAutoDev + LLM 代码生成                  | 用户选元素，AI 写代码，不造轮子               |

### 1.2 不选 LangGraph 的替代方案

| 替代方案                      | 不选理由                    |
| ------------------------- | ----------------------- |
| 自研轻量编排 (Function Calling) | 工具数 61 个，编排逻辑复杂，自研维护成本高 |
| OpenAI Assistants API     | 强绑定 OpenAI，内网部署不兼容      |
| LangChain AgentExecutor   | 无状态机，不支持 Solo 模式的复杂流程控制 |

```python
# backend/services/agent/state.py

from typing import Annotated, TypedDict
from langgraph.graph.message import add_messages


class AgentState(TypedDict):
    # 对话历史（只放对话文本，不放工具返回的大 JSON）
    messages: Annotated[list, add_messages]

    # 结构化数据区（工具返回的数据存这里，不进 LLM context）
    audio_annotations: dict          # {audio_id: annotation_data}
    test_cases_created: list         # 已创建的用例列表
    task_id: int                     # 当前任务ID
    task_results: dict               # 任务评估结果
    analysis_report: str             # 生成的分析报告
    picked_elements: list            # UiAutoDev 选中的元素列表
    generated_code: str              # 生成的驱动代码

    # Agent 内部状态
    iteration_count: int             # 当前循环轮数
    pending_action: dict             # 等待用户确认的操作
    plan: dict                       # 当前执行计划
    completed_steps: list[str]       # 已完成的步骤
    solo_mode: bool                  # 是否 Solo 模式
```

### 4.2 Supervisor 节点

```python
# backend/services/agent/agents/supervisor.py

from langgraph.types import Command
from langchain_openai import ChatOpenAI
from backend.services.agent.state import AgentState
from backend.services.agent.prompts.supervisor_prompt import SYSTEM_PROMPT


def supervisor_node(state: AgentState) -> Command:
    """Supervisor 节点：LLM 路由决策"""

    model = ChatOpenAI(
        model=settings.LLM_MODEL,
        temperature=0.1,
        api_key=settings.LLM_API_KEY,
        base_url=settings.LLM_BASE_URL,
    )

    # 构建精简的 messages：系统提示 + 任务摘要 + 最近5轮对话
    system_prompt = SYSTEM_PROMPT
    task_summary = _build_task_summary(state)
    recent_messages = state["messages"][-10:]  # 最近5轮

    messages = [
        {"role": "system", "content": system_prompt},
        {"role": "system", "content": f"当前任务摘要：{task_summary}"},
        *recent_messages,
    ]

    # LLM 决策下一步去哪个 Agent
    response = model.with_structured_output(Router).invoke(messages)

    next_agent = response["next"]

    # 判断是否完成
    if next_agent == "FINISH" or state.get("iteration_count", 0) >= 50:
        return Command(goto=END)

    # Solo 模式 check-in
    if (state.get("solo_mode") and
            state.get("iteration_count", 0) % settings.AGENT_SOLO_CHECKIN_INTERVAL == 0):
        return Command(goto="check_in")

    return Command(goto=next_agent)


def _build_task_summary(state: AgentState) -> str:
    """构建当前任务摘要（不把完整数据塞进 messages）"""
    parts = []
    if state.get("completed_steps"):
        parts.append(f"已完成: {', '.join(state['completed_steps'])}")
    if state.get("plan"):
        parts.append(f"当前计划: {state['plan']}")
    if state.get("audio_annotations"):
        parts.append(f"已读取 {len(state['audio_annotations'])} 条标注")
    if state.get("test_cases_created"):
        parts.append(f"已创建 {len(state['test_cases_created'])} 个用例")
    if state.get("task_id"):
        parts.append(f"当前任务: #{state['task_id']}")
    return " | ".join(parts) if parts else "无"


class Router(TypedDict):
    next: str  # 目标 Agent 名称或 "FINISH"
```

### 4.3 主图构建

```python
# backend/services/agent/graph_builder.py

from langgraph.graph import StateGraph, END
from langgraph.checkpoint.postgres import PostgresSaver
from backend.services.agent.state import AgentState
from backend.services.agent.agents.supervisor import supervisor_node
from backend.services.agent.agents.audio_agent import audio_subgraph
from backend.services.agent.agents.testcase_agent import testcase_subgraph
from backend.services.agent.agents.task_agent import task_subgraph
from backend.services.agent.agents.analysis_agent import analysis_subgraph
from backend.services.agent.agents.compare_agent import compare_subgraph
from backend.services.agent.agents.codegen_agent import codegen_subgraph
from backend.services.agent.agents.log_agent import log_subgraph
from backend.services.agent.agents.algo_agent import algo_subgraph


def build_agent_graph(checkpointer: PostgresSaver):
    """构建主图：Supervisor + 各子图"""

    builder = StateGraph(AgentState)

    # 添加节点
    builder.add_node("supervisor", supervisor_node)
    builder.add_node("audio", audio_subgraph())
    builder.add_node("testcase", testcase_subgraph())
    builder.add_node("task", task_subgraph())
    builder.add_node("analysis", analysis_subgraph())
    builder.add_node("compare", compare_subgraph())
    builder.add_node("codegen", codegen_subgraph())
    builder.add_node("log", log_subgraph())
    builder.add_node("algo", algo_subgraph())
    builder.add_node("check_in", check_in_node)

    # 入口 → Supervisor
    builder.set_entry_point("supervisor")

    # Supervisor → 各子图（通过 Command 动态路由）
    # 子图 → Supervisor（每个子图完成后回到 Supervisor）
    for node in ["audio", "testcase", "task", "analysis", "compare",
                 "codegen", "log", "algo", "check_in"]:
        builder.add_edge(node, "supervisor")

    # 编译图
    graph = builder.compile(
        checkpointer=checkpointer,
        recursion_limit=settings.AGENT_RECURSION_LIMIT,
    )

    return graph


def check_in_node(state: AgentState) -> Command:
    """Solo 模式 check-in 节点"""
    from langgraph.types import interrupt

    progress = {
        "iteration": state.get("iteration_count", 0),
        "completed": state.get("completed_steps", []),
        "summary": _build_task_summary(state),
    }

    approval = interrupt({
        "type": "check_in",
        "progress": progress,
        "message": f"已执行 {progress['iteration']} 轮，"
                   f"已完成: {progress['completed']}",
        "options": ["继续", "跳过后续确认", "停止"],
    })

    if approval == "停止":
        return Command(goto=END)
    # 继续或跳过后续确认都回到 Supervisor
    return Command(update={"solo_mode": approval != "停止"})
```

```python
# backend/services/agent/tools/codegen_tools.py

from langchain_core.tools import tool


@tool
def generate_driver_from_elements(
    system: str,
    app_name: str,
    elements: list[dict],
    user_description: str = "",
) -> dict:
    """根据用户从 UiAutoDev 选择的 UI 元素生成驱动代码

    用户在 UiAutoDev 中选择关键 UI 元素，元素信息自动推送到对话面板，
    本工具将元素信息 + 用户描述一起喂给 LLM 生成 BaseDeviceDriver 驱动类代码。

    Args:
        system: android / harmonyos / ios
        app_name: APP 包名，如 com.doubao.android
        elements: 用户选择的元素列表
            每个元素: action/click, resource_id, xpath, text, class, bounds, user_label
        user_description: 用户对操作流程的自然语言描述
    """
    from backend.services.llm.llm_client import llm_client

    # 选择代码模板
    template = _get_driver_template(system)

    # 构建 LLM 输入
    elements_desc = _format_elements_for_llm(elements)

    code = llm_client.generate(
        system=f"""你是设备驱动代码生成专家。
        根据用户从 UiAutoDev 选择的 UI 元素信息，
        生成继承 {template['base_class']} 的驱动类。

        要求：
        1. 用 resource_id 优先定位，xpath 兜底
        2. 实现 initialize() / get_results() / teardown()
        3. 使用 {template['cmd_tool']} 命令控制设备
        4. 使用 {template['ui_framework']} 定位元素
        5. 中文注释每步操作
        6. get_results() 从用户标记为 extract 的元素提取结果
        """,
        user_message=f"""系统: {system}
APP: {app_name}
用户描述: {user_description}

用户选择的元素:

{elements_desc}
""",
    )

    return {
        "code": code,
        "file_path": (
            f"backend/utils/device_driver/"
            f"{system.lower()}_{app_name.split('.')[-1]}_driver.py"
        ),
    }


def _get_driver_template(system: str) -> dict:
    templates = {
        "android": {
            "base_class": "BaseDeviceDriver",
            "cmd_tool": "adb",
            "ui_framework": "uiautomator2 (u2)",
        },
        "harmonyos": {
            "base_class": "HarmonyDriver",
            "cmd_tool": "hdc",
            "ui_framework": "hypium (UiDriver/By)",
        },
        "ios": {
            "base_class": "BaseDeviceDriver",
            "cmd_tool": "wda",
            "ui_framework": "facebook-wda",
        },
    }
    return templates.get(system, templates["android"])


def _format_elements_for_llm(elements: list[dict]) -> str:
    lines = []
    for i, e in enumerate(elements, 1):
        action = e.get("action", "click")
        label = e.get("user_label", "")

        if action == "wait":
            lines.append(f"Step {i}: 等待 {e.get('duration', 3)}秒")
            continue

        text = e.get("text", "")
        rid = e.get("resource_id", "")
        xpath = e.get("xpath", "")
        cls = e.get("class", "").split(".")[-1]

        lines.append(f"Step {i}: {action} {label or text}")
        lines.append(f"  元素: text='{text}', class={cls}")
        if rid:
            lines.append(f"  resource_id: {rid}")
        if xpath:
            lines.append(f"  xpath: {xpath}")

    return "\n".join(lines)


@tool
def register_driver_to_factory(
    code: str,
    file_path: str,
    keywords: list[str],
    system: str,
) -> dict:
    """将生成的驱动代码写入文件并注册到 DriverFactory

    Args:
        code: 驱动类完整代码
        file_path: 写入的文件路径
        keywords: 驱动匹配关键字列表
        system: android / harmonyos / ios
    """
    import os

    # 确保目录存在
    os.makedirs(os.path.dirname(file_path), exist_ok=True)

    # 写入文件
    with open(file_path, "w", encoding="utf-8") as f:
        f.write(code)

    # 修改 driver_factory.py 的 _register_defaults()
    # 添加新驱动的注册代码
    _patch_factory_registration(file_path, keywords, system)

    return {
        "success": True,
        "file_path": file_path,
        "keywords": keywords,
        "system": system,
    }
```

```python
    return {

        "action": action,
        "target": target,
        "success": data["success"],
        "screenshot": data["screenshot"],  # base64 JPEG, ~200KB
        "error": data.get("error"),
        "extracted_text": data.get("text") if action == "extract" else None,
```

```
1. 用户在 UiAutoDev 浏览器界面选好关键元素
2. Agent 生成驱动代码
3. 用户说"逐步调试"
4. Agent 逐步调 debug_execute_step：
```

- UiAutoDev 是 Web 服务（pip install uiautodev; uiautodev server），用户在浏览器中选元素和查看 UI 树

## 六、沙盒与安全（未来扩展）

> **当前阶段不需要实现沙盒。**
>
> Agent 主要是调现有 API + LLM 文本分析，不涉及任意代码执行：
>
> * 工具调的是已有的 Controller 层（已有权限验证）
>
> * LLM 只做文本生成和分析，不执行代码
>
> * 设备驱动代码由 LLM 生成 → 用户在对话面板审批 → Agent 写入文件 → 注册到 DriverFactory
>
> 以下沙盒方案为**未来扩展**：当 Agent 自动执行生成的代码（如自动测试驱动）时启用。

### 6.1 沙盒架构

```
Agent 生成代码
  ↓
Sandbox Manager
  ├── 代码静态检查（AST 分析，禁止危险操作）
  ├── Docker 容器隔离（文件系统/网络/进程隔离）
  ├── 资源限制（CPU/内存/超时）
  ├── 设备访问白名单（只允许 ADB/HDC 端口）
  └── 结果回传（执行成功/失败/输出日志）
```

### 6.2 代码静态检查

```python
# backend/services/agent/sandbox/code_checker.py
import ast

DANGEROUS_MODULES = {"os", "subprocess", "shutil", "ctypes", "sys"}
DANGEROUS_CALLS = {"eval", "exec", "open", "__import__"}

def check_code_safety(code: str) -> tuple[bool, str]:
    """静态检查生成代码的安全性
    
    Returns:
        (is_safe, reason)
    """
    try:
        tree = ast.parse(code)
    except SyntaxError as e:
        return False, f"语法错误: {e}"
    
    for node in ast.walk(tree):
        # 检查 import
        if isinstance(node, ast.Import):
            for alias in node.names:
                if alias.name.split(".")[0] in DANGEROUS_MODULES:
                    return False, f"禁止导入 {alias.name}"
        
        # 检查函数调用
        if isinstance(node, ast.Call):
            func_name = getattr(node.func, "id", "")
            if func_name in DANGEROUS_CALLS:
                return False, f"禁止调用 {func_name}()"
    
    return True, "通过"
```

### 6.3 Docker 沙盒执行

```python
# backend/services/agent/sandbox/sandbox_runner.py
import docker
import tempfile
import os

class SandboxRunner:
    def __init__(self):
        self.client = docker.from_env()
    
    def run_code(self, code: str, device_sn: str = None,
                 timeout: int = 60) -> dict:
        """在 Docker 沙盒中执行代码
        
        Args:
            code: 要执行的 Python 代码
            device_sn: 设备序列号（映射 ADB 端口）
            timeout: 超时秒数
        """
        # 1. 静态检查
        is_safe, reason = check_code_safety(code)
        if not is_safe:
            return {"success": False, "error": f"安全检查失败: {reason}"}
        
        # 2. 写入临时文件
        with tempfile.NamedTemporaryFile(
            mode="w", suffix=".py", delete=False
        ) as f:
            f.write(code)
            script_path = f.name
        
        try:
            # 3. 创建容器并执行
            container = self.client.containers.run(
                image="agent-sandbox:latest",  # 预构建的沙盒镜像
                command=f"python /tmp/script.py",
                volumes={
                    script_path: {"bind": "/tmp/script.py", "mode": "ro"},
                },
                # 设备访问：映射 ADB 端口
                device_requests=[
                    docker.types.DeviceRequest(
                        device_ids=["all"],
                        capabilities=[["usb"]],
                    )
                ] if device_sn else None,
                # 资源限制
                mem_limit="512m",
                cpu_quota=100000,  # 1 CPU
                network_mode="bridge",
                detach=True,
            )
            
            # 4. 等待执行完成
            result = container.exec_run(
                f"timeout {timeout} python /tmp/script.py",
                workdir="/tmp",
            )
            
            # 5. 清理容器
            container.remove(force=True)
            
            return {
                "success": result.exit_code == 0,
                "output": result.output.decode("utf-8"),
                "exit_code": result.exit_code,
            }
        
        except Exception as e:
            return {"success": False, "error": str(e)}
        finally:
            os.unlink(script_path)
```

```typescript
  const messages = ref([])
  const streaming = ref(false)
  const interruptData = ref(null)
  const soloProgress = ref(null)

  async function sendMessage(message: string, options: object = {}) {
    streaming.value = true

    const response = await fetch('/api/v1/agent/chat/stream', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        message,
        thread_id: getCurrentThreadId(),
        ...options,
      }),
    })

    const reader = response.body!.getReader()
    const decoder = new TextDecoder()

    while (true) {
      const { done, value } = await reader.read()
      if (done) break

      const lines = decoder.decode(value).split('\n')
      for (const line of lines) {
        if (line.startsWith('data: ')) {
          const event = JSON.parse(line.slice(6))

          if (event.type === 'token') {
            // token 流，追加到当前 AI 回复
            appendToken(event.data)
          } else if (event.type === 'state_update') {
            // 节点状态更新
            if (event.data.__interrupt__) {
              interruptData.value = event.data.__interrupt__
            }
          }
        }
      }
    }

    streaming.value = false
  }

  async function resumeAgent(approval: string) {
    interruptData.value = null
    // 调用 /chat/resume 端点，继续 SSE
    ...
  }

  return { messages, streaming, interruptData, soloProgress, sendMessage, resumeAgent }
}
```

## 九、Agent 编排方式对比

### 9.1 三种编排方式

| 方式                | 原理                          | 优点               | 缺点        |
| ----------------- | --------------------------- | ---------------- | --------- |
| 自研轻量编排            | LLM Function Calling + 自写循环 | 完全可控，依赖最少        | 工具多了维护成本高 |
| LangGraph (选)     | 状态机 + Supervisor 路由         | 状态机成熟，Solo模式天然支持 | 依赖较重      |
| OpenAI Assistants | 平台托管 Agent                  | 上手最快             | 强绑定，内网不兼容 |

### 9.2 选择 LangGraph 的理由

1. 工具数量 61 个，Supervisor 路由模式成熟
2. Solo 模式的 Loop + check-in 用状态机天然实现
3. `interrupt()` 的 human-in-the-loop 机制完善
4. Checkpointer 复用 PostgreSQL，进程重启不丢
5. 子图隔离上下文，长任务不爆 context

## 十一、运行期 MCP 集成

> 本节说明 Agent 运行期需要通过 MCP（Model Context Protocol）协议接入的外部能力。MCP 是 Agent 调用外部工具/资源的标准协议层，让 LangGraph 工具层与具体实现解耦，便于替换和扩展。
>
> 区分：
> - **MCP（运行期）**：Agent 运行时通过 MCP 协议调用外部能力，跑在 Flask 进程内
> - **Skill（开发期）**：Trae IDE 辅助开发用，不属于运行期范畴

```python
# backend/services/agent/tools/log_tools.py
@tool
async def search_logs_via_mcp(
    task_id: int = None,
    level: str = "ERROR",
    keyword: str = None,
) -> dict:
    """通过 MCP 搜索日志文件"""
    async with ClientSession.connect("filesystem-mcp") as session:
        log_dir = f"logs/tasks/{task_id}" if task_id else "logs"
        files = await session.call_tool("list_directory", {"path": log_dir})
        results = []
        for f in files:
            grep_result = await session.call_tool("grep_files", {
                "path": f["path"],
                "pattern": keyword or level,
            })
            results.extend(grep_result["matches"])
        return {"matches": results, "count": len(results)}
```
