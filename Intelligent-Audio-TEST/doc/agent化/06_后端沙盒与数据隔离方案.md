# 灵犀Agent 后端沙盒与数据隔离方案

> 状态：目标设计，非已实现功能。承接 [00_DeepSeek_Harness统一迁移设计.md](00_DeepSeek_Harness统一迁移设计.md)（技术选型）与 [04_前后端改造方案.md](04_前后端改造方案.md)（前后端细化）；本文档细化「后端沙盒怎么做、每个用户对话与文件怎么保存、用户数据如何隔离」三个落地问题。与 00 冲突时以 00 为准。

## 1. 定位与范围

DSH（DeepSeek Harness）作为统一 Agent Runtime 的前提下，本文档回答实施层面的四个问题：

1. 后端沙盒的访问边界是什么（什么能碰、什么不能碰）
2. 每个用户的对话与 Run 怎么持久化（业务层落库）
3. 文件（报告文档/音频/运行产物）放哪里
4. 用户之间数据如何隔离（网络边界 + 行级可见性 + agent 无凭证）

## 2. 沙盒访问边界（三层模型）

DSH 以独立受限 Node 进程运行（隔离容器/VM，非 root、只读基础层、最小资源配额）。访问边界按三层界定：

| 层 | 可访问 | 不可访问 |
|---|---|---|
| 笼内（沙盒自身） | 自己的工作目录与运行产物（中间文件、临时素材，会话结束清理）；被授权挂载的只读素材（源码、文档） | — |
| 笼外（系统层面） | 出站白名单端点（Agent Bridge、经验证的模型 API） | 宿主机 Shell / 任意文件系统；生产数据库；OSS；任意出站 |
| 唯一出口 | Agent Bridge → 授权 API / gRPC Adapter（短期凭证、细粒度权限）→ 业务服务 | 不经 Bridge 的任何业务数据访问 |

**多会话隔离**：不只「DSH 整体关在一个笼子里」，而是每个用户、每个会话各有一个独立沙盒/工作目录，互不共享（DSH 多会话隔离，00 文档 §5 M0 有核验项）。

**部署红线（上线前阻断项，00 文档 §4 重申）**：
- DSH 进程无生产数据库凭证、无设备直连凭证、无宿主机 Shell/任意文件权限
- 不挂载生产数据卷（PostgreSQL 数据、OSS 桶、业务日志目录）进沙盒
- 出站网络仅放行必要端点
- 未通过安全审查、故障演练与能力评测前，生产开关保持关闭

## 3. grep / 检索隔离语义

- `rg`/`grep` 只用于**沙盒内只读素材的源码定位**（00 文档 §1：不默认引入向量数据库，源码定位可由受限检索工具使用 rg）。
- 业务数据**一律从授权 API 获取**，不经文件系统。
- grep 物理上够不到后端数据：沙盒内没有生产 DB 文件、没有数据卷挂载、没有连接凭证，PostgreSQL/OSS 不在沙盒的文件系统内。
- 例外风险仅出现在「误把生产数据卷/日志/导出文件挂进沙盒」时——属部署失误，由第 2 节红线兜底。

## 4. 用户数据隔离（三层保证）

用户无法直接操作数据库，用户之间数据按行级隔离（admin 豁免除外）：

1. **网络边界**：一切访问只走 `浏览器 → api_gateway → 业务服务 → PostgreSQL`。数据库端口只对服务容器开放（Docker 网络内部寻址），浏览器/用户端拿不到连接串，不存在直连路径。
2. **行级可见性（INT-465 数据可见性）**：
   - `visibility_filter` 按当前用户注入行级过滤：private 只出 owner 的行，shared 出共享可见的行
   - 创建/修改/删除前 owner 校验
   - RBAC 权限码控制操作层（report:write、task:execute 等）
3. **agent 无特权通道**：DSH 无生产凭证，读任何数据都经 Bridge → 业务服务按当前用户重校验权限与行级过滤。agent 调工具等价于「该用户自己调 API」，隔离边界完全复用现有模型。写操作再加一层：提案 → 审批 → 幂等执行，模型不能直接落库。

**admin 豁免说明**：现有可见性模型中 admin 角色可见全部数据，属产品设计而非漏洞；其他角色严格按行级隔离。

## 5. 会话持久化（Bridge + PostgreSQL）

双层，不混为一谈（00 文档 §2 职责归属）：

- **DSH Session Log**：只管运行期模型会话（Agent Loop 主日志），**不自动等于业务记录**
- **我方 Agent Bridge + PostgreSQL**：持久化业务会话——按 user_id 隔离的会话映射、Agent Run → 业务任务映射、事件断线重放、审批状态、取消/恢复

建议落库五张表（字段待立项后评审定稿，命名沿用项目 snake_case 口径）：

| 表 | 职责 | 关键字段（草案） |
|---|---|---|
| `agent_sessions` | 每个用户的会话 | id、user_id、title、status（active/archived/deleted）、created_at、updated_at |
| `agent_runs` | 一次 Agent 执行的 Run 记录，关联业务任务 | id、session_id、user_id、task_type、business_ref_id（关联业务任务/报告 id）、status、input_summary、output_summary、created_at、finished_at |
| `agent_messages` | 对话消息（用户/助手/工具轮次） | id、session_id、run_id、role（user/assistant/tool）、content、tool_name、tool_arguments、tool_result_ref、created_at |
| `agent_events` | 事件流，断线重放用 | id、session_id、run_id、event_type、payload、seq、created_at |
| `agent_approvals` | 写操作提案审批 | id、session_id、run_id、proposal_type、business_action、payload、status（pending/approved/rejected/expired）、approved_by、expired_at |

隔离与一致性的硬约束：

- 所有表按 `user_id` 隔离，查询一律注入行级过滤（对齐第 4 节）
- Agent Run 到业务任务的映射必须幂等（00 文档 §2：上游 Session Log 并不自动等于我方业务任务的幂等事务记录）
- 事件断线重放、取消、审批状态、用户隔离在 Bridge 层有独立契约，须经端到端测试验证

## 6. 文件持久化（业务资产归业务服务）

「文件」按业务资产拆开，全部由现有业务服务持久化，DSH 不持有生产数据：

| 资产 | 落点 | 说明 |
|---|---|---|
| 报告文档 / 版本 | Report Studio（报告七表 + 文档版本表，乐观锁） | 灵犀Agent 首期主战场（Report First）；多轮编辑与人工并发不丢版本 |
| 音频 | 现有音频存储 / OSS | 文档生成里只放追溯链接，不拷贝实体 |
| DSH 运行产物 | 隔离工作目录 | 不落生产，会话结束清理 |

## 7. 与浏览器直连 MCP 的关系

正式口径（00 文档 §2）：**MCP 只在必须与外部服务互操作时使用，不为域内业务调用强制引入 MCP**——域内工具用 DSH 插件/现有服务。

浏览器直连 MCP（前端当 MCP client，调 `/api/v1/mcp` 的 tools/list、tools/call）可作为轻量过渡或外部 agent 通道，但不是正式 Agent 底座。对比：

| 场景 | 浏览器直连 MCP | 后端沙盒（DSH） |
|---|---|---|
| 纯问答 + 短工具调用 | 够用，落地快 | 也可以 |
| 长任务（评估/任务执行/报告生成，异步秒~分钟级） | 需自写轮询/SSE/断线重试，页面刷新会话即断 | 后台常驻、事件推送、天然支持 |
| 多轮依赖（工具 A 结果喂工具 B） | 上下文全堆浏览器 | 后端管理状态，可靠 |
| 审计/风控/并发限制 | 弱（逻辑在客户端，可被绕过） | 强（Bridge 统一出口） |

## 8. 落地顺序（对齐 00 文档 §5 迁移阶段）

- **M0**：锁定 DSH 版本与最小权限 Profile；核验沙盒无凭证/不挂卷/出站白名单三项边界；多会话隔离实测
- **M1 报告基础闭环**：Agent Bridge + Run/SSE；`report_get_facts` / `report_query_metrics` 只读工具；会话五表先落 `agent_sessions` / `agent_runs` / `agent_messages`
- **M2 编辑与联调**：会话式局部编辑、版本历史/恢复；补 `agent_events` 断线重放
- **M3 正式报告交付**：图表/PPTX/PDF/HTML 固定版本交付；补 `agent_approvals` 写操作审批
- **M4+**：诊断/重测提案、非报告场景扩展（通用 Agent 工作台、自动化导入、设备驱动提案）
