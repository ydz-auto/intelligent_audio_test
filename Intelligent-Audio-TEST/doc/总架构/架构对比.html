⚠️ 当前单体架构问题

耦合严重 设备驱动与 Flask HTTP Server 共用进程，设备通信阻塞 HTTP 响应
扩展性差 无法独立扩展任务执行能力
故障影响大 任务执行异常可能影响 API 响应
资源竞争 设备控制线程与 HTTP 处理线程竞争资源
部署不灵活 无法针对不同负载场景独立部署

🚪 API Gateway 端口 5000

  • HTTP 路由 - 接收前端请求，转发到对应服务
  • 认证授权 - JWT Token 验证、权限检查
  • 限流控制 - 基于 IP/用户/接口的限流
  • 请求校验 - Pydantic Schema 验证
  • 响应格式化 - 统一响应格式、错误处理
  • WebSocket 代理 - 聚合多服务 WebSocket 推送
  • 静态文件 - 报告导出、音频文件服务

📋 Task Service 端口 5001

  • 任务调度 - APScheduler 后台任务调度
  • 测试执行 - API/E2E 测试用例执行
  • 评估计算 - 维度评分、结果汇总
  • 算法映射 - 参数提取、字段映射、参考参数生成
  • 进度上报 - 通过 Redis Pub/Sub 推送进度
  • 日志写入 - 写入 PostgreSQL logs 表
  • gRPC 客户端 - 调用 Device Service

📱 Device Service 5002/50051

  • 设备通信 - Android/HarmonyOS 设备驱动
  • 音频播放 - 音频文件播放控制
  • SPL 映射 - 声压级校准和映射
  • 设备监控 - 设备状态监控和上报
  • gRPC 服务端 - 提供设备控制接口
  • 设备池管理 - 多实验室设备统一管理

🔗 服务间通信方式

通信场景 通信方式 说明
API Gateway → Task Service HTTP REST 任务启动/控制/查询
Task Service → Device Service gRPC 设备控制、音频播放
各服务 → 前端 WebSocket 进度推送、日志推送
Task Service → API Gateway Redis Pub/Sub 事件通知
各服务 → Storage S3/HTTP 文件上传下载

数据库分区提升日志查询性能
