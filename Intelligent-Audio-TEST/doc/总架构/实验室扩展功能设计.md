# 实验室扩展功能设计文档

## 1. 背景与目标

### 1.1 问题背景

当前系统存在以下问题：
- 设备、播放设备、用例等资源缺乏物理位置管理
- 无法支持跨实验室的测试任务执行
- 设备和资源无法按地理位置分组管理

### 1.2 扩展目标

1. **实验室管理**：支持多个物理实验室的创建和管理
2. **资源归属**：设备、播放设备、用例归属到特定实验室
3. **任务多实验室支持**：一个任务可以在多个实验室执行
4. **流程隔离**：通过实验室选择过滤后续可选资源
5. **服务拆分兼容**：设计与服务拆分架构完全兼容

## 2. 业务流程设计

### 2.1 当前流程（5步骤）

```
选择算法 → 选择用例 → 选择设备 → 选择播放设备 → 确认测试
```

### 2.2 扩展后流程（6步骤）

```
选择算法 → 选择实验室 → 选择用例 → 选择设备 → 选择播放设备 → 确认测试
       ↑ 可多选                    ↑ 按实验室过滤
```

### 2.3 流程说明

| 步骤 | 操作 | 业务规则 |
|------|------|----------|
| Step 1 | 选择算法 | 不变，根据算法过滤用例 |
| Step 2 | **选择实验室** | **可多选**，定义任务执行范围 |
| Step 3 | 选择用例 | **仅显示**属于已选实验室的用例 |
| Step 4 | 选择设备 | **仅显示**属于已选实验室的设备 |
| Step 5 | 选择播放设备 | **仅显示**属于已选实验室的播放设备 |
| Step 6 | 确认测试 | 创建任务，关联实验室和资源 |

## 4. 数据库模型

### 4.1 实验室表（新增）

```sql
CREATE TABLE laboratories (
    id SERIAL PRIMARY KEY,
    code VARCHAR(50) UNIQUE NOT NULL COMMENT '实验室代码，如 LAB-A-01',
    name VARCHAR(100) NOT NULL COMMENT '实验室名称',
    building VARCHAR(50) COMMENT '所在楼栋',
    floor VARCHAR(20) COMMENT '所在楼层',
    room_number VARCHAR(50) COMMENT '房间号',
    description TEXT COMMENT '实验室描述',
    status VARCHAR(20) DEFAULT 'active' COMMENT '状态 (active/inactive/maintenance)',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_laboratories_code ON laboratories(code);
CREATE INDEX idx_laboratories_status ON laboratories(status);
```

### 4.2 设备表（修改）

```sql
ALTER TABLE devices ADD COLUMN lab_id INTEGER REFERENCES laboratories(id);
CREATE INDEX idx_devices_lab_id ON devices(lab_id);
```

### 4.3 播放设备表（修改）

```sql
ALTER TABLE playback_devices ADD COLUMN lab_id INTEGER REFERENCES laboratories(id);
CREATE INDEX idx_playback_devices_lab_id ON playback_devices(lab_id);
```

### 4.4 用例表（修改）

```sql
ALTER TABLE test_cases ADD COLUMN lab_id INTEGER REFERENCES laboratories(id);
CREATE INDEX idx_test_cases_lab_id ON test_cases(lab_id);
```

### 4.5 任务-实验室关联表（新增）

```sql
CREATE TABLE task_laboratory_relations (
    id SERIAL PRIMARY KEY,
    task_id INTEGER NOT NULL REFERENCES test_tasks(id) ON DELETE CASCADE,
    lab_id INTEGER NOT NULL REFERENCES laboratories(id),
    priority INTEGER DEFAULT 1 COMMENT '实验室优先级，1最高',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(task_id, lab_id)
);

CREATE INDEX idx_task_lab_task ON task_laboratory_relations(task_id);
CREATE INDEX idx_task_lab_lab ON task_laboratory_relations(lab_id);
```

## 5. API 接口设计

| DELETE | /api/laboratories/{id} | 删除实验室 |
| GET | /api/laboratories/{id}/summary | 获取实验室资源统计 |

### 5.2 资源查询

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/laboratories/{lab_id}/devices | 获取实验室下的设备 |
| GET | /api/laboratories/{lab_id}/playback_devices | 获取实验室下的播放设备 |
| GET | /api/laboratories/{lab_id}/test_cases | 获取实验室下的用例 |

## 6. 业务规则

### 6.1 归属规则

| 关系 | 基数 | 说明 |
|------|------|------|
| 实验室 → 设备 | 1:N | 一个设备只属于一个实验室 |
| 实验室 → 播放设备 | 1:N | 一个播放设备只属于一个实验室 |
| 实验室 → 用例 | 1:N | 一个用例只属于一个实验室 |
| 任务 → 实验室 | N:M | 一个任务可以在多个实验室执行 |

### 6.2 过滤规则

创建任务时，后续步骤的可选范围根据前一步的选择动态过滤：

```
Step 2 选择实验室 [1, 2] 后：

Step 3 用例列表 = 用例 WHERE lab_id IN [1, 2]
Step 4 设备列表 = 设备 WHERE lab_id IN [1, 2]
Step 5 播放设备列表 = 播放设备 WHERE lab_id IN [1, 2]
```

### 6.3 校验规则

创建任务时，后端必须校验：

1. **用例归属**：所有 case_ids 必须属于 lab_ids 中的某个实验室
2. **设备归属**：所有 device_ids 必须属于 lab_ids 中的某个实验室
3. **播放设备归属**：所有 playback_device_ids 必须属于 lab_ids 中的某个实验室

### 7.3 兼容性结论

| 特性 | 兼容性 | 说明 |
|------|--------|------|
| 实验室模型 | ✅ | 纯数据模型，与服务拆分正交 |
| 资源归属 | ✅ | API Gateway 统一管理资源关系 |
| 任务分发 | ✅ | 可按 lab_id 分发到对应实验室的 Device Service |
| 独立扩缩容 | ✅ | 繁忙实验室可增加 Device Service 实例 |
| 故障隔离 | ✅ | 某实验室故障不影响其他实验室 |
| S3 对象存储 | ✅ | 各实验室共享存储，音频/报告统一管理 |

## 8. 部署说明

### 8.1 单体部署（当前）

所有服务部署在同一台服务器，实验室通过 `lab_id` 字段区分。
本地存储用于音频、报告、日志文件。

### 8.2 分布式部署（未来）

每个实验室部署独立的 Device Service，共享 S3 对象存储：

```yaml
# docker-compose.yml 示例
services:
  api_gateway:
    image: ${REGISTRY}/api-gateway:latest
    ports:
      - "5000:5000"
    environment:
      - STORAGE_TYPE=s3
      - S3_ENDPOINT=minio:9000

  device_service_lab_a:
    image: ${REGISTRY}/device-service:latest
    environment:
      - LAB_CODE=LAB-A-01
      - LAB_ID=1
      - STORAGE_TYPE=s3
      - S3_ENDPOINT=minio:9000
    devices:
      - /dev/sound/card0
    network_mode: host

  minio:
    image: minio/minio:latest
    ports:
      - "9000:9000"
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    volumes:
      - minio_data:/data

volumes:
  minio_data:
```
