## 1. 系统概览

本系统是一个智能语音测试平台，支持两种测试模式：

| 模式 | 被测目标 | 适用场景 |
|------|---------|---------|
| **E2E 测试** | 物理设备（Android/HarmonyOS） | 智能音箱、车机、手机语音助手等硬件设备 |
| **API 测试** | 云端 API（HTTP REST） | 语音云服务、翻译 API 等纯软件接口 |

**主要页面导航**：

| 页面 | 路由 | 用途 |
|------|------|------|
| 首页 | `/` | 系统总览 |
| 音频管理 | `/AudioImport` | 上传、管理音频文件 |
| 用例管理 | `/TestCaseManager` | 创建、编辑测试用例 |
| 算法配置 | `/AlgorithmConfig` | 配置算法参数模板 |
| 设备管理 | `/Device` | 管理测试设备 / 被测 API |
| E2E 测试 | `/E2ETest` | 端到端测试向导 |
| API 测试 | `/APITest` | API 测试向导 |
| 测试报告 | `/test-reports` | 查看测试结果 |

## 2. 上传音频

点击侧边栏「音频管理」进入 `/AudioImport` 页面。系统提供两种上传方式：单文件上传和文件夹批量导入。

### 2.1 单文件/多文件上传

1. 点击「上传音频」按钮，弹出上传弹窗
2. **选择文件**：点击选择或直接拖拽文件到弹窗。可以**同时选择音频文件和同名的标注文件**（`.txt` / `.json` / `.rttm` / `.stm` / `.jsonl`），系统会按文件名（去扩展名）自动关联
3. **关联标注**（可选）：系统自动按同名规则匹配音频与标注文件。例如 `test01.wav` 和 `test01.json` 会自动关联。UI 会显示「已关联文本文件」/「未关联文本文件」标签
4. **标注代码**（可选）：弹窗中有「标注代码」输入框，可手动指定标注类型（如 `asr`、`translation`、`diarization`、`reference`）。留空则系统根据文件名启发式推断：含 `asr` → asr，含 `trans` → translation，rttm/stm → diarization，否则 → reference
5. 点击「开始上传」

> **关联规则**：文件上传通过浏览器 File API 选择，不依赖文件系统路径。前端按 basename（去扩展名后的文件名）匹配音频和标注文件。所以只要把音频和标注文件一起拖进弹窗，且文件名相同（去扩展名），就会自动关联。

### 2.2 文件夹批量导入

1. 点击「批量从文件夹导入」按钮
2. **选择文件夹**：选择整个音频目录（浏览器会读取目录下所有文件及子目录）
3. **设置分组**（可选）：按子文件夹结构自动分组，默认用根文件夹名作分组名，可手动修改
4. 系统会自动识别音频文件和同名的标注/文本文件
5. 点击「开始导入」

> **关联规则**：文件夹导入使用 `webkitRelativePath`（含相对目录），按**相对路径 + basename** 匹配。例如 `sub/test01.wav` 和 `sub/test01.json` 会关联，但 `sub/test01.wav` 和 `other/test01.json` 不会误关联。

### 2.3 标注文件格式详解

标注文件在上传时由**前端解析**（后端只接收已解析的结构化数据）。不同格式的解析规则如下：

#### 支持的格式

| 格式 | 扩展名 | 用途 |
|------|--------|------|
| 文本 | `.txt` | 简单 ASR 文本和翻译 |
| JSON | `.json` | 带时间戳的分段标注、多类型标注 |
| JSONL | `.jsonl` | 逐行 JSON 的分段标注 |
| RTTM | `.rttm` | 说话人分离标注 |
| STM | `.stm` | 说话人分离标注 |

#### .txt 格式

第一行作为 ASR 参考文本，后续每行作为翻译文本（格式：`翻译文本<TAB>方向` 或 `翻译文本<空格>方向`）：

```
你好，我想了解一下天气
Hello, I'd like to know about the weather    en
今天天气很好    ja
```

#### .json 格式

支持三种结构：

**结构 A：单文本型**（整段文本，无时间戳）

```json
{
  "name": "asr",
  "source_language": "zh",
  "text": "整段参考文本"
}
```

**结构 B：分段列表型**（带时间戳和说话人）

```json
{
  "name": "diarization",
  "code": "diarization",
  "source_language": "zh",
  "txt": [
    {"speaker": "spk1", "start": 0.5, "end": 2.3, "text": "你好", "confidence": 0.95},
    {"speaker": "spk2", "start": 2.5, "end": 4.0, "text": "谢谢", "confidence": 0.9}
  ]
}
```

> **注意**：JSON 中分段列表使用 `txt` 数组（不是 `segments`）。顶层直接放 `segments` 数组的 JSON 不会被正确解析。

**结构 C：多标注嵌套型**（一个文件包含多类标注）

```json
{
  "annotations": [
    {
      "name": "asr",
      "code": "asr",
      "source_language": "zh",
      "txt": [{"text": "参考文本", "start": 0, "end": 5}]
    },
    {
      "name": "translation",
      "code": "translation",
      "source_language": "zh",
      "target_language": "en",
      "txt": [{"text": "Reference text", "start": 0, "end": 5}]
    }
  ]
}
```

segment 内已知字段：`speaker`、`start`、`end`、`text`、`confidence`，其他字段（如 `emotion`）会被保留在 `extra_fields` 中。

#### .jsonl 格式

每行一个 JSON 对象（即一个 segment），会被自动包装成 `{txt: [...]}` 处理：

```
{"speaker": "spk1", "start": 0.5, "end": 2.3, "text": "你好", "confidence": 0.95}
{"speaker": "spk2", "start": 2.5, "end": 4.0, "text": "谢谢", "confidence": 0.9}
```

#### .rttm 格式

标准 RTTM 格式，按空白分隔，识别以 `SPEAKER` 开头且至少 8 字段的行：

```
SPEAKER file001 1 0.50 1.80 <NA> <NA> spk1 <NA> <NA>
SPEAKER file001 1 2.50 1.50 <NA> <NA> spk2 <NA> <NA>
```

- 第 4 字段 → start
- 第 5 字段 → duration（end = start + duration）
- 第 8 字段 → speaker
- text 为空

解析后自动设置 `name=code=type=diarization`。

#### .stm 格式

标准 STM 格式，至少 6 字段，按空白分隔：

```
file001 spk1 0.50 2.30 1 你好
file001 spk2 2.50 4.00 1 谢谢
```

- 第 2 字段 → speaker
- 第 3 字段 → start
- 第 4 字段 → end
- 第 6 字段起 → text（空格拼接）

解析后自动设置 `name=code=type=diarization`。

#### 标注存储与使用

- 上传时标注被解析后存入数据库 `audio_annotations` 表，每个标注记录包含：`format`、`code`、`data`、`source_language`、`target_language`
- 创建测试用例时，系统会自动从音频的标注中提取参考参数（reference_params），作为评估时的对比基准
- 同一个音频可以关联多个标注（如同时有 ASR 文本、翻译、说话人分离）

### 2.4 上传选项与自动创建用例

上传弹窗和文件夹导入弹窗都提供「上传选项」配置区域：

| 选项 | 说明 | 默认值 |
|------|------|--------|
| 同时创建测试用例 | 上传完成后自动生成测试用例 | 关闭 |
| 测试类型 | `api` 或 `e2e` | api |
| 播放设备 | E2E 用例的播放设备（E2E 时必填） | - |
| 默认 SPL | 声压级（E2E 用例用） | - |
| 分组名称 | 用例分组名 | 算法类型或文件夹名 |

勾选「同时创建测试用例」后，系统会为每个音频创建一个单轮用例：
- 用例名格式：`测试用例_<音频名>`
- 用例关联该音频和一个可选的噪声音频
- 自动从音频的标注中生成参考参数（reference_params）
- 用例继承音频的标签

### 2.5 上传特性

- **分块上传**：大文件自动分块（10MB/块），支持 30GB+ 大文件
- **断点续传**：页面刷新后可通过 LocalStorage 恢复上传进度
- **完整性校验**：使用 MD5 校验文件完整性
- **自动转码**：后端通过 ffmpeg 将音频转为 WAV 格式，保持原始采样率和位深

### 2.6 上传后管理

上传完成后，音频会出现在列表中，可以：
- 试听音频
- 查看关联的标注文本
- 编辑音频信息
- 删除音频

## 3. 生成测试用例

### 3.1 用例类型

| 用例类型 | `test_type` | 说明 |
|---------|-------------|------|
| API 用例 | `api` | 通过云端 API 测试，音频直接传给 API |
| E2E 用例 | `e2e` | 通过物理设备测试，需要播放设备 |

### 3.2 创建用例的入口

1. **用例管理页面**：`/TestCaseManager` → 点击「新增用例」
2. **E2E 测试向导 Step 1**：`/E2ETest` → 步骤 1 中直接新增
3. **API 测试向导 Step 1**：`/APITest` → 步骤 1 中直接新增
4. **上传音频时自动创建**：上传时勾选「同时创建测试用例」

### 3.3 用例配置

在用例表单弹窗（CaseForm）中填写：

**基础信息**：
- **用例名称**：如「翻译测试-中文场景01」
- **算法类型**：如 `translation`（选择后表单会动态加载对应的算法参数）
- **标签**：如「中文」「翻译」（便于筛选）

**测试类型**：选择 `api` 或 `e2e`，表单会根据类型显示/隐藏对应字段

**音频配置**：
- 选择关联的音频文件（干声）
- E2E 用例还需配置播放设备、SPL（声压级）
- 可选配置背景噪声音频

**算法参数**：
- 根据算法类型动态显示参数表单（如翻译方向、语言对等）
- 参数由 `case_algorithm_params` 表驱动，DynamicForm 动态渲染

**评估维度**：
- 选择评估维度，实际可用维度取决于评估服务（eval_server）支持的计算器
- 当前 eval_server 支持 **WER**（词错误率）和 **DER**（二极管错误率）

**参考参数**：
- 创建用例时系统会自动从音频标注中提取生成参考参数
- 参考参数是评估时的对比基准
- 同一音频在不同算法类型下生成的参考参数不同（由 `AlgorithmReferenceParam` 表配置驱动）

### 3.4 用例的其他操作

- **复制用例**：快速基于已有用例创建新用例
- **导入/导出**：支持 Excel 批量导入导出用例
- **下载模板**：从 `/TestCaseManager` 下载导入模板

## 4. 端到端（E2E）测试

### 4.1 前置准备

1. **设备已连接**：在 `/Device` 页面确认测试设备已连接（ADB/HDC）并在线
2. **播放设备已配置**：确认播放设备（音箱）已添加
3. **用例已创建**：在 `/TestCaseManager` 或测试向导中准备好 `e2e` 类型用例
4. **算法已配置**（可选）：在 `/AlgorithmConfig` 配置算法参数模板

### 4.2 E2E 测试五步向导

进入 `/E2ETest` 页面，按以下步骤操作：

#### Step 0：选择算法
- 在算法选择面板中选择算法类型
- 可新增或配置算法参数

#### Step 1：选择测试用例
- 用例列表会按分组展示，仅显示 `test_type='e2e'` 的用例
- 勾选要执行的用例（支持多选）
- 可在此新增、编辑、导入、导出用例

#### Step 2：选择测试设备
- 设备资源网格显示所有在线设备
- 支持扫描设备（点击「扫描」按钮触发 ADB/HDC 扫描）
- 按状态过滤（在线/离线/忙碌）
- 选择要使用的设备（支持多选，可并行测试）

#### Step 3：执行测试
1. 点击「开始任务」创建并启动任务
2. 测试执行组件展示实时进度：
   - 总进度条
   - 完成 / 进行中 / 待执行 / 失败 数量统计
   - 每个用例的执行状态
3. 支持的操作：
   - **暂停**：暂停当前任务
   - **恢复**：恢复暂停的任务
   - **停止**：终止任务执行
   - **查看日志**：实时查看执行日志

#### Step 4：查看结果
- 任务完成后自动跳转到结果面板
- 展示测试报告

### 4.3 E2E 执行流程

每个 E2E 用例的执行是**单轮线性流程**：

1. **获取数据**：验证参数，加载用例配置、音频、参考参数
2. **准备音频**：从用例配置中提取干声音频和噪声音频，准备播放信息
3. **初始化设备**：获取设备信息，初始化设备驱动（ADB/HDC）
4. **设备预处理**：调用设备驱动的 `pre_process` 方法
5. **播放音频**：执行音频播放（支持干声 + 噪声的交叠播放）
6. **设备后处理**：调用设备驱动的 `post_process` 方法
7. **采集结果**：等待设备响应，从设备采集识别结果
8. **处理结果**：处理采集到的结果，提交评估服务进行评分

### 4.4 进度查看

- 前端通过 **WebSocket（SocketIO）** 实时接收进度推送
- 测试执行组件展示每个用例的执行状态
- 刷新页面后可重新连接恢复进度显示

## 5. API 测试

### 5.1 前置准备

1. **被测 API 已配置**：在 `/Device` 页面的「测试 API 管理」标签中添加被测 API
2. **api_adapter_service 已启动**：确保适配器服务（默认端口 8000）运行中
3. **eval_server 已启动**：确保评估服务运行中
4. **用例已创建**：准备好 `test_type='api'` 的用例

### 5.2 配置被测 API

在 `/Device` 页面 → 「测试 API 管理」标签：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 名称 | API 名称 | 翻译API-火山引擎 |
| 厂商 | 厂商标识 | volc |
| API URL | 被测 API 地址 | http://192.168.1.100:9000 |
| 算法类型 | 关联的算法 | translation |
| 最大并发 | 并发上限 | 5 |
| 超时时间 | 单次请求超时（秒） | 60 |
| 最大音频时长 | 音频时长上限（秒） | 120 |

配置完成后建议点击「连接测试」验证 API 可达性。

### 5.3 API 测试五步向导

进入 `/APITest` 页面：

#### Step 0：选择算法
- 选择算法类型

#### Step 1：选择测试用例
- 仅显示 `test_type='api'` 的用例
- 勾选要执行的用例

#### Step 2：选择被测 API
- API 资源网格显示所有在线 API
- 按算法类型过滤（只显示匹配所选算法的 API）
- 选择要测试的 API（支持多选）

#### Step 3：执行测试
- 使用测试执行组件展示进度
- 支持暂停/恢复/停止

#### Step 4：查看结果
- 展示测试报告

### 5.4 API 测试执行流程

三服务协作架构：

```
主后端 (Flask)  →  api_adapter_service (8000)  →  被测厂商 API (9000)
```

每个 API 用例的执行是**单轮线性流程**：

1. **获取数据**：验证参数，加载用例配置、音频、参考参数
2. **健康检查**：检查 `api_adapter_service` 可用性
3. **创建远程任务**：将音频和参数发送到 `api_adapter_service`
4. **等待完成**：轮询任务状态直到完成或超时
5. **获取结果**：从适配器服务获取最终结果
6. **提取结果**：按配置的响应映射提取 ASR 文本、翻译等字段
7. **创建记录**：保存测试结果到数据库
8. **提交评估**：将结果提交给评估服务评分

### 5.5 API 与 E2E 关键差异

| 维度 | API 测试 | E2E 测试 |
|------|---------|---------|
| 被测目标 | 云端 API | 物理设备 |
| 中转服务 | api_adapter_service (8000) | 无 |
| 音频播放 | 无（直接传给 API） | 有（播放设备 + 交叠播放） |
| 噪声 | 无 | 有 |
| 设备管理 | 无 | 有（ADB/HDC） |

## 7. 常见问题

### Q1：上传大文件失败怎么办？

- 系统支持分块上传（10MB/块）和断点续传
- 刷新页面后可从 LocalStorage 恢复上传进度
- 确认网络稳定，单块上传失败会自动重试

### Q2：标注文件没有自动关联到音频？

- 检查文件名是否一致（去扩展名后必须相同），如 `test01.wav` 和 `test01.json`
- 文件夹导入时检查是否在同一子目录下（按相对路径 + basename 匹配）
- 单文件上传时确保音频和标注文件一起拖入弹窗
- 检查标注文件格式是否正确（JSON 用 `txt` 数组而非 `segments`）

### Q3：E2E 测试设备不在线？

- 在 `/Device` 页面点击「扫描设备」重新扫描
- 确认 ADB（Android）或 HDC（HarmonyOS）已安装并配置到 PATH
- 检查设备 USB 调试是否开启 / 无线调试是否连接
- 点击「健康检查」确认设备状态

### Q4：API 测试报连接错误？

- 确认 `api_adapter_service`（默认端口 8000）已启动
- 确认 `eval_server`（评估服务）已启动
- 在「测试 API 管理」中点击「连接测试」验证被测 API 可达
- 检查被测 API 的 URL、Headers（Authorization）、超时配置

### Q5：如何批量创建用例？

- **方式 1**：上传音频时勾选「同时创建测试用例」
- **方式 2**：文件夹批量导入时设置分组，自动为每个音频创建用例
- **方式 3**：下载用例导入模板，填写 Excel 后批量导入

### Q6：如何重新评估已有结果？

- 在报告详情页点击「重新评估」
- 系统会基于已有的测试结果重新调用评估服务
- 无需重新执行测试，节省时间

### Q7：参考参数（reference_params）是怎么生成的？

- 创建用例时，系统自动从音频关联的标注中提取生成
- 生成规则由 `AlgorithmReferenceParam` 表配置驱动（按算法类型不同而不同）
- 标注的 `code`/`format`/`source_language`/`target_language` 必须和配置中的 `annotation_code`/`annotation_format` 匹配才能正确提取
- 同一音频在不同算法类型下生成的参考参数完全不同
