## 一、项目概述

### 1.1 技术栈

| 类别 | 技术 |
|------|------|
| 后端框架 | Flask + Flask-SocketIO |
| 数据库 | PostgreSQL + SQLAlchemy ORM |

3. **工厂模式应用**: DeviceDriverFactory 实现设备驱动的动态创建
4. **策略模式应用**: 不同设备驱动通过关键字匹配选择

## 三、数据模型审计

### 3.1 核心实体关系

```
Task (测试任务)
  ├── 1:N → TaskCase (任务用例关联)
  ├── N:M → Device (被测设备)
  ├── N:M → API (API服务)
  └── 1:N → TestResult (测试结果)
        └── 1:N → TestResultDimension (维度得分)

TestCase (测试用例)
  ├── N:1 → TestCaseGroup (用例分组)
  ├── N:M → Audio (音频文件)
  └── N:M → Tag (标签)

Dimension (评估维度)
  ├── N:1 → Category (评估分类)
  └── 自关联 → parent_dimension (主维度-子维度)
```

### 3.2 设计亮点

1. **统一时间处理**: 所有时间戳使用东八区时间 (`utc8now()`)
2. **逻辑删除**: 使用 `deleted` / `is_deleted` 标志实现软删除
3. **JSON 配置**: 灵活存储动态配置数据
4. **索引优化**: 合理的复合索引设计

```python
# models.py - 索引设计示例
__table_args__ = (
```

## 四、核心模块审计

### 4.1 执行引擎 (ExecutionEngine)

**文件位置**: `backend/utils/execution_engine.py`

**设计特点**:
- 单例模式确保全局唯一实例
- 任务队列管理 + 并发控制
- 独立线程池隔离 (API任务池 / 设备控制池 / 音频播放池)
- 任务暂停/恢复/停止机制完善
- 服务重启时自动恢复任务状态

**关键代码**:
```python
# 独立线程池隔离 - 解决前端刷新导致音频播放卡顿问题
self.api_task_pool = ThreadPoolExecutor(max_workers=10, thread_name_prefix='api_task_')
self.device_control_pool = ThreadPoolExecutor(max_workers=5, thread_name_prefix='device_ctrl_')
self.audio_playback_pool = ThreadPoolExecutor(max_workers=3, thread_name_prefix='audio_play_')
```

**潜在问题**:
- 数据库会话管理可优化，建议使用上下文管理器确保会话关闭

### 4.2 评估服务 (EvaluationService)

**文件位置**: `backend/utils/evaluation_service.py`

**设计特点**:
- 多端点 Worker 架构，按评估API端点分组处理
- 异步提交评估任务，不阻塞主流程
- 支持主维度-子维度层级评估
- 自动加载维度端点配置

**架构图**:
```
EvaluationService
    ├── api_client (EvaluationAPIClient)
    ├── result_processor (EvaluationResultProcessor)
    └── endpoint_workers: {endpoint_url: EndpointWorker}
          └── task_queue + worker_thread
```

### 4.3 设备驱动工厂 (DeviceDriverFactory)

**文件位置**: `backend/device_driver/driver_factory.py`

**设计特点**:
- 工厂模式 + 策略模式组合

- Mock 模式支持测试
- 自动清理设备连接

## 五、安全性审计

### 5.1 🔴 高风险问题

| 序号 | 问题 | 文件位置 | 风险等级 | 说明 |
|------|------|----------|----------|------|
| 1 | 硬编码数据库密码 | `config/config.py:13` | **高** | `postgresql://...:intelligent_audio_test666@...` |
| 2 | 弱密钥 | `config/config.py:7` | **高** | `SECRET_KEY = 'dev-key-12345'` 过于简单 |
| 3 | CORS 全开 | `app.py:45` | **中高** | `cors_allowed_origins="*"` 允许所有来源 |

### 5.2 🟡 中风险问题

| 序号 | 问题 | 说明 |
|------|------|------|
| 1 | 无认证中间件 | 缺少统一的身份认证拦截器 |
| 2 | 敏感信息日志 | 部分日志可能包含敏感数据 |
| 3 | WebSocket 无认证 | WebSocket 连接未做身份验证 |
| 4 | 硬编码路径 | ffmpeg 路径硬编码在配置中 |
