## 系统启动

1. 启动后端服务（Flask）：
   ```bash
   cd backend
   python app.py
   ```
2. 启动前端（开发模式）：
   ```bash
   cd frontend
   npm run dev
   ```
   或使用 Electron 打包后的桌面端应用。

3. 打开应用后，首页导航栏提供以下入口：

   | 菜单 | 路径 | 用途 |
   |---|---|---|
   | 首页 | `/` | 仪表盘概览 |
   | 音频导入 | `/AudioImport` | 上传音频、生成用例 |
   | 用例管理 | `/TestCaseManager` | 查看和编辑测试用例 |
   | API 测试 | `/APITest` | API 接口测试流程 |
   | 端到端测试 | `/E2ETest` | 物理设备端到端测试 |
   | 任务记录 | `/tasks` | 查看历史任务 |
   | 历史报告 | `/history-reports` | 查看和对比报告 |
   | 算法配置 | `/AlgorithmConfig` | 管理算法定义与参数 |
   | 设备管理 | `/Device` | 管理测试设备 |
   | 评估维度 | `/Evaluation` | 管理评估维度 |

## 上传音频生成测试用例

### 总览

进入 **音频导入** 页面（`/AudioImport`），你可以：

- 上传单个或多个音频文件
- 导入整个文件夹（保留目录结构）
- 在上传时勾选"生成测试用例"，系统会自动根据音频和配置生成对应的测试用例
- 支持分片上传、MD5 秒传、断点续传

### 单文件上传

1. 在音频导入页面，点击 **"上传音频"** 按钮，弹出上传弹窗。
2. 在弹窗中配置上传选项（详见[上传配置项说明](#上传配置项说明)）。
3. 将音频文件拖拽到上传区域，或点击区域选择文件。支持 `.wav`、`.mp3`、`.flac`、`.aac`、`.m4a`、`.ogg` 等常见音频格式。
4. 点击 **"开始上传"**。
5. 上传过程中可看到实时进度条，支持暂停和继续。
6. 上传完成后：
   - 若勾选了 **"生成测试用例"**，系统会在后端自动创建测试用例。
   - 页面提示是否跳转到用例管理页面。

#### 同时上传标注文件

如果音频带有标注（如 ASR 转写文本、说话人分段、翻译参考等），可以将**同名标注文件**与音频文件一起选中或拖入上传区域。系统会自动按文件名匹配（去除扩展名后比对），将标注绑定到对应音频。

- **支持的标注格式**：`.json`、`.jsonl`、`.rttm`、`.stm`、`.txt`
- **同名匹配规则**：标注文件与音频文件去掉扩展名后名称一致即可匹配。例如 `group1.wav` 对应 `group1.json`。
- **标注内容**：JSON/JSONL/RTTM/STM 文件可包含 segments 分段信息（起止时间、说话人、文本等）；`.txt` 文件作为 ASR 参考文本。
- **多轮统一标注**：JSON 文件中可包含 `rounds` 数组，每个 round 的 segments 通过 `audio` 字段指定对应音频，系统会自动分发到各轮。
- **标注代码**：可在弹窗中的"标注代码"下拉框中指定（留空则使用 JSON 内的 `code`/`name` 字段）。

> **提示**：标注数据会在上传时一起发送给后端，用于参考参数提取和结果评估（如计算 WER、说话人匹配等）。若不传标注文件，音频仍可正常上传，但部分依赖标注的评估维度将无法计算。

### 文件夹批量导入

1. 在音频导入页面，点击 **"文件夹导入"** 按钮，弹出文件夹导入弹窗。
2. 选择本地文件夹，系统会解析目录结构并按叶子文件夹对音频进行分组。
3. 文件夹内的标注文件（`.json`/`.jsonl`/`.rttm`/`.stm`/`.txt`）也会被自动识别并按同名规则匹配到对应音频。
4. 配置上传选项（与单文件上传相同）。
5. 点击 **"开始上传"**，系统会按文件夹结构批量上传所有音频文件。
6. 上传完成后，每个叶子文件夹会生成一个测试用例分组，分组内的音频按多轮（rounds）配置组织。

> **提示**：文件夹导入适合批量回归测试场景，可以一次性导入数十至数百个音频并自动生成结构化的测试用例。

### 上传配置项说明

在上传弹窗中，你需要配置以下选项：

| 配置项 | 说明 | 示例 |
|---|---|---|
| **音频类型** | 音频的角色分类 | 干声 (dry)、噪声 (noise)、提示词 (prompt)、混合音频 (mixed) |
| **生成测试用例** | 是否在上传时自动生成测试用例 | 勾选后会在上传完成后自动创建用例 |
| **测试类型** | 生成的用例用于哪种测试 | API 测试、E2E 测试、或两者都选 |
| **算法类型** | 被测算法的类型 | ASR（语音识别）、翻译等（需在算法配置页面预先配置） |
| **算法参数** | 传给被测算法的参数 | 根据 `AlgorithmConfig` 中定义的参数表单填写 |
| **播放设备** | E2E 测试时播放音频的设备 | 在设备管理中预先注册的播放设备 |
| **声压级 (SPL)** | 播放音量 | 默认 65 dB |
| **评估维度** | 用于评估结果的维度 | 在评估维度页面预先配置 |
| **标签** | 给音频和用例打标签 | 用于分类和过滤 |
| **分组命名方式** | 测试用例分组的命名规则 | 根目录名 (root)、文件夹名 (folder)、自定义 |

> **多轮测试**：如果上传多个音频文件，系统会将它们组织为多轮（rounds）测试用例。每轮播放一个音频，E2E 执行器会逐轮执行并聚合结果。

### 测试用例管理

上传完成后，进入 **用例管理** 页面（`/TestCaseManager`）：

- **查看用例列表**：支持按分组、标签视图浏览，分页展示。
- **编辑用例**：点击用例卡片打开编辑弹窗，可修改算法参数、音频列表、噪声干扰、参考路径、评估维度等。
- **批量操作**：支持批量修改算法参数、播放设备、SPL、评估维度、噪声、标签、分组等。
- **复制用例**：快速复制现有用例。
- **刷新参考参数**：对用例重新提取参考参数（异步任务，完成后自动更新）。

## 端到端 (E2E) 测试

E2E 测试是本系统的核心功能，通过物理设备播放音频 → 设备采集 → 结果评估的完整链路进行端到端测试。

进入 **端到端测试** 页面（`/E2ETest`），按照 5 步向导完成测试：

### 步骤 1：选择算法

1. 在向导第一步，从算法列表中选择本次测试使用的算法类型。
2. 可选配置算法参数（如需覆盖默认参数）。
3. 点击 **"下一步"**。

### 步骤 2：选择测试用例

1. 系统自动过滤出 `type='e2e'` 的测试用例。
2. 勾选需要执行的测试用例（支持多选）。
3. 可通过分组、标签、搜索快速定位用例。
4. 点击 **"下一步"**。

> **提示**：如果列表为空，说明还没有 E2E 类型的测试用例，请先到音频导入页面上传音频并勾选"生成测试用例"且测试类型选择"E2E 测试"。

### 步骤 3：选择测试设备

1. 选择用于本次测试的物理设备（如测试手机、智能音箱等）。
2. 如设备列表为空，可点击 **"扫描设备"** 按钮自动发现局域网内的设备。
3. 确认设备在线后，点击 **"下一步"**。

### 步骤 4：执行测试

1. 确认用例和设备信息无误后，点击 **"创建并启动任务"**。
2. 系统创建测试任务并开始执行，后端 E2E 执行器按以下流程工作：
   - **准备阶段**：初始化设备、处理参考参数
   - **多轮循环**：按用例配置的 rounds 逐轮执行（播放音频 → 设备采集 → 收集结果）
   - **结果聚合**：多轮结果聚合
   - **评估入队**：结果发送至评估服务计算维度分数
   - **设备清理**：恢复设备状态
3. 执行过程中，页面实时显示：
   - **进度条**：整体完成百分比
   - **日志列表**：实时执行日志（通过 WebSocket 推送）
   - **用例状态卡片**：每个用例的当前状态（等待/执行中/完成/失败）

> **控制操作**：支持暂停、恢复、停止任务。如需重试失败用例，可在任务记录页面操作。

### 步骤 5：查看结果

1. 测试完成后，点击 **"查看结果"** 跳转到报告页面。
2. 报告页面包含：
   - **总览卡片**：整体通过率、平均分等
   - **用例详情**：每个用例的得分、维度明细
   - **时间轴对比**：参考音频与实际采集音频的时间轴可视化对比
   - **图表分析**：按维度、分类、标签的对比图表
3. 支持多任务对比和二次对比。

## API 测试

API 测试与 E2E 测试流程类似，但不需要物理设备，而是直接调用被测算法的 API 接口。

进入 **API 测试** 页面（`/APITest`）：

1. **选择算法**：选择算法类型
2. **选择测试用例**：系统过滤 `type='api'` 的用例
3. **选择 API 端点**：选择被测 API 地址（需预先在 API 管理中配置），支持健康检查
4. **执行测试**：系统通过 API 执行器并发调用被测接口，支持多轮会话
5. **查看结果**：跳转报告页面

> **与 E2E 的区别**：API 测试不涉及音频播放和设备采集，直接将音频数据（或标注参数）通过 HTTP 发送给被测 API，适用于纯算法接口的批量回归测试。

## 报告查看与对比

- **历史报告**（`/history-reports`）：查看所有历史任务报告，支持按时间、算法、状态过滤。
- **报告详情**（`/report/:id`）：查看单个任务的完整报告，包括维度得分、时间轴对比、图表分析等。
- **报告对比**：选择多个报告进行横向对比，支持二次对比（对比结果的再对比）。

## 常见问题

### Q: 上传时提示"MD5 计算失败"？
A: 确保音频文件未被占用（其他程序未打开），且文件大小未超过系统限制。

### Q: 上传后没有生成测试用例？
A: 检查上传时是否勾选了"生成测试用例"选项。若已勾选仍未生成，查看后端日志确认是否报错。

### Q: E2E 测试设备列表为空？
A: 确保设备已通过 `Device` 页面注册，或在步骤 3 点击"扫描设备"自动发现。设备需与测试服务在同一局域网内。

### Q: E2E 测试执行失败？
A: 排查以下点：
- 播放设备是否在线且音量/SPL 设置正确
- 被测设备是否正常响应
- 查看任务执行日志（`LogView` 页面）获取详细错误信息

### Q: 测试用例列表为空？
A: E2E 测试页面只显示 `type='e2e'` 的用例，API 测试页面只显示 `type='api'` 的用例。上传音频时需正确选择测试类型。也可在用例管理页面手动创建或编辑用例类型。

### Q: 如何修改已有用例的算法参数？
A: 进入用例管理页面，点击用例卡片打开编辑弹窗，在"算法参数"步骤中修改。也可使用批量操作功能同时对多个用例修改参数。
