# 测试用例导入导出功能文档

## 1. 功能概述

本功能实现了通过Excel表格和JSON格式的测试用例导入导出功能，支持批量新增与更新，适用于复杂的测试用例管理场景。

**核心特性**：
- 多Sheet Excel模板设计，清晰组织复杂用例数据
- 以用例ID为主键：有ID则更新，无ID则新增
- 关联数据通过ID优先关联，避免重名/改名导致关联错误
- CaseTags Sheet 支持用例-标签关系的显式维护
- 实时导入预览，显示详细数据统计
- 模板下载功能，提供标准导入格式
- 支持批量操作，提高管理效率
- **通用算法参数支持**：通过 algorithm_type 和 algorithm_params 适配多种算法类型

## 2. 算法类型支持

### 2.1 支持的算法类型

系统支持多种算法类型，每种算法有不同的专属参数：

| 算法类型 | 算法标识 | 说明 | 专属参数 |
|----------|----------|------|----------|
| 翻译 | translation | 语音翻译 | translation_direction_id, translation_direction 等 |
| ASR | asr | 语音识别 | - |
| TTS | tts | 语音合成 | - |
| 声纹识别 | speaker_recognition | 说话人识别 | overlap_rate 等 |
| VAD | vad | 语音活动检测 | - |

### 2.2 算法参数结构

所有算法专属参数统一存储在 `algorithm_params` 字段中：

```json
{
  "algorithm_type": "translation",
  "algorithm_params": {
    "translation_direction_id": 1,
    "translation_direction": "zh2en"
  }
}
```

不同算法的参数由数据库 `case_algorithm_params` 表动态配置。

## 3. Excel模板设计

### 3.1 模板结构

```
Excel模板
├── TestCases（用例主信息）
├── AudioConfigs（音频配置）
├── APIDimensions（API评测维度）
├── E2EDimensions（E2E评测维度）
├── Tags（标签配置）
├── Groups（分组配置）
└── CaseTags（用例-标签关联）
```

### 3.2 字段定义

#### TestCases Sheet（用例主信息）

| 字段名 | 数据类型 | 必填 | 说明 | 示例值 |
|--------|---------|------|------|--------|
| ID | 文本 | 否 | 用例ID；有值表示更新该用例，无值表示新增 | 550e8400-e29b... |
| NAME | 文本 | 是 | 用例名称 | ASR准确率测试_001 |
| DESCRIPTION | 文本 | 否 | 用例描述 | 测试语音识别准确率 |
| GROUP_NAME | 文本 | 是 | 分组名称 | 语音测试组 |
| GROUP_ID | 文本 | 否 | 分组ID（优先使用） | 72b8bda7-... |
| ALGORITHM_TYPE | 文本 | 否 | 算法类型 | translation/asr/tts/speaker_recognition/vad |
| ALGORITHM_PARAMS | 文本 | 否 | 算法参数(JSON格式) | {"translation_direction_id":1} |
| TEST_TYPE | 文本 | 否 | api/e2e/both | api |
| NOISE_AUDIO_NAME | 文本 | 否 | 背景噪声名称 | 办公室噪声 |
| NOISE_AUDIO_ID | 数值 | 否 | 背景噪声音频ID（优先使用） | 123 |
| NOISE_SPL | 数值 | 否 | 声压级(dB) | 50 |
| ASR_REFERENCE_TEXT | 文本 | 否 | ASR参考文本 | 你好，世界 |
| TRANSLATION_REFERENCE_TEXT | 文本 | 否 | 翻译参考文本 | Hello, world |
| ASR_REFERENCE_TEXT_API | 文本 | 否 | API测试配置的ASR参考文本 | 你好，世界 |
| TRANSLATION_REFERENCE_TEXT_API | 文本 | 否 | API测试配置的翻译参考文本 | Hello, world |
| ASR_REFERENCE_TEXT_E2E | 文本 | 否 | 端到端测试配置的ASR参考文本 | 你好，世界 |
| TRANSLATION_REFERENCE_TEXT_E2E | 文本 | 否 | 端到端测试配置的翻译参考文本 | Hello, world |
| TAGS | 文本 | 否 | 逗号分隔的标签 | 语音,ASR,基础测试 |
| REMARKS | 文本 | 否 | 额外说明 | 优先级：高 |

**重要说明**：
- `ALGORITHM_TYPE` 字段用于指定用例所属的算法类型
- `ALGORITHM_PARAMS` 字段用于存储算法专属参数（JSON格式字符串）
- 参考文本由系统根据 `AudioConfigs`（按 `TEST_TYPE` 区分 api/e2e）与算法配置自动生成并刷新
- `ASR_REFERENCE_TEXT` / `TRANSLATION_REFERENCE_TEXT` 为兼容字段，建议优先使用带 `_API` / `_E2E` 后缀的字段区分两套配置
- **已移除单独的翻译方向字段**，翻译方向参数需通过 `ALGORITHM_PARAMS` 传入，如 `{"translation_direction_id": 1}`

## 4. 导入语义控制

### 4.1 基于ID的新增/更新规则

| 条件 | 操作类型 | 说明 |
|------|---------|------|
| TestCases.ID 为空 | 新增（INSERT） | 创建新用例并生成新ID；关联Sheet建议用 CASE_NAME 关联 |
| TestCases.ID 有值 | 更新（UPDATE） | 严格更新指定ID的用例；若ID不存在则报错，不会自动按名称匹配；若该用例已逻辑删除则会自动恢复 |

### 4.2 操作示例

**场景1：新增翻译算法用例**
```
ID留空，NAME="翻译测试用例"，GROUP_NAME="翻译测试组"
ALGORITHM_TYPE="translation"，ALGORITHM_PARAMS="{"translation_direction_id":1}"
结果：创建新的翻译类型用例
```

**场景2：新增ASR算法用例**
```
ID留空，NAME="ASR测试用例"，GROUP_NAME="ASR测试组"
ALGORITHM_TYPE="asr"
结果：创建新的ASR类型用例
```

**场景3：更新用例**
```
ID="550e8400-..."，ALGORITHM_PARAMS="{"translation_direction_id":2}"
结果：更新该用例的算法参数
```

**场景4：批量操作**
```
在TestCases Sheet中添加多行：
- 行1: ID留空，NAME="用例1"，ALGORITHM_TYPE="translation"
- 行2: ID="..."，NAME="用例2"，ALGORITHM_TYPE="asr"
结果：依次执行新增、更新操作
```

## 5. 后端API接口

### 5.1 导入/导出接口

| 方法 | 路径 | 功能 | 请求参数 | 响应格式 |
|------|------|------|----------|----------|
| POST | /api/v1/testcases/import | 导入测试用例 | file: 文件流 | `{code: 200, data: {imported_count, updated_count, errors}}` |
| POST | /api/v1/testcases/export | 导出测试用例 | ids: 用例ID列表<br>format: json/xlsx/csv | JSON或文件流 |
| GET | /api/v1/testcases/template/download | 下载模板 | - | Excel文件流 |
| POST | /api/v1/testcases/import/preview | 预览导入文件 | file: 文件流 | `{code: 200, data: {testCases, audioConfigs, ...}}` |

### 5.2 导入处理流程

1. **文件解析**：解析Excel的多个Sheet
2. **数据校验**：验证必填字段、数据格式
3. **确定操作类型**：根据 TestCases.ID 是否为空判定新增/更新
4. **批量处理**：
   - 处理标签和分组（去重、创建）
   - 处理用例主信息（新增/更新）
   - 处理关联数据（音频配置、维度配置）
   - **解析 ALGORITHM_PARAMS 字段**，提取算法参数
5. **刷新参考文本**：自动生成并更新参考文本
6. **返回结果**：返回详细的操作统计和错误信息

### 5.3 导出处理流程

1. **数据查询**：根据条件查询测试用例
2. **数据转换**：
   - 主用例数据转换为TestCases Sheet（包含 algorithm_type 和 algorithm_params）
   - 音频配置展开为AudioConfigs Sheet
   - 维度配置展开为对应维度Sheet
3. **文件生成**：生成多Sheet Excel文件
4. **返回文件**：返回Excel文件流

## 7. 使用指南

### 7.1 导入用例

**步骤**：
1. **下载模板**：点击"下载模板"按钮获取标准Excel模板
2. **填写数据**：按照模板格式填写测试用例数据
   - 在 ALGORITHM_TYPE 列填写算法类型（translation/asr/tts/speaker_recognition/vad）
   - 在 ALGORITHM_PARAMS 列填写算法参数（JSON格式），如 `{"translation_direction_id":1}`
3. **上传文件**：选择填写好的Excel文件
4. **查看预览**：系统显示导入预览，包括用例数量、音频配置等
5. **执行导入**：点击"导入"按钮执行操作
6. **查看结果**：系统显示导入结果统计

**注意事项**：
- 必填字段必须填写完整
- 更新/删除操作需要提供正确的ID
- 音频配置和维度配置需要通过CASE_NAME关联主用例
- ALGORITHM_PARAMS 必须是有效的JSON格式字符串

### 7.2 导出用例

**步骤**：
1. **选择分组**：在导出配置中选择要导出的测试组
2. **配置选项**：选择测试类型、导出格式、包含选项
3. **查看预览**：系统显示导出预览，包括分组统计
4. **执行导出**：点击"导出"按钮生成文件
5. **下载文件**：系统自动下载生成的文件

**导出格式说明**：
- **Excel**：多Sheet结构，包含完整用例数据（含 algorithm_type 和 algorithm_params）
- **JSON**：完整数据结构，包含所有配置
- **CSV**：扁平化数据，适合简单查看

### 7.3 批量操作

**批量新增**：
- 在TestCases Sheet中添加多行数据
- 每行保持ID为空
- 填写不同的用例名称和算法类型

**批量更新**：
- 在TestCases Sheet中添加多行数据
- 每行提供要更新的ID
- 修改需要更新的字段值

说明：
- Excel导入不支持删除；删除请在系统页面或调用删除接口完成

## 8. 错误处理与故障排除

### 8.1 常见错误

| 错误类型 | 错误信息 | 解决方案 |
|----------|---------|----------|
| 文件格式错误 | 请选择.csv、.json或.xlsx格式的文件 | 检查文件扩展名 |
| 文件大小超限 | 文件大小不能超过10MB | 减小文件大小或分批导入 |
| 必填字段缺失 | NAME字段不能为空 | 填写必填字段 |
| ID格式错误 | 无效的用例ID格式 | 确保ID为UUID格式 |
| 分组不存在 | 分组不存在且未指定创建 | 确保GROUP_NAME存在或允许自动创建 |
| 数据格式错误 | WEIGHT必须为0-100之间的数值 | 修正数据格式 |
| 算法参数格式错误 | ALGORITHM_PARAMS必须是有效的JSON | 检查JSON格式是否正确 |

### 8.2 故障排除

1. **导入失败**：
   - 检查Excel文件格式是否正确
   - 验证必填字段是否填写完整
   - 检查ID格式是否为UUID
   - 检查ALGORITHM_PARAMS是否为有效的JSON格式
   - 查看错误信息获取详细原因

2. **导出失败**：
   - 检查选择的测试组是否存在
   - 确认网络连接正常
   - 检查服务器日志获取详细错误

3. **预览失败**：
   - 检查文件是否损坏
   - 确认文件格式正确
   - 尝试重新上传文件
