# 语音测试管理系统 - 系统架构文档

## 1. 系统概述

语音测试管理系统是一个基于Electron+Flask+SQLite的桌面应用，用于管理和执行语音测试任务。系统支持音频文件上传、设备管理、任务调度、结果报告生成等功能，采用前后端分离架构，通过RESTful API和WebSocket进行通信。

## 2. 架构设计

### 2.1 总体架构

系统采用经典的三层架构设计：

1. **表现层**：Electron桌面应用，负责用户交互和界面展示
2. **业务逻辑层**：Flask后端服务，处理业务逻辑和数据处理
3. **数据层**：SQLite数据库，存储系统数据

## 3. 模块设计

### 3.1 前端模块

#### 3.1.1 测试用例管理模块
- **功能**：创建、编辑、删除测试用例，导入导出功能
- **主要组件**：TestCaseListContainer、TestCaseModal、AddTestCaseModal
- **数据流**：
  - 获取测试用例列表：GET /api/v1/testcases
  - 创建测试用例：POST /api/v1/testcases
  - 更新测试用例：PUT /api/v1/testcases/{id}
  - 删除测试用例：DELETE /api/v1/testcases/{id}
  - 导入测试用例：POST /api/v1/testcases/import
  - 导出测试用例：POST /api/v1/testcases/export
  - 下载模板：GET /api/v1/testcases/template/download

#### 3.1.2 设备管理模块
- **功能**：管理音频输入输出设备
- **主要组件**：DeviceList、DeviceForm
- **数据流**：
  - 获取设备列表：GET /api/v1/test-devices
  - 创建设备：POST /api/v1/test-devices
  - 更新设备：PUT /api/v1/test-devices/{id}
  - 删除设备：DELETE /api/v1/test-devices/{id}

#### 3.1.3 任务管理模块
- **功能**：创建和执行测试任务
- **主要组件**：TaskList、TaskDetailModal、TaskTypeModal
- **数据流**：
  - 获取任务列表：GET /api/v1/tasks
  - 创建任务：POST /api/v1/tasks
  - 执行任务：POST /api/v1/tasks/{id}/run
  - 停止任务：POST /api/v1/tasks/{id}/stop
  - 获取任务状态：WebSocket 实时推送

#### 3.1.4 音频管理模块
- **功能**：上传和管理音频文件
- **主要组件**：AudioUpload、AudioList、AudioImport
- **数据流**：
  - 上传音频文件：POST /api/v1/audios/upload

  - 获取音频详情：GET /api/v1/audios/{id}

  - 文件夹批量导入：POST /api/v1/audios/folder-import
  - 删除音频文件：DELETE /api/v1/audios/{id}

#### 3.1.5 报告管理模块
- **功能**：生成和查看测试结果报告
- **主要组件**：ReportList、ReportDetail、ComparisonTableComponent
- **数据流**：

  - 获取报告详情：GET /api/v1/reports/{id}

#### 3.1.6 日志管理模块
- **功能**：查看实时日志
- **主要组件**：LogViewer
- **数据流**：
  - WebSocket 实时获取日志：/ws/logs 命名空间

#### 3.1.7 API配置管理模块

- **数据流**：

### 3.3 数据层

   - 存储测试任务信息

   - 存储任务与测试用例的关联关系

   - 存储测试执行结果
   - 字段：id, task_case_id, execution_status, error_message, result_data

   - 存储音频文件信息
   - 字段：id, name, path, size, duration, sampling_rate, channels, format, created_at

7. **评估维度表 (dimensions)**
   - 存储评估维度信息
   - 字段：id, name, type, description, keywords, score_unit, result_type, threshold

8. **标签表 (tags)**
   - 存储通用标签

9. **用例标签关联表 (test_case_tags)**
   - 存储用例与标签的关联
   - 字段：id, testcase_id, tag_id

10. **API配置表 (api_configs)**
    - 存储第三方API配置信息
    - 字段：id, name, description, status, meta, default_max_process, default_max_timeout, default_max_audio_duration, health_score

11. **播放设备表 (playback_devices)**
    - 存储回放设备信息
    - 字段：id, name, device_type, device_unique_id, description, status, config

12. **设备表 (devices)**
    - 存储测试设备信息
    - 字段：id, name, type, description, created_at, updated_at

13. **日志表 (logs)**
    - 存储系统日志
    - 字段：id, level, module, category, message, task_id, api_id, test_case_id, created_at

14. **SPL映射表 (spl_mappings)**
    - 存储声压级映射配置
    - 字段：id, name, description, mappings, created_at, updated_at

15. **翻译方向表 (translation_directions)**
    - 存储翻译方向配置
    - 字段：id, name, source_language, target_language, description

16. **音频翻译表 (audio_translations)**
    - 存储音频翻译文本
    - 字段：id, audio_id, direction_id, translated_text

## 5. 接口设计

### 5.1 RESTful API 设计原则

1. **资源导向**：使用名词表示资源，如 /api/v1/testcases
2. **HTTP 方法**：使用 HTTP 方法表示操作，如 GET/POST/PUT/DELETE
3. **状态码**：使用标准 HTTP 状态码表示响应状态
4. **响应格式**：统一使用 JSON 格式返回数据
5. **版本控制**：在 URL 中包含版本号，如 /api/v1/
6. **分页**：列表接口支持分页，使用 page 和 page_size 参数
7. **过滤**：支持按字段过滤，使用 query 参数
8. **排序**：支持按字段排序，使用 sort 参数

### 5.2 统一响应格式

所有 API 接口返回统一格式：

```json
{
  "code": 0,      // 0 表示成功，非0表示失败
  "message": "操作成功",  // 响应消息
  "data": {},     // 响应数据
  "detail": null  // 错误详情，仅在失败时返回
}
```

### 5.4 WebSocket 接口

#### 5.4.1 任务状态推送
- **命名空间**：默认命名空间
- **连接地址**：ws://localhost:5000/socket.io/
- **事件**：
  - task_status_update：任务状态更新
  - task_case_update：任务用例状态更新
  - task_progress：任务进度更新

#### 5.4.2 日志推送
- **命名空间**：/ws/logs
- **连接地址**：ws://localhost:5000/ws/logs
- **事件**：
  - log_message：新日志消息
  - set_filter：设置日志过滤条件

#### 5.4.3 执行引擎推送
- **命名空间**：默认命名空间
- **事件**：
  - execution_started：执行开始
  - execution_completed：执行完成
  - execution_failed：执行失败

## 7. 安全设计

- **数据备份**：定期备份数据库

### 7.3 网络安全
- **HTTPS**：生产环境使用 HTTPS

- **日志安全**：敏感信息脱敏

- **依赖安全**：定期更新依赖包
- **请求限制**：实现 API 请求频率限制
