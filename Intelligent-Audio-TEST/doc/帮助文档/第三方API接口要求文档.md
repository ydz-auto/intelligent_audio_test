# 第三方API接口要求文档

## 1. 概述

本文档定义了第三方API需要提供的接口规范，用于与系统进行集成。系统将调用这些接口进行音频处理、任务执行等操作。第三方API需要严格按照本文档的规范实现相应的接口，以确保与系统的正常集成。

## 2. 基础信息

### 2.1 协议要求

- **通信协议**: HTTP/HTTPS
- **请求方法**: POST（优先），GET（可选）
- **响应格式**: JSON
- **字符编码**: UTF-8
- **数据传输**: 支持JSON和表单数据
- **音频传输**: 支持二进制文件上传

### 2.2 统一响应格式

所有API接口必须返回统一格式的响应：

```json
{
  "code": 0, // 0 表示成功，非0表示失败
  "message": "操作成功", // 响应消息
  "data": {}, // 响应数据，根据接口不同而变化
  "request_id": "uuid-string" // 请求唯一标识符，用于日志追踪
}
```

**错误码定义**:

| 错误码 | 描述 | 说明 |
|--------|------|------|
| 0 | 成功 | 操作成功 |
| 1001 | 参数错误 | 请求参数格式不正确或缺少必填参数 |
| 1002 | 音频格式不支持 | 上传的音频格式不被支持 |
| 1003 | 音频时长超出限制 | 上传的音频时长超过了API允许的最大时长 |
| 1004 | 系统内部错误 | API服务内部出现错误 |
| 1005 | 请求频率过高 | 超过了API的请求频率限制 |
| 1006 | 认证失败 | API认证失败 |
| 1007 | 资源不存在 | 请求的资源不存在 |

## 3. 接口详细说明

### 3.1 系统接口

#### 3.1.1 健康检查

**URL**: `/health`
**方法**: GET
**功能**: 检查API服务的健康状态

**请求参数**: 无

**响应数据**:

```json
{
  "code": 0,
  "message": "服务正常",
  "data": {
    "status": "healthy",
    "version": "1.0.0",
    "timestamp": 1234567890
  },
  "request_id": "uuid-string"
}
```

### 3.2 音频处理接口

#### 3.2.1 创建任务

**URL**: `/api/create_task`
**方法**: POST
**功能**: 提交音频处理任务，返回任务ID

**请求参数**:

| 参数名 | 类型 | 必填 | 描述 | 示例值 |
|--------|------|------|------|--------|
| audio_path | string | 是 | 音频文件路径（绝对路径） | "D:\\audios\\test.wav" |
| trans_direction | string | 是 | 翻译方向，如"zh2en" | "zh2en" |
| vendor | string | 是 | 供应商标识 | "mock" |

**请求示例**:

```json
{
  "audio_path": "D:\\audios\\test.wav",
  "trans_direction": "zh2en",
  "vendor": "mock"
}
```

**响应数据**:

```json
{
  "code": 0,
  "message": "任务创建成功",
  "data": {
    "task_id": "task-123456789"
  },
  "request_id": "uuid-string"
}
```

#### 3.2.2 获取任务状态

**URL**: `/api/get_status/{task_id}`
**方法**: GET
**功能**: 查询指定任务的执行状态和进度

**路径参数**:

| 参数名 | 类型 | 必填 | 描述 | 示例值 |
|--------|------|------|------|--------|
| task_id | string | 是 | 任务ID | "task-123456789" |

**请求参数**:

| 参数名 | 类型 | 必填 | 描述 | 示例值 |
|--------|------|------|------|--------|
| task_id | string | 是 | 任务ID（也可通过路径参数传递） | "task-123456789" |

**响应数据**:

```json
{
  "code": 0,
  "message": "查询成功",
  "data": {
    "task_id": "task-123456789",
    "status": "running", // running, completed, success, failed, error
    "progress": 50, // 0-100
    "start_time": 1234567890,
    "end_time": null
  },
  "request_id": "uuid-string"
}
```

#### 3.2.3 获取帧结果

**URL**: `/api/get_frame_results/{task_id}`
**方法**: GET
**功能**: 查询任务的帧级别结果（用于调试）

**路径参数**:

| 参数名 | 类型 | 必填 | 描述 | 示例值 |
|--------|------|------|------|--------|
| task_id | string | 是 | 任务ID | "task-123456789" |

**请求参数**:

| 参数名 | 类型 | 必填 | 描述 | 示例值 |
|--------|------|------|------|--------|
| page | int | 否 | 页码，默认1 | 1 |
| page_size | int | 否 | 每页条数，默认5 | 10 |

**响应数据**:

```json
{
  "code": 0,
  "message": "查询成功",
  "data": [
    {
      "frame_id": 1,
      "asr_result": "第一帧识别结果",
      "trans_result": "First frame translation",
      "timestamp": 1234567890
    },
    {
      "frame_id": 2,
      "asr_result": "第二帧识别结果",
      "trans_result": "Second frame translation",
      "timestamp": 1234567891
    }
  ],
  "request_id": "uuid-string"
}
```

#### 3.2.4 获取最终结果

**URL**: `/api/get_final_result/{task_id}`

**路径参数**:

|--------|------|------|------|--------|
| task_id | string | 是 | 任务ID | "task-123456789" |

**请求参数**:

| 参数名 | 类型 | 必填 | 描述 | 示例值 |
|--------|------|------|------|--------|
| task_id | string | 是 | 任务ID（也可通过路径参数传递） | "task-123456789" |

**响应数据**:

```json
{
  "code": 0,
  "message": "查询成功",
  "data": {
    "task_id": "task-123456789",
```

### 3.3 错误处理要求

1. **错误响应格式**: 所有错误必须返回统一的错误格式
2. **错误码规范**: 必须使用标准的HTTP状态码和自定义错误码
3. **错误信息**: 必须包含清晰的错误描述，便于调试
4. **重试机制**: API需要支持幂等性，允许客户端重试请求

**错误响应示例**:

```json
{
  "code": 1001,
  "message": "参数错误",
  "data": null,
  "error": "缺少必填参数: audio_path",
  "request_id": "uuid-string"
}
```

## 4. 音频处理要求

### 4.1 支持的音频格式

第三方API需要支持以下音频格式：

| 格式 | 扩展名 | MIME类型 |
|------|--------|----------|
| WAV | .wav | audio/wav |
| MP3 | .mp3 | audio/mpeg |
| FLAC | .flac | audio/flac |

### 4.2 音频参数要求

- **采样率**: 支持 8kHz, 16kHz, 22.05kHz, 44.1kHz, 48kHz
- **位深度**: 支持 16bit, 24bit
- **声道数**: 支持单声道（优先），立体声
- **最大时长**: 至少支持60秒，建议支持3600秒
- **文件大小**: 至少支持10MB，建议支持100MB

### 4.3 处理结果要求

音频处理结果需要包含以下信息：

- **最终识别结果**: 完整的ASR识别文本
- **最终翻译结果**: 完整的翻译文本（如果适用）
- **任务状态**: 任务的最终状态
- **处理时间**: 任务的开始时间、结束时间和总处理时长

## 5. 性能要求

### 5.1 响应时间

- **健康检查**: 响应时间不超过1秒
- **任务创建**: 响应时间不超过5秒
- **状态查询**: 响应时间不超过2秒
- **结果查询**: 响应时间不超过5秒
- **任务处理**: 处理速度不低于1.5倍实时速度（例如：60秒音频，处理时间不超过40秒）

### 5.2 并发要求

- **并发请求数**: 至少支持10个并发请求
- **每秒请求数**: 至少支持50个请求/秒

### 5.3 稳定性要求

- **服务可用性**: 99.9%以上
- **错误率**: 低于0.1%
- **故障恢复时间**: 小于5分钟

## 6. 集成测试要求

### 6.1 测试环境

第三方API需要提供测试环境，用于系统集成测试：

- **测试URL**: 提供专门的测试环境URL
- **测试数据**: 提供测试用的音频文件和预期结果
- **测试账号**: 提供测试用的API Key或账号

### 6.2 测试用例

第三方API需要通过以下测试用例：

1. **健康检查测试**: 验证健康检查接口返回正常
2. **任务创建测试**: 验证能够成功创建任务并返回任务ID
3. **任务状态查询测试**: 验证能够查询到正确的任务状态和进度
4. **结果查询测试**: 验证能够查询到正确的最终结果
5. **错误处理测试**: 验证错误情况下的处理逻辑
6. **并发测试**: 验证并发请求下的处理能力
7. **边界测试**: 验证音频时长、大小等边界条件

## 7. 监控和日志

### 7.1 监控要求

第三方API需要提供以下监控指标：

- **请求量**: 每秒/每分钟请求数
- **响应时间**: 平均响应时间、最大响应时间
- **错误率**: 错误请求占总请求的比例
- **成功率**: 成功请求占总请求的比例

### 7.2 日志要求

第三方API需要记录以下日志信息：

- **请求日志**: 包含请求URL、参数、时间、IP等信息
- **响应日志**: 包含响应状态、时间、数据大小等信息
- **错误日志**: 包含错误码、错误信息、堆栈跟踪等
- **性能日志**: 包含处理时间、资源消耗等信息
