# 音频导入与测试用例生成使用文档

> 适用范围：智能语音测试系统（Intelligent-Audio-TEST）
> 对应版本：多轮上传 + 统一标注文件 + isFinalMerge 机制（2026-07-08 后）
> 相关代码：
> - 前端入口：`frontend/src/views/AudioImportLogic/audioImport.ts`
> - 文件夹解析：`frontend/src/utils/folderParser.ts`
> - 文件夹导入弹窗：`frontend/src/components/common/modal/FolderImportModal.vue`
> - 普通上传弹窗：`frontend/src/components/common/modal/UploadFileModal.vue`
> - 后端用例创建：`backend/controllers/audio_controller.py` → `_create_test_case_from_audio`
> - 后端合并：`backend/controllers/audio_controller.py` → `merge_chunks`

## 一、功能概述

音频导入是测试数据准备的入口，支持多种方式把音频文件入库，并可在导入时**自动生成测试用例**。导入过程支持：

- 分块上传（10MB/块，支持 30GB+ 大文件、1280+ 文件批量）
- MD5 秒传（相同文件不重复上传）
- 断点续传（页面刷新后可恢复）
- 标注文件自动解析（JSON / RTTM / STM / TXT）
- 统一标注文件（含 `rounds` 数组，控制多轮用例结构）
- 按文件夹结构自动分组，每个子文件夹独立生成一个测试用例

---

## 二、导入入口与方式

系统提供 5 种导入入口，其中只有 2 种走完整的分片上传 + 用例生成流程：

| 入口 | 触发位置 | 是否解析文件夹结构 | 是否支持生成测试用例 |
|------|---------|----------------|----------------|
| 上传音频 | 页面「上传音频」按钮 → `UploadFileModal` | 否（多选/拖拽） | 是 |
| 批量从文件夹导入 | 页面「批量从文件夹导入」按钮 → `FolderImportModal` | 是（按最子级文件夹分组） | 是 |
| 拖拽到页面 | 拖拽文件到页面 | 否 | 是（走 `startUploadProcess`） |
| 直接选文件 | 调用 `pickFiles` | 否 | 是（走 `startUploadProcess`） |
| URL 导入 | `URLImportModal`（模态已注册） | 否 | 否（仅入库，不生成用例） |

> 说明：URL 导入模态已注册但未接入 `startUploadProcess`，当前仅下载入库，不创建测试用例。如需通过 URL 导入生成用例，需额外开发。

### 2.1 上传音频（UploadFileModal）

- 支持文件多选和拖拽
- 支持的音频格式：`wav`、`mp3`、`m4a`、`flac`、`aac`、`ogg`
- 不解析 `webkitRelativePath`，所有文件无文件夹结构
- 可配置生成测试用例，但**无统一标注文件概念**，每个文件按文件名独立分组

### 2.2 批量从文件夹导入（FolderImportModal）

- 选择整个文件夹，保留 `webkitRelativePath`
- 按「最子级文件夹」自动分组：`root/folder1/audio.wav` → 分组键 `folder1`
- 每个分组独立构建一个 `testCaseConfig`，独立生成一个测试用例
- 支持统一标注文件（如 `9/9.json`），按分组键分发覆盖该分组的 rounds 配置
- 支持的标注格式：`json`、`jsonl`、`rttm`、`stm`、`txt`

## 三、测试用例生成模式

### 3.1 核心原则：轮次由 JSON 配置决定

**所有批量导入的轮次结构最终都看 JSON 配置**，具体是 `rounds` 数组：

1. **分组有同名 JSON 且含 `rounds` 数组** → 该分组的 rounds **完全由 JSON 决定**，覆盖 folderParser 的自动推断
2. **分组无 rounds JSON** → folderParser 按该分组音频数量自动推断：
   - 1 个音频 → 1 轮 1 音频
   - N 个音频 → 1 轮 N 音频（`single_round_multi_audio`）

> 重要：分组内多音频不一定是「1 轮 N 音频」。只有在该分组**没有 rounds JSON** 时才按音频数推断；**有 rounds JSON 时完全按 JSON 的轮次结构走**，可能是 N 轮每轮 M 音频。

### 3.2 用例生成模式总览

#### 模式 A：文件夹导入（有文件夹结构）

**每个子文件夹 = 1 个独立测试用例**

- 代码位置：`audioImport.ts` 的 `startUploadProcess` 中 `groupTestCaseConfigs`
- 每个分组（最子级文件夹）独立构建 `testCaseConfig`
- 分组内最后一个文件 `mergeChunks` 时才 `createTestCase=true`，之前的文件只入库
- 后端在最后一个文件合并时，从数据库按 `audio_name` 查到该分组所有已入库音频的 `audio_id`，填入 rounds

**示例**：
- 40 个子文件夹，每个 1 个音频 + 同名 JSON → 生成 40 个用例，每个用例 1 轮
- 1 个子文件夹含 3 个音频 + `9.json`（3 轮）→ 生成 1 个用例，该用例 3 轮

#### 模式 B：非文件夹导入（UploadFileModal / 拖拽 / pickFiles）

**所有文件按文件名分组，通常每个文件自成一组**

- 无 `webkitRelativePath`，分组键退化为「文件名去扩展名」
- 每个文件独立成用例（1 轮 1 音频）
- UploadFileModal 未传 `unifiedRoundsByGroup`，无法表达「多个文件属同一多轮用例」

> 局限：若想让多个独立文件归属同一多轮用例，需使用文件夹导入方式，把文件放入同一子文件夹并配同名 JSON。

### 3.3 用例创建时机：isFinalMerge 机制

多轮上传时，只有分组内最后一个文件 `mergeChunks` 时才创建用例：

```
前端 startUploadProcess
→ 遍历 pendingTasks:
    isGroupFinalMerge = hasGroupRounds && (processedInGroup === pendingInGroup - 1)
    effectiveOptions = (hasGroupRounds && !isGroupFinalMerge)
      ? { ...uploadOptions, createTestCase: false }
      : uploadOptions
→ 只有最后一个文件 createTestCase=true，触发后端 _create_test_case_from_audio
```

前几个文件 `createTestCase=false` 只入库；最后一个文件合并时，后端按 `audio_name` 查库补全所有 `audio_id`。

### 3.4 audio_id 补全机制

最后一个音频 `mergeChunks` 时，前几个音频已入库。后端按 `audio_name` 从数据库查到所有已入库音频的 ID，填入 `rounds_resolved` 对应位置：

```python
# 后端 audio_id 填充逻辑
audio_name_to_id = {}
for round_item in rounds_resolved:
    for audio_item in round_item.get('audios', []):
        item_name = audio_item.get('audio_name') or ''
        if item_name and not audio_item.get('audio_id') and item_name not in audio_name_to_id:
            found = Audio.query.filter_by(name=item_name, deleted=False).first()
            if found:
                audio_name_to_id[item_name] = found.id
```

## 四、统一标注文件格式

### 4.1 文件位置规则

统一标注文件（含 `rounds` 数组）支持两种放置方式：

1. **父级目录同名**：`group1/group1.json`（文件名 = 最子级文件夹名）
2. **同级目录**：`样例/样例.json` + `样例/*.wav`（标注文件和音频文件放同一层）

### 4.2 JSON 结构

```json
{
  "rounds": [
    {
      "round_number": 1,
      "segments": [
        {
          "audio": "audio1.wav",
          "spl": 65,
          "playback_device_name": "设备正面（0.5m+0°）",
          "query": "用户提问内容",
          "correctAnswer": "",
          "correctnessType": "",
          "text": " ",
          "rail_distance": 80,
          "volume_level": 60,
          "interferers": [],
          "voiceprint_enabled": false,
          "voiceprint_spl": 70.0,
          "voiceprint_wait_time": 5.0,
          "input_text": "用户提问内容"
        }
      ]
    },
    {
      "round_number": 2,
      "segments": [
        {
          "audio": "audio2.wav",
          "spl": 70,
          "playback_device_name": "4m+135°",
          "query": "第二轮提问..."
        }
      ]
    }
  ]
}
```

### 4.3 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `rounds` | array | 轮次数组，每项是一轮 |
| `rounds[].round_number` | number | 轮次序号 |
| `rounds[].segments` | array | 该轮的音频段数组 |
| `segments[].audio` | string | 音频文件名（用于匹配音频文件） |
| `segments[].spl` | number | 该音频的声压级 |
| `segments[].playback_device_name` | string | 播放设备名称（后端按名字查表换 `playback_device_id`） |
| `segments[].query` | string | 用户提问/参考文本 |
| `segments[].input_text` | string | 输入文本 |
| `segments[].interferers` | array | 干扰人配置 |
| `segments[].voiceprint_enabled` | boolean | 是否启用声纹 |
| `segments[].voiceprint_spl` | number | 声纹声压级 |
| `segments[].voiceprint_wait_time` | number | 声纹等待时间 |

> 解析流程：`FolderImportModal.vue` 解析统一标注文件 → 提取 rounds 到 `unifiedRoundsByGroup`（按分组键分发）→ `audioImport.ts` 用该分组的 `unifiedRoundsByGroup[groupKey]` 覆盖 `groupConfig.rounds` → `mergeChunks` 透传 `testCaseConfig` → 后端 pydantic 解析 rounds → `rounds_config`

## 五、上传配置选项

### 5.1 通用选项

| 选项 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `audioType` | radio | `dry` | 音频类型：`dry`（干声）/`noise`（噪声）/`prompt`（提示词）/`mixed`（混合） |
| `createTestCase` | boolean | `false` | 是否生成测试用例 |
| `algorithmType` | select | `''` | 算法类型 |
| `testTypes` | checkbox | `['api']` | 测试类型：`api` / `e2e` |
| `dimensions` | dimensions | `[]` | 评估维度（可按 API/E2E 分别配置单轮/多轮评估范围） |
| `playbackDeviceId` | select | `null` | 播放设备 |
| `defaultSpl` | number | `65.0` | 默认声压级 |
| `groupNameType` | radio | `root` | 用例分组：`root`（根目录）/`folder`（文件夹名）/`custom`（自定义） |
| `customGroupName` | text | `''` | 自定义分组名称 |
| `inheritTags` | boolean | `true` | 是否继承音频标签到用例 |

### 5.2 维度的单轮/多轮评估范围

评估维度可按 API 和 E2E 分别配置使用范围：

- `single`（单轮评估）：每轮独立打分
- `multi`（多轮聚合）：所有轮次执行完成后，将多轮结果汇总后统一送给评估端点

两者可同时选择，表示「每轮独立评估 + 多轮结果聚合」。

> 多轮聚合评估不支持需要音频文件的维度。

### 5.3 文件夹分组设置

当 `createTestCase=true` 且 `groupNameType=custom` 时，FolderImportModal 会显示「文件夹分组设置」，允许为每个子文件夹单独指定分组名。

## 六、标注文件解析

### 6.1 支持的标注格式

| 格式 | 扩展名 | 用途 |
|------|--------|------|
| JSON | `.json` | 支持「带时间戳数组」「纯文本」「统一标注 rounds」三种结构 |
| JSONL | `.jsonl` | 每行一个 JSON 对象 |
| RTTM | `.rttm` | 说话人日记标注 |
| STM | `.stm` | NIST 说话人标注 |
| TXT | `.txt` | ASR 文本（已移除自动解析，改为前端显式传 annotations） |

### 6.2 标注匹配规则

FolderImportModal 解析标注文件后，按 `segment.audio` 字段匹配音频文件：

1. 优先按完整 baseKey 匹配（标注目录 + audio 相对路径，去扩展名）
2. 回退按文件名匹配（不带目录前缀）

### 6.3 标注存储

- 所有音频标注由前端解析并存储到 `AudioAnnotation` 表
- 后端不再解析任何标注文件，只负责存储前端传递的标注数据
- 标注数据在 `merge_chunks` 时通过 `annotations` 数组传递，或更新元数据时通过 `update_metadata` 传递

## 七、典型使用场景

### 场景 1：批量导入单轮用例（每个子文件夹 1 个音频）

**目录结构**：
```
接管准确率/
├── 1/
│   ├── B-TA-001_..._今天天气怎么样.json
│   └── B-TA-001_..._今天天气怎么样.wav
├── 2/
│   ├── B-TA-002_..._上海明天气温.json
│   └── B-TA-002_..._上海明天气温.wav
└── ...
```

**结果**：40 个子文件夹 → 40 个独立测试用例，每个用例 1 轮 1 音频。

**配置**：
- 选择「批量从文件夹导入」
- 勾选「生成测试用例」
- 选择测试类型（API / E2E）
- 配置算法类型、播放设备、SPL

### 场景 2：多轮对话用例（一个子文件夹多个音频 + 统一标注）

**目录结构**：
```
9/
├── 9.json                                    # 含 rounds 数组（3 轮）
├── B-TA-009_..._第01轮_想学新乐器求建议.wav
├── B-TA-009_..._第02轮_吉他尤克里里哪个易上手.wav
└── B-TA-009_..._第03轮_决定先学尤克里里.wav
```

**9.json 结构**：
```json
{
  "rounds": [
    { "round_number": 1, "segments": [{ "audio": "B-TA-009_..._第01轮_想学新乐器求建议.wav", "spl": 65.0, "playback_device_name": "设备正面（0.5m+0°）" }] },
    { "round_number": 2, "segments": [{ "audio": "B-TA-009_..._第02轮_吉他尤克里里哪个易上手.wav", "spl": 65.0, "playback_device_name": "设备正面（0.5m+0°）" }] },
    { "round_number": 3, "segments": [{ "audio": "B-TA-009_..._第03轮_决定先学尤克里里.wav", "spl": 65.0, "playback_device_name": "设备正面（0.5m+0°）" }] }
  ]
}
```

**结果**：1 个子文件夹 → 1 个测试用例，该用例 3 轮，每轮 1 音频。

### 场景 3：混合导入（单轮 + 多轮）

**目录结构**：
```
接管准确率/
├── 1/  (1 个音频 + 1 个 JSON)   → 1 个用例，1 轮
├── 2/  (1 个音频 + 1 个 JSON)   → 1 个用例，1 轮
└── 9/  (3 个音频 + 9.json 多轮) → 1 个用例，3 轮
```

**结果**：3 个子文件夹 → 3 个独立测试用例（2 个单轮 + 1 个多轮）。

### 场景 4：单轮多音频（无统一标注 JSON）

**目录结构**：
```
group1/
├── audio1.wav
├── audio2.wav
└── audio3.wav
```

**结果**：1 个子文件夹 → 1 个用例，1 轮 3 音频（folderParser 按 `single_round_multi_audio` 推断）。

> 若需控制为多轮，请加同名 JSON 含 `rounds` 数组。

## 八、完整上传流程

### 8.1 前端流程

```
用户选择文件/文件夹
→ FolderImportModal 解析标注文件、提取 unifiedRoundsByGroup
→ emit('confirm', { files, config, folderGroupMappings, unifiedRoundsByGroup })
→ audioImport.ts startUploadProcess(files, folderGroupMappings, unifiedRoundsByGroup)
→ extractAudioFiles + groupAudioItemsByLeafFolder 分组
→ 为每个分组构建 groupTestCaseConfig（unifiedRoundsByGroup 覆盖 rounds）
→ audiosApi.initUpload() 获取 taskId
→ 为每个文件计算 MD5、创建 UploadFile 记录
→ 遍历文件分块上传：
    isGroupFinalMerge = 该分组最后一个待处理文件
    effectiveOptions.createTestCase = isGroupFinalMerge
    uploadFileChunks / processMergeForExistingFile
→ 分组最后一个文件 mergeChunks 时 createTestCase=true
→ 后端 _create_test_case_from_audio 创建用例
```

### 8.2 后端流程（merge_chunks）

```
接收 mergeChunks 请求（含 testCaseConfig.rounds）
→ 验证文件、任务
→ 秒传检查（MD5 命中则跳过分片合并）
→ 合并分片、提取元数据、保存音频
→ 持久化标注（_persist_annotations_and_raw）
→ 如果 createTestCase=true：
    _create_test_case_from_audio(audio_id, ..., rounds_config)
    → 剥离 algorithm_params 到独立列
    → 按 audio_name 查库补全所有 audio_id
    → 从标注 JSON 提取 spl / playback_device_name 注入到 audios
    → 构建 config.rounds
    → 创建 TestCase 记录
→ db.session.commit()
→ 返回 audio_id / test_case_id / test_case_count
```

## 九、已知限制与注意事项

1. **URL 导入不生成用例**：`URLImportModal` 已注册但未接入 `startUploadProcess`，仅下载入库。
2. **非文件夹入口无法表达多轮归属**：UploadFileModal / 拖拽 / pickFiles 无文件夹结构，每个文件独立成用例，无法把多个独立文件归属同一多轮用例。
3. **断点续传不传 tcConfig**：`resumeUploadTask` 调用 `uploadFileChunks` 时未传 `tcConfig`，续传的文件不走分组用例创建逻辑，可能导致用例不完整。
4. **秒传文件仍会触发用例创建**：秒传文件 `total_chunks=0` 但仍调用 `processMergeForExistingFile`，若该文件是分组最后一个，仍会创建用例。
5. **标注文件必须与子文件夹同名**：统一标注文件位置规则是「文件名 = 最子级文件夹名」或「与音频同级」，否则无法匹配到分组。
6. **audio_name 必须与音频文件名完全一致**：统一标注 JSON 里 `segment.audio` 字段必须与音频文件名（含扩展名）完全一致，否则后端无法按 `audio_name` 查库匹配 `audio_id`。
7. **多轮聚合评估不支持需要音频文件的维度**：如某维度需要音频文件作为参考，则不能用于多轮聚合评估。
