# 报告管理接口

## 1. 概述

本文档描述了测试报告管理模块的 API 接口规范。该模块提供测试报告的增删改查、生成、对比分析、导出等功能。

## 2. 通用规范

### 2.1 基础路径

所有接口的基础路径为 `/api/v1/reports`

### 2.2 通用响应格式

所有接口采用统一的响应格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    // 响应数据
  }
}
```

**字段说明：**

| 字段 | 类型 | 描述 |
|------|------|------|
| code | INTEGER | 错误码，0 表示成功 |
| message | STRING | 操作提示信息 |
| data | OBJECT/ARRAY | 响应数据 |

### 2.3 错误响应格式

```json
{
  "code": 400,
  "message": "错误描述信息",
  "data": null
}
```

### 2.4 HTTP 状态码

| 状态码 | 描述 |
|--------|------|
| 200 | 请求成功 |
| 201 | 资源创建成功 |
| 400 | 请求参数错误 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

## 3. 接口详情

### 3.1 获取报告列表

#### 3.1.1 接口信息

- **URL**: `/api/v1/reports`
- **方法**: `GET`
- **功能**: 获取测试报告列表，支持分页、搜索和筛选

#### 3.1.2 请求参数

| 参数名 | 类型 | 位置 | 必需 | 描述 |
|--------|------|------|------|------|
| page | INTEGER | query | 否 | 页码，默认 1 |
| per_page | INTEGER | query | 否 | 每页记录数，默认 10 |
| type | STRING | query | 否 | 报告类型：task/comparison/secondary_comparison/trend |
| status | STRING | query | 否 | 报告状态：completed/failed/running |
| keyword | STRING | query | 否 | 搜索关键字，匹配报告名称 |

| endTime | STRING | query | 否 | 结束时间，ISO 8601 格式 |

## 4. 报告类型说明

| 类型 | 描述 |
|------|------|
| task | 单任务报告，针对单个测试任务的执行结果 |
| comparison | 对比报告，对比多个任务的测试结果 |
| secondary_comparison | 二次对比报告，对比多个报告的性能趋势 |
| trend | 趋势报告，测试结果趋势分析 |

## 5. 状态说明

| 状态 | 描述 |
|------|------|
| running | 报告生成中 |
| completed | 报告生成完成 |
| failed | 报告生成失败 |

## 6. 注意事项

1. **异步生成**：报告生成是异步操作，提交生成请求后会立即返回，报告在后台生成。
2. **分页查询**：大量报告时建议使用分页查询，默认每页 10 条。
3. **时间过滤**：startTime 和 endTime 需要使用 ISO 8601 格式，如 `2023-01-01T00:00:00`。
4. **导出限制**：导出接口最多支持同时导出 100 个报告。
5. **对比报告**：生成对比报告时，任务数量建议在 2-10 之间，过多会影响分析效果。

## 7. Benchmark 报告接口

> 【实现演进裁定 2026-10-16（INT-481）】Benchmark 排行能力 2026-10-15 恢复实施（INT-400 #8，INT-476）；本章节按 INT-481 后端落地口径回写（报告发布端点 + `benchmark_reports` 第五表），权限码见 `docs/RBAC权限划分.md` §3.16 注。完整设计见《功能设计文档/05_报告管理/报告Benchmark排行功能设计文档.md》§7.3。

基础路径：`/api/v1/benchmarks`（网关 BFF `benchmark_bp.py` 挂载，prefix `/api/v1/benchmarks`）。

### 7.1 发布 Benchmark 报告

`POST /api/v1/benchmarks/reports`

- 权限：`benchmark:report:publish`
- 请求体（全部字段可选 = 聚合当前全量排行快照）：

```json
{
  "taskId": 123,
  "suite": "full-duplex-v1",
  "category": "voice_llm",
  "source": "platform_test",
  "algorithmSet": "",
  "name": "",
  "description": ""
}
```

- 行为：聚合当前排行 ReadModel 快照（可按 suite/category/source 筛选）→ 复用报告 7 表结构建报告主记录（`report_type='benchmark'`，状态 published）→ `benchmark_reports` 落库（`ranking_data` 为发布时点快照，报告不随后续重算漂移）→ 发布 `REPORT_EVENTS` 事件 + 审计。
- 响应：成功 201，`data` 为发布记录（含 `id`/`version`/`report_id`/计数等）。

### 7.2 Benchmark 报告列表

`GET /api/v1/benchmarks/reports`

- 权限：`benchmark:report:read`
- 查询参数：`suite` / `category` / `source`（仅 `platform_test` / `external_import`）/ `taskId` / `page` / `perPage`
- 响应：分页信封 `{items, total, page, per_page, pages}`，`items` 按 `published_at` 倒序；列表不携带大体积 `ranking_data` 快照（详情接口再取）。

### 7.3 Benchmark 报告详情

`GET /api/v1/benchmarks/reports/{reportId}`

- 权限：`benchmark:report:read`
- 响应：发布记录完整字段（含 `ranking_data` 排行快照）；记录不存在返回 404。

## 8. 报告统计分析接口

> 【实施裁定 2026-10-19（INT-791）】本组端点按 FEAT 契约审查（INT-754 17:49 结论）落地，供 G04 报告统计分析页接真实接口。走 report_service 应用层 + 网关透传，不绕网关直连。统计结果四形态（overview/detail/chart/anomaly）；趋势只返回时间序列，预测呈现归前端（不引入后端 ML 预测）。异常统计识别规则见 §8.5。

基础路径：`/api/v1/reports/statistics`（网关 BFF `report_bp.py` 挂载，prefix `/api/v1/reports`）。权限：`report:read`，无新权限码。

### 8.1 统计分析

`GET /api/v1/reports/statistics`

- 权限：`report:read`
- 查询参数：

| 参数名 | 类型 | 必需 | 描述 |
|--------|------|------|------|
| dimension | STRING | 否 | 统计维度：`time`（默认）\|`task_type`\|`device_type`\|`evaluation_metric` |
| start_time | STRING | 否 | 开始时间，ISO 8601（如 `2023-01-01T00:00:00`），按报告创建时间过滤 |
| end_time | STRING | 否 | 结束时间，ISO 8601 |
| algorithm_type | STRING | 否 | 算法类型过滤（按报告用例级算法类型归属匹配） |

- 响应：统一信封 `{success, message, data}`，`data` 含四形态：

```json
{
  "dimension": "time",
  "overview": {
    "report_count": 12, "completed_reports": 10, "failed_reports": 2,
    "total_cases": 360, "completed_cases": 320, "failed_cases": 40,
    "pass_rate": 88.9, "duration": 7200.0
  },
  "detail": [
    {"group": "2026-10-01", "report_count": 3, "total_cases": 90,
     "completed_cases": 80, "failed_cases": 10, "pass_rate": 88.9,
     "duration": 1800.0}
  ],
  "chart": {
    "categories": ["2026-10-01"],
    "series": [
      {"name": "报告数量", "data": [3]},
      {"name": "总用例数", "data": [90]},
      {"name": "通过率", "data": [88.9]}
    ]
  },
  "anomaly": [
    {"type": "low_pass_rate", "report_id": 5, "report_name": "xxx",
     "message": "通过率偏低", "value": 42.5}
  ]
}
```

- 维度说明：
  - `time`：按报告创建日期（YYYY-MM-DD）分组；detail 每行含 `group`。
  - `task_type`：按报告级设备/API 参与形态派生分组（`api`=无物理设备、`e2e`=含物理设备且无 API、`mixed`=物理+API 兼有；对照任务级 INT-273 派生口径）。
  - `device_type`：按报告元数据设备类型分组；detail 每行含 `device_count`。
  - `evaluation_metric`：按评估指标聚合（detail 每行含 `metric`/`report_count`/`average_value`/`min`/`max`）；chart series 为「平均得分」。

### 8.2 趋势分析

`GET /api/v1/reports/statistics/trend`

- 权限：`report:read`
- 查询参数：

| 参数名 | 类型 | 必需 | 描述 |
|--------|------|------|------|
| trend_type | STRING | 否 | 趋势类型：`time`（默认）\|`dimension` |
| metric | STRING | 否 | 评估指标名（`trend_type=dimension` 时按该指标展开；缺省返回全部指标） |
| start_time | STRING | 否 | 开始时间，ISO 8601 |
| end_time | STRING | 否 | 结束时间，ISO 8601 |

- 响应：

```json
{
  "trend_type": "time",
  "time_trend": [
    {"date": "2026-10-01", "report_count": 3, "total_cases": 90,
     "pass_rate": 88.9, "duration": 1800.0}
  ],
  "dimension_trend": [
    {"metric": "清晰度", "points": [{"date": "2026-10-01", "value": 85.5}]}
  ]
}
```

- 说明：`trend_type=time` 返回 `time_trend` 时间序列；`trend_type=dimension` 返回 `dimension_trend`（按指标聚合的时间序列）。**只返回时间序列数据，预测呈现（虚线等）归前端**，不引入后端 ML 预测。

### 8.3 报表生成

`POST /api/v1/reports/statistics/report`

- 权限：`report:read`
- 请求体：

```json
{
  "report_type": "report_count",
  "content": "",
  "format": "csv",
  "time_range": {"start_time": "2026-10-01T00:00:00", "end_time": "2026-10-31T23:59:59"}
}
```

| 字段 | 类型 | 必需 | 描述 |
|------|------|------|------|
| report_type | STRING | 是 | 报表类型：`report_count`（报告数量，默认）\|`case_execution`（用例执行）\|`evaluation_metric`（评估指标）\|`device_performance`（设备性能） |
| content | STRING | 否 | 报表内容（可空，§2.2 口径预留扩展） |
| format | STRING | 否 | 格式：`csv`（默认）\|`excel`\|`pdf`\|`html` |
| time_range | OBJECT | 否 | 时间范围 `{start_time, end_time}`（ISO 8601，按报告创建时间过滤） |

- 响应：复用导出二进制下载链路（`mime_type`/`filename`/`content_base64`，路由层转 `Content-Disposition: attachment` Blob 下载）：

```json
{
  "filename": "statistics_report_20261019.csv",
  "format": "csv",
  "content_base64": "<base64>",
  "mime_type": "text/csv"
}
```

- 说明：`device_performance` 报表逐设备行（数据源为报告 `report_metric_stats.device_stats` 快照）；其余报表按时间分组或按指标聚合。

### 8.4 错误码

| 错误码 | 描述 |
|--------|------|
| 400 | dimension / trend_type / report_type / format 非法值，或参数格式错误 |

### 8.5 异常统计识别规则

| 规则 | 判定 | 说明 |
|------|------|------|
| 无用例数据 | `total_cases = 0` | 报告无用例数据（anomaly type=`no_cases`） |
| 通过率偏低 | `total_cases > 0 且 pass_rate < 60` | 通过率低于阈值（type=`low_pass_rate`） |
| 数据异常 | `failed_cases > total_cases 或 pass_rate > 100` | 数据超出合理范围（type=`data_error`） |

> 注：规则为实施裁定定稿值（INT-791）；如需调整阈值或新增规则，回写本文档并开对齐卡。
