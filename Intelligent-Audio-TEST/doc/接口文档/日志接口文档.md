# 日志管理模块 API 接口文档

## 概述

日志管理模块负责系统日志的查看、统计、导出和实时监控。通过 RESTful API 和 WebSocket 提供完整的日志管理功能，支持分页查询、高级过滤、批量标记、选择性清除和多格式导出。

## 基础信息

- **基础路径**: `/api/v1/logs`
- **WebSocket 路径**: `/ws/logs`
- **Content-Type**: `application/json`

## 错误响应格式

所有接口在发生错误时返回统一格式的错误响应：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "错误描述信息"
  },
  "data": null
}
```

### 通用错误码

| 错误码 | 说明 |
|--------|------|
| PARAM_MISSING | 缺少必要参数 |
| PARAM_INVALID | 参数格式无效 |
| NOT_FOUND | 资源不存在 |
| DATABASE_ERROR | 数据库操作失败 |

## 接口列表

### 1. 获取日志列表

获取系统日志列表，支持分页和高级过滤。

**请求信息**

| 属性 | 值 |
|------|-----|
| URL | `GET /api/v1/logs` |
| 方法 | GET |

**请求参数 (Query Parameters)**

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| page | integer | 否 | 1 | 当前页码，从 1 开始 |
| perPage | integer | 否 | 50 | 每页显示数量，支持参数别名: per_page |
| level | string | 否 | - | 日志级别筛选，支持多级别如 "debug,info,warning" |
| module | string | 否 | - | 模块名称筛选（精确匹配） |
| category | string | 否 | - | 日志分类筛选 (system/execution/device/task/api) |
| keyword | string | 否 | - | 关键字搜索，匹配日志内容 |
| contentInclude | string | 否 | - | 内容包含关键词，参数别名: content_include |
| contentExclude | string | 否 | - | 内容排除关键词，参数别名: content_exclude |
| startTime | string | 否 | - | 开始时间筛选，ISO 8601 格式，参数别名: start_time |
| endTime | string | 否 | - | 结束时间筛选，ISO 8601 格式，参数别名: end_time |
| mark | string | 否 | - | 标记筛选 ('true' 或 'false') |
| deviceId | integer | 否 | - | 设备 ID 筛选，参数别名: device_id |
| taskId | integer | 否 | - | 任务 ID 筛选，参数别名: task_id |
| apiId | integer | 否 | - | API ID 筛选，参数别名: api_id |
| testCaseId | integer | 否 | - | 测试用例 ID 筛选，参数别名: test_case_id |
| threadId | string | 否 | - | 线程 ID 筛选（模糊匹配），参数别名: thread_id |

**请求示例**

```bash
curl -X GET "http://localhost:5000/api/v1/logs?page=1&perPage=20&level=error&module=TASK" \
  -H "Content-Type: application/json"
```

**成功响应**

```json
{
  "success": true,
  "error": null,
  "data": {
    "items": [
      {
        "id": 1234,
        "time": "2024-01-15T10:30:45",
        "level": "error",
        "category": "system",
        "module": "TASK",
        "source": "backend",
        "content": "Task execution failed: connection timeout",
        "mark": "flagged",
        "deviceId": 1,
        "taskId": 5,
        "apiId": null,
        "testCaseId": "case_001",
        "threadId": "12345"
      }
    ],
    "total": 150,
    "page": 1,
    "perPage": 20,
    "pages": 8
  }
}
```

**响应字段说明**

| 字段 | 类型 | 说明 |
|------|------|------|
| items | array | 日志条目数组 |
| items[].id | integer | 日志唯一标识 |
| items[].time | string | 日志时间，ISO 8601 格式 |
| items[].level | string | 日志级别 (debug/info/warning/error) |
| items[].category | string | 日志分类 |
| items[].module | string | 模块名称 |
| items[].source | string | 日志来源 |
| items[].content | string | 日志内容 |
| items[].mark | string | 标记状态 |
| items[].deviceId | integer | 关联设备 ID |
| items[].taskId | integer | 关联任务 ID |
| items[].apiId | integer | 关联 API ID |
| items[].testCaseId | string | 关联测试用例 ID |
| items[].threadId | string | 线程 ID |
| total | integer | 符合条件的日志总数 |
| page | integer | 当前页码 |
| perPage | integer | 每页数量 |
| pages | integer | 总页数 |

| URL | `POST /api/v1/logs/refresh` |


### 4. 标记日志

对日志进行标记或取消标记。

**请求信息**

| 属性 | 值 |
|------|-----|
| URL | `POST /api/v1/logs/mark` |
| 方法 | POST |

**请求体 (Request Body)**

```json
{
  "logIds": [1, 2, 3],
  "mark": "flagged"
}
```

**请求字段说明**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| logIds | array | 是 | 需要标记的日志 ID 数组，参数别名: log_ids |
| mark | string | 否 | 标记值，默认为 'flagged' |

**请求示例**

```bash
curl -X POST "http://localhost:5000/api/v1/logs/mark" \
  -H "Content-Type: application/json" \
  -d '{"logIds": [1234, 1235], "mark": "important"}'
```

**成功响应**

```json
{
  "success": true,
  "error": null,
  "data": null,
  "message": "已为 2 条日志添加标记: important"
}
```

**错误响应**

```json
{
  "success": false,
  "error": {
    "code": "PARAM_MISSING",
    "message": "缺少必要参数: logIds"
  },
  "data": null
}
```

### 5. 清除日志

清除历史日志，支持选择性保留已标记的日志。

**请求信息**

| 属性 | 值 |
|------|-----|
| URL | `POST /api/v1/logs/clear` |
| 方法 | POST |

**请求体 (Request Body)**

```json
{
  "beforeDatetime": "2024-01-01T00:00:00",
  "keepMarked": true
}
```

**请求字段说明**

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| beforeDatetime | string | 否 | - | 清除此时间之前的日志，参数别名: before_datetime |
| keepMarked | boolean | 否 | true | 是否保留已标记的日志，参数别名: keep_marked |

**请求示例**

```bash
curl -X POST "http://localhost:5000/api/v1/logs/clear" \
  -H "Content-Type: application/json" \
  -d '{"beforeDatetime": "2024-01-01T00:00:00", "keepMarked": true}'
```

**成功响应**

```json
{
  "success": true,
  "error": null,
  "data": {
    "deletedCount": 150
  },
  "message": "已成功清除 150 条历史日志"
}
```

### 6. 导出日志

导出日志文件，支持多种格式。

**请求信息**

| 属性 | 值 |
|------|-----|
| URL | `POST /api/v1/logs/export` |
| 方法 | POST |

**请求体 (Request Body)**

```json
{
  "logIds": [1, 2, 3],
  "format": "excel"
}
```

**请求字段说明**

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| logIds | array | 否 | - | 指定导出的日志 ID 数组，参数别名: log_ids，不传则使用过滤条件 |
| format | string | 否 | excel | 导出格式: excel, csv, json, txt |

**请求示例**

```bash
curl -X POST "http://localhost:5000/api/v1/logs/export" \
  -H "Content-Type: application/json" \
  -d '{"logIds": [1234, 1235, 1236], "format": "excel"}' \
  -o logs_export.xlsx
```

**成功响应**

返回文件流，Content-Type 根据导出格式不同而变化:
- Excel: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- CSV: `text/csv`
- JSON: `application/json`
- TXT: `text/plain`

## WebSocket 接口

### 连接日志 WebSocket

建立实时日志推送连接。

**连接信息**

| 属性 | 值 |
|------|-----|
| URL | `ws://localhost:5000/ws/logs` |
| 命名空间 | `/ws/logs` |

**连接示例**

```javascript
const socket = io('http://localhost:5000/ws/logs', {
  transports: ['websocket']
});

socket.on('connect', () => {
  console.log('Connected to Log WebSocket');
});

socket.on('logs', (data) => {
  console.log('Received logs:', data);
});

socket.on('task_log', (data) => {
  console.log('Received task log:', data);
});
```

### 事件列表

#### 客户端 → 服务器

| 事件名 | 数据格式 | 说明 |
|--------|----------|------|
| set_filter | `{ "levels": ["error"], "modules": ["TASK"] }` | 设置日志过滤配置 |
| disconnect | - | 断开连接 (自动触发) |

#### 服务器 → 客户端

| 事件名 | 数据格式 | 说明 |
|--------|----------|------|
| status | `{ "type": "STATUS", "data": { "isMonitoring": true, "message": "Connected to Log Server" } }` | 连接状态 |
| status | `{ "type": "FILTER_APPLIED", "data": { "levels": ["error"] } }` | 过滤配置已应用 |
| logs | `{ "type": "LOG_BATCH", "data": [{ "id": 1234, "time": "...", "level": "error", "module": "TASK", "content": "...", "mark": "" }] }` | 日志数据推送 |
| task_log | `{ "taskId": 5, "log": { "time": "...", "level": "error", "module": "TASK", "content": "..." } }` | 任务相关日志推送 |

## 性能考虑

1. **分页查询**: 使用 SQLAlchemy 的 `paginate()` 方法，自动处理大结果集的分页
2. **批量导出**: 导出功能使用 pandas 进行数据处理，支持最多 100 条日志的同步获取
3. **实时推送**: WebSocket 推送支持节流，可配置聚合多条日志后批量推送
4. **数据库索引**: Log 表的 level、module、time、task_id 等字段建议建立索引以优化查询性能
5. **异步处理**: 日志写入采用异步队列处理，避免阻塞主请求

---

## 使用建议

1. **前端轮询替代**: 如果不使用 WebSocket，建议使用 `refresh_logs` 接口每隔 5-10 秒轮询一次
2. **导出限制**: 建议单次导出不超过 10000 条日志，避免内存溢出
3. **日志清理**: 定期清理旧日志，建议保留最近 30 天的日志数据
4. **标记功能**: 重要日志使用标记功能，便于后续查找和导出
5. **多级别过滤**: 使用 `level=debug,info,warning,error` 可同时筛选多个级别
