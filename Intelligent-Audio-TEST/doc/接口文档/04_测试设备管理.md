# 测试设备管理接口

## 4. 测试设备管理接口

### 4.1 获取测试设备列表

#### 4.1.1 接口信息

- **URL**: `/api/v1/test-devices`
- **方法**: `GET`
- **功能**: 获取测试设备列表，支持分页、搜索和筛选

#### 4.1.2 请求参数

| 参数名 | 类型 | 位置 | 必需 | 描述 |
|--------|------|------|------|------|
| page | INTEGER | query | 否 | 页码，默认1 |
| per_page | INTEGER | query | 否 | 每页记录数，默认10 |
| keyword | STRING | query | 否 | 搜索关键字，支持设备名称、型号和位置 |
| status | STRING | query | 否 | 设备状态筛选：online/offline/maintenance/testing |
| type | STRING | query | 否 | 设备类型筛选 |

#### 4.1.3 响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [
      {
        "id": 1,
        "name": "测试设备001",
        "model": "设备型号",
        "description": "测试用设备描述",
        "type": "phone",
        "system": "Android",
        "systemVersion": "14",
        "appName": "测试应用",
        "appVersion": "1.0.0",
        "location": "实验室A",
        "maxAudioDuration": 300,
        "status": "online",
        "lastOnlineAt": "2024-01-15T10:00:00",
        "createdAt": "2023-01-01T10:00:00",
        "updatedAt": "2024-01-10T10:00:00"
      }
    ],
    "total": 100,
    "page": 1,
    "per_page": 10,
    "pages": 10
  }
}
```

### 4.2 获取批量设备状态

#### 4.2.1 接口信息

- **URL**: `/api/v1/test-devices/status`
- **方法**: `GET`
- **功能**: 批量获取设备状态，用于HTTP轮询降级

#### 4.2.2 请求参数

| 参数名 | 类型 | 位置 | 必需 | 描述 |
|--------|------|------|------|------|
| ids | INTEGER[] | query | 否 | 设备ID列表，不传则返回所有设备 |

#### 4.2.3 响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [
      {
        "id": 1,
        "name": "测试设备001",
        "status": "online",
        "lastOnlineAt": "2024-01-15T10:00:00"
      }
    ],
    "total": 1
  }
}
```

### 4.4 新增测试设备

#### 4.4.1 接口信息

- **URL**: `/api/v1/test-devices`
- **方法**: `POST`
- **功能**: 创建新的测试设备

#### 4.4.2 请求参数

| 参数名 | 类型 | 位置 | 必需 | 描述 |
|--------|------|------|------|------|
| name | STRING | body | 是 | 设备名称 |
| model | STRING | body | 是 | 设备型号 |
| type | STRING | body | 是 | 设备类型 |
| system | STRING | body | 是 | 操作系统 |
| systemVersion | STRING | body | 是 | 系统版本 |
| appName | STRING | body | 是 | 应用名称 |
| appVersion | STRING | body | 是 | 应用版本 |
| description | STRING | body | 否 | 设备描述 |
| location | STRING | body | 否 | 设备位置 |
| maxAudioDuration | FLOAT | body | 否 | 最大音频时长 |
| status | STRING | body | 否 | 设备状态，默认offline |

#### 4.4.3 请求示例

```json
{
  "name": "新测试设备",
  "model": "设备型号X",
  "type": "phone",
  "system": "Android",
  "systemVersion": "14",
  "appName": "测试应用",
  "appVersion": "1.0.0",
  "description": "新的测试设备",
  "location": "实验室A",
  "maxAudioDuration": 300,
  "status": "offline"
}
```

#### 4.4.4 响应示例

```json
{
  "code": 0,
  "message": "设备注册成功",
  "data": {
    "id": 3
  }
}
```

### 4.6 删除测试设备

#### 4.6.1 接口信息

- **URL**: `/api/v1/test-devices/:id`
- **方法**: `DELETE`
- **功能**: 逻辑删除测试设备。**注意：若设备已关联测试任务，无法删除**

#### 4.6.2 请求参数

| 参数名 | 类型 | 位置 | 必需 | 描述 |
|--------|------|------|------|------|
| id | INTEGER | path | 是 | 测试设备ID |

#### 4.6.3 响应示例

```json
{
  "code": 0,
  "message": "设备已删除 (逻辑删除)"
}
```

### 4.7 扫描物理设备

#### 4.7.1 接口信息

- **URL**: `/api/v1/test-devices/scan`

### 4.10 批量健康检查

#### 4.10.1 接口信息

- **URL**: `/api/v1/test-devices/health-check`
- **方法**: `POST`
- **功能**: 对指定的多个设备执行健康检查（ADB连接测试或网络Ping测试），并通过WebSocket实时更新状态

#### 4.10.2 请求参数

| 参数名 | 类型 | 位置 | 必需 | 描述 |
|--------|------|------|------|------|
| device_ids | INTEGER[] | body | 否 | 测试设备ID列表，不传则检查所有设备 |

#### 4.10.3 请求示例

```json
{
  "device_ids": [1, 2, 3]
}
```

#### 4.10.4 响应示例

```json
{
  "code": 0,
  "message": "健康检查任务已启动，状态将通过 WebSocket 实时更新"
}
```

### 4.11 获取可用设备序列号列表

#### 4.11.1 接口信息

- **URL**: `/api/v1/test-devices/available-serials`
- **方法**: `GET`
- **功能**: 获取通过ADB/HDC命令扫描到的可用设备序列号列表

#### 4.11.2 响应示例

```json
{
  "code": 0,
  "message": "成功获取 4 个设备序列号",
  "data": [
    "emulator-5554",
    "192.168.1.100:5555",
    "00008101-001A246C0A02001E",
    "DEMO-HARMONY-001"
  ]
}
```
