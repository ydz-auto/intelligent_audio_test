# 语音交互大模型自动化测试平台接入需求文档

> 本模板用于规范需求方提交被测算法接入需求的内容格式，请按各章节要求完整填写。

## 一、算法基本信息

### 1.1 算法标识

| 字段 | 内容 | 说明 |
|------|------|------|
| 算法名称 | 语音交互大模型 | 算法的业务名称，如"语音翻译算法"、"语音LLM" |
| 算法类型 | 语音LLM | 选择：语音识别(ASR) / 语音翻译 / 语音LLM / 声纹识别 / 语音合成 / 其他 |
| 提供方 | - | 算法提供方名称 |
| 负责人 | - | 需求方对接负责人 |

### 1.2 测试类型

| 测试类型 | 是否需要 | 备注 |
|----------|----------|------|
| 端到端测试 | 是 | 通过人工嘴、音箱、真实设备（安装待测APP）进行完整流程测试，模拟真实用户交互场景 |
| API测试 | 是 | 通过API接口调用语音交互大模型进行测试，覆盖纯接口层面的功能验证 |

## 二、端到端测试需求

### 2.1 设备控制要求

#### 2.1.1 被测设备要求

| 字段 | 内容 |
|------|------|
| 设备类型 | 手机/平板/智能音箱/车载设备/其他 |
| 操作系统 | Android / HarmonyOS / iOS / 其他 |
| 系统版本要求 | 按需配置 |
| APP名称 | 待测语音交互大模型对应的客户端APP |
| APP版本要求 | 按需配置 |
| 设备数量要求 | 最少3台（支持并行测试，适配不同终端类型） |

**被测设备控制方式**：

| 控制环节 | 控制方式 | 接口/工具 | 详细说明 |
|----------|----------|-----------|----------|
| 设备连接 | USB / 网络 | ADB/ATX/设备厂商SDK | 通过USB直连或局域网连接设备，支持多设备同时管控 |
| APP启动 | 自动启动 | ADB/APP自动化测试框架 | 支持批量自动启动待测APP，支持启动后自动初始化配置 |
| 测试触发 | 语音唤醒 / 按键触发 / API调用 | 人工嘴播放音频/模拟按键工具/内部API | 支持通过人工嘴播放唤醒词触发、模拟物理按键触发、APP内部API调用触发 |
| 状态监控 | 日志监控 / 界面监控 / 音频监控 | 设备日志采集工具/屏幕录制工具/音频采集模块 | 实时监控APP运行日志、界面状态、音频输入输出状态，支持异常状态实时告警 |
| 结果获取 | 设备日志 / 设备接口 / 屏幕OCR / 音频采集 | 日志解析工具/OCR识别引擎/音频采集卡 | 支持从设备日志、APP接口、屏幕内容、音频流多维度获取交互结果 |
| 设备复位 | 自动复位 | 自动化脚本 | 每轮测试后自动清理APP缓存、恢复初始状态，支持批量设备复位 |

#### 2.1.2 放音设备要求

| 字段 | 内容 |
|------|------|
| 放音设备类型 | 噪声播放设备 / 干声播放设备 / 两者都需要 |
| 是否需要同步播放 | 是（噪声+干声同步播放，支持干扰人声/背景音乐同步播放） |
| 放音设备数量 | 至少4台（1台主讲人人工嘴+3台干扰人人工嘴+1台噪声音箱） |

**放音设备细分配置**：

| 设备角色 | 设备类型 | 功能说明 |
|----------|----------|----------|
| 主讲人人工嘴 | 高保真语音播放设备 | 模拟用户（主讲人）的语音输入，支持实时语音播放、自定义语速/音量/音色 |
| 干扰人人工嘴 | 多通道语音播放设备 | 模拟多干扰人场景，支持不同位置、不同语速、不同内容的干扰语音播放 |
| 噪声音箱 | 环境噪声播放设备 | 模拟各类场景噪声（家居/车载/公共场所），支持噪声类型、声压级自定义 |

#### 2.1.3 其他设备要求（如有）

| 设备名称 | 功能描述 | 数量要求 |
|----------|----------|----------|
| 音频采集设备 | 采集被测设备的音频输入/输出，用于后续评测 | 至少2台 |
| 声压计 | 实时监测播放音频的声压级，确保符合测试标准 | 至少1台 |
| 多模态交互模拟器 | 模拟多模态输入（语音+视觉+文本），对接待测模型 | 至少1台 |

**其他设备控制方式**：

| 设备名称 | 控制环节 | 控制方式 | 接口/工具 | 详细说明 |
|----------|----------|----------|-----------|----------|
| 人工嘴 | 设备连接 | 网络/串口 | 设备厂商控制协议 | 通过局域网或串口连接人工嘴设备，支持批量管控 |
| 人工嘴 | 操作控制 | 自动控制 | 自定义控制SDK | 支持播放内容、音量、语速、播放时机的精准控制，支持主讲人/干扰人语音同步/异步播放 |
| 人工嘴 | 状态获取 | 实时反馈 | 设备状态查询接口 | 实时获取播放进度、音量、设备在线状态等信息 |
| 噪声音箱 | 设备连接 | 网络/蓝牙 | 音箱控制API | 通过网络或蓝牙连接，支持多音箱同步控制 |
| 噪声音箱 | 操作控制 | 自动控制 | 噪声库管理系统 | 支持噪声类型选择、声压级调节、播放时长配置 |
| 噪声音箱 | 状态获取 | 实时反馈 | 音箱状态查询接口 | 实时获取噪声播放状态、声压级、设备健康状态 |
| 多模态交互模拟器 | 设备连接 | 网络 | REST API/WebSocket | 通过网络接口与模拟器通信，支持实时指令下发 |
| 多模态交互模拟器 | 操作控制 | 自动控制 | 多模态交互协议 | 支持模拟语音、文本、图像等多模态输入，模拟用户与待测模型实时交互 |
| 多模态交互模拟器 | 状态获取 | 实时反馈 | 状态推送接口 | 实时获取交互进度、输入输出内容、模拟器运行状态 |

### 2.2 多轮交互流程

#### 2.2.1 是否需要多轮交互

| 字段 | 内容 |
|------|------|
| 是否多轮 | 是 |
| 最大轮数 | 支持自定义（默认最大20轮） |
| 多轮类型 | 动态轮数（根据响应判断是否继续） |

#### 2.2.2 多轮交互流程描述（如是）

| 轮次 | 输入类型 | 输入内容来源 | 输入触发方式 | 预期输出 | 等待时间 | 是否需要单独评价 | 备注 |
|------|----------|--------------|--------------|----------|----------|------------------|------|
| 第1轮 | 语音 | 测试用例配置（固定内容）/多模态模型生成（动态内容） | 自动播放音频 | 符合交互逻辑的语音/文本响应 | 自定义（默认3s） | 是 | 支持全双工交互，允许打断式输入 |
| 第2轮 | 语音/文本 | 前一轮输出（动态内容）/多模态模型生成 | 自动播放音频/自动发送文本 | 符合上下文逻辑的语音/文本响应 | 自定义（默认3s） | 是 | 支持根据前一轮响应动态生成输入内容 |
| 第3轮 | 语音/文本/按键操作 | 前一轮输出/测试用例配置 | 自动播放音频/自动发送文本/模拟按键 | 符合交互逻辑的响应 | 自定义（默认3s） | 是 | 支持混合输入类型 |
| ... | 语音/文本/其他 | 前一轮输出/多模态模型生成/外部系统输入 | 自动播放音频/自动发送文本/其他 | 符合上下文逻辑的响应 | 自定义 | 是 | 支持动态终止轮次（无有效响应时停止） |
| 第N轮 | 语音/文本 | 前一轮输出/多模态模型生成 | 自动播放音频/自动发送文本 | 符合交互逻辑的结束响应 | 自定义（默认5s） | 是 | 支持全双工交互评测，参考Full-Duplex-Bench基准 |

**输入类型选项**：语音 / 文本 / 按键操作 / 其他
**输入内容来源选项**：
- 测试用例配置（固定内容）
- 前一轮输出（动态内容）
- 外部系统输入
- 多模态模型生成（模拟用户动态输入）
- 其他
**输入触发方式选项**：
- 自动播放音频
- 自动发送文本
- 模拟按键操作
- 等待用户操作
- 实时打断（全双工场景下的中途输入）
- 其他

#### 2.2.3 多轮交互评价方式（如是）

| 字段 | 内容 |
|------|------|
| 评价时机 | 混合方式（关键轮次单独评价 + 全部轮次结束后统一评价） |
| 每轮评价维度 | 响应准确率、响应时长、交互流畅度、意图理解准确率 |
| 整体评价维度 | 多轮上下文一致性、任务完成率、用户体验评分、全双工交互体验 |
| 多轮结果汇总方式 | 加权平均（关键轮次权重更高） |

**每轮评价维度配置表**（如每轮单独评价）：

| 轮次 | 评价维度 | 评价方式 | Prompt是否相同 | 备注 |
|------|----------|----------|----------------|------|
| 第1轮 | 唤醒成功率、响应准确率、响应时长 | LLM（三方裁判模型） | 否 | 唤醒轮次单独配置Prompt |
| 第2轮 | 意图理解准确率、响应相关性、流畅度 | LLM（三方裁判模型） | 否 | 按交互场景定制Prompt |
| 第3轮 | 上下文一致性、响应准确率 | LLM（三方裁判模型） | 否 | 重点关注上下文关联 |
| ... | 响应准确率、流畅度、交互自然度 | LLM（三方裁判模型） | 否 | 动态调整Prompt适配场景 |
| 第N轮 | 任务完成率、结束响应合理性 | LLM（三方裁判模型） | 否 | 结束轮次重点评价任务完成度 |

#### 2.2.4 多轮交互状态管理

| 字段 | 内容 |
|------|------|
| 是否需要保持会话状态 | 是 |
| 状态保持方式 | 设备端保持 / 服务端保持 | 同时支持两端状态监控，确保会话上下文不丢失 |
| 状态重置时机 | 每个用例开始前 | 用例执行前重置会话状态，避免上下文污染 |
| 状态重置方式 | 自动重置 | 通过API调用或脚本自动清理会话缓存，恢复初始状态 |

### 2.3 结果获取方式

|------|------|

## 三、API测试需求

### 3.1 API基本信息

| 字段 | 内容 |
|------|------|
| API名称 | 语音交互大模型接口 |
| API端点(URL) | 按需配置（支持开发/测试/生产环境切换） |
| 协议 | HTTP / HTTPS / WebSocket | WebSocket用于实时语音交互，HTTP/HTTPS用于文本/非实时交互 |
| 环境 | 开发环境 / 测试环境 / 生产环境 | 支持多环境一键切换，适配不同测试阶段 |
| 认证方式 | Token / OAuth | 支持Token有效期配置，OAuth授权流程自动化 |
| 认证参数 | token_key / client_id / client_secret | 支持参数加密存储和自动注入 |

### 3.2 API请求格式

#### 3.2.1 请求头(Headers)

```json
{
  "Content-Type": "application/json",
  "Authorization": "Bearer {token}",
  "Session-ID": "{session_id}",
  "Device-ID": "{device_id}",
  "Interaction-Type": "full_duplex" // 标识是否为全双工交互
}
```

#### 3.2.2 请求体(Body)模板

```json
{
  "session_id": "{session_id}",
  "round": {current_round},
  "input_type": "{input_type}", // voice/text/multimodal
  "input_content": "{input_content}", // 文本内容或音频URL
  "audio_params": {
    "format": "wav/mp3/flac",
    "sample_rate": 16000,
    "channel": 1,
    "duration": {audio_duration}
  },
  "full_duplex_config": {
    "allow_interruption": true,
    "interruption_sensitivity": 0.8,
    "overlap_timeout": 3000
  },
  "context": {
    "history": [
      {
        "round": 1,
        "input": "{prev_input}",
        "output": "{prev_output}"
      }
    ],
    "user_profile": "{user_profile}"
  }
}
```

**可变参数说明表**：

| 参数名 | 参数类型 | 是否必填 | 取值来源 | 说明 |
|--------|----------|----------|----------|------|
| session_id | string | 是 | 系统生成 | 标识唯一会话，用于多轮上下文管理 |
| round | int | 是 | 系统生成 | 当前交互轮次 |
| input_type | string | 是 | 测试用例配置 | 输入类型：voice/text/multimodal |
| input_content | string | 是 | 测试用例配置/多模态模型生成 | 文本内容或音频文件URL |
| audio_params | object | 否 | 测试用例配置 | 音频参数，仅输入类型为voice时必填 |
| full_duplex_config | object | 否 | 测试用例配置 | 全双工交互配置，仅全双工场景必填 |
| context | object | 是 | 会话上下文 | 历史交互记录，用于多轮上下文管理 |

### 3.3 API响应格式

#### 3.3.1 响应体结构

```json
{
  "code": 200,
  "msg": "success",
  "session_id": "{session_id}",
  "round": {current_round},
  "output_type": "{output_type}", // voice/text
  "output_content": "{output_content}", // 文本响应或音频URL
  "response_metrics": {
    "response_time": {response_time_ms},
    "interruption_handled": true/false,
    "overlap_duration": {overlap_duration_ms},
    "turn_taking_latency": {latency_ms}
  },
  "context_updated": {
    "history": [
      {
        "round": 1,
        "input": "{prev_input}",
        "output": "{prev_output}"
      },
      {
        "round": {current_round},
        "input": "{current_input}",
        "output": "{current_output}"
      }
    ]
  }
}
```

#### 3.3.2 结果字段映射

| 字段名 | 字段含义 | 数据类型 | 是否必返回 |
|--------|----------|----------|------------|
| code | 响应状态码 | int | 是 |
| msg | 响应信息 | string | 是 |
| session_id | 会话ID | string | 是 |
| round | 当前轮次 | int | 是 |
| output_type | 输出类型 | string | 是 |
| output_content | 输出内容 | string | 是 |
| response_metrics | 响应指标 | object | 是 |
| response_metrics.response_time | 响应时长(ms) | int | 是 |
| response_metrics.interruption_handled | 是否处理打断 | boolean | 否 |
| response_metrics.overlap_duration | 语音重叠时长(ms) | int | 否 |
| response_metrics.turn_taking_latency | 轮次切换延迟(ms) | int | 否 |
| context_updated | 更新后的上下文 | object | 是 |

### 3.4 API性能参数

| 字段 | 内容 |
|------|------|
| 最大并发数 | 支持自定义配置（默认100） |
| 单次请求超时时间 | 自定义（默认10秒，全双工场景支持30秒） |
| 最大音频时长限制 | 自定义（默认60秒，支持长语音分段处理） |
| QPS限制 | 支持自定义配置（默认50） |

### 3.5 多轮交互需求（语音LLM等）

#### 3.5.1 是否需要多轮交互

| 字段 | 内容 |
|------|------|
| 是否多轮 | 是 |
| 最大轮数 | 支持自定义（默认20轮） |
| 多轮类型 | 动态轮数（根据响应判断是否继续） |

#### 3.5.2 会话管理方式（如是）

| 字段 | 内容 |
|------|------|
| 会话管理方式 | Session ID / Context历史 | 双维度管理，Session ID标识会话，Context传递历史交互 |
| 会话标识参数名 | session_id | 用于标识多轮对话的参数名 |
| 会话标识生成方式 | 系统生成 | 按固定规则生成唯一Session ID，支持自定义规则 |
| 会话有效期 | 自定义（默认1小时） | 支持会话超时自动清理 |

**会话上下文传递方式**：

| 方式 | 是否使用 | 详细说明 |
|------|----------|----------|
| Session ID传递 | 是 | 仅传递会话标识，服务端保存历史，减少请求体大小 |
| 历史Context传递 | 是 | 全双工场景下携带精简版历史上下文，确保实时性 |

### 4.3 统计方式配置

#### 4.3.1 单维度统计方式

| 字段 | 内容 |
|------|------|
| 统计方式 | 按用例配置权重加权平均 | 重点维度（如全双工体验）权重更高 |
| 统计层级 | 任务级统计 / 设备级统计 / 标签级统计 | 支持多维度交叉统计 |
| 是否需要分场景统计 | 是（按标签、用例类型、交互场景分组统计） | 如按打断场景/正常场景/多轮场景分别统计 |

**统计方式详细说明**：

| 统计方式 | 适用数据类型 | 计算公式 | 说明 |
|----------|--------------|----------|------|
| 按用例直接平均 | 数值型 | sum(各用例评分) / 用例数量 | 基础指标快速统计 |
| 按用例配置权重加权平均 | 数值型 | sum(用例评分 × 用例权重) / sum(用例权重) | 全双工相关用例权重翻倍 |
| 按用例时长加权平均 | 数值型 | sum(用例评分 × 用例时长) / sum(用例时长) | 长语音交互场景适用 |
| 按标签分组统计 | 数值型 | 先按标签分组，再组内平均 | 支持场景对比分析（如不同设备/不同干扰强度） |
| 非数值统计 | 字符串/枚举 | 见下方详细说明 | 如交互状态、错误类型的分布统计 |

#### 4.3.2 非数值型维度统计方式

| 字段 | 内容 |
|------|------|
| 是否有非数值型维度 | 是 | 如交互状态、错误类型等 |

**非数值统计方式详细说明**：

| 统计方式 | 适用场景 | 统计方法 | 示例 |
