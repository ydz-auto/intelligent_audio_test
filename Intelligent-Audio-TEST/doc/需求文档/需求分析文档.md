# 智能语音测试系统需求分析文档

## 1. 技术架构需求和约束

### 1.1 技术栈
- **前端框架**: Electron^29.4.4 + 原生HTML/CSS/JS
- **后端框架**: Flask
- **数据库**: PostgreSql
- **编程语言**: Python 3.10
- **架构模式**: MVC

### 1.2 约束条件
- **设备兼容性**: 适配桌面端，默认页面大小适配1k显示器、适配1/4的1k显示器
- **性能要求**: 支持多任务并行处理（API任务可并行，端到端任务串行）
- **存储要求**: 本地文件系统存储日志和音频文件
- **安全要求**: 本地数据存储安全性保障

### 2.4 报告功能统一规范

所有报告（任务报告、任务对比报告、历史报告对比报告）应遵循统一的结构和样式：

**统一报告结构**:
- **设备/API信息对比**：展示参与报告的设备和API的基本信息对比
- **用例在设备/API上的执行数量对比**：统计各设备/API上的用例执行情况
- **详细的分析结论**：支持编辑的分析结论文本
- **按用例分组对比**：
  - 筛选卡片：支持按用例分组筛选
  - 评估维度筛选卡片：支持按评估维度筛选
  - 对比图表：
    - 表格：详细的数据表格
    - 柱状图：直观的数量对比
    - 雷达图：多维性能对比
    - 正态分布图：为每个设备/API生成独立的正态分布，支持多设备对比
- **按用例标签对比**：按标签分组展示对比结果
- **具体用例对比**：展示具体用例的执行结果对比

**报告类型**:
1. **任务报告**：单个测试任务的详细报告
2. **任务对比报告**：多个测试任务的对比分析报告
3. **历史报告对比报告**：多个已保存报告的对比分析报告

**报告操作**:
- 报告保存功能
- 报告发布/草稿状态管理
- 报告导出功能（支持CSV、PDF格式）
- 分析结论编辑功能
- 报告名称和描述自定义

## 3. 数据模型设计

### 3.1 核心数据实体

#### 3.1.1 测试用例表 (test_case)
- id: 主键
- name: 用例名称
- status: 状态（1=生效/2=失效）
- logic_delete: 逻辑删除（0=否/1=是）
- create_time: 创建时间
- update_time: 更新时间

#### 3.1.2 音频表 (audio)
- id: 主键
- name: 音频名称
- path: 音频路径
- type: 音频类型（1=噪声/2=干声）
- asr_text: ASR参考文本
- language: 语种
- target_language: 目标语种
- trans_text: 翻译参考文本
- duration: 时长（秒）
- status: 状态（1=生效/2=失效）
- logic_delete: 逻辑删除（0=否/1=是）
- create_time: 创建时间
- update_time: 更新时间

#### 3.1.2.1 测试用例音频关联表 (test_case_audio_relation)
- id: 主键
- case_id: 测试用例ID（外键）
- test_type: 测试类型（1=端到端/2=API）
- clean_audio_id: 干声音频ID（外键，端到端测试必填）
- noise_audio_id: 噪声音频ID（外键，端到端测试可选）
- api_audio_id: API测试音频ID（外键，API测试必填）
- clean_playback_device_id: 干声播放设备ID（外键，端到端测试必填）
- noise_playback_device_id: 噪声播放设备ID（外键，端到端测试可选）
- status: 状态（1=生效/2=失效）
- create_time: 创建时间
- update_time: 更新时间

#### 3.1.3 测试设备表 (test_device)
- id: 主键
- model: 设备型号
- tags: 标签
- image: 图片
- status: 状态（1=在线/2=下线）
- system: 系统（安卓/鸿蒙/ios）
- system_version: 系统版本
- app_name: 测试APP名
- app_version: APP版本
- max_audio_duration: 单次执行用例最长音频时长限制（秒）
- logic_delete: 逻辑删除（0=否/1=是）
- create_time: 创建时间
- update_time: 更新时间

#### 3.1.4 播放设备表 (playback_device)
- id: 主键
- name: 设备名
- type: 类型（1=噪声/2=干声）
- sample_rate: 采样率
- device_id: 唯一设备ID
- tags: 标签列表
- status: 状态（1=在线/2=下线）
- logic_delete: 逻辑删除（0=否/1=是）
- create_time: 创建时间
- update_time: 更新时间
- creator: 创建人

#### 3.1.5 测试API表 (test_api)
- id: 主键
- name: API名称
- endpoint: API端点
- protocol: 协议（HTTP/HTTPS）
- environment: 环境（开发/测试/生产）
- version: 版本
- max_process: 最大进程数
- max_timeout: 最大超时时间（秒）
- max_audio_duration: 单次执行用例最长音频时长限制（秒）
- health_status: API健康状态（healthy/unhealthy/unknown）
- status: 状态（1=在线/2=离线/3=维护中）
- description: 描述
- logic_delete: 逻辑删除（0=否/1=是）
- create_time: 创建时间
- update_time: 更新时间

#### 3.1.6 评估维度表 (evaluation_dimension)
- id: 主键
- name: 维度名称
- keyword: 关键字（支持多个关键字，逗号分隔）
- data_type: 结果数据类型（1=百分数/2=整数/3=小数/5=字符串）
- api_url: API链接
- max_process: 最大进程数
- expected_time: 预计执行时长（秒）
- min_value: 结果最小值
- max_value: 结果最大值
- decimal_places: 保留小数位数
- weight: 权重（1-10）
- timeout: 预计允许时间（秒）
- rule: 评分规则（JSON格式）
- type: 维度类型（性能指标/功能指标/质量指标/环境适应性）
- status: 状态（1=生效/2=失效）
- description: 描述
- logic_delete: 逻辑删除（0=否/1=是）
- create_time: 创建时间
- update_time: 更新时间

#### 3.1.7 测试任务表 (test_task)
- id: 主键

- type: 任务类型（1=端到端/2=API）

- device_ids: 关联设备列表
- case_ids: 关联用例列表

- excel_path: 结果Excel路径
- excel_create_time: Excel生成时间

- create_time: 创建时间

- id: 主键

- device_id: 设备ID（外键）
- asr_result: ASR识别结果
- trans_result: 翻译结果
- evaluation_results: 评估结果（JSON格式）

#### 3.1.8 测试报告表 (test_report)
- id: 主键
- name: 报告名称
- description: 报告描述

- comparison_data: 对比数据（JSON格式，包含分析结论、标签分析结论等）
- duration: 测试时长（秒）
- creator: 创建人
- logic_delete: 逻辑删除（0=否/1=是）
- create_time: 创建时间
- update_time: 更新时间

### 3.2 关系映射
- 测试用例与音频：通过测试用例音频关联表实现多对多关系，支持同一用例为不同测试类型配置不同音频
- 测试用例与评估维度：多对多关系（一个用例可选择多个评估维度）
- 测试任务与测试用例：多对多关系（一个任务可包含多个用例）
- 测试任务与测试设备：多对多关系（一个任务可在多个设备上执行）
- 测试任务与测试结果：一对多关系（一个任务可产生多个结果）
- 测试用例音频关联表与播放设备：多对一关系（一个关联记录对应一个干声播放设备和一个可选的噪声播放设备）

## 4. 功能流程和用户交互

### 4.1 端到端测试流程
1. **选择测试用例**：用户创建或选择测试用例，配置端到端测试的干声和噪声音频及对应的播放设备
2. **选择测试设备**：用户选择测试设备
3. **执行测试**：系统开始执行测试任务，实时监控进度
4. **查看结果**：测试完成后，用户查看任务报告和用例执行结果

### 4.2 API测试流程
1. **选择测试用例**：用户选择测试用例，配置API测试音频（可与端到端测试音频不同）
2. **选择被测API**：用户选择被测API并测试其可用性
3. **执行测试**：系统开始执行API测试任务，实时监控进度
4. **查看结果**：测试完成后，用户查看任务报告和用例执行结果

### 4.3 共性交互设计
- **页面导航**：每个测试流程页面最上边显示流程图，点击步骤可跳转对应子页面
- **步骤控制**：每个子页面最下边有"上一步""下一步"按钮，串联子页面逻辑
- **数据可视化**：使用直方图、正态分布图等展示测试结果
- **标签管理**：统一的标签管理系统，用于分组和筛选数据

## 5. 技术风险和假设项

### 5.1 技术风险

#### 5.1.1 音频播放同步性风险
**风险描述**：多音频（噪声+干声）同步播放可能存在延迟或不同步问题
**影响范围**：端到端测试模块
**缓解策略**：使用专业音频处理库（如pyaudio）精确控制播放时间，增加同步校验机制

#### 5.1.2 多任务并行处理风险
**风险描述**：API任务并行处理可能导致系统资源耗尽
**影响范围**：API测试模块
**缓解策略**：实现任务队列和资源限制机制，根据API最大进程数动态调整并行度

#### 5.1.3 数据存储性能风险
**风险描述**：PostgreSql数据库在大量测试数据存储和查询时可能性能不足
**影响范围**：所有数据管理模块
**缓解策略**：优化数据库索引设计，实现数据分区和定期清理机制

### 5.2 假设项

#### 5.2.1 音频格式兼容性假设
**假设**：系统支持的音频格式包括常见格式（如WAV、MP3），用户提供的音频文件符合这些格式要求
**验证方式**：开发前明确支持的音频格式列表，进行兼容性测试

#### 5.2.2 设备接口假设
**假设**：测试设备提供标准接口用于获取ASR和翻译结果
**验证方式**：与设备供应商确认接口规范，开发适配层

#### 5.2.3 评估API稳定性假设
**假设**：评估维度对应的API接口稳定可用，返回格式符合规范
**验证方式**：实现API健康度监控和容错机制，支持API配置动态更新
