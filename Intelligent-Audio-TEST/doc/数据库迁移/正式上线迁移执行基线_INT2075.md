## 4. 依赖联动规则

- **B 段内部**：30/31/32/52 均直接依赖 14（`algorithm_definitions` voice_llm 行存在、`param_mappings`/
  关联表外键引用）。正式上线按 §3 判据 14 跳过时，30/31/32/52 **同步跳过**，不单独拆跑。
- **B → A**：
  - 56（fix_voice_llm_reference_params）的目标是 `algorithm_reference_params` 中 7 行
    （通常由 14 的 Step 6 写入）。生产已有这 7 行（INT-2071 隔离库即「目标 7 行，更新 3 行」）→
    56 独立可跑、不受 14 跳过影响；若目标行整体缺失（异常形态）→ 56 打印「未找到」不新增，
    需先补跑 14 或人工核对，不能依赖 56 建行。
  - 49（seed_voice_llm_device_output）目标行是 `algorithm_device_params` 的 voice_llm 声明，
    与 14 无强依赖（14 跳过不影响 49 对存量行订正）。
- **A 段内部时序**：57（ANALYZE）必须是最后一步；43/48/51/53/54/55 等 DDL 必须排在 57 之前
  （BOOTSTRAP_STEPS 已固定，按 runbook 顺序执行即可）。
- **两段式不改变引导链代码**：`BOOTSTRAP_STEPS` 仍含全量 57 步（全新库建库需要 seed）。
  存量生产库上线时由执行 agent 按本基线跳过 B 段并记录，**不改 `db_bootstrap_entrypoint.py`**；
  若后续需要把两段式固化进引导链（加 `SKIP_SEED` 开关之类），另开实施卡评审，不在本卡范围。

## 5. 执行前提（INT-2071 实测发现的 3 处链缺口，正式切换前核对目标库形态）

1. **INT-423 未入链（visibility 列）**：步骤 2 `remove_foreign_keys_and_soft_delete` 无条件建
   `idx_*_created_visibility` 复合索引；旧生产库（热备恢复形态）无 `visibility` 列 →
   `UndefinedColumn`。INT-2071 补跑 `scripts/migrations/202610/add_visibility_columns_int423.py`
   （10 表加列 + 索引）后通过。**目标库若缺该列：必须在步骤 2 之前补跑 INT-423**；全新库
   （create_all 已建列）无需。
2. **INT-47 顺序反了（时间戳 DB 默认）**：步骤 6/14~20 等 seed 裸 INSERT 不带 created_at/updated_at；
   旧库时间戳列 NOT NULL 且无 DB 级默认 → `NotNullViolation`。INT-2071 提前补跑
   `add_timestamp_db_defaults`（72 列 SET DEFAULT now()）后通过。**目标库若缺默认：必须把步骤 21
   提前到首个 seed（步骤 6）之前执行**。
3. **步骤 45 需超级用户**：`CREATE EXTENSION pg_stat_statements` 需超管；restored 生产集群
   superuser=postgres、业务账号非超管 → `InsufficientPrivilege`。以 postgres 连接执行或由 DBA 完成；
   且 `shared_preload_libraries` 须含 pg_stat_statements（compose postgres 服务 command 已配）才真正采集。
