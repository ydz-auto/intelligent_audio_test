# VibeCoding 效率提升指南

## 概述

VibeCoding（氛围编程）是一种利用大模型 AI（如 Claude、GPT 等）辅助编程的新型开发模式。本项目（智能语音测试管理系统）采用 Electron + Vue 3 + TypeScript + Flask + SQLAlchemy + SQLite 技术栈，在 1 人团队、5 个月时间内完成了约 500 人天的工作量。由于**前后端联调效率低下**，整体 AI 辅助效率约 **5 倍**。

**核心原则**：AI 辅助开发 ≠ 完全依赖 AI。**前后端代码全 AI 生成**，**人工负责调试 + 审核 + 测试**。设计阶段和易用性问题必须人工介入。

## 二、后端案例：音频引擎开发

以音频引擎（Audio Engine）开发为例，说明设计、开发、调试、测试、修复等各阶段的 AI 辅助与人工介入策略。

### 2.1 设计阶段 - 必须人工介入

**人工职责**：

- 分析 PyAudio 设备流限制的技术背景
- 设计 `play_multi` 同设备多音频混合方案
- 制定 `overlap_rate` / `overlap_time` 重叠播放规则
- 设计 `speakers_map` Speaker 感知交叠算法
- 确定设备与声道映射关系

**案例**：Speaker 感知交叠播放功能设计

```
问题背景分析（人工）：
- 连续同说话人交叠：同一说话人的连续语音不应发生时间重叠
- 跨音频同一说话人交叠：不同音频中相同说话人不应交叠

解决方案设计（人工）：
- 从 diarization 标注中提取 speaker 标签集合
- 比较相邻音频的 speakers 集合
- 有共同 speaker → 顺序播放
- 无共同 speaker → 按 overlap_rate 交叠

AI 辅助：可让 AI 生成规则对比表格
人工确认：确认规则是否符合业务预期
```

| 设计要素     | 人工介入 | AI 辅助   |
| -------- | ---- | ------- |
| 问题分析     | ✅    | ❌       |
| 技术方案选型   | ✅    | ❌       |
| 核心算法设计   | ✅    | ❌       |
| 数据结构设计   | ✅    | ⚠️ 生成草稿 |
| API 接口设计 | ✅    | ⚠️ 生成草稿 |

### 2.2 开发阶段 - 全 AI 生成

**原则**：前后端代码 100% 由 AI 生成，人工不参与代码编写，只负责审核。

**AI 生成**：

- 生成 `_extract_speakers_from_audio()` 函数框架
- 生成 `_calculate_speaker_aware_offsets()` 计算逻辑
- 生成 `extract_speakers_from_annotations()` 数据库查询代码
- 生成 `calculate_speaker_aware_audio_delays()` 延迟计算
- 生成完整的音频引擎模块代码

**人工审核**（代码生成后）：

- 确认 `speakers_map` 数据结构是否正确
- 验证交集判断逻辑 `has_common_speaker = len(curr_speakers & prev_speakers) > 0`
- 检查边界条件处理（空集合、首个音频等）


| 开发任务   | AI 生成 | 人工审核 | 效率提升   |
| ------ | ----- | ---- | ------ |
| 基础函数框架 | 100%  | 0%   | **5x** |
| 数据查询逻辑 | 100%  | 0%   | **5x** |
| 边界条件处理 | 100%  | 0%   | **5x** |
| 业务逻辑整合 | 100%  | 0%   | **5x** |

### 2.3 调试阶段 - AI 辅助 + 人工验证

**AI 辅助**：

- 分析多音频并行播放问题日志
- 定位 `play_multi` callback 中音频覆盖问题
- 生成修复建议：`=` 改为 `+=` 实现音频混合

**人工验证**：

- 确认 `out_buffer[ch_idx:...] += audio_data[:limit]` 混合逻辑
- 验证设备级别延迟移除是否正确
- 确认单音频 delay 传递问题修复

**案例**：多音频并行播放问题修复

```
问题发现（人工）：
- 只有一个音频能播放，其他音频丢失
- 不同设备的音频播放间隔过长

AI 分析日志：
- AI 解析 callback 函数逻辑
- AI 定位到 out_buffer 使用 = 赋值导致覆盖
- AI 生成修复建议：改为 += 混合

人工验证：
- 确认修复方案不会引入新问题
- 实际测试验证修复效果
```
