## 环境问题（曾阻断 M14，已解阻）

- 宿主 `com.docker.backend.exe`（PID 15800）持有 **13999 个 `Bound` 套接字**，独占 Windows 动态端口段 49152–65534（共 16384），仅剩约 1400 个可用；`Get-NetTCPConnection` 连续 4 次采样稳定在 ~14890。
- 症状：新建连接随机失败 —— Python `WinError 10055(WSAENOBUFS)`/`10048`、curl 约 1/6 成功、Playwright `net::ERR_NO_BUFFER_SPACE`、Selenium `session not created: DevToolsActivePort file doesn't exist`；`multica` CLI 也间歇 `Could not reach`。
- 容器内 → 宿主 gRPC（`host.docker.internal:50052/50053`）同样受影响，冷连接成功率约 1/8，通道建立后稳定（6/6 200），故后端矩阵全部改在容器内跑。
- 影响面：只影响宿主侧浏览器验收与宿主 CLI；容器内 HTTP 全量矩阵不受影响。
- **解阻（INT-2264）**：重启 Docker Desktop backend 后 Bound 14894→882，宿主建连恢复正常；本 run 起 Docker 引擎并按 `docker start` 拉起 14 个容器（未 compose up、未重建镜像），四端 10/10 可用，复测完成 M14。

## 观察（非本卡回归，供后续卡参考）

1. **主库存量 `audios.md5` 与实际字节不一致**：同一库导出的 ZIP 首次回导时按 md5 未命中，`audio_registered_count=2` 重复登记；再导一次即 `reused=2`。与既有结论一致（导出的 manifest md5 取包内字节，而历史行 md5 列是旧值），不影响本卡判定，但回导前应预期有一次重复登记。
2. **全量导出耗时 44.7s / 596 条**（N+1 逐条 gRPC，INT-2225 走查已记 P2），勾选/分组导出 < 1s。
3. 卡面账号 `接线测试_admin` 在主库不存在，建议矩阵卡统一写 `dev_user`。
