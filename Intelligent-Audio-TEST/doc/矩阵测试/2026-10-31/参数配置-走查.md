## 结论先看

- **三层解析本身是干净的**：`get_device_params` / `_scoped_mapping_buckets` 的优先级（设备覆盖 > 设备绑定策略 > 算法级默认）互斥清晰，绑定只接受 `scope='device'`（INT-2186 到位），策略按算法类型过滤（INT-2259 已修，`config_cache.py:980-994,1016-1025`）。
- **最严重的两处都是「整份保存」语义把作用域外的行一起清了**：
  1. 后端：算法定义整份保存 `_upsert_device_api_params` / `_upsert_mappings` 只过滤了 `api_id IS NULL`，**没有过滤 `device_id IS NULL`**（`_algorithm_full_save.py:110-113,300-302`），设备级参数行/映射行会被提交集外软删，且因自然键碰撞可能被改写（P0-1）。React「设备参数」抽屉正好在写这批行（`device-param-api.ts:62,70,145,152`），所以不是理论风险。
  2. React：参数策略管理器用「API 语义」的简化表单编辑**任何** scope 的策略（列表不带 scope 过滤），保存时把 `required/default_value/help_text/hidden` 写死为空、把映射 `source/sourceDirection` 写死成 `api/output`（P0-3）。
- **设备级映射在真机链路是死路**：`device_result_collector.convert_results` / `build_case_result_log` 读 `res['_device_id']`，全仓没有任何写入方（结果行里的键是 `device_id`），设备级输出映射永远不生效（P1-2）。
- **策略保存的「缺省即清空」面**：`ParamProfileSaveRequest.model_dump()` 把未传的 `config` 序列化成 `None`，`save()` 见 `'config' in data` 就写 NULL —— 任何不带 `config` 的编辑都会清掉配置快照（P1-1）。
- 前端「三层解析」在 React 侧被实现了 **5 份、键口径 3 套**，都不含绑定策略层，设备抽屉文案却写三层；「另存为新策略」因此会丢生效值（P1-5）。
- **迁移的「幂等」只到结构层，没到语义层**：`add_device_id_scope` 每次部署无条件 DROP+CREATE 两条 `param_mappings` 唯一索引（SKIP 分支永不触发，P1-9）；`migrate_device_params_to_profiles` 每次部署把已解绑设备重新绑回、把已软删的策略行复活（P1-9）。两者都在引导链里、每次部署执行。
- 新 Vue **完全没有**「参数策略 / 设备参数绑定」域（`paramProfile`/`device-scope` 在 `frontend/src` 零命中），只有算法配置弹窗内的参数/映射编辑，需要规划师确认是否补 FEAT（记 P2，不单独开卡）。

## 检查项逐项结论

1. **分层（DDD）**：✅ 后端解析全部收敛在 `algorithm_service/infrastructure`（`config_cache` 读快照），网关只做 HTTP→gRPC 代理，参数策略 DTO 与 PO 分离；跨服务一律 gRPC + ACL（`shared/clients/_grpc_algo_audio.py`、`device_service/infrastructure/acl/*`），未发现绕网关直连。⚠️ 前端：React 转换在 `infrastructure/dto|api`，但 `device-param-api.ts:174-219` 在 **api 层**做了 snake→camel；新 Vue `algorithmApi.ts` 仍留手写转换（与 adapter 声明冲突）。
2. **坏味道（魔法值/大函数/重复实现）**：❌ 未达标。`scope/source/direction/param_type` 在前端多处硬编码；三层解析 React 实现 5 份、新 Vue 前端未复制（这点干净）；`config_cache.get_device_params` 与 `_scoped_mapping_buckets` 各写一遍优先级（同一文件内，尚可接受）。
3. **枚举化**：⚠️ 部分。后端 `_PROFILE_SCOPES` 白名单 + 网关 `Literal` 到位（INT-2186）；`scope/source` 在网关/服务层仍是裸字符串比较，`ParamMappingCreate.source_type` 无枚举；前端 React 有 `PARAM_PROFILE_SCOPES` 运行时数组，新 Vue `domain/enums.ts` 无 ParamScope/ParamSource；前后端枚举各写一份（无共享 schema，靠人工对齐）。
4. **配置化**：⚠️ `_PROFILE_SCOPES`/`_AUDIO_DIRECTIONS` 为模块常量；`DEFAULT_AUDIO_CONFIG` 集中在 domain（好）；解析优先级写在代码注释而非配置（可接受，属领域规则）。
5. **数据一致性**：❌ 有三处会破数据：算法定义整份保存软删设备级行（P0-1）、策略编辑缺省即清空（P1-1）、数据下沉迁移每次部署复活已解绑/已软删行（P1-9）。`deleted` 口径在四张策略表统一为 `NOT NULL DEFAULT false`（INT-2184 到位，`DeviceParamBinding` 模型 `server_default=text('false')`、迁移显式写 false）；但 `algorithm_device_params` / `param_mappings` 仍无 `server_default`（P3）。补偿性双写：设备级下沉迁移**保留**算法级行作兜底（脚本注释有说明），三层解析对齐，但两份声明单向复制，存在漂移窗口（P2，待确认设计意图）。
