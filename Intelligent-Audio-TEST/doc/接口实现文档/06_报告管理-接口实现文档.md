# 报告管理接口实现文档 (MVC架构版)

## 1. 架构映射 (Architectural Mapping)

遵循 Electron + Flask + MVC 架构规范，报告管理模块的职责划分如下：

| 层次 | 组件 | 职责 |
| :--- | :--- | :--- |
| **View (Renderer)** | `HistoryReports.vue`, `TestReports.vue` | UI 渲染、报告列表展示、图表可视化 |
| **Controller (Renderer)** | `HistoryReports.js`, `Tasks.js` | 状态管理、调用 Preload API、处理导出/对比逻辑 |
| **Preload (Adapter)** | `preload.ts` (contextBridge) | 暴露受控的 `reportsAPI`，处理 IPC 通信，**端到端类型校验** |
| **Controller (Flask)** | `report_controller.py` | 处理 REST 请求，执行复杂的数据聚合与对比算法 |
| **Model (Flask/SQLAlchemy)** | `Report`, `TestResult`, `TestTask` | 数据库实体映射，处理 JSON 序列化 |

## 2. 数据契约与类型安全 (Data Contract & Type Safety)

所有接口遵循统一的响应格式，并共享 `shared/types/report.ts` 中的 TypeScript 定义。

### 2.1 统一响应格式

成功响应：
```json
{
  "success": true,
  "error": null,
  "data": {
    // 响应数据
  },

```

错误响应：
```json
{

    "code": 400,
```

### 2.2 核心类型定义 (Shared Types)
```typescript
// 见 shared/types/report.ts
export enum ReportType {
  TASK = 'task',
  COMPARISON = 'comparison',
  SECONDARY_COMPARISON = 'secondary_comparison',
  TREND = 'trend'
}

export enum ReportStatus {
  RUNNING = 'running',
  COMPLETED = 'completed',
  FAILED = 'failed'
}

export interface Report {
  id: number;
  name: string;
  type: ReportType;
  task_id?: number;
  task_name?: string;
  summary: ReportSummary;
  description?: string;
  status: ReportStatus;
  created_at: string;
  completed_at?: string;
}

export interface ReportSummary {
  total?: number;
  passed?: number;
  failed?: number;
  success_rate?: number;
  overall_success_rate?: number;
  avg_duration?: number;
  report_count?: number;
  // 对比报告特有
  avg_success_rate?: number;
  success_rates?: Record<string, number>;
  // 二次对比特有
  trend_data?: TrendData[];
  flaky_cases_count?: number;
}

export interface TrendData {
  report_id: number;
  name: string;
  created_at: string;
  success_rate: number;
  avg_duration: number;
  delta_success_rate: number;
  delta_duration_percent: number;
}

export interface FlakyCase {
  case_id: number;
  name: string;
  history: Array<{ report_id?: number; task_id?: number; status: string }>;
```

### 3.2 生成任务报告 (POST /api/v1/reports/generate-task-report)

**Controller 实现：** `report_controller.py::ReportController.generate_task_report()`

**同步执行流程：**
1. 接收 `task_id`, `name`(可选), `description`(可选) 参数
2. 验证 `task_id` 存在，获取对应的 Task 对象
3. 生成报告名称（如果未提供）：`任务报告_任务名称_时间戳`
4. 执行数据聚合和统计
5. 创建 `Report` 记录，状态为 `completed`
6. 返回报告 ID 和成功消息

**数据聚合与统计逻辑：**
1. **基础统计**：
   - `total_cases`：任务的总用例数
   - `completed_cases`：任务的已完成用例数
   - `failed_cases`：任务的失败用例数
   - `passed_cases`：`completed_cases - failed_cases`
   - `success_rate`：`(passed_cases / total_cases) * 100`
2. **维度得分统计**：
   - 获取所有 TestResult 记录
   - 获取所有关联的 TestResultDimension 记录
   - 获取所有 Dimension 记录及其权重
   - 按 Dimension ID 聚合得分：
     - 计算每个维度的总分和记录数
     - 计算每个维度的平均分
     - 构建 `dimension_scores` 列表：`[{"id": dim_id, "name": dim_name, "average_score": avg_score}]`
3. **任务时长统计**：
   - 从 Task 对象获取 `duration` 字段
   - 计算 `started_at` 到 `completed_at` 的时间差

**报告记录创建：**
```python
new_report = Report(
    name=name,
    type='task',
    task_id=task_id,
    summary=summary,
    description=description,
    status='completed'
)
db.session.add(new_report)
db.session.commit()
```

### 3.3 生成对比报告 (POST /api/v1/reports/compare)

**Controller 实现：** `report_controller.py::ReportController.compare()`

**参数验证：**
- `task_ids`: 必需，至少 2 个任务 ID
- `name`, `description`: 可选

**数据聚合算法：**
1. 按 `created_at` 升序加载所有关联任务
2. 计算每个任务的成功率（从 TestResult 聚合）
3. 构建 `success_rates` 字典：`{task_id: success_rate}`
4. 识别不稳定项 (Flaky Cases)：
   - 遍历所有测试用例 ID
   - 统计同一用例在不同任务中的失败率
   - 失败率 > 0 且 < 100% 的用例标记为不稳定

**对比报告 Summary 结构：**
```python
{
    "report_count": len(tasks),
    "overall_success_rate": overall_rate,
    "avg_success_rate": sum_rates / count,
    "success_rates": {str(task_id): rate for each task},
    "avg_duration": sum_durations / count
}
```

**对比报告 ComparisonData 结构：**
```python
{
    "reports": [
        {
            "task_id": task.id,
            "task_name": task.name,
            "success_rate": rate,
            "total": total_tests,
            "passed": passed_tests,
            "failed": failed_tests
        }
    ],
    "flaky_cases": [
        {
            "case_id": case_id,
            "name": case.name,
            "history": [
                {"task_id": 1, "status": "passed"},
                {"task_id": 2, "status": "failed"}
            ],
            "fail_rate": 0.5
        }
    ]
}
```

### 3.4 二次对比报告 (POST /api/v1/reports/secondary-compare)

**Controller 实现：** `report_controller.py::ReportController.secondary_compare()`

**参数验证：**
- `report_ids`: 必需，至少 2 个报告 ID
- `description`: 可选

**趋势分析算法：**
1. 按 `created_at` 升序加载所有报告
2. 遍历报告列表，计算相邻报告间的差异：
   - `delta_success_rate`: 当前成功率 - 前一个成功率
   - `delta_duration_percent`: ((当前时长 - 前一个时长) / 前一个时长) * 100

**Flaky Cases 识别逻辑：**
- 仅处理 `type='task'` 的原始报告
- 从关联的 Task 中获取 TestResult
- 统计同一 TestCase 在不同报告中的执行状态
- 状态不一致的用例标记为不稳定项

**趋势数据字段说明：**
| 字段 | 类型 | 描述 |
|------|------|------|
| report_id | INTEGER | 报告 ID |
| name | STRING | 报告名称 |
| created_at | STRING | 创建时间 ISO 格式 |
| success_rate | FLOAT | 成功率 (%) |
| avg_duration | FLOAT | 平均执行时长 (秒) |
| delta_success_rate | FLOAT | 相比上一个报告的成功率变化 |
| delta_duration_percent | FLOAT | 相比上一个报告的执行时长变化百分比 |

**二次对比报告 Summary 结构：**
```python
{
    "report_count": len(reports),
    "trend_data": trend_data,
    "flaky_cases_count": len(flaky_cases)
}
```

### 3.5 删除报告 (DELETE /api/v1/reports/<int:id>)

**Controller 实现：** `report_controller.py::ReportController.delete()`

**删除逻辑：**
1. 根据 ID 查询 Report
2. 如果不存在，返回 404 错误
3. 删除 Report 记录（级联删除依赖数据）
4. 返回删除成功响应

### 3.6 批量删除报告 (POST /api/v1/reports/batch-delete)

**Controller 实现：** `report_controller.py::ReportController.batch_delete()`

**参数：**
- `ids`: 报告 ID 数组

**批量删除逻辑：**
1. 过滤掉无效的 ID
2. 使用 `filter(Report.id.in_(ids))` 批量查询
3. 执行批量删除
4. 返回删除数量

### 3.7 导出报告 (GET /api/v1/reports/export)

**Controller 实现：** `report_controller.py::ReportController.export()`

**参数：**
- `ids`: 报告 ID 列表，逗号分隔 (query string)

**CSV 流式导出逻辑：**
1. 解析 `ids` 参数（支持逗号分隔的字符串）
2. 批量查询报告记录
3. 构建 CSV 数据流：
   - 表头：name, type, status, success_rate, total, passed, failed, created_at
   - 每行对应一个报告
4. 使用 `Response` + `iter_content` 实现流式下载
5. 设置 `Content-Type: text/csv` 和 `Content-Disposition`

**CSV 导出示例：**
```
name,type,status,success_rate,total,passed,failed,created_at
测试报告_20230101,task,completed,95.0,100,95,5,2023-01-01T10:00:00
对比报告_20230105,comparison,completed,90.0,300,270,30,2023-01-05T14:00:00
```

## 4. 冲突解决与性能优化

### 4.1 数据库优化

**SQLAlchemy 配置：**
- 使用 `joinedload(Report.task)` 预加载关联数据，避免 N+1 查询
- 分页使用 `query.paginate()` 内置方法
- 过滤条件按需构建，支持可选参数

**查询优化：**
- 大量报告时使用分页查询，默认每页 10 条
- 时间范围过滤使用 ISO 8601 格式字符串
- 关键字搜索使用 `LIKE` 模糊匹配

### 4.2 数据转换中间层

**snake_case 到 camelCase 转换：**
- Preload 层负责字段名转换
- `created_at` -> `createdAt`
- `task_id` -> `taskId`
- `test_case_id` -> `testCaseId`

### 4.3 错误处理

**统一错误响应：**
```python
return error_response(message, ErrorCode.Xxx, status_code)
```

**错误码定义：**
| 错误码 | 描述 |
|--------|------|
| 400 | 请求参数错误 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |
