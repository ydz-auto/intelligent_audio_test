# 任务管理接口实现文档

## 1. 模块概述
任务管理模块是系统的执行中枢。它负责协调测试用例、测试设备和 API 配置，启动并监控自动化测试流程。任务支持异步执行，并实时更新进度和结果。

## 2. 接口详细实现思路

### 7.1 获取任务列表 (GET /api/v1/tasks)
**实现思路：**
1. **参数解析**：从查询参数中提取 `page`, `per_page`, `status`, `type`, `start_date`, `end_date`。
2. **构建查询**：
   - 基础查询：`Task.query.filter_by(deleted=False)`
   - 动态过滤：
     - 按 `status` 精确匹配
     - 按 `type` 精确匹配
     - 按时间范围过滤，支持 ISO 格式的 `start_date` 和 `end_date`
3. **排序与分页**：按 `created_at` 降序排序，使用 SQLAlchemy 的 `paginate()` 方法实现分页
4. **数据组装**：
   - 遍历查询结果，提取任务基本信息
   - 查询关联的标签名称
   - 构造包含 `items`, `total`, `page`, `per_page`, `pages` 字段的响应结构

### 7.2 获取任务详情 (GET /api/v1/tasks/:id)
**实现思路：**
1. **资源查找**：根据路径参数 `id` 查找任务，确保其存在且 `deleted == False`
2. **关联数据提取**：
   - 查询关联的 `TaskCase` 表，获取每个用例的执行状态、开始时间、完成时间和耗时
   - 查询关联的 `Device` 表，获取设备详情
   - 查询关联的 `API` 表，获取 API 详情
3. **数据组装**：
   - 构造包含任务基本信息、用例列表、设备列表、API 列表的响应结构
   - 用例信息包含 `caseId`, `name`, `status`, `startedAt`, `completedAt`, `duration`
   - 设备信息包含 `id`, `name`, `status`, `model`
   - API 信息包含 `id`, `name`, `status`, `endpoint`

### 7.3 创建任务 (POST /api/v1/tasks)
**实现思路：**
1. **参数接收与验证**：
   - 接收 `name`, `type`, `description`, `config` 等基本参数
   - 支持扁平结构或 `parameters` 嵌套结构，优先使用嵌套结构
   - 从参数中提取 `caseIds`/`case_ids`, `deviceIds`/`device_ids`, `apiIds`/`api_ids`, `tags` 等
2. **主记录创建**：
   - 在 `tasks` 表中创建新记录，初始状态为 `pending`
   - 设置 `total_cases` 为用例列表长度
   - 使用 `db.session.flush()` 获取新生成的任务 ID
3. **关联关系建立**：
   - **用例关联**：为每个用例 ID 创建 `TaskCase` 记录
   - **设备关联**：为每个设备 ID 创建 `TaskDevice` 记录
   - **API 关联**：为每个 API ID 创建 `TaskAPI` 记录
   - **标签关联**：查询或创建标签，建立任务与标签的多对多关联
4. **事务处理**：使用数据库事务确保主记录与所有关联关系的创建操作原子化
5. **响应**：返回新创建的任务 ID 和成功消息，HTTP 状态码 201

### 7.4 获取任务用例详情 (GET /api/v1/tasks/:id/cases/:case_id/detail)
**实现思路：**
1. **资源查找**：根据路径参数 `task_id` 和 `case_id` 查找任务和关联的用例。
2. **关联数据提取**：
   - 查询 `task_case_relations` 表获取用例执行详情。
   - 获取用例的测试结果和评估维度分数。
3. **数据组装**：返回用例执行的详细信息，包括音频、评估结果等。

### 7.5 启动任务 (POST /api/v1/tasks/:id/start)
**实现思路：**
1. **任务存在性检查**：根据路径参数 `id` 查找任务，若不存在则返回 404 错误
2. **状态校验**：确保任务状态为 `pending`, `failed`, `stopped` 或 `completed`，否则返回 400 错误
3. **环境预检**：
   - **E2E 类型任务**：检查所有关联设备是否在线
     - 遍历 `task.devices` 列表
     - 检查每个设备的 `status` 是否为 `online`
     - 若有离线设备，返回包含离线设备名称的错误信息
   - **API 类型任务**：检查所有关联 API 是否在线
     - 遍历 `task.apis` 列表
     - 检查每个 API 的 `status` 是否为 `online`
     - 若有离线 API，返回包含 API 名称的错误信息
4. **调用执行引擎**：
   - 获取当前 Flask 应用实例
   - 调用 `execution_engine.start_task(app, task_id)` 启动异步执行
   - 执行引擎负责将任务状态改为 `running`，并开始执行测试用例
5. **响应**：返回包含任务 ID 和开始时间的成功消息

### 7.6 任务控制与运行时干预 (POST /api/v1/tasks/:id/control)
**实现思路：**
1. **参数接收**：接收 `action` ('pause' | 'resume' | 'stop' | 'retry' | 'skip') 和可选的 `case_id`。
2. **动作逻辑**：
   - **retry**：将指定 `case_id` 状态重置为 `pending`，并通知异步引擎重新调度。
   - **skip**：将指定 `case_id` 标记为 `skipped`，引擎自动跳转到下一个用例。
   - **pause/resume/stop**：通过信号机制（如线程事件或信号量）控制 Worker。
3. **实现机制**：详细机制请参考 [09_用例执行-接口实现文档.md](./09_用例执行-接口实现文档.md) 第 3.2 节。

### 7.7 动态用例调整 (PATCH /api/v1/tasks/:id/cases)
**实现思路：**
1. **中途新增**：前端 `TestExecutionComponent` 触发 `addTestCase` 事件时调用。允许向 `task_case_relations` 添加新的待执行用例。
2. **中途移除**：允许移除状态为 `pending` 的用例（触发 `removeTestCase` 事件）。
3. **进度重计**：调整后，异步引擎需重新计算 `total_cases` 和 `progress`。

### 7.8 任务统计与进度推送 (SocketIO & GET)
**实现思路：**
1. **实时进度 (SocketIO)**：使用 `flask-socketio` 在命名空间 `/ws/tasks` 下推送。
   - **事件: `task_progress`**: 推送 `ITaskProgress` 类型数据。包含 `totalProgress`, `completedCount`, `status` 等。
   - **事件: `error_alert`**: 当检测到连续失败或设备断连时，主动推送 `error_alert` 消息，触发前端弹窗。
2. **进度查询 (GET /api/v1/tasks/:id/progress)**：用于 WebSocket 不通时的 HTTP 轮询降级。
   - **响应**: 同 `task_progress` 事件的 Payload。
3. **标签统计 (GET /api/v1/tasks/:id/stats)**：
   - 聚合各标签（如 `wakeWord`, `recognition`）的通过率、平均耗时。
   - 返回结构化数据供前端 `tagStats` 渲染。

### 7.9 任务删除 (DELETE /api/v1/tasks/:id)
**实现思路：**
1. **级联清理**：物理删除或逻辑删除任务主表记录，并同步删除 `task_case_relations` 等中间表数据。

### 7.10 重试任务 (POST /api/v1/tasks/:id/retry)
**实现思路：**
1. **状态校验**：确保任务状态为 `failed` 或 `stopped`。
2. **重置用例**：将所有失败或跳过的用例状态重置为 `pending`。
3. **重新启动**：调用执行引擎重新启动任务。
4. **响应**：返回重置的用例数量和新任务状态。

### 7.11 停止任务 (POST /api/v1/tasks/:id/stop)
**实现思路：**
1. **状态校验**：确保任务状态为 `running` 或 `paused`。
2. **停止执行**：通过信号机制通知执行引擎停止当前任务。
3. **状态更新**：将任务状态更新为 `stopped`。
4. **资源清理**：释放占用的设备和其他资源。
5. **响应**：返回停止结果信息。

### 7.12 任务统计 (GET /api/v1/tasks/:id/stats)
**实现思路：**
1. **数据聚合**：统计任务中各状态用例的数量（pending, running, passed, failed, skipped）。
2. **性能统计**：计算平均执行时间、通过率等指标。
3. **按标签聚合**：支持按标签分组统计。
4. **响应**：返回统计结果供前端图表展示。

### 7.13 批量操作 (POST /api/v1/tasks/batch-action)
**实现思路：**
1. **参数接收**：接收 `task_ids` (数组) 和 `action` ('delete' | 'stop' | 'export')。
2. **批量删除**：逻辑删除多个任务。
3. **批量停止**：停止多个运行中的任务。
4. **导出逻辑**：支持导出为 PDF (使用 `ReportLab`), Excel (使用 `pandas`), JSON。
