# 播放设备管理接口实现文档

## 1. 模块概述

播放设备管理模块负责管理用于播放测试音频的硬件设备（如专业音箱、人工嘴、耳机等）。这些设备通常连接在测试工位的音频输出端口，通过 `audio_service` 与底层音频驱动进行交互。模块支持设备的增删改查、设备扫描、设备测试、SPL映射关联等核心功能。

### 1.1 核心功能

- **设备管理**：支持播放设备的全生命周期管理，包括添加、更新、删除（逻辑删除）和查询
- **设备扫描**：自动扫描系统中可用的物理音频设备，过滤已注册的设备
- **设备测试**：支持对单个播放设备进行播放测试，通过独立线程执行异步播放
- **SPL映射关联**：将播放设备与声压级校准曲线进行关联，确保测试时音频输出的准确性
- **状态管理**：实时跟踪设备在线状态和测试状态，支持在线、离线、测试中三种状态

### 1.2 依赖模块

- `audio_service`：音频服务模块，提供物理设备枚举、设备索引获取、音频播放驱动等底层功能
- `PlaybackDevice` 模型：数据库模型，对应 `playback_devices` 表
- `SplMapping` 模型：SPL映射模型，用于音频校准
- `LogController`：日志控制器，用于记录设备操作和测试日志
- `db`：SQLAlchemy数据库实例
- `threading`：多线程支持，用于设备测试的异步执行

### 1.3 测试状态管理

模块使用全局字典 `test_stop_events` 跟踪正在测试中的设备：

```python
# 设备测试状态管理
test_stop_events: Dict[int, threading.Event] = {}
```

- **测试启动**：创建 `threading.Event` 对象并存储设备ID与事件的映射
- **测试停止**：设置事件标志，触发播放线程退出
- **线程清理**：播放线程结束后自动清理对应的事件对象

## 2. 接口详细实现思路

### 5.1 获取播放设备列表 (GET /api/v1/playback-devices)

**接口路径**：`GET /api/v1/playback-devices`

**实现思路**：

1. **参数解析**：从请求参数中提取分页参数 `page` 和 `per_page`，以及过滤参数 `type` 和 `keyword`

2. **基础查询**：构建 `PlaybackDevice` 模型的基础查询，过滤条件为 `is_deleted == 0`

3. **类型过滤**：当 `type` 参数存在时，添加 `type == value` 的过滤条件

4. **关键字搜索**：当 `keyword` 参数存在时，使用 `or_` 组合多个字段的模糊匹配：
   - `name` 字段 LIKE `%keyword%`
   - `device_unique_id` 字段 LIKE `%keyword%`
   - `description` 字段 LIKE `%keyword%`

5. **分页处理**：使用 `paginate` 方法执行分页查询，返回符合条件的结果集

6. **数据转换**：将数据库查询结果转换为API响应格式，字段命名使用 camelCase：
   - `id`：设备唯一标识
   - `name`：设备名称
   - `type`：设备类型（speaker/headphone）
   - `deviceUniqueId`：物理设备唯一标识
   - `channelIndex`：音频通道索引
   - `sampleRate`：采样率
   - `splMappingId`：当前关联的SPL映射ID
   - `status`：设备状态（1: online, 2: offline, 3: testing）
   - `description`：设备描述信息
   - `createdAt`：创建时间
   - `updatedAt`：更新时间

7. **响应组装**：调用 `success_response` 函数，组装包含分页信息的响应数据

**代码实现要点**：

```python
@staticmethod
def list(page=1, per_page=10, type=None, keyword=None):
    try:
        query = PlaybackDevice.query.filter_by(is_deleted=0)

        if type:
            query = query.filter_by(type=type)

        if keyword:
            search = f"%{keyword}%"
            query = query.filter(
                or_(
                    PlaybackDevice.name.ilike(search),
                    PlaybackDevice.device_unique_id.ilike(search),
                    PlaybackDevice.description.ilike(search)
                )
            )

        pagination = query.paginate(page=page, per_page=per_page, error_out=False)
        
        items = [{
            "id": item.id,
            "name": item.name,
            "type": item.type,
            "deviceUniqueId": item.device_unique_id,
            "channelIndex": item.channel_index,
            "sampleRate": item.sample_rate,
            "splMappingId": item.current_spl_mapping_id,
            "status": item.status,
            "description": item.description,
            "createdAt": item.created_at.isoformat(),
            "updatedAt": item.updated_at.isoformat()
        } for item in pagination.items]

        return success_response({
            "items": items,
            "pagination": {
                "page": pagination.page,
                "perPage": pagination.per_page,
                "total": pagination.total,
                "totalPages": pagination.pages
            }
        }, "获取播放设备列表成功")
    except Exception as e:
        return error_response(f"获取播放设备列表失败: {str(e)}")
```

### 5.3 新增播放设备 (POST /api/v1/playback-devices)

**接口路径**：`POST /api/v1/playback-devices`

**实现思路**：

1. **参数验证**：使用 `@use_kwargs` 装饰器验证请求体参数，包括名称、类型、设备唯一ID、通道索引、采样率等必填字段

2. **唯一性校验**：检查相同 `device_unique_id` 和 `channel_index` 组合的设备是否已存在，避免重复注册

3. **设备索引获取**：调用 `audio_service.get_device_index()` 验证设备是否可用，获取对应的物理设备索引

4. **记录创建**：创建 `PlaybackDevice` 实例，设置初始状态为在线（status=1）

5. **数据持久化**：调用 `db.session.add()` 和 `db.session.commit()` 保存到数据库

6. **响应返回**：返回新创建设备的完整信息

**代码实现要点**：

```python
@staticmethod
def create(name, type, device_unique_id, channel_index, sample_rate, description=None):
    # 检查设备是否已注册
    existing = PlaybackDevice.query.filter_by(
        device_unique_id=device_unique_id,
        channel_index=channel_index,
        is_deleted=0
    ).first()
    if existing:
        return error_response("该设备通道已被注册")
    
    # 验证设备索引
    device_index = audio_service.get_device_index(device_unique_id)
    if device_index is None:
        return error_response(f"无法定位物理设备: {device_unique_id}")
    
    device = PlaybackDevice(
        name=name,
        type=type,
        device_unique_id=device_unique_id,
        channel_index=channel_index,
        sample_rate=sample_rate,
        description=description,
        status=1  # online
    )
    db.session.add(device)
    db.session.commit()
    
    return success_response({
        "id": device.id,
        "name": device.name,
        "type": device.type,
        "deviceUniqueId": device.device_unique_id,
        "channelIndex": device.channel_index,
        "sampleRate": device.sample_rate,
        "status": device.status
    }, "播放设备添加成功")
```

### 5.5 删除播放设备 (DELETE /api/v1/playback-devices/:id)

**接口路径**：`DELETE /api/v1/playback-devices/:id`

**实现思路**：

1. **资源检索**：根据ID获取待删除的设备记录

2. **存在性校验**：设备不存在或已删除时返回404错误

3. **逻辑删除**：设置 `is_deleted = 1`，保留数据库记录供审计追溯

4. **状态通知**：如果设备当前处于测试中状态，触发停止测试流程

5. **关联处理**：在 `test_case_ audios` 表中若有引用此设备的配置，不做强制解除，但前端应提示用户更新配置

6. **数据持久化**：调用 `db.session.commit()` 保存更改

7. **响应返回**：返回操作成功确认

**代码实现要点**：

```python
@staticmethod
def delete(id):
    device = PlaybackDevice.query.get(id)
    if not device or device.is_deleted:
        return error_response("未找到播放设备", 404)
    
    # 如果设备正在测试中，停止测试
    if id in test_stop_events:
        test_stop_events[id].set()
    
    device.is_deleted = 1
    device.updated_at = func.now()
    db.session.commit()
    
    return success_response({"id": id}, "播放设备删除成功")
```

### 5.6 扫描可用设备 (POST /api/v1/playback-devices/scan)

**接口路径**：`POST /api/v1/playback-devices/scan`

**实现思路**：

1. **获取物理设备列表**：调用 `audio_service.get_all_physical_devices()` 获取系统中所有可用的物理音频设备

2. **获取已注册设备**：查询 `PlaybackDevice` 表中所有未删除的记录，构建已注册设备的唯一标识集合（使用 `device_unique_id_channel_index` 组合作为键）

3. **过滤未注册设备**：遍历物理设备列表，排除已在注册集合中的设备

4. **格式化扫描结果**：将物理设备信息转换为API响应格式，添加默认字段值

5. **响应返回**：返回扫描到的新设备列表

**代码实现要点**：

```python
@staticmethod
def scan():
    try:
        # 1. 获取物理设备列表
        physical_devices = audio_service.get_all_physical_devices()
        
        # 2. 获取已注册的设备
        registered = PlaybackDevice.query.filter_by(is_deleted=0).all()
        registered_keys = set([f"{d.device_unique_id}_{d.channel_index}" for d in registered])
        
        # 3. 过滤出未注册的设备
        scanned_results = []
        for dev in physical_devices:
            key = f"{dev['unique_id']}_{dev['channel_index']}"
            if key not in registered_keys:
                scanned_results.append({
                    "name": dev['name'],
                    "model": f"Hardware Channel ({dev['host_api']})",
                    "deviceUniqueId": dev['unique_id'],
                    "channelIndex": dev['channel_index'],
                    "sampleRate": dev['sample_rate'],
                    "type": "dry",
                    "status": "online"
                })
        
        return success_response(scanned_results, f"成功扫描到 {len(scanned_results)} 个新通道")
    except Exception as e:
        return error_response(f"扫描失败: {str(e)}")
```

### 5.7 测试播放设备 (POST /api/v1/playback-devices/:id/test)

**接口路径**：`POST /api/v1/playback-devices/:id/test`

**实现思路**：

1. **资源检索**：获取指定ID的播放设备记录

2. **存在性校验**：设备不存在时返回404错误

3. **测试音频文件准备**：确定测试音频文件路径，默认为 `resources/samples/test_audio_48k.wav`，支持绝对路径和相对路径

4. **音频文件校验**：检查测试音频文件是否存在，不存在时尝试创建目录并返回错误提示

5. **物理设备索引获取**：调用 `audio_service.get_device_index()` 获取设备在系统中的索引

6. **测试状态设置**：将设备状态更新为测试中（status=3），更新数据库

7. **创建停止事件**：为当前测试创建 `threading.Event` 对象，用于控制播放线程的停止

8. **启动播放线程**：创建后台线程执行播放任务：
   - 调用 `audio_service.driver.play()` 执行音频播放
   - 循环播放模式（loop=True）
   - 通过 `stop_event` 监听停止信号
   - 记录调试日志和错误日志
   - 播放结束后自动清理状态

9. **响应返回**：返回测试启动信息，包括设备ID、状态、测试音频文件名和设备索引

**代码实现要点**：

```python
@staticmethod
def test(device_id):
    device = PlaybackDevice.query.get(device_id)
    if not device:
        return error_response("未找到播放设备", 404)
    
    try:
        # 1. 确定音频文件路径
        sample_audio = "resources/samples/test_audio_48k.wav"
        if not os.path.isabs(sample_audio):
            sample_audio = os.path.join(current_app.root_path, '..', sample_audio)
        
        if not os.path.exists(sample_audio):
            os.makedirs(os.path.dirname(sample_audio), exist_ok=True)
            return error_response(f"音频文件不存在: {sample_audio}。请先预置测试音频。")

        # 2. 获取物理设备索引
        device_index = audio_service.get_device_index(device.device_unique_id)
        if device_index is None:
            return error_response(f"无法定位物理设备: {device.device_unique_id}")

        # 3. 启动异步播放线程
        stop_event = threading.Event()
        test_stop_events[device_id] = stop_event

        def play_thread():
            try:
                # 调用驱动进行播放
                audio_service.driver.play(
                    file_path=sample_audio,
                    device_index=device_index,
                    channel_index=device.channel_index,
                    loop=True,
                    stop_event=stop_event
                )
            except Exception as e:
                print(f"Playback thread error: {e}")
            finally:
                # 恢复设备状态
                with current_app.app_context():
                    d = PlaybackDevice.query.get(device_id)
                    if d:
                        d.status = 2  # online
                        db.session.commit()
                    test_stop_events.pop(device_id, None)

        thread = threading.Thread(target=play_thread, daemon=True)
        thread.start()

        # 更新设备状态为测试中
        device.status = 3  # testing
        db.session.commit()
        
        return success_response({
            "id": device.id, 
            "status": "testing",
            "sample_audio": os.path.basename(sample_audio),
            "device_index": device_index
        }, "音频驱动已启动播放")
    except Exception as e:
        db.session.rollback()
        return error_response(str(e))
```

### 5.8 停止设备测试 (POST /api/v1/playback-devices/:id/stop-test)

**接口路径**：`POST /api/v1/playback-devices/:id/stop-test`

**实现思路**：

1. **资源检索**：获取指定ID的播放设备记录

2. **存在性校验**：设备不存在时返回404错误

3. **测试状态检查**：检查 `test_stop_events` 中是否存在该设备的停止事件

4. **触发停止**：设置停止事件标志，通知播放线程退出循环

5. **状态更新**：将设备状态更新为在线（status=2）

6. **等待线程退出**（可选）：可以调用 `thread.join()` 等待线程完全退出，或依赖守护线程自动清理

7. **数据持久化**：调用 `db.session.commit()` 保存状态更改

8. **响应返回**：返回操作成功确认

**代码实现要点**：

```python
@staticmethod
def stop_test(id):
    if id not in test_stop_events:
        return error_response("该设备当前未在测试中", 400)
    
    try:
        # 触发停止事件
        test_stop_events[id].set()
        
        # 更新设备状态
        device = PlaybackDevice.query.get(id)
        if device:
            device.status = 2  # online
            db.session.commit()
        
        return success_response({"id": id}, "已停止测试")
    except Exception as e:
        db.session.rollback()
        return error_response(f"停止测试失败: {str(e)}")
```

### 5.9 关联 SPL 映射 (POST /api/v1/playback-devices/:id/associate-spl)

**接口路径**：`POST /api/v1/playback-devices/:id/associate-spl`

**实现思路**：

1. **参数接收**：从请求体接收 `spl_mapping_id` 参数

2. **设备检索**：获取指定ID的播放设备记录

3. **SPL映射校验**：验证指定的SPL映射记录存在且 `device_type` 与当前播放设备类型匹配

4. **建立关联**：更新 `PlaybackDevice` 的 `current_spl_mapping_id` 字段

5. **数据持久化**：调用 `db.session.commit()` 保存关联关系

6. **响应返回**：返回关联成功确认信息

**代码实现要点**：

```python
@staticmethod
def associate_spl(id, spl_mapping_id):
    device = PlaybackDevice.query.get(id)
    if not device or device.is_deleted:
        return error_response("未找到播放设备", 404)
    
    spl_mapping = SplMapping.query.get(spl_mapping_id)
    if not spl_mapping:
        return error_response("未找到SPL映射", 404)
    
    if spl_mapping.device_type != device.type:
        return error_response(
            f"SPL映射的设备类型({spl_mapping.device_type})与播放设备类型({device.type})不匹配"
        )
    
    device.current_spl_mapping_id = spl_mapping_id
    device.updated_at = func.now()
    db.session.commit()
    
    return success_response({
        "id": device.id,
        "splMappingId": device.current_spl_mapping_id
    }, "SPL映射关联成功")
```

## 3. 音频服务集成

### 3.1 audio_service 接口

模块通过 `audio_service` 与底层音频驱动进行交互，主要使用以下接口：

| 接口方法 | 功能描述 | 参数说明 |
|---------|---------|---------|
| `get_all_physical_devices()` | 获取系统中所有可用的物理音频设备 | 无 |
| `get_device_index(unique_id)` | 根据设备唯一标识获取系统索引 | `unique_id`：设备唯一标识 |
| `driver.play()` | 执行音频播放 | `file_path`：音频文件路径<br>`device_index`：设备索引<br>`channel_index`：通道索引<br>`loop`：是否循环播放<br>`stop_event`：停止事件对象 |

### 3.2 物理设备信息结构

`get_all_physical_devices()` 返回的设备信息结构如下：

```python
{
    "name": "设备名称",
    "host_api": "主机API类型",
    "unique_id": "设备唯一标识",
    "channel_index": "通道索引",
    "sample_rate": "采样率",
    "max_input_channels": "最大输入通道数",
    "max_output_channels": "最大输出通道数"
}
```

### 3.3 设备索引映射

设备唯一标识（`unique_id`）与系统设备索引（`device_index`）的映射关系：

- `unique_id`：设备在 PortAudio 中的唯一标识符，通常为数字字符串
- `device_index`：设备在 `audio_service` 内部的索引编号，用于调用驱动方法时指定设备

在调用 `audio_service.driver.play()` 时需要使用 `device_index` 参数。

## 5. 错误处理规范

### 5.1 错误响应格式

所有接口在发生错误时返回统一格式的错误响应：

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "错误描述信息"
  },
  "data": null
}
```

### 5.2 常见错误码

| 错误码 | HTTP状态码 | 说明 | 处理建议 |
|-------|-----------|------|---------|
| `DEVICE_NOT_FOUND` | 404 | 设备不存在 | 检查设备ID是否正确 |
| `DEVICE_ALREADY_REGISTERED` | 400 | 设备已注册 | 设备通道组合重复 |
| `DEVICE_NOT_LOCATABLE` | 400 | 无法定位物理设备 | 检查设备是否连接 |
| `DEVICE_NOT_TESTING` | 400 | 设备未在测试中 | 无需停止或已停止 |
| `AUDIO_FILE_NOT_FOUND` | 400 | 音频文件不存在 | 检查测试音频文件路径 |
| `SPL_MAPPING_NOT_FOUND` | 404 | SPL映射不存在 | 检查映射ID |
| `SPL_MAPPING_TYPE_MISMATCH` | 400 | SPL映射类型不匹配 | 选择类型匹配的映射 |

### 5.3 异常捕获

所有接口使用 try-except 块包裹业务逻辑，捕获异常后调用 `error_response()` 返回通用错误信息，避免内部实现细节泄露。

## 6. 性能优化策略

### 6.1 查询优化

- 使用 `paginate()` 方法进行分页查询，避免一次性加载全部数据
- 对常用查询字段创建索引
- 使用 `or_()` 组合多个模糊查询条件，减少数据库查询次数

### 6.2 异步执行

- 设备测试使用独立线程执行，避免阻塞主请求
- 使用守护线程（`daemon=True`），确保程序退出时自动清理
- 使用 `threading.Event` 实现线程间的优雅退出

### 6.3 资源管理

- 测试完成后自动清理 `test_stop_events` 中的记录
- 使用上下文管理器确保数据库会话的正确提交和回滚
- 及时关闭不需要的数据库会话连接

## 7. 日志记录规范
