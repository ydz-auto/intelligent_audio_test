# 测试用例管理接口实现文档

## 1. 模块概述
测试用例管理模块负责系统中测试用例的完整生命周期管理。测试用例表采用统一设计，不再区分 API 测试和端到端 (E2E) 类型，而是通过灵活的配置支持不同的测试场景，并提供标签管理和分组归类功能。

## 2. 接口详细实现思路

### 2.1 获取测试用例列表 (GET /api/v1/testcases)
**实现思路：**
1. **参数解析与验证**：从查询参数中提取 `page`, `per_page`/`perPage`, `keyword`, `tag`, `group_id`, `type`。对分页参数进行整数转换并设置默认值（1, 10），支持驼峰式和下划线式参数格式。
2. **构建基础查询**：使用 SQLAlchemy 对 `test_cases` 表启动查询，过滤条件为 `deleted == False`。
3. **动态过滤**：
   - 若提供 `keyword`：在 `name` 或 `description` 字段上使用 `LIKE` 进行模糊搜索。
   - 若提供 `tag`：通过关联表 `test_case_tags` 和 `tags` 表，筛选包含指定标签名称的用例。
   - 若提供 `group_id`：精确匹配 `group_id` 字段。
   - 若提供 `type`：暂未实现过滤逻辑。
4. **分页处理**：使用 SQLAlchemy 的 `paginate()` 方法实现高效分页。
5. **数据组装**：
   - 遍历查询结果，提取用例基本信息。
   - 对每个用例，查询关联的 `tags` 名称。
   - 确定测试用例类型（从 `config.audios` 数组中获取第一个音频的 `test_type`）。
   - 构造统一的分页响应结构，包含 `items`, `total`, `page`, `per_page`, `pages` 字段，支持 `groupId` 和 `groupName` 字段。

### 2.2 获取测试用例详情 (GET /api/v1/testcases/:id)
**实现思路：**
1. **资源查找**：根据路径参数 `id` 在 `test_cases` 表中查找记录，确保其存在且 `deleted == False`。
2. **逻辑删除校验**：若记录不存在或已删除，返回 404 错误。
3. **关联数据提取**：
   - 查询关联的 `tags` 表获取所有标签名称列表。
   - 从 `config.audios` 数组中提取所有关联的音频配置：
     - 遍历 `config.audios` 数组，对每个音频项，查询关联的 `Audio` 表获取音频名称。
     - 组装音频信息，包含 `id`, `audioId`, `audioName`, `testType`, `spl`, `playbackDeviceId`, `playOrder` 字段。
   - 从 `config.dimensions` 中提取所有关联的评估维度信息，支持两种格式：
     - 数组格式（旧格式兼容）：直接使用维度ID列表
     - 对象格式：`{ api: [维度ID列表], e2e: [维度ID列表] }`（新格式）：合并所有类型的维度ID
   - 去重维度ID，查询关联的 `Dimension` 表获取维度名称和类型。
   - 从 `config.background_noise` 中获取背景噪声配置。
4. **测试类型确定**：从 `config.audios` 数组中获取第一个音频的 `test_type` 作为测试用例类型。
5. **结果返回**：将模型对象转换为字典，包含完整配置信息、标签列表、音频列表及维度列表，支持前端展示和编辑，返回 `groupId`, `groupName`, `group` 等字段。

### 2.3 新增测试用例 (POST /api/v1/testcases)
**实现思路：**
1. **数据验证与格式兼容**：
   - 支持驼峰式和下划线式参数格式（如 `groupId` 和 `group_id`）。
   - 校验必填字段 `name`，以及 `group_id` 或 `group` 名称。
2. **分组处理**：
   - 支持通过 `group_id` 直接指定分组。
   - 若提供 `group` 名称，自动查找对应的分组 ID，若不存在则返回错误。
3. **名称唯一性校验**：在所属分组内检查是否存在同名用例，若存在则返回错误。
4. **配置处理**：
   - 合并配置，支持从 `config` 对象或直接从请求体获取配置信息：
     - 创建 `merged_config` 作为最终配置对象。
     - 若提供了完整的 `config`，使用它作为基础。
     - 支持从请求体直接传入 `backgroundNoiseId`/`background_noise_id` 和 `backgroundNoiseSpl`/`background_noise_spl` 字段，转换为 `config.background_noise` 格式。
   - 处理音频配置：
     - 支持从请求体直接传入 `audios` 字段。
     - 验证每个音频项必须包含 `audioId`/`audio_id`, `testType`/`test_type`, `spl`, `playOrder`/`play_order` 字段。
     - 验证当 `test_type` 为 `e2e` 时，必须提供 `playbackDeviceId`/`playback_device_id`。
     - 将音频配置转换为标准格式 `{ audio_id, test_type, spl, playback_device_id, play_order }` 并存储到 `config.audios`。
   - 处理评测维度配置：
     - 支持从请求体直接传入 `dimensions` 字段。
     - 支持两种格式：
       - 数组格式（旧格式）：自动转换为 `{ api: [...], e2e: [...] }`
       - 对象格式（新格式）：直接使用 `{ api: [...], e2e: [...] }`
     - 将处理后的维度配置存储到 `config.dimensions`。
   - 处理标签配置：
     - 支持从请求体直接传入 `tags` 字段。
     - 将标签配置存储到 `config.tags`。
5. **事务处理**：
   - **创建主记录**：生成 UUID 作为用例 ID，在 `test_cases` 表中创建记录，将所有配置存储到 `config` 字段。
   - **处理标签关联**：
     - 解析 `tags` 列表，对每个标签名称，查询 `tags` 表，若不存在则创建新标签。
     - 通过 `test_case_tags` 关联表建立标签与测试用例的关联关系。
6. **异常处理**：
   - 若发生数据库错误，执行事务回滚。
   - 捕获并返回所有异常信息。
7. **成功响应**：
   - 返回新创建的用例 ID。
   - 返回 HTTP 状态码 201（Created）。

### 2.4 更新测试用例 (PUT /api/v1/testcases/:id)
**实现思路：**
1. **资源查找**：确保用例存在且未删除。
2. **数据验证与格式兼容**：支持驼峰式和下划线式参数格式。
3. **名称唯一性校验**：在更新名称时，检查同组下是否存在除自己以外的同名用例。
4. **分组处理**：支持通过 `group_id` 或 `group` 名称更新分组。
5. **配置合并与增量更新**：
   - 基于现有的 `config` 字段创建合并配置。
   - 若提供了完整的 `config`，使用它作为基础。
   - 仅对请求体中存在的字段进行修改。
   - 更新 `name`, `description`, `group_id` 及 `config` JSON 字段。
6. **背景噪声更新**：支持从 `config` 对象或直接从请求体更新背景噪声配置，存储到 `config.background_noise`。
7. **音频配置更新**：支持从请求体直接传入 `audios` 字段，转换为标准格式后存储到 `config.audios`。
8. **评测维度更新**：支持从请求体直接传入 `dimensions` 字段，支持两种格式：
   - 数组格式（旧格式）：自动转换为 `{ api: [...], e2e: [...] }`
   - 对象格式（新格式）：直接使用 `{ api: [...], e2e: [...] }`
9. **标签关联更新**：
   - 若请求包含 `tags`，重置 `test_case_tags` 关联，自动创建不存在的标签。
10. **自动更新时间**：设置 `updated_at` 为当前时间。
11. **事务提交**：确保主表和标签关联表更新的一致性，发生错误时回滚事务。

### 2.5 删除测试用例 (DELETE /api/v1/testcases/:id)
**实现思路：**
1. **资源查找**：根据路径参数 `id` 获取目标测试用例记录。
2. **逻辑删除校验**：若记录不存在或已删除，返回 404 错误。
3. **执行逻辑删除**：将 `deleted` 字段标记为 `True`，保留历史记录和关联关系。
4. **更新时间**：设置 `updated_at` 为当前时间。
5. **事务处理**：确保删除操作的原子性，发生错误时回滚事务。

### 2.6 复制测试用例 (POST /api/v1/testcases/:id/copy)
**实现思路：**
1. **资源查找**：根据 `id` 查找原始测试用例，确保其存在且未删除。
2. **数据深度拷贝**：
   - 生成新的 UUID 作为用例 ID。
   - 创建新的用例记录，名称默认为 `原始名称_copy`。
   - 复制主表字段（描述、分组 ID、`config` 字段等），直接复用 `config` 字段的完整配置。
3. **关联关系克隆**：
   - **标签克隆**：复制原用例的所有标签关联。
   - **配置克隆**：直接复制原用例的 `config` 字段，包含所有音频配置、评测维度配置和背景噪声配置。
4. **事务保障**：使用数据库事务确保主记录与所有关联关系的克隆操作原子化。
5. **结果返回**：返回新生成的测试用例 ID 和成功消息。

### 2.7 试听测试用例 (POST /api/v1/testcases/:id/preview)
**实现思路：**
1. **资源查找**：根据 `id` 查找测试用例，确保其存在且未删除。
2. **音频资源检查**：检查用例是否关联了音频资源，若无则返回错误。
3. **预览任务管理**：
   - 生成唯一的预览任务 ID（格式：`PREVIEW_{tc_id}`）。
   - 停止之前可能存在的预览任务。
4. **背景噪声处理**：
   - 若配置了背景噪声，获取对应的音频文件和播放设备。
   - 根据 SPL 映射计算增益值。
   - 调用音频服务播放背景噪声（循环播放）。
5. **干声音频播放**：
   - 按 `play_order` 对音频进行排序。
   - 获取每个音频的文件路径和播放设备。
   - 根据 SPL 映射计算增益值。
   - 调用音频服务播放音频（目前实现为仅播放第一个音频）。
6. **结果返回**：返回预览任务 ID 和状态信息。

### 2.8 停止预览测试用例 (POST /api/v1/testcases/:id/stop_preview)
**实现思路：**
1. **预览任务管理**：
   - 生成唯一的预览任务 ID（格式：`PREVIEW_{tc_id}`）。
2. **停止预览**：调用音频服务停止对应的预览任务。
3. **结果返回**：返回测试用例 ID 和停止状态信息。

### 2.12 导出测试用例 (POST /api/v1/testcases/export)

**实现思路：**

1. **请求解析**：路由 `routes/testcase_bp.py:31`（`require_permission('testcase:import_export')`，INT-2214 与 import 对齐补齐）→ `TestCaseImportExportService.export_cases` → `TestCaseExportService._query_cases_for_export` 解析 `TestCaseExportRequest`：`ids`（必填，空 → 400「未指定要导出的用例ID」）、`format`（`json` / `csv` / `xlsx` / `zip`，默认 `json`）、`include_deleted`、`include_reference_params`（ZIP 默认 `true`）、`include_audios`（ZIP 默认 `false`）。基类 `extra="ignore"` 会静默丢弃未声明字段——`include_audios` 在本卡前就是这样被丢弃的（INT-2196 实测「加/不加同包同大小」）。
2. **数据读取**：`_build_export_rows` 逐个 id 走 ACL `GetTestCaseDetail`（单条失败跳过，全部取不到 → 400「未找到指定的测试用例」），`_build_case_row` 保留整份 `config` 并产出导出列。
3. **按格式生成**：`json` / `csv` / `xlsx` 走既有实现；`zip` 走 `_generate_zip_export`（manifest + testcases.json + 可选参考参数 / 音频附件）。
4. **结果返回**：文件流 `Response`（附件下载）；参数/依赖错误走 `error_response` → JSON。

**请求**

| 项 | 值 |
|------|------|
| 方法 / 路径 | `POST /api/v1/testcases/export` |
| 权限点 | `testcase:import_export`（INT-2214 起；此前无权限点） |
| Content-Type | `application/json` |
| 字段 | `ids: string[]`（必填）、`format: string`（默认 `json`）、`include_deleted: bool`（默认 `false`）、`include_reference_params: bool`（ZIP 默认 `true`）、`include_audios: bool`（ZIP 默认 `false`） |

**ZIP 包结构（`format=zip`）**

| 包内路径 | 说明 |
|------|------|
| `manifest.json` | 包清单（见下表） |
| `testcases.json` | `{version, exported_at, total_count, test_cases[]}`；`test_cases[]` 为导出数据行（含整份 `config`） |
| `reference_params/{case_id}/round_{n}.json` | `include_reference_params=true` 且用例有参考参数文件时打包（读取失败仅告警跳过） |
| `audios/{audio_id}.{ext}` | `include_audios=true` 且能读到二进制时打包；同一 `audio_id` 被多个用例引用只打 1 份 |

**`include_audios` 口径（INT-2214）**

- **引用收集全口径**：单点实现在 `shared/utils/testcase_helpers.collect_case_audio_references`，导出 / 导入校验 / 任务数据导出三处共用：
  - direct：`rounds[].audios[].audio_id`、`rounds[].audios[].interferers[].audio_id`（干扰人）、顶层 `audios[].audio_id`（未轮次化平面形态兜底）；
  - noise：顶层 / 轮次级 / segment 级（`rounds[].audios[]` 内）的 `background_noise.audio_id` / `backgroundNoise.audio_id`。
- **元数据**：一次批量 `GetAudiosByIds`（`AudioAclRepositoryImpl.get_by_ids`），不做 owner / 可见性过滤——随用例引用导出（INT-564 裁定），与任务数据导出口径一致。
- **二进制**：`shared.infrastructure.storage.storage_load_bytes(audio.file_path)`；单条读不到只计入 missing。
- **扩展名**：`audios[].format` 优先；缺失/非法时回落 `file_path` 后缀；都没有兜底 `bin`。
- **md5 / size**：按**包内实际字节**计算（保证 `manifest.audios[].md5` 与包内文件一致，供后续导入回导按 md5 去重）；主库存量 `audios.md5` 与对象存储字节不一致时以包内字节为准。
- **`include_audios=false` / 老客户端不传**：包内文件条目与旧行为完全一致（无 `audios/`），manifest 新增字段为空值 / 0（见下表，属预期，不算包结构破坏）。

**`manifest.json` 字段**

| 字段 | 类型 | 说明 |
|------|------|------|
| `format` | STRING | `intelligent-audio-testcase-package` |
| `version` | STRING | `PACKAGE_VERSION`，INT-2214 起 `1.1`（结构变更留痕；导入端当前不读 manifest，不写版本分支） |
| `exported_at` | STRING | 东八区 ISO8601 |
| `total_count` | INT | 导出用例数 |
| `options.include_reference_params` | BOOL | 是否打包参考参数 |
| `options.include_audios` | BOOL | 是否打包音频（INT-2214 新增） |
| `reference_param_file_count` | INT | 实际打包的参考参数文件数 |
| `audio_file_count` | INT | 实际打包的音频文件数（去重后；INT-2214 新增） |
| `missing_audio_count` | INT | 引用了但未打包的音频数（INT-2214 新增） |
| `missing_audio_ids` | INT[] | 未打包的音频 id（库中不存在 / 二进制读不到；INT-2214 新增） |
| `audios` | ARRAY | 音频清单 `[{id, name, file, md5, size, format}]`，按 id 去重、与包内文件一一对应（INT-2214 新增） |

**失败分类（两类，不得混淆）**

| 场景 | 行为 |
|------|------|
| audio_service ACL 查询失败 / 返回非列表（依赖不可用） | **整包 5xx**：HTTP 503、`code=306`、JSON 错误体，不产出半包（`include_audios=true` 时一个音频都没带上却返回 200 是最坏体验） |
| 引用 id 库中不存在 / 二进制读不到 / `file_path` 缺失 | **HTTP 200** 正常出包，计入 `missing_audio_count` / `missing_audio_ids`，不静默跳过 |
| 未勾选 / 不传 `include_audios` | 200，包内无 `audios/`，两个计数为 0、`audios` / `missing_audio_ids` 为空数组 |

**已知边界**

- 导入端当前**完全不读 manifest**（`_parse_zip_rows` 只取 `testcases.json`），`audios/` 对老导入端无破坏；**音频导入回导**（按 md5 复用 / 未命中登记 / `audio_id` 重映射）另卡，本卡不实现。因此导入仍按 INT-2182 行级报「音频 X 不存在」，文档与前端**不得**宣称导入后音频自动可用。
- ZIP 包内含音频时体积随引用音频总大小增长；无单包大小上限（与任务数据导出同口径）。

### 2.14 导入预览 (POST /api/v1/testcases/import/preview)
**实现思路：**
1. **文件解析**：路由 `routes/testcase_bp.py:48`（`require_permission('testcase:import_export')`）委托 `TestCaseImportService.preview_import:776`；取 multipart 字段 `file`，按扩展名判定格式（`json` / `csv` / `xlsx` / `xls` / `zip`）。上传包装 `_UploadedFile` 无 `seek`，故先整体读入内存流复用（`_build_preview_result:813`），预览填充与行级校验共用一份字节。
2. **数据预览**：四种格式各填一份预览行——`_fill_excel_preview:940` / `_fill_json_preview:969` / `_fill_csv_preview:977` / `_fill_zip_preview:926`；`totalRows` = 解析出的数据行数（表头不计）。ZIP 预览不把包内参考参数内容透给前端。
3. **行级校验**：预览填充完成后，由 `_build_preview_result:797` 统一填 `data.errors`，**四种格式只有这一份实现**（不在 4 个 `_fill_*_preview` 里各写一份）。校验行由导入同一解析函数产出（`_parse_rows_for_validation:857`：`_parse_json_file` / `_parse_csv_rows` / `_parse_excel_rows` / `_parse_zip_rows`），逐行调 `_validate_row_full:398` = `_validate_imported_case:391`（名称必须是非空字符串）+ `_build_case_payload:619` 纯计算（标签收集、噪声/音频/维度合并，`group=None` 不查不建分组）；**没有**拿预览原始行或 `_normalize_preview_case` 当校验口径。ZIP 直接复用预览期已解析的行（`_fill_zip_preview:937`），不二次解包。
4. **重复检测**：`_detect_preview_duplicates:868` 只读查重（不建分组、不写库），仅前 `PREVIEW_DUPLICATE_SCAN_LIMIT = 500` 行参与（`shared/constants/testcase_transfer.py:63`），超出置 `duplicateScanTruncated=true`；**行级校验不受该上限约束**。
5. **结果返回**：成功走 `success_response(data=...)` → HTTP 200；结构性解析失败、格式不支持由 `preview_import` 兜成 `error_response` → HTTP 400，`message` 形如 `预览失败: ...`。

**请求**

| 项 | 值 |
|------|------|
| 方法 / 路径 | `POST /api/v1/testcases/import/preview` |
| 权限点 | `testcase:import_export` |
| Content-Type | `multipart/form-data` |
| 表单字段 | `file`（必填）：`.json` / `.csv` / `.xlsx` / `.xls` / `.zip` |

**响应 `data` 字段**

| 字段 | 类型 | 描述 |
|------|------|------|
| `totalRows` | INT | 解析出的数据行数（表头不计）；旧版单 Sheet Excel 取首 Sheet 行数，新版取 `TestCases` Sheet 行数 |
| `testCases` | ARRAY | 预览行（各格式原始行；ZIP 已剥掉 `reference_params_content`），与 `totalRows` 条数一致 |
| `errors` | STRING[] | 行级校验错误，元素格式 `第{N}行: 原因`，逐条见下 |
| `duplicates` | ARRAY | 重复用例，元素 `{row, name, id, existingId, existingName, matchedBy}`；`row` 与 `errors` 同一 1 起行号口径 |
| `duplicateCount` | INT | `duplicates.length` |
| `duplicateScanTruncated` | BOOL | `totalRows > 500` 时为 `true`（重复检测只看前 500 行） |
| `duplicateStrategyDefault` | STRING | 导入默认重复策略，取值 `skip` / `overwrite` / `copy`，默认 `skip` |
| `audioConfigs` / `dimensions` / `tags` / `groups` | ARRAY | 仅 Excel 多 Sheet 格式命中同名 Sheet 时填充，其余格式为空数组 |

**`errors` 契约**

- 元素格式固定 `第{N}行: 原因`（ASCII 冒号 + 空格）；`N` = 该文件经导入解析函数产出的行下标 + 1，**表头不计行号**。
- 与导入回执完全同口径：`POST /api/v1/testcases/import` 的 `data.errors` 出自 `_create_cases_from_rows:441`，同一 `第{idx + 1}行` 文案、同一行级处理（`_validate_imported_case` + `_build_case_payload` 纯计算），因此两侧逐条可比对。类型错误（如 `tags` 非数组、`audios` 元素非对象、`name` 非字符串）预览即报，不再拖到导入（INT-2181）。
- 名称行级规则：空值（`null` / 缺省 / 空串）→ `用例名称不能为空`；非字符串（JSON/ZIP 的数字、旧版单 Sheet Excel 的数字单元格，如 `12345`）→ `用例名称必须是字符串`。导入侧 `_find_existing_case:568` 的 `.strip()` 不再会抛出 `'int' object has no attribute 'strip'` —— 该检查已提前到两侧共用的 `_validate_imported_case`。
- 引用音频规则（INT-2182，口径 INT-2214 扩面）：名称校验通过后校验用例引用的音频是否在库中存在，覆盖 `shared/utils/testcase_helpers.collect_case_audio_references` 与导出同源的全口径——direct（`rounds[].audios[].audio_id`、`rounds[].audios[].interferers[].audio_id`、顶层 `audios[]`）+ 各级背景噪音（顶层 / 轮次 / segment 级 `background_noise`|`backgroundNoise.audio_id`），另加解析期已落好的扁平 `audios[]`（CSV/Excel 扁平格式 `AUDIO_ID` 列）；缺失文案 `音频 {id} 不存在`，多个合并一条、同 id 跨轮只报一次。软删音频视同不存在；音频服务查询失败时 fail-open（仅告警，不阻断整包导入）。
- **每个坏行只出 1 条**（单行校验返回单条消息），多字段非法的行不会重复计数。
- **全量校验、无扫描上限**，也没有 `errorsScanTruncated` 之类的截断字段；不要与 `duplicateScanTruncated` 混用。
- JSON / CSV / Excel（新格式与旧版单 Sheet）/ ZIP 四类格式都生效。
- 单行校验抛异常时按该行的 1 条错误回，不中断其余行；结构性解析异常（JSON 非对象、ZIP 包非法等）整体失败并 400 `预览失败: ...`，**不会**静默返回 `errors: []`。
- 预览只覆盖**行级数据校验**；`_persist_case`（建/覆盖/副本落库）与 `_restore_reference_params`（ZIP 参考参数回写）的失败依赖真实写库，只出现在导入回执，预览无法预判。重复行在导入时按策略可能被跳过，导入回执也不为它产生行级错误。

**行为变更（相对旧实现）**

- 旧版单 Sheet Excel（无 `TestCases` Sheet）：此前预览 `testCases=[]`、`totalRows=0`，而 `errors` 已按解析行给出行号，二者不一致；现按首 Sheet 原始行补齐 `testCases` / `totalRows`（`_fill_excel_preview:938-945`）。带 `TestCases` Sheet 的新格式 Excel 行为不变（仍只取 `TestCases`）。
- `duplicates` / `duplicateCount` / `duplicateScanTruncated` / `duplicateStrategyDefault` 的语义与上限均未改动。
- INT-2181：预览行级校验由「只判名称非空」扩到导入同口径（加跑 `_build_case_payload` 纯计算），`tags` 非数组等类型错误行由预览直接报出；`_validate_imported_case` 同时补齐名称类型校验（非字符串 → `用例名称必须是字符串`，导入侧原会在此后 `_find_existing_case` 抛 AttributeError）。仅名称校验的旧行为不再保留。
- INT-2182：`_validate_imported_case` 在名称校验后增加引用音频存在性校验（预览与导入共用），缺失音频的行不再悬空落库。

**已知边界（本卡不修）**

- JSON 必须是对象 `{"test_cases": [...]}`；裸数组返回 400，`message` = `预览失败: 'list' object has no attribute 'get'`（`_fill_json_preview:969` 调 `data.get`）。
- 系统导出的 CSV 表头是 `NAME`（`testcase_export_service.py:311,343`），而旧版导入/预览的列映射只认 `用例名称`（`_parse_legacy_format:171` 起的 `column_map`）→ 导出的 CSV 直接回导会被逐行判成 `用例名称不能为空`。这是父卡风险 R1（另卡处理），**不要**据此认为「导出 CSV」与「导入模板」表头一致。
- 预览的行级校验与导入共用解析函数与 `_build_case_payload`：Excel 新格式预览会对同一文件解析两次（`_fill_case_audios:308` 按名查音频的 gRPC 调用也随之翻倍）；扁平格式且带噪声音频名的 JSON/CSV/ZIP 行，校验期也会按名查一次音频（只读）。ZIP 已复用首次解析结果。
- INT-2182 的引用校验（INT-2214 起与导出同口径）只覆盖音频引用；`playback_device_id` / 播放设备与逻辑音箱的引用存在性仍未校验（范围外）。

**前端消费口径**

- 通过行级校验、可进入导入的行数 = `totalRows - errors.length`；实际新增 / 覆盖 / 跳过 / 副本数还要看 `duplicates` 与重复策略（`duplicateStrategyDefault` 默认 `skip`）。
- `errors` 为空数组只表示「无坏行」，不代表一定能导入（重复行见 `duplicates`）。
