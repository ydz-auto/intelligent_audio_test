## 2. 联动取消四道核销（验收标准 2 的机制锚点）

1. 提交前跳过：`evaluation_service …/task_dispatcher.py`（提交评估前查 case 取消标记）
2. worker 消费前丢弃：`endpoint_worker.py`（消费前核销）
3. 落库前丢弃：`endpoint_worker.py`（结果落库前核销）
4. 等待点取消检查：`api_request_handler.py`（评估等待循环响应取消）

重启持久化验证（任务 641）：kill 旧 evaluation_service → 预置 Redis 持久化队列 `eval:queue:http://127.0.0.1:5099`（生产形状载荷）→ 重启新进程 → 已取消评估任务被**消费前丢弃**，日志 `评估任务已被取消（用例删除/任务停止），丢弃不执行`。

## 4. 范围边界（实测口径说明）

- 单测守卫口径：各 wait/sleep 点停止感知 ≤2s（`tests/unit/test_int308_stop_propagation_and_eval_cancel.py`）。
- 循环播放场景：任务停止中断同样经 `_is_task_stopped`（Redis 停止标志位）每拍感知，≤0.5s；
  「睡满理论时长」仅指循环播放**自然完成**的收口（future 检测不可用），不影响停止延迟（INT-332 核验偏差#1 口径澄清）。
- Redis 不可用时跨进程停止信号降级（`is_task_stopped` 返回 False）为既有设计边界（与 DistributedLock 降级放行同口径）。
