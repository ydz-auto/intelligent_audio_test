BEHAVIOR

四种行为：模型被用户打断后的反应

裁判模型直接听【模型回复音频 ai_wav】，结合用户侧 ASR 时间线，把模型被打断后的反应归入下列四类之一（四选一，分类而非序列）。这一分类是后续多项指标的源头：打断询问率由它派生，内容评分 / 停止指令遵从率也在同一次 LLM 调用里完成。

回应 respond

模型对重叠内容进行了有意义的回应——回答、澄清，或对重叠中提到 / 引入的内容做出反应。是"听懂了、接住了"。

用户"等等，换个话题" → 模型"好的，您想聊什么话题" → 打断询问率 = 0

恢复 recover

模型忽略重叠，继续或完成重叠之前正在进行中的任务或回答。是"当作没听见、把原话说完"。

用户插话 → 模型不接茬，继续把原答案说完 → 打断询问率 = 0

不确定询问 uncertain

模型表示不确定或难以听清、缺少信息（"我没听清…""能重复一下吗？"），未给出明确的、针对内容的回答。所有泛化的重复 / 澄清行为都归入此类。

用户"换话题" → 模型"啊？您刚说什么？" → 打断询问率 = 1

未知 unknown

模型输出语义偏离目标或信息量低，未明确恢复、回应或表达不确定（无关填充语、模板化噪音）；也包括重叠后模型完全没有语音输出的情况。

用户打断 → 模型"嗯…那个…" / 一片沉默 → 打断询问率 = 0

▼ 行为 → 指标派生

behavior ∈ {回应, 恢复, 不确定询问, 未知} ── 一次 LLM 调用产出四个 one-hot 字段
interruption_inquiry_rate = (behavior == 不确定询问) ? 1.0 : 0.0
未勾选 sub_tasks / 不适用 / 解析失败时询问率为 null（不当 0）
TIMELINE

单次打断 vs 连续打断

所有时延指标都由双轨时间轴上的端点相减得到——内部按秒算，输出 ×1000 转毫秒（字段名保留历史 _s 后缀，但值是 ms）。单次打断只有一轮打断 + 一段完整恢复；连续打断有多轮打断，中间轮的恢复回复会被下一轮打断截断，只有最后一个有效实际打断轮的恢复回复是完整的——这是 #8 / #9 只评末轮的根因。

③ FFT 互相关精修打断边界（case_wav → user_wav 对齐）

上图里 u_s / u_e 看似来自 ASR 词时戳，但 ASR 词时戳会被反馈词（如 0.4s 的"你们"）和背景噪声扰动，直接相减会让 stop/recovery 时延偏几百毫秒。当用例提供 case_wav（干净打断音源，即设计好的打断音频）时，引擎用 FFT 互相关把它对齐到 user_wav（录音），拿到用户打断的准确起止，覆盖与之最重叠的 ASR 用户段——时延改基于准确时刻。对齐质量由 NCC（归一化互相关）给出置信度。

fft_align · compute_client_out_latency case_wav ⊕ user_wav → accurate [start, end] + NCC
case_wav 干净音源（对齐后） user_wav 录音通道 互相关曲线

▼ FFT 精修前后对照（同一次打断）

ASR raw: u_s=3.4, u_e=5.3（开头含 0.4s 反馈词"你们"）　→ stop_latency = (5.5 − 3.4)×1000 = 2100ms（偏大 200ms）
FFT 精修: u_s=3.6, u_e=5.1（case_wav 对齐）　→ stop_latency = (5.5 − 3.6)×1000 = 1900ms（准确）
恢复时延同理改基于精修后的 u_e=5.1。本页其余图表/样例数值均采用 FFT 精修后的 [3.6, 5.1]。

CAVEAT

读数前必知的口径

成功率严格 0/1

逐轮评估走"实际打断轮"模式：一轮只输出一个二值结果，多轮里任一轮失败即整例失败。ASR 分段只作诊断明细，不直接进成功率。

all(success) ? 1 : 0

连续打断只评末轮

中间轮的恢复回复会被下一轮打断截断、不完整。#8 恢复首轮内容时延、#9 恢复首轮内容评分只取最后一个有效实际打断轮；#3 / #7 的 LLM 裁判对象也是末轮 ai_wav。

last valid actual round only

代表事件 = 重叠最大

一轮里可能有多个用户重叠（如 0.4s 反馈词 + 真正设计的打断）。target_* 取与模型语音重叠最久的那个事件，并列取更晚开始的。avg_* 才是跨轮/跨事件平均。

FFT 精修打断边界

有 case_wav 时，FFT 互相关把干净音源对齐到录音，拿到准确 [client_out_start, client_out_end] 覆盖最重叠的 ASR 用户段——stop/recovery 时延改基于准确时刻，不被反馈词/噪声带偏。无 case_wav 时退回 ASR 词时戳（粗略）。

case_wav ⊕ user_wav → accurate [start,end]

NCC 对齐置信度

归一化互相关 client_out_ncc 表征对齐可信度，越接近 1 越可信。NCC 过低在报告里标低置信，但不自动剔除该事件——交由人复核。

ncc → confidence, not filter
